105743 要把“谁介绍了客户或合约”整理成销售合约可直接使用的管理归属。输入中的介绍关系是一条条人员、部门、比例记录；输出则以销售合约和交易对手为载体，把最多三组归属横向放在同一行。

这段加工分两次写入：先生成任务内部的 `otc_div_temp`，再把它作为合约级、客户级两种关联来源，回接当日销售基础并写管理归属快照。**前三组的形成、合约与客户关系的连接、逐字段回退是三个不同动作，必须分别理解。**

## 客户／合约介绍关系

先读取客户介绍关系、合约介绍关系及香港客户介绍关系，保留本次日期下符合各来源有效条件的记录，再用 `UNION ALL` 合并。客户级记录使用 `client_id`，合约级记录使用 `Contract_Code`；不适用的另一种键填为空字符串。

这一步还没有把介绍关系对应到每一份销售合约。同一客户可以有多条介绍记录，合约也可以有自己的介绍记录。两类记录暂时并列存在，后面才能分别用客户号和合约号找到它们。

## 排序并补人员机构

每一路先按自己的业务键分区：客户关系按客户号，合约关系按 `Contract_Code`。分区内按分配比例降序，再按客户经理排序，得到 `seq`。

随后按人员和部门的关联入口补充员工编号、姓名、在职状态、机构名称及所属分支等属性。员工使用 OA 用户等标识匹配；部门资料按机构编号补齐。机构分支资料另有交易日函数的取数口径，不应笼统解释为“所有属性都来自同一天的历史版本”。

**排序序号表达归属位置，人员机构关联表达属性补充。** 补齐属性后的记录仍是介绍关系行，尚未变成最终的一行三组结果；人员或机构匹配是否会扩行，不能仅由存在这些 Join 判定。

## otc_div_temp：横向前三组

接着按 `Contract_Code、client_id` 分组，用 `MAX(CASE WHEN seq=1/2/3 THEN ... END)` 分别取每个位置的机构、人员及比例，写入 `otc_div_temp`。

这是本任务第一次明确改变记录的组织方式：同一业务键下的多条介绍关系，变成一行中的第 1、2、3 组字段。该临时结果后面会被读取两次，分别当作合约级归属 `ci` 和客户级归属 `cpi`；它不是一个外部业务系统。

示意，非真实数据：

| 输入介绍关系            | 排序位置 | 临时结果中的位置    |
| ----------------------- | -------- | ------------------- |
| 客户 C001，甲，比例 0.6 | 1        | 人员1=甲，比例1=0.6 |
| 客户 C001，乙，比例 0.3 | 2        | 人员2=乙，比例2=0.3 |
| 客户 C001，丙，比例 0.1 | 3        | 人员3=丙，比例3=0.1 |

这三条输入对应临时结果的一行。序号超过 3 的关系没有进入这些槽位。条件聚合还会使用空字符串、零等默认值；因此，不能从“有三个位置”推导出比例完整或必然合计为 1，也不能把默认空字符串当成 NULL。

## 回接销售、逐字段回退

第二次写入以当日销售基础为主记录，先取 `Agt_Id、Cutp_Pty_Id、Inr_Seri_No、Book_Bel_Dept`，限定账簿部门为 OTC 或 OTC_HK，再去重这些选出字段。

同一份 `otc_div_temp` 在这里承担两个不同的关联角色：

| 关联角色          | 取临时结果中的哪类记录 | 怎样接回销售                                                          |
| ----------------- | ---------------------- | --------------------------------------------------------------------- |
| `ci`：合约级归属  | `Contract_Code` 非空   | `ci.Contract_Code = info.Agt_Id`                                      |
| `cpi`：客户级归属 | `client_id` 非空       | 通常连接 `info.Cutp_Pty_Id`；指定客户的部分收益凭证场景使用替代客户号 |

随后才在输出表达式里，对机构、人员、比例等字段**分别**使用 `COALESCE(ci字段, cpi字段)`。它不是先选中某一整套关系再全部照搬。SQL 还继续关联客户／合约经办人、内部合约资料及交易属性等，补充其他管理角色。

下面是说明回退方式的表达式示意，并非完整 SQL：

```sql
coalesce(ci.Inr_Org_Name_1, cpi.Inr_Org_Name_1)
coalesce(ci.Cust_Mngr_Name_1, cpi.Cust_Mngr_Name_1)
coalesce(ci.Allo_Prop_1, cpi.Allo_Prop_1)
```

示意，非真实数据：假设关联后的合约级人员为甲、比例为 0.6，机构名称为 NULL；客户级机构名称为机构乙。输出可能保留甲和 0.6，同时取机构乙。**同一组字段可以混合来源。** 如果合约级机构名称实际为 `''`，`COALESCE` 会保留空字符串，不会自动取机构乙。

这里使用的是销售 `Agt_Id`。它在适用产品中来自内部合约号，不能与模型中同样叫“合约编号”、但来自技术 ID 的字段直接按名称关联。

## 管理归属快照

最终 `SELECT DISTINCT` 后，覆盖写入 `T98_OTC_COMP_MNG_RELA_INFO` 的加工日分区。输出保留销售 `Agt_Id`、交易对手 `Pty_Id`、最多三组归属及其他管理角色；它不是一位介绍人一行。

`Busi_Date` 表示本次管理归属快照日期。候选理解入口是销售合约、交易对手和快照日，但 `DISTINCT` 只去掉完全相同的输出记录，不能证明这几个字段在所有关联后唯一。

118143 用这份归属形成参数快照，118141 用它参与收入分配；两者并行读取。107491 的计提日展开不是105743的后续步骤。若收入把历史计提金额与本次管理归属相配，还需要区分“本次归属”与“历史计提日当时的归属”。比例完整性、匹配扩行及历史适用性仍保留为证据缺口。
