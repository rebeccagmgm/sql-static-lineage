## Context

原地图是固定导出＋人工编排＋留存 SQL／知识的静态 HTML。当前实际总览为 14 节点、18 可视边；固定范围 3,615 任务、2,740 表身份、111 schema、245 方向。来源穿透和可重跑计算尚未形成通用实现。

详细方案唯一维护于：

- [具体模块、合同、算法与命令](../../../docs/processing-map/next-iteration/implementation-plan.md)

## Goals / Non-Goals

**Goals:** 保留原骨架解释力；输入、标签或范围改变后由规则重算；来源／区域／对象在主画面逐层阅读；SQL 与知识可追证据；以另一来源验证复用。

**Non-Goals:** 全库地图、通用图探索平台、G6、动态图服务、SQL 解析或因果引擎、图发布器改造、全量元数据内存加载、全部任务语义重建。

## Decisions

1. 首批消费现存固定 network，用 manifest 与精确成员重算绑定裸数组 sidecar；不重跑 ignored 的调查 exporter。
2. 结构计算、knowledge、视图定义、布局和前端分开；metadata 用已有 JSONL offset 能力提取小包。
3. 图中 datasetId 为主键；物理类型必须有元数据／DDL 依据，多标签不等于唯一全局父组。
4. 新视图使用阶段分列和确定性排序／路由，布局不写回知识或底图。
5. 第一版预计算有界视图，浏览器读快照；未知、未分类、缺少说明与未展示方向都有明确入口。
6. 原 HTML 保留，新入口并列；旧专题在匹配版本下复用，版本失配时保留有标识的历史参考或标需复核。
7. 关系保持“同任务读取—输出关联”语义，不能从旧导出补出字段因果、实际落地或批次接续。

## Risks / Trade-offs

- 234 个 Titans 对象的元数据精确匹配率未知：实施时报告实际命中与歧义；结构可读不依赖全部解释完成。
- 元数据目录可达 GB 级：单独准备／复用索引，普通 build 不扫描原始目录。
- 自动布局可能不及旧人工摆放：用实际页面截图验收阅读效果，不用逐节点坐标补丁掩盖问题。
- 任意历史版本图查询不是已有通用能力：保留固定输入包复现，不让 CLI 接受的参数成为假版本保证。
- 人工知识不足会影响解释深度：用少量真实问题完整追到证据验证价值，不用类别数量或节点规模冒充完成。

## Migration Plan

按 [tasks.md](tasks.md) 执行：输入与精确重算 → 元数据／知识 → Titans 纵向样本 → 骨架与来源细化 → odata → 第二来源迁移与回归。原入口不切换；用户验收 next 后再决定后续推广。

## Open Questions

当前没有阻止开始固定材料导入和关系重算的待决架构问题。实施中需实测元数据命中、分类依据与布局效果；这些是应交付的调查结果，不能预先填入推测值。

本环境未找到 OpenSpec CLI。文件按仓库 spec-driven 结构人工编写，未执行 OpenSpec status／validate，所有实施任务保持未完成。
