## Why

用户认可原《股衍加工地图 · 从全局到证据》的主加工骨架，但现有区域选择、布局与代表链仍经过人工编排，换数据不能直接重建同样的分析。“Titans 可见来源”点击后只有侧栏区域统计；odata 下钻则以两组案例代替整个区域的解释。之前扩展规模的尝试没有复现原骨架的阅读价值。

本次先在现有 3,615 个任务的固定材料内打通可复用方法：自动兑现分组／关系规则，以主画面逐层穿透到有依据的业务解释，随后在另一来源范围验证迁移。0、1、2、4 是全局骨架工作，只有第 3 项单独针对 odata。

## What Changes

- 导入已存在的固定图材料，建立可校验、可搬迁的输入包；从任务—表身份重算区域成员与方向集合。
- 提取视图配置、共享 knowledge 分类与解释、新的构建期计算和确定性自动布局；不为新节点写死坐标或计数。
- 保留主加工骨架、并行路线、跨层读取、交付／日志边界，支持来源主画面分析、分类成员、具体对象与消费关系穿透。
- 将 odata 首层改成区域分析，原三任务降为明确标注的加工案例，修正批次接续和“统一口径”的误读。
- 生成带图、输入、知识、视图及算法版本的离线快照和并列的 `docs/processing-map-next.html`，保留原 HTML 与既有 SQL／knowledge／本金阅读。
- 用本批另一个来源验证同模板复用；技术一致性与用户阅读价值分别验收。

## Capabilities

### New Capabilities

- `processing-map`: 有界固定材料消费、规则驱动的骨架与来源分析、共享分类、对象穿透、版本与证据适用性、离线兼容及迁移验收。

### Modified Capabilities

None. 不改 Input Pack、Machine Facts、图发布器、正式图查询语义或既有 task knowledge 合同。

## Impact

- 新逻辑位于 `scripts/processing-map/next/`，必要时抽出原 payload 构造以复用。
- 增量修改原 view.js／样式／模板和 package scripts，保持旧 DATA 兼容及已有未提交修改。
- 数据包位于配置 dataRoot 下；业务分类／解释放共享 knowledge；原始全库 JSONL 和投影不会进入 HTML。
- 本批不接 G6，不建动态服务，不重新导出或发布图，不扩十几万任务，不要求遍读全部任务 SQL。

详细范围、已核验基线与交接说明见 [实施入口](../../../docs/processing-map/next-iteration/README.md)。当前仅完成方案编写，未开始实现。
