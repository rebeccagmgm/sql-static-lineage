# OTC 语义提取工作流

独立 Node.js 24 工具，无第三方运行依赖。不导入父仓库源码，不参与图谱构建或发布；只读访问配置指定的底稿、SQLite 和已启动的图谱 HTTP 查询接口。输出和人工修改全部保存在自己的 `.local/` 中。

流程：底稿条目 → 表/字段/字典/文档/图谱证据包 → 模型抽取候选 → 程序校验 → 本地界面修改确认 → 导出语义模型。

## 当前入口：CDM 原生模型试点

本轮正式实体、属性和关系**直接选择 CDM 7.0.0 的定义**，不再沿用旧模型生成的自定义实体关系。旧通用候选仅保留历史入口；不会送入 CDM 提取上下文或进入本轮共享登记。程序对 CDM 源文件核对固定版本、提交和原始 SHA-256，保留声明位置、继承、基数和 reference 标记。这是五个选定类型的阅读与映射工具，不是完整 Rune 解析器或 CDM 实例运行时。

```powershell
npm run pilot:prepare  # 只读取现有资料、SQLite 和图谱，准备固定七组证据
npm run pilot:run      # 串行调用已配置 API；先期权，再普通互换
npm run pilot:run -- --retry-failed # 将程序检查错误交回模型纠正，已成功请求复用缓存
npm run pilot:revalidate # 仅按当前程序规则重校验已保存的无效输出，不调用 API
npm run pilot:report   # 导出 .local/pilot-report.json，含共享登记和审核统计
npm start             # 打开 /pilot；已有 ?item=... 链接继续可用
```

界面分为标准模型、合约、参与方、账户、待映射、已确认。标准定义只读；用户编辑内部字段、数据范围、映射说明和待补问题。每个实体或关系的数据对应可以独立保存草稿、退回补证或确认。所有映射目前都标记为 partial；尚未执行业务行查询或完整 CDM 实例校验。

- CDM 原生属性关系必须符合声明所属类型（允许继承）和目标类型。不能把关系中间的 Counterparty 角色节点随意省略；已有 Trade.party 等原生属性则可按本身含义评估。
- A17/A18 等内部关联找不到明确的 CDM 属性时进入 `unmappedRelations`，不能确认成自创正式关系。内部账户主键也不自动等于 CDM accountNumber。
- “内部映射已审核”和“CDM 含义对应已核对”分别保存。共享登记按 CDM 固定编号复用，不把不同产品的范围合并。已确认映射在后续步骤调用前动态读取；未确认的较早步骤只作为对照候选。
- 每次保存检查结构、字段、证据引用及范围。存在问题、缺映射或物理身份不明确时不能确认。审核采用版本检查，防止旧页面覆盖新记录；端点修改会撤回相关关系确认并记录原因。
- 取证优先标识、角色、类型、日期和分区字段；覆盖本条目最多 8 个任务，并沿图谱直接字段来源补一跳元数据。SQL 保留带行号的相关窗口；截断和 SQL/图谱快照尚未对齐会显示为缺口。
- 试点包单独采用 `pilotMaxPackChars=128000`，超限直接停止，不静默删除必要证据。它不是目标用量，累计 token 保护线仍沿用现有配置。
- 退回补证保留原因，不自动重新付费调用。补充源资料后重新 prepare 生成新证据版本；已有审核不会被新提取覆盖。任一试点条目存在尚未核清的 uncertain/inflight 请求时，即使输入版本变化也暂停该条目，需先核实该次请求。
- 用户明确授权重试某次不确定请求后，可使用 `npm run pilot:run -- --ids T03-038 --retry-uncertain`，一次只允许一个指定条目。原调用和用量预留保留，记录替代请求；纠错请求的上下文随重试保留。该选项不会使未知消费变成零消费。
- 原生属性若指向本轮未选的 CDM 类型，只有端点、证据及映射引用均合法时才隔离到只读 `rejectedCandidates`；保留原建议，不进入正式关系或人工确认。其他错误继续阻断。离线重校验记录前后输出；纠错请求及其缓存关联单独留痕。
- 本轮没有接入 Jev。后续有人工核对样本时，可另行比较候选筛选收益；现阶段继续使用已有 API。

新增接口：`GET /api/pilot` 返回试点、共享登记及统计，`POST /api/pilot/review` 保存单项审核，沿用本地来源和 CSRF 检查。原 `/api/review` 不允许批量确认 CDM 试点。新增状态表均位于工作流自己的 SQLite，不改变源库或图谱。

报告里的“直接确认 / 修改确认 / 退回”按当前版本的实体或关系映射项计数，跨产品复用按已确认的 CDM 标识计数；不是业务准确率，也不是 7000 多个任务的覆盖率。人工尚未审核时指标为零。

## 快速使用

以下命令均在本目录执行。首次使用可直接采用 `config.example.json`，或复制为已忽略的 `config.local.json` 后调整路径、模型与预算。

```powershell
# 只组包，无 API 调用；按业务分类轮换选取，默认 20 条
npm run prepare

# 也可按底稿编号或关键词选择
npm run prepare -- --ids T03-021,T03-066,IN122 --limit 3
npm run prepare -- --query 期权 --limit 20

# API 地址支持 Base URL 或完整 chat/completions 路径
# 下方是 PowerShell 临时设置方式；已配置 .env.local 时可省略
$env:SEMANTIC_API_URL = '<你的接口地址>'
$env:SEMANTIC_API_KEY = '<在本机配置，不写入仓库>'
npm run extract -- --limit 20

npm run status
npm start
# 浏览器打开控制台打印的本地地址
npm run export
npm test
```

完整命令帮助：`node src/cli.mjs help`。可给任何命令加 `--config 路径`。

持久配置使用本目录 `.env.local`，格式见 `.env.example`：每行 `变量名=值`，不使用 PowerShell 的 `$env:` 前缀。接口地址和密钥均留在本地。

`prepare --offline` 明确跳过图谱，只使用本地快照。正常模式下图谱不可用也会保留离线结果，并在每个输入包记录缺口。不会替你启动、重建或发布图谱。

## 输入与范围

- `models` 适配现有工作簿 JSON 的 `main`，`interfaces` 适配 `interfaces`。初始目录库存包含这两个来源的全部条目；实际准备哪些包由筛选决定。
- 一个包以一个业务条目为起点，保留表和范围，不把 7000 多个任务全部送给模型。相同表的元数据在组包进程内缓存；图谱详情按发布版本、元数据版本和任务缓存。
- 元数据 SQLite 读取 `current.json` 指向的快照，所有源库使用只读连接。同名表存在多个物理候选时分别保留；只匹配到一个元数据条目也不声称已核验业务身份。
- 图谱使用 `/api/status`、`/api/task`。批次开始、结束检查发布版本，版本变化则本批不保存。这里只取已有字段绑定与控制事实，没有重新计算全链血缘。
- 图谱包含写入身份；本地 SQL 摘录独立标记快照来源，尚未验证其 SQL 哈希与图谱绑定哈希一致。模型必须保留这一缺口。
- 文档依据表名定位相关章节，按匹配程度和章节长度排序。文档、字段、码值与任务均有数量/长度上限，截断会记录；按表名找到的资料不是已确认实体关系。
- 现有资料标题、术语和码值供提取参考；模型输出是候选。不会执行文档/SQL 中的指令，也不会查询业务行数据。外发内容经过凭证、连接串、地址与本机绝对路径过滤。

## Token 与续跑

默认累计保护线为 **1,000,000 token**，按同一 `.local/state.sqlite` 内所有调用累计，跨命令重启也不归零。用户可在配置中调整；保护线用于避免失控循环，不代表应该用完。

1. 调用前按消息 UTF-8 字节数、消息余量及最大输出预留预算。它是保守准入估算，不是模型的精确 tokenizer 结果。
2. 成功收到 API `usage` 后，以其 `total_tokens` 替换预留，并保存输入、输出、推理等接口实际返回的细分字段。接口未返回的细分项不猜测。
3. 超时、断流、HTTP 错误或缺少 usage 保留预留、暂停批次，不自动重试不确定请求。因此预算记录可能高于真实账单。
4. 达到预算或剩余额度不足以预留下一包就暂停。服务若不遵守输出限制，或报告用量超出预留，也立即暂停；应用预算不是服务商的账户级硬限额。
5. 缓存键包含输入、提示词版本、模型、请求参数及接口地址的哈希；密钥不入库。同一请求已完成或待核对时直接跳过。
6. 已付费但输出结构不合格的结果标为 `invalid`；确认后用 `--retry-failed` 只重试这些结果。不确定调用不会被该参数自动重试。
7. 每个输入包都有内容哈希。证据、图谱版本、模型或提示规则改变可能触发新提取；旧输入、调用和人工审核历史仍保留。当前采用保守版本失效策略，尚未做跨图谱版本的逐字段变更裁剪。

工作流同时只允许一个提取进程。异常退出后如果留下 `.local/run.lock`，先核对其中 PID 是否已退出，再删除这一个锁文件；未结束调用仍保留预算，不会被静默当成免费失败。

接口适配支持普通 JSON 和 SSE。默认使用流式请求并请求 usage，默认不强制 `response_format`；可在配置中启用 `jsonMode`。默认发送 `thinking.type=disabled`，该参数依据 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/guides/thinking_mode/)，其他供应商可从 `extraBody` 移除。本次代理实测仍返回推理内容，因此不能假定推理已关闭。单次输出上限 **32,768 token**、超时 5 分钟，均可配置；累计记录接口实际 usage。模型必须按提示返回约定 JSON，结构、证据引用、实体端点和物理字段会由程序验证。结构检查不等于业务正确，遇到无效输出会暂停整批，避免重复花费。

本地 `.env.local` 支持 `SEMANTIC_API_URL` 和 `SEMANTIC_API_KEY`。该文件已被本目录 `.gitignore` 忽略；只有提取命令读取它，网页服务不加载密钥。操作系统现有环境变量优先，不会被文件覆盖。移动模块时需自行携带本地配置，勿将密钥文件提交到 Git。

## 可视化维护

- 左侧按条目检索，默认仅显示当前输入版本，可展开历史。
- 实体页修改名称、粒度、代表属性和目录归属。
- 关系页修改起点、终点、名称与含义；数据映射页修改范围和字段对应。
- 证据页查看输入来源、字段、图谱绑定、SQL 摘录和缺口。
- “保存草稿 / 暂不采用 / 确认采用”写入工作流自己的 SQLite，保留编辑历史。不会回写原有资料或图谱。
- 跨条目合并采用人工设置相同“统一实体编号”。导出时如果同编号的定义或属性不同，会列出冲突，不静默覆盖。
- 同一输入已经人工编辑的结果优先展示和导出，后续模型调用不会自动覆盖它。输入证据改变后会出现新版本，旧审核不自动迁移。
- 接口调用由 CLI 运行。网页只能查看和编辑候选，不持有密钥，不触发付费调用。

## 代码分工与验证

`sources.mjs` 只读组包；`model.mjs` 提示与输出合同；`runner.mjs` API、续跑和导出；`state.mjs` 本地持久化；`server.mjs` 与 `web/` 提供本地维护页面。全部位于本目录，可以整体移走后修改配置路径。

`npm test` 覆盖预算准入、真实 usage 替换、不确定调用保留、缓存跳过、引用和字段校验、流式响应、分类轮换、审核持久化、同名输入重跑不覆盖人工结果，以及本地服务的来源和 CSRF 校验。测试使用模拟 API，不消耗外部额度。

## 首轮试跑记录（2026-09-18）

已索引 303 个整理条目、准备 23 个证据包；选取合约主资料、合约与账户关系、协议组关系、分成比例、ETF 参数和结算明细共 6 包实际调用。当前 5 包返回候选、1 包未提出实体；合计 15 条实体候选、9 条关系候选、23 条数据映射，尚未跨条目合并，也未人工采用。该数量不表示已完成全量 OTC 语义模型。

累计 18 次接口调用（含适配调试与重试），接口回报 293,957 token；另有 51,578 token 因早期请求未返回 usage 而保守预留，不是确认消费。相同配置再次执行这 6 包时，实测新增请求为 0。修正后的配置为 48,000 字符输入窗口、32,768 最大输出 token、1,000,000 累计保护线。

18 项自动测试通过；Edge 浏览器验证了实体修改、映射修改、草稿保存与刷新恢复、依据跳转、无效结果禁止采用、窄屏布局。浏览器写入测试使用独立临时副本，没有把试跑候选代替用户确认。
