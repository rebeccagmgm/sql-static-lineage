## 通用修复

原读取投影只传递 EQ/IN 的字面值集合，BETWEEN、上下界和函数结构被压成 NON_LITERAL_PRESENT。现在局部投影额外保留有明确读取范围的谓词树，接续层按完整布尔结构判断已知写入分区是否落入读取范围。

支持 EQ、IN、BETWEEN、GT/GTE/LT/LTE、AND；日期比较采用符号上下界，不代入今天的日期抽样。保留月份和年份偏移；支持同月月初、同年年初、内置 LAST_DAY 的月末上界。比如 `${yyyyMM}` 必定在 `[${yyyyMM,-2M}, ${yyyyMM}]` 内；`${yyyy-MM-dd}` 必定在 `[${yyyy-MM}-01, ${yyyy-MM-dd}]` 内。月初/月末存在相等可能，因此不能擅自证明严格大小关系。

只有全部相关分区条件都可证明、写分区值明确时才新增确认。不按任务、表名、字段名、标签常量特判。未知值、NULL、OR、跨 Join/UNION 后缺少读取实例绑定的过滤、交易日 UDF、字段自引用都不会因为这次扩展被放行。普通数字和字符串也不会被当成日期做大小比较。

用户随后明确：日分区只需同粒度接续，当天、前一天和前一交易日不因偏移而阻断匹配。这是项目匹配口径，不是 SQL 日期值相等。已识别的日粒度模板及有明确日粒度输入的 pretradedate/date_add/date_sub/add_months/last_day 等表达式可按此规则接续；原始表达式保留，月份分区、标签、h15/h1930 等批次值不受这条日粒度规则影响。无分区过滤的读取也可消费已知日粒度写入。字段自引用、未知函数和缺失标签值仍不能借此确认。

缓存生成器版本为 `1.3.13`，图编译器为 `1.0.16`；以后扩图会自动生成并消费这些范围证据。函数知识已存入数据目录的 `knowledge/function-catalog.sqlite`；当前规则由代码执行，SQLite 尚未作为投影运行时规则源。
