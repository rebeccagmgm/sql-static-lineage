# 缺少生产写入证据：接手范围

先读 scope.json 的基线版本和统计。范围严格限于 1088 处读取、163 个消费任务、362 张表，已排除策略终点；这是导出基线的 NO_KNOWN_WRITER 分类，不代表已经找到某个真实生产任务。

- `tables.csv`：按表汇总，优先查被多个消费者读取的表。
- `consumer-tasks.csv`、`consumer-task-ids.txt`：消费任务范围。
- `reads.csv`、`scope.json`：逐读取位置、物理表名、冻结 Evidence 和 projection 的本地路径。

接手者仅核验这些对象：先看已有 Evidence、Input Pack、Facts 和任务覆盖状态；不足时再有界查询平台生产任务。把结果分为：已有材料漏投影、生产任务漏采、解析失败、外部来源、确无可得证据。区分 SQL 实际写入与任务配置目标，调度关联不能代替写入证据。

每条交付消费任务/读取位置、表名、生产任务及真实写入（若找到）、证据路径、根因、可修复动作。403/权限阻塞记下即停。不要扩大成全域扫描，不要自行发布图；不要改当前主任务正在处理的分区解析代码。
