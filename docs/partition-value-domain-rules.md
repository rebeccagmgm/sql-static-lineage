# 分区传值的通用规则与验收

修复单位是 SQL 运算规则，不是任务、表或某个分区常量。Machine Facts 保留表达式、关系和读写实例；局部分析追踪值域；接续层比较读取与写入范围；展示层保留确定性边界。

| 运算 | 规则 | 不允许的推断 |
|---|---|---|
| 常量、直接字段与改名 | 沿唯一字段绑定传值 | 按同名字段猜来源 |
| 临时表 | 读取表达式绑定到此前明确写入，再递归分析 | 跨写入实例或倒序追值 |
| UNION | 所有分支都有完整值域后取并集 | 漏掉未知分支，或把不同已知值判冲突 |
| 外连接 | 保留侧不变，另一侧增加可能的 SQL NULL | 把 NULL 当通配符，或把全部已知值丢成 UNKNOWN |
| 确认接续 | 非 NULL 值还须有独立、明确的分支证据 | 用值域上限直接冒充确认依据 |
| 排除接续 | 读取必须足以证明两个范围不相交 | 复杂条件下只比较一个扁平字面值就排除 |

例如，某 UNION 的一个分支明确输出 `A`，其他分支经过外连接只能输出 `A` 或 NULL，则完整范围为 `A（可能含 NULL）`。读取 `A` 可找到明确的分支证据；读取其他字面值不会因为 NULL 而自动匹配。只有外连接上限、没有明确非 NULL 分支证据时，不升级为确认。

当前边界：新增的可含 NULL 值域仅应用于单分区字段；纯 NULL、多字段组合未证明、复杂表达式、来源歧义仍保留未知。未知分支不会因为其他分支已知而被忽略。

默认回归覆盖：替换表名、字段名和常量后行为不变；INNER/LEFT/RIGHT/FULL JOIN 两侧；UNION 的 NULL 与缺失分支；缺少非 NULL 分支证据；错误读写绑定；读取其他值及复杂条件；范围身份与显示。测试位于 `tests/project-graph/task-local/partition-alternatives.test.ts`，随默认 `npm test` 执行。

真实任务只用于评估覆盖面。发布前另外核验同一任务范围、逐读取确认转移、主指标与边界指标，不能用“影响多少读取”代替“实际确认多少读取”。

日粒度识别同时接受调度变量 `${data_day_str}`，适用于写分区和嵌套函数的读取参数；只识别完整变量名，不扩展到同名前缀、附加批次后缀或未知变量。原始表达式不改写。存量投影必须携带当前生成器输出的 `partitionRange` 才能消费读取范围规则；更新接续编译器并不自动补齐旧投影。

读取范围也必须保留运算结构：局部投影的 `partitionRange` 保留有明确读取范围的谓词树，接续层按项目匹配口径比较分区。用户明确日分区按同粒度接续，当天、前一天、前一交易日不因偏移阻断；这不声称日期值相等。日粒度函数仅识别有明确日粒度输入的已知函数组合，表达式原样保留。其他分区仍比较 EQ/IN、BETWEEN、上下界及 AND，保留偏移和严格边界。跨 Join/UNION 后缺少读取实例绑定、字段自引用、未知写分区、OR 和可能含 NULL 的写入不通过此扩展。详见 [331 个读取范围修复与验收](material-gap-exports/no-known-writer-20260910/partition-analysis-20260911.md)。函数文档与用户口径分别存入 SQLite，当前由代码执行规则，不直接加载数据库中的任意资料为规则。
