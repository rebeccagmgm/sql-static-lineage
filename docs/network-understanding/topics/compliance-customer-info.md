# 合规客户资料：机构、产品和关联人员怎样连接

机构客户、产品客户、管理人和自然人角色是不同对象。一只产品可以有管理机构、法人、实际控制人和授权办理人；将这些字段组织在一行，并不意味着他们使用同一个身份编号，也不保证各来源都只有一条记录。

本页解释 177390、178833、219085 的主要来源分支、身份与日期差异。目标包括 `dm_cmpl_n.unit_cust_info` 与 `dm_cmpl_n.pdt_cust_info_all`。多个任务写同一目标的事实不等于已经证明执行时互不覆盖，具体写入与分区契约仍需核实。

<a id="compliance-customer-identities"></a>

## 身份关联决定哪些人能进入一行

股衍机构/产品的入口按主体 `Pty_Id` 连接客户基本资料，再用受益所有人模型的角色码补充人员。产品接口对角色 `'6'` 的授权办理人按证件生效日期**升序**取第一条；这不是“取最新授权人”。角色 `'5'`、`'8'` 等关联没有在相同位置统一去重，多条来源记录可能把一条客户展开成多条。

托管分支先把 ECR 客户映射到组合，再连接 MOT 管理人，最终关联条件是机构代码相符 **或客户名称相同**。输出客户号取 MOT 编号去掉前缀，名称可以回退 ECR。名称关联可能产生多匹配；没有匹配时也可能保留客户名而客户号为空，不能把有名称当成身份已统一。

托管人员先按角色组织：已有角色 `'5'/'6'/'8'`，另外把没有同客户同名角色 `'8'` 的角色 `'9'` 补成 `'8'`；随后按客户分组，以各字段的 `MAX` 填入角色字段。多个同角色人员存在时，字段分别取最大值不保证姓名、证件号和日期来自同一个人。这个风险来自聚合方式，是否实际发生需查看对应资料的唯一性。

来源：178833 `query` 142–162；219085 `query` 457–488、535–594。基础对象背景见[主体与客户](party-and-customer.md)。

<a id="compliance-customer-labels"></a>

## 跨境、存续和协议标签不是独立证明

177390 的跨境标签从参数日合约与结构中推导，再按交易对手映射后的客户号取最大标志。期权侧含 `OPTION_ISDA` 或跨币种结构条件；互换侧结合账簿部门、排除内部互换、币种及指定跨境类型判断。这里只把源码条件组织成客户属性，不等于确认实际发生了某笔跨境资金交易。

更容易遗漏的是关系日期：177390 的客户映射使用 `strt_date < 参数日 <= end_date`；178833 对应股衍产品分支使用 `strt_date <= 参数日 < end_date`。假设某关系从 9 月 1 日开始、旧关系也在该日结束，两种写法会在当天选择不同版本。同一天两份接口出现不同客户映射，不能直接归因于数据迟到。

股衍机构分支把 `Montr_Flag='1'` 转为“是否存续”，把协议类型文本包含 `SAC` 转为“是否签订 SAC”，并把“是否现金交易”写为常量 `'0'`。固收 OOM 分支使用 `aml_monitor_flag='true'` 与 `protocol_type` 的相应文本条件。这些都应按来源字段解释，不能把标签名扩展成独立核验结论。ECR 直接来源中不少相同标签为空，空值也不能统一解释为“否”。

来源：177390 `query` 415–434、517–576；178833 `query` 263–269、316–326；219085 `query` 135–153、227–245。

<a id="compliance-customer-fields"></a>

## 比较同名字段前先看实际赋值

- 股衍及投行部分注册资本输出使用源值乘 10,000；ECR 直接资料与托管所示分支未使用同一个乘法。直接比较数值前需要核对源字段单位。
- 投行分支 `tax_register` 实际引用所关联记录的 `Pty_Cate_Cd`，而非从目标字段名就能判断的税务登记号码。证件类型和部分业务建立日期也可能为空。
- 托管分支的企业性质中文、行业名称分别沿用对应源代码字段，没有在这些赋值位置翻译成中文；证件号按统一社会信用代码、组织机构代码、营业执照顺序择一。
- 某些证件到期日缺失回退 `'99991231'`。这只是接口替代值，不能作为证件经核实永久有效的证明。

来源：177390 `query` 78–110、339–355；178833 `query` 63–84、273–294；219085 `query` 371–405、541–583。

改变角色资料、客户类型、映射关系有效期或源字段单位，会同时影响客户身份、接口行数、合规属性及后续统计。先确认这些公共基础，再与合约交易记录核对，能避免把粒度、字段映射或日期差异误判成交易遗漏。
