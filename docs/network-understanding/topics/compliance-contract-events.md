# 合约如何成为合规交易记录

`dm_cmpl_n.aml_comp_trd_info` 使用交易接口的通用字段，承载期权及互换合约的建立、部分终止和最终终止。这里的“成交金额”可能来自名义本金，“成交数量”可能由名义本金除以价格计算，而不是从一条实际证券成交直接复制。

三个任务分别写分组 `01`、`02`、`03`：176599 为单标的期权，176600 为多标的期权，176610 为互换。建表语句只按 `grp_id` 分区，不能再凭源数据的业务日期假定目标是每日独立分区。任务的覆盖或追加方式还要看实际执行配置，本页不以建表语句代替它。

<a id="compliance-option-events"></a>

## 单标的期权：一份当前合约信息展开为三类历史记录

单标的输入是参数日的 `T98_SB_OTC_OPT_COMP_INFO`，限定指定期权来源、`Comp_Stat_Cd != '218'`、部门为 `OTC/GFS_FICC`，且起始定价日不早于 `2022-01-01`。它必须关联参数日、`Bask_Type IS NULL` 的结构信息。状态排除并不等于只保留所有意义上的有效合约。

| 分支     | 发生日期                         | 数量与金额                                                                                     | 其他条件                                                                                              |
| -------- | -------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 建立     | 起始定价日；成交日期另取下单日期 | 数量为初始名义本金 ÷ 经汇率因子调整的初始确认价格；金额为初始名义本金                          | 方向常量 `'1'`                                                                                        |
| 部分终止 | 生命周期事件日                   | 数量为名义本金变动额 ÷ 调整后的初始确认价格；价格另取提前终止价格；金额为名义本金变动额        | 事件类型 `PARTIAL_TERMINATION`、状态 `'3'`、审批结束时间非空、事件日期不早于 `2022-01-01`；方向 `'2'` |
| 最终终止 | 提前终止日优先，否则结束定价日   | 金额为计算出的剩余名义本金，缺失则回退初始本金；数量仍以初始确认价格换算，价格取终止日确认价格 | 终止日期不晚于参数日；方向 `'2'`                                                                      |

剩余本金的子查询把部分终止事件按调整前后本金大小赋正负号，按事件日期累计，取日期倒序第一条；它比外层排除更多状态。该子查询的事件筛选只有起始下限，没有额外的“事件日 ≤ 参数日”条件。是否会读到未来事件，取决于源表实际包含什么，不能替 SQL 补上日期限制。同日多个事件的排序也没有唯一事件号作为第二排序键。

价格为零时，数量计算的分母改成 NULL；汇率缺失时特定分支回退 1。因此缺失价格可能产生空数量，缺失汇率却可能产生看似正常的数值。后者并不证明汇率无影响。数量保留六位小数，剩余本金计算中涉及两位小数舍入。

举例：假设初始名义本金为 100 万元、初始价格为 100、汇率因子为 1，建立记录的数量为 10,000。之后部分终止名义本金 20 万元，记录数量为 2,000，即使提前终止价格为 110，接口金额仍取 20 万元，而不是数量乘价格得到的 22 万元。这个例子说明字段的构造差异，不是实际资金收付案例。

来源：176599 `query` 62–237、239–375、423–434、475–483、540–621。

<a id="compliance-basket-events"></a>

## 多标的期权：先展开成分，再决定如何分配

多标的把结构条件改成 `Bask_Type IS NOT NULL`，通过篮子成分连接证券资料与确认价格，保留同样的建立、部分终止、终止三类分支。此时粒度向“合约事件 × 成分标的”展开，不能再把每行都视为一份完整合约。

- `BEST_OF/WORST_OF` 使用成分调整后初始价格的平均值计算数量，并按参与聚合的行数分配名义本金。代码的计数是 `COUNT(1)`，不是明确的去重证券数；关联重复会影响分母。
- 其他篮子按 `bask_compnt_prop` 分配名义本金，再除以成分价格计算数量。比例缺失回退 1，没有在此统一归一化，也没有在此证明比例和为 1。
- 建立、部分终止、终止的金额公式并不完全一致：建立和终止分支在分配后还乘汇率因子，部分终止金额分支没有同一层乘法。
- 终止分支虽然关联了终止日价格 `QR1`，输出 `BUSINESS_PRICE` 仍引用初始价格 `QR`。这与单标的终止分支不同，应按代码现状解释，不能仅凭命名改写为终止价。

例如，两成分篮子如果两条比例都缺失，普通分支可能把整份本金各分配一次。这里指出的是 SQL 在该输入下的结果；本次没有证明真实比例数据存在这种缺失。

来源：176600 `query` 1–30、146–160、333–344、523–540、659–661。

<a id="compliance-swap-events"></a>

## 互换：数量与价格来自持仓或事件明细

互换使用参数日的合约宽表与账簿资料，限定部门 `OTC/GFS_FICC`、合约状态不为 `'218'`、起始定价日不早于 `2022-01-01`。结构腿、历史持仓、登记事件与证券资料共同提供标的和数量。

建立分支取持仓 `Vol/Bgng_Pric`，金额为二者乘积；部分平仓读取状态 `'3'` 的 `CLOSE_STOCKS` 事件，以事件来源标识连接变动明细，再按持仓编号关联，取 `Occu_Qty/Pric`；终止分支取 `End_Vol/End_Pric`，发生日期优先实际结算日，否则结束定价日，并要求该日期不晚于参数日。互换的“成交金额”因此又是一套算法。

这里有一个重要的取数边界：`trs_pos` 先在每份合约下选择不晚于终止/结算日期的最大持仓日期，再由各分支要求这个日期等于起始日、部分平仓日或终止日。它不是为每一个事件日独立取一份历史持仓。若选出的日期不等于某分支事件日，左关联可能保留记录而数量、价格为空。查询中算出的 `TER_HAND` 也不等于最终使用的 `BUSINESS_AMOUNT`，后者在终止分支直接取 `End_Vol`。

来源：176610 `query` 1–68、187–201、246–293、349–351、426–456、522–524、603、634。

## 三类记录共用的身份与字段陷阱

客户号由交易对手经 `T01_PTY_RELA_H` 映射到 `Rela_Pty_Id`，交易接口使用 `strt_date < 参数日` 且 `end_date >= 参数日`。关系生效当天是否纳入，必须与客户资料接口逐一比较。

名为 `FUND_ACCOUNT` 的输出在这里来自 `Ast_Acct_Bnk_Name`，不能仅因目标字段叫资金账号，就据此断言它是可连接余额明细的账户主键。`OPTION_NAME` 在期权分支装内部订单号，在互换分支装内部合约号；订单流水、设备、委托渠道等许多字段直接为空。`BUSINESS_FLAG` 来自当前合约状态，未必代表历史事件发生时的状态。账户余额则按分支事件日期关联期初余额。

因此，对账至少要对齐合约/标的粒度、建立或终止分支、身份有效期、价格时点、币种和字段定义。改变篮子成分、交易对手关系、当前合约状态或历史确认价格，都可能改变重新生成的历史接口记录。

本页解释以上关键规则，尚未完成全部接口字段、实际唯一性和执行配置的逐项验收。SQL 返回相同名称不证明身份相同；SQL 形成记录也不证明报送完成。
