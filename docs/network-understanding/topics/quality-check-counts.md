# 数量检查：比较集合的基数，不等于逐行核对

[质量检查总览](quality-check-families.md) · [逐任务证据](../evidence/quality-review.json)

本页覆盖241项数量关系、7项直接数量差和10项存在性/原始计数规则。它们回答“按这段SQL构造出来的集合有多少行”，而不是自动证明两边业务对象和金额逐行相等。

<a id="quality-count-comparison"></a>

## 两侧计数：0行是否允许，要读外层CASE

常见返回规则有三种：

| 条件                                                           | 返回                                  | 空集合的含义                       |
| -------------------------------------------------------------- | ------------------------------------- | ---------------------------------- |
| `t1.cnt=t2.cnt`                                                | 相等1，否则0                          | 两边都为0也会返回1                 |
| 先判断 `t1.cnt=0`，再判断相等；或 `t1.cnt<>t2.cnt OR t1.cnt=0` | 空模型或不等0，其余1                  | 明确要求模型有行；两边都空返回0    |
| 112150 再加 `t1.cnt1=0`                                        | 总数不等、总数为0或当日行数为0均返回0 | 总数相等还不够，模型中需有当日记录 |

例如126848要求有效主体关系数非零且等于当日来源映射数；128389是同类对象的相等检查，却没有非空分支。前者不是后者的同义副本。112149取当日模型持仓数，112150则数指定来源的模型全表，并额外求当日行数。账本按每份查询分别记录。

这类查询多数把两个无分组聚合结果连接起来；有的显式 `ON 1=1`，有的只有 `JOIN`。本文解释其预期的两项计数关系，不把当前执行方言是否接受省略连接条件视作已验证。

### “同一天”不只有一种日期

模型侧可能限定 `busi_date=D`、有效期 `strt_date<=D AND end_date>D`、`del_flag='0'`，也可能只限定 `src_tbl`。来源侧可能检查采集分区 `BUSI_DATE`，又加 `SRC_BUSI_DATE`、估值日、报告日、生成日或 `AS_OF`。两种日期不能互换。

| 例子                   | 集合构造上的实际差异                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| 111945、112149、122089 | 来源分别再限定生成日、源业务日、记录日为计算日                                                                |
| 112349/112350          | 压测来源同时限定采集日期及 `AS_OF`，且模型非空                                                                |
| 158225、161097、209914 | 模型取最近15日下界；来源取当日分区中源业务日期最近15日的记录                                                  |
| 137658                 | 从当日更新记录提取一组报告日期，再按这组日期选择模型和来源；不是简单只比当天业务日期                          |
| 196798                 | 模型当日；客户基础来源使用 `default.pretradedate(date_sub(D,-1),1)` 和7种指定来源，交易日函数展开未在本次执行 |
| 205564                 | 当月宽表去重客户数；标签表取截至指定月份的全部行数。月末含本月，非月末截至上月；不是当月标签客户去重数        |

表名、模型 `src_tbl` 标签和实际读取表也不一定同名。172490等读取PB表的 `grp_id='h15'`，模型仍保留普通表的来源标签；209915又同时限定源业务日期；211232亦读取PB期权源。220912实际计数 `D_CAPITAL_DAILY_ACTUAL_BALANCE_P` 的 `busi_date='h21'`，226280读取账户P表的 `busi_date='h1930'`。这些值必须作为原SQL中的分区值保留，不能替换成推测的业务日期。

### 不是所有源行都预期生成一行模型

| 任务           | SQL写下的预期基数                                                |
| -------------- | ---------------------------------------------------------------- |
| 126880、128357 | 协议关系数 = 当日互换源行数 × 2                                  |
| 128360、226280 | 协议主体关系数 = 账户源行数 × 2；两个任务来源分区范围不同        |
| 128517         | 协议统计信息数 = 当日簿记源行数 × 3                              |
| 141786         | 协议分类数 = SBL与TRS关联后的行数 × 2                            |
| 160870         | 重要联系人模型数 = 客户扩展参数数 × 2，且模型不得为空            |
| 122047         | 同一客户源查询 `UNION ALL` 两次，相当于该选择范围的两倍          |
| 122050         | 客户源查询两次，再 `UNION ALL` 客户扩展参数；不能简化成统一两倍  |
| 186244         | 部门名称 DISTINCT 行与公司名称 DISTINCT 行做 `UNION ALL` 后计数  |
| 204007         | `COUNT(DISTINCT DEPARTMENT)+COUNT(DISTINCT COMPANY)`，且模型非空 |
| 192332         | 比较来源 `COUNT(DISTINCT KEY_TRADE_ID)`，模型不得为空            |

186244与204007都保留“部门”和“公司”两个角色集合中的重叠名称，不能当成两集合整体去重。两者对NULL也不同：`SELECT DISTINCT`可能保留一条NULL再被外层COUNT计数，`COUNT(DISTINCT column)`通常不计NULL。数量预期来自这些表达式，不能把它们推广成已证明的业务一对多关系。

### 关联后再计数：连接基数也被包含在检查里

部分任务复现了加工的连接和过滤，而不是直接数贴源表：

- 111912将净值累计与TRS、期权主表左连接；111935/111937用产品关联交易再关联期权。没有额外去重，关联侧一对多会进入计数。
- 111932/111934、121975/121977将余额关联账户主表，并要求账户键非空；未找到主账户的来源行不进入预期数量。账户主表没有相同的当日分区条件，需保留这个范围差异。
- 121815/121820、121969/121970、121972/121973、137896、141782将行权价、票息、敲入/敲出观察日、确认价、退费比例与当日期权主表内连接。这里数的是被主表接收的关联行。
- 137424/137426/137427把基础/点差比例经内部合约号连到交易、互换、期权或极速确认号；137532进一步连主部门人员与离职人员的 `UNION ALL`，137556使用清算日期转换参与交易连接。它们检验的是这种连接后的行数，不能从计数相等单独证明销售归属、费率或结算金额准确。
- 145207/187755将合约标的关系通过协议统计类型 `09` 的内容字段映射到有效协议，再接当日互换主表；两任务分别选择普通TRS与FAST_TRS来源。不能只凭来源名称认作直接一行对一行。
- 185826先把簿记映射规则连接到簿记映射主记录；186235使用 `EXISTS` 只纳入指定产品族的Vega指标；193123用业务日期及合约号排除另一个极速来源已有的行。
- FAST_TRS系列如183562、186879、188671–188675、188711、188730排除 `LONG_SHORT_SWAP`；有的再限定持仓类型或组合编号非空。被排除业务不能因模型计数相等而视为已经检查。

`EXISTS`不会因匹配到多条字典/产品记录而复制当前行；普通JOIN会。即使两侧数量相等，少一条、重复另一条仍可能相互抵销。需要逐键或字段核对时，应看[模型内容比较](quality-check-business.md#quality-full-comparison)，而不是提升本页结论。

## 直接数量差：返回的是模型数减来源数

209812、209818、209821、209828、211234、220863、242504返回 `t1.cnt-t2.cnt AS result_value`。0表示计数相等，正值表示模型侧更多，负值表示来源侧更多；该SQL没有替平台定义阈值和最终成功状态。

它们分别涉及付款计划、合约文件、观察日票息、初始保证金、标的出借、外汇敞口、功能菜单映射。209821/209828/211234模型侧也限当日；其余模型侧按来源选全表，来源侧均取当日分区。来源列表不同不能省略。两边都空同样返回0。

## 存在性、必要分组和原始计数

| 任务           | SQL实际返回                                         | 覆盖范围与限制                                                    |
| -------------- | --------------------------------------------------- | ----------------------------------------------------------------- |
| 64401          | 当日分区、当日报告日且 `rule_id='23'` 的 `COUNT(1)` | 返回原始数量，没有SQL内的通过阈值                                 |
| 168857         | 当日常速TRS表计数为0时返回一行 `cnt=0`，否则空集    | 空集在这里意味着没有发现“空表”情况；不同于198209                  |
| 198209         | 表有行则返回一行常量1，否则空集                     | 没有日期条件，不能证明当天数据及时到达                            |
| 215299、218359 | 当日期权/互换交易明细有行1，否则0                   | 只要求至少一行，不验证全量到达                                    |
| 142877         | 计算日内8项有效的组合类别/数据来源条件全部有行才为1 | 组02、03、06和5项指定来源条件；组08条件被注释，实际不要求该类到达 |
| 183485         | 当日票据明细组01、02、03均有行才为1                 | 任一组缺失返回0                                                   |
| 183489         | 当日回购明细GF1或TITANS任一来源有行即为1            | 是OR，不要求两个来源同时到达                                      |
| 223331、223336 | 指定表 `busi_date='h22'` 的原始行数                 | 名称中的“固定值”没有在SQL里给出目标值；需要平台配置解释           |

没有读到平台期望值、比较运算和执行日志的地方，本文明确停留在返回值含义。原始SQL有行、平台显示完成、业务数据已经可用是三个不同结论。
