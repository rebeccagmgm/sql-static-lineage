# 码表、系数与配置：业务结果背后的公共规则

公共参考数据至少承担三种不同责任：码表解释值的含义，业务参数给消费计算提供输入，流程/指标/菜单配置描述应用如何组织信息。它们都会影响结果，但存了一条配置不等于该规则已实际执行。

本页覆盖当前 `EDW_COD` 的 14 项任务，连接它们与已经解释的经营、权限、合规和估值过程。来源以固定发布 SQL 为准；其中字面日期与占位符混合存在，不据某份展开文本推断所有任务的运行日期策略。

<a id="reference-dictionary"></a>
## 码表：代码值必须带上字典身份

142305 以 `REF_DW_CD_LIST` 的字典定义连接 TIT 字典明细，要求编码方式为源系统字典、来源表匹配，按字典名称连接；排除表示抬头的 `'!'` 和失效时间非空的字典项。第一段是左关联，字典定义存在而没有合格明细时仍可能出现空码值记录。

随后它另外追加 `Exchange` 字典到 `CD082`。两段分别 `DISTINCT` 不保证合并后互不重复。`CD082` 的中文标签为“源交易类别代码”，实际这段来源却是 `Exchange`；理解一个码值必须同时检查定义、来源和使用方。

这里可解释为什么 `'1'` 不是一个通用业务含义：必须保留字典编号、代码值及必要来源条件。客户状态、市场类型和删除标志都可能使用同样的字符串，在各自字典中含义不同。实际消费者已包括客户宽表、合约销售资料和合规交易接口；例如合规页用 `CD035` 解释币种、用 `CD082` 补充市场名称。

来源：142305 `query` 1–51；消费关系见当前任务目录中的确认读取记录，具体合规字段见[合规交易记录](compliance-contract-events.md)。

<a id="reference-dictionary-history"></a>
## 码表历史：备注参与身份，来源不直接参与匹配键

212728 将当前 `REF_DW_CD_VAL` 与历史有效记录比较，匹配键为 `Dw_Cd_Id + Dw_Cd_Val + Remark`，并将 NULL 当作空串。字典中文名、取值描述、编码方式、维护人、来源和源表是变更比较字段。

这有两个具体含义。改变备注可能使记录被识别为另一条身份，而不只是同一记录的属性更新；相同字典号、码值、备注却来自多条来源时，源表本身不在关联键中，需核实是否出现多匹配。它也没有按业务日过滤当前码表输入，而是记录整个当前码表状态的历史。

例如，代码 `A` 的描述由“甲类”改成“乙类”，新旧区间可以保留两个解释；但历史报表如果每次都连接当前码表，仍会把旧记录显示成新描述。历史存在不等于消费者已经按历史日期使用它。本发布目录未找到该历史表的确认外部读取记录，这只是当前图的证据边界。

来源：212728 `create` 27–70、`query` 中的历史维护分支。

## 合约系数：先绑定合约，再区分内部、交叉和香港口径

133052、133054、133055 从合约内部编号连接 TIT 交易主表，再依次识别互换、期权和快收确认信息。互换和期权使用交易主键，修饰符分别为 `20206/20207`；快收分支使用确认编号与 `20206-KST`。未识别成功时输出空编号/修饰符，没有在此自动消除记录。关联优先级、未匹配值与来源日期会影响后续系数是否能找到合约。

| 参数来源 | 输出含义 | 本段没有做的事 |
|---|---|---|
| 133052，价差系数 | 源年化价差、绝对价差、生效日和计算类型，内部/交叉类型沿用源值 | 不在此计算销售收入，不按生效日独立选出唯一当前有效系数 |
| 133054，内部基础系数 | 类型常量 `INR`，基础收益取 `BASE_EARNING_RATE`，保留拟定基础系数 | 额外奖励字段为空 |
| 133055，交叉基础系数 | 类型常量 `CROSS`，同名基础收益字段取 `BASE_AWARD_RATE`，保留额外奖励标志和金额 | 拟定基础系数为空 |
| 224028，香港佣金 | 类型 `CROSS`、部门 `OTC_HK`，费率进入 `Cms_Fee_Rate`；另识别外汇远期及快速互换 | 年化/绝对价差和生效日期为空，不能套用境内价差公式 |

这些参数来源均保留或转换源删除标志；看到一行参数不等于它仍有效。上面的同名“基础收益”来自不同源字段，也不能仅凭目标列名将内部和交叉口径合并。

133052 还从参数临时资料中按六个业务属性分组，取更新时间倒序第一条，补入审批事件、客户及拟稿人。246739 则读取模板指定的未删除参数，按相同六属性取最新，再排除正式价差表已经存在的组合，形成补充参数。

六属性为合约编号、内部/交叉类型、合约类型、计算方式、年化系数和绝对系数。判断“正式已经存在”的条件使用普通等号；涉及 NULL 时，不能视同 NULL 安全相等。它按更新时间择一，也不等于按生效日期或审批通过时间择一。审批事件编号只建立关联，不证明审批通过。

当前图中，113993、114013、118141、118143 等经营加工确认读取这两类系数表。因此变更编号映射、参数优先级或去重条件，可能改变销售参数及日报；金额如何使用系数，继续读[经营分析与客户服务](../chapters/08-operations-and-customers.md)。

来源：133052 `query` 1–72；133054/133055 各 `query` 1–42；224028 `query` 1–49；246739 `query` 1–86。

## 流程、指标和菜单配置各自描述什么

128577 与 210337 都写流程定义，保留流程定义号、BPMN 编号、名称和业务模块，并排除源禁用标志。前者读取日表，后者读取 `_P` 表的 `h15` 批次；二者写同一来源分区标签。批次区别没有变成目标中的独立日期或批次字段，不能仅按输出标签认定两个来源相同，也不能在缺少执行顺序时推断谁的结果最终留下。

173967、173971、173973 将估值报告配置拆成指标基本定义、父子关系历史和附加配置。基本定义中的业务描述、单位及很多计算属性为空；附加配置保留脚本类型、脚本内容、元素类型和处理器代码。保存脚本文本不证明已执行它，也不证明其输出值正确。

173971 的父子关系意图是以指标和关系类型为键保存父指标变化，但当前 `query` 文本在读取中间表之前先删除了临时表，而 `create` 槽位才包含构造步骤。按通常先 create 后 query 的次序存在执行疑点；本页不替实际执行器假定额外的重建步骤，账本将其保留为待核。

177760 保存菜单名称、展示编号、层级及父展示编号；其 `Menu_Id` 由 `TIT288-` 加源 `MENU_ID` 构造。242349 的功能菜单映射却把源 `MENU_NUMBER` 写进名为 `Menu_Id` 的列，两者不属于相同编码域。已有权限消费者 207529 会使用功能菜单映射，关联应以该消费者的实际字段为准，不能简单连接两个同名 `Menu_Id`。

来源：128577/210337 `query`；173967/173973 `query`；173971 `create` 15–47、`query` 34–92；177760 `query` 3–29；242349 `query` 5–16。权限结果见[跨系统人员角色与权限](cross-system-user-roles.md)。

## 阅读公共参数时的三个判断

先判断这是对象身份、字典说明、计算输入还是应用配置；再核实键、来源、有效期、删除状态和缺省值；最后沿实际消费者确认它怎样影响结果。这样才能区分“代码解释变了”“参加计算的参数变了”和“实际计算结果变了”。

本页解释上述 14 项的关键合同和边界，没有执行计算、验证参数业务正确性或确认实际部署顺序。全部来源及读取行段见[公共基础审阅记录](../evidence/public-foundation-review.json)。
