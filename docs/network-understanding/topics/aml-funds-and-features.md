# AML 资金与评级基础：资产、发生额和行为特征怎样连接

这条链把客户身份接到资产、资金流水、交割记录和委托记录，再生成用于后续评级的基础特征。基础特征回答“纳入了多少资产、发生了多少交易、某个行为偏离多大”，并不直接等于最终风险等级。

<a id="aml-assets"></a>

## 资产先选择一个客户表示，再带入金额

78396 从 `aml_client` 按内部客户号关联前一日客户资产，生成 `aml_total_asset`。所读文本输出日期为 `20260522`，资产来源日期为 `2026-05-21`。总资产、净资产先转为整数，关联不到则填零，因此零值不能直接当成已经核实“没有资产”。

同一内部客户号有多个客户记录时，按客户状态、开户日期与排序编号选择一条。输出的外部客户号是该规则选出的代表，不等于内部客户号只对应一个业务客户。这里还把港币、美元资产写为零，本币资产沿用总资产，不能据此解释真实币种构成。

<a id="aml-monthly-flows"></a>

## 月度宽表中的 31 个金额格子

78493 和 78554 都把当天金额放进相应日序号列，再带入本月既有记录，清零旧记录的当天列，按客户与业务标志汇总。读者可以把它理解为：每行有 31 个日金额格子，当天重算其中一格，再合成月内结果；结果本身仍按当前处理日分区保存。

| 比较项             | 资金流水月表：78493                        | 交割月表：78554                |
| ------------------ | ------------------------------------------ | ------------------------------ |
| 日输入             | 当日资金流水                               | 普通交割与场外产品交割         |
| 业务标志           | 左关联允许标志，未知标志仍以 `-1` 保留     | 内关联纳入标志，未匹配记录排除 |
| 金额方向           | 取绝对值；备注包含“失败”时转为负值         | 取交割金额绝对值               |
| 所读文本的币种因子 | 各分支均为 `1`                             | 各分支均为 `1`                 |
| 客户关联           | 按营业部与客户号连接四类客户资料的合并结果 | 同左                           |

所以，同一客户的两张月表金额不同，不必先认定丢数：它们的纳入范围和符号规则本就不同。若客户合并结果不是营业部与客户号唯一，关联还可能放大行数。

两份查询使用共享中间表追加数据，但查询片段中没有清空该表；同时读取当月多个既有分区。如果上游清理和分区保留合同未落实，可能重复带入历史。现有材料没有证明这种情况实际发生，也没有证明片段可独立重跑。需要执行包装与分区保留证据，才能确认幂等性。

<a id="aml-rating-features"></a>

## 评级基础表具体装了什么

79856 组织以下基础指标。这里的编号是该 SQL 的指标定义，不能跨版本或跨系统直接套用。

| 指标   | 实际计算对象与口径                                                                           | 解释边界                                                           |
| ------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `2001` | 所选客户资产的总资产                                                                         | 继承整数转换、缺失填零及代表客户选择                               |
| `2002` | 港币资产加美元资产，再按文本中的因子换算                                                     | 若仅由上面的资产任务供数，两项已被填零，不能解释为经核验的外币敞口 |
| `3001` | 特定委托属性且价格、成交量额为正的记录，计算委托价相对收盘价的绝对偏离，取内部客户号下最大值 | 是最大偏离，不是平均偏离；受价格与记录筛选影响                     |
| `3002` | 指定资金业务标志在给定日期窗口内的日金额合计                                                 | 依赖月度 31 列重建日期及资金流水口径                               |
| `3003` | 指定交割标志在给定窗口内的日金额合计                                                         | 与资金不同；此段使用追加写入，需要清理合同判断重跑效果             |
| `3004` | 较短窗口内，指定外币资金标志的绝对金额，经汇率比值换算后汇总                                 | 汇率空值和零值处理不同，不能笼统视为都按 `1` 换算                  |
| `3005` | 与上一类筛选相应的记录条数                                                                   | 不是去重客户数，也没有按唯一事件编号去重                           |

所读文本中，较长窗口从 `20251123 + 1` 到 `20260522`，较短窗口为 `(20260422, 20260522]`。这些是具体快照中的边界，不足以证明调度每天如何推导参数。格式化为三位小数也不能补回上游已经截掉的精度。

## 固收频繁交易与大额资金候选

157884 从衍生品交易事件汇总中选择指定日的事件类型 `1`，再按客户名称关联交易对手资料，排除指定行业并要求客户资格复核条件成立。按证件编号与名称分组，计数达到五条便生成 `81215` 候选。这里是关联后记录数，并未按唯一交易号去重；名称关联重复可能影响计数。输出还按客户号倒序选择一个客户表示，并带有固定占位字段。

157885 的 `81216` 有两条候选规则：事件类型 `4`、正向金额，单笔严格大于五千万元；或交易日期从基准日前 30 天到基准日、两端都包含的窗口内，合计严格大于八千万元。这个窗口包含 31 个自然日期，不能直接称为“当月”；正向金额累计也不等于净流量。

一个客户可能同时满足两条规则，但后续行号按证件编号与名称分组，没有把规则类型纳入分组，最终取一条可能丢掉另一类候选。候选结果中的总资产零值和其他常量是输出填充值，不能反推真实客户状况。以上是当前 SQL 中的筛选规则，不是对客户违法、最终评级或已发告警的判断。
