# 业务检查与例外：先验证规则有检出能力

[质量检查总览](quality-check-families.md) · [逐任务证据](../evidence/quality-review.json)

本页覆盖37项：外键8项、条件非空4项、比例1项、汇率1项、模型逐字段比较1项、明确的比较逻辑矛盾2项、业务日期存在性3项和波动规则17项。这里解释发布SQL的实际含义，没有执行或修复源SQL。

## 外键：只检查明确列出的那一端

58208检查主体关系表 `PTY_ID` 是否存在于主体主表，并没有同时检查 `RELA_PTY_ID`；65463检查当日个人表的主体编号。两者都是 `NOT EXISTS`，发现缺失返回0，否则1。键比较使用TRIM，但NULL键仍不能用普通等号匹配，因而会落入缺失集合。

64637只检查计算日有效的主体分类关系，并排除指定来源及三个对象标识；65281检查用户角色关系中的用户是否在用户主表，但排除多种来源和一组指定用户。本文保留“存在这些豁免”的事实，不复制个人标识，也不声称豁免对象已经补齐。242511检查系统功能的系统编号是否在系统信息表，不检查每项菜单映射是否授权正确。

174345返回当日持仓腿在 `pdata_nds.ref_trs_leg` 中不存在的腿编号明细，结果按腿去重；并未限定被关联腿主表的日期。154360/154363两份发布文本相同：从最近15日下界的OTC互换损益汇总中，先按合约与日期内连接持仓、排除5种状态，再按日期和内部合约号左连接交易标的信息，输出右侧日期为空的缺失明细。原SQL关于“结构化腿”的注释不能扩大为显式腿类型过滤，因为那段连接已被注释。

这种完整性只能覆盖内连接后仍存在的左侧对象：没有持仓而在前一步消失的合约，不会由154360/154363报告。返回明细不等于给出了平台通过标志。

## 比例合计：两位精度下合为1，不等于每列有效

152678在当日 `DM_OTC_N.OTC_SALE_DAILY_RPT` 中查：

```sql
cast(allo_prop_1 + allo_prop_2 + allo_prop_3 as decimal(10,2)) <> 1
```

最多返回一条异常明细，正常为空集。它没有分别限制每一列非空、非负或不大于1，也没有比较分配后金额与分配前金额。正负值抵销仍可能合计为1；任一NULL可能使合计比较为未知而漏出异常集合；转为两位小数会丢失更细精度差异。因此不能称作完整的分配比例或金额守恒校验。

## 汇率：异常过滤之后，返回列只会是0

144585对 `pdata_news_n.t02_fxr_cfets_quot` 取 `src_id IN ('MD','TL')`、`grp_id='01'` 和SQL限定的2023年以来日期。`100JPY/CNY` 的报价先除100并ROUND到6位，其余报价乘1。按交易日、本币和外币代码求组内均值，再算每行偏差。

内层CASE在偏差介于±`1e-10`时写1，否则0；但最外层WHERE只保留偏差小于负阈值或大于正阈值的行。因此最终是**异常行返回0，无偏差超限时为空集**，没有正常行1。一个分组只有一个非空来源值时，它等于自己的均值，不能证明已经完成多源比对；NULL偏差也不进入异常WHERE。没有检查每组是否同时包含MD和TL，更没有纳入名称可能提及的其他系统来源。

## 模型逐字段比较：真正的差异条件需要在WHERE里

145989将指定来源的 `T98_OTC_SWAP_COMP_LEG_VALU_INFO` 与当日 `D_POS_TRS_LEG_VALUATION` 全外连接，键是估值/腿持仓编号及模型业务日对源业务日。WHERE逐项比较 `NVL(源列,'') <> NVL(模型列,'')`，任一比较不同则计为异常；异常计数为0返回1，否则0。

比较内容包括合约、腿、腿类型、币种、方向、簿记及产品标识，买入额和开平仓费，利息及汇率，名义本金和市值，当日/累计已实现与未实现损益，动态名义本金，已清算/未清算收益，以及原币、本币和不同估值方式的成组字段。本文只解释这些对应关系被逐项比较，没有核实每一业务映射应否如此定义。

全外连接加NULL归一比较可以报告单侧缺行及字段差异，但NULL与空串被视为相同；数值列与空串的类型转换受方言影响。模型侧只限来源、没有当日过滤，源侧是当日采集分区；该分区究竟含哪些源业务日期需要实际数据确认。多条同键且字段完全相同的重复记录，仍可能在连接后全部满足相等，所以内容比较不能替代主键检查。

<a id="quality-contradictions"></a>

## 两项静态矛盾：定义存在，但无法按预期报告差异

### 223385：连接要求日期相等，WHERE又要求不等

该任务将当日履保参数源与履保参数模型FULL JOIN，ON中要求多个业务字段相等，最后还要求：

```sql
substr(a.SRC_BUSI_DATE,1,10) = b.Busi_Date
-- 唯一的外层筛选
where substr(a.SRC_BUSI_DATE,1,10) <> b.Busi_Date
```

成功匹配的行无法再满足日期不等；未匹配行一侧为NULL，不等比较为未知。按通常SQL三值逻辑，WHERE没有行，外层 `COUNT=0` 返回1。这个问题由条件本身导致，不依赖假设数据恰好一致。它不能作为模型内容一致的有效静态保证。

### 156838：只取全局两行，匹配后又要求连接列为空

查询从最近30日下界的bundle记录按日期、交易编号、簿记和合约类型分组，再用没有PARTITION BY的 `ROW_NUMBER() OVER(ORDER BY busi_date DESC)` 取全局第1、2行。它不是给每个合约取前后两期，同日排列也没有进一步排序键。

两行FULL JOIN要求交易编号、book、contract_type都相等；WHERE再要求双方交易编号相等，且book或contract_type任一侧为NULL。匹配成功需要这些等号比较为真，因此不能同时满足NULL条件；不匹配行一侧交易编号为NULL，又过不了WHERE的交易编号相等。结果按所示逻辑为空，不能检出原意中的簿记/合约类型变化。

这两项在账本中记为“家族规则已解释，并发现静态逻辑缺陷”，不是“检查验证通过”。本文没有修改任务，也没有声称某次生产运行因此发生了误判。

<a id="quality-business-date"></a>

## 业务日期检查：返回的是找到日期的行

155614、155638、155639都先选最新采集分区，再找报告日或 `AS_OF` 为计算日的记录。155614/155639用最近30日下界内的MAX分区；155638的MAX来自全表，随后仍要与最近30日的数据连接。155614最多返回10行，其余两份没有该LIMIT。

虽然名称写“T-1”，实际最终比较是 `${yyyy-MM-dd}`，不是SQL内显式减1日。这三份返回所找到的业务日期行，没找到则空集，没有内置0/1旗标；不能按异常明细查询的约定解释空集。找到若干当日记录也不能证明当天所有应有对象都已到达。

## 波动检查：分母、阈值、窗口与返回方向都不同

前一日/当日计数为0时，多数比例查询没有单独分支；除零可能报错或产生NULL，取决于执行引擎，不能预设它一定报警。173126/173127明确处理前期为0，和这些模板不同。

155876的PV空串被转为0，其他内容CAST为DOUBLE；旧PV为负时分母没有取绝对值，算出的比值可能为负，无法超过正阈值。旧PV为0、缺少第二个业务日、非数字PV也不是这条语句已安全处理的情况。它不能替代合约级市值或损益正确性检查。

206127的分区值是字符串h10/h13，不是计算日期。若执行引擎在分母0时得到NULL，则 `ratio>1.3 OR ratio<0.7` 为未知，CASE会走ELSE 1，并通过外层筛选；若引擎直接报错则表现不同。本文保留这个分支风险，不臆测运行环境。

### 3σ：当月参与阈值估计，本身就限制了检出能力

两份SQL都将窗口写为 `${yyyMM,-6M}` 至 `${yyyyMM}`，再限不早于 `${yyyy}01`，注意下界原文只有三个y，平台如何展开未在本次验证。阈值由该窗口内每标签、每个有记录月份的行数计算，包含当月；缺失月份没有补零。

**若这些占位符按“前6月到当月”展开，且`busi_mon`为规范月份，则每标签最多7个样本。** 一个被纳入均值与总体标准差的样本，其标准化偏差最多为 `sqrt(n-1)`；当 `n<=7` 时，小于3。因此在这个明确前提下，当月计数不可能突破由这至多7个样本共同计算的严格3σ边界。直观上，极端当月值也把均值和标准差一起拉向自己。这个结论是对公式的静态推导，不是对实际占位符展开或运行结果的宣称。

197640以历史阈值表为左侧，197782以当月计数表为左侧；两者不能说成只是换了表名。某标签当月消失时，前者可能在NULL比较后走ELSE 0，后者可能根本没有该标签的驱动行而在其他标签行上累计0；全部驱动行都为空时SUM可能返回NULL。只输出SQL列出的标签，未列出的新标签也不产生新列。这些实现均不能代替“本月每个必备标签都有数据”的检查。

从这些例外可见，质量任务本身也需要按对象、时间、条件和结果协议核验。发布SQL支持本文的静态解释；某次检查是否运行、平台怎样判值以及下游实际消费是否可信，仍需要各自证据。
