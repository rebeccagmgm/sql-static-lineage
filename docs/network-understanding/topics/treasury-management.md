# 资金部如何使用股衍数据：资产、融资与履保视图

资金部消费的是已经整理过的业务视图：资产是什么、名义金额有多少、融资与票据有哪些条款、合约怎样关联账簿和客户、组合保证金处于什么状态。它与[财务交割接口](../chapters/07-finance-and-valuation.md)共用一些业务事实，输出目的和粒度却不同。

本页覆盖 `DM_FMS_N` 全部 14 项：6 个加工、6 个导出和2个独立回执。12 项共 2,534 行发布 SQL 已核读，两个回执使用当前 Pack 中独立保存的补充 SQL。原始来源、行号、哈希与边界见[证据索引](../evidence/treasury-evidence.md)。这里解释当前图能看到的股衍输入部分，不声称覆盖资金部所有资产类别或整个管理系统。

| 香港回购明细 | 互换合约、资产腿、对手、计息腿、汇率 | 满足回购筛选的合约及其融资条款 | 163099 |
| 香港票据明细 `grp03` | 产品、票据交易、票据属性、互换腿、汇率 | 产品及相关客户、发行与计息信息 | 167808 |
| 期权交易明细 | 交易关系、期权合约、结构、事件、履保方案 | 合约与结构、标的等组合明细 | 214155 |
| 互换交易明细 | 交易关系、互换合约、不同腿、持仓、对冲与借券 | 合约、腿与标的等组合明细 | 214154 |
| 每日组合履保 | NDS 组合结果、合约参数、账户余额、账户组合映射 | 组合结果与其关联参数、余额和解释字段 | 217643 |

## 资产概览：持仓余额来自动态名义本金

134690 从计算日合约销售信息中选择期权，以及标的类型为债券或策略指数的 TRS；同时要求协议号匹配 `OPT-GFED%`。所有条件共同起作用，不能只根据前半个条件说它覆盖全部互换。合约生效状态过滤被注释掉，结果会按实际状态显示生效或终止。

`Hld_Amt` 取动态名义本金，数量和持仓市值填 NULL，账户编号实际上放合约号，`Dept` 放交易对手全名。币种、估值账套、会计科目、管理人等列在这条分支中为空；`Frgn_Flag` 固定境内，来源系统和业务分组固定为 TITANS 与 03。这是一种面向资金部统一列结构的适配，不能把每个列名都按其通常含义解读。

标的侧补指数成员标志、一级行业、基金两级分类、总市值、PE/PB 和跟踪指数。指数成员要求进入日期不晚于计算日、退出日期晚于计算日或为空；行业取当前有效分类并按进入日期选一行；股票估值先按 `grp_id` 升序、再按交易日降序选一行。所以“估值最新”其实服从分组优先级，不能简化成所有来源中全局最新的一条。

还有两处静态不一致：资产类别的特殊分支判断 `Busi_Type='互换簿记'`，但来源子查询保留的值是 `OPTION` 或 `TRS`，此特殊分支不会在这些值上命中；业务品种配置固定取 `O0101001`（期权）并 `ON 1=1` 连接，不按每条合约重新挑选业务品种。配置若有多行，还可能放大输出。来源宽表本身的销售关系粒度同样需要保留。

来源：134690 `query` 46–121、123–261 行。

## 香港回购：下一自然日与三种同值利率

162676 从交易内部编号、有效账簿关系进入，连接互换分类、当天合约与资产腿。它把起初定价日的持仓标的代码合并成字符串，再要求结果恰好为 `FEE.REPO`；同时要求状态字典描述为生效、交易对手英文简称不在 GFS/GFSX。缺少右侧简称或状态字典的行也可能因这些 `WHERE` 条件被排除。

结构腿决定我司身份与支付方向，非结构腿提供固定/浮动利率。最终排除“我司乙方、乙方支付、结构腿”同时成立的记录。输入缺值时应按 SQL 三值逻辑理解，不能假设 `NOT` 一定保留未知行。

这个视图将起息日写为计算日，到期日写为下一自然日，期限计算为一天。原本取香港下一交易日的连接被注释掉。因此周末或假日不应自动解释为延至下一交易日。

固定腿利率与浮动利差先乘 100。固定利率为空时，港币使用不晚于计算日的最新隔夜 HIBOR 加利差，其他币种使用最新隔夜 SOFR 加利差。`Actual_Rate`、`Initial_Rate`、`Reset_Rate` 三列使用同一表达式，没有在这份视图中分别重建初始与重置历史。

回购金额与还款金额都取动态名义本金；折港币金额乘当天汇率表中不晚于计算日的最新汇率。`Haircut` 实际是动态名义本金除以初始名义本金并保留两位小数，没有执行“1 减该比率”或乘 100。质押券名称、代码、全价、市值等多列为空；对手全称列实际取卖方英文简称。它们是已确认的字段赋值，不能扩写为完整的抵押品明细。

来源：162676 `query` 1–115、153–254 行。一个合约若存在多条非结构腿或重复起初持仓，行数和字符串筛选都可能受影响；没有数据验证时不保证一合约一行。

## 香港票据：发行、库存和担保列中哪些是常量

163640 从 TITANS 产品信息取融资票据及其他非空产品类型，排除已作废、编号含 TEST 及三个明确测试产品。代码没有只保留 EFFECTIVE，结构型产品曾有的账簿限制也已注释掉。

交易、起息、到期日期来自产品。融资票据的发行金额是总名义金额减库存；其他产品是面值乘认购数量。但在本脚本中，库存固定 0、折价率固定 100，所以融资票据发行金额等于总名义金额，折价金额也等于总名义金额。不能把这些列的存在当作已经采集了独立库存和折价数据。

买卖方向、发行人、担保人、DVP、是否配资和是否担保等多项由 SQL 固定赋值。这里仅说明接口如何填列，不据此判断一只具体产品法律上的担保安排。配资金额与期权日期等列为空。

产品通过截至计算日的票据交易记录连接客户，再通过产品资产记录选内部交易编号，连接互换非结构腿补利率、计息基准、付息频率和利差。资产记录的选行排序是标的代码降序，不是按时间取最新。产品交易记录虽然 `DISTINCT`，仍包含客户编号等列；同一产品关联多个客户或计息腿时，总名义金额可能在多行重复。

发行部门还有一个字符串处理差异：内层先删掉部门中的下划线，外层再判断是否等于 `HK_FICC`。对于原值 HK_FICC，外层实际看到的是 HKFICC，不会命中转换为 FICC 的分支。

来源：163640 `query` 46–90、91–194 行。原币金额乘港币汇率形成折港币金额；汇率缺失没有自动补成 1。

## 期权明细：结构窗口、状态与部分终止事件

207458 必须取得有效的内部交易编号、业务类型、账簿关系，并匹配当天期权合约与结构信息。业务类型排除资管子公司 `OPTION_SAC_GFA`，账簿关系排除两个明确测试编号。

纳入条件是“结构起初定价日已到，且提前终止日或期末定价日尚未到”，**或者**合约状态为生效。这不是要求两个条件同时满足；仍标生效的合约即使不在前述日期窗口内，也可能保留。

动态名义本金由初始本金加部分终止事件变动计算：若调整后小于调整前，变动量取负，否则取正。事件业务日不晚于计算日，空日期先回退到 1999-01-01；只取 `PARTIAL_TERMINATION`，事件生效状态过滤被注释掉。不能描述为“仅汇总已生效事件”。这段累计前还连接了合约结构，如果一个合约有多条结构，事件可能被重复带入累计；具体是否发生需要来源唯一性验证。

结构提供类型、子类型、方向、标的、标签及定价日期；合约提供初始/绝对名义本金、费用、兑付日和审批状态；履保参数与组合方案补保证金和担保信息。外层同样按结构展开，并不保证本金只出现一次。

最重要的日期区别是：履保参数取 `date_sub(CURRENT_DATE(),1)`，其余主要材料取参数业务日。补跑过去某日时，SQL 仍会读取运行时昨天的履保参数。代码注释解释为模型仅保留最近一天，但这里没有重新验证真实保留策略，不能把这个视图当作完全可重现的历史截面。

来源：207458 `query` 74–123、131–217、253–349 行。

## 互换明细：合约、不同腿、标的与借券来源一起展开

207753 通过有效交易属性、分类、账簿与产品关系定位合约，再连接当天互换信息、结构腿、非结构腿、当天持仓及标的。随后补对冲渠道、券源池、关联合约、配对合约、担保与客户法人信息。

结构腿决定结构收益方向、多空、期初持仓及标的；非结构腿提供固定利率或浮动利差及其挂钩标的。多个结构腿、计息腿、持仓标的、对冲记录或报备记录都可能扩展明细，整份合约名义本金并没有因此按这些行分摊。直接对所有行汇总本金需要先解决这个粒度问题。

本视图的固定利率和利差直接取模型值，没有像回购、票据视图那样乘 100。比较资金部不同结果的利率时，不能只因为字段名相似就假设量纲相同。

最终仍采用“处在日期窗口内，或状态为生效”的并列纳入条件，并排除业务类型显示值 `SBL_GMASLA_OTCHK`。配对合约关系的有效期使用 `End_Date >= 计算日`，其他多数交易关系使用严格大于；边界日语义不同。

有三个字段不能靠名字推断：实际终止日取报备事件的实际结算日期；实际兑付日取模型 `Actl_Trmt_Date`，脚本注释说明其源含义是实际兑付日；大额名义本金审批状态固定为空并注释待采集。履保参数也取运行时昨天，存在与期权明细相同的历史重算边界。

来源：207753 `query` 118–182、205–275、350–478、486–555 行。

## 组合履保：已算结果与账户余额的重新拼接

215700 的主表是 NDS 已计算的组合每日结果，要求落地分区和源业务日均对应参数日。`IS_CALC='Y'` 过滤被注释掉；不应把被纳入自动解释为已参与履保计算。

组合还必须存在保证金账户映射，并属于 OPTION、TRS、MIXTURE、N_CROSS_DMA 四种用途。组合视角合约参数按组合和源日期左连接；账户、客户、部门、方案与标的描述继续补入。

“批次保证金余额”直接取组合结果；“实时保证金余额”由当天 NDS 账户当前余额重新汇总。后者只纳入反向转码后启用为 Y 的账户，余额缺失按 0，按“账户币种汇率 ÷ 组合盯市币种汇率”换算。两边汇率缺失都用 1，取价日使用计算日的最近交易日规则。这个 fallback 使数值仍可能产生，却不能证明币种换算正确；名称“实时”也不证明读取时延。

多列是同一值的不同接口别名：

| 输出列 | 实际来源 |
|---|---|
| `DYNAMIC_NOTIONAL`、`NOTIONAL1`、`NOTIONAL_OR_VALUE` | 同一个组合动态名义本金 |
| `NOTIONAL2` | 固定 0 |
| `INNER_VALUE`、`MARK_INNER_VALUE` | 同一个内在价值 |
| `FEE`、`UNPAY_FEE` | 同一个费用值 |
| `CALL_REQUIRE`、`MARGIN_REQUIRE` | 同一个履约保障要求 |
| `ADD_REMARGINABLE` | 需追加金额加空值按 0 处理的垫资金额 |

这些别名不能作为独立指标再相加。合约参数包含多条组合视角行时，也不能直接假设最终组合一行。标的描述会去重、排序、拼接并截取前 2,000 字符；它是有限长展示摘要，不是完整可逆的持仓列表。

来源：215700 `query` 1–206、208–265、326–477 行。风险和保证金计算的原始模型见[资金与保证金](../chapters/05-funds-and-margin.md)及[风险主题](../chapters/06-risk-and-pricing.md)。

## 导出与回执的范围必须一起看

| 导出 | 查询范围 | 前置清理 |
|---|---|---|
| 114802 权衍资产 | 02/03/04/05/06/09 为参数日；08 为参数日前15日至当日的含端点窗口 | 相同日期和分组条件 |
| 163099 香港回购 | 参数日，所有来源分区 | 只删除目标参数日 |
| 167808 香港票据 | 参数日，未限定 `grp_id` | **删除目标全表**，不是只删参数日；导出列不保留 `grp_id` |
| 214154 互换、214155 期权、217643 组合履保 | 参数日 | 只删除目标参数日 |

因此资产推送的历史回刷窗口与其他接口不同，票据目标端的历史保存方式也不能套用本地按日分区的模型。对同一来源下其他分组的数据，此处只确认它们被导出读取，不能把本页 grp03 的业务规则复制到其他分组。

五个导出的 `finish` 读取目标参数日记录数并写日志，状态直接为 0、开始与结束时间均取写日志时的当前时间。资产导出还配有 144442、203181 两条独立补充回执，分别统计排除 02/07 和仅 02 的参数日记录；它们不会覆盖资产导出中 08 分组整个历史回刷窗口。完整说明见[交付回执](../chapters/15-delivery-and-controls.md#counted-delivery-log)。

上述 SQL 可以解释输出和清理的设计行为，不能证明清理、导入、回执都已成功执行，也不能证明目标业务界面已消费。静态知识保留这个界限，才能正确解释重跑、历史对账和金额差异。
