# 考核后处理：团队层级、排名与 K1 计分

上游指标传入 temp_indi_data 后，164991 继续重建团队指标、修正初始值、分组排名并计算 K1 分数。本页连接[收入与评价接口](performance-income-and-evaluation.md)及[资产传输窗口](performance-output-contracts.md)，解释“同一个指标值为何到了考核系统还能变化”。

证据分两类：164991 使用固定发布 evidence 的 query 1–619；156254 与 166545 的固定发布中没有 SQL，本页使用 supplemental-pack-inventory.json 明确登记的当前 Input Pack 快照。补充脚本按 task.json.sqlFiles 精确路径读取，元数据和内容 hash 均复核；它们没有被混记为发布 SQL。三项明确加入本主题原有 299 项范围，合计 302 项。脚本从未执行。

## 从一层团队业绩，走到可递归的团队考核

164991 先截断 tbusi_team_info_all 和临时豁免指标表。使用 CONNECT BY 将团队负责人作为根，沿 upper_emp_grp_id 递归，把各层团队归到根负责人；只允许同业务月接续。这与指标层 199817 等“一层直接成员＋子团队成员”的拼接不同。此处的根从所有有负责人的团队开始，同一成员可属于多个层级根，不能假定所有团队长指标相加守恒。[164991：query 1–12][^164991]

团队考核豁免以 temp_indi_data 中 emp_excl_kpi_flag_mon_busi=1 为准。脚本分别统计满 12 个月且最低档合格的人数、团队总人数、满 12 个月人数；总人数还排除当前投顾序列而在季度末零售序列的转换人员。count(1) 依赖团队成员、人员历史和指标连接唯一性，并非 count distinct 员工。零售团队评分对每人 K2 分数封顶 100 再求和。[164991：query 14–141][^164991]

投顾评分按条件选来源：季度末确认日尚未达到条件或登记月份处于季度末前六个月至季度末区间时，取季度末 K1；否则若当前月在机构保护期，取当月总创收达标率；其余取季度末投顾业绩分。每人封顶 100、缺失补 0，再归根团队。季度末人员状态或指标在当前月运行时是否已准备齐全，是运行依赖；SQL 能证明它要读季度末，不能证明那些数据已经存在。[164991：query 143–190][^164991]

<a id="pp-rank"></a>
## 指标初始值、团队平均和期初资产排名

脚本给业务序列人员另写效率合格标志：效率初始值为空或大于 1 给 0，其余给 1。之后除效率两项外，将空初始值补成指标值；部分产品／平均收入指标的初始值又被改为“指标值－人员等级调整表的基础参数”。因此 indi_init_val 不是在所有步骤都等于第一次收到的原始值。[164991：query 193–230][^164991]

业务总监季度 K2 平均分对团队人员取 k2_act_sco_sc×100 的和除成员数，空分数贡献 0，排除本人、指定离职状态，并限制岗位类别；结果封顶 100，零人数通过 nullif/coalesce 给 0。它按另外一张人员岗位关系表构造团队，不能与前段递归团队人数混用。[164991：query 232–269][^164991]

投顾排名先在序列和分公司内按期初标准资产降序 rank，rank/人数先四舍五入到两位，再按 <=25%、<=50%、<=75%、其余分四组；随后在同一资产组内分别按增长率、净值降序排名，并输出该组人数。并列 rank 会跳号，四组未必各占精确四分之一；缺失值排最后。这个分组适用于人员，和主篇客户分资产规模评分不是同一模型。[164991：query 271–377][^164991]

## K1 得分：先按组件达标率封顶，再乘固定权重

164991 为指定业务序列、岗位、级别员工从 temp_indi_data 取每个源指标的最大初始值，从目标配置表按指标、级别、试用／正式状态取最大目标值及转换方式。组件公式为：

`min(源初始值 / 目标值 × 100 / 地区系数（仅 cvrt_mode=1 时）, 组件上限) × 权重`


地区系数缺失默认 1；目标缺失／为 0、需要转换而地区系数为 0 的组件被过滤。有效组件求和并保留两位；缺组件不重新归一化权重，全部组件缺失则可能没有得分行。脚本用 merge 更新已有员工月指标，只在能匹配正式指标 ID 时插入新行。[164991：query 380–498、501–619][^164991]

| 人员与阶段 | 组件及固定权重 | 各组件上限 |
|---|---|---|
| 区域总监，试用 | 在岗人力 50%、开发资产 30%、团队产品额 20% | 均 120 |
| 区域总监，正式 | 团队半年平均收入 70%、人力达标人数 30% | 分别 150、100 |
| 其他指定业务岗位，试用 | 产品额 20%、平均总收入 40%、开发资产 20%、近半年新增高净值客户 20% | 均 120 |
| 其他指定业务岗位，正式 | 产品额 50%、半年平均收入 50% | 均 120 |

第一组目标 exam_type=118；其他岗位目标 exam_type 在 106、117 中，并只有新增高净值客户组件要求地区匹配。其他组件不要求目标地区相等，但目标数据仍按地区分组；若多个地区同指标、级别、阶段配置并存，连接可能产生多行。脚本没有自行证明配置唯一。源码这些权重是当前计算事实，不代表已核验正式人事制度。[164991：query 382–458、503–589][^164991]

## 上月后处理只对部分步骤限制九日前

补充任务 166545 与发布任务 164991 的非空行在显式替换“上月参数→本月参数”后，593 行中有 585 行一致；其余 8 行全部逐条核读，并另查原文日期条件。它整体处理上月，但只对“补空初始值”和“投顾三项排名的删除与插入”加计算日 <= 当前月 9 日。团队重算、基础参数调整、K1 组件计算并没有同样的 9 日判断。不能将其简写成“上月所有考核九日后完全固化”。[166545：补充 query 1–615，差异 222、272、331、352、375][^166545]

两个脚本使用共享且整表截断的中间表，并多次 commit。它们不是从首句至末句一个全有或全无事务；并发重跑是否互相影响、具体调度先后及失败恢复方式，需要运行配置证据。本页只说明有这类写入边界，不执行或修复源脚本。

## 机构标准资产排名：年末基期、当前组织和固定 A/B/C 组

补充任务 156254 读取机构年日均折标资产报表，构造去年 12 月与当前月两个时点，按当前组织字典汇营业部和分公司，缺值补 0。公司占比为机构资产/公司合计×100；资产增长率为当前/上期−1 再乘 100；占比增长值是两个百分值相减，占比增长率再次做相对变化。分公司增长目标来自当年有效目标及最新 ID 的地区系数，计算 sum(target)×sum(coef)，并用于增长目标完成率。[156254：补充 query 1–109][^156254]

几个实现细节必须保留：lag 只按 org_id 分组，没有 org_flag；中间结果又按月、机构取最大资产一条删除重复。增长目标完成率的零值保护检查的是上期司占比及目标，而公式另除上期资产。目标或系数表多行时的 sum×sum 是否符合制度，不能由静态 SQL 保证。[156254：补充 query 71–118][^156254]

分公司按脚本写死的 A/B/C 机构名单分组，输出全体及组内五项排名和六项均值；营业部在所属分公司内排名，组均值等字段固定 0。没有进入中间结果的组织补全零行。最后把宽列 unpivot 成机构×月×指标代码，删除并重插当前及前两个月这些指标；当前步骤只重建当前月中间结果，前两月取的是已有历史中间表记录，而非本脚本重算三个月全部基础资产。[156254：补充 query 124–299][^156254]

本页区分了原始／初始值调整、排名、达标率和得分；仍未确认人员历史、目标配置的唯一性、真实发薪采用的指标集合或制度审批。多个 SQL 已经给出分数，也不能越过这一证据边界声称最终工资正确。
