# OTC 组合定义、标签与对手指标

本页解释的是同一批 OTC 合约如何被组织成可查询对象，如何贴上不同用途的分类，再形成公司、交易对手主体、客户与机构、员工等不同粒度的规模和收入指标。查询时必须同时固定**对象、标签维度、金额来源、时间窗和归属关系日期**；这五项不同，即使名称都含“场外衍生品规模”，也不能直接比较。

证据固定为发布版本 `df6f0ae4b6ef465f751351b14fd02ea08542d824d7bfea36e5a58dd1039e23c3`，清单生成时间为 2026-09-07T06:05:52.799Z。本页逐槽读取 21 个任务的 SQL；末尾证据表列明槽位和行数。这里只证明固定 SQL 的表达和存储接口，没有使用实际业务数据验证关联唯一性、数值正确性或成功入库。

## 对象先分清：合约类型、合约、交易对手和主体

`OTC_DERI_CONTR_TYPE` 的组合值是源合约类型代码 `Src_Contr_Type`，组合名是对应描述。任务 **200369** 从计算日 `T98_OTC_DERI_COMP_SALE_INFO` 的 `Grp_Id in ('01','02','03')` 取 distinct 代码与描述。它保存的是“类型词典”，并不是某笔合约。新代码按当前最大组合号加行号分配 ID；已有代码保留 ID、更新名称；原先存在但本次来源中消失的代码保留记录，状态置 0，结束日最多收口到计算日前一天。源中重新出现的代码会按现有分支重新置为 1。源表若同一代码有多个不同描述，distinct 仍可能保留多行；该 SQL 没有选择唯一描述的规则。〔200369：query 1–64；prepare 1–13〕[^otc-200369]

`OTC_DERI_CONTR` 才表示具体合约。任务 **237301** 以期权协议号 `Opt_Comp_Agt_Id` 或互换协议号 `Swap_Comp_Agt_Id` 为组合值，内部订单/合约号为显示名称；SQL 注释明确显示名称允许重复。期权只取指定自营期权来源，互换包括常速、极速、多空三个子类。两者均纳入状态 101（正常/生效）、229（未生效）、226（已终止）、225（待终止）、252（待审核终止），沿用上述“新增、保号更新、缺失置失效”的定义维护。期权与互换之间使用 UNION ALL，没有额外跨源去重。〔237301：query 1–93；prepare 1–13〕[^otc-237301]

因此，`grp_def.status=1` 的准确含义是**该组合仍在本次定义范围内**。它不能直接翻译成“该合约正在生效”：定义来源明确包括未生效和已终止合约。开始日期 1900-01-01、结束日期 2099-12-31 是定义维护的默认有效区间，也不是交易的起止定价日。

本页另有两种客户对象：`OTC_COUNTERPARTY` 用交易对手参与方 ID 识别客户；`OTC_DERI_CUTP_ENTY` 用统一社会信用代码识别主体。后者由客户表的 `PTY_ID → USCC` 映射把多个对手 ID 汇到同一主体，选用两类 OTC 对手来源和 `pretradedate(计算日+1日,1)` 的客户快照。只接纳已存在的有效主体组合，缺客户映射或缺组合定义都会在 INNER JOIN 中失去输出。这个日期函数的具体交易日历实现未在这 21 个任务中展开。

## 交叉合约类型如何判定

期权部分只取与合约组合定义相同的五种状态和自营期权来源。标的家族优先使用篮子成分家族的 collect_set 拼接值，缺篮子值才使用单标的家族。由此，“EQUITY;INDEX”这样的混合篮子不会等同于单一 EQUITY；SQL 没有把混合篮子分摊成多个家族。账簿、单标的、篮子三个连接都是 LEFT JOIN，分类规则要承受其缺失值。〔241773：query 101–182〕[^otc-241773]

- **旧版期权**：自动赎回先按是否 SNOWBALL/SECURED 区分保本雪球，其他自动赎回再分股票/GDR 与非股票；安全气囊同样按股票家族分。Risky/AIRBAGX 的限售分支要求 EQUITY 且限售标志 1，流通分支则只要求限售标志经补 0 后不等于 1。另有指定账簿柜台与销售对手的北上 QIS 分支，最后将其他结构分为股票/GDR 和非股票。旧版 CASE 没有 ELSE，某些空家族或未覆盖组合会得到空标签。
- **新版期权**：股票/GDR 上先排除 Risky、AIRBAGX/M/L、CUSTOMISED 和指定 SNOWBALL 结构，归为个股期权；INDEX/FUND 中的累购累沽、安全气囊及特定自动赎回归指数/ETF期权；QIS 按北上特例、现货类和两个指定非现货标的区分；再判断 Risky/AIRBAGX 限售/流通，剩余全部归“其他期权”。新版有兜底标签。
- **旧版常速互换**：先识别指定香港部门的跨境借券、香港多头持券、北上期货和北上QFII；再按互换类型区分北上A股、多空互换、南下期货。南下跨境结合标的家族、币种、IPO 与限售标志细分债券、IPO、限售股票、港股和其他股票市场；指定香港公司的返利利息费用合约与指数增强分别归类，其余“其他互换”。
- **新版常速互换**：优先为股票/GDR 借券互换、QIS、南下期货分类；南下跨境或南下场内期权结合股票/GDR和IPO标志归 IPO 或南下跨境股票；保留指定公司北上指数增强，其余“其他互换”。新版规则不再保留旧版全部细类。
- **多空互换**：指定 B_LONG_SHORT_SWAP 归金仕达多空，其余该子类归多空互换。**极速互换**：只有 N_CROSS_DMA_SWAP 输出北上极速标签；其他极速类型即使存在于合约组合定义，也不会经此任务取得交叉类型标签。

常速互换的账簿为 INNER JOIN，缺账簿会失去分类；合约交易标的及结构腿是 LEFT JOIN，按协议号相连，SQL 没有对子表选择“唯一一条”的窗口或去重规则。如果一份合约有多个标的/结构腿记录，是否会得到多条分类需要用数据验证，不能假定每份合约只能有一个标签。〔241773：query 192–435〕[^otc-241773]

## 两种“年日均”不能视为同一个指标

任务 **203879**（主体）与 **206208**（机构/员工交叉销售）的合约级公式相同：

```text
合约值 = sum(所选动态名义本金明细)
       / datediff(if(合约结束日 <= 计算日, 计算日, 合约结束日), 起始定价日)

合约结束日 = coalesce(提前终止日, 期末定价日)
```

这里分母取的是结束日与计算日中的**较晚日期**到起始日的天数，不加 1；SQL 注释“截至当前有效天数”不能覆盖实际表达。输入仅要求当日合约快照的结束日大于当年1月1日；明细要求结束日大于年初、业务日不晚于计算日且不晚于明细结束日，**没有明细业务日 >= 年初的下界，也没有分母起始日钳在年初**。因此它不是“当年每天余额求和 / 当年已过自然日数”，也不能凭名称认为是按存续日数至今天平均。零天数、负天数、跨年历史明细和未来结束日都会影响值，SQL 没有显式保护。尚未用业务数据判断这是否为设计意图或错误。〔203879：query 1–43；206208：query 1–25〕[^otc-203879][^otc-206208]

203879 将每份合约的上述值按主体求和，再按主体与经营报表类型求和。所有未匹配类型的合约统一补成 DMA 标签 `tag074450119`，尽管注释只提“手工合约号”；实际条件没有限定手工来源。206208 则取计算日管理关系，将三套营业部、分公司、员工和分配比例展开三行，按 `合约值 × 分配比例` 分别汇总到营业部、分公司、员工，另输出分公司 × 报表类型明细。它只排除当前输出对象字段为空的关系，没有重算比例、保证比例和为1或去重关系的规则，也没有采用下面旧指标的机构回退规则。〔203879：query 46–82；206208：query 27–118〕[^otc-203879][^otc-206208]

## 客户、机构与员工的自然日均如何分配

**147921、148124、93338** 是另一组计算。三者以计算日合约快照（组别01/02/03、排除 FEE_SWAP）连接历史动态名义本金，再用**计算日管理关系**分配历史金额；它们没有按每个历史日重新取得管理关系。金额不因名称含“交叉销售”就等于收入。与主篇初始本金成交规模的区别是：这里累积每天的动态余额，再除自然日数。[^otc-147921][^otc-148124][^otc-93338]

| 任务       | 历史金额范围和分母                                                             | 输出与特殊差异                                                                      |
| ---------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| **147921** | 年初至计算日；明细日还须在其起止定价日内（含首尾）；除以年初至计算日天数+1     | 客户对手 × 营业部/分公司本部 × 当月分区 × 两类标签                                  |
| **148124** | 月初至计算日；同样校验明细起止定价日；除以月初至计算日天数+1                   | 中间层按客户、机构、员工、标签分组，最终只投影客户和机构两个组合 ID，员工维没有输出 |
| **93338**  | 年初至计算日；本任务未增加明细日落在起止定价区间的条件；除以年初至计算日天数+1 | 员工 × 计算日 × 无分类标签；最终 STAFF 组合连接未过滤 status=1                      |

这里日均的分母不会随缺失数据日变小。它也没有补齐日历或主动前值填充：需要源附加明细已经覆盖适用自然日，才能按“每日余额”解释。147921 即使叫年日均，目标分区仍是业务月份；它是该次计算截至日的年日均快照，不是一次输出全年每个月。

三者先经过相同的交叉销售资格筛选：至少一套机构不属于默认/排除机构集合，或协议号在固定历史例外清单内；还必须至少一套客户经理账号不是默认账号。随后，每个关系槽位各生成一条分配：若本槽机构不满足数字 ID 小于8000，则按固定次序回退到另外槽位的机构/员工，但**仍乘本槽位的分配比例**。第二、第三槽要求比例非零。若三套机构都属于指定分公司本部集合，则走另三条分支，保留原槽位的机构或员工。没有比例归一化，也没有合约去重；结果零值行被过滤。〔147921：query 16–119；148124：query 19–136；93338：query 13–97〕[^otc-147921][^otc-148124][^otc-93338]

147921 的两类标签依据部门、期货标的、是否境外对手/指定公司、标的币种及 Risky/安全气囊排除集合判断；币种取合约 `Undrl_Curr`，用 CNY 比较。148124 用证券基础表的 `crrc_cd`，用代码 156 比较，且证券连接不指定业务日。两个“月/年变体”因此不只是时间窗不同。148124 内部员工分组最后隐藏员工列，意味着**客户×机构×月×标签不能未经验证就当成唯一键**；同键多行可能代表不同员工分配，而不是可直接删掉的重复。93338 则可能保留已失效 STAFF 定义，不能套用其他指标“只含当前员工”的解释。〔147921：query 11–15、121–127；148124：query 14–18、34–38、46–63、135–144；93338：query 98〕[^otc-147921][^otc-148124][^otc-93338]

## 公司规模与报备范围也有不同口径

任务 **171370** 同一张“公司当日合约规模”里有五组 UNION ALL 输出。前两组以计算日销售合约信息和附加明细的动态本金为金额源，两层结束日都必须严格大于计算日，分别按业务类型、经营报表合约类型汇总。其余分支改读互换合约汇总表，金额换算表达为：

```text
原币动态名义本金 ×
  (原币为CNY时1；
   否则本币为CNY时用本币原币期初汇率；
   否则结算币为CNY时用结算期初汇率；
   否则NULL)
```

第三组按账簿部门汇总，第四组专取指定部门的北上跨境期货，二者允许五种合约状态，SQL 未重用前两组的结束日过滤；第五组为指定境内债券账簿，仅排除作废状态218，按源互换类型与“对手是否指定FICC主体”的复合标签汇总。因此这些标签切片的输入对象集合不一致；不能把所有标签加总成“公司总规模”，也不能要求不同维度之和天然相等。汇率空值时乘积为空，SUM 是否少计要进一步查数据。〔171370：query 1–149〕[^otc-171370]

任务 **162610** 的“报备合约月末规模”取计算日销售合约快照的动态名义本金；**162618** 的“报备合约月交易规模”取同一快照、起始定价日在当月月初至计算日的初始名义本金。两者都用内部流水号反连接报备事件，把两类来源中 `Rgst_Stat_Cd='SKIP_REPORT'` 的合约排除，并分别输出公司总计和业务类型分类。报备事件未按业务日过滤，分类标签也未筛有效状态；未知业务类型可进入空标签组。〔162610、162618：query 1–40〕[^otc-162610][^otc-162618]

这只能称“排除已标为免报的合约范围”，不能称“均已成功报备”：SQL 没有要求其他报备状态成功。162610 名称含“月末”，但查询只是计算日快照、写当前月份，没有最后一天检查；是否只在月末调度，需要另查调度和消费约定。两个任务也没有自行添加组别01/02/03、当前存续或 FEE_SWAP 排除条件，不应从其他规模任务移植这些限制。

## 季度销售奖励和销售收入来自 CRM 结算结果

**203306** 按公司与经营报表合约类型汇总 `Curr_Actl_Rwd`，**203311** 汇总 `Dev_Dept_Rwd`。来源为计算日 `T98_OTC_DERI_UNDRL_INCOME_RWD_SUM` 中指定 CRM 源表，`Sett_Time` 选**上一个季度**：一季度运行取上年04，其余取本年前一季度，输出分区相应为上年Q4或本年前一季度。合约类型则用计算日合约与分类映射补齐，而非上季末映射。〔203306、203311：query 1–39〕[^otc-203306][^otc-203311]

这里没有从名义本金乘销售费率重新计算收入，也没有从收益扣成本的利润公式。两个结果直接相信上游结算金额。合约或分类缺失时统一补 DMA，但 GROUP BY 是补值前的 `tag.tag_id`；若同时存在真实 DMA 与未匹配组，最终可能出现两个同 DMA 标签的输出行。203311 的内部 SELECT 还连续选择了两次同名 `Dev_Dept_Rwd`，其方言下列解析和运行行为需要实测。两个 query 均没有对结算记录按合约或结算版本选择唯一行。

## 更新接口、可问的问题和仍待验证的边界

所有 21 个任务的 create/prepare/query 槽位都已读取。类型和合约定义的 prepare 只建组合定义表；标签任务的 create/prepare 只建日期分区标签表。多数指标 prepare 建表并删除**计算日或当前月份**分区，query 计算相应结果。243357 的 query 重读近三个月，但 prepare 只显式删除计算日分区；203306/203311 的 prepare 仅建表，未显式清除上季分区。具体写入覆盖/追加模式不在这些槽位中显式出现，不能仅从 query 范围断言历史分区已正确刷新。部分日期占位符使用大写 YYYY-MM-DD/ YYYYMM，实际平台归一化未在此页执行验证。

用这组知识可以直接区分：某份合约是否进入定义、是否进入创收资格、按哪个版本归交叉类型、某主体近月“交易天数”数什么、年日均是否用自然年分母、客户到机构/员工如何分配、月末报备范围排除了谁，以及季度奖励究竟取哪个上游金额。对于具体金额或某份合约缺失，还需要把问题缩到计算日、协议号/主体、标签和源明细进行复核。

以下边界已定位到 SQL，尚未用业务数据或运行记录核验：

| 边界                                                           | 影响                                                       |
| -------------------------------------------------------------- | ---------------------------------------------------------- |
| 203879/206208 的非自然年分母、历史明细无年初下界、分母无零保护 | 同名“年日均”与147921/93338不能直接对账；公式意图待业务确认 |
