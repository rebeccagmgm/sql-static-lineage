# 经营分析与客户服务：业务事实怎样变成日常可用的信息

经营层把前面已经定义的客户、合约、持仓、事件和行情，组织成业务人员能使用的客户清单、销售收入、经营日报和运营接口。这里最容易误解的地方，是把“表名叫日报”理解成每张表都只装当天数据，把“客户”理解成唯一的一种主体，把“收入”理解成已经收到的钱。

这组页面以当前发布中的 `DM_OTC_N` 202 项任务为主范围，另纳入实际写入 `dm_otc_n.t02_ira_indx_info` 的 234231，共 203 项。它覆盖整个经营域的实际主要家族。SQL 能说明加工口径和接口边界；本文没有取得运行后数据或业务验收结果。

<a id="customers"></a>
## 客户是谁，谁负责，签约信息在哪里

从交易对手编号到管理人、统一社会信用代码，再到代签产品和销售经办人，是几条不同的关系。客户权限清单、客户经营画像和开户签约进度也不是同一张表。[客户、签约结果与销售归属](../topics/operations-customers-and-sales.md)解释这些连接，以及客户标签的实际计算条件。

<a id="sales"></a>
## 一笔业务的销售收入归谁

内部引入、境内交叉销售、香港交叉销售有独立范围和参数。合同级参数优先于默认参数，展示最新参数与按历史有效期计提又有不同用途。[销售参数与销售收入](../topics/operations-sales-income.md)解释三套口径、主经办人与引入经办人的分成、三组机构分配比例和期末补足。

<a id="reports"></a>
## 日报、规模、创收和客户经营指标怎样形成

创收日报的当前分区可以装多年的计提日。客户规模趋势取动态名义本金，年创收取计提创收之和，持仓盈亏又接了结算流水和估值结果。[经营日报与指标](../topics/operations-revenue-and-reports.md)给出具体公式、时间和粒度，并指出指标名称与实现不一致的地方。

<a id="contracts"></a>
## 如何给客户和运营提供合约、观察、估值与事件信息

合约服务把模型字段重新组合成期权参数、互换腿、标的持仓、观察日、生命周期和收付清单。[合约与存续服务](../topics/operations-contract-service.md)按业务问题解释这些视图，保留内部编号、外部编号、产品编号和子交易编号的差异。

<a id="settlement"></a>
## 成交、ETF 申赎、来款和交割能追到哪里

普通 ATP 回报、ETF 成分回报、中登余额与结算文件、实时代收代付各有自己的对象粒度和日期。[成交、收付与交割接口](../topics/operations-trading-and-settlement.md)说明可核实的关联，并明确哪些生产 SQL 缺失。实时代收代付明细带有中登交收状态，不能仅因有收付金额就当作客户银行来款。

<a id="delivery"></a>
## 下游到底收到什么范围的数据

PB 批次、按日模型、日内快照、市场数据、MQ 报表、ED/特定客户服务和不同数据库导出，都不是同一套筛选。[下游交付与市场数据服务](../topics/operations-delivery-and-market-data.md)集中说明替换窗口、选数日期、状态标志和重复出口的差异。

<a id="scope"></a>
## 怎么审计这组解释

[逐任务审阅账本](../evidence/operations-review.json)给出 203 项的家族、审阅层级、发布 SQL 全槽位行号和哈希、具体筛选、输出与来源的物理对象、TablePack/DDL 路径及缺口。`BUSINESS_SEMANTICS_EXPLAINED` 只表示该项在页面明确指出的对象、连接、时间或公式已经解释；`TEMPLATE_VERIFIED` 表示已核对传输/加工结构和变体，不代表所有字段的业务含义已确认；`LOCATED` 保留材料不足的项。

正文的 `任务号 · slot · 行` 指向该发布版本的 evidence JSON；行号是其中相应 `sqlSources.content` 的行号，不是 JSON 文件的物理行号。DDL 链接用于复核字段定义，定义里叫“唯一标识”不等于数据库已经约束唯一。

固定发布无 SQL 的 10 项是：204973、212278、219441、230204、237978、239327、239363、239991、246250、246559。按当前任务类别和 ID 核对精确任务包路径，除 212278 的 `task.json` 存在且 `sqlFiles=[]`，其余九项的该路径仍不存在。本组没有把同名 SQL 或别的任务替代成这些项的证据。其中 246250 已通过当前平台精确任务只读补查取得 SQL，见[ETF 成分回报的补充证据](../topics/operations-trading-and-settlement.md)；该脚本属于发布之后的独立补充，其余 9 项仍保留 `LOCATED`。另有 26 项虽未形成正式投影，但有发布 SQL，可核实文本中的传输筛选；账本同时保留它们的 `SCHEDULE_ONLY` / `COLLECTION_FAILED` 状态。
