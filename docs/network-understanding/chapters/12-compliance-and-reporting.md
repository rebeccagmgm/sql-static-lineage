# 合规与报送：业务事实怎样成为客户资料、交易记录和复评候选

合规加工从业务系统取得客户身份、关系、合约、事件、持仓和账户信息，再按使用方的字段组织结果。因此，一条合规“成交记录”可能表示合约建立或部分终止；一条客户记录可能合并多个来源的证照与联系人。读这些结果，首先要问每行代表什么、身份如何转换、日期取自哪里。

本页连接衍生品合约交易接口、机构及产品客户接口，以及 AML 的客户身份、资金特征、名单辅助控制和复评候选。这里讨论已核读的 SQL 规则，不据此评价法律合规性或声称报送已被接收。接口全字段、受益人、完整黑名单与 CISP 等缺口在页末保留。

## 一笔业务在这里怎样展开

| 阶段             | 业务对象与主要处理                                                       | 输出怎样使用                                     |
| ---------------- | ------------------------------------------------------------------------ | ------------------------------------------------ |
| 识别人和机构     | 业务系统客户号、统一主体、交易对手映射、管理人、法人、控制人和授权办理人 | 组织机构客户与产品客户资料；保留来源和日期差异   |
| 组织交易记录     | 合约建立、部分终止、最终终止；关联标的、价格、名义本金和账户余额         | 合规交易接口；其“数量”和“金额”必须按分支解释     |
| 补充客户资料     | 按客户号与营业部关联限制措施、代理人、资金信息，做码值翻译               | AML 综合客户资料；关联不到与字段为空仍是不同情形 |
| 选择后续处理对象 | 客户状态映射、当前与历史复评记录合并、日期门槛和未完成记录排除           | 待计算标志或告警候选；不是已复评、已派发的证明   |

73353、73354 的 SQL 分别直接读取 `dm_cmpl_n.unit_cust_info` 和 `dm_cmpl_n.pdt_cust_info_all`，组织 AML 综合机构与产品资料，已经确认这条消费联系。它不证明某批数据实际送达、完整纳入或处理成功。

## AML 的客户资料补充：客户号还需要营业部

76489 的查询把 `aml_config` 中开启的指定配置按逗号拆开，追加到 `t_aml_config`；随后读取并覆盖 `aml_client_inte_unit`，按 **客户号与营业部** 关联 `aml_client_unit`，补入限制措施和代理人资料，再用字典 `1041` 翻译代理人证件类型。相同客户号跨营业部不能自动合成一条。

该份发布文本还有两处会影响使用：资金关联使用字面日期 `aml_fund.oc_date = 20260522`，没有保留报表日期占位符；输出 `id_begin_date/id_end_date` 实际使用 `sale_begin_date/sale_end_date`。这不能支持把该份材料的资金叫作“今天的资产”，也不能仅按输出字段名解释证件期限。字面日期是否由上游模板参数展开、配置追加是否由其他步骤清空、覆盖读取同一表在实际引擎中的执行方式，本次均未核实。来源：76489 `query` 1–41。

## 客户状态、复评候选和实际派发是三个环节

79144 读取并覆盖 `aml_client`，只按 `client_status = '0'` 把 `exec_ctr1` 写成 `'1'`，其他状态写成 `'0'`；其余列主要沿用。这个标志表示该 SQL 的状态映射，不包含评分计算或实际复评结果。来源：79144 `query` 1–15。

244647 合并当前与历史复评检查记录，只纳入客户状态 `'0'`、检查状态 `'5'`、删除标志 `'0'`、有效结束日期大于零的记录。它按 `inner_client_id`，依归档日期和发生时间倒序选一条，筛出到期门槛内的记录，再排除存在未完成评级和指定生效日期客户的内部客户号。

**这一份发布 SQL 使用字面基准日期 `2026-08-27`，门槛是该日加八天，输出分区也为该日。** 因此这份材料不能直接解释为“当前未来八天应复评的客户”；日期是否来自模板展开仍需原始配置证据。最后一步还重新关联当前检查表，其条件与前面挑选最新记录的条件并不完全相同；同一内部客户号多个外部客户号、排序并列，以及 `NOT IN` 子查询出现 NULL 时，均需核实数据约束。输出是告警候选客户号，不证明通知已发送或复评漏派发已经业务确认。来源：244647 `query` 6–59、`create` 6–22。

## 当前还不能据此回答什么

AML 新增正文解释了 15 项任务中的具体关键规则，没有承诺整项任务全字段验收。73353、73354 的长接口转换、77827 的其余客户同步仍有未读细节；76580、76585 的出口、78292 的受益人和 95819 的完整黑名单仍需业务核读。部分 SQL 的参数展开与执行包装不完整疑点单独保留，不将文本疑点当作已经发生的系统故障。相关范围见 [AML 审阅记录](../evidence/aml-review.json)与[内容覆盖账本](../evidence/coverage-summary-19-reviews.md)。

同样，CISP 报送、托管估值和审计消费各有独立输入与口径，不能因为它们也叫“报送”而套用本页规则。固收保证金与 A1020 的已知证据见[固收的资金与交付](../topics/fixed-income-funds-and-delivery.md)。本页没有确认监管文件版本、实际报送频率、运行成功、送达或接收回执。
