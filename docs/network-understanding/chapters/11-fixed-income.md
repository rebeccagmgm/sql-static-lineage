# 固收：从合约与账户到规模、盈亏、资金和客户服务

这里的固收数据网络围绕两条业务线展开：TITANS 管理期权、收益互换及其账簿、结构腿、生命周期和持仓；衡泰交易与账户模型进入债券、回购、信用产品及客户协同统计。两条线在客户、机构、销售和 CRM 使用场景中相遇，但没有一张表能代表全部固收业务。

本主题解释固定发布中实际归属 `DM_FII_N` 的 57 项、`DM_FII_N_TEMP` 的 11 项及 `DM_FII_TEST` 的 7 项，共 75 项。临时 topic 可能写入正式 schema，正式 topic 也可能包含没有部门筛选的公共宽表；因此本文按实际 SQL 的读写、筛选和粒度解释。“固收任务”不自动意味着“只包含固收数据”。

## 先回答：业务规模到底量了什么

<a id="funds"></a>
## 资金余额、保证金日报和推送分别证明什么

<a id="scope"></a>
## 证据怎样使用

[逐任务审阅账本](../evidence/fixed-income-review.json)固定 75 个任务 ID，记录全部可用发布 SQL 的槽位、行号、哈希和精确物理对象的 TablePack/DDL。正文的“任务号 · 槽位 · 行”指相应 evidence JSON 中 `sqlSources.content` 的行号。元数据说明只用于解释字段定义；DDL 注释中的“主键”不等于唯一性已被验证。

`BUSINESS_SEMANTICS_EXPLAINED` 只覆盖页面明确解释的业务对象、公式、连接与时间；`TEMPLATE_VERIFIED` 表示已核实传输/加工模板及特有差异；`LOCATED` 表示具体材料缺口。发布中的静态 SQL、当前平台补查、元数据登记状态和真实运行是不同证据。本文没有执行业务 SQL，也没有据此声称下游已收到正确数据。
