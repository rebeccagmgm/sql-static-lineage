# 香港普通互换：事件金额、佣金和返息基数怎样进入收入

本页沿 `HK_TRS_DEMO` 从逐日本金和交易事件算到最终日报。与[普通期权主线](README.md)相比，香港普通互换增加**交易佣金**；返息费用互换还会替换年化项使用的本金。两项都属于[02收入CASE](02_原始当日收入.sql)的普通TRS分支，没有另外一套累计输出。

## 一、先固定同一份合约、四个计提日

以下为构造输入，金额假设已用同一计价单位，非生产记录。每个连接在本例均只有一条匹配记录。

| 输入 | 本例值 | 来源和进入条件 |
| --- | --- | --- |
| 合约/客户 | HK_TRS_DEMO / HK_CLIENT_DEMO | 销售主信息及香港准入客户，管理归属至少一组机构非8846 |
| 业务/源类型/香港分类 | TRS / N_CROSS_SWAP / N_CROSS_SWAP | [01](01_合约日与资料.sql)按香港名单重新分类；不是特殊LONG_HOLD_SWAP |
| 香港标的类型 | EQUITY | 源标的EQUITY，无优先命中的两类期货类型 |
| 日期/账簿 | 2026-09-18期初、09-20结束；09-21加工；OTCHK-互换-ISDA | 通过香港范围；提前终止日NULL |
| 主信息本金/汇率 | 初始3,650,000；`Cny_Ex_Rate=1` | 期初佣金直接用初始本金；其他日事件佣金用这份汇率 |
| 逐日本金 | 18/19/20/21日依次3,650,000 / 2,920,000 / 1,825,000 / 0 | 107491的det，代表各日动态本金，不从本页事件金额倒算 |
| 价差 | 合约年化0.006，9月18日起生效 | 合约号＋计提日；来源和过滤见[03](03_参数匹配.sql)第一节 |
| 基准 | 合约年化0.004 | 合约号，不按每个计提日挑版本 |
| 佣金 | 合约0.001，9月18日起生效；客户回退参数0.002 | 合约号＋计提日优先；客户＋TRS＋EQUITY＋期初日作为回退 |
| 收入比例/引入经办 | 0.7 / 0.3 / 0；有引入经办 | 三组收入比例与本金40/60分别使用 |

佣金参数本身的生产/匹配见[公共佣金专题](../../公共加工/08_经营系数_佣金/README.md)，使用的是同一份HK_TRS_DEMO。本页继续解释选中0.001之后乘什么、哪一天乘以及最后输出多少。

## 二、9月19日发生额为什么是365,000

[04_返息基数与交易事件](04_返息基数与交易事件.sql)的evt连接两路事件，先UNION ALL，再按合约与事件日汇总。为了观察这个行为，本例特意给两路各一条相同输出合约、日期的构造记录，不据此断言真实生产的两路都会同时存在。

| 来源 | 本例记录及匹配 | 进入汇总的金额 |
| --- | --- | ---: |
| 普通TRS主事件＋结构腿明细 | 主事件状态3、CLOSE_STOCKS、事件日09-19；按事件源ID＋合约ID匹配结构腿，`Occu_Qty=-1000`、`Pric=100` | `abs(-1000)×100=100,000` |
| FAST事件 | BUY方向、OPEN事件，交易日09-19，`Chg_Vol=2650`、`Mtch_Full_Pric=100` | `abs(2650)×100=265,000` |
| 当日汇总 | 同一 `Otc_Comp_Agt_Id`、同一事件日 | **365,000** |

合约主信息另带 `Inr_Seri_No=HK_TRS_SOURCE`，evt输出合同键也为HK_TRS_SOURCE；真实ON用这个源合约身份与计提日接回，不是直接拿展示合约号或 `Otc_Seri_No` 连接。

数量取绝对值，价格不取绝对值；UNION ALL不去重。这个365,000是**交易发生额**，不是净增仓165,000，也不是9月19日动态本金2,920,000。普通TRS事件有状态/日期过滤；FAST分支有自己的方向/事件类型条件，原文未补相同状态和2024年日期条件。这些差异均保留。

本例9月20日没有事件，evt没有匹配到记录。公式通过 `coalesce(evt.Occu_Amt,0)` 得到0；它不会把19日发生额延续到20日。

## 三、每天分别算年化贡献和交易佣金

[02](02_原始当日收入.sql)普通TRS“年化＋年化”的表达式同时算三项：

```text
存续日内：
年化价差 = det动态本金 × 0.006 ÷ 365
年化基准 = det动态本金 × 0.004 ÷ 365
交易佣金 = 佣金基数 × 0.001

佣金基数：期初日 → info初始本金
          其他日 → coalesce(evt事件发生额,0) × info.Cny_Ex_Rate
```

`commis_calc_type`虽然被参数JOIN读入，收入没有用它判断年化/绝对分支；佣金也没有除365。期初日优先取初始本金，本例不需给18日再补一笔同额事件才能算佣金。

| 计提日 | 年化价差 | 年化基准 | 佣金基数 | 佣金0.001 | 原始收入 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 9月18日 | 60 | 40 | 初始本金3,650,000 | 3,650 | **3,750** |
| 9月19日 | 48 | 32 | 事件365,000×汇率1 | 365 | **445** |
| 9月20日 | 30 | 20 | 缺事件补0×汇率1 | 0 | **50** |
| 9月21日 | 0 | 0 | 不在存续区间，外层IF返回0 | 0 | **0** |

最后一日不是把历史收入扣回，而是这行原始收入为0。期初/结束边界在普通TRS分支包含首尾；提前终止日非NULL时替代期末日。

## 四、同一笔445如何进日报

这份合约香港分类为N_CROSS_SWAP，不是期权两类保底对象，所以[05](05_保底与历史奖励.sql)把原始收入3750/445/50/0原样作为调整后收入；香港没有金仕达系统费用扣除层。

[06](06_分配与累计.sql)按合约＋香港分类、计提日累计，每日分别乘三组比例后再累计：

| 计提日 | 日报当日收入 | 总累计 | 第1组累计70% | 第2组累计30% |
| --- | ---: | ---: | ---: | ---: |
| 9月18日 | 3,750 | 3,750 | 2,625 | 1,125 |
| 9月19日 | 445 | 4,195 | 2,936.5 | 1,258.5 |
| 9月20日 | 50 | 4,245 | 2,971.5 | 1,273.5 |
| 9月21日 | 0 | 4,245 | 2,971.5 | 1,273.5 |

因此[07](07_日报输出.sql)的9月19日这一行是 `Accrued_Date=2026-09-19`、`busi_date=2026-09-21`、`Curr_Prvs_Sales_Income=445`、`Accum_prvs_sales_income=4195`。香港只输出三组累计值，没有三组当日收入列。

本金另做40/60：9月19日动态本金主经办1,168,000、引入1,752,000；这两个数不参与上表70/30收入计算。互换分组02的当日 `Absl_Nom_Prin=0`，但原SQL `Accum_Absl_Nom_Prin` 实际使用动态本金累计表达式，所以20日为8,395,000，不能从字段名推断应为0。

## 五、只改佣金参数，观察结果怎样不同

其他输入都固定，先将合约佣金置NULL：每个字段COALESCE回退客户0.002，所以佣金翻倍，18/19/20/21收入7400/810/50/0，累计8260。不是价差、基准也一起换成客户侧。

再单独把两路佣金都置NULL：`0×NULL`仍为NULL，20日即使没有交易也一样。存续三天原始收入都变NULL，结束后外层IF仍返回0；05不做TRS保底，日报当日NULL/NULL/NULL/0。06累计表达式COALESCE每项为0，所以总累计和组累计显示0。**累计0不能证明当日收入都成功算成0。**

只缺事件不缺佣金时则不同：20日是完整数值50。只缺主信息汇率时，其他日 `0×NULL`或`事件×NULL`也可使佣金项为NULL；期初日直接用初始本金，没有用这份汇率。SQL未在这一路给汇率补1。

## 六、返息费用互换换的是哪一个本金

继续固定同一组日期、初始本金、逐日本金、事件和佣金，把源类型改FEE_SWAP、用途改REBATE_INTEREST，香港分类也变FEE_SWAP，合约仍处在允许账簿/客户范围。以下是观察分支的一组构造变体，不表示修改真实合约。

[04](04_返息基数与交易事件.sql)从 `d_trd_daily_rebate_interest` 按加工日取快照，再用 `KEY_INSTRUMENT_ID=info.Otc_Seri_No`、`substr(calc_date,1,10)=det.busi_date` 匹配。本例三天 `DAILY_BASE_AMOUNT=3,650,000`；源注释是“本日计息基数”，不能直接称它是动态名义本金。

汇率来自 `t02_fxr_cfets_quot`，按 **info结算币种＋计提日**，来源TIT、分组01，三天中间价均0.5；与交易佣金使用的主信息汇率1分开。于是年化两项所用本金每天为1,825,000：

```text
年化价差＋基准 = 本日计息基数3,650,000 × 当日汇率0.5 × (0.006+0.004) ÷ 365
               = 50
交易佣金仍为3650 / 365 / 0，不用上面的0.5再折算一次
最终日收入 = 3700 / 415 / 50 / 0
最终累计 = 3700 / 4115 / 4165 / 4165
```

这份变体仍不做期权保底。第1/2/3组最终累计2915.5/1249.5/0；9月19日输出收入415、累计4115、组累计2880.5/1234.5/0。展示的 `Dyna_Nom_Prin` 仍是det的2,920,000，本任务没有把展示本金改成1,825,000；所以不能只拿日报动态本金乘年化系数复算这条返息收入。

仅缺当日中间价：公式补1，年化贡献每天100，收入3750/465/100/0，累计4315。仅缺本日计息基数：即使有当日汇率，年化项仍NULL，存续收入NULL；本例按年化＋年化分支，不会自动回退det本金。年化项才切换本日计息基数，绝对项始终使用期初初始本金。

## 七、四种计算组合仍在一个CASE里

以第三节普通TRS输入为准，绝对价差也假设0.006、基准0.004，仅改变两类计算方式：

| 价差/基准 | 18日 | 19日 | 20日 | 21日 | 主要差异 |
| --- | ---: | ---: | ---: | ---: | --- |
| 年化/年化 | 3,750 | 445 | 50 | 0 | 两项随每日本金计提，另加佣金 |
| 年化/绝对 | 18,310 | 413 | 30 | 0 | 期初基准14,600一次确认，后续只留年化价差与佣金 |
| 绝对/年化 | 25,590 | 397 | 20 | 0 | 期初价差21,900一次确认，后续只留年化基准与佣金 |
| 绝对/绝对 | 40,150 | 365 | 0 | 0 | 期初两项36,500一次确认，后续存续日仍可有事件佣金 |

全部保留原CASE和加法位置，没有把四种分支强行抽成一个通用表达式。固定输入是为了看清这份SQL，不验证真实参数单位、事件唯一性或币种来源。复核用[checks.test.mjs](checks.test.mjs)从实际交付SQL提取事件聚合、收入、调整和累计；不是另抄一个简化公式自证。
