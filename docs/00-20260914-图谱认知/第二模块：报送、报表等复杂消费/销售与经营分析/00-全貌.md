# 销售与经营分析

同一组公共加工（销售基础、管理归属、逐日金额）支撑多条经营结果。先选要解释的收入，再沿该专题读参数、公式、归属和输出；需要追来源时，回查[公共加工](../公共加工/README.md)。

## 先选一条收入路径

| 要理解什么 | 阅读入口 | 这条路径新增的重点 |
| --- | --- | --- |
| 交叉销售收入 | [118141：交叉收入](118141_交叉销售收入/README.md) | 普通期权、普通互换、AIRBAG和金仕达；原始收入、保底或系统费用、三组归属与累计 |
| 对内销售收入 | [114013：对内收入](114013_对内销售收入/README.md) | 对内分类、基础系数乘数、B2B初始估值、内部主／引入经办收入分配 |
| 香港销售收入 | [220979：香港收入](220979_香港销售收入/README.md) | 香港分类、返息计息基数、交易事件佣金、香港参数及历史奖励 |

每个入口都对应本任务的主脚本、必要模块和完整SQL。公共查询按原样被使用，各消费的分类、筛选与公式在自己的主线解释；它们不是把同一份收入换一个名称输出。

## 公共结果怎样在这里分叉

| 同一个问题         | 交叉118141        | 对内114013                  | 香港220979                    |
| ------------- | --------------- | ------------------------- | --------------------------- |
| 用哪套经营分类？      | 使用公共主信息的经营分类    | 本任务优先规则＋对内分类映射，再回退其他类别    | 本任务重新形成香港合约与标的分类            |
| 哪些参数共同生产？     | 合约价差、合约基准等      | 价差T99的INR记录、内部合约基准及内部基础参数 | 部分共同合约参数＋香港专用配置；多张配置直接读OIS  |
| 40%／60%用来分什么？ | 普通主／引入经办的本金     | 内部主／引入经办的收入               | 普通主／引入经办的本金                 |
| 三组介绍比例用在哪里？   | 三组当日收入及累计       | 此日报按内部经办分配，不能套三组公式        | 三组累计收入；没有与118141相同的三组当日收入输出 |
| 历史奖励从哪里读？     | 203358整理的收入奖励汇总 | 本查询没有这一层期权保底调整            | 香港奖励源表，本查询内汇总               |

详细的连接身份、日期及适用范围见[公共结果如何进入收入与规模](../公共加工/07_公共结果如何进入收入与规模.md)。比如销售基础和管理归属的`busi_date`是本次快照日，逐日金额的`busi_date`是计提日；三者按合约号连接，不自动证明实际一对一。

**参数查询与日报分别生成。** 118143、113993、220981是交叉、对内、香港的参数查询；对应日报自行读源参数，没有先读取这些参数查询DM表。以对内为例，113993展示计算方式时优先价差，114013普通收入计算时优先类型基础参数；参数页面的展示不能直接替代日报公式。

## 证据范围

原有专题沿用图版本`9dbe5623…`（2026-09-16）绑定材料；本轮114013补入8月31日采集的本地调度SQL，220979的9月1日快照与公共目录冻结副本一致。参数生产另有9月5日快照，各专题索引保留具体来源和哈希。整理日期不等于源SQL更新日，也不证明这些快照属于同次生产运行。
