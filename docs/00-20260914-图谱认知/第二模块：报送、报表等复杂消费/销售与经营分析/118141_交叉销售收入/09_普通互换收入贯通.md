# 普通互换：持仓变化怎样变成每天的销售收入

普通互换这条路不难在收入公式，而难在**初始本金、加工日持仓、历史计提日本金不是一回事**。先把金额来源分清，再接[118141主脚本](00_主脚本.sql)的收入、调整、分配和输出。

本页是普通互换路径，不包括优先命中的 AIRBAG、关联合约非空的 LONG_HOLD_SWAP、金仕达，也不包括入口已排除的费用互换、FAST 和香港部门。它们不能仅因 `Busi_Type=TRS` 就套本页公式。

## 1. 先认清两条本金线

```text
当前快照内可见的历史持仓：每个“腿＋标的”挑最早记录
  → Σ(期初交易价 × 初始数量)，按腿汇总
  → 合约主信息换算人民币 → info.Init_Nom_Prin（初始本金）

当前快照内的历史持仓：按实际源业务日取当日记录
  → Σ(期初交易价 × 当日数量)，按内部交易键＋日期汇总
  → 107491选择期初／结束后／普通日期规则
  → det.Dyna_Nom_Prin（这一个计提日的动态本金）
```

`info` 是 `pdata_n.t98_otc_deri_comp_sale_info`（合约销售基础），`det` 是 `pdata_n.t98_otc_deri_comp_sale_adtnl_det`（逐日本金与费用）。118141 连接两者时用 `Agt_Id` 合约号；互换持仓先前连接用的则是内部交易键 `Inr_Seri_No`，不能混用。

| 金额 | 实际生产位置 | 最容易混淆的地方 |
| --- | --- | --- |
| 初始本金 `info.Init_Nom_Prin` | [初始持仓](../../公共加工/01_合约主信息/sql/04_业务模块/02_普通互换/07_初始持仓.sql) → [本金与汇率](../../公共加工/01_合约主信息/sql/04_业务模块/02_普通互换/10_本金与汇率.sql) | 每个腿＋标的各选最早可见历史，未必是同一天；初始价×初始数量，不是当前市价×当前数量 |
| 逐日本金 `det.Dyna_Nom_Prin` | [普通互换历史持仓](../../公共加工/03_逐日本金与费用/03_普通互换历史持仓.sql) → [107491主脚本](../../公共加工/03_逐日本金与费用/00_主脚本.sql) | 每个历史日分别算；不是把主信息的加工日动态本金复制到每天 |

两条持仓线都读取 `odata_n_tit.d_pos_trs_leg_his_pos`（【AI】持仓-TRS浮动及结构化腿历史持仓）。逐日线还经 `d_ref_trs_leg`（TRS腿基本信息）只选结构腿，再按交易汇总。第一条的按腿汇总与第二条的按交易汇总不同，不预设多腿情况下金额相等。

107491 对普通互换的选择顺序是：**期初日取初始本金；晚于结束日取0；其他日期取该日持仓金额×汇率，乘积为空补0。** 它不把昨天的持仓自动延续到今天。以下算例只设一个结构腿、一个标的，所有连接各匹配一条记录。

## 2. 同一份合约的输入

以下都是构造数值，不是生产记录。年份2026，金额假设为人民币元；合约人民币汇率为1。

| 项目 | 本例 |
| --- | --- |
| 合约 | `TRS_DEMO`，业务类型TRS，经营类型 `TRS_N_STOCK`，分组02；不命中特殊分支 |
| 日期 | 9月18日期初，9月20日期末，无提前终止；9月21日加工 |
| 初始持仓 | 期初交易价10 × 初始数量365,000 = 3,650,000 |
| 客户与归属 | 归属中至少一组机构不是8846；有引入经办人；三组收入比例0.7、0.3、0 |
| 合约价差 | 原合约号匹配TRS_DEMO，年化0.006，生效区间覆盖18—21日 |
| 合约基准 | 原合约号匹配TRS_DEMO，年化0.004；本JOIN不按计提日选择版本 |
| 其他参数 | 客户类型价差、类型基准无匹配；成本率不影响普通价差＋基准公式 |

参数已通过各自来源、删除和身份过滤。完整匹配规则在[03_参数匹配](03_参数匹配.sql)，这里不另造一套简化JOIN。

| 计提日 | 源持仓的期初价×当日数量 | 107491交给118141的动态本金 | 为什么 |
| --- | ---: | ---: | --- |
| 9月18日 | 10×365,000 | 3,650,000 | 实际优先取主信息初始本金；本例恰好与持仓相等 |
| 9月19日 | 10×292,000 | 2,920,000 | 数量减少，按这一天的持仓金额计算 |
| 9月20日 | 10×182,500 | 1,825,000 | 结束日仍计算，不提前归零 |
| 9月21日 | 不影响本行选择 | 0 | 已晚于结束日 |

## 3. 从本金走到当日收入

[02选择入口](02_原始当日收入.sql)先检查特殊分支，本例均不命中，随后进入[02.4_普通互换原始收入](02.4_普通互换原始收入.sql)的“价差年化＋基准年化”。只想看互换公式时，直接打开02.4；它由02实际引用，不是另一份参考副本。

```text
有效日期内的原始收入 = 当日动态本金 × (0.006 + 0.004) ÷ 365
18日：3,650,000 × 0.01 ÷ 365 = 100
19日：2,920,000 × 0.01 ÷ 365 =  80
20日：1,825,000 × 0.01 ÷ 365 =  50
21日：不在定价起止区间内            =   0
```

这不是互换客户结算损益，也不是现金支付；是本任务按本金和经营参数形成的销售收入。价差、基准的“计算类型”和“系数”各自取合约侧优先、NULL才回退类型侧，零不会触发回退。

## 4. 调整、分配和日报

[04_收入调整](04_收入调整.sql)只有金仕达系统费用和两个期权经营类型的保底分支。本例都不命中，所以**普通互换的100、80、50不会套用期权0.1%保底**。

[06_分配与累计](06_分配与累计.sql)再用三组介绍比例分配：

| 计提日 | 调整后当日收入 | 第1组70% | 第2组30% | 第3组 | 合约累计收入 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 9月18日 | 100 | 70 | 30 | 0 | 100 |
| 9月19日 | 80 | 56 | 24 | 0 | 180 |
| 9月20日 | 50 | 35 | 15 | 0 | 230 |
| 9月21日 | 0 | 0 | 0 | 0 | 230 |

收入累计按合约＋经营类型、按计提日排序。第1组最终累计161，第2组69。初始本金另按主经办／引入经办分成1,460,000和2,190,000；**本金40/60不再叠乘到上表收入上**。

[07_日报输出](07_日报输出.sql)不另算收入。9月20日那一行的 `Curr_Prvs_Sales_Income=50`、`Accum_prvs_sales_income=230`、`Accrued_Date=2026-09-20`，而 `busi_date=2026-09-21`；其他三行的加工日也都是21日。多数输出列转换为字符串。

## 5. 只改一个条件，会发生什么？

**提前终止日改成19日，先固定det输入以单看118141：** 年化收入变成100、80、0、0，累计停在180；没有期权式保底。真实重新加工时107491也会按新结束日处理本金，不能把这里的隔离算例当作已发生的历史重算。

**把基准系数改成0，类型侧即使有0.004也不接替：** 收入变成60、48、30、0。只有合约系数为NULL时才回退到类型侧。

**若9月19日det本金本身为NULL：** 展示的动态本金会补0，但原始收入公式直接读det原值，收入为NULL；后续累计对NULL收入补0。不能反过来说“看见展示本金0，所以该行收入必然是数值0”。

## 6. 年化／绝对不是四套不同业务

它们是同一份合约的两项收入分别选择计算方式。为便于复算，另设绝对价差0.002、绝对基准0.001，年化值仍为0.006与0.004，其他输入不变：

| 价差／基准 | 9月18日 | 9月19日 | 9月20日 | 9月21日 |
| --- | ---: | ---: | ---: | ---: |
| 年化／年化 | 100 | 80 | 50 | 0 |
| 年化／绝对 | 60＋3,650＝3,710 | 48 | 30 | 0 |
| 绝对／年化 | 7,300＋40＝7,340 | 32 | 20 | 0 |
| 绝对／绝对 | 7,300＋3,650＝10,950 | 0 | 0 | 0 |

年化项用**动态本金**、有效日期内逐日计算；绝对项用**初始本金**、仅期初日计算。不要把“绝对方式”误读为对收入取绝对值。

最后一处容易误读：本任务给普通互换的展示列 `Absl_Nom_Prin` 填0，但 `Accum_Absl_Nom_Prin` 原式仍累计有效日动态本金，本例最终为8,395,000。它既不是该展示列的简单累加，也不是收入的绝对计算方式；这里解释原式，不自行修正字段口径。
