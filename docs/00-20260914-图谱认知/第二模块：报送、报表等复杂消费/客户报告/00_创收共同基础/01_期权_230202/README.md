# 期权客户创收：合约日怎样得到创收与期初NPV

任务 **230202**，写入共同创收日报 `DM_OTC_N.OTC_REV_DAILY_RPT` 的 `grp_id='01'` 分支。依据2026-09-22从平台取得的SQL，不再使用缺少末尾两个业务字段的旧图版查询。

**先理解动态对冲的一组两份合约，再看静态分摊与安全气囊。**这里计算的是客户创收，不是118141销售收入分配；不是把之前的“价差×本金”套进来。

## 一、这条主线到底做了什么

```text
报告日合约主信息 info ──INNER JOIN── 合约逐日明细 det
                              │ 合约×计提日（非唯一性承诺）
       ┌──────────────────────┼───────────────────────────┐
       │                      │                           │
 每日费用、客户USCC       模拟对冲／持仓盈亏         参考利率／汇率／成本参数
       │                      │                           │
       └──────────────────────┼───────────────────────────┘
                              ▼
         当日创收 Curr_Rev：先气囊，再动态，再静态，否则0
         NPV创收 Opt_Npv_Curr_Rev：独立按柜台判断、仅期初日确认
                              │
       输出74列（含报告日busi_date、分支grp_id两个分区列）
```

SQL先写SELECT表达式，再写FROM来源；**第一遍阅读可以先看[01合约日底座](01_合约日底座.sql)、再对照[06当日创收](06_当日创收.sql)**。主脚本中的include只是按原SQL位置引用文件，不代表数据库物理执行顺序。

### 合约日底座不是“所有存续期权”

普通／动态入口读取报告日的[合约主信息](../../../公共加工/01_合约主信息/README.md)，限制OTC账簿、`grp_id='01'`、`COALESCE(提前终止日,期末日)>='2022-01-01'`，排除静态柜台及`Agt_Clas_Cd='TRS_INNER'`。**这不是协议状态筛选，也不要求合约在报告日仍存续。**静态入口另读，未写同样的TRS_INNER排除条件，不能为了文案整齐把两入口说成完全相同。

然后按合约编号连接[107491逐日本金与费用](../../../公共加工/03_逐日本金与费用/README.md)产出的 `T98_OTC_DERI_COMP_SALE_ADTNL_DET`。该读取只保留明细自身 `busi_date BETWEEN Strt_Pric_Date AND End_Pric_Date` 的行；INNER JOIN没有匹配就没有结果。本任务没有另外写“明细日<=本次报告日”，也没有把info的提前终止日再次用到明细过滤中。上游明细是否已截断，应在107491核对，不能在这里臆加条件。

因此输出一行可以按“合约＋计提日”理解，但左侧客户、估值等一对多命中仍可能扩行。本任务没有总去重；后面的窗口在**全部连接后的行集**上计算，重复不只影响最终行数，也会改变金额。

## 二、正常例子：两份动态对冲期权，共同分配一个标的残差

以下为**构造数据**，不是生产数据。报告日快照取2026-09-22，其中两份合约A、B都有2026-01-05的逐日明细；期初定价日也都是1月5日。两份合约属于同一客户甲，柜台均为`DYNAMIC_HEDGING`，不是RISKY/AIRBAGX气囊类型，所有连接恰好一条。

### 2.1 先把原始来源摆在一起

| 来源与字段 | 中文用途 | 合约A | 合约B |
| --- | --- | ---: | ---: |
| `T98_SB_TIT_DAY_HOLD_INDX.Simu_Hedg_Pal`，别名pe | 本合约模拟对冲盈亏 | 100 | 200 |
| 同表 `delta`，别名pe | 模拟对冲敏感度，用其绝对值作权重 | 30 | 70 |
| 同表 `Undrl_Sum_Compr`、`busi_date` | 窗口组键：标的汇总组合＋日 | U1／2026-01-05 | U1／2026-01-05 |
| `T98_OTC_BOOK_HOLD_SUM.Tdy_Yield`，别名pd | 本合约当日持仓盈亏 | 20 | -10 |
| 03模块汇总结果 `u.Tdy_Yield` | 对应标的当日总盈亏 | 400 | 400 |
| `t02_fxr_cfets_quot.mid_price`，别名mid | 本计提日、结算币种的人民币汇率 | 1 | 1 |
| 合约主信息 `Bgng_Npv`，别名info | 期初NPV | 1,000 | 2,000 |

400是**同一份标的日总盈亏**连接到两份合约，不是两份各400需要再合计800。SQL先把它与组内模拟盈亏之和相减，再用权重分配。

本例假设每行都匹配同一标的汇总、结算币种和汇率相同，这才便于做组内合计核对。真实SQL的两套标的键不同：

- `u`按 `info.Undrl_Wd_Cd = u.Map_Undrl_Cd`＋明细日连接。
- 窗口按 `pe.Undrl_Sum_Compr`＋`pe.busi_date`分组。

不能仅凭都叫“标的”就假设它们永远一一对应，也不能在不同币种、不同匹配情况下无条件套用下面的组内守恒结论。

### 2.2 实际表达式怎样一步步算

[06动态分支](06_当日创收.sql)对应的阅读公式是：

```text
组内绝对delta合计 = |30| + |70| = 100
组内模拟对冲盈亏 = 100 + 200 = 300
标的残差         = 标的总盈亏400 - 模拟对冲合计300 = 100

A的权重 = 30/100 = 0.3
A的创收 = (模拟100 + 持仓20  + 0.3×残差100)×汇率1 = 150

B的权重 = 70/100 = 0.7
B的创收 = (模拟200 + 持仓-10 + 0.7×残差100)×汇率1 = 260
```

本例合计410，可以核对为标的总盈亏400＋两份合约持仓盈亏净额10。**不是仅把400按30%／70%分配成120和280**，也不是模拟盈亏再全额叠加标的总盈亏。

### 2.3 NPV独立确认，最后怎样进入客户年度创收

[07NPV分支](07_NPV创收.sql)对动态柜台只检查本行 `info.Strt_Pric_Date=det.busi_date`。本例命中期初日：A输出NPV创收1,000，B输出2,000。

| 输出 | 合约A | 合约B | 含义 |
| --- | ---: | ---: | --- |
| `Curr_Rev` | 150 | 260 | 本日创收，已经按上述对冲公式形成 |
| `Opt_Npv_Curr_Rev` | 1,000 | 2,000 | 期初日的另一列NPV创收，不自动加回上一列 |
| `Accrued_Date` | 2026-01-05 | 2026-01-05 | 收入所属计提日 |
| `busi_date`／`grp_id` | 2026-09-22／01 | 2026-09-22／01 | 本次输出快照及期权分支 |

若客户甲本年只有这两条创收记录，[227701年度创收](../../01_年度创收_227701/README.md)的期权创收会累计 **410／10000＝0.041万元**。它求和的是`Curr_Rev`，不会把3,000元NPV列自动加进去。其他客户报表若读NPV列，需分别核其使用位置。

### 只改一个输入：标的总盈亏400改为500

模拟盈亏、持仓盈亏、delta都不变，新残差变成200：A创收180，B创收330，合计510。多出的100按30和70分给两合约。

若只将A的delta从30改为-30，权重与结果都不变，因为程序取绝对值。若将B移到另一个`pe.Undrl_Sum_Compr`组，则各自成为单行窗口：A为420、B为390，已经不是本例共同分配关系；这说明窗口键不是无关紧要的展示属性。

## 三、动态对冲的三种盈亏，究竟怎样接过来

| 结果别名 | 实际来源与连接 | 为什么需要它 |
| --- | --- | --- |
| `pe` | `T98_SB_TIT_DAY_HOLD_INDX`的TIT日终指标来源；场外流水号＋账簿＋明细日，且柜台为动态 | 给本合约模拟盈亏、delta和窗口组键 |
| `pd` | `T98_OTC_BOOK_HOLD_SUM`的TIT逐日持仓来源；场外流水号＋账簿＋明细日，无柜台限制 | 给本合约真实持仓日盈亏；静态分支也使用 |
| `u` | 账簿持仓＋报告日动态账簿资料，再补产品／腿／证券识别，按匹配标的＋历史持仓日求和 | 给动态对冲整体标的盈亏，供残差计算 |

`u`优先使用账簿附加资料 `T03_OTC_DERI_BOOK_ADTNL_INFO.Map_Undrl_Cd`；空串先转NULL，再回退证券基础资料 `t02_tit_scr_base_info.undrl_clas`。备用工具识别沿以下路径：

```text
历史账簿持仓的Src_Prd_Id
   → 报告日有效的T03_AGT_PRD_RELA_H交易产品关系
   → 报告日的T03_OTC_SWAP_COMP_LEG_INFO结构腿
   → 与历史持仓日相同的T03_OTC_SWAP_COMP_HOLD_INFO腿持仓
   → COALESCE(腿持仓产品号,原持仓产品号)
   → t02_tit_scr_base_info.in_code → undrl_clas
```

这条链混合“报告日的关系／账簿／腿资料”和“历史日持仓”，不是每张表都取同一个日分区。INNER JOIN动态账簿资料会决定哪些持仓进入u；后续LEFT JOIN保留缺失侧，但可能多匹配。具体业务含义为按当前映射重看历史还是其他制度设计，SQL本身不予证明。

## 四、静态对冲：同组本金分摊，不是delta分摊

静态入口先把自身合约号和`rel_agt_id`拼接、按逗号拆开，再按拆开的字符串排序，给每个合约取第一项作为 `prop_group`。比如A关联B、B关联A，且字符串A排在B前，两者能取到A作为组号。但**这不是自动求关联网络的连通分量**：多层关联、单向关联或不同写法不保证归到同组。

同一 `prop_group＋det.busi_date` 内，[06静态分支](06_当日创收.sql)实际用：

```text
本行比例 = det.Init_Nom_Prin
          ÷ SUM(排除三个指定客户后的 info.Init_Nom_Prin)
本行创收 = 本行比例 × SUM(pd.Tdy_Yield × 每行汇率)
```

注意分子来自**逐日明细det**，分母来自**主合约info**，并不是同一个字段别名换了写法。静态组没有使用动态`pe.delta`。

构造一组两合约，初始本金主信息和明细恰好相等：

| 合约 | info初始本金 | det初始本金 | 持仓盈亏pd | 汇率 | 期初NPV |
| --- | ---: | ---: | ---: | ---: | ---: |
| S1 | 100 | 100 | 40 | 1 | 1,000 |
| S2 | 300 | 300 | 60 | 1 | 3,000 |

分母400，组内盈亏100，创收分别为25和75。若两行均处于各自期初日，组内NPV4,000同样按25%／75%分配，输出1,000和3,000；若S1不是自己的期初日，S1的NPV输出0，窗口里的NPV合计却仍包含其源NPV，因为窗口没有先按期初日过滤。

只改S1的det初始本金为200，info仍为100：创收变为50和75，合计125，不再等于组内盈亏100。不要为了让例子守恒，把SQL分子误写成info。

程序还在分母中将三名指定客户 `DEV1100101715／DEV1100103266／DEV1100105899` 的本金置0，但分子、组内盈亏和NPV没有同样剔除。若S1是其中之一，分母变300，创收为33.333…和100，合计133.333…。客户名单的制度原因待确认，不能擅自称作“剔除内部交易全部影响”。

## 五、安全气囊：类型优先，三条公式不能混成一条

`Src_Contr_Type`为`RISKY`或`AIRBAGX`时，优先走[06前三个分支](06_当日创收.sql)，不再用动态／静态创收公式。**但07的NPV仍独立按柜台判断。**例如同一行既是AIRBAGX又是动态柜台，Curr_Rev走气囊，期初日NPV仍可非零。

### 5.1 共用输入先对齐

| 名称 | 实际来源与用法 |
| --- | --- |
| 其他费／期权费 | `T98_OTC_OPT_COMP_EDAY_PRVS_FEE.Tdy_Prvs_Fee`，按产品号＋日汇总；`Fee_Type_Cd='37'`为期权费，其余非37为其他费 |
| 预估期权费率 | 主合约 `info.Opt_Fee_Rate`，用于第一分支比例计算 |
| 初保线／基保线 | 主合约 `info.Init_Marg_Prop／Base_Marg_Rate`；有关联合约时部分公式改用基保线 |
| 是否有关联 | `COALESCE(info.Marg_Agt_Id,'')=''`判断无关联，NULL和空串同样算无关联 |
| 当日动态本金 | `det.Dyna_Nom_Prin`直接参与第二、三分支；不是08输出列补0后的值 |
| CNY成本 | OIS客户创收系数 `g_client_revenue_coefficient.value`，`currency='CNY'`，别名co_c |
| 非CNY成本 | 同表非CNY配置；HKD标的取HKD，否则取OTHER，别名co |
| 参考利率 | `t02_ira_ibor.ir`；HKD取HIBOR3M，其余取SOFR；除100后参与FLEXO分支 |
| 汇率 | 按**结算币种＋计提日**匹配，不按标的币种匹配；最后转换气囊整笔结果 |

三分支都有同一外框：`其他费＋处理后的期权费`，再乘汇率。若原期权费`<=0`，处理后的期权费直接为0，**不是把原负期权费加回**；但其他费仍保留。若原期权费大于0，扣成本后为负也不会再截零。

### 5.2 用一组输入比三条路径

统一构造输入：其他费10元、预估期权费率10%、动态本金1,000,000元、初保线20%、基保线10%、CNY成本3%、非CNY成本2%、参考利率源值5（除100后5%）、汇率1、无关联合约。

| 优先分支 | 额外条件／本例期权费 | 计算与结果 |
| --- | --- | --- |
| ① 人民币／HKD COMPOSITE | 标的CNY，或标的HKD且COMPOSITE；期权费100 | `10＋100×(1－3%/10%)＝80` |
| ② FLEXO | 未命中①且FLEXO；期权费200 | 净成本`5%＋2%－20%×3%=6.4%`；`10＋200－1,000,000×6.4%/365≈34.657534` |
| ③ 其余气囊 | 未命中①②；期权费200 | 净成本`3.5%－20%×3%=2.9%`；`10＋200－1,000,000×2.9%/365≈130.547945` |

①中如果标的CNY同时写FLEXO，仍先命中①，不能因为看到FLEXO就选②。HKD COMPOSITE也按①处理；其他HKD情形按后续条件判断。

只把“无关联”改成有关联：

- ①的校正因子变成`(1－20%)/(1－10%)=8/9`，结果`10＋100×(1－3%/10%/(8/9))=76.25`。
- ②的抵减比例从初保20%改成基保10%，净成本变6.7%，结果约26.438356。
- ③也把抵减比例换成基保线，但不采用①的8/9因子。

再只把②的期权费从200降到100，仍大于0，所以仍扣全部日成本，结果约 **-65.342466**。这与“原期权费<=0直接走0”的分支是两回事。

`0.035`、`365`、指定柜台与三客户名单的制度依据不由代码给出。本文解释程序怎样使用，不将其包装成已确认的定价制度。

### 5.3 成本如何跨生效日切换

05模块从报告日系数快照中筛选未删除、AIRBAGX、CAPITAL_COST配置，通过`LEAD(effective_date)`确定每条的终止日为下一条生效日前一天，再逐日展开。

例如同一CNY配置有：

| 生效日 | 成本值 | 在报告日2026-09-22快照内展开的范围 |
| --- | ---: | --- |
| 2026-01-01 | 3% | 2026-01-01～2026-06-30 |
| 2026-07-01 | 4% | 2026-07-01～2026-09-22 |

第一分支其他输入不变，6月30日为80，7月1日改用4%后为70。不是按本次报告日永远给所有历史日使用4%。同日多条有效配置没有明确次序规则，也没有去重；生效日前无历史配置时不会自动向前填值。

参考利率cr是另一条时间链：按平台交易日UDF选择每月末交易日数据，从下月1日展开到下一次区间开始前一日，最后延续至报告日。月末节假日、UDF交易日历和利率缺报情况须独立核验，不把测试里的普通日期运算当作平台交易日历。

## 六、缺失、零与提前终止：哪些会改变理解

| 场景 | SQL行为 | 不能误读成什么 |
| --- | --- | --- |
| 动态delta全0或缺失 | 分母为0，没有保护条件 | 不能宣称“无风险就创收0”；测试兼容层得到NULL，生产引擎行为须实测 |
| 动态持仓或模拟盈亏缺失 | 分别补0；u缺失也补0，残差仍继续计算 | 补0不证明资料完整，尤其可能分配出负残差 |
| 汇率缺失 | 按1计算 | 不证明源金额就是人民币 |
| 静态组本金分母为0 | 没有保护条件 | 不能默认平均分摊或输出0 |
| 气囊费用无匹配 | 其他费与期权费为NULL，未整体补0 | 不是无费用就无收入 |
| CNY／非CNY成本缺失 | 正期权费分支可能传播NULL；源参考利率缺失则单独补0 | `coalesce(cr.ir/100,0)`不能推广为所有成本都补0 |
| CNY成本明确为0 | 第一分支例子得到110 | 0与没有配置NULL完全不同 |
| 期权费率0、初保或基保为1 | 第一分支含除法，可能出现零分母 | 不擅自填默认费率或改公式 |
| 提前终止日存在 | 输出期末日优先取它、终止标志为1；当日创收CASE本身没有再次按该日截断 | 是否停止产生明细由上游det及入口决定，不是06另行处理 |
| 提前终止日空串 | COALESCE不回退；终止标志却为0 | 期末日回退与终止标志判断不是同一套空值规则 |
| 气囊也是动态柜台 | 气囊优先算本行Curr_Rev，但其已连接pe行仍在动态窗口中 | CASE没有将气囊行先从组内剔除 |
