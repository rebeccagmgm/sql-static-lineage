# 标签与协同：哪些是条件判断，哪些是奖励金额

这一组补充客户画像，不能把“有某标签”“有某种关系”和“已收到一笔钱”混成同一件事。

| 阅读问题 | 对应专题 | 输出如何产生 |
| --- | --- | --- |
| 为什么被标成前十大、单笔小、高换手或有垫资？ | [231146客户标签](01_客户标签_231146/README.md) | 三路条件并列产生标签；没有要求先进入同一份客户总名单 |
| 托管、研究、财富、商机各显示什么关系和金额？ | [232556部门协同](02_部门协同_232556/README.md) | 客户底座先展开四栏目，再补奖励与财富产品指标；栏目金额并不互斥 |

第一张表先问“命中了哪个条件”。规模前十可能因为并列超过十人；高换手不等于这里计算过换手率；有垫资不等于核验过实际付款。其“有垫资”还会进入229121客户综合指标，传递的是规则结果而不是额外风险证明。

第二张表先问“摘要和金额分别依据什么”。研究关系依奖励汇总行是否存在，财富关系却依据代签产品指标是否为正；财富奖励金额另算。因而可以“无财富代销”但有财富部门奖励，也可以“有财富代销”而金额缺失。

两者都要继续核身份键：日报客户名称＋USCC、按名称匹配的奖励、由交易对手关系映射的管理人，不能只因展示名称相同就断言是同一粒度。专题正常算例之后保留这些匹配变化的对照，不通过改生产SQL掩盖差异。
