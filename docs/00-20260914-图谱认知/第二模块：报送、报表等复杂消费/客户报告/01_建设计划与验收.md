## 每个任务必须过的验收

1. **业务入口**：回答为什么有这张表、统计谁、一行是什么、最后交给谁。英文关键字段旁给中文用途及真实来源。
2. **加工主线**：复杂 SQL 有主脚本和输入输出明确的模块；并列输入不画成串行。简单 SQL 保留完整，不强造层级。
3. **金额和条件**：明确字段值来源与过滤／连接／窗口的作用区别；日期、单位、NULL／0、重复匹配与 CASE 优先级不省略。
4. **连续算例**：同一客户／合约跨必要日期计算到底，构造数据明确标记。至少一个只改变单项条件的对照；不把另写的简化公式当作实际 SQL 验证。
5. **语义对应**：保存冻结来源与版本；只加注释／拆片段应完整 token 对应。结构改写需可还原映射并验证字段顺序、连接、过滤及窗口范围。
6. **阅读对应**：主脚本可找到模块来源和去向；链接有效；没有“先读所有上游才知道当前步骤”的死循环；未展开边界不冒充完成。
7. **收尾审查**：代码／测试变更独立审查，主代理还需按读者路线核读。自动测试通过不代替业务可读性，也不代替生产数据验收。

结构对照以合约主信息期权主脚本和107491主脚本为实物样板：输入、加工阶段、补充关联、输出必须在SQL中真正承接。不能只把原有长JOIN搬进独立文件，或用正文解释掩盖模块内部仍难读的问题；复杂模块继续拆实际阶段，短而完整的计算保留。每个模块应能定位真实源字段、输入粒度、计算结果和消费位置；不以文件数或CTE数量作为目标。

详细规范沿用[SQL 拆解与业务说明标准](../建设台账/SQL拆解与业务说明标准.md)。
