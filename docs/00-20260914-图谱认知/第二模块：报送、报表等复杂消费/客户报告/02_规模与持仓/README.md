# 三种规模怎样一起看：每天剩多少、今年新增多少、分布在哪些标的

这三份查询都读取 `DM_OTC_N.OTC_REV_DAILY_RPT`（合约创收日报），但回答不同问题。**先区分余额和发生额，再核对各自筛选范围。**查询本身很短，保留三份完整SQL，不再拆成没有独立业务意义的小片段。

下文单位与公式描述的是本次冻结的DM查询，不保证旧`gf_otc`测试落表同版。2026-09-23的[单客户实样](../06_单客户贯穿核验/README.md)中，3月规模走势数值具有亿元缩放特征，但8–9月源查询与搬运查询均未找到该缩放；不能直接拿旧值套下面的“元”口径。

```text
报告日的合约创收日报：一份快照里有多个合约、多个计提日
                 │
     ┌───────────┼──────────────────┐
     ▼           ▼                  ▼
 每日规模      业务统计             标的持仓
 公司＋日      公司＋业务类别       公司＋业务＋标的＋日
 每天剩多少    新增／存量／创收     本金分布在哪里
 单位：元      金额不换单位         本金÷10000：万元
```

三个结果并列生产，不是先汇总每日规模再拆回标的。金额如何在上游形成，见[创收共同基础](../00_创收共同基础/README.md)；这里不复制期权／互换／金仕达的创收公式。

## 一、先找准要读的那份SQL

| 要回答的问题 | 实际查询与结果表 | 一行是什么 |
| --- | --- | --- |
| 客户每天有多少期权、互换本金？ | [01_每日规模_227697.sql](01_每日规模_227697.sql) → `dm_otc_n.bi_otc_amount_change` | 公司USCC＋公司名称＋计提日，期权和互换各一列 |
| 各类业务去年／今年新增多少，当前存量和今年创收多少？ | [02_业务统计_228008.sql](02_业务统计_228008.sql) → `dm_otc_n.bi_otc_busi_stat` | 公司USCC＋公司名称＋原始业务类型＋合约类型描述，输出报告日 |
| 每天的持仓本金分布在哪些标的？ | [03_标的持仓_234355.sql](03_标的持仓_234355.sql) → `dm_otc_n.bi_otc_underlying_analysis` | 公司USCC＋公司名称＋原始业务类型＋标的代码＋标的名称＋计提日 |

“公司”不是只按名称分组：三者都同时使用 `USCC`（统一社会信用代码）与 `Cutp_Pty_Full_Name`（客户名称）。同一USCC不同名称会拆组；标的表同一代码不同名称也会拆组。

图谱确认的后续交付分别为：227697→230265→`gf_otc.bi_otc_amount_change`，228008→230262→`gf_otc.bi_otc_busi_stat`，234355→234407→`gf_otc.bi_otc_underlying_analysis`。这是交付路径证据，不是本次已核验前台展示或生产运行。

## 二、共同来源，却不是同一统计范围

三份SQL的输入表都只取**报告日快照**：源 `busi_date='${yyyy-MM-dd}'`；以下历史期间筛选的是该快照里的 `Accrued_Date`（计提日）。不是每天回到历史分区各取一次。

| 范围条件 | 227697 每日规模 | 228008 业务统计 | 234355 标的持仓 |
| --- | --- | --- | --- |
| 计提日 | 报告日前12个月～报告日，两端包含 | 上年1月1日～报告日，两端包含 | 同每日规模 |
| 生产分支 `grp_id` | **没有限制** | 01期权／02普通互换／03金仕达 | 同业务统计 |
| `Busi_Type` 业务类型 | 只收OPTION／TRS | 没有额外过滤 | 没有额外过滤 |
| `Strt_Pric_Date` 期初定价日 | 没有额外门槛 | **必须≥2025-04-01** | 没有额外门槛 |
| 输出 `busi_date` | 计提日 | 报告日 | 计提日 |

因此业务统计中的“去年新增”也不是无条件覆盖上一整年：例如2026年报告会因期初日门槛排除2025年1～3月开始的合约。SQL注释说这是采用新合约类型规则的范围；规则制度的生效依据不由本查询证明。

没有日历补齐。一个客户某天没有入选记录，227697／234355不会凭空生成一行零；业务统计有历史记录却没有报告日记录时，仍可输出该业务类别，只是存量为0。

## 三、金额字段不要被名字带偏

输入字段均来自上述创收日报，当前使用位置如下：

| 输入字段与中文意义 | 这里怎样用 | 不代表什么 |
| --- | --- | --- |
| `Dyna_Nom_Prin` 该计提日动态名义本金 | 每日规模按日求和；业务统计只汇总报告日；标的表按日、标的求和后÷10000 | 不是当日新增额，也不是本金变化额 |
| `Init_Nom_Prin` 初始名义本金 | 业务统计只在 `Accrued_Date=Strt_Pric_Date` 的起始日记录计入新增 | 不把存续期间每次加仓都计作新增 |
| `Curr_Rev` 当日计提创收 | 业务统计汇总当年记录，命名为 `real_pnl` | 本查询并未重新计算Delta；也不是客户投资盈亏 |
| `Opt_Npv_Curr_Rev` 当日期权NPV计提创收 | 业务统计单独汇总当年记录为 `npv_revenue` | 不与 `Curr_Rev` 自动相加 |
| `Undrl_Curr` 标的币种 | 业务统计的跨境期权存量条件：OPTION且不等于CNY | 不是客户注册地，也不是结算币种；互换不进入这一列 |
| `Undrl_Wd_Cd／Undrl_Name` 标的代码／名称 | 标的表两者同时分组 | 不是只按代码汇总 |

业务统计沿用来源的金额单位，不额外做汇率转换或万元换算。本金与创收承接上游人民币金额口径；只有234355明确除10000。两处容易误读的输出需要特别保留：

- `option_amount_change／swap_amount_change` 虽名为“规模变动”，实际只是逐日存量；SQL没有今日减昨日。
- `underlying_type` 虽目标注释为“合约类型”，实际把OPTION写为“期权”，其他全部写为“互换”，不是股票／指数等标的分类。`current_pnl` 则恒为NULL，表示此查询没有提供盈亏值，不是盈亏为0。

利润率的实际定义是：

```text
报告日存量 > 0：profit_rate = 今年累计Curr_Rev / 报告日动态本金
否则          ：profit_rate = 0
```

它是“期间累计金额÷时点余额”，不是平均资本收益率，也没有年化或乘100。本金减少即使创收不变，比例也可能升高；不能只据这个比例推断经营效率改善。

## 四、用同一客户三份合约，算出三张表

以下均为**构造输入**，不是生产数据。报告日2026-09-22，五行都位于该日创收日报快照；客户名称“示例客户”、USCC为U001。为突出范围差异，仅提供这些合约日记录，不声称是完整日历或完整真实客户历史。

| 合约／分支 | 业务／合约类型 | 期初日 | 计提日 | 初始本金元 | 动态本金元 | Curr_Rev元 | NPV创收元 | 标的／币种 |
| --- | --- | --- | --- | ---: | ---: | ---: | ---: | --- |
| A／01 | OPTION／欧式期权 | 2025-03-01 | 2026-09-22 | 1,000,000 | 1,000,000 | 10 | 0 | OLD／CNY |
| B／01 | OPTION／欧式期权 | 2026-01-01 | 2026-01-01 | 2,000,000 | 2,000,000 | 20 | 200 | HK／HKD |
| B／01 | OPTION／欧式期权 | 2026-01-01 | 2026-09-22 | 2,000,000 | 1,500,000 | 30 | 0 | HK／HKD |
| C／02 | TRS／南下互换 | 2025-10-01 | 2025-10-01 | 2,000,000 | 2,000,000 | 40 | 0 | CSI／CNY |
| C／02 | TRS／南下互换 | 2025-10-01 | 2026-09-22 | 2,000,000 | 1,000,000 | 50 | 0 | CSI／CNY |

标的名称各自固定，不发生改名。正常例子重点是贯通消费；这里的Curr_Rev作为上游输入，不用另一套简化公式冒充它的生产过程。

### 4.1 每日规模：得到三个日期，不算差额

| 输出日期 | 期权规模元 | 互换规模元 |
| --- | ---: | ---: |
| 2025-10-01 | 0 | 2,000,000 |
| 2026-01-01 | 2,000,000 | 0 |
| 2026-09-22 | 2,500,000 | 1,000,000 |

9月22日期权＝A的100万＋B的150万＝250万元。A虽然很早开始，当前记录仍符合每日规模范围。不要把本例1月1日的互换0理解为C真实当天无持仓：构造输入未提供C该日日记录，查询不会自行补出来。

### 4.2 标的持仓：同一份本金按标的展开，并换成万元

| 输出日期 | 展示业务 | 标的 | 规模万元 | 盈亏 |
| --- | --- | --- | ---: | --- |
| 2025-10-01 | 互换 | CSI | 200 | NULL |
| 2026-01-01 | 期权 | HK | 200 | NULL |
| 2026-09-22 | 期权 | OLD | 100 | NULL |
| 2026-09-22 | 期权 | HK | 150 | NULL |
| 2026-09-22 | 互换 | CSI | 100 | NULL |

9月22日期权100＋150＝250万元，与每日规模2,500,000元相符。输入当日创收非0并不会让本表的盈亏列出现数值。

### 4.3 业务统计：旧合约A先被排除，期权存量只剩150万元

A的期初日2025-03-01早于门槛2025-04-01，因此A整行不参与本表任何指标。剩下B、C：

| 输出业务类别 | 去年新增元 | 今年新增元 | 当日存量元 | 跨境期权存量元 | 今年NPV元 | 今年创收元 | 利润率原值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 期权／欧式期权 | 0 | 2,000,000 | 1,500,000 | 1,500,000 | 200 | 50 | 50÷1,500,000≈0.0000333333 |
| 互换／南下互换 | 2,000,000 | 0 | 1,000,000 | 0 | 0 | 50 | 50÷1,000,000＝0.00005 |

B只有起初那行进入今年新增：200万元；9月22日的150万元是存量，不再加一次新增。今年创收取20＋30＝50元；C的40元属于去年，不进今年创收。两行输出日期均为报告日2026-09-22。

期权利润率原值若展示为百分数约0.00333333%，互换为0.005%；SQL原值没有乘100。两类比例不能相加或取简单平均后称客户整体利润率，应以相同范围汇总分子、分母再算。

## 五、只改一个条件，观察哪张表改变

| 从上述五行输入作一项变化 | 每日规模／标的持仓 | 业务统计 |
| --- | --- | --- |
| 只把A期初日改为2025-04-01 | 不变 | A进入；期权存量变250万元、当年创收60元；但没有A起始日日记录，新增仍不增加 |
| 只删B起始日记录 | 删除1月1日的那份规模记录 | 今年新增和NPV均归0；当日存量仍150万元，今年创收剩30元 |
| 只删所有报告日记录 | 保留历史结果，不造当日零行 | B、C历史类别仍在；存量0、利润率0，即使B今年创收仍有20元 |
| 只复制B报告日行 | 当日期权多150万元；HK标的多150万元 | 存量与跨境规模各多150万元、当年创收多30元；新增不变 |
| 只复制B起始日行 | 1月1日期权多200万元 | 今年新增多200万元、NPV多200元、创收多20元；当日存量不变 |

没有一张查询按合约号去重。因此“本来应是一份合约一天一行”必须由上游证据支持，不能拿概念粒度替代数据唯一性核验。

再看两个范围例外：增加一条`grp_id='04'`的TRS记录，会进入每日规模而被另外两张排除；增加一条`grp_id='02'`但业务类型不是OPTION／TRS的记录，每日规模排除，标的持仓却把它显示为“互换”，业务统计原样显示业务类型。这是代码允许的差异，不声称生产确有此类记录。

## 六、空值、0和缺行要分开

| 情形 | 实际结果／应有理解 |
| --- | --- |
| 某客户日只有OPTION有效金额 | 每日规模的TRS列因CASE ELSE 0为0，不是另外找到了一份零本金互换 |
| 某组本金全NULL | 标的表SUM结果为NULL；每日规模的CASE SUM也可能为NULL，不能说ELSE 0消除了所有NULL |
| 同组新增另一个业务类型行 | 它对某列贡献ELSE 0，可能把原先全NULL的SUM变为0；观察结果时需同时看输入行 |
| 业务统计当日存量为0、负数或NULL | `>0`不成立，利润率为0；不等于当年创收也为0 |
| 业务统计存量为正，分子CASE的全部输入均为NULL | 分子及利润率为NULL；仅说“今年创收全NULL”还不够：同组若另有去年行，它产生ELSE 0，SUM(NULL,0)会变0，利润率也为0 |
| 标的币种NULL | `!= 'CNY'`不成立，不计跨境期权规模；空字符串不是NULL，不能自动同等处理 |
| 没有符合范围的记录 | 不生成结果行，不是输出一组全0 |

生产者通常对动态本金展示列做COALESCE补0，消费检查仍保留NULL反例，用于说明这三份查询本身提供什么保证；反例不证明当前生产一定存在NULL。

## 七、怎样核对三张表，而不误报金额不一致

每日规模与标的持仓核对，至少要同报告快照、同USCC和名称、同计提日、同OPTION／TRS范围，并统一`grp_id`限制；标的金额先汇总全部标的，再由万元乘10000。NULL单独核，不擅自等同0。

业务统计只能拿报告日的`stock_size`与另两张当天余额比较，还要统一2025-04-01期初门槛。**另两张结果已经没有合约期初日，不能仅靠三张结果表无损剔除旧合约。**需要回到共同源表构造同范围的对账桥梁。

本例的250万元与150万元，差的正是旧合约A的100万元。这个差异可以解释，并不需要修改SQL让三表强行相等。
