# 互换交易统计：交易频率、常做类型、胜率的样本为何不完全相同

任务 **228241** 生成 `dm_otc_n.bi_otc_swap_trd_stat`（OTC互换交易统计表），按客户输出“近一年”和“历史”两个期间的交易特征。它不是逐日收入表，也不是把每笔交易从开仓到平仓全部重新计算。

**先从创收日报找到起始日记录，统计笔数和初始本金；再并列补类型排名与当前估值。**最需要留意的是：交易笔数、平均规模、盈利笔数并未使用完全相同的去重方式，估值缺失还会让它们采用不同样本。

## 一、先读主脚本上的三条支线

```text
报告日创收日报：互换、计提日=期初定价日
                     │
           每行展开“近一年”“历史”，按各自日期范围筛选
                     │
       ┌─────────────┼─────────────────────────┐
       ▼             ▼                         ▼
 02 开仓合约统计   03 各类型笔数排名       04 内连接当前主合约
 笔数/均额/本金   取前两名横向展示                │ 内部流水号
       │             │                         ▼
       │             │                   05 当前腿估值汇总
       │             │                  盈利行数/估值合约数/盈亏
       └─────────────┼─────────────────────────┘
                     ▼
              01 指标输出 → 客户×期间
```

[00主脚本](00_主脚本.sql)里，`t1`就是[02开仓统计](02_开仓合约统计.sql)，`t2`是[03类型前两名](03_交易类型前两名.sql)，`t3`是[04估值匹配样本](04_估值匹配与胜率样本.sql)，不是三个未交代来源的中间表。[01指标输出](01_指标输出.sql)只组合它们的结果。

类型排名、估值匹配相互独立，不能画成先排名再计算盈利。主脚本保留原来的LEFT JOIN：缺估值不会删除t1已有客户期间行，但胜率／收益率可能是NULL。

## 二、先界定“新交易”“近一年”“历史”

共同输入是 `DM_OTC_N.OTC_REV_DAILY_RPT`（合约创收日报）。取报告日 `busi_date` 快照中 `Busi_Type='TRS'` 且 `Accrued_Date=Strt_Pric_Date` 的记录，含义是“这个合约的期初日记录”，不是“每个有持仓的日子都算一笔交易”。

| 程序中的期间标签 | 实际入选日期 | 频率计算的周数 |
| --- | --- | --- |
| 近一年 | 上年1月1日～报告日，双闭 | 报告日与上年1月1日的天数差÷7 |
| 历史 | 计提日≤报告日，无本任务新增下限 | 报告日与本客户入选记录中最早计提日的天数差÷7 |

以报告日2026-09-22为例，“近一年”从2025-01-01开始，共629天差，不是滚动365天，也不是本年年初到今天。原SQL文字注释和实际宏不完全一致，这里按实际宏解释，保留输出标签不改程序口径。

“历史”也只覆盖当前快照实际提供的起始日记录，不证明包含客户全生命周期。缺失起始日行的合约不会靠当前持仓补回来。该查询对创收日报**没有grp_id限制**，不能把入选TRS直接等同于分支02；只有估值匹配中另读的主合约明确限制02。

## 三、各金额、笔数实际来自哪里

| 内容 | 实际来源／计算 | 影响 |
| --- | --- | --- |
| 客户ID与名称 | 日报`USCC`＋`Cutp_Pty_Full_Name` | 02、03同时按这两项分组 |
| 交易笔数 | 日报`COUNT(DISTINCT Agt_Id)`，Agt_Id是合约号 | 合约去重计数，不是开仓记录行数 |
| 平均规模／总本金 | 日报`AVG／SUM(Init_Nom_Prin)`，初始名义本金 | **按入选行**计算，没有先每合约去重 |
| 交易类型 | 日报`Contr_Type_Desc`合约类型描述 | 类型内部数不同合约，再按笔数降序取两名 |
| 估值身份 | 日报Agt_Id→`PDATA_N.T98_OTC_DERI_COMP_SALE_INFO.Agt_Id`→`Inr_Seri_No`内部流水号 | 主合约取报告日、grp02，INNER JOIN |
| 估值金额 | `PDATA_N.T98_OTC_SWAP_COMP_LEG_VALU_INFO`互换合约腿估值 | 报告日、来源限定`ODATA_N_TIT.D_POS_TRS_LEG_VALUATION`，按`Swap_Comp_Agt_Id`汇总 |
| 合约盈亏 `pnl` | `SUM(Lcrrc_Accum_Unrlz_Yield + Lcrrc_Accum_Rlz_Yield)` | 本币累计未实现收益＋累计已实现收益；先逐行相加再SUM |
| 胜率分子／分母 | 匹配行中`pnl>0`的行数／匹配后不同合约数 | 缺估值的合约不在这个分母；重复匹配时分子可被放大 |
| 收益率 | 匹配后累计估值盈亏之和／02全部入选开仓行的初始本金之和 | 两边样本可不同；不按期间做估值差分，不年化 |

估值字段叫“累计”很重要：这里按开仓期间挑合约，再取它们**报告日的累计估值**，不是用报告日估值减期间起点估值。SQL也没有为两种期间分别生成不同的合约估值金额。

本金承接上游初始本金口径，估值字段为本币收益，本任务没有新增汇率换算。正常算例假设已在可比较的同一币种；实际币种一致性、收益正负的经济视角以及估值覆盖率需结合源系统确认，不仅凭字段名作制度结论。

## 四、一位客户、四份合约，完整算到输出

以下为构造输入，报告日2026-09-22，USCC为U001，名称“示例客户”；四份合约均各有一条起始日记录、一个主合约匹配和一份聚合估值。金额统一按元演示。

| 合约 | 期初日＝计提日 | 类型 | 初始本金 | 未实现收益 | 已实现收益 | 05汇总盈亏 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| A | 2025-06-01 | 类型甲 | 1,000,000 | 80 | 20 | 100 |
| B | 2026-01-01 | 类型甲 | 2,000,000 | -60 | 10 | -50 |
| C | 2026-09-01 | 类型乙 | 3,000,000 | 0 | 0 | 0 |
| D | 2024-01-01 | 类型甲 | 4,000,000 | 150 | 50 | 200 |

### 4.1 “近一年”：A、B、C进入，D不进入

```text
02：不同合约3份；初始本金合计600万元；平均每行200万元
03：类型甲2份、类型乙1份 → 第一类型甲，第二类型乙
04：三份都有估值；只有A盈亏>0 → 盈利行1，估值合约3，累计盈亏50元
01：
  每周频率 = 3 / (629/7) ≈ 0.0333863 笔/周
  平均规模 = 2,000,000 元
  交易胜率 = 1/3 ≈ 33.3333%
  收益率   = 50/6,000,000 ≈ 0.00000833333（转百分数约0.000833333%）
```

胜率0.333333与百分数33.3333%是同一值的不同展示，SQL没有乘100。C盈亏恰为0，不算赢；负收益B仍在估值分母内。

### 4.2 “历史”：再加入D

```text
02：4份合约；本金1000万元；平均250万元；最早入选日期2024-01-01
03：类型甲3份，类型乙1份
04：盈利A、D共2行；不同合约4份；累计盈亏100-50+0+200=250元
01：
  每周频率 = 4 / (995/7) ≈ 0.0281407 笔/周
  胜率     = 2/4 = 50%
  收益率   = 250/10,000,000 = 0.000025（0.0025%）
```

最终是同一客户两行，不是把两个期间加总成七笔交易。A、B、C本来就同时出现在两个期间。

## 五、只改变一项，解释指标为什么变了

### 5.1 删除C估值，不删除C交易记录

02仍有A、B、C，交易笔数3、平均200万元、总本金600万元；04只剩A、B，胜率变为1/2。C原盈亏为0，所以总盈亏仍50元，收益率仍50/600万元。

胜率从1/3升到1/2，**不代表某份合约转盈，只是可匹配估值的样本缩小**。若三份估值均缺失，t3整组不存在；最终胜率和收益率是NULL，类型排名仍可显示。

### 5.2 只复制A的起始日记录

02不同合约数仍3，但本金行变为100、100、200、300万元：合计700万元，平均175万元。03类型甲仍是2份不同合约。

04匹配后的盈利A出现两行，盈利行数2，合约分母仍3；盈亏变为100＋100－50＝150元。胜率2/3，收益率150/700万元。**去重笔数没有保护其他金额或胜率。**若只让主合约A在连接后出现四次，胜率甚至可为4/3；SQL没有一合约一条匹配或胜率封顶约束，测试保留该扩行反例，不声称生产已有此问题。

### 5.3 只把一个估值收益分量改成NULL

若A的未实现收益变NULL、已实现仍20，则该行`NULL+20`为NULL，不是20。A聚合估值仍有一行但金额NULL；它仍算一个匹配合约，`pnl>0`不命中盈利，总盈亏SUM忽略它。近一年总盈亏仅剩-50元，胜率0/3。

如果同合约另有完整收益腿，那条腿仍可被SUM计入。不能把“SUM忽略NULL”理解为先把每个收益字段都补零。

## 六、排名和客户连接还有两处粒度差异

**排名并列没有稳定次序。**03按不同合约数降序用ROW_NUMBER，只取rn≤2。两个类型同为1笔，谁第一未指定；只有一个类型时第二类型与第二笔数都是NULL。没有取“所有并列前二”的逻辑。

**公司名称参加分组，却没有参加最终连接。**02和03按USCC＋名称＋期间分组，00只用USCC＋期间连t2；04也只按USCC＋期间聚合。若同一USCC有两个名称，02的每个名称组可能匹配03两个名称组，出现扩行；两名称还共用04合计的估值指标。不能把结果承诺为“每个USCC每期间必一行”。

另外，USCC为NULL虽然可以形成分组，却不会通过普通`=`匹配另一个NULL；类型／估值补充可能因此缺失。应核源客户身份，不能直接把缺失解释成客户没有交易或没有收益。
