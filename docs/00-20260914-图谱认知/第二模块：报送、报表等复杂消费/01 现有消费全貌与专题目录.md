**第二模块先发现加工网络，再确定业务专题：折叠第一模块的入模细节和第四模块的简单交付段，保留基础输入、公共加工、结果分支及其依赖。** 2026-09-18 已完成九库范围的第一轮结构发现，见[加工网络发现与边界压缩](02%20加工网络发现与边界压缩.md)。

当前盘点既覆盖现有图的读写对象，也检查了图外目录线索。下文六个业务方向是核对标签，20 项代表结果是样本；它们都不能代替完整专题目录。NDS、T98、T99、DM 和香港供数是加工经过的位置，也不直接决定专题边界。

**范围及后续处理决定统一登记在[建设台账](建设台账/README.md)**：表台账记录公共结果的含义和用途；调度台账按输出／写入实例记录展开、折叠或本次不展开的决定。自动线索和人工核对分列，避免每轮分析重新圈范围。

台账现已覆盖主图全部 **7,255 个物理表节点、7,478 个调度任务**。下文的九库统计和候选加工群是首批分析结果，不再作为登记边界；分析可以分批，台账不裁剪对象。

**公共加工已开始独立建设，阅读入口见[公共加工](公共加工/README.md)。** 第一组包含销售与规模共同基础、四个生产分支、管理归属、逐日金额及消费边界。后续业务专题引用公共结果，再解释自己的规则；全量登记与公共加工正文分别维护范围和含义。

## 1. 用哪些业务问题核对发现结果

以下分类不作为聚组算法的预设标签。先检查共同输入和实际加工关系，再用业务问题判断：哪些属于公共基础，哪些应拆为独立结果分支，哪些需要补充新方向。

| 业务方向            | 读者要理解什么                         | 本轮已经找到的专题入口                          |
| --------------- | ------------------------------- | ------------------------------------ |
| **销售与经营分析**     | 业务收入、规模和交易明细如何形成，怎样归属人员与机构？     | 交叉销售收入、对内销售收入、销售参数、客户每日规模、带经营归属的交易明细 |
| **持仓、风险与盈亏分析**  | 持仓和定价结果怎样转成风险、压力测试和业务盈亏结果？      | 期权 Greeks 明细、压力测试与限额、互换合约盈亏          |
| **资金、保证金与运营分析** | 组合履保、账户余额、资金变化怎样共同表达业务状态？       | 组合保证金明细；资金与结算其他结果继续按输出登记             |
| **财务与估值系统供数**   | 哪些结果直接承接财务源口径，哪些重新组织成估值系统需要的数据？ | TRS 财务盈亏、估值系统互换交割明细                  |
| **监管与协会报送**     | 特定报送项目需要哪些主记录、明细、附件和统计口径？       | 客户保证金、收益凭证、跨境业务、主协议、香港合约报备、已报备合约月末规模 |
| **客户准入与服务管理**   | 客户如何准入、怎样管理，报告服务生成和发送到了哪一步？     | 准入进度、已准入客户管理、估值报告生成与发送结果查询           |

另有两种内容需要保留明确位置：

- **公共加工**：例如销售归属、逐日本金、参数、人员机构和日历。它们服务多个结果，指定一处详解，其他专题引用。
- **应用支撑结果**：例如用户账簿权限查询。它本身也是消费输出，但不宜硬塞进销售、财务或风险类。先作为支撑索引独立登记，数量和用途清楚后再决定是否单独成篇。

本轮发现的“同一交易对手输出”、功能菜单映射等也保留在索引中：对象含义衔接第一模块，搬运与交付衔接第四模块，第二模块说明它们在相关结果中的用途。

## 3. 从加工网络发现专题

九库共有 **1,919 个写入关联物理对象、2,698 个关联写入任务**。第一轮按文档边界和任务类型单列入模、推送及未见读取部分，剩余 2,191 个任务用于共同输入发现；其中 309 个任务形成 101 个候选组，1,882 个仍独立保留。**101 是结构核对批次，不是专题总数，也不是聚类准确率。**

| 发现的结构 | 对专题整理的直接影响 |
| --- | --- |
| 客户每日规模与月度／年度规模指标共用经营归属及逐日金额 | 报表与指标跨 `dm_otc_n`、`dm_index_n` 一起核对 |
| 交叉销售、对内销售、香港销售各有收入与参数分支，同时复用经营基础 | 先解释公共基础，再分别解释收入口径；补入原样本未单列的香港销售 |
| 互换共同基础被风险、财务、香港等结果复用 | 公共加工独立解释，结果按实际用途分支，不能整组定为一个财务专题 |
| 期权共同基础支撑 Greeks、合约结果与盈亏 | 解释共同合约、子交易定价和持仓基础，再看各输出的粒度与计算 |
| 人员模型加工仍在剩余集合中 | 第一模块边界未覆盖全部对象，剩余部分不自动属于第二模块 |
| 组合保证金、估值报告服务本轮未聚组 | 未成簇也可能有重要复杂加工，必须保留独立结果及直接加工关系 |

压缩是折叠细节，不是删除依赖；入模文档命中和推送任务类型都需要进一步核对。共享客户、证券、机构、字典也不能单独促成合组。发现方法、全部候选、129 个跨群共享输入及四次路径抽查见[加工网络发现与边界压缩](02%20加工网络发现与边界压缩.md)。

这轮已计算共同输入分组，尚未完成全量串行加工接续。专题最终按 **基础输入 → 公共加工 → 专题加工 → 结果分支 → 交付位置** 登记，允许多个组归入同一专题，也允许一个组拆到多个用途分支。

## 5. 计算和 SQL 核对改变了哪些判断

**DM 不等于复杂加工。** 在 `dm_otc_n` 的 384 个写入关联表中，191 个至少有一个写入关联任务出现 Join、Union、Group、窗口或聚合词法线索，180 个的全部写入关联任务均未出现这些线索，其余 13 个为条件转换等情况。这只用于选取精读对象，不能自动命名为“复杂／简单”或当作业务分类。

**NDS 可以承载已经加工好的业务结果。** 财务盈亏报表读取 `pdata_nds.fin_trs_plreport` 后只做日期筛选与投影；这要求往前解释源结果，而不是因下游 SQL 短就把整个专题判作搬运。

**同一专题可以跨基础模型、T98、T99、NDS、DM。** 客户准入同时使用流程、机构与人员；估值报告服务组合 T01 配置、T05 执行事件及 NDS 报告生成资料。按表前缀编目录会把一个问题拆散。

**T95 报送资料需要按项目成组解释。** 现有表不只保证金和收益凭证，还包括跨境业务、互换交易确认书、担保品、费用端与权益端支付、存续持仓及附件。不能一张表各写一篇，也不能以一个“T95 复杂加工”概括全部。

**图内候选范围会比股衍业务范围大。** 客户、机构、证券和参数可被许多业务复用。计算所得的连通范围只能用于发现线索；不能把整片连通图自动命名为一个业务模块。本轮未把无分区限制的同表连通结果作为确认消费清单。

| 图内末端不等于最终用户消费 | 例如风险与报送输出常在图内不再被读取 | 后续按专题核对接口、报表或接收系统；本轮未验证生产运行和交付 |

33 条未命中的直接专题候选中，包括合约初始／动态名义本金、交易对手成交笔数、客户年度／季度销售收入等。这表明仅沿已有销售报表或 T98 表继续向下找，可能遗漏同类业务的指标消费。
