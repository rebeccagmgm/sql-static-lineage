# 逐日本金与费用

任务 **107491** 将销售基础与事件、持仓、费用资料组合，形成 `pdata_n.t98_otc_deri_comp_sale_adtnl_det`。它解决“这条合约基础记录在某个计提日应带什么金额和费率”，后续收入和规模消费再决定如何计算、分配或累计。

需要逐段读懂SQL时，从[107491分模块阅读入口](107491_逐日本金与费用/README.md)开始：先看合约日展开，再走通期权事件与本金，最后对照互换、金仕达和FAST。主脚本保留完整连接与最终本金CASE。

## 一次快照怎样展开多个计提日

1. 读取销售基础的当前参数日分区，以 `coalesce(Early_Term_Date, End_Pric_Date)` 作为有效结束边界；保留结束日大于2021-09-30、开始日不晚于结束日的记录。
2. 使用 `default.gfgreatest(Strt_Pric_Date, date_sub(参数日,150))` 定位起点，通过 `posexplode` 和日期加法展开到参数日。
3. 输出 `busi_date=Accrued_Date`，并以 `busi_date,grp_id` 动态分区覆盖写入。

它从当前快照回看并重组一段日期，不是每天读取一份当日销售基础快照。展开也没有统一在终止日截断，部分分支通过金额表达式处理终止后的值。[SQL L11、L38–50](证据/107491-query.sql)

**150日是这段SQL的重算／展开窗口，不能单凭它断言目标表只剩150日历史。** 动态分区写入未在本段表达“删除全部其他历史分区”；全年覆盖、旧分区是否保留以及补跑策略需要存储和运行证据。

## 动态本金按四个分组分别形成

| 分组          | 计算资料与连接身份                                                | `Dyna_Nom_Prin` 的核心处理                                       |
| ----------- | -------------------------------------------------------- | ----------------------------------------------------------- |
| 01：期权       | 生效的部分终止、提前锁盈事件，按 `key_option_deal_id=Inr_Seri_No` 及计提日连接 | 开始日取初始本金；结束日之后为0；其他日期用累计名本变化×汇率加初始本金，缺事件时回退初始本金             |
| 02：普通互换     | 结构腿历史持仓，按交易键及源业务日期聚合后连接 `Inr_Seri_No`                    | 开始日取初始本金；结束日之后为0；其他日期取 `sum(Init_Price×Quantity)×汇率`，缺历史值补0 |
| 03：KS       | 确认信息按确认键及业务日期，用下一业务记录日期形成延续区间，连接 `Agt_Id`                | 直接取 `ks.dynamic_notional`；本CASE分支没有另乘汇率，也没有统一加终止后归零表达式      |
| 04：FAST TRS | `EOD_POSITION` 历史按工具及源业务日汇总，连接 `Otc_Seri_No`             | `coalesce(动态本金×汇率,0)`；当前分支没有与01/02相同的开始日／终止日CASE            |

期权事件先按合约、事件日汇总，再依据事件前后名本比较确定变化方向并累计，随后延续到下一事件前一天。它不是把事件金额直接作为每日余额。01的开始日优先分支也意味着该日并不直接使用累计调整值。[SQL L22–26、L53–131](证据/107491-query.sql)

## 其他金额与参数各有日期规则

| 输出 | 来源与处理 | 使用边界 |
| --- | --- | --- |
| `Inta` | KS确认记录的 `accrued_interest × (-1)` | 使用区间延续后的KS记录；不能脱离源含义解释成当日新增利息 |
| `Fnd_Cost` | 同一KS区间记录的 `occupy_cost` | 与逐笔当天费用字段区分 |
| `Trd_Cms`、`Trd_Cms_Cost` | KS源 `profit`、`fee_cost` 按业务日直接连接，缺失补0 | 与上面延续区间的处理不同 |
| `Marg_Prop` | `d_ks_trs_for_risk` 的 `GUARANTEE_RATIO`，按合同和生成日期整理后延续 | 当前同日去重排序没有提供额外稳定优先键，不能宣称已选中业务最新版本 |
| `fee_rate` | `d_trd_daily_accrual_fee` 中 `ACCRUAL_PREMIUM_FEE`，按工具和计算日期延续 | 输出的是费率字段，不是由此计算完成的收入 |

依据：[SQL L27–39、L100–159](证据/107491-query.sql)。历史持仓和当天KS费用分支有各自窗口，不能把一个窗口条件推广到所有输入。

## 粒度与复用限制

SQL保留销售基础记录中的合约、业务类型、客户、标的及分组，并展开计提日，最终没有统一按合约／计提日聚合。基础若已有多行、关联源若重复，结果仍可能多行；`Agt_Id+Busi_Date+Grp_Id` 只是核验入口，尚不能登记为已证明主键。

收入消费可能对累计值、特殊产品和奖励另做处理；存续规模可能采用严格的终止日排除；期间指标还需要选择分子日期范围和分母。公共明细提供可用数据，不替每个消费统一定义“存续”“全年”“日均”。
