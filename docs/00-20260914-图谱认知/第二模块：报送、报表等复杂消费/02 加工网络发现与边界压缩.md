# 加工网络发现与边界压缩

**先折叠入模和纯交付细节，再识别公共加工及结果分支，最后确定业务专题。** 本轮按这个顺序对现有九库范围做了结构发现。发现结果支持把销售、规模、互换和期权等内容理解为共享基础上的加工网络；还不能将算法分组直接当作最终专题。

主图仍为 `9dbe5623…`，包含 7,478 个调度任务；本轮沿用其中 6,039 个已投影任务的固定材料，未使用 next。九库是待审范围，包含公司级指标和其他业务，不能整体认定为股衍业务。

本页记录首批九库分析，不是全量登记边界。[建设台账](建设台账/README.md)现已覆盖主图全部 7,255 个物理表节点及 7,478 个调度；可以在台账中选择分析范围，但不能据此删去未分析对象。

## 1. 压缩后要看见什么

```mermaid
flowchart LR
  A["第一模块：入模细节可展开"] --> B["基础输入：对象、事件、源结果"]
  B --> C["公共加工：归属、逐日金额、持仓整理等"]
  B --> D["专题加工群"]
  C --> D
  D --> E["业务结果：报表、指标、查询、报送材料"]
  E --> F["第四模块：交付细节可展开"]
```

这是阅读结构，不表示每项结果都经过全部五层。NDS 中已有源系统加工结果可以直接成为输入；某项业务结果也可以继续成为另一项加工的输入。

| 边界 | 本轮怎样处理 | 必须保留什么 |
| --- | --- | --- |
| 第一模块入模 | 从 TIT、OIS 现有正文和索引查找 T01～T10 模型落点，作为折叠生产侧的候选 | 物理身份、入模任务、文档入口、全部下游读取；名称命中不等于各分支已核验 |
| 第四模块交付 | 推送类型任务暂不参与共同输入聚组，单列规则核对；已核对的纯交付段可在阅读图中折叠 | 接收对象、源结果、批次和过滤条件；不删除原任务 |
| 公共输入与加工 | 保留跨群复用关系；高复用输入不单独促成合组 | 哪些加工群读取它、它由谁形成、属于基础对象还是新增计算 |
| 未确认部分 | 独立登记，保持可追溯 | 未见读取、未聚组、文档未覆盖、接收位置未核等具体原因 |

**不能按表前缀或所在模块整批压缩。** 第四模块已核对的曲线接口 `220488` 有来源选择和期限映射，境外行情接口 `234508` 有配置、日期及价格筛选，都需要保留规则。第一模块列出的候选也不能直接提升为已确认入模。

几个关键定位点：

- K006 的 7 个任务共同读取 `pdata_n.t98_otc_comp_mng_rela_info` 和 `pdata_n.t98_otc_deri_comp_sale_adtnl_det`。抽查 `93338` 的年度日均动态本金 SQL，包含年初至加工日范围、归属分支和人员汇总；客户每日规模 `224351` 已在上一轮核对。
- K099 的收入任务为 `220979`，参数任务为 `220981`。本轮核对前者固定 SQL 的输入和加工线索，包含香港参数、逐日金额及累计计提窗口；尚未逐条解释香港收入公式。
- K008 的 `176330` 输出 `dm_rsk_n.otc_comp_marg_det`；组内同时存在互换盈亏和财务供数。共享输入足以支持共用基础的核对方向，不足以证明这些结果具有同一金额口径。

## 4. 公共基础应怎样单独解释

“被很多任务读取”只说明复用，不直接说明业务职责。本轮已经区分出三种需要不同处理的情形：

| 情形 | 实际线索 | 处理方式 |
| --- | --- | --- |
| 通用定义和技术支撑 | `dm_index_n.grp_def` 被本轮中间集合中 445 个任务读取；`pdata_n.ref_cd_cvt_map` 被 221 个任务读取 | 保留依赖，在具体专题说明使用方式；不能据此把所有指标或加工合成一组 |
| 基础业务对象 | 证券资料、客户名称、账簿附加信息 | 引用第一模块；若第一模块缺内容，登记补齐，不能假定已经压缩完成 |
| 业务公共加工 | 销售基础、管理归属、逐日金额；互换／期权合约与持仓整理 | 建立公共加工说明，各结果分支引用并补自己的范围、时间与计算口径 |

例如 `pdata_n.t98_otc_deri_comp_sale_info` 在本轮中间集合中有 42 个实际读取任务，连接 7 个候选组。它应保留为跨组输入，不能用它把规模、销售收入和其他指标全部合成一个专题。

同一表可以同时是某段加工的结果和多个专题的输入。公共加工与专题结果是相对职责，不要求每张表只有一个永久分类。

## 5. 共同输入发现之后，还必须补什么

**本轮完成的是共同输入分组和四个边界样本的路径核对，没有完成整张剩余网络的串行加工接续。**

已知的组合保证金任务 `176877`、估值报告服务 `146622` 在当前阈值下仍未聚组。它们都有多来源加工，只是没有足够相似的另一任务。因此不能用“有没有成簇”筛掉孤立结果。

后续核对按以下顺序进行：

1. **补生产侧边界。** 区分“文档提到”与“对象、粒度、关键入模规则已解释”，并收回人员模型等遗漏的第一模块内容。源系统已算好的结果仍需说明承接边界。
2. **补串行加工关系。** 对候选群及未聚组任务，沿正式图查询直接加工关系，逐步补齐中间产物。保留任务、写次、物理身份及范围，不用同表读写的无界连通代替因果。
3. **核对公共加工。** 先审销售基础／归属／逐日金额、互换与期权共同基础，判断哪些值得单独讲解，哪些只是共享维表。
4. **分清结果与交付。** 核对输出是否改变粒度、范围或金额口径，以及实际接收位置。第四模块已核对的 ETF 路径 `237781 → 237796` 可作技术适配与推送折叠样本；不推广到其他同表任务。
5. **再确定专题。** 一个组可以拆成多个业务专题，多个组也可以归入同一专题。保留公共输入和独立结果，不为形成整齐目录强制归类。

每个正式专题最终应能填写：**基础输入、公共加工、专题加工、结果分支、交付位置、尚未解释的依赖**。缺少其中一项时注明具体缺口，不标为全貌已完成。

## 6. 计算口径与可复核材料

本轮将任务作为比较单位，只用物理身份已确认的读取记录；保留原始任务读写，未将一个任务的全部输入输出两两声明为因果。聚组方法为：

- 第一模块文档命中的基础模型，以及被至少 30 个中间任务读取的输入，不参与相似度计算，但仍保留在依赖底账。
- 两任务至少共同读取 2 个剩余物理对象；每个输入按 `1 / log2(2 + 读取任务数)` 加权，共同输入权重除以并集输入权重，达到 0.55 才形成候选联系。
- 候选联系的连通分量作为核对批次，不保证任意两个成员都相似，也不证明它们是同一业务专题。未成组任务全部保留。
- 将高复用阈值换成 20／30／50，相似度换成 0.45／0.55／0.65，得到 86～113 个候选组、236～393 个成组任务。阈值会影响数量，**101 不是客观业务专题总数**；敏感性计算也不等于正确性验证。

本轮另使用正式 CLI 对 `220979`、`176330`、`93338`、`237796` 做上游深度 2、上限 200 边的核对。四次均为同一发布版本、`TASK_SCHEDULE` 范围、未触及边数上限，均到达深度边界。查询要求实际读写边，调度只限制导航范围；这四个样本不代表全量分组已获得分区因果确认。
