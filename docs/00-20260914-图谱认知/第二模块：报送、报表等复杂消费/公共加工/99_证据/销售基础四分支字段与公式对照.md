# 销售基础四分支字段与公式对照

**目标表：`pdata_n.t98_otc_deri_comp_sale_info`。** 四个任务按产品分支并行写入：先统一合约身份、分类和本金，再供管理归属、逐日金额、收入及规模消费使用。下文 `D` 表示加工参数日，`FX` 表示该分支输出的 `Cny_Ex_Rate`。

## 1. 四个入口与写入范围

| 分组／任务     | 主要事实来源（均在 `odata_n_tit`）                                                | 合约身份                          | 范围和行形态                                                         |
| --------- | ----------------------------------------------------------------------- | ----------------------------- | -------------------------------------------------------------- |
| 01／86840  | `d_trd_otc_trade`、`d_ref_otc_option_deal`、`d_ref_option_deal_structure` | `Agt_Id=internal_trade_id`    | 期权合约联接结构，保留结构的标的与条款。不能未验证就说每份合约只有一行                            |
| 02／86841  | `d_trd_otc_trade`、`d_ref_trs`、`d_ref_trs_leg`、`d_pos_trs_leg_his_pos`   | `Agt_Id=internal_trade_id`    | 结构腿和非结构腿分别按合约连接；历史持仓按腿聚合。多腿和其他一对多连接可能影响最终行数                    |

## 3. 从哪些连接形成一行

表名前缀除注明外均为 `odata_n_tit`。下表列改变身份、粒度或金额的关键连接；客户、字典和其他属性见第6节。

| 分支 | 输入及连接键 | 连接前处理 | 进入输出后要注意什么 |
| --- | --- | --- | --- |
| 01 | `d_trd_otc_trade` **内连** `d_ref_otc_option_deal`：`key_otc_trade_id` | 两侧读D日快照 | 无期权合约匹配的交易不进入 |
| 01 | **左连** `d_ref_option_deal_structure`：`key_otc_trade_id` | 未在该子查询按合约取唯一结构 | 标的、分类、日期取结构字段；一份合约多结构是否扩行待核 |
| 01 | 结构 `underlying_ins_id` 左连工具／篮子 `key_instrument_id` | 篮子成分按`key_instrument_id`聚合名称、类别 | 输出仍用结构标的ID；篮子成分被拼成列表，不是逐成分输出 |
| 02 | 交易内连 `d_ref_trs`：`key_otc_trade_id` | D日快照 | 形成普通TRS入口 |
| 02 | 合约分别左连 `d_ref_trs_leg` 两次：`key_otc_trade_id` | 一路`STRUCTURE_LEG_TYPE`；另一路所有非结构腿 | 两路均可能多条，不能假定合约唯一或两路一一对应 |
| 02 | 结构腿左连持仓初始聚合：`key_leg_id` | 每`腿+标的ID`按`src_busi_date ASC`取首条；再按腿聚合 | 初始值来自当前快照可见首条；标的列表与初始本金在腿级形成 |
| 02 | 初始聚合再左连当日持仓聚合：`key_leg_id` | `substring(src_busi_date,1,10)=D`，按腿求和 | 动态本金不按同一标的逐条回连；没有初始聚合键时也不能接上该动态聚合 |
| 03 | `d_ks_trade_comfirm_info`作为入口 | 每确认键按`business_date DESC`取`rn=1` | 相同业务日并列时没有额外排序键，不能声称业务最新版已唯一确定 |
| 03 | 确认键左连 `d_ks_trs_eod_postion`聚合 | 每`确认键+标的代码`按`src_busi_date DESC`取首条，再按确认键拼接 | 标的来自各标的最新可见记录；最终要求聚合代码非空 |
| 04 | 交易内连 `d_ref_fast_trs`：`key_otc_trade_id` | 限定`N_CROSS_DMA_SWAP` | 仅该FAST TRS业务分支 |
| 04 | 左连历史持仓初始聚合：交易 `key_instrument_id` | `EOD_POSITION`；每`工具+wind_code`按源日期ASC取首条，再按工具聚合 | 不保证所有标的的首条来自同一天 |
| 04 | 左连历史持仓当日聚合：交易 `key_instrument_id` | `EOD_POSITION`且源日期为D，按工具求和 | 与初始聚合分别连接交易；动态金额缺失补0 |

依据：[86840](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055365.sql) L182–239；[86841](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055616.sql) L160–242；[86842](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055882.sql) L105–154；[220650](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105056086.sql) L105–174。**四段最终SELECT均未统一按`Agt_Id`聚合／去重；分支内聚合不等于最终合约唯一。**

## 4. 本金与汇率：按分支读公式

| 分组 | `Init_Nom_Prin` | `Dyna_Nom_Prin` | 汇率表达 |
| --- | --- | --- | --- |
| 01 | `deal.Initial_Notional × FX` | `FX × if(D between 开始日 and coalesce(提前终止日,结束日), coalesce(deal.Notional,0),0)` | 见下方优先级；区间包含开始、结束两端 |
| 02 | `Σ首条持仓(Init_Price×Init_Quantity) × FX`，按腿 | `coalesce(Σ当日持仓(Init_Price×Quantity),0) × FX`，按腿 | 没有01那一层开始／终止日期归零；FX为空时不能认为结果已补0 |
| 03 | `if(trs_type='B_LONG_SHORT_SWAP',dynamic_notional,notional)` | 当前所选确认记录 `dynamic_notional` | `FX=NULL`；这两个金额表达式不乘FX |
| 04 | `Σ各工具/标的首条持仓.dynamic_notional`，按工具 | `coalesce(Σ当日持仓.dynamic_notional,'0')`，按工具 | `FX='1'`；金额表达式未另外乘FX |

| 分支 | `Cny_Ex_Rate`选择顺序（按顺序命中） | 币种／价格日期边界 |
| --- | --- | --- |
| 01 | ①`COLLATERAL_NOTIONAL_CURRENCY='CNY'`→1；②`SETTLEMENT_CURRENCY='CNY'`→`ds.INIT_NOTL_EXCHANGE_RATE`；③否则→`mid.MIDRATE` | 中间价按抵押名本币种与`ds.start_date=quote_date`连接；该连接未另加D日分区条件 |
| 02 | ①`CURRENCY='CNY'`→1；②`BASE_CURRENCY='CNY'`→`BASE_INIT_EXCHANGE_RATE`；③`SETTLEMENT_CURRENCY='CNY'`→`SETTLE_INIT_EXCHANGE_RATE` | 无ELSE；三项都未命中则NULL |
| 03 | NULL | 输出`Sett_Crrc_Cd='CNY'`，不据此证明上游全部币种已核实 |
| 04 | 常量1 | 输出结算币种仍取`rt.SETTLEMENT_CURRENCY`，不能由常量1反推源币种 |

**关键差别：03的部分“初始本金”取动态本金；02/04取快照内可见首条持仓。均不能无条件解释为签约时不变的原始本金。**

依据：[86840](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055365.sql) L95–120、L199–201；[86841](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055616.sql) L83–98、L193–242；[86842](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055882.sql) L37–43、L108–112；[220650](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105056086.sql) L37–43、L127–174。

## 7. 下游使用时的最小核对项

| 要核对 | 不能默认成立的结论 |
| --- | --- |
| 选哪些`grp_id`、部门、产品和状态 | 四分支全部纳入，或基础表只含存续合约 |
| 用哪个身份连接 | `Agt_Id`、`Inr_Seri_No`、`Otc_Seri_No`可互换 |
| 用哪一套分类匹配参数 | 经营分类等同源分类，或全部合约采用新CASE |
| 取哪种本金、日期和币种 | 同名金额跨分支同义，或缺汇率已经统一补0 |
| 多结构、多腿及属性连接后的基数 | `Agt_Id+busi_date+grp_id`已经证明唯一 |
