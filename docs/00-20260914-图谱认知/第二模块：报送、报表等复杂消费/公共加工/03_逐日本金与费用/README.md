# 107491：从合约主信息到逐日本金与费用

合约主信息回答“这是一份什么合约、当前整理出的本金与条款是什么”。本任务继续回答：**这份合约在某个计提日，应当带什么本金、利息、交易收入成本和费率？**

输出为 `pdata_n.t98_otc_deri_comp_sale_adtnl_det`（场外衍生品合约销售收入附加明细）。它还没有算销售收入、没有分配给销售人员；118141等消费会继续套系数、收入公式和分成规则。

## 第一遍只走一份期权

按这个顺序打开，先不用把所有分支都读完：

1. [合约范围与计提日](01_合约范围与计提日.sql)：一份当前合约资料，为什么变成多天记录？
2. [期权事件与名本变动](02_期权事件与名本变动.sql)：事件如何改变本金，又怎样延续到每天？
3. [主脚本](00_主脚本.sql)：按合约键与计提日连接后，最终CASE怎样选本金？

文件编号是阅读导航，不是业务代码。每个模块定义命名的查询结果（CTE）；主脚本集中保留实际JOIN、四类本金CASE和全部输出字段。

```text
合约主信息的加工日快照
  └─ 展开计提日：一份基础记录 → 多个合约日info
       ├─ 期权：累计事件变化evt
       ├─ 普通互换：该日结构腿持仓金额his_dy
       ├─ 金仕达：延续金额ks；当天交易收入成本ks_t
       ├─ FAST：该日日终持仓金额nd
       └─ 延续的保证金比例prop、计提费率fee
                         ↓
                主脚本按业务分组选择本金
                         ↓
          按计提日busi_date、业务分组grp_id写入
```

## 先分清两个“日”

| 日期 | 在SQL里是什么 | 决定什么 |
| --- | --- | --- |
| 加工日 | 参数 `${data_day_str}` | 本次读取哪一份源表快照；输出到Data_Etl_Date等留痕字段 |
| 计提日 | `Accrued_Date` | 当前结果代表哪一天；最终写入目标表的 `busi_date` 分区 |

源快照里可能保留多个历史业务日。这里取**当前快照中的历史记录**，并非逐天读取当时保存的合约快照。合约的客户、类型、初始本金、汇率等仍跟随本次主信息资料。

日期起点取期初定价日与“加工日前150天”中较晚者，终点为加工日，首尾包含。例如9月21日加工、9月18日期初，就展开18、19、20、21日。回看150日跨度时最多覆盖151个日期，不能把它理解为目标表只保存150行或150天历史。

合约入口先要求：结束边界晚于2021-09-30，且期初不晚于结束边界。结束边界取 `COALESCE(提前终止日,期末定价日)`，只在NULL时回退，不额外处理空串。**展开没有在结束边界停止**，金额是否归零要看分支CASE。

## 用一个期权例子走通

假设本次加工日为9月21日；合约9月18日期初、9月20日结束，初始本金1000、汇率1。源事件中9月19日名本减少200，9月20日再减少100；两条都已生效且属于本SQL选取的事件类型。

| 计提日 | 匹配到的累计变化 | 最终动态本金 | 原因 |
| --- | --- | --- | --- |
| 9月18日 | 尚无事件 | 1000 | 期初定价日优先取初始本金 |
| 9月19日 | -200 | 800 | 初始本金1000＋累计变化-200 |
| 9月20日 | -300 | 700 | 结束当日仍进入金额计算，不是“到期当天就归零” |
| 9月21日 | -300 | 0 | 日期已晚于结束边界，优先归零 |

事件文件里的 `notional_change` 是**累计变化**，不是当日本金，也不是仅当天发生的变化。事件之间的日期沿用上一次累计值；从未匹配到事件时，主脚本回退初始本金。

同一天有多个事件时，原SQL先取最大调整前本金、最小调整后本金、变动金额之和，再统一判断增减方向。因此它不是逐笔事件按时间顺序复算。本次保留这个口径，不另行修正。

## 再对照四类本金

所有分组的 `Init_Nom_Prin` 都直接取合约主信息。下面比较的是最终 `Dyna_Nom_Prin`：

| 分组 | 期初定价日 | 其他日期的来源／公式 | 晚于结束边界 | 缺金额或汇率时 |
| --- | --- | --- | --- | --- |
| 期权01 | 直接取初始本金 | 初始本金＋累计事件变化×汇率 | 0 | 普通计算路径先回退初始本金，再回退0 |
| 普通互换02 | 直接取初始本金 | 当日结构腿持仓Σ(期初价×数量)×汇率 | 0 | 普通计算路径的乘积为NULL时补0 |
| 金仕达03 | 不特判期初 | 延续后的确认记录 `dynamic_notional` | 没有额外归零判断 | 保持NULL；不另乘汇率 |
| FAST04 | 不特判期初 | 当日日终持仓Σ(dynamic_notional)×汇率 | 没有额外归零判断 | 乘积为NULL时补0 |

期权、普通互换在“期初定价日”分支直接返回初始本金，该值本身为NULL时不会再走后面的补0。期权在事件存在但汇率缺失时，也可能因整条算式为NULL而回退初始本金。

普通互换持仓模块虽还计算了 `Init_Nom_Prin_Org`，主脚本并未使用它。FAST持仓金额的源注释是标的币种；即使乘了合约主信息的汇率字段，也不能跳过核对其实际取值与上游换汇口径。

## 哪些延续，哪些只匹配当天

这是本任务最重要的第二条区分：

| 输入 | 时间处理 | 没匹配到时，主脚本如何输出 |
| --- | --- | --- |
| 期权累计事件变化 | 从事件日延续到下一事件日前一天 | 动态本金按期权CASE回退 |
| 普通互换历史持仓 | 按源业务日期直接匹配，不延续 | 持仓金额乘积补0，期初／结束后另有优先规则 |
| 金仕达本金、应记利息、用资成本 | 从本业务日延续到下一业务日前一天 | 对应金额保持NULL |
| 金仕达股票交易收入、成本 | 按实际业务日期匹配，不延续 | 分别补0 |
| FAST日终持仓 | 按源持仓日期匹配，不延续 | 金额乘积补0 |
| 金仕达履约保证比例 | 按合约、生成日取一条后延续 | 保持NULL |
| 计提费率 | 从原计提日延续到下一计提日前一天 | 保持NULL |

延续区间的最后一条记录以“加工日次日”作为右边界，所以通常延续到加工日。事件、金仕达延续金额、比例和费率的源查询没有统一加150日过滤：窗口前的一条记录仍可能延续进窗口，不能为了看起来统一而补上该条件。

例：金仕达18日有利息10、股票交易收入8，20日才有新记录。19日可继续输出取反后的利息-10，但当天没交易收入记录时输出0，而不是沿用8。源字段“当日应记利息”不保证消费后每一行都是计提日当天新增的利息。

## 看JOIN时，对准身份和日期

这些是实际连接条件，不是已验证唯一键：

| 主脚本别名 | 模块产物 | 连接合约主信息的身份 | 日期 |
| --- | --- | --- | --- |
| `evt` | 期权事件累计变化 | `key_option_deal_id = Inr_Seri_No` | 同一计提日 |
| `his_dy` | 普通互换逐日持仓金额 | `key_otc_trade_id = Inr_Seri_No` | 同一计提日 |
| `ks / ks_t` | 金仕达金额／交易收入成本 | `key_trade_comfirm_id = Agt_Id` | 同一计提日 |
| `nd` | FAST逐日持仓金额 | `key_instrument_id = Otc_Seri_No` | 同一计提日 |
| `prop` | 金仕达履约保证比例 | `CONTRACT_ID = Agt_Id` | 同一计提日 |
| `fee` | 延续后的计提费率 | `key_instrument_id = Otc_Seri_No` | 同一计提日 |

金仕达风控源字段CONTRACT_ID注释是“合约编号”，但代码把它接到主信息Agt_Id（金仕达确认书id）。这里只确认连接写法，实际编号能否对应仍需要数据证据。

所有资料都用LEFT JOIN，而且连接条件**没有另加grp_id限制**。CASE只选择哪份金额，不能防止其他连接的重复匹配扩大行数。输出也没有最终按合约、计提日去重，因此一行应理解为“一条基础记录展开出的合约日及其匹配结果”，不能直接认定为全局唯一的“合约＋日期”。

公共明细也不替消费统一定义“存续”“全年”“日均”：存续规模可能严格排除终止日，期间指标还要各自确定分子日期范围和分母。见[公共结果的消费边界](../07_公共结果如何进入收入与规模.md)。

- 原始基准：[107491冻结SQL](../99_证据/107491-query.sql)，绑定2026-09-16发布版本，索引核对日2026-09-18；没有查询线上最新任务，也没有执行生产SQL。
- 表与字段释义来自本地Hive / gfhive元数据记录，目录构建于2026-09-16；源表记录采集于2026-08-21、目标表于8月22日。`【AI】`沿用原标记，不当作人工确认定义。历史持仓腿键备注为空，其连接用途按SQL说明。
- 本地函数知识记载 `default.gfgreatest` 返回最大值，`default.datekey2date('20160101')` 示例返回 `2016-01-01`（2025-10-01资料）；不据此推定全部空值、非法日期行为。
- 同日重复记录、未来日期形成的负展开跨度、字符串金额的异常转换仍是原有边界。金仕达保证金同日去重没有稳定裁决键，不能称为“最新记录”。未新增过滤、去重或补造业务规则。
- 动态分区覆盖按计提日和分组写入；这段SQL不证明其他历史分区被删除，也不证明任务已成功运行。
- 写入标识为`write-observation:107491:8`。已有[上游表级查询](../99_证据/20260918-107491上游.json)使用同版主图、深度2，未触发条数截断，但停在深度边界且仍有未证明范围；不能把导航结果当作全链已确认。
