
**“计提”可以先理解成：把应归属于某一天的收入，计算并记到那一天。** 它不等于当天实际收到钱。

拿你正在看的销售日报举例：

假设一份合约：

- 本金365万元；
- 年化价差系数0.6%；
- 按这套规则，每天对应的价差收入是：`365万元 × 0.6% ÷ 365 = 60元`。

那么，9月15日对应60元、9月16日也对应60元。**这就是把收入按天算出来；这笔钱什么时候结算、支付，是另一件事。**

你可以把当前SQL里的几个词这样读：

|原词|好理解的说法|
|---|---|
|计提日|**这笔收入算在哪一天**|
|加工日|**系统在哪一天跑这次计算**|
|结算／支付日|**什么时候结算／实际付钱**|

例如系统9月22日重新计算9月15日的收入：加工日是22日，计提日仍是15日。

另外，**计提不一定是平均分到每天**：这份SQL中的年化价差按天算，绝对价差则只在合约期初定价日计算一次。这里只是在解释日报的收入归属规则，不代表已经形成会计凭证。

---


**计提 = 给每天的业务归属记一笔“应该产生多少收入/费用”。**

不是问：

> 钱什么时候到账？

而是问：

> 这一天，这个合约应该贡献多少收入？

---

举个最简单的例子。

你租房：

合同：

```
一年租金 36500 元
```

实际付款：

```
1月1日一次性支付36500
```

但是会计上不能说：

> 1月1日收入36500，其他日收入0

因为这36500对应的是一年使用权。

所以每天：

```
36500 ÷ 365 = 100元/天
```

每天记：

```
1月1日  收入100
1月2日  收入100
...
12月31日 收入100
```

这就是**计提**。

---

回到你的期权/衍生品。

比如：

一个合约：

```
本金：365万
年化收益/价差：0.6%
期限：1年
```

系统认为：

这一年产生：

```
365万 × 0.6% = 21900元
```

那么每天：

```
21900 ÷ 365 = 60元
```

所以：

```
9月15日
应该归属收入 60元

9月16日
应该归属收入 60元
```

---

但是：

客户什么时候付钱？

可能：

- 到期一次结算
    
- 月度结算
    
- 提前终止结算
    

例如：

9月15日产生60元：

```
计提日：9月15日
金额：60元
```

但是：

```
实际支付日：2027年1月1日
```

也可以。

---

对应你 SQL：

为什么要生成：

```sql
Accrued_Date
```

因为它不是交易日期。

它代表：

> 这条收入/费用应该归属于哪一天。

所以：

```
一份合约
    |
    + 9月18日 计提
    + 9月19日 计提
    + 9月20日 计提
    + 9月21日 计提
```

最后形成日报。

---

你前面看到：

```text
contract_days
```

本质就是：

把：

```
一张合约
```

变成：

```
每天一行
```

因为后面才能计算：

```
9月18日应该计提多少钱
9月19日应该计提多少钱
...
```

---

三个日期这样记：

|概念|问的问题|
|---|---|
|加工日|今天系统跑哪一天的数据？|
|计提日 Accrued_Date|这笔收入属于哪一天？|
|结算日|什么时候真正收付款？|

比如：

今天系统跑：

```
9月22日
```

但是补算：

```
9月20日的收入
```

那么：

```
加工日 = 9月22日
计提日 = 9月20日
```

---

结合你现在看的 SQL：

`contract_days` 的意义就是：

> 先生成“每天的账”，后面的收入/费用逻辑才能往每天这个账里填金额。

你之前理解 TRS/期权本金时用“状态”，这里要换成“时间归属”的概念。计提不是改变本金，而是在回答：**这一天应该记多少收益/费用。**
