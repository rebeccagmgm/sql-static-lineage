# 销售基础经营分类规则

**这一步是在给合约补一个经营分类标签。** 比如，交易系统记录“安全气囊”这一源类型，销售加工还会看它挂钩股票还是指数、合约何时开始，再决定放进“个股期权”还是“指数/ETF期权”等类别。

## 1. 先分清：来源分组、源类型、经营分类

| 看什么         | 对应字段                              | 例子／含义                                      |
| ----------- | --------------------------------- | ------------------------------------------ |
| 从哪一路加工进来    | `grp_id`                          | 01期权、02普通互换、03金仕达、04指定FAST TRS业务。它决定采用哪段加工 |
| 源系统记录的合约类型  | `Src_Contr_Type`                  | `AIRBAG`（安全气囊）、`AUTOCALL`（自动赎回）等，保留源类型     |
| 本次加工归入的经营类别 | `Contr_Type_Cd`＋`Contr_Type_Desc` | `OPTION_STOCK`＋“个股期权”等，是综合条件后的分类结果         |

例如，一条记录可以同时是：**01分组 → 源类型为安全气囊 → 经营类别为个股期权**。三个字段没有矛盾，它们回答的问题不同。

下游118141会用这个经营类别匹配价差、基础系数等参数，因此分类变化可能改变参数命中。依据：[118141 SQL](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055153.sql) L349、L381、L398。

## 2. 按什么顺序判断

| 步骤      | 判断内容                             | 容易看错的地方               |
| ------- | -------------------------------- | --------------------- |
| ①看来源分组  | 期权、普通互换、KS、FAST TRS分别判断          | 不是把四组混在一起套一张规则表       |
| ②看合约开始日 | 期权／普通互换：≤2025-03-31用旧规则，晚于该日用新规则 | 看的是合约开始日，不是今天的加工日期    |
| ③逐条匹配条件 | 在选中的规则中，从上往下找第一条命中项              | 一份合约即使符合多条，也只取最先命中的类别 |
| ④输出类别   | 保存经营分类代码及中文名称                    | 源合约类型仍另外保留，不被替换掉      |

下面先看新规则。中文类别采用当前SQL输出的名称；名称本身不代表本轮已确认正式产品制度。

## 3. 期权怎样分类：看标的，也看条款

这段SQL把`EQUITY/GDR`放入股票类判断，把`INDEX/FUND`放入指数／基金类判断；`QIS`进入量化策略指数分支。判断仍使用原始类别值，不是靠证券名称猜测。

| 优先顺序 | 归入什么类别                                                   | 要满足什么条件                                                               |
| ---- | -------------------------------------------------------- | --------------------------------------------------------------------- |
| 1    | **个股期权**<br>`OPTION_STOCK`                               | 股票类标的；源类型不在下方列出的五个特殊类型中；并且不是“自动赎回＋SNOWBALL子类型”                        |
| 2    | **指数/ETF期权**<br>`OPTION_IDX_ETF`                         | 指数／基金类标的；源类型为`ACCUMULATOR`、`DECCUMULATOR`、安全气囊，或“自动赎回且子类型不等于SNOWBALL” |
| 3    | **北上量化策略指数期权**<br>`OPTION_N_CROSS_QTF_STRG_IDX`          | 标的类别为QIS，同时交易台为`OTCHK_QIS`、卖方代码为`11613`                               |
| 4    | **量化策略指数期权（现货类）**<br>`OPTION_QTF_STRG_IDX_SPOT`          | 标的类别为QIS，标的代码不在`GAMMA.WI / CHARM.WI`中；前面的北上分支优先                       |
| 5    | **量化策略指数期权（非现货类）**<br>`OPTION_QTF_STRG_IDX_NONSPOT`      | 标的类别为QIS，标的代码在`GAMMA.WI / CHARM.WI`中；前面的北上分支优先                        |
| 6    | **Risky和安全气囊X（限售股）**<br>`OPTION_RISKY_AIRBAGX_PRI_STOCK` | 源类型为`RISKY/AIRBAGX`，标的类别为`EQUITY`，限售标志`PRIVATE_PLACEMENT=Y`           |
| 7    | **Risky和安全气囊X（流通股）**<br>`OPTION_RISKY_AIRBAGX_CIR_STOCK` | 源类型为`RISKY/AIRBAGX`，限售标志不是Y；这里明确把NULL先按N处理。当前条件没有再限定标的必须为股票           |
| 最后   | **其他期权**<br>`OPTION_OTHER_NONSTOCK`                      | 前面所有条件都未命中                                                            |

第1行排除的五个源类型是：`RISKY / AIRBAGX / AIRBAGM / AIRBAGL / CUSTOMISED`。这些代码保留精确范围，不把未知类型名称自行翻译成产品定义。

**两个细节：**“其他期权”的代码虽带`NONSTOCK`，当前SQL中文名就是“其他期权”，不能据代码认定全部是非股票；“流通股”分支也不能被中文名称补上SQL中没有的股票条件。

依据：[86840 SQL](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055365.sql) L34–47（条件与代码）、L62–75（中文名称）。

## 4. 普通互换怎样分类：看源类型、标的、IPO及公司

| 优先顺序 | 归入什么类别                                       | 要满足什么条件                                                        |
| ---- | -------------------------------------------- | -------------------------------------------------------------- |
| 1    | **借券互换**<br>`TRS_SHORT_SELL`                 | 源类型为`LEND_SWAP`，标的类别为`EQUITY/GDR`                              |
| 2    | **南下量化策略指数互换**<br>`TRS_S_CROSS_QTF_STRG_IDX` | 标的类别为QIS；本条没有再限定源互换类型                                          |
| 3    | **南下期货**<br>`TRS_S_CROSS_FUTURES`            | 源类型为`S_CROSS_FUTURE_SWAP`                                      |
| 4    | **南下IPO**<br>`TRS_S_IPO`                     | 源类型为`S_CROSS_SWAP/S_CROSS_OPTION_SWAP`；股票类标的；标的币种不是CNY；IPO标志为Y |
| 5    | **南下跨境股票**<br>`TRS_S_CROSS_STOCK`            | 上述两种源类型；股票类标的；IPO标志为N或NULL。此条没有再限制币种                           |
| 6    | **北上指数增强**<br>`TRS_N_CROSS_INDEX_ENHANCE`    | 账簿公司为`GFS_HK`，源类型为`INDEX_ENHANCE_SWAP`                         |
| 最后   | **其它互换类型**<br>`TRS_OTHER_SWAP`               | 前面所有条件都未命中                                                     |

“南下／北上”是当前SQL给出的分类名称，本表严格按右列条件说明，没有从名称追加地域或客户范围。依据：[86841 SQL](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055616.sql) L35–41、L57–63。

## 5. 为什么还要保留旧规则

**旧合约在今天加工，仍会按它的开始日选择旧规则。** 下表帮助理解变化；完整旧条件仍保留在[精确条件对照](../99_证据/经营分类精确条件对照.md)。

| 观察对象            | 旧规则（开始日≤2025-03-31）     | 新规则中的变化                         |
| --------------- | ----------------------- | ------------------------------- |
| 期权中的自动赎回、安全气囊   | 多个类别保留条款类型，并区分股票／非股票    | 部分合约归到“个股期权”“指数/ETF期权”；仍需满足各自条件 |
| 量化策略指数期权        | 有北上QIS专门分支              | 继续保留北上分支，并增加现货／非现货QIS分类         |
| 普通互换的南下股票相关分支   | 区分限售股、港股及其他股票市场；另有IPO分支 | 非IPO股票进入同一个“南下跨境股票”分支；IPO仍单列    |
| 北上A股、多空互换、南下债券等 | 有各自明确的旧分支               | 新CASE不再单列这些旧类别，需重新匹配，不能直接继承旧代码  |
| 无条件命中的期权        | 旧CASE没有兜底，可能输出NULL      | 新CASE兜底为“其他期权”                  |

依据：[86840 SQL](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055365.sql) L21–75、[86841 SQL](../../../../attachments/02.1-销售基础经营分类规则/IMG-02.1-销售基础经营分类规则-20260921105055616.sql) L21–64。

## 查到具体记录时再看这些技术边界

- **空值：**“不属于某集合”通常不会自动包含NULL；只有SQL明确写了`coalesce`或`is null`才按对应规则处理。
- **组合标的：**部分标的类别／币种先聚合成字符串，随后按整串比较，不能自行当作逐成分判断。
- **按需追溯：**[精确条件对照](../99_证据/经营分类精确条件对照.md)保留原有全部新旧条件、源字段和输出代码；[四个生产分支](README.md)解释这些输入怎样形成。
- **SQL复用：**目标表DDL、3个公共视图和4个分支脚本的[拆分方案](公共视图抽取.md)已按可复用主脚本数标记；该方案不是已上线对象。
