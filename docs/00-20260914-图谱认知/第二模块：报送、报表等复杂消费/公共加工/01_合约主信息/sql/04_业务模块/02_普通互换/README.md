# 02 普通互换：从合约、腿、持仓读到销售主信息

这组 SQL 把互换合约、挂钩标的、客户、保证金和利率条款放在一起，形成销售经营使用的合约资料。先理解三个对象：**合约管整体信息，腿区分持仓与利率条款，持仓记录腿下面的标的和数量。**

“普通互换”是当前分支的名称，包含多种源互换类型。最终由[主脚本](../00_分支主脚本/02_普通互换.sql)写入 `T98_OTC_DERI_COMP_SALE_INFO` 的 `grp_id='02'` 分区。

## 先认清三个对象

| 对象 | 在这里记录什么 | 连接入口 |
| --- | --- | --- |
| 互换合约 | 客户、互换类型、起止定价日、币种、合约状态 | `key_otc_trade_id`：内部交易流水号 |
| 互换腿 | 结构腿提供持仓入口及 IPO/限售属性；非结构腿提供固定或浮动利率等条款 | 通过交易键接合约；腿自身有 `key_leg_id` |
| 腿的历史持仓 | 标的证券、源业务日期、期初交易价、初始数量、当日数量 | 通过 `key_leg_id` 接结构腿 |

同一份合约可以连接多条腿，同一条腿可以涉及多个标的。这里的交易键、腿键、标的证券内码分别属于不同对象。

### 初始持仓文件内部怎么接起来

打开 `07_初始持仓.sql` 后，按以下四步读：

| 步骤 | 中间结果 | 每一步做什么／保留什么 |
| --- | --- | --- |
| ① 历史排序 | `ranked_initial_positions` | 加工日快照内，按“腿＋标的”分别依源业务日升序编号；此时未删历史记录 |
| ② 选初始记录 | `first_initial_positions` | 每组取编号1；不同标的可选到不同日期 |
| ③ 补标的属性 | `initial_position_details` | 关联证券、工具池、期货属性及字典；保留LEFT JOIN的多条匹配，不去重 |
| ④ 按腿汇总 | `initial_position` | 汇总初始本金及标的摘要；主脚本仍用 `his_ini` 引用这个结果 |

注意：金额在补标的属性后汇总，维表多条匹配可能放大金额，并未做去重。

## 为什么需要“初始持仓”和“当日持仓”

普通互换先从 `odata_n_tit.d_pos_trs_leg_his_pos`（腿的历史持仓表）算金额，再乘合约提供的汇率。两个文件都输出名为 `Nom_Prin` 的金额，但选取记录和数量字段不同：

| 比较项 | 初始持仓（07_初始持仓.sql） | 当日持仓（08_当日持仓.sql） |
| --- | --- | --- |
| 快照范围 | 加工日快照 | 加工日快照 |
| 从快照中选哪些记录 | 每个“腿＋标的”按 `src_busi_date` 取最早一条 | `src_busi_date` 的日期部分等于加工日 |
| 价格 | 所选最早记录的 `Init_Price` | 当日记录自身的 `Init_Price`，不取初始持仓结果中的价格 |
| 数量 | `Init_Quantity` | `Quantity` |
| 金额 | Σ（期初交易价 × 初始数量） | Σ（期初交易价 × 当日数量） |
| 在主脚本中的引用 | `his_ini.Nom_Prin` | `his_dy.Nom_Prin` |
| 其他用途 | 汇总标的代码、名称、证券集、币种，供分类与展示 | 只提供动态本金计算所需金额 |

### 持仓金额怎样变成输出本金

假设单一标的、无重复匹配：初始记录是期初价10、初始数量100，初始持仓金额为1000；当日记录是期初价10、当日数量60，当日持仓金额为600。这还没做人民币换算。

在 [10_本金与汇率.sql](00-20260914-图谱认知/第二模块：报送、报表等复杂消费/公共加工/01_合约主信息/sql/04_业务模块/02_普通互换/10_本金与汇率.sql) 中，合约别名 `rt` 来自 `odata_n_tit.d_ref_trs`（场外交易-TRS），按以下顺序选**同一个汇率**用于两份金额：

| 首个满足的条件 | 采用的汇率 |
| --- | --- |
| 合约币种 `currency='CNY'` | 1 |
| 本币币种 `base_currency='CNY'` | `base_init_exchange_rate` |
| 结算币种 `settlement_currency='CNY'` | `settle_init_exchange_rate` |
| 都不满足 | NULL |

假设本例满足第二项，所选汇率为0.9，则**初始名义本金=1000×0.9=900，动态名义本金=600×0.9=540**。这里的“动态”使用当日数量，不是用当天市价重估。绝对名义本金则固定输出 `'0.0'`，并未另算。

初始金额缺失不补0；当日金额缺失先补0，但汇率缺失时乘积仍为NULL。实际连接是“结构腿 → 初始持仓结果 → 当日持仓结果”，当日结果通过初始结果的腿键接入，而不是从初始结果取价格、数量。

这里的“初始”不是一张固定的合约首日持仓清单。它按每个标的分别寻找最早记录，可能取到不同日期；后来才加入的标的，其首条记录也可能进入结果。当日持仓缺失时，不会自动延续前一日数据。

与期权对照：期权分支直接读取合约上的 `initial_notional`、`notional`；普通互换从持仓计算。这是当前加工的来源差异。原有[期权 vs TRS 本金计算方式笔记](<笔记/期权 vs TRS 本金计算方式.md>)可配合阅读，范围限定在这组销售基础 SQL。

## 两种“标的”、两套“关联合约”

| 容易混淆的对象 | 来源与用途 |
| --- | --- |
| 持仓证券标的 | 历史持仓的 `underlying_ins_id` 接证券资料；输出 `Undrl_Ins_Id`，并参与本金、经营分类 |
| 浮动利率挂钩标的 | 非结构腿的 `underlying_ins_id`；仅浮动腿时输出 `Float_Undrl_Cd`，不用于替换持仓证券 |
| `Rel_Agt_Id` | 当前互换的 `relatedOption` 属性值直接输出；本 SQL 没有继续读取关联期权的条款 |
| `Marg_Agt_Id` | 从有效期权—互换关联关系中，按互换交易键汇总期权交易键；这个方向没有另限 `LONG_HOLD_SWAP` |

互换的固定/浮动利率来自腿；共享目标表中的期权票息、敲入、敲出等字段在本分支填 NULL。有关联期权属性，不代表本分支已经拼入了期权条款。

## 源字段名字与输出名字要对着看

| 源字段 | 本地元数据原义 | 这份 SQL 的使用方式 |
| --- | --- | --- |
| `rt.start_date` | 期初定价日 | 输出 `Strt_Pric_Date`，并用于经营分类的新旧口径分界 |
| `TOCR.actual_settlement_date` | 实际结算日 | 输出目标字段 `Early_Term_Date`（提前终止日） |
| `rtl.ipo_type` | 【AI】限售类型 | 用于 IPO 标志和南下 IPO 分类；不要用该注释覆盖实际判断条件 |
| `rtl_f.fixed_rate` | 固定利率 | 固定腿输出 `fixed_rate`；浮动腿仍取同名字段输出 `Float_Base_Rate` |
| `rt.seller` | 卖方，关联交易对手ID | 参与买卖方向判断及卖方交易对手编号输出，不能当作销售人员 |

分类和标的展示中的币种取自初始持仓关联的证券表，不是上面选择汇率时使用的合约币种。

## 怎样理解最终一行

持仓结果按腿汇总，主查询还会同时关联结构腿、非结构腿、客户及报备等资料，因此**不能默认最终一合约一行**。多个标的拼接出的字段是摘要，各列独立收集且未指定顺序，不能按分号位置重新拼出完整成分明细。

对照连接与筛选看[主脚本](../00_分支主脚本/02_普通互换.sql)，需要连续阅读时看[完整 SQL](../../05_完整SQL/02_普通互换.sql)。
