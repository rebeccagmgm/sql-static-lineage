# 04 指定 FAST TRS：北上极速的合约、持仓与本金

这条分支只处理极速互换合约表中 `trs_type='N_CROSS_DMA_SWAP'` 的记录，本地类型字典名称为“北上极速”，**不是全部 FAST 互换**。结果写入销售主信息表 `T98_OTC_DERI_COMP_SALE_INFO` 的 `grp_id='04'` 分区。

先抓住与普通互换的区别：**本分支不经过结构腿取持仓，不用价格乘数量计算本金，而是直接汇总源持仓金额。**

## 先认识三个对象

| 对象／实际来源 | 提供什么 | 怎样连接 |
| --- | --- | --- |
| OTC交易：`odata_n_tit.d_trd_otc_trade` | 主合约编号、内部交易键、工具键及所属账簿 | 是主查询起点；公共视图已连接账簿并限定OTC/OTC_HK、排除测试账簿 |
| 极速互换合约：`odata_n_tit.d_ref_fast_trs` | 类型、期限、状态、客户、卖方、结算币种等 | 通过 `key_otc_trade_id` 连接交易，只收北上极速类型 |
| 北上极速腿历史持仓：`odata_n_tit.d_pos_fast_trs_leg_his_pos` | 每个标的的日期、代码、类型、币种及金额 | 按 `key_instrument_id` 汇总后接交易的工具键 |

持仓表虽叫“腿历史持仓”，但本 SQL **没有连接腿表，也没有按腿键汇总**。持仓表的 `key_instrument_id` 注释为“合约ID”；证券基本信息表的同名字段则是“证券内码”，两者不应当作同一个标的键。

## 沿这条主线读

```text
交易 ──交易键──→ 指定FAST合约：确定业务范围、客户与期限
  ├─工具键──→ 初始持仓：各标的最早日终记录 → 标的资料＋初始本金
  └─工具键──→ 当日持仓：加工日日终记录     → 动态本金
                                      ↓
                     输出本金：直接取汇总金额，不再换汇
```

两份持仓各自读取同一张源表，分别直连交易；不是先算初始持仓，再从中算当日持仓。

## 初始和当日：同一个金额字段，两种选日方式

两边都限定数据日期 `busi_date` 为加工日、持仓类型为 `EOD_POSITION`（日终持仓）。`src_busi_date` 则是源持仓日期，用来区别历史记录与当天记录。

| 比较项 | 初始持仓结果 `initial_position` | 当日持仓结果 `daily_position` |
| --- | --- | --- |
| 主脚本别名 | `dy`，这里不表示“当日” | `np` |
| 选记录 | 按“工具键＋WIND代码”分别取最早源持仓日期的一条 | 源持仓日期的日期部分等于加工日，保留符合条件的全部记录 |
| 金额来源 | 所选最早记录的 `dynamic_notional` | 当日记录的 `dynamic_notional` |
| 汇总前处理 | 先补证券、期货、类型字典资料，再求和 | 直接求和，不补维表 |
| 汇总粒度 | 每个合约工具键一行 | 每个合约工具键一行 |
| 输出引用 | `dy.Init_Nom_Prin`，缺失保持NULL | `np.Dyna_Nom_Prin`，输出时缺失补 `'0'` |
| 其他用途 | 提供最终展示的标的摘要 | 只提供动态本金 |

例如同币种且无重复匹配时，A标的最早金额100、B标的最早金额200，初始本金为300；当日A为80、B为150，动态本金为230。A、B的最早记录可以来自不同日期；后来加入的标的，也可能贡献它的首条记录。这不是固定合约首日的完整持仓清单。

**“初始本金”也取 `dynamic_notional`，没有取源表的 `notional`，也没有重算价格×数量。** 源表同时存在这些字段，不代表本SQL都使用它们。源系统如何算出 `dynamic_notional`，不由这段消费SQL证明。

### 初始持仓内部的四步

`07_初始持仓.sql` 内部顺着四个结果读即可，不需要跳子文件：

1. `ranked_initial_positions`：按工具键、WIND代码给历史记录排序。
2. `first_initial_positions`：每组取编号1；同日并列没有额外裁决键。
3. `initial_position_details`：逐条补证券资料，并计算标的市场类别。
4. `initial_position`：按合约工具键汇总金额、拼接展示属性。

补资料后的重复匹配仍参与金额汇总；没有因为拆成四步而新增去重。当日持仓模块没有这些维表连接，因此两边受重复匹配影响的路径不同。

## 汇率1，不等于已经证明金额是人民币

本SQL固定输出 `Cny_Ex_Rate='1'`，直接采用两份持仓汇总金额，不查市场汇率、不乘期初汇率，也不另加合约起止日期判断。`Absl_Nom_Prin`固定为 `'0.0'`，不是取绝对值计算。

本地元数据把**持仓表**的 `dynamic_notional` 注释为“动态名义本金（标的币种）”，把**合约表**的同名字段注释为“动态名义本金（结算币种）”。本分支读的是前者。因此只能确认本层未换汇，不能把合约表注释拿来说明持仓金额，更不能仅凭固定汇率1断言全部为人民币金额。

原SQL按合约工具键求和，未按币种分组；上游是否限制单一币种、是否做过其他换算，仍需上游证据确认。本次保留原口径，不补造换算。

## 标的类型、币种和中文名称并非同一个来源

| 输出内容 | 实际来源／规则 |
| --- | --- |
| 标的ID、WIND代码、简称 | 所选最早持仓记录的 `underlying_ins_id / wind_code / ins_sht_desc` |
| 标的长名称 | 持仓WIND代码连接证券表 `d_ref_instrument.wind_code`，取证券全名 |
| 标的市场类别 `Undrl_Type` | 用**持仓记录的标的类型** `ins_family` 判断股票类，再按**证券表币种**区分港股、美股、其他股票；非股票类为NON_STOCK，其余为“-” |
| 源标的类型 `Src_Undrl_Type` | 持仓表的 `ins_family` |
| 源标的类型描述 | 用证券表的 `ins_family` 查CD128字典，不是直接查持仓类型 |
| 展示币种 `Undrl_Curr` | 持仓表的 `currency`，不是用于市场分类的证券表币种，也不是合约结算币种 |
| 期货类型 | 证券表的证券内码连接期货属性表 `d_ref_future_properties` |

市场分类中的股票类包括EQUITY、GDR、BASKET；币种HKD对应HK_STOCK，USD对应US_STOCK，其他非NULL值对应OTH_STOCK（空串也满足该条件）。证券币种为NULL时，股票类会落到“-”，不能当成“其他市场”。

代码／名称按分号拼接，类型／币种按逗号拼接；各列独立收集、未指定顺序，不能按位置重新组成标的明细。类型代码和描述甚至可能来自两边不同的 `ins_family`，有差异时不能擅自互相替换。

## 分类与附属资料：哪些保留、哪些只是固定输出

- **经营分类**与源合约类型两组字段相同，都取 `rt.trs_type` 和CD382字典名称；不套普通互换按日期切换的新旧分类。字典没匹配到时，名称保持NULL。
- **保证金合约编号**直接取保证金参数的 `margin_internal_trade_id`；不是普通互换那条“汇总关联期权交易键”的来源。`relatedOption`属性另行输出关联合约编号。
- **提前终止日**这个目标字段取合约报备的 `actual_settlement_date`，源字段原义是实际结算日。
- **限售、IPO标志**均固定为 `'0'`，不是本SQL检查了实际属性后得出的判断。
- **固定／浮动利率、期权条款**未在本分支读取，按原SQL填NULL或空串；`seller`是卖方，不是销售人员。

最终保留EFFECTIVE、EFFECTIVE_PENDING、TERMINATED、TERMINATING、TERMINATING_PENDING五类状态，包含已终止合约，不是“只留存续”。两份持仓虽各按工具键汇总，其他资料的多条匹配仍可能扩展结果，不能默认最终一合约一行。
