# 01期权：按加工关系阅读

这里分四层，不再把九份SQL平铺。**先理解核心加工，再按需看补充资料，最后看金额与输出。**

~~~text
01_公共输入
    │
    ▼
02_核心加工：合约基础 → 标的识别 → 经营分类
    │
    ▼
主脚本补充关联 ◀── 03_补充资料（客户与保证金 / 条款 / 估值）
    │              公共客户、组合计划和汇率也在主脚本关联
    ▼
04_金额与输出：计算本金 → 排列90列 → 主脚本写入01分区
~~~

这是阅读和数据依赖关系，不是数据库物理执行顺序。补充资料是并列输入，不是三道串行加工。

## 表名和字段旁的中文从哪里来

表注释、关键字段释义来自本地表元数据 SQLite（2026-09-16 构建；本次命中记录采集于 2026-08-21～22），按 Hive / gfhive / 完整表名匹配，不借用其他系统同名表的注释。它们是离线快照，不代表平台当前状态。

- `【AI】` 是元数据原有标记，照录但不当成人工确认定义。
- 汇率表的表注释、篮子表的 `busi_date` 注释缺失，已回看对应原始 `ddl.sql`，仍为空；SQL用途说明与元数据释义分开写。
- 字段单位、日期含义优先照录元数据；例如 `start_date` 是“期初定价日”，`collateral_notional` 是“绝对名义本金（元）”。条款模块保留百分比与价格的区别。
- 来源入口：[本地 SQLite 查询导航](../../../../../../../local-sqlite-guide.md)；原始 DDL 位于相邻数据目录的 `tables/hive/<完整表名>__gfhive/ddl.sql`。新增说明只改注释，不改筛选、连接或金额公式。
