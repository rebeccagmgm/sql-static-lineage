# 对内与香港：基础系数、基础收益率不是同一个量

对内普通收入把**基础系数作为额外乘数**，把**基础收益率与价差相加**；交叉与香港普通收入中的基础奖励系数则按年化／绝对方式形成一项贡献。它们可以共用生产说明，不能据“基准”二字统一公式或选择优先级。

本页负责参数从哪里来、怎样匹配；[114013对内收入](../../销售与经营分析/114013_对内销售收入/README.md)和[220979香港收入](../../销售与经营分析/220979_香港销售收入/README.md)负责从这些参数继续算到日报。

## 对内先准备三份资料，不能画成串行的三步

```text
G_INR_CONTRACT_MAPPING ─121685→ 分类映射mp ─┐
收入专题本地CASE分类 ────────────────────┤ 确定内部类型
G_INR_BASE_RATE ────────121683→ 类型参数b ─┘ 再按期初日选版本
G_INR_CONTRACT_BASE_RATE ─133054→ 合约参数cb ── 按合约号匹配
                                                       ↓
                      114013分别选择计算方式、系数、收益率
```

| 生产任务与完整SQL | 写入PDATA_N结果 | 一条配置保存什么 | 下游何时用 |
| --- | --- | --- | --- |
| [121685分类映射](09_对内分类映射生产_121685.sql) | `T99_OTC_DERI_INR_BASE_MAPPING` | 源合约类型、子类型、标的类型串与运管类型编号 | 收入专题重新分类后的回退映射 |
| [121683类型基础参数](08_对内类型基础参数生产_121683.sql) | `T99_OTC_DERI_INR_BASE_REF` | 类型、实际生效日、计算方式、系数、基础及附加收益率 | 按最终内部类型＋合约期初日匹配 |
| [133054合约基础参数](07_对内合约基准生产_133054.sql) | `T99_DERI_COMP_BASE_COEF_REF` | 识别后的合约、计算方式、系数与基础收益率 | 按原合约号匹配，不用日期挑版本 |

121683、121685只是完整原值映射，生产时将Y/N删除标志转为1/0，仍保留记录；目标按源表＋业务日期覆盖。133054还补身份，按来源分区写入合约基准T99；源合约号进入`Inr_Comp_No`，识别结果进入`Agt_Id`，额外奖励两列填空。三个生产查询均没有把收益率除100。

### 类型怎么定，为什么还要映射表？

114013先在自己的主信息层做CASE，形成`info.Inr_Contr_Type_Cd`。映射表消费时将`Src_Undrl_Type_Cd_Str`按逗号拆开，再连接源合约类型、子类型与归整后的标的类型；最终用于取参数的类型是：

```sql
coalesce(info.Inr_Contr_Type_Cd, mp.otc_contract_type, 'CD017')
```

所以121685并没有一次性替三份收入完成经营分类。该映射的源子类型为NULL时可回退主体子类型参与比较，空串不会回退；主线会保留具体ON条件。多条映射命中会扩行，备用类型`CD017`也不代表已证明其业务制度含义。

### 类型b按期初日选，合约cb没有按日选

类型参数只取当日快照、指定源、未删除的行；同类型按`Actl_Vld_Day`排序，区间为当前生效日至下一生效日前一天，最后延续到运行日。展开后用**内部类型＋合约期初日**匹配。计提日跨过另一版本生效日，并不会因此改用新类型参数。

合约参数只取`G_INR_CONTRACT_BASE_RATE`来源、未删除且`Agt_Id != ''`的行，按`Inr_Comp_No = info.Agt_Id`匹配；没有LEAD、按日期筛选或最新一条选择。同一合约多条配置仍可能扩行。

## 跟一份对内合约选完三个值

沿用对内收入主线的构造合约`INR_DEMO`：期初9月18日、结束9月20日，本次加工9月21日。普通OPTION未命中B2B、RISKY、AIRBAG等前置分支；本地CASE分类为空，映射`mp`提供CD017。这里的CD017是示例维护值，不以默认回退冒充实际分类结果。参数记录不存在重复。

| 输入 | 计算方式 | 基础系数 | 基础收益率 | 附加收益率或价差 |
| --- | --- | ---: | ---: | ---: |
| 类型b，CD017，9月1日生效 | ANNUALIZED | 1 | 0.004 | 0.002 |
| 合约cb，合约号INR_DEMO | ABSOLUTE | 2 | 0.003 | 不提供 |
| 合约价差sp，INR，从9月18日生效 | ANNUALIZED | 不提供 | 不提供 | 年化0.002，绝对0.01 |

9月18—20日计算收入时，类型b均由9月18日期初命中9月1日的版本。两路基准与价差均连接后，分别选择：

| 要选的值 | 114013实际优先级 | INR_DEMO得到什么 |
| --- | --- | --- |
| 普通分支计算方式 | `b.base_calculation → cb.base_calculation → sp.Spread_Calculation → 'ABSOLUTE'` | 年化，来自类型b；合约cb的ABSOLUTE不优先 |
| 基础系数 | `cb.Base_Coef → b.Base_Coef → 0`（公式内） | 2，来自合约cb |
| 基础收益率 | `cb.Base_Rate → b.Base_Rate → 0`（公式内） | 0.003，来自合约cb |
| 年化分支价差 | `sp.Annualized_Spread → b.Spread_Rate → 0` | 0.002，来自合约价差sp |

9月18日动态本金3,650,000，普通年化分支得到`3,650,000 × 2 × (0.003 + 0.002) ÷ 365 = 100`；19日、20日本金分别2,920,000、1,825,000，收入依次为80、50。它们是分配前原始收入；主线继续说明9月21日本金0、主／引入经办40%／60%分配和累计230。由本页选出的同一组参数进入后续计算，不重新换一份合约。

只将合约cb的基础系数改成NULL，其他不变，就回退到类型1，18—20日得到50／40／25；改为0则为0。只把类型计算方式改NULL，便回退合约ABSOLUTE，期初用绝对价差0.01得到`3,650,000 × 2 × (0.003 + 0.01) = 94,900`，后两日为0。**“合约优先”一句话解释不了这组结果。** 空串也不触发COALESCE回退。

### 参数查询113993的展示不等于114013的计算方式

两者共用三份上游，但消费并不完全相同：

| 消费 | 计算方式选择 |
| --- | --- |
| 114013普通收入CASE | 类型b优先，其次合约cb，再取价差sp，最后默认ABSOLUTE |
| 113993的`Calc_Method`展示 | `coalesce(sp.Spread_Calculation,b.base_calculation)`，价差优先且没有cb |

113993合约价差还用生效日倒序选第一条，并输出配置历史；114013按计提日展开。参数查询看到的类型、费率或最新版本不直接证明日报历史日使用同一组参数。

## 香港：合约基准继续共用，类型基准直接按业务与标的匹配

合约侧`s_ba`仍读133055生产的`O_CONTRACT_BASE_RATE`来源分区，以`Inr_Comp_No = info.Agt_Id`匹配；不读取133054的INR分区。合约参数缺失时，香港类型侧`c_ba`提供后备值：

| 项目 | 220979／220981实际行为 |
| --- | --- |
| 输入 | `ODATA_N_OIS.G_REV_HK_SALES_BASE_COEF`当日快照，`is_deleted='N'` |
| 匹配 | `business_type = info.Busi_Type`且`underlying_type = info.HK_Undrl_Type` |
| 读入 | `base_calculation`基础奖励计算方式、`base_award_rate`基础奖励系数 |
| 日期 | 不展开区间，不用期初日或计提日做此JOIN |
| 选择 | 计算方式与系数分别优先合约`s_ba`，NULL才回退`c_ba`；类型没有统一默认值 |

沿用香港收入主线的`HK_TRS_DEMO`：TRS＋EQUITY、期初9月18日、结束9月20日、9月21日加工。合约侧基准为年化0.004，类型侧也提供年化0.004的后备值，正常选择来自合约；与年化价差0.006合用，在18日本金3,650,000上先形成100的年化项，再由主线接上佣金。

从原例只令合约配置不再匹配，则计算方式和系数都回退类型，数字仍为年化0.004；来源变化不一定改变金额。只把合约计算方式改NULL，系数仍0.004，就得到“类型侧年化＋合约侧系数”的组合。两路类型都缺失时，普通收入CASE可能不命中，不能把系数补0误读成整笔收入必为0。

[224025生产SQL](10_香港类型基准生产_224025.sql)把同一香港源配置写入`T99_DERI_COMP_TYPE_BASE_COEF_REF`的独立来源分区，`Bel_Busi_Dept='OTC_HK'`，合约类型、生效日及期初日期上下限填空。**220979／220981冻结SQL仍直接读取ODATA**，这个并行T99映射不是日报必经节点，也不能替香港源补出一套不存在的日期规则。
