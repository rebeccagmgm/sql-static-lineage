# 香港资金成本：给特殊期权匹配哪一个成本率？

香港资金成本为`RISKY／AIRBAGX`收入分支提供费率扣减项。**参数一行代表一种香港合约类型、标的类型及适用日期范围的配置，不是一份合约已经发生的每日成本金额。** 普通香港期权和普通互换的价差／基准／佣金分支没有统一扣除这项成本。

## 先分清配置生产和日报实际读取

```text
G_REV_HK_CAPITAL_COST当日配置 ───────────→ 220979的cc参数
             │                          按香港合约类型＋标的类型＋期初日匹配
             └─ 224026原值映射 → 资金成本T99香港来源分区
```

[224026完整生产SQL](05_香港资金成本生产_224026.sql)是简单映射：

| 香港源字段 | T99目标字段 | 在这条生产中怎样处理 |
| --- | --- | --- |
| `BUSINESS_TYPE` | `Busi_Type` | 保留业务类型 |
| `CONTRACT_TYPE / CONTRACT_TYPE_NAME` | `Src_Comp_Type_Cd / Src_Comp_Type_Desc` | 保留香港合约分类 |
| `UNDERLYING_TYPE` | `Src_Undrl_Type_Cd` | 保留香港标的类型 |
| `CAPITAL_COST` | `Fnd_Cost` | 原值传递，没有除100或乘本金 |
| `START_DATE / END_DATE` | `Intr_Strt_Date / Intr_End_Date` | 原值传递，未截短或展开日期 |
| `IS_DELETED` | `Del_Flag` | Y/N转1/0，生产仍保留这些行 |

目标为`PDATA_N.T99_DERI_COMP_TYPE_FND_COST_REF`的该来源分区，`Bel_Busi_Dept='OTC_HK'`，`Vld_Date`与`Src_Dept_No`填空。一行源配置输出一行，无JOIN、聚合或去重。

220979的冻结SQL却直接读取`ODATA_N_OIS.G_REV_HK_CAPITAL_COST`，没有读这份T99结果。因此图中是并行去向，不是“先224026，再220979”。220981参数查询没有这路资金成本JOIN，不能把它当作香港所有配置的统一展示页。

## 日报按期初日选择，业务类型没有进入ON

220979先筛加工日、`is_deleted='N'`，再展开配置区间。`start_date='2023-01-01'`替换为`2024-01-01`，`end_date='2999-12-31'`替换为运行日。正常区间含首尾。

| cc字段 | 在JOIN中的角色 |
| --- | --- |
| `contract_type` | 等于`info.HK_Contr_Type_Cd`，香港专题生成的合约分类 |
| `underlying_type` | 等于`info.HK_Undrl_Type`，香港专题生成的标的分类 |
| 展开后的`busi_date` | 等于`info.Strt_Pric_Date`，合约期初日 |
| `business_type` | SELECT读出，但ON未使用 |
| `capital_cost` | 匹配成功后供特殊收入公式使用 |

它没有用收入计提日选参数，也没有因为读出`business_type`就按业务类型隔离。重复配置、重叠区间，乃至仅业务类型不同的记录，都可能匹配多条；当前LEFT JOIN没有选最新或去重。

## 同一份HK_RISKY_DEMO，从配置0.05到每天120

沿用[香港特殊收入主线](../../销售与经营分析/220979_香港销售收入/README.md)的构造合约：9月18日期初、9月20日结束、9月21日加工；`OPTION / RISKY / Res_Flag=0`，分类为`OPTION_RISKY_AIRBAGX_CIR_STOCK`，香港标的类型EQUITY，抵扣模式不是DEDUCTION，保证金关联合约为空。

假定两条源配置均未删除，且没有其他重复匹配：

| 配置的香港合约类型及标的 | START_DATE—END_DATE | CAPITAL_COST |
| --- | --- | ---: |
| OPTION_RISKY_AIRBAGX_CIR_STOCK＋EQUITY | 2026-09-01—2026-09-18 | 0.05 |
| 同一组合 | 2026-09-19—2026-09-30 | 0.06 |

9月18—20日的合约日记录均拿期初9月18日匹配第一条，所以`cc.capital_cost=0.05`。19日不会因为计提日跨到下一段就换0.06。

| 输入／阶段 | 本例值与结果 | 来源／使用位置 |
| --- | --- | --- |
| 参数生产参考 | 0.05仍写成T99.Fnd_Cost=0.05 | 本目录05；生产没有算金额 |
| 日报参数匹配 | 实际从ODATA选中0.05 | 香港主线03的cc JOIN |
| 18—20日每日动态本金 | 3,650,000 | 逐日本金明细`det.Dyna_Nom_Prin` |
| 初始保证金比例、费率 | 0.2、0.106 | 主信息`Init_Marg_Prop`、逐日明细`det.fee_rate`；不是成本配置提供 |
| 原始当日收入 | `3,650,000 × (1−0.2) × (0.106÷1.06−0.05) ÷365 ×0.3 = 120` | 香港主线原始收入，无关联保证金分支 |

三日共360；9月21日本例动态本金为0，收入为0。后续按70%／30%介绍比例分配为252／108，主线继续解释累计；不能把120误称为“资金成本金额”，它已经是使用成本率后的完整特殊分支收入。

从原例只把命中配置的`CAPITAL_COST`由0.05改为0.06，每天收入变为96；若只把这一值改NULL，引用它的公式返回NULL，不按零成本处理。若只把`Marg_Agt_Id`填成`MARGIN_DEMO`，则切到有关联分支，使用同一成本率及基础保证金率`Base_Marg_Rate=0.1`，每天为105；这条分支如何换保证金基数由收入主线解释，参数生产没有随之变化。

## 与118141共用概念，不能共用整个匹配模块

| 区别 | 118141 | 220979香港 |
| --- | --- | --- |
| 实际输入 | 133057生产的资金成本T99、OTC部门 | 直接读香港OIS配置 |
| 分类匹配 | 经营合约类型＋期初日 | 香港合约类型＋香港标的类型＋期初日 |
| 日期下限替换 | 1900-01-01→2019-01-01 | 2023-01-01→2024-01-01 |
| 主要使用分支 | AIRBAG、金仕达 | RISKY、AIRBAGX |

源字段中文注释为“资金成本”；“费率”来自公式用途，未额外宣称维护界面的单位制度。1.06、0.3是冻结SQL中的常数，本专题不解释为未核验的税率或分配制度。
