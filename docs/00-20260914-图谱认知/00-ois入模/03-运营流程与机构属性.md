# 运营流程与机构属性

OIS 同时保存配置和过程记录。配置说明一项业务应如何组织；事件说明某次处理留下了什么记录。把它们区分开，才能理解为什么同一个客户、同一份报告或同一个流程会出现多个状态。

## 1. 报告配置进入 T01，客户号通过简称关联取得

147452 将 `G_VALUE_REPORT_CONFIG` 写入 `T01_OTC_CUTP_VALU_RPT_CFG_INFO`。配置 ID 成为 `Valu_Rpt_Cfg_Id`，同时保留报告周期、模板、有效标志、时间组、节假日规则及展示开关。

其中 Pty_Id 不是主源直接提供，而是这样取得：

1. 合并国内非 HK 客户资料与香港客户资料。
2. 去除简称中的普通空格。
3. 按简称分组，以 AUDIT_STATUS、CLIENT_ID 降序选一条。
4. 报告配置的交易对手简称与选出的简称做 LEFT JOIN。

所以，配置存在但 Pty_Id 为空，可能来自简称未匹配；取一条的排序不能证明简称天然唯一，也不能未经字典确认将其称为“最新已审核客户”。[147452](证据/SQL/147452.json)，原 98–107、148–161 行。

配置还保留资金账户拆分、算头算尾计息、显示拆分资金流水、添加参考估值、均价及价值拆分等开关。这些字段帮助解释报告呈现和处理口径，但当前任务只传递配置，没有执行估值、计息或邮件发送。[147452](证据/SQL/147452.json)，原 123–140 行。

## 2. 报告执行进入 T05，事件身份包含状态和时间

147451 从 `G_VALUE_REPORT_EXECUTION` 构造：

```text
Evt_Id = OIS019-配置ID-状态-估值日-更新时间
```

去重范围同样是配置 ID、估值日、更新时间、状态，组内按发送时间降序取一条。失败后重新生成成功可以保留为不同事件；这张表不能直接解释为“每天每份配置仅有一条最终状态”。来源读取覆盖业务日往前 3 个月至业务日，输出保留来源业务日期。[147451](证据/SQL/147451.json)，原 32–60 行。

本地 CD1164 的 1/2 为成功/失败，3/4 为重新生成成功/失败，5/6 为手动发送成功/失败。应结合事件含义读状态，不能将“重新生成成功”直接当成邮件已送达。字典记录日期为 2024-03-04。[字典选录](证据/字典选录.json)。

现有图返回了构成事件 ID 的四个源字段。其跨任务接续当前为候选 UNKNOWN，不能写成已确认的完整生产链；任务内拼接逻辑则有 SQL 直接支持。[事件字段图证据](证据/图谱-147451-evt_id.json)。

## 3. 审批状态、流程节点与参数内容是三个维度

246857 将 `G_CROSS_SELL_APPROVAL_PROCESS` 写入 `T05_OTC_DERI_COMP_SALE_INCOME_PARA_APPR_EVT`，事件 ID 为 `OIS061-` 加源 ID，同时保留拟稿人、处理人、业务部门及创建更新时间。

源 CURRENT_STATUS 的 DRAFT/TRADER_REVIEW/CLOSED 分别转为 21/1/38；CURRENT_ACTIVITY_ID 的 01/02/03 分别转为 draft/auditing/ended，其他值原样保留。一个字段表达审批状态，另一个表达流程阶段，不应把它们都缩成“是否成功”。[246857](证据/SQL/246857.json)，原 35–67 行。

本地 SQL 能说明字段如何转换；目标状态 38 的业务含义仍应回到相应字典或流程定义，不能仅凭 CLOSED 推出参数已经生效。这里未检查真实流程执行或审批记录。

## 4. 划款流程保留多个结果维度

229695 将 `G_TRANSM_FLOW` 写入 `T05_OTC_DERI_CUST_TRAN_PROC`。事件 ID 为 `OIS057-` 加 FLOW_ID，另保留流程号、客户号、收付款资料、金额、划款日、到账日和关联流程号。

它分别转换：

- PROCESS_STATUS → 流程状态；
- XINYI_TRANSM_STATUS → 转账状态；
- FILE_UPLOAD_RESULT → 附件上传状态。

三组转换都按目标表字段、源表字段和来源 OIS 限定，并在未匹配时回退源值。因此，流程关闭、转账成功、附件上传完成不能互相代替。[229695](证据/SQL/229695.json)，原 53–119 行。

该 SQL 快照绑定的是 2026-05-24。它提供静态转换规则，不证明当天或当前任何一笔款项实际到账。源字段 SOURCE 和 TRADE_CHANNEL 作为流程属性保留下来，也不能据此宣布它们已经独立进入 T08 渠道主题。

## 5. 营业部辖区在这里是 T04 机构属性

246687 读取 `G_HS_ALLBRANCH`：BRANCH_NO 左补零到四位后作为内部机构编号，统计信息类型固定为 16，PROVINCE 写入统计内容描述，数量和数值字段填空。SQL 对 16 的注释为“内部机构所属辖区名称”。目标是 `T04_INR_ORG_STATI_INFO_H`。[246687](证据/SQL/246687.json)，原 29–41 行。

这条任务表达“某机构所属辖区”，没有在已读分支中生成 T06 区域对象。字段包含省份、交易渠道或金额，不决定所属模型主题；目标记录所描述的主体及其粒度更有解释力。

## 6. 从业务问题选择入口

| 遇到的问题 | 首先看什么 | 再核对什么 |
|---|---|---|
| 某客户有配置却查不到报告 | T01 报告配置及简称匹配 | T05 对应配置 ID、估值日、状态和发送时间 |
| 同一天既有失败又有成功 | 执行事件身份及去重分组 | 是否为不同更新时间、不同状态类型 |
| 分成或系数有值，为什么没有收入结果 | T01/T03 归属与 T99 参数 | 实际消费参数的计算任务；本专题没有据此计算收入 |
| 流程结束但款项是否到账不清楚 | 划款流程、转账、上传三个状态 | 实际回执或指定日期业务数据，不能只看流程字段 |
| 源有省份为何 T06 没有路径 | 实际目标与写入字段 | 是否只是 T04 机构属性，或存在尚未发现的独立路径 |
