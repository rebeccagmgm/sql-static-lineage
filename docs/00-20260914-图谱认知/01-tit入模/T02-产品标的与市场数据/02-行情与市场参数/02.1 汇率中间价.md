# 02.1 汇率中间价

**这一组保存某个币种在某个报价日对应人民币的中间价，供香港汇率接口和财务业务使用。**

取数核心是源 `CURRENCY`、`QUOTE_DATE`、`MIDRATE`。入模负责转换币种代码和日期，直接承接中间价值；没有从买卖价计算中间价，也没有生成外汇远期价格。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 源取数范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_REF_RMB_MIDRATE` | `PDATA_NEWS_N.T02_FXR_CFETS_QUOT` | 处理日 `BUSI_DATE` | 105616 |
| `ODATA_N_TIT.D_REF_RMB_MIDRATE_PB` | 同上 | 处理日 `BUSI_DATE`，且 `GRP_ID='h15'` | 144298 |

两个分支都写入目标 **`SRC_ID='TIT'、GRP_ID='01'`**。源 `_PB` 是独立取数分支，但目标没有另设一个 h15 分组。

两项 SQL 没有在这一入模中关联金融工具主数据，也不依赖 `KEY_INSTRUMENT_ID`。

## 2. 一条记录描述什么

| 取数原字段／规则 → 入模字段 | 含义 |
| --- | --- |
| `CURRENCY` → `SRC_CRRC_CD` | 保留源币种代码，香港及财务消费会直接使用 |
| `CURRENCY` 经代码转换 → `CRRC_CD` | 转换后的标准币种代码 |
| 固定 `'156'` → `FRGN_CRRC_CD` | 对应的另一端固定为人民币 |
| `QUOTE_DATE` 日期部分 → `TRD_DT` | 报价日，转为 `yyyyMMdd` |
| `MIDRATE` → `MID_PRICE` | 中间价，数值原样承接 |
| `UPDATED_DATETIME` → `REC_UPD_TIME` | 源记录更新时间 |
| 任务处理日 → `BUSI_DATE` | 此次入模的处理日期 |

**业务上按“源币种＋报价日”查对应记录。** 标准化后的两个币种字段一起表达币种关系，但目标列的“本币／外币”注释不能代替实际赋值：固定人民币的是 `FRGN_CRRC_CD`。

105616 将报价日、标准源币种和 `156` 组成 `REC_ID`、`SRC_REC_ID`；144298 这两个编号字段为空。因此，不能只依赖记录编号连接两个分支的数据。

## 3. 币种怎么转换

两条 SQL 都查询：

`PDATA_NEWS_N.T02_PUB_COVT_CONST`，条件 **`SRC_ID='WD'、CONST_TYPE_CD='fin00001'`**，用源 `CURRENCY` 匹配 `SRC_CONST_CD`，取 `CONST_CD`。

也就是说，**数据来源是 TIT，但这一处币种转换使用 WD 的币种转换分支**。不要把转换表的来源条件随手替换为 TIT。

| 分支 | 转换命中 | 转换未命中 |
| --- | --- | --- |
| 105616 普通来源 | 使用转换后的标准币种 | `CRRC_CD` 为空；源 `SRC_CRRC_CD` 仍保留 |
| 144298 PB 来源 | 使用转换后的标准币种 | 源为 `BYN` 时写 `'974'`，其他保留源币种字符串 |

`BYN → 974` 是 144298 中的特殊赋值规则，应按本任务代码理解。PB 的 `CRRC_CD` 在转换未命中时可能保留字母代码，因此不能假定该列每条记录都是统一数值编码。

## 4. 中间价怎样读

这两项入模都采用：

```text
源 MIDRATE → 模型 MID_PRICE
```

没有取倒数、乘除 100，或按币种重新决定每单位／每百单位报价。需要实际金额换算时，结合源端报价口径及业务消费公式判断方向和倍率。

源 `QUOTE_DATE` 决定报价所属日期，源 `BUSI_DATE` 是本次取数条件。比如处理日取得一条前一报价日记录，目标 `TRD_DT` 仍保存原报价日，不会被改成处理日。

一个排查来源时需知道的细节：144298 实际读取 `_PB`，但目标 `SRC_TBL` 仍固定写普通表名 `odata_n_tit.d_ref_rmb_midrate`。**要判断这份值来自哪个分支，需要结合调度，不能只看 `SRC_TBL`。**

## 5. 下游具体用在哪里

### 香港汇率接口：166014

任务 `dm_hk_n.ref_rmb_midrate` 从模型 TIT／01 读取：

| 模型字段 | 接口字段 |
| --- | --- |
| `SRC_CRRC_CD` | `CURRENCY` |
| `TRD_DT` | `QUOTE_DATE`，还原日期格式 |
| `MID_PRICE` | `MIDRATE` |
| `REC_UPD_TIME` | `UPDATED_DATETIME` |

这一消费使用源币种，没有把中间价换成买卖报价，也没有改变中间价值。

### 互换财务损益：118174

任务 `dm_fin_n.v_fin_trs_plreport` 将汇率与互换或持仓数据连接：

- 存续互换分支按**合约结算币种＋持仓业务日**匹配 `SRC_CRRC_CD＋TRD_DT`。
- 另一结算相关分支按结算币种，取**实际结算日期，缺失时取结束定价日**匹配报价。
- 持仓分支还会把主数据币种转换为源字母代码，再按持仓日期匹配。

已查输出 `exchangeRateCny` 对非 CNY 使用 `MID_PRICE`，对 CNY 使用 `1`。这说明本表确实参与财务人民币汇率字段的取数；不同业务分支选择报价日期的方式并不相同。

依据：入模 SQL 105616、144298；消费 SQL 166014、118174；币种规则取自对应入模 SQL，未将任务特例扩展为通用币种字典。
