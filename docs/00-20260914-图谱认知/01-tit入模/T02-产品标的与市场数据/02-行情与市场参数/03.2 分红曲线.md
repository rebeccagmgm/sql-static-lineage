# 03.2 分红曲线

**分红曲线保存某标的在不同期限上的分红收益率参数。先用定义识别“哪条曲线、哪个标的”，再从行情取得某个日期、期限的数值。**

例如，查询某标的未来不同期限的分红参数，需要的是曲线节点；查询某次分红的每股金额、登记日、除权日，则去查公司行为。两类资料在业务上有关联，但本次曲线入模直接接收源端数值，没有根据分红事件重新生成曲线。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源／分组 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_REF_DIV_CURVE_DEF` | `PDATA_NEWS_N.T02_FIN_CURV_DEF` | TIT／02 | 103207 |
| `ODATA_N_TIT.D_REF_DIV_CURVE` | `PDATA_NEWS_N.T02_FIN_CURV_MKT_QUOT` | TIT／02 | 103200 |
| `ODATA_N_TIT.M_REF_DIV_CURVE` | `PDATA_NEWS_N.T02_FIN_CURV_MKT_QUOT` | TIT／03 | 228422 |

三条均取源表处理业务日的 `BUSI_DATE`。两条行情分别入模到 02、03，字段取法相似，但来源独立；已查任务没有规定二者谁覆盖谁、缺失时互补或取更晚一条。

## 2. 曲线、标的、行情各是什么编号

| 对象 | 原字段 → 入模字段 | 用来连接什么 |
| --- | --- | --- |
| 分红曲线定义 | `D_REF_DIV_CURVE_DEF.KEY_CURVE_ID` → 定义 02 的 `REC_ID`、`CURV_CD_SRC` | 分红曲线自身 |
| 曲线所属标的 | `D_REF_DIV_CURVE_DEF.KEY_INSTRUMENT_ID` → 定义 02 的 `UNDRL_NO` | TIT 金融工具内码，可回主数据查名称、类别和代码 |
| 分红行情所属曲线 | 两张行情源表的 `KEY_DIV_CURVE_ID` → 行情的 `REC_ID` | 与曲线编号对应，再按日期和期限读取节点 |
| LBR 因子所引用的曲线 | `T02_FIN_CURV_FCTR_DEF.DIVD_CURV_ID` | 在风控消费中直接对应 TIT 分红行情 `REC_ID` |

定义 02 的 `UNDRL_NO` 直接保存源工具内码，没有在这项入模中转成统一证券编号。`SRC_SYS_PRDNO='TIT-曲线编号'` 指向曲线，不能用于查该标的的金融工具主档。

**一个标的编号不足以说明采用哪条分红曲线。** 查询所选曲线时，还要结合定价环境配置或因子定义中的曲线引用。

## 3. 定义里保存哪些规则

| 原字段 → 入模字段 | 含义 |
| --- | --- |
| `CURVE_NAME` → `CURV_NAME` | 分红曲线名称 |
| `CURVE_INTERPOLATOR` → `CURV_ACS_TYPE` | 曲线节点之间的插值规则 |
| `HOLIDAY` → `CAL` | 使用哪套日历 |
| `DATE_ROLL` → `DATE_ADJ_REGU` | 日期遇非交易日怎样调整 |
| `DAY_COUNT` → `INTA_DAY_CALC_REGU` | 计息天数规则 |
| `INTEREST_FREQUENCY` → `ITPY_FREQ` | 源频率配置 |
| `CURVE_EXPIRY_TYPE` → `EXPIRY_TYPE` | 源期限表达方式 |

这一分组的 `CRRC_CD`、`CURV_TYPE`、`MKT_QUOT_SRC`、`CURV_ID_SRC` 等字段为空。普通收益率定义通过 `CURV_ID_SRC` 引用行情的规则，不能直接套到分红定义。

插值方法的常用源码为 `LINEAR`（线性）、`LOG_LINEAR`（对数线性）、`SPLINE`（立方样条）、`STEP_UP`（步长），见 TIT `InterpolatorType` 字典。详细计息、日历规则沿用源代码，不由本次入模计算日期或收益率。

## 4. 分红数值要读 YIELD

| 原字段 → 入模字段 | 业务含义 |
| --- | --- |
| `KEY_DIV_CURVE_ID` → `REC_ID` | 分红曲线编号 |
| `QUOTE_DATE` → `TRD_DT` | 报价日期，转为 `yyyyMMdd` |
| `TENOR` → `TERM` | 期限节点 |
| **`YTM` → `YIELD`** | **分红收益率** |
| `UPDATED_DATETIME` → `REC_UPD_TIME` | 源记录的更新时间 |

虽然源字段叫 `YTM`，源注释明确是“分红收益率”。到了模型，数值写在 **`YIELD`**；目标 `YTM`、`SPOT_INTRT`、`FWD_INTRT` 和 `MATY_DT` 在这两个分红分支中均为空。

因此，读分红曲线时应保留 **来源分组、曲线编号、报价日期、期限、`YIELD`**。处理日期只是本次入模日期，曲线数值的日期以 `TRD_DT` 为准。

两条分红入模及已查因子消费均直接传递数值，没有乘除 100；当前字段证据未给出统一的百分数缩放约定，实际计算时应沿所用曲线确认原数值口径。

## 5. 怎样进入 LBR 分红因子行情

消费 **182230 → `DM_RSK_N.DIV_CURV_FCTR_MKT_QUOT`** 的业务链为：

```text
LBR 通用因子定义 T02_FIN_FCTR_DEF
  FCTR_ENGINE_HAND_METHOD = DIV_CURVE_DEF_SYNC
               ↓ FCTR_ID
LBR 曲线因子定义 T02_FIN_CURV_FCTR_DEF
  DIVD_CURV_ID：这个因子引用的分红曲线
               ↓ 等于 REC_ID
TIT 分红曲线行情 T02_FIN_CURV_MKT_QUOT（TIT／02）
  TRD_DT ＋ TERM ＋ YIELD
               ↓
分红因子行情：因子编号 ＋ 曲线编号 ＋ 工具内码 ＋ 节点数值
```

`DIV_CURVE_DEF_SYNC` 是这项消费使用的处理方法筛选值。它先限定需要同步分红曲线的因子，再依据曲线因子定义找到数值，**不是给每一条 TIT 分红曲线自动生成一个因子**。

这项 SQL 中，输出的工具内码来自因子定义 `SRC_SYS_PRDNO` 去掉来源前缀；没有先连接 TIT 分红曲线定义表。因而，理解定义表有助于读懂曲线，实际追取数路径则应按上述消费连接读取。

**182230 明确只读行情 TIT／02。** 行情 TIT／03 来自 `M_REF_DIV_CURVE`，目前未在这项消费中使用；不能仅因字段一致就把 03 也计入该因子输出。

## 6. 从业务问题出发怎样查

- 查“这是谁的分红曲线”：从定义 02 的 `UNDRL_NO` 找工具身份，同时看曲线编号和名称。
- 查“这条曲线某日的参数”：按曲线编号、来源分组、`TRD_DT` 取出各 `TERM` 的 `YIELD`。
- 查“某个风控因子实际用了哪份数据”：从因子编号查 `DIVD_CURV_ID`，再沿 182230 的 TIT／02 分支核对。
- 查“某个定价环境选了哪条曲线”：查看环境＋标的对应的 `KEY_DIV_CURVE_ID`，再回本篇查询定义与数值。
