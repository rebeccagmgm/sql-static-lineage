# 06.3 自营做市敏感度与损益

**这张表把场内期权工具的价格、理论价、单位敏感度和源端损益分解放在一起，帮助理解“这个期权工具的风险表现，以及损益被解释到哪些因素”。**

例如，一份期权既有自身价格，也有标的价格、波动率和 Delta、Vega 等指标；源端还提供 Delta、Vega 等因素对应的损益分项。入模将这些已有数值一起保存，便于对照。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_POS_QG_CLEARING_GREEKS` | `PDATA_NEWS_N.T02_OPT_OST_QTF_SSTV_INDX_TIT` | `SRC_ID='TIT'、GRP_ID='01'` | 219014 |

源表注释为“自营做市绩效合约 Greeks 表”，其中敏感度字段注释明确使用“场内期权单位”口径。

## 2. 取数逻辑

1. 取源 `BUSI_DATE` 等于处理业务日的数据。
2. 用期权工具 **`KEY_INSTRUMENT_ID = T02_SCR_BASE_INFO.IN_CODE`**，在 TIT 主数据中补 `SECU_ID`。
3. 再用标的工具 **`UNDERLYING_INS_ID = T02_SCR_BASE_INFO.IN_CODE`**，补 `UNDRL_SECU_ID`。
4. 价格、敏感度和损益分项直接承接，源 `SRC_BUSI_DATE` 整理成日期键。

两次身份关联分别对应期权本身与它的挂钩标的。未匹配到主数据的源记录仍保留，本任务没有按持仓数量重新加权，也没有重新计算损益分解。

## 3. 先认期权，再认标的和日期

| 身份或日期 | 源字段 → 入模字段 | 阅读要点 |
| --- | --- | --- |
| 期权工具 | `KEY_INSTRUMENT_ID` → `SCR_IN_CODE`，并补 `SECU_ID` | 这条结果属于哪一个期权工具 |
| 期权代码 | `WIND_CODE`、`SCCODE` → `WIND_CD`、`COMP_CD` | 保存工具的 WIND 代码和合约代码 |
| 挂钩标的 | `UNDERLYING_INS_ID` → `UNDRL_IN_CODE`，并补 `UNDRL_SECU_ID` | 指向另一项工具身份 |
| 标的代码与名称 | `UNDERLYING_WIND_CODE`、`UNDERLYING_SHT_DESC` → `UNDRL_WIND_CD`、`UNDRL_ABBR` | 帮助识别标的 |
| 结果业务日 | `SRC_BUSI_DATE` → `SRC_BUSI_DATE` | 这组结果属于哪一天；目标 `BUSI_DATE` 另写调度日 |
| 期权方向与到期 | `PC_FLAG`、`MATURITY_DATE`、`DTM` → `OPT_DIR`、`COMP_MATY_DATE`、`MATY_TERM` | 方向保留源代码；`DTM` 的具体时间单位未在当前注释中明确 |

**这里的“合约代码”指场内期权工具代码。** 这条入模没有交易 ID、账簿、账户、交易腿或持仓数量字段，因此不能直接把一行解释为某个账户持有的某一笔交易或某条腿。

目标 `REC_ID` 为空；业务上先以期权工具和源业务日定位，并保留源记录差异，不凭空设定唯一键。

## 4. 价格与单位敏感度

### 4.1 先看定价涉及的数值

| 源字段 → 入模字段 | 业务含义 |
| --- | --- |
| `STRIKE` → `OPT_EXER_PRIC` | 期权行权价 |
| `PRICE` → `OPT_PRIC` | 源端期权价格 |
| `UL_PRICE` → `OPT_UNDRL_PRIC` | 源端标的价格 |
| `VALUE` → `THRY_PRIC` | 源端理论价 |
| `BASIS`、`FORWARD` → `BASI`、`FWD` | 源端基差与远期相关数值，入模未提供两者计算公式 |
| `VOLATILITY` → `VOLA` | 源端波动率，没有在本任务拟合或反解 |

期权价格、标的价格、理论价分别承接不同源字段。比较价格差异时，需要先确认这些值的时点及源端取价规则。

### 4.2 单位敏感度单独成组

| 源字段 | 入模字段 |
| --- | --- |
| `DELTA_PCT`、`GAMMA_PCT` | `TRD_OPT_UNIT_DELTA`、`TRD_OPT_UNIT_GAMMA` |
| `VEGA_PCT`、`THETA_PCT` | `TRD_OPT_UNIT_VEGA`、`TRD_OPT_UNIT_THETA` |
| `VOMMA_PCT`、`RHO_Q_PCT` | `TRD_OPT_UNIT_VOMMA`、`TRD_OPT_UNIT_RHO_Q` |
| `CHARM_PCT`、`VANNA_PCT`、`VETA_PCT` | `TRD_OPT_UNIT_CHARM`、`TRD_OPT_UNIT_VANNA`、`TRD_OPT_UNIT_VETA` |

源与目标注释都按单位指标描述这组数值。具体归一到多少合约、怎样处理乘数、扰动采用何种幅度，当前入模没有展开；不能直接把单位指标当作账户总风险金额。

## 5. 损益分解保存了什么

| 源字段 | 入模字段 | 怎么理解 |
| --- | --- | --- |
| `DECOMP_DETAIL_PNL_TOTAL` | `PNL_TOT` | 源端分解明细总盈亏 |
| `DECOMP_DETAIL_PNL_DELTA`、`…_GAMMA` | `PNL_DELTA`、`PNL_GAMMA` | 对应指标命名的损益分项 |
| `DECOMP_DETAIL_PNL_VEGA`、`…_THETA` | `PNL_VEGA`、`PNL_THETA` | 波动率、时间等方向的分项结果 |
| `DECOMP_DETAIL_PNL_VOMMA`、`…_VANNA`、`…_CHARM`、`…_VETA`、`…_RHOQ` | `PNL_VOMMA`、`PNL_VANNA`、`PNL_CHARM`、`PNL_VETA`、`PNL_RHOQ` | 源端进一步细分的结果 |
| `DECOMP_DETAIL_FORWARD_ERROR` | `PNL_DEVI` | 源端 forward error；目标注释为预期实际偏差 |
| `DECOMP_DETAIL_PNL_UNEXPLAINED` | `PNL_UNEXPLN` | 源端未能解释的部分 |

这组字段适合先看总盈亏，再看各项分解和未解释部分。入模没有验证“各项之和等于总盈亏”，也没有给出全部分项是否互斥、使用哪一币种及哪个持仓基数的规则。

**风险敏感度和损益分项分开读。** 前者描述对变化的敏感程度，后者已经是源端给出的分解结果；本任务没有用前者乘行情变化推导后者。
