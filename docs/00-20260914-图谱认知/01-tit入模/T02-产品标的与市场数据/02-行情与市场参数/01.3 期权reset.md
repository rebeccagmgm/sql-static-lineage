# 01.3 期权 reset

**这一条保存源端为某个期权、某个标的维护的观察日 reset 值。入模把它放进“期权行情表”的结算价字段，下游香港接口再按 reset 值读取。**

这里能确定的是“哪个期权、关联哪个标的、哪个观察日、reset 值是多少”。这个值在具体合约中用于怎样的重置或观察规则，还要结合期权条款；本表没有提供该计算规则。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.R_REF_OPTION_QUOTE_RESET` | `PDATA_NEWS_N.T02_OPT_MKT_QUOT` | `SRC_ID='TIT'、GRP_ID='01'` | 139409 |

取源表处理日 `BUSI_DATE` 的记录。期权内码和标的内码分别关联 `PDATA_NEWS_N.T02_SCR_BASE_INFO` 的 TIT 主数据，补各自身份，然后直接承接观察日和 reset 值。

入模没有从股票收盘价、执行价或期权理论价计算 `RESET_VALUE`，也没有根据数值判断是否发生敲入、敲出或到期结算。

## 2. 两个编号分别指谁

| 内容 | 取数原字段 → 入模字段 | 含义 |
| --- | --- | --- |
| 期权内码 | `KEY_INSTRUMENT_ID` → `REC_ID`、`SRC_REC_ID` | 这份 reset 记录属于哪个期权工具 |
| 期权统一身份 | 按 `KEY_INSTRUMENT_ID` 匹配主数据 → `SECU_ID`、`SRC_SYS_PRDNO` | 期权自身的证券身份 |
| 标的内码 | `UNDERLYING_INS_ID` → `REMARK.undrl_src_sys_prdno='TIT-'+标的内码` | 这条 reset 记录关联的标的工具 |
| 标的统一身份 | 按 `UNDERLYING_INS_ID` 匹配主数据 → `REMARK.undrl_secu_id` | 对应标的的统一证券编号 |
| 观察日 | `OBS_DATE` → `TRD_DATE` | 源观察日转为日期键 |
| reset 值 | `RESET_VALUE` → `SETT_PRIC` | 直接承接源值 |

**期权内码与标的内码属于两个位置。** 不能拿 `REC_ID` 直接当股票内码去查股票行情，也不能只看 `SECU_ID` 就认为它指向挂钩标的。

## 3. 记录维度怎样理解

阅读时至少保留 **期权内码＋观察日＋标的内码**，这样才能说明一个 reset 值属于哪条业务记录。

目标 `REC_ID` 只接收期权内码，没有将观察日和标的拼进去。因此，不应仅凭 `REC_ID` 就推断同一期权在所有日期只有一个 reset 值，或按 `REC_ID` 单列去重。

| 日期字段 | 含义 |
| --- | --- |
| 源 `BUSI_DATE` | 此次取数的数据日期 |
| 源 `OBS_DATE`／目标 `TRD_DATE` | 记录对应的观察日期 |
| 目标 `BUSI_DATE` | 任务处理日期 |
| 目标记录更新时间 | 139409 写本次任务时间；没有承接源 `UPDATED_DATETIME` |

在查历史观察值时，使用观察日定位记录，不能只看跑数日期或目标更新时间。

## 4. 为什么写到“结算价”

139409 对目标行情字段的填充是：

| 目标内容 | 本分支取值 |
| --- | --- |
| `SETT_PRIC` | 源 `RESET_VALUE` |
| 开高低收 | 空 |
| 成交量、成交额、持仓量 | 空 |
| 前结算价、涨跌和涨跌幅 | 空 |
| `REMARK` | 两个标的身份字段 |

**`SETT_PRIC` 在这个来源分支中应按 reset 值理解。** 单凭目标字段名，不能将它解释成交易所每日结算价；这条入模也没有形成完整的期权日行情。

场内期权普通开高低收来自 `ODATA_N_TIT.D_MKT_INS_DAILY_INFO` 的共用行情链，消费 175878 按 `LISTEDOPTION` 分类后输出。两条路径的来源和使用目的分别保留。

## 5. 下游具体怎样使用

### 香港 reset 接口：134518

目标为 `DM_HK_N.REF_OPTION_QUOTE_RESET`，字段还原关系明确：

- `REC_ID` → `KEY_INSTRUMENT_ID`。
- `TRD_DATE` → `OBS_DATE`。
- `SETT_PRIC` → `RESET_VALUE`。
- 从 `REMARK.undrl_src_sys_prdno` 取出标的内码 → `UNDERLYING_INS_ID`。

它还做了业务范围限定：

1. 用期权内码关联 `PDATA_N.T03_OTC_OPT_COMP_SUB_TRD_INFO.SRC_PRD_ID`，该分支来源为 `ODATA_N_TIT.D_REF_INS_OPTION_INFO`，取处理日资料。
2. 按 `BOOK_AGT_ID` 关联 `PDATA_N.T03_OTC_DERI_BOOK_ADTNL_INFO`，取来源 `ODATA_N_TIT.D_REF_BOOK` 的处理日账簿资料。
3. 保留账簿 `BEL_CO='GFS_HK'` 的记录。

因此，香港接口只取对应账簿范围内的期权。接口的 `UPDATED_DATETIME`、`UPDATED_BY` 置空，也没有恢复源端维护人和维护时间。

### 财务消费：220853

任务 `dm_fin_n.civ_opt_mkt_quot` 读取目标 TIT／01 的行情字段，直接传递 `SETT_PRIC`、观察日期、备注及来源，没有另算价格。解释其这个分支时仍要沿用 reset 的源含义。

依据：入模 SQL 139409；消费 SQL 134518、220853、175878；`ODATA_N_TIT.R_REF_OPTION_QUOTE_RESET` 字段元数据。
