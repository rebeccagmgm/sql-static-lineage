# 03.1 收益率曲线

**收益率曲线把不同期限对应的利率放在一起。这里要同时认识“业务上定义的曲线”和“它引用的行情曲线”，再按报价日期、期限取得数值。**

例如，某条业务曲线有自己的名称、币种、计息和插值规则，同时引用一条 WIND 行情曲线。下游将二者连接后，才能得到“按这套规则使用的各期限利率”。

## 1. 从哪里取，分别进入哪里

| 取数原表 | 入模表 | 来源／分组 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_REF_CURVE` | `PDATA_NEWS_N.T02_FIN_CURV_DEF` | TIT／01 | 103203 |
| `ODATA_N_TIT.TIT_R_REF_INSTRUMENT_WIND_CURVE_S` | `PDATA_NEWS_N.T02_FIN_CURV_DEF` | TIT／03 | 172069 |
| `ODATA_N_TIT.D_REF_WIND_YIELD_CURVE` | `PDATA_NEWS_N.T02_FIN_CURV_MKT_QUOT` | TIT／01 | 103198 |

三条入模均读取源表处理业务日的 `BUSI_DATE`。普通定义保留规则并转换币种，代码对应表保留 WIND 代码与描述，行情分支接收源端各期限节点；没有在这里重新构建或插值计算曲线。

## 2. 最重要的是分清两种曲线编号

| 编号 | 原字段 → 入模字段 | 指向什么 |
| --- | --- | --- |
| 业务曲线自身编号 | `D_REF_CURVE.KEY_CURVE_ID` → 定义 01 的 `REC_ID`、`CURV_CD_SRC` | 这套曲线定义自身 |
| 引用的行情曲线编号 | `D_REF_CURVE.QUOTE_REFERENCE_ID` → 定义 01 的 `CURV_ID_SRC` | 该定义使用哪条行情曲线 |
| WIND 行情曲线编号 | `D_REF_WIND_YIELD_CURVE.KEY_WIND_CURVE_ID` → 行情 01 的 `REC_ID` | 各日期、期限的数值属于哪条曲线 |
| WIND 代码对应编号 | `TIT_R_REF_INSTRUMENT_WIND_CURVE_S.KEY_WIND_CURVE_ID` → 定义 03 的 `REC_ID` | 补充该行情曲线的外部代码与描述 |

已查消费 **155160** 的实际连接为：

```text
普通曲线定义（TIT／01）
  KEY_CURVE_ID → REC_ID：定义自身编号
  QUOTE_REFERENCE_ID → CURV_ID_SRC
                         ↓ 等于
收益率行情（TIT／01）.REC_ID
  ＋ TRD_DT：报价日期
  ＋ TERM：期限
                         ↓ 同一 REC_ID
WIND 代码对应（定义 TIT／03）
```

**不要直接用普通定义的 `REC_ID` 连接收益率行情的 `REC_ID`。** `SRC_SYS_PRDNO='TIT-…'` 在这里也由曲线编号组成，不能把它当作金融工具内码。

## 3. 曲线定义说明哪些业务规则

| 内容 | 原字段 → 入模字段 | 读取含义 |
| --- | --- | --- |
| 名称与币种 | `CURVE_NAME` → `CURV_NAME`；`CURVE_CURRENCY` → `CRRC_CD` | 名称直接接收；币种通过 `T02_PUB_COVT_CONST` 的 **WD／fin00001** 转换 |
| 曲线种类 | `CURVE_TYPE`、`CURVE_TYPE_CODE` → `CURV_TYPE`、`CURV_TYPE_CD` | 曲线类型和源类型编码分别保留 |
| 行情来源 | `QUOTE_SOURCE`、`QUOTE_TYPE` → `MKT_QUOT_SRC`、`QUOT_TYPE` | 来源与报价类型；入模未限定来源值必须为 WIND |
| 节点间取值规则 | `CURVE_INTERPOLATOR` → `CURV_ACS_TYPE` | 源配置的插值方法 |
| 日期及计息 | `HOLIDAY`、`DATE_ROLL`、`DAY_COUNT` → `CAL`、`DATE_ADJ_REGU`、`INTA_DAY_CALC_REGU` | 日历、非交易日调整及计息天数规则 |
| 计息频率 | `INTEREST_FREQUENCY` → `ITPY_FREQ` | 源频率原值；不是报价刷新频率 |
| 点差与期限表达 | `SPREAD_TYPE`、`CURVE_EXPIRY_TYPE` → `SPRD_TYPE`、`EXPIRY_TYPE` | 点差表达及期限类型原值 |

WIND 代码对应的 **定义 03** 有不同含义：`WIND_CURVE_CODE` 写 `CURV_TYPE_CD`，`CURVE_NAME` 写 `CURV_TYPE`，源 `QUOTE_TYPE` 存入 `REMARK.quote_type`；这一分组的 `CURV_NAME` 为空。不要跨分组把 `CURV_TYPE` 都按普通曲线种类解释。

### 常用码值

本地 TIT 字典日期为 `2026-09-14`，以下域与 `D_REF_CURVE` 字段注释对应；入模保留源代码。

| 代码域 | 源码 | 含义 |
| --- | --- | --- |
| `YieldCurveType` | `ZERO_COUPON` | 零息债券曲线 |
| `YieldCurveType` | `SPOT` | 即期收益率 |
| `YieldCurveType` | `FORWARD` | 远期收益率 |
| `YieldCurveType` | `DISCOUNT` | 折现率曲线，沿用源字典名称 |
| `InterpolatorType` | `LINEAR`、`LOG_LINEAR` | 线性插值、对数线性插值 |
| `InterpolatorType` | `SPLINE`、`STEP_UP` | 立方样条插值、步长插值 |

`SPREAD_TYPE` 要保留实际值：本地 `SpreadType` 字典列出 `MONEYNESS`（绝对值）、`PERCENTAGE`（相对值），而建表注释列的是 `ABSOLUTE`、`RELATIVE`。已查 SQL 没有转换两套值，不能直接互相替换。

## 4. 每个日期、期限上的数值从哪列读

| 原字段 → 行情字段 | 含义 |
| --- | --- |
| `QUOTE_DATE` → `TRD_DT` | 行情日期，转成 `yyyyMMdd` |
| `TENOR` → `TERM` | 期限节点，原样接收 |
| `YTM` → `YTM` | 到期收益率，目标注释为 `%` |
| `SYTM` → `SPOT_INTRT` | 即期利率，目标注释为 `%` |
| `FYTM` → `FWD_INTRT` | 远期利率，目标注释为 `%` |
| `YIELD` → `YIELD` | 源收益率字段，独立于前三列保留 |
| `EXPIRY_DATE` → `MATY_DT` | 节点到期日期，转成日期键；与行情日期区分 |

一条曲线可以有多个日期、多个期限节点，单独的 `REC_ID` 不能标识某个节点。查数时一起保留 **行情曲线编号、`TRD_DT`、`TERM`、`MATY_DT`**，再明确自己要的是哪种收益率。

该入模没有乘除 100。不要把“利率报价”分支 `RATE × 100` 的口径套到这里；`TENOR` 的期限单位也应按源取值和曲线规则读取。

## 5. 已确认用到哪里

**155160 → `DM_RSK_N.V_RISK_YIELD_CURVE`**：以 TIT／01 曲线行情连接普通定义，输出行情日期、期限、`YTM`，并附带曲线名称、币种、计息和插值规则；再用定义 03 补 WIND 曲线描述。

这项消费要求行情能匹配普通曲线定义，币种通过 WD／fin00001 反查源币种代码。虽然入模保存即期、远期和 `YIELD`，该视图实际选择的是 **`YTM`**，不能把所有保存字段都说成已被它使用。

定价环境如何选中这条普通曲线，另见定价环境主题；本篇解决选中以后，曲线定义与行情怎样连接。
