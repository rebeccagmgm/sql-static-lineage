# 06.1 期权定价与 Greeks

**这组记录回答：某笔交易在某个业务日，源端给出的价格、净现值、持仓规模和风险敏感度是多少。**

Greeks 用来描述价格对标的价格、波动率、时间等变化的敏感程度。例如 Delta 帮助观察标的价格变化的影响，Vega 帮助观察波动率变化的影响。本表同时保存原始指标、百分比指标及 BASE 指标，读数时要保留各自口径。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_V_GREEKS_PRICING_RM` | `PDATA_NEWS_N.T02_OPT_GREEK_VAL_DET` | TIT／01 | 103255 |
| 同上 | `PDATA_NEWS_N.T02_OPT_GREEK_VAL_DET_H` | TIT／01，另按 `BUSI_DATE` 分区 | 114560 |
| `ODATA_N_TIT.D_V_GREEKS_PRICING_RM_P` | `PDATA_NEWS_N.T02_OPT_GREEK_VAL_DET_H` | TIT／01，源取 `BUSI_DATE='h15'` | 245011 |

三个分支都接收源端已有结果，没有在入模重新计算价格或 Greeks。

## 2. 取数逻辑与日期

| 分支 | 怎样取数 | 目标业务日期 |
| --- | --- | --- |
| 103255 | 取源 `BUSI_DATE` 等于处理业务日的记录，直接映射交易与指标字段 | 调度处理日 |
| 114560 | 已见 SQL 从普通源表按业务日期范围读取，但尾部条件截断，无法确定完整范围 | 源 `A.BUSI_DATE` |
| 245011 | 取 `_P` 表的 `h15` 分区 | 源 `SRC_BUSI_DATE` 的日期部分 |

**245011 实际读取 `_P` 表，虽然其 `SRC_TBL` 字段仍写普通表名。** 查询原数据时应跟随实际取数表。`h15` 是源分区标识，源结果属于哪天仍看 `SRC_BUSI_DATE`。

本地可见 `_H` 表增加业务日期分区，另承接 `RHO_Q_BASE`、`CEGA_BASE`、部门等字段；当前不凭 `_H` 后缀推断完整历史维护或回刷规则。

## 3. 一条记录怎样认出所属交易

| 业务身份 | 源字段 → 入模字段 | 怎样使用 |
| --- | --- | --- |
| 交易编号 | `TRADE_ID` → `REC_ID`、`DEAL_NO` | 查某笔交易时的直接入口；SQL 未证明单列全局唯一 |
| 产品引用 | `PRODUCT_REFERENCE` → `PRD_NO`；加 `TIT-` → `SRC_SYS_PRDNO` | 保留源产品引用，本分支未关联工具主数据核实其键域 |
| 内部关联编码 | `INTERNAL_REFERENCE` → `JOIN_CODE` | 辅助识别交易，不能直接代替合约或工具内码 |
| 账簿及交易集合 | `BOOK`、`BUNDLE_ID`、`BUNDLE_NAME` → `DEAL_THIS_FN`、`DEAL_SET_ID`、`DEAL_SET_NAME` | 看交易归属哪个账簿、集合 |
| 标的描述与代码 | `UNDERLYING_SECURITY`、`UNDERLYING_PRODUCT_CODE_EXCH` → `UNDRL_CD`、`UNDRL_EXCH_CODE` | 本表保存源代码，未补统一标的证券编号 |
| 交易状态与方向 | `TRADESTATUS`、`BUY_SELL` → `DEAL_STAT`、`TRANSCN_DIR` | 直接保留源状态和买卖方向 |

因此，这张表可作为“交易结果明细”阅读。要接到 T03 合约、子交易或 T02 工具资料，应先核对对应编号的定义，不能统一去掉 `TIT-` 就连接 `KEY_INSTRUMENT_ID`。

## 4. 价格、规模与敏感度分别看哪些字段

### 4.1 交易规模和价值

| 想看什么 | 源字段 → 入模字段 | 阅读要点 |
| --- | --- | --- |
| 名义本金与剩余名义规模 | `NOTIONAL` → `NOM`；`OUTSTANDING_NOTIONAL` → `NOM_PRIN` | 两列分别承接，SQL 未把它们相加或相互替代 |
| 持仓头寸、合约大小 | `QUANTITY` → `HLD_POS_POS`；`CONTRACT_SIZE` → `COMP_MAJOR_MINOR` | 用于理解规模，不能据此自行假定指标已经乘过多少次 |
| 交易价格与结果价格 | `TRADE_PRICE` → `DEAL_PRIC`；`PRICE` → `PRIC` | 交易信息中的价格与定价结果分别保存 |
| 净现值与现值 | `NPV` → `NET_NOW_VAL`；`PV` → `NOW_VALL` | 直接承接源结果，入模未提供两者差额的组成公式 |
| 标的价格 | `UNDERLYING_SPOT` → `UNDRL_PD_PRIC`；`UNDERLYING_SPOT2` → `UNDRL_SPOT_PRIC` | 两个源字段均保留，不能仅因都叫即期价就合成一个 |
| 标的远期价格 | `UNDERLYING_FWD_PRICE` → `UNDRL_FWD_EXEC_PRIC` | 沿源字段理解，入模未重新推算远期价 |

### 4.2 风险指标

| 指标组 | 入模字段 | 阅读要点 |
| --- | --- | --- |
| 标的价格敏感度 | `DELTA`、`GAMMA`、`CASH_DELTA` | 对应源同名结果，各列度量方式需要分别确认 |
| 时间与波动率敏感度 | `THETA`、`VEGA` | 对应源同名结果；SQL 未规定一天或一个波动率百分点的缩放 |
| 百分比指标 | `DELTA_PCT`、`GAMMA_PCT`、`THETA_PCT`、`VEGA_PCT` | 直接承接源百分比列，不能将其当普通敏感度再次求和 |
| BASE 指标 | `NPV_BASE`、`DELTA_BASE`、`VEGA_BASE` 等 | 入模直接承接；通用 BASE 列的换算基准尚不能由本 SQL 完整确定 |
| 波动率 | `IMPLIEDVOLATILITY` → `IMPL_VOLA`；`FX_VOLATILITY` → `VOLA` | 后一列具体来自外汇波动率字段，不能当作前一列的替代 |
| 其他风险 | `CEGA`、`RHO_R`、`RHO_Q`、`RHO_RF`、`VEGA_FX`、`DELTA_FX` | 保留源结果；精确扰动方式和金额单位需源端定价口径 |

**单位、币种和规模一致后才能比较或汇总。** 同名指标出现在交易表、单标的表和做市单位指标表，并不代表计算尺度一致。

## 5. 入模明确转换了什么

| 字段 | 明确规则 |
| --- | --- |
| 交易货币 `CRRC_CD` | 源 `TRADE_CURRENCY='CNY'` 时写 `156`，其他值原样保留；不是全币种字典转换 |
| 产品货币 `PRD_CRRC` | 直接保留 `PRODUCT_CURRENCY`，与上述交易货币分别读取 |
| 敲入标志 `KNOCKED_IN_FLAG` | `IS_KNOCKED_IN='Y'` → `1`；`N` → `0`；其他源值保留 |
| 敲入日期 `KNOCKED_IN_DT` | 截取 `KNOCKED_IN_DATE` 到秒，保存源端已经给出的日期 |

敲入状态也是源端结果。本任务没有读取障碍观察计划和行情重新判定是否敲入。
