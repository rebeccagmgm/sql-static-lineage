# 01.2 风管行情

**风管行情是另一份按工具、报价日期提供的价格与净值资料；已确认的价格类因子消费会优先选择它。**

源表元数据名称为“风管部私募行情数据表”。它保存单位净值和资产净值，也承接收盘价、结算价、虚拟净值及市值；入模没有按工具类别额外限制为基金。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_MKT_RISK_DAILY_INFO` | `PDATA_NEWS_N.T02_PRD_UNIT_NAV_S_TIT` | `SRC_ID='TIT'、GRP_ID='01'` | 207284 |

取源表处理日 `BUSI_DATE` 的记录，按 `KEY_INSTRUMENT_ID` 关联 `PDATA_NEWS_N.T02_SCR_BASE_INFO` 的 TIT 主数据，补统一证券编号、源系统产品编号、证券代码和币种。

行情数值直接承接；没有在入模中调整净值、计算收益率、用市值倒算净值，或选择风管与普通行情的优先级。

## 2. 一条记录在描述什么

| 维度 | 取数原字段 → 入模字段 | 读取要点 |
| --- | --- | --- |
| 工具 | `KEY_INSTRUMENT_ID` 关联主数据 → `SECU_ID`、`SRC_SYS_PRDNO`、`SCR_CD` | 数值属于哪个工具 |
| 报价日期 | `QUOTE_DATE` → `TRD_DT` | 取源日期部分，转成 `yyyyMMdd` |
| 记录编号 | `KEY_INSTRUMENT_ID` 与完整 `QUOTE_DATE` 拼接后生成 → `REC_ID`、`SRC_REC_ID` | SQL 注释将这两个源字段列为记录主键 |
| 行情来源 | `SOURCE_NAME` → `MKT_QUOT_SRC` | 风管记录中保留的具体来源 |
| 处理日期 | 任务处理日 → `BUSI_DATE` | 本次入模处理日期 |
| 更新时间 | `UPDATED_DATETIME` → `REC_UPD_TIME` | 源记录修改时间 |

**看业务记录时先用“工具＋报价日”，核对重复时再保留源 `QUOTE_DATE` 的完整值。** 目标报价日只保留日期，而记录编号使用源完整值，两者的精度并不完全相同。

主数据关联没有匹配时仍保留源记录，但 `SRC_SYS_PRDNO` 等身份字段可能为空；后续需要工具身份的消费因此可能无法使用它。

## 3. 主要数值怎样区分

| 取数原字段 → 入模字段 | 含义 | 读取方式 |
| --- | --- | --- |
| `UNIT_NAV` → `SHR_NAV` | 单位净值 | 与基金资产净值分开读取 |
| `NAV` → `NET_ASSET` | 资产净值 | 保存源端总量口径，未按份额重新计算 |
| `VIRTUAL_NAV` → `VRTL_NAV` | 虚拟净值 | 独立承接源字段；其源端生成规则未在本入模 SQL 中展开 |
| `CLOSE_QUOTE` → `CLOS_PRIC` | 收盘价 | 与单位净值分别提供，入模没有互相替代 |
| `SETTLE_QUOTE` → `SETT_PRIC` | 结算价 | 不由收盘价计算 |
| `AMOUNT` → `TRAMT` | 成交额 | 数值原样承接 |
| `CIRCULATION_MARKET_VALUE` → `CIR_MVAL` | 流通市值 | 源端提供的流通市值 |
| `MARKET_VALUE` → `TOT_MVAL` | 总市值 | 本来源元数据标为总市值 |

同名 `MARKET_VALUE` 在通用行情来源中标为“持仓市值”，在风管来源中标为“总市值”；两张表的字段注释应分别使用。

本分支没有业务类别或净值状态的代码转换。`SOURCE_NAME` 也直接保存，没有在入模中映射为统一的行情来源枚举。

## 4. “风管优先”具体是什么意思

已查消费 **182738：`DM_RSK_N.PRIC_FCTR_MKT_QUOT_DAY`**，按工具内码和报价日期选择 TIT 行情来源：

| 情况 | 消费怎样处理 |
| --- | --- |
| 同工具、同报价日存在风管记录，且能匹配 LBR 权益因子 | 使用风管的 `CLOS_PRIC` 和 `SHR_NAV`，输出该因子的收盘价和单位净值 |
| 同工具、同报价日不存在风管记录 | 普通 TIT 行情可进入补充分支，但仍需匹配 LBR 权益因子或汇率因子 |
| 风管记录存在，但某个数值为空 | SQL 没有按字段回退普通行情；普通来源的对应记录仍被排除 |

**这是按记录来源选择，不是逐字段补齐。** 例如风管有当天记录但单位净值为空，不能推断下游会自动从普通行情补上单位净值。

还有一个范围差异：普通分支会匹配 LBR 权益因子或汇率因子，风管分支只匹配 LBR 权益因子。普通记录是否被排除，判断的是风管同工具同日报价是否存在，未要求该风管记录先成功匹配因子。

## 5. 输出了哪些数值

182738 的风管分支实际输出：

- 工具对应的 `FCTR_ID`，来源是 `PDATA_NEWS_N.T02_FIN_EQUI_FCTR_INFO` 的 `LBR／01`。
- 行情日期 `TRD_DT`。
- `CLOS_PRIC` → 因子 `PRIC_CLOS`。
- `SHR_NAV` → 因子 `FND_UNIT_NAV`。
- 来源标识、来源表和源更新时间。

这个分支将涨跌幅、复权价格、复权因子、累计及复权单位净值置空；没有用风管收盘价或净值现场计算收益率。风管表中的虚拟净值、资产净值、结算价及市值也未进入该分支输出。

## 6. 查数顺序

先确认风管记录的工具与报价日，再查 TIT 主数据是否补上 `SRC_SYS_PRDNO`，最后查 LBR 权益因子是否存在对应内码。需要解释与普通行情的差异时，比较同工具、同报价日的两份记录及来源字段。

这样可以区分“源端没有报价”“身份未对应”“消费排除了普通来源”和“数值本身为空”，不会只因目标因子缺一项就直接判断源数据缺失。

依据：入模 SQL 207284；消费 SQL 182738；`ODATA_N_TIT.D_MKT_RISK_DAILY_INFO` 字段元数据。
