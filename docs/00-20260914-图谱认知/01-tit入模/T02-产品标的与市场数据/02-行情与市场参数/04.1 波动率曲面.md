# 04.1 波动率曲面

**波动率曲面把某个标的在不同期限、执行价等条件下的波动率组织起来。查数时依次看“曲面定义 → 结构维度 → 某日实例”，实际数值在实例表。**

同一标的可以对应不同名称、类型或规则的曲面。只有标的编号，还不足以决定使用哪一张；定价环境或因子定义会进一步指定曲面编号。

## 1. 三张原表分别提供什么

| 取数原表 | 入模表 | 来源／分组 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_REF_VOL_SURFACE` | `PDATA_NEWS_N.T02_FIN_VOL_CURV_SURF` | TIT／01 | 103242 |
| `ODATA_N_TIT.D_REF_VOL_SURFACE_STRUCTURE` | `PDATA_NEWS_N.T02_FIN_VOL_CURV_SURF` | TIT／02 | 103245 |
| `ODATA_N_TIT.D_REF_VOLSURFACE_INSTANCE` | `PDATA_NEWS_N.T02_FIN_VOLA_INSTC` | TIT／01 | 103248 |

定义和结构读取源处理业务日的 `BUSI_DATE`。实例 **103248 读取源表时没有当天 `BUSI_DATE` 条件**，实际曲面日期来自 `ASOF_DATE`；不能把入模处理日当成全部实例的日期。

三项入模接收源配置和源数值，没有执行曲面拟合、插值或波动率计算。

## 2. 一张曲面怎样和标的连接

| 关系 | 原字段 → 入模字段 | 含义 |
| --- | --- | --- |
| 曲面自身 | 三表的 `KEY_VOL_SURFACE_ID` → `CURV_SURF_ID` | 定义、结构、实例的共同曲面编号 |
| 曲面的来源标识 | `KEY_VOL_SURFACE_ID` → `SRC_SYS_PRDNO='TIT-曲面编号'` | 曲面身份，不能当作工具身份 |
| 曲面的标的 | 定义的 `KEY_INSTRUMENT_ID` → `UNDRL_SRC_SYS_PRDNO='TIT-工具编号'` | 对应金融工具主数据 |
| 标的统一编号 | 定义的 `KEY_INSTRUMENT_ID` 关联主数据 `IN_CODE` → `UNDRL_SECU_ID` | 从 TIT 主数据补充统一证券编号 |

定义的主数据匹配使用 `T02_SCR_BASE_INFO` 的 TIT 来源；匹配不到时，原曲面记录仍保留。定义分支先将曲面和工具 ID 转成整数再拼接，结构和实例则按源编号传递，核对连接时应使用实际编号表达。

这几个分支的 `REC_ID` 为空。**曲面身份看 `CURV_SURF_ID`，节点还要带上日期、期限及执行价，不能靠 `REC_ID` 找唯一记录。**

## 3. 定义、结构、实例各查哪些字段

### 3.1 定义：这张曲面按什么规则描述

| 原字段 → 定义 01 字段 | 业务含义 |
| --- | --- |
| `VOL_SURFACE_NAME`、`SURFACE_CLASS_NAME` → `CURV_SURF_NAME`、`CURV_SURF_CLAS_NAME` | 曲面名称和分类名称 |
| `VOL_SURFACE_TYPE` → `CURV_SURF_TYPE` | 源曲面类型 |
| `CURRENCY_CODE` → `CRRC_CD` | 源币种直接承接，本分支没有币种转码 |
| `VOL_SURF_GENERATOR`、`VOL_MODEL` → `CURV_SURF_GEN`、`VOL_MDL` | 源端生成器、波动率模型配置 |
| `VOL_SURF_INTERP` → `INTRPN_METHOD` | 插值方法配置 |
| `VOL_SURF_STRIKE_TYPE` → `EXEC_TYPE_DEF` | 执行价维度的表达类型 |
| `VOL_SURF_EXPIRY_TYPE` → `MATY_TYPE_CD` | 到期／期限维度的表达类型 |
| `CALENDAR`、`DAY_COUNT`、`DATE_ROLL` → `CAL`、`INTA_DAY_CACL_REGU`、`DATE_ADJ_REGU` | 日历、计息天数和日期调整规则 |
| `SPREAD_TYPE`、`TIME_ZONES` → `SPRD_TYPE`、`TIME_ZONES` | 点差类型和时区 |

建表注释列出的曲面类型如下；入模原样保存这些代码，没有重新分类。

| `VOL_SURFACE_TYPE` | 注释含义 |
| --- | --- |
| `HISTORICAL_VOLATILITY` | 历史波动率 |
| `IMPLY_VOLATILITY_SURFACE` | 隐含波动率曲面 |
| `LEGACY_IMPLIED_VOL` | 旧版隐含波动率曲面；注释标为拟废弃类型，不能据此判断当前记录已失效 |

`PERCENTAGE`、`MONEYNESS` 是执行价表达的源代码，不能只按词面给 `STRIKE` 统一补上“元”或“%”。到期类型注释也混有历史／隐含波动率描述，查节点时以源实际值、`TENOR`、`EXPIRY_DATE` 共同判断，不仅按类型名推断。

### 3.2 结构：列出哪些节点及参数

| 原字段 → 定义 02 字段 | 在这一分组中表示什么 |
| --- | --- |
| `STRIKE` → `EXER_PRIC` | 执行价维度原值 |
| `TENOR` → `TERM` | 期限维度原值 |
| `SPREAD` → `DATA_SET` | 源结构中的 spread 参数；目标名字“数据集合”不能替代源含义 |

结构 02 没有曲面名称、标的或波动率数值，需要通过 `CURV_SURF_ID` 回定义 01 读取规则。结构的 spread 也不能当作实例波动率。

### 3.3 实例：某个时点、节点上的波动率

| 原字段 → 实例字段 | 含义 |
| --- | --- |
| `ASOF_DATE` → `CURV_SURF_DATE` | 曲面参数日期／时点，保留至秒 |
| `TENOR` → `TERM` | 期限 |
| `STRIKE` → `EXEC_PRIC` | 执行价维度原值 |
| **`VOL` → `INTRPN`** | **源波动率数值直接承接** |
| `EXPIRY_DATE` → `MATY_DATE` | 到期时点 |
| `CREATED_DATETIME` → `ESTB_TIME_SRC` | 源实例创建时间 |

`INTRPN` 的目标注释写“插值”，但本项 SQL 的值来源就是 **`VOL`**。读取时应叫“波动率数值”，不能说入模现场算出了一个插值结果。

## 4. 风控实际消费的是哪些曲面

**176548 → `DM_RSK_N.VOLA_MKT_QUOT_DAY`** 包含两条来源不同的分支。其中 TIT 实例分支需要同时满足：

1. LBR 通用因子定义的处理方法属于 `VOL_GENERIC_ATM_CALC`、`VOL_FUTURE_ATM_CALC`、`VOL_MANUAL_INPUT_CALC`、`VOL_IMPLIED_BENCHMARK_CALC`。
2. 当日 `T02_FIN_VOLA_CATE_FCTR_DEF` 中 `VOLA_SRFC_TYPE='TERM'`，且 `VOLA_CURV_ID` 非空。
3. 因子的标的来源编号能匹配当日 `T02_FIN_UNDRL_DATA_LBR`。
4. 因子定义 `VOLA_CURV_ID` 与 TIT 实例 `CURV_SURF_ID` 对应。

该分支输出 **`TERM → DIM1`，`INTRPN ÷ 100 → VOLA`**，波动率保留六位小数；`DIM2`、`DIM3` 为空，没有输出 `EXEC_PRIC`。例如源 `VOL=20` 时，此公式输出 `0.200000`，这是换算示例。

因此，这条消费覆盖的是上述条件下的**期限型波动率因子数据**，不能概括成“所有 TIT 曲面完整进入风控”。它也没有在读取时按 `STRIKE` 选择 ATM 节点；处理方法名称中的 ATM 不等于该 SQL 现场做了平值点筛选。

另一条分支面向 `VOL_CMF_EWMA_HIS_CALC`、`VOL_FX_EWMA_HIS_CALC`、`VOL_IR_CF_HIS_CALC` 等方法，读取 LBR `T02_FIN_FCTR_DATA` 的 02 分组；这一分支数值不是来自 TIT 实例。

## 5. 财务怎样接收曲面

| 消费 | 实际读取 |
| --- | --- |
| **226123 → `DM_FIN_N.CIV_FIN_VOL_CURV_SURF`** | 读取 TIT 定义 01 和结构 02；对满足条件的港股统一证券编号补齐五位代码，其余曲面资料继续传递 |
| **226134 → `DM_FIN_N.CIV_FIN_VOLA_INSTC`** | 读取 TIT 实例 01，限定 `CURV_SURF_DATE` 的日期部分等于指定业务日，以该日期作为输出业务日 |

这里的财务实例消费明确选择曲面日期，而实例入模本身没有当天源分区限制。这两个环节的日期范围要分开理解。

## 6. 实际查询顺序

**先确定曲面编号 → 看定义中的标的、类型和维度规则 → 看结构 → 按曲面日期取完整节点 → 最后核对消费选取条件和单位换算。**

如果从一份交易出发，还应先查它所用的定价环境及曲面选择配置；如果从风控因子出发，就从因子定义的 `VOLA_CURV_ID` 开始。

依据：入模 SQL 103242、103245、103248；消费 SQL 176548、226123、226134；对应源表字段元数据与入模建表注释。
