# 06.5 限售股估值

**这张表保存股票在特定估值日、特定解禁安排下的估值和折价，供财务等下游使用。**

同一只股票如果对应不同解禁日期，限售安排不同，结果也需要分别保存。理解记录时，既要认出股票，也要看“哪一天估值、哪一天解禁”；只按股票代码查一条价格是不够的。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.M_REF_RESTRICTED_STOCK_DAILY` | `PDATA_NEWS_N.T02_STK_RSTK_DISC_INFO` | `SRC_ID='TIT'、GRP_ID='01'` | 228593 |

源表已经提供折扣价、公允价值、期权价值、流动性折扣和限售股估值等结果。入模承接这些数值，没有重新运行限售折价模型。

## 2. 取数逻辑：特别注意估值日

1. 直接读取 `M_REF_RESTRICTED_STOCK_DAILY`；**当前已查 SQL 没有按源 `BUSI_DATE` 过滤**。
2. 按 **`KEY_INSTRUMENT_ID = T02_SCR_BASE_INFO.IN_CODE`** 关联 TIT 工具主数据，补 `SECU_ID`。
3. 将工具编号加 `TIT-` 写 `SRC_SYS_PRDNO`，日期转为日期键，估值和折价字段直接承接。
4. 目标 `BUSI_DATE` 写调度处理日，实际估值日期由源 `QUOTE_DATE` 写到 `TRD_DT`。

因此，目标 `BUSI_DATE` 相同的记录可能对应不同 `TRD_DT`。要查某天的估值应看 `TRD_DT`，不能只按处理日筛选后就当成当天价格。

主数据关联未命中的源记录仍保留。入模没有只保留 `INS_FAMILY='EQUITY'`：该值映射 `SCR_TYPE='STK'`，其他值映射 `99`，源类别另保存在 `REMARK.src_scr_type`。

## 3. 一条估值记录怎样定位

| 维度 | 源字段 → 入模字段 | 说明 |
| --- | --- | --- |
| 股票工具 | `KEY_INSTRUMENT_ID` → `SRC_SYS_PRDNO`，并补 `SECU_ID` | 说明被估值的证券 |
| 估值日期 | `QUOTE_DATE` → `TRD_DT` | 这组估值和折价属于哪一天 |
| 解禁日期 | `RELEASE_DATE` → `LIFT_DAY` | 对应哪一次解禁安排 |
| 标的最后交易日 | `LAST_TRADE_DATE` → `UNDRL_STK_LAST_TRD_DAY` | 与估值日、解禁日分别保存 |
| 参照标的 | `REFERENCE_UNDERLYING` → `REF_UNDRL_CD` | 保存源端参照标的代码；当前入模未继续补其名称或统一证券编号 |

记录编号 `REC_ID`、`SRC_REC_ID` 由工具编号、原始 `QUOTE_DATE`、原始 `RELEASE_DATE` 组合生成。这体现了源设计要区分**证券＋估值日＋解禁安排**；它没有对最终业务行做额外去重校验。

## 4. 各种价格与折价不要混读

| 源字段 → 入模字段 | 模型字段含义 | 阅读要点 |
| --- | --- | --- |
| `CLOSE_QUOTE` → `ENAY_PRIC` | 日终价格 | 原样承接源价格，入模未另接交易所行情 |
| `DISCOUNT_QUOTE` → `DISC_PRIC` | 折扣价 | 与下列限售股估值分别保存，不能自动互相替代 |
| `FAIR_VALUE` → `UNDRL_STK_FAIR_VAL` | 标的股票公允价值（元） | 源端已有结果 |
| `OPTION_VALUE` → `OPT_VAL` | 期权价值（元） | 估值记录中的组成信息，当前 SQL 没有给出其计算模型 |
| `DISCOUNT_PCT` → `LIQD_DISC` | 流动性折扣（%） | 直接承接源字段 |
| `RESTRICTED_VALUE` → `RSTK_VALU` | 限售股估值（元） | 已确认被财务价格分支实际使用的结果 |
| `REMAINING_MATURITY` → `REMN_TERM` | 剩余期限（年） | 直接承接，没有在本任务用解禁日重新计算 |
| `VOLATILITY` → `EXPE_VOLA` | 预期波动率（%） | 源值直接写入 |
| `YIELD` → `EXPE_STK_PRFT_YIELD` | 预期股利收益率（%） | 源值直接写入 |

以上单位来自目标字段注释；当前本地原表字段注释为空，入模也没有百分比缩放。正式做数值比较时需要再确认源值单位，不能仅凭 `%` 注释自行乘除 100。

**当前 SQL 没有给出“公允价值减期权价值等于限售股估值”等公式。** 这些列同时存在能帮助理解估值记录包含哪些内容，但不能替代源端模型说明。

## 5. 财务如何实际使用

### 5.1 估值明细直接下发

调度 **228801** 读取本表 **TIT／01**，输出 **`DM_FIN_N.CIV_STK_RSTK_DISC_INFO`**，保留证券、估值日、解禁日及全部价格、折价字段。该消费没有在 SQL 中再次估值。

### 5.2 进入财务股票价格分支

调度 **211987** 输出 **`DM_FIN_N.FIN_GF_FI_QUOT_STOCK`**。其中限售股分支按以下逻辑使用本表：

1. 从 `T02_SCR_INFO_TOT` 的 **FIA／06** 取财务工具资料，读取备注中的 `fi_code_u`、`r_end_date` 等信息。
2. 用 **`fi_code_u = SECU_ID` 按点分隔后的第 3 段**，匹配 TIT／01 的估值证券；同时要求 **`r_end_date = LIFT_DAY`**，对应解禁安排。
3. 读取 `T99_TRD_CAL_REF` 中指定交易所日历。源日历 `TRD_FLAG='0'` 时使用上一交易日，否则使用当日，令该日期等于估值 `TRD_DT`。
4. 保留 `REF_UNDRL_CD IS NOT NULL` 的匹配结果，输出财务工具编号、名称及日历日期。

这里必须同时匹配证券与解禁日；同一证券有多次解禁时，不能省掉解禁条件。

| 财务输出字段 | 这个分支实际取什么 |
| --- | --- |
| `STRT_DATE`、`END_DATE` | 匹配日历的日期 |
| `CLOS_PRIC` | `RSTK_VALU` |
| `CLOS_PRIC_FRNT_EDA`、`CLOS_PRIC_PST_EDA` | 同样直接取 `RSTK_VALU` |
| `TOT_MVAL`、`CIR_MVAL` | 该分支也直接写 `RSTK_VALU`，SQL 未乘股数重新计算市值 |
| 开盘、最高、最低、成交量等 | 该分支留空 |

**因此，下游虽然叫收盘价、前复权价、后复权价，这个限售股分支放入的是同一个限售估值。** 它不能直接解释成交易所收盘行情，也没有在这条分支重新进行前后复权计算。

日历连接还可能把上一交易日估值用于相应非交易日的财务日期，这由已查 SQL 的日期对应决定，不能仅按输出日期推断源端当天新算了一次估值。

## 6. 查一笔财务限售股价格时的顺序

1. 先确认财务工具对应的证券与解禁日。
2. 在本表找对应的 `SECU_ID`、`LIFT_DAY` 和 `TRD_DT`，读取 `RSTK_VALU`。
3. 再按财务日历核对输出日期，确认是否沿用了上一交易日。
4. 如需解释估值为什么是这个数，再比较同条记录的公允价值、期权价值、折价和期限，并向源端追估值规则。
