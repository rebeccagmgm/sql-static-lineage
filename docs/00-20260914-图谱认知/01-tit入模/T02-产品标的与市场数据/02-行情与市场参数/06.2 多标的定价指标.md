# 06.2 多标的定价指标

**多标的期权的结果要分两层看：每一项挂钩标的分别对应哪些风险，以及两项标的之间有哪些交叉指标。**

例如，一笔期权挂钩 A、B 两项标的：单项记录分别给出 A、B 的价格、波动率、Delta、Vega；交叉记录则用 X／Y 标的对保存 Gamma、CEGA、相关性等。两个分组共同描述结果，但记录维度并不相同。

## 1. 从哪里取，进入哪张表

目标统一为 **`PDATA_NEWS_N.T02_OPT_MUTL_UNDRL_PRCG_INDX`**，`SRC_ID='TIT'`。

| 业务内容 | 取数原表（`ODATA_N_TIT`） | `GRP_ID` | 调度 |
| --- | --- | --- | --- |
| X／Y 标的交叉指标 | `D_V_RISK_OPTION_CROSS_METRIC` | 01 | 104483 |
| 同类指标的 h15 来源 | `D_V_RISK_OPTION_CROSS_METRIC_P` | 01 | 244510 |
| 单项标的指标 | `D_V_RISK_OPTION_PART_METRIC` | 02 | 104487 |
| 同类指标的 h15 来源 | `D_V_RISK_OPTION_PART_METRIC_P` | 02 | 244515 |

**01 和 02 是交叉与单项两种业务粒度，不能理解成同一记录的两个版本。** 普通分支与 h15 分支分别写入对应的同一个来源分组，目标没有额外保留独立的 h15 分组。

## 2. 取数逻辑

1. 普通分支取源 `BUSI_DATE` 等于处理业务日的记录；h15 分支取 `_P` 表的 `BUSI_DATE='h15'`。
2. 用源 **`KEY_INSTRUMENT_ID = T02_TIT_SCR_BASE_INFO.IN_CODE`** 补充 `SECU_ID`；该关联子查询对内码和证券编号去重，没有另写分组筛选。
3. 合约、交易、标的和指标直接承接；`KEY_INSTRUMENT_ID` 加 `TIT-` 写入 `SRC_SYS_PRDNO`。
4. 源业务日期转换为日期键后写 `SRC_BUSI_DATE`，目标 `BUSI_DATE` 写调度处理日。

身份未匹配的源结果仍保留。h15 分支的 `SRC_TBL` 仍记录普通表名，找原数据应使用上表实际 `_P` 来源。

## 3. 哪些编号需要一起保留

| 身份 | 01 交叉分组 | 02 单项分组 |
| --- | --- | --- |
| 工具 | `KEY_INSTRUMENT_ID` → `SCR_INCD`，并补 `SECU_ID` | 同左 |
| 合约 | `INTERNAL_TRADE_ID` → `COMP_NO` | 同左 |
| 交易 | `TRADE_ID` → `DEAL_NO` | `EXTERNAL_TRADE_ID` → `DEAL_NO` |
| 源业务日 | `SRC_BUSI_DATE` → `SRC_BUSI_DATE` | 同左 |
| 标的 | `WIND_CODE_X`、`WIND_CODE_Y` → `WIND_CD_X`、`WIND_CD_Y` | `UNDERLYING_WIND_CODE` → `WIND_CD_X`，Y 列留空 |
| 标的名称 | `INS_DESC_X`、`INS_DESC_Y` → 两端简称 | `UNDERLYING` → `UNDRL_ABBR_X` |

交叉源的 `TRADE_ID` 注释指向子交易 `EXTERNAL_TRADE_ID`，因此两个分组的 `DEAL_NO` 有对应线索；实际拼接仍应结合合约、工具和源业务日核验，不能只按单列交易号连接。

`SCR_INCD` 是源结果记录中的工具身份，X／Y 列才说明参与计算的挂钩标的。查标的行情时使用对应标的代码并核对代码映射，不要拿 `SCR_INCD` 自动代替 X 或 Y。

## 4. 01 组：两个标的一起看

| 源字段 → 入模字段 | 保存内容 | 阅读要点 |
| --- | --- | --- |
| `WIND_CODE_X`、`WIND_CODE_Y` → `WIND_CD_X`、`WIND_CD_Y` | 一对标的代码 | 保留 X／Y 位置；SQL 未做对称去重或交换归一 |
| `GAMMA` → `GAMMA` | 该标的对记录中的 Gamma 指标 | 按交叉来源理解，具体源端计算定义另核实 |
| `UNIT_GAMMA` → `UNIT_GAMMA` | 对应单位 Gamma | 与普通 Gamma 分列保存，SQL 未做单位换算 |
| `CEGA` → `CEGA` | CEGA 指标 | 源端已有结果 |
| `CORR` → `CORR` | 对应标的对的相关性 | 不是入模根据历史收益率重新计算 |

这一组不填单项的期初价、现价、波动率点、Delta 和 Vega。相关列为空表示**本来源分支不提供这些值**，不能当成这些风险为零。

## 5. 02 组：每项标的分别看

| 源字段 → 入模字段 | 保存内容 | 阅读要点 |
| --- | --- | --- |
| `BEGIN_PRICE` → `UNDRL_BGNG_PRIC` | 标的期初价 | 直接保留源值，期初基准需结合交易条款 |
| `UNDERLYING_SPOT` → `UNDRL_CLOS_PRIC` | 标的物收市价 | 来源为定价结果记录，不是在本任务另查日行情 |
| `UNDERLYING_SPOT_DATE` → `UNDRL_CLOS_PRIC_DATE` | 上述价格的日期 | 可能与源业务日承担不同含义，查数时分别保留 |
| `VOL` → `VOLA_DOT` | 定价使用的波动率点 | 这里是该记录使用的一个值，没有完整曲面节点 |
| `DELTA`、`VEGA`、`RHO_Q` → 同名字段 | 该标的对应的敏感度 | 直接承接源结果 |
| `UNIT_DELTA`、`UNIT_VEGA` → 同名字段 | 对应单位敏感度 | 不能不核对尺度就与普通指标混加 |

本组 Y 标的、Gamma、单位 Gamma、CEGA、CORR 留空。它没有通过与 01 组连接把交叉指标摊到每项标的上。

## 6. 用它分析一笔交易的顺序

1. 先确定合约、交易与源业务日期，分别取 01、02 两组。
2. 在 02 组逐项确认标的、价格日期、波动率及敏感度。
3. 在 01 组确认哪些 X／Y 标的对具有交叉指标和相关性。
4. 需要篮子定义、权重或标的构成时，再查产品基础资料中的多标的期权篮子；本结果表没有权重字段。

目标 `REC_ID` 在这些分支中为空。不能按它去重；也不能把两个分组直接连接后对所有数值求和，否则一个单项指标可能被多个标的对重复带出。
