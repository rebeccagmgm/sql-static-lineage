# 05 定价环境与因子

**定价环境回答“这次配置选择哪条曲线、哪张曲面”；因子定义回答“风控用哪个编号识别这项市场数据，它对应哪个工具或参数”。**

前面已经知道价格、曲线和曲面是什么，本章继续讲它们怎样被选择和组织。例如给某标的选择一张波动率曲面，与把该标的行情对应到一个风险因子，是两条不同的关系。

## 1. 分哪几篇读

| 子篇 | 主要讲清什么 | 主要模型 |
| --- | --- | --- |
| [05.1 定价环境与参数选择](05.1%20定价环境与参数选择.md) | 环境身份、普通曲线、分红曲线和波动率曲面的选择关系 | `T02_FIN_PRCG_ENV_CURV`、`T02_FIN_PRCG_ENV_DIVD_CURV`、`T02_FIN_PRCG_VOL_CURV_SURF` |
| [05.2 因子与市场数据的对应](05.2%20因子与市场数据的对应.md) | LBR 权益／曲线因子如何连接 TIT 工具与曲线数值 | `T02_FIN_EQUI_FCTR_INFO`、`T02_FIN_CURV_FCTR_DEF` |

以上模型均位于 `PDATA_NEWS_N`。环境配置写 TIT 来源，两个因子定义模型写 LBR 来源。

## 2. 先把两类关系分清

```text
定价环境
    ├─ 按币种、交易类型选择普通曲线
    ├─ 按标的选择分红曲线
    └─ 按标的、看涨／看跌范围选择波动率曲面

因子定义
    ├─ 因子ID → 工具内码 → 该工具的价格／净值
    └─ 因子ID → 分红曲线ID → 该曲线的日期、期限和数值
```

环境 ID、工具内码、曲线 ID、曲面 ID、因子 ID 各自识别不同对象。读一条记录时，先问“这个编号指的是谁”，再沿相应关系查定义或数值。

## 3. 来源与职责

| 资料 | 主体来源 | TIT 在其中负责什么 | 代表入模调度 |
| --- | --- | --- | --- |
| 环境身份和曲线／曲面选择 | `ODATA_N_TIT` 的环境配置表 | 提供源配置，入模承接选择关系并补部分币种或工具编号 | 226617、103238、103252、103249 |
| 权益类因子定义 | `ODATA_N_LBR.M_REF_EQUITY_FACTOR_DEF` | 按源标的内码补 TIT 工具身份，并补交易所名称 | 168302 |
| 曲线类因子定义 | `ODATA_N_LBR.M_REF_FACTOR_CURVE_DEF` | 按源标的内码补 TIT 工具身份，并补日历／交易所名称 | 170265 |

因子定义来自 LBR，TIT 行情来自另一条取数链；下游通过工具或曲线的对应关系把两者接起来。两个因子入模都没有在这里产生市场报价或拟合曲线。

## 4. 已确认的实际用途

| 用途 | 实际取什么 | 消费调度 |
| --- | --- | --- |
| 定价环境权限核查 | 取 TIT／02 环境名称，补充用户资源权限的显示名称 | 208181 |
| 财务环境资料 | 取 TIT／02 环境身份信息 | 226709 |
| 财务曲面选择配置 | 取 TIT／01 的环境—标的—曲面关系 | 226067 |
| 风控价格类因子行情 | 把 TIT 价格／净值按工具内码接到 LBR 因子编号 | 182738 |
| 风控分红因子行情 | 按因子 ID、分红曲线 ID 连接 TIT／02 曲线行情 | 182230 |

这些 SQL 能证明资料怎样被读取。若要确定某份合约某次估值到底使用了哪套环境和参数，还需合约或定价运行记录提供对应；配置存在本身不等于已经参与那次计算。
