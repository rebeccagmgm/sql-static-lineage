# 01 日常价格与净值

**这一组回答：某个金融工具在某一天，源系统提供了什么价格、净值和交易数据，以及下游实际选用了哪一份。**

主数据先告诉我们工具是谁；行情再告诉我们它在什么日期值多少。股票、指数、期货、场内期权和基金共用一个普通行情入口，风管行情和期权 reset 则有各自的来源与用途。

## 1. 三条入口怎样区分

| 子篇 | 业务内容 | 取数原表 → 入模表 | 调度 |
| --- | --- | --- | --- |
| [01.1 通用行情](01.1%20通用行情.md) | 开高低收、结算价、成交量额、复权信息、净值 | `ODATA_N_TIT.D_MKT_INS_DAILY_INFO` → `PDATA_NEWS_N.TYZX_EXCH_QUOT_H_FK` | 104663 |
| [01.2 风管行情](01.2%20风管行情.md) | 风管提供的单位净值、资产净值、收盘价等 | `ODATA_N_TIT.D_MKT_RISK_DAILY_INFO` → `PDATA_NEWS_N.T02_PRD_UNIT_NAV_S_TIT` | 207284 |
| [01.3 期权 reset](01.3%20期权reset.md) | 某期权、某标的在观察日的 reset 值 | `ODATA_N_TIT.R_REF_OPTION_QUOTE_RESET` → `PDATA_NEWS_N.T02_OPT_MKT_QUOT` | 139409 |

三条入模均写入 `SRC_ID='TIT'、GRP_ID='01'`。目标表名只是入口：普通行情没有 T02 前缀；风管表并非仅有基金净值；期权行情表的这个分支主要承接 reset 值。

## 2. 查数时先确定三件事

| 要确定什么 | 实际怎样找 |
| --- | --- |
| 查谁的行情 | 用 `KEY_INSTRUMENT_ID` 找工具；查合约挂钩资产时，先从结构或持仓取得标的内码 |
| 查哪一天 | 普通和风管行情看 `QUOTE_DATE`，reset 看 `OBS_DATE`；入模对应 `TRD_DT` 或 `TRD_DATE` |
| 查哪种数值 | 收盘价、结算价、单位净值、资产净值、reset 各有含义，按用途选字段 |

**处理日 `BUSI_DATE` 与报价／观察日分别使用。** 通用行情入模未按源 `BUSI_DATE` 筛选；风管与 reset 入模取处理日的源数据，但其中的行情日期仍来自记录本身。

## 3. 一条共同的使用路径

```text
金融工具内码
    → 主数据：名称、类别、市场、币种与外部代码
    → 行情：报价日、数值、来源
    → 消费：按工具类别分流，或与因子编号对应
```

普通行情通过 `TIT-工具内码` 保存源系统产品身份，下游再结合主数据分出股票指数、期货、场内期权和基金。风管行情用于价格类因子时，还要找到对应的 LBR 权益因子。

## 4. 下游怎样选用

| 使用场景 | 已确认的取法 |
| --- | --- |
| 风控股票指数、期货、场内期权、基金日行情 | 从通用行情取数，按主数据类别分流；175782、164723、175878、175843 |
| 风控价格类因子行情 | 182738 按工具＋报价日优先使用风管来源；没有同日风管记录的普通行情才进入其补充分支 |
| 香港期权 reset | 134518 将 `SETT_PRIC` 还原为 `RESET_VALUE`，并限定到关联 `GFS_HK` 账簿的期权 |

**“风管优先”是具体消费任务的来源选择规则。** 它没有改变通用行情入模，也不表示所有下游都采用风管价格；详细规则见 01.2。

依据：入模 SQL 104663、207284、139409；消费 SQL 164723、175782、175843、175878、182738、134518。
