# 行情与市场参数全貌

**产品基础资料回答“这是什么、有什么条款”；这一部分接着回答“某一天值多少、定价使用什么市场参数、选择哪套配置，以及已经得到什么估值和风险结果”。**

先把这几种东西分清，再去看表和字段。例如，知道一份期权挂钩哪只股票后，还需要找股票价格、相关利率和分红曲线、波动率；选用哪一条曲线、哪一张曲面由配置说明。最后看到的期权理论价、Greeks 和损益，则属于计算结果。

本篇覆盖当前 TIT 入模盘点中的相关资料，包含 TIT 提供的数据，以及 TIT 参与身份、字典补充的 LBR 因子资料。先在本篇建立全貌，再按第 8 节导航进入六组子篇。

## 1. 先看全貌：六组资料各回答什么

| 资料组          | 主要回答什么                          | 典型内容                                 |
| ------------ | ------------------------------- | ------------------------------------ |
| **日常价格与净值**  | 某个工具在某天的价格、成交和净值是什么？            | 股票、指数、期货、场内期权、基金共用行情；风管行情；期权 reset 值 |
| **汇率与利率**    | 某天某币种的中间价、某利率工具的报价是多少？          | 人民币汇率中间价、利率指标报价与批次                   |
| **收益率与分红曲线** | 不同期限分别使用什么利率或分红参数？              | 曲线定义、外部曲线代码映射、各日期和期限的曲线数值            |
| **波动率与相关性**  | 不同期限、执行价下的波动率是多少，两项工具之间的相关性是多少？ | 波动率曲面定义、结构点、实例数值，相关性数据               |
| **定价环境与因子**  | 选哪套参数？风控用哪个因子编号识别这项市场数据？        | 定价环境、环境与曲线／曲面的对应，权益和曲线因子定义           |
| **估值与风险结果**  | 源系统已经算出了什么价格、敏感度、损益或折价？         | 期权 Greeks、多标的指标、自营做市损益分解、隐含参数、限售股估值  |

**同一工具可以同时出现在多组资料中。** 例如一份场内期权有自身的日行情，也可能有定价产生的理论价和敏感度；这些数值的业务含义、来源与日期不能互相替代。

### 四种性质，要先认出来

| 性质 | 直观理解 | 本地资料中的例子 |
| --- | --- | --- |
| 市场数值 | 某天实际提供了哪个数值 | 收盘价、净值、汇率、利率、波动率实例 |
| 定义与结构 | 这个参数对象是什么，用哪些维度和规则描述 | 曲线的名称、币种、计息规则；曲面的标的、期限和执行价结构 |
| 选择配置 | 在某个业务环境下使用哪个参数对象 | 环境＋币种＋交易类型选曲线；环境＋标的选分红曲线或波动率曲面 |
| 计算结果 | 根据合约、行情和规则已经算出的数值 | 理论价、Greeks、损益分解、限售股估值 |

其中，曲线可以先理解为**沿期限排列的一组参数**；波动率曲面还增加执行价等维度。定义告诉我们这组数据如何描述，某日实例或行情才给出具体数值。

## 2. 这些资料从哪里来，TIT 负责什么

### 2.1 经 TIT 采集到数综，不等于全部由 TIT 原创或计算

贴源层 `ODATA_N_TIT` 中既有市场数据，也有源端维护的配置和已经生成的计算结果。例如：

- `D_MKT_INS_DAILY_INFO` 提供通用工具行情，并保留行情来源字段。
- `D_REF_WIND_YIELD_CURVE` 提供 WIND 收益率曲线数据。
- `D_CFG_PRICING_ENV_*` 提供定价时选择曲线、曲面的配置。
- `D_V_GREEKS_PRICING_RM` 等提供源端已有的定价与风险指标。

已查入模大多负责承接数值、关联编号、转换日期或代码，部分做明确的单位换算。**看到目标表里有理论价、波动率、相关系数，并不表示这项入模任务运行了定价、拟合或相关性计算。**

### 2.2 LBR 因子资料与 TIT 行情会在消费中连接

`T02_FIN_EQUI_FCTR_INFO`、`T02_FIN_CURV_FCTR_DEF` 的主体分别来自 LBR 的权益因子、曲线因子定义，目标写入 **`SRC_ID='LBR'`**。TIT 参与证券身份与交易所字典补充。

下游再利用“因子对应哪个工具或曲线”的关系，把 TIT 价格、净值或曲线数值接到因子上。例如风控价格类因子行情会同时使用 LBR 权益因子定义和 TIT 行情。

因此，这两张表属于本篇需要理解的连接资料；不能把它们写成 TIT 独立提供的因子定义。

## 3. 资料分别从哪里入模

以下未另注明的原表均在 **`ODATA_N_TIT`**，入模表均在 **`PDATA_NEWS_N`**。表中列各业务分支的代表调度，重点保留来源、分组和内容差异。

### 3.1 日常价格与净值

| 资料 | 取数原表 → 入模表 | 入模内容／代表调度 |
| --- | --- | --- |
| 通用工具行情 | `D_MKT_INS_DAILY_INFO` → `TYZX_EXCH_QUOT_H_FK`（TIT／01） | 开高低收、结算价、成交量额、持仓量、复权信息和净值等；104663 |
| 风管行情 | `D_MKT_RISK_DAILY_INFO` → `T02_PRD_UNIT_NAV_S_TIT`（TIT／01） | 单位净值、资产净值、虚拟净值、收盘价、结算价、市值及来源等；207284 |
| 期权 reset 值 | `R_REF_OPTION_QUOTE_RESET` → `T02_OPT_MKT_QUOT`（TIT／01） | 观察日写交易日期，`RESET_VALUE` 写 `SETT_PRIC`；139409 |

### 3.4 波动率与相关性

| 资料 | 取数原表 → 入模表 | 保存什么／代表调度 |
| --- | --- | --- |
| 波动率曲面定义 | `D_REF_VOL_SURFACE` → `T02_FIN_VOL_CURV_SURF`（TIT／01） | 曲面编号、标的、名称、类型、生成器、插值及日期规则；103242 |
| 曲面结构 | `D_REF_VOL_SURFACE_STRUCTURE` → `T02_FIN_VOL_CURV_SURF`（TIT／02） | 执行价、期限和 spread 等结构参数；103245 |
| 曲面实例数值 | `D_REF_VOLSURFACE_INSTANCE` → `T02_FIN_VOLA_INSTC`（TIT／01） | 曲面日期、期限、执行价、到期日和 `VOL` 数值；103248 |
| 相关性 | `D_REF_CORRELATION_DAILY_INFO` → `T02_OTH_CORRE_FCTR`（TIT／01） | 工具 X、工具 Y、日期和相关系数；两端写入 `FCTR_X`、`FCTR_Y`。117794 |

曲面定义中保存了生成或插值方法，表示源端配置采用什么规则；这几项入模 SQL 没有据此重新拟合曲面。实例中的 `VOL` 直接写到目标字段 `INTRPN`，不能因为目标注释为“插值”，就把它理解成本任务现场计算的结果。

相关性源字段 `CORRELATION_X`、`CORRELATION_Y` 对应 **TIT 工具内码**；目标虽命名为 `FCTR_X`、`FCTR_Y`，不能把它们直接当作 LBR 因子 ID。查数时同时保留工具 X、工具 Y 和日期，两端可按工具内码查主数据；接入 LBR 风险因子时再按对应关系匹配。

**定价环境告诉我们“选谁”，曲线和曲面资料告诉我们“选到的对象及数值是什么”。** 仅有选择配置，既没有完整市场数值，也不证明某份合约已经使用它完成定价。

一个易误读字段是 `T02_FIN_PRCG_ENV_CURV.DIVD_CURV_ID`：在 TIT／01 中，它来自普通配置的 `KEY_CURVE_ID`。实际业务要按该来源理解，不能只凭目标字段名把这一组都叫成分红曲线配置。

这一组已经是源端提供的计算结果。入模主要负责接收和映射，没有在这里重新计算 Greeks、损益分解或限售股折价。

Greeks 可以先理解为**价格对标的价格、波动率等变化的敏感程度**。但具体一列是单位敏感度、整笔金额还是按名义本金归一后的指标，要结合来源字段和计算口径确认，不能只按同名列相加。

`T02_OPT_GREEK_VAL_DET_H` 还带业务日期分区，批次使用源业务日期；部分旧 SQL 尾部不完整，当前不据 `_H` 后缀推断完整历史维护或回刷规则。

## 4. 编号和关系怎样串起来

### 4.1 工具身份 → 日常行情

```text
金融工具 KEY_INSTRUMENT_ID
    ├─ 主数据：叫什么、是什么类型、在哪个市场
    └─ 行情：哪个报价日，价格／净值／成交量是多少
```

股票、期货、期权等行情先按工具身份匹配，再结合工具类别分流。要查某份合约挂钩标的的价格，应先从合约结构或持仓取得**挂钩标的内码**，再找该工具行情；合约自身的工具编号与挂钩标的编号分别使用。

### 4.2 曲线定义 → 引用的行情曲线 → 日期与期限

已查风控收益率视图 **155160** 的具体连接是：

```text
T02_FIN_CURV_DEF（TIT／01）
    CURV_ID_SRC：引用的行情曲线编号
         ↓ 等于
T02_FIN_CURV_MKT_QUOT（TIT／01）.REC_ID
         ↓ 按日期、期限读取各节点数值
T02_FIN_CURV_DEF（TIT／03）补 WIND 曲线描述
```

这里用的是定义中的 `CURV_ID_SRC`，不能把所有“曲线编号”列不加区分地相等连接。分红曲线、因子与曲线的连接也要看相应业务键。

### 4.3 定价环境 → 曲面／曲线；因子 → 对应市场数据

| 关系 | 主要连接字段 | 能确定什么 |
| --- | --- | --- |
| 环境 → 普通曲线 | `KEY_PRICING_ENV_ID`＋币种＋交易类型 → `KEY_CURVE_ID` | 该配置选择哪条曲线 |
| 环境 → 分红曲线 | 环境＋`KEY_INSTRUMENT_ID` → `KEY_DIV_CURVE_ID` | 给某标的选择哪条分红曲线 |
| 环境 → 波动率曲面 | 环境＋标的＋`CALL_OR_PUT` → `KEY_VOL_SURFACE_ID` | 选择哪张曲面及权利范围 |
| 曲面 → 实例 | `KEY_VOL_SURFACE_ID`，再结合曲面日期、期限、执行价等 | 该曲面在具体日期和节点上的数值 |
| 权益因子 → 工具行情 | 因子定义中的工具对应关系 | 将价格或净值对应到因子编号 |

**`KEY_INSTRUMENT_ID`、曲线 ID、曲面 ID、环境 ID、因子 ID 分别属于不同对象。** 本部分的 `SRC_SYS_PRDNO` 也可能由曲线、曲面或环境编号拼接；不能统一去掉 `TIT-` 就当作金融工具内码查询。

| 财务限售股价格 | 按证券与解禁日期等条件匹配限售股估值，用于相应价格分支 | `DM_FIN_N.FIN_GF_FI_QUOT_STOCK`／211987 |

以上说明具体分支的使用方式。曲线行情 03、利率批次、部分环境配置以及多张 T02 Greeks／多标的结果表，现有证据尚未确认明确业务读取。

风控存在名称相似的 Greeks、多标的指标和篮子结果，其中已查任务 **176827、176831、177267** 是从 T03／T98 等资料重新组装；不能仅凭结果同名，就连成上述 T02 结果表的下游。

## 6. 查数时优先看这五件事

### 6.1 看数值属于哪种业务含义

收盘价、结算价、reset 值、单位净值、理论价、限售股估值都可能最终被放进名称含“价格”的字段。先确定来源分支和数值含义，再比较金额。

例如 `T02_OPT_MKT_QUOT` 的 TIT／01 中，`SETT_PRIC` 实际来自 reset 值；`T02_FIN_VOLA_INSTC.INTRPN` 实际来自源 `VOL`。

### 6.2 看实际报价或观察日期

| 日期 | 主要表示什么 |
| --- | --- |
| `BUSI_DATE` | 数据处理或来源分区日期，具体用法以任务为准 |
| 报价日、`TRD_DT`／`TRD_DATE` | 该行情对应的日期 |
| `OBS_DATE`、`ASOF_DATE`／曲面日期 | 观察或参数实例所对应的时点 |
| 到期日、解禁日 | 合约期限或估值条件，不是本次跑数日期 |

普通行情 **104663**、波动率实例 **103248**、限售股估值 **228593** 的源读取都没有按当天 `BUSI_DATE` 过滤。不能看到目标处理日，就把里面的每条报价、曲面实例或估值都认定为当天数据；限售股估值还应看源 `QUOTE_DATE` 对应的 `TRD_DT`。

### 6.3 看单位和比例怎样变换

- **利率**：源 `RATE × 100` 入模，已查风控消费再除以 100。例如源值 `0.02` → 模型值 `2` → 风控值 `0.02`，这是 SQL 运算示例。
- **波动率**：实例入模直接接收 `VOL`；已查波动率消费分支将 `INTRPN ÷ 100` 后输出。
- **涨跌和成交量**：共用行情的源注释对不同品种给出不同含义。场内期权、港股期货的涨跌字段是价格变化，其它类型标为百分比；成交量也有股、张、千克、手之分。
- **汇率**：已查 TIT 入模承接中间价并指定另一币种为人民币，没有做倒数换算。具体金额如何折算，继续看消费公式及源报价口径。

### 6.4 看来源、分组和批次

同一目标表中的不同 `SRC_ID`、`GRP_ID` 可能装着完全不同的内容。尤其曲线定义、曲线行情、定价环境、多标的指标都按组区分业务；`0830h`、`h15` 等还用于选择批次。

查到这张表有消费者，只能作为追查入口；还要确认消费者是否读取了所关心的来源分支。

### 6.5 看配置与结果是否真的接上

存在一份定价配置和一份风险结果，不能自动证明该结果使用了这套配置。要还原某份合约某次定价，仍需明确合约／交易、估值日、使用的环境与参数版本，以及结果记录之间的对应。
