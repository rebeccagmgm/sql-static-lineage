# 02.2 利率报价

**这一条保存利率工具在某个报价日的利率数值。工具叫什么、期限多长、怎样计息由基础资料解释；这里给出它在具体日期的报价。**

最重要的换算是：**源 `RATE × 100` 写模型 `INTRT`，模型单位为 `%`；风控货币市场利率消费再除以 100，输出小数报价。**

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 源取数范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.M_REF_CBOND_RATE` | `PDATA_NEWS_N.T02_IRA_INDX_INFO` | 处理日 `BUSI_DATE` | 165804 |
| `ODATA_N_TIT.M_REF_CBOND_RATE_P` | `PDATA_NEWS_N.T02_IRA_INDX_INFO_PB` | 固定 `BUSI_DATE='h0830'` | 239826 |

普通目标为 `SRC_ID='TIT'、GRP_ID='01'`；批次目标在此基础上增加 **`TIME_FLAG='0830h'`**。

两条都直接读取源利率，补工具身份与名称，转换报价日期并乘 100。没有按币种、期限、利率正负或工具类型额外过滤，也没有从债券价格计算收益率。

## 2. 先知道报价属于哪个工具

| 分支 | 工具身份来源 | 连接方式 |
| --- | --- | --- |
| 165804 普通 | `PDATA_NEWS_N.T02_SCR_BASE_INFO`，`SRC_ID='TIT'` | 源 `KEY_INSTRUMENT_ID = IN_CODE` |
| 239826 批次 | `PDATA_NEWS_N.T02_TIT_SCR_BASE_INFO`，`SRC_ID='TIT'、GRP_ID='01'` | 同样按工具内码连接 |

两条分别从所连接的主数据取得 `SECU_ID`、`SRC_SYS_PRDNO`、`CH_NAME`，名称写入 `INDX_NAME`。源利率记录没有匹配到主数据时仍保留，但这些身份或名称字段可能为空。

要进一步了解币种、期限、计息与结算惯例，可以沿同一工具身份查基础资料中来自 `ODATA_N_TIT.D_REF_RATE_PROPERITES` 的 `PDATA_NEWS_N.T02_TIT_IRA_CRRC_ATTR`。这些属性没有在本报价入模中重新拼成一条完整条款记录。

## 3. 一条记录的维度与字段

| 内容 | 取数原字段／规则 → 入模字段 | 含义 |
| --- | --- | --- |
| 工具 | `KEY_INSTRUMENT_ID` 关联主数据 → `SECU_ID`、`SRC_SYS_PRDNO` | 哪个利率工具 |
| 报价日期 | `QUOTE_DATE` 日期部分 → `TRD_DT` | 利率属于哪个日期 |
| 记录编号 | 工具内码＋报价日期 → `REC_ID` | 明确保留工具和日期两个维度 |
| 利率 | `CAST(RATE AS DOUBLE) × 100` → `INTRT` | 模型利率，单位 `%` |
| 名称 | 主数据 `CH_NAME` → `INDX_NAME` | 工具对应的名称 |
| 源更新时间 | `UPDATED_DATETIME` → `REC_UPD_TIME` | 来源记录修改时间 |
| 处理日期 | 任务处理日 → `BUSI_DATE` | 入模处理日 |
| 批次 | 固定 `'0830h'` → 批次表 `TIME_FLAG` | 标识这一批报价 |

指标父节点编号、父节点类型、父节点名称和指标类型在这两条 SQL 中均为空。目标有这些通用列，不表示本分支已经构建利率指标层级。

## 4. 单位在三层怎样变化

下面用一个假设数值说明 SQL 的换算关系：

| 所在位置 | 数值示例 | 表达口径 |
| --- | --- | --- |
| 源 `M_REF_CBOND_RATE.RATE` | `0.025` | 源小数值 |
| 模型 `T02_IRA_INDX_INFO.INTRT` | `2.5` | 百分数，表示 `2.5%` |
| 风控 `CRRC_MKT_INTRT.MIN_PRIC` | `0.02500000` | 模型值除 100，转 `DECIMAL(18,8)` |

这三处数值不同，但在这条换算链中表达同一利率。对账时先确认列所在层级；直接把源 `RATE` 与模型 `INTRT` 相减，会得到没有业务意义的差异。

香港利率信息消费 181104 直接传递 `INTRT`，没有除 100，因此不能把所有消费输出都统一当作小数。

## 5. 0830h 批次怎样理解

239826 的源条件和目标批次写法分别是：

```text
源 M_REF_CBOND_RATE_P：BUSI_DATE = 'h0830'
目标 T02_IRA_INDX_INFO_PB：TIME_FLAG = '0830h'
```

源条件中的 `h0830` 是固定标识，不是日历日期。记录的实际报价日期仍从 `QUOTE_DATE` 取得；目标 `BUSI_DATE` 则写任务处理日。

普通表和批次表保存位置不同，身份补充也分别使用不同主数据表。查某个时点采用哪份利率，需要同时确认消费读的是普通表还是批次表，而不是仅比较工具内码和日期。

## 6. 下游实际怎样使用

### 风控货币市场利率：166041

任务 `dm_rsk_n.crrc_mkt_intrt` 读取普通模型表 TIT／01，通过源系统产品编号取工具内码，再匹配 `PDATA_NEWS_N.T02_TIT_SCR_BASE_INFO` 的 **TIT／02、`DATE_SRC='WIND'`** 外部编码，输出市场数据代码。

它将 `INTRT / 100` 写入 `MIN_PRIC`；买价 `BID_PRIC`、卖价 `ASK_PRIC` 为空。因此，这个接口提供的是利率中间报价，未从本源分支得到双边报价。

外部代码使用必须匹配的连接关系，缺少对应 WIND 代码的模型记录不会进入这项输出。

### 香港利率信息：181104

任务 `dm_hk_n.info_tit_ira_indx_day` 读取普通模型表 TIT／01，传递工具身份、名称、报价日期和 `INTRT`，保留模型百分数单位。

上述两项已查消费均读取普通表。批次表已有明确入模来源与批次，但本篇证据未确认它被这两项消费使用。

依据：入模 SQL 165804、239826；消费 SQL 166041、181104；利率属性来源参照入模 170648。数值示例只演示已查 SQL 的倍率关系。
