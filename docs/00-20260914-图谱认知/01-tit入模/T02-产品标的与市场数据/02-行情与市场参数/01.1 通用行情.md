# 01.1 通用行情

**`D_MKT_INS_DAILY_INFO` 是 TIT 的共用工具日行情入口：同一张表承接股票、指数、期货、场内期权和基金等工具的价格、成交及净值资料。**

先通过工具内码知道“这是哪个工具”，再按报价日期读取需要的数值。各品种会使用不同字段：期货关心结算价和持仓量，基金关心单位净值，股票还会用复权价格和交易状态。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_MKT_INS_DAILY_INFO` | `PDATA_NEWS_N.TYZX_EXCH_QUOT_H_FK` | `SRC_ID='TIT'、GRP_ID='01'` | 104663 |

已查入模**没有按源 `BUSI_DATE`、工具类别、行情来源或交易状态筛选**。它承接源记录，补证券身份与币种，保留源报价日期；股票、期货等分类发生在后续消费。

## 2. 工具、日期和来源怎么认

| 内容     | 取数原字段 → 入模字段                                              | 怎样理解                            |
| ------ | --------------------------------------------------------- | ------------------------------- |
| 工具身份   | `KEY_INSTRUMENT_ID` → `SRC_SYS_PRDNO='TIT-'+内码`           | 行情对应的金融工具                       |
| 统一证券编号 | 优先按工具内码匹配 TIT 主数据；未取到时按 `WIND_CODE` 匹配 WD 主数据 → `SECU_ID` | 两条身份匹配路径有先后顺序                   |
| 报价日期   | `QUOTE_DATE` → `TRD_DT`                                   | 行情所属日期，格式转为 `yyyyMMdd`          |
| 处理日期   | 任务处理日 → `BUSI_DATE`                                       | 入模处理日期，不能代替报价日期                 |
| 币种     | TIT 主数据 `CRRC_CD` → `CRRC_CD`                             | 来自 TIT 身份分支；WD 编号补位不同时补币种       |
| 数据来源   | `SOURCE_NAME` → `DATA_SRC`                                | 保留源端提供的行情来源                     |
| 外部代码   | `WIND_CODE` → `UNDRL_WIND_CD`                             | 行情记录携带的代码；目标列名中的“标的”不另外建立合约挂钩关系 |

两条身份匹配使用 `PDATA_NEWS_N.T02_SCR_BASE_INFO`，分别限定 `SRC_ID='TIT'` 和 `SRC_ID='WD'`。没有过滤未匹配到 `SECU_ID` 的行情。

**阅读维度至少保留“工具＋报价日期＋来源”。** 源表另有 `QUOTE_TYPE` 行情类型，104663 没有将它映射到目标独立字段，也没有按它去重；仅凭工具＋日期不能假定目标必然只有一条。

## 3. 价格、量额和净值分别取什么

| 内容 | 取数原字段 → 入模字段 | 业务含义 |
| --- | --- | --- |
| 昨收、开高低收 | `PRECLOSE_QUOTE`、`OPEN_QUOTE`、`HIGH_QUOTE`、`LOW_QUOTE`、`CLOSE_QUOTE` → `PRIC_PRE_CLOS`、`PRIC_OPEN`、`PRIC_HIGH`、`PRIC_LOW`、`PRIC_CLOS` | 普通价格序列 |
| 结算及买卖价 | `SETTLE_QUOTE`、`BID`、`ASK` → `SETT_PRIC`、`BUYING_PRIC`、`SELLING_PRIC` | 各自独立承接，未由收盘价计算 |
| 成交与持仓 | `VOLUME`、`AMOUNT`、`OPEN_INTEREST` → `DEAL_VOL`、`DEAL_AMT`、`OPEN_INTR` | 成交量、成交金额和持仓量 |
| 市值 | `MARKET_VALUE`、`CIRCULATION_MARKET_VALUE` → `OPEN_INTR_MVAL`、`CIR_MVAL` | 本来源元数据分别标为持仓市值、流通市值 |
| 均价 | `AVG_PRICE` → `PRIC_AVG` | 源端提供的 VWAP，入模没有用量额重算 |
| 涨跌 | `PCTCHANGE` → `PRIC_CHG` | 数值原样承接，具体单位要结合品种 |
| 单位与资产净值 | `UNIT_NAV`、`NAV` → `FND_UNIT_NAV`、`NAV` | 单位净值与资产净值分别保存 |
| 累计与复权净值 | `ACCUM_SHR_NAV`、`ADJ_SHR_NAV` → `ACCUM_UNIT_NAV`、`EDA_UNIT_NAV` | 源端已有的累计、复权单位净值 |

### 复权价格

`ADJPRECLOSE_QUOTE`、`ADJOPEN_QUOTE`、`ADJHIGH_QUOTE`、`ADJLOW_QUOTE`、`ADJCLOSE_QUOTE` 分别写入复权昨收及开高低收字段；`ADJ_FACTOR` 写入 `PRIC_ADJFACTOR`。

**复权价格和复权因子都来自源端，入模没有重新计算复权。** 对比价格序列时，普通收盘与复权收盘应各自保持一致口径。

## 4. 单位与交易状态

目标 SQL 注释明确保留了品种差异：

- `PRIC_CHG`：场内期权和港股期货记价格变化；其他类型记涨跌幅。
- `DEAL_VOL`：港股股票为股、港股期货为张、黄金现货为千克，其他默认手。
- `OPEN_INTR`：港股期货为张，其他默认手。

因此，不能把这张共用表的成交量统一解释为股，也不能把每个 `PRIC_CHG` 都当作百分比。

`TRADE_STATUS` 原样写入 `TRD_STAT`。源元数据指向字典 `WindInstrumentTradeStatus`；本地 TIT 字典业务日期 `2026-09-14` 的含义为：

| 源码 | 含义 |
| --- | --- |
| `TRADING` | 交易 |
| `SUSPENSION` | 停牌 |

状态用于解释当天行情背景，104663 本身没有据此排除停牌记录。

## 5. 下游实际用到哪里

| 消费表／调度 | 分类与使用 |
| --- | --- |
| `DM_RSK_N.FUTR_MKT_QUOT`／164723 | 主数据类别 `FUTURE`，输出开高低收、结算价、成交量额、币种 |
| `DM_RSK_N.TRD_OPT_MKT_QUOT_DAY`／175878 | 类别 `LISTEDOPTION`，输出价格、涨跌、复权收盘、均价和成交量 |
| `DM_RSK_N.STK_SPI_MKT_QUOT_DAY`／175782 | 类别 `INDEX`、`EQUITY`，输出价格、复权因子、交易状态等 |
| `DM_RSK_N.FND_MKT_QUOT_DAY`／175843 | 类别 `FUND`，输出收盘价、资产净值、累计及复权单位净值 |
| `DM_RSK_N.PRIC_FCTR_MKT_QUOT_DAY`／182738 | 按内码匹配 LBR 权益／汇率因子，并排除已存在同工具同日风管行情的普通行情 |

前四类消费结合 `PDATA_NEWS_N.T02_TIT_SCR_BASE_INFO` 的 **01 工具身份、02 外部编码**，使用 `DATE_SRC='WIND'` 的代码。因此，源行情已有记录但缺少所需主数据类别或外部代码时，不一定进入这些分类输出。

182738 的普通行情分支还将 `PRIC_CHG / 100` 输出为因子涨跌幅。这是该消费的实际换算，不能反过来证明通用行情所有品种的 `PRIC_CHG` 都具有同一单位。

依据：入模 SQL 104663；消费 SQL 164723、175878、175782、175843、182738；对应源表字段元数据；TIT 字典 `WindInstrumentTradeStatus`。
