# 01 金融工具主数据

**这一篇讲清楚：TIT 怎样给金融工具建立身份，这些身份怎样进入 T02，又怎样与合约、标的和行情连接。**

## 1. 金融工具是什么

`D_REF_INSTRUMENT` 是 TIT 的金融工具基础资料表。每个工具用 `KEY_INSTRUMENT_ID` 识别，记录名称、类别、市场、币种等基本属性。

“金融工具”覆盖的对象很广：

| 对象                 | 在这张表里保存什么                       |
| ------------------ | ------------------------------- |
| 股票、基金、债券、期货、场内期权   | 市场工具的身份，如股票名称、证券代码，或某个月份的期货合约   |
| 互换、场外期权、外汇远期合约     | 合约自身在金融工具体系中的身份，简称通常可以看到合约编号    |
| 指数、货币对、浮动利率、篮子、曲线等 | 参考工具或组合对象的身份；具体报价、成分、条款在对应资料中保存 |

例如，工具 `84414` 是股票“玮俊生物科技”，代码为 `0660.HK`；工具 `100225` 是互换合约 `TRS-CCTBBWY20220002` 的工具记录。

**所以，看到“工具编号”后，先查它的类别和名称，再判断它在业务中是什么角色。**

## 2. 资料从哪里来

```text
TIT 原库 titans_dm.ref_instrument
    ↓ 采集调度：78330、78349
ODATA_N_TIT.D_REF_INSTRUMENT
    ↓ 入模
T02 通用金融工具资料 ＋ TIT 扩展资料
```

数综从 TIT 的这张表采集资料。表里的 `DATA_SOURCE` 则进一步记录工具在 TIT 内的来源标记，例如：

- `WIND`、`ICE`：可以在股票、期货、场内期权等工具中看到。
- `tradeflow`：可以在互换、期权、外汇远期等合约工具中看到。
- `product`、`Titans`、`MANUAL` 等：分别可见于票据工具、策略指数、手工维护资料等记录。

**“数综从 TIT 采集”与“这条记录的来源标记是 WIND”可以同时成立。** `WIND_CODE` 表示代码，`DATA_SOURCE` 表示来源，两个字段分别使用。

## 3. 怎样进入 T02

### 3.1 两张表分别负责什么

| 入模表 | 负责什么 | 取数原表与关联 | 调度 |
| --- | --- | --- | --- |
| `PDATA_NEWS_N.T02_SCR_BASE_INFO` | **通用身份**：统一证券编号、标准类别、名称、市场和币种 | 读取 `ODATA_N_TIT.D_REF_INSTRUMENT`，转换类别、市场和币种，匹配证券代码替换关系 | 103230、103232 |
| `PDATA_NEWS_N.T02_TIT_SCR_BASE_INFO` | **TIT 扩展资料**：在通用身份上保留源类别、子类、原始代码、到期日等属性 | 仍以 `ODATA_N_TIT.D_REF_INSTRUMENT` 为主表，再按工具内码关联通用表 | 103234、103235 |

通用表使用 `SRC_ID='TIT'`；这里讨论的扩展资料使用 `SRC_ID='TIT'、GRP_ID='01'`。

**两张表配合使用：通用表提供统一身份和标准口径，扩展表保留 TIT 的具体业务分类和属性。**

### 3.2 取数逻辑

以普通分支 103230、103234 为例：

1. **先取处理业务日的工具资料。** 原表用 `BUSI_DATE` 选取日期，没有按到期日过滤。
2. **形成通用身份。** 源内码保留为 `IN_CODE`，加 `TIT-` 前缀形成 `SRC_SYS_PRDNO`；类型、市场、币种转换为通用口径。币种查 `T02_PUB_COVT_CONST` 的 TIT／`fin00001` 规则；生成候选 `SECU_ID` 后，按证券代码、类别、市场、来源匹配 `T02_SCR_CD_RPLC_INFO`，优先采用替换编号，再按身份字段组合去重。
3. **补充 TIT 属性。** 扩展任务按 `D_REF_INSTRUMENT.KEY_INSTRUMENT_ID = T02_SCR_BASE_INFO.IN_CODE` 左关联通用表，取得统一编号、名称、标准类别等；源类别、子类、到期日等直接从原表取。

扩展任务关联通用表时只限定 `SRC_ID='TIT'`，没有再按业务日期等值关联。通用表未匹配到时，源记录仍保留，从通用表取的编号、名称等可能为空。

另有 `D_REF_INSTRUMENT_PB` 批次，调度为 144303、211515，具体补码逻辑应看对应任务；扩展表的 **02 组**来自 `D_REF_INSTRUMENT_CODE`，调度为 103236、103237，用于其他编码资料。

### 3.3 几个编号怎样对应

| 字段 | 含义 | 对应方式 |
| --- | --- | --- |
| `KEY_INSTRUMENT_ID` → `IN_CODE` | ==TIT 工具内码== | 原表 `100225` 原样进入 T02 的 `IN_CODE` |
| `SRC_SYS_PRDNO` | ==源系统产品编号== | TIT 分支按 `TIT-`＋工具内码形成，例如 `TIT-100225` |
| `SECU_ID` | ==数综统一证券编号== | 通用表生成或匹配取得；扩展表关联取得 |
| `WIND_CODE` → `WIND_CD_SRC` | 原始外部／市场代码 | 扩展表保留完整值；通用表 `SCR_CD` 取代码点号前部分，例如 `0660.HK` → `0660` |

查源工具使用 `IN_CODE`；对接源系统产品编号使用 `SRC_SYS_PRDNO`；使用数综统一证券身份时看 `SECU_ID`。

### 3.4 几种“类型”分别回答什么

| 类型字段 | 回答的问题 | 例子 |
| --- | --- | --- |
| `INS_FAMILY` → `SCR_TYPE_SRC` | TIT 把它归为什么工具？ | `TRS` 收益互换、`EQUITY` 股票、`FX_FORWARD` 外汇远期合约 |
| `INS_SUBTYPE` → `SUB_TYPE` | 这个工具还有什么子类？ | `OTCOPTION` 下可有 `VANILLA` 香草期权、`AUTOCALL` 自动赎回、`SINGLE_BARRIER` 单障碍期权 |
| `SCR_TYPE` | 数综把它归入哪个通用类别？ | `EQUITY→STK`；`TRS→OTH`；`FX_FORWARD` 按普通分支的兜底规则进入 `OTH` |

**查询“到底是什么工具”时，保留源类别 `SCR_TYPE_SRC`。** 多种源类别会归入同一个标准类别，例如仅凭 `OTH` 无法区分互换和外汇远期。

交易表的 `BUSINESS_TYPE` 还属于另一套业务分类。例如工具 `1185245` 的家族是 `FX_FORWARD`，对应交易的业务类型是 `FX_SWAP`，两个字段表达的层次不同。

## 4. 怎样关联和使用

### 4.1 合约怎样找到自己的工具记录

以互换合约为例：

```text
D_TRD_OTC_TRADE
    合约编号 KEY_OTC_TRADE_ID = 14571
    工具编号 KEY_INSTRUMENT_ID = 100225
                  ↓ 按工具编号关联
D_REF_INSTRUMENT
    KEY_INSTRUMENT_ID = 100225
    INS_FAMILY = TRS
    INS_SHT_DESC = TRS-CCTBBWY20220002
```

这就解释了 T03“合约→源产品”中的“产品”：这里关联的是合约自身的金融工具身份。任务 **105386** 从交易表取工具编号，在 `PDATA_N.T03_AGT_PRD_RELA_H` 中将 `SRC_PRD_ID` 保留为 `100225`、`PRD_ID` 拼为 `TIT-100225`；它分别对应 T02 的 `IN_CODE`、`SRC_SYS_PRDNO`。这里的关系字段写法依据入模 SQL。

`P_PRD_PRODUCT.KEY_PROD_ID` 是发行产品的另一套键，另见“03 发行产品与票据”，需要通过实际关系字段连接。

### 4.2 挂钩的股票、指数或篮子从哪里找

查询挂钩标的，要先从结构或持仓中取得标的编号，再回到金融工具主数据查名称、类别和代码。

| 想查的关系        | 取工具编号的字段                                        | 关联到哪里                                |
| ------------ | ----------------------------------------------- | ------------------------------------ |
| 合约 → 自身的工具身份 | `D_TRD_OTC_TRADE.KEY_INSTRUMENT_ID`             | `D_REF_INSTRUMENT.KEY_INSTRUMENT_ID` |
| 场外期权 → 挂钩标的  | `D_REF_OPTION_DEAL_STRUCTURE.UNDERLYING_INS_ID` | 同上；若为篮子，继续查成分关系                      |
| 普通互换持仓 → 标的  | `D_POS_TRS_LEG_HIS_POS.UNDERLYING_INS_ID`       | 同上；结合具体腿和持仓记录读取                      |
| GDR → 基础证券   | `D_REF_INSTRUMENT.BASE_UNDERLYING_INS_ID`       | 同表的工具内码；转换比例见 `TRANSFORM_PROPORTION` |

期权和互换的标的关联分别见消费任务 **86840、86841**。本表的 `BASE_UNDERLYING_INS_ID` 是 **GDR 专用字段**；期权、互换的挂钩关系使用各自结构或持仓中的标的字段。

`OTCOPTION` 和 `OTC_OPTION_CONTRACT` 也是两个独立工具类别：前者可带期权结构子类，后者可通过交易工具键查到合约身份。两类记录如何对应，仍需关系键确认。

### 4.3 下游使用这些资料做什么

| 用途 | 金融工具资料提供什么 |
| --- | --- |
| 期货、场内期权等品种属性入模 | 通过工具内码补统一证券编号，再连接品种专属属性 |
| 行情识别与分流 | 用类别和代码识别报价对象，价格和曲线数值见“02 行情与市场参数” |
| OTC、香港等系统的证券和标的资料 | 提供名称、类别、编码，用于证券资料、标的定义和报价标的等消费 |
| 合约、持仓的标的展示与分类 | 86840、86841 直接关联源工具表，补标的名称、代码及类别 |

工具主数据用于识别对象。判断合约是否存续、是否有持仓或是否准入，继续查相应的状态、持仓和配置资料。

## 附录 B：基本属性取数对照

以下为 **103234 普通分支**的主要取数。编号和类别见正文，其他属性按用途查本表。

| 属性          | 取数原字段                                             | 扩展表中的去向与处理                                         |
| ----------- | ------------------------------------------------- | -------------------------------------------------- |
| 名称与描述       | `INS_SHT_DESC`、`INS_LNG_DESC`、`DESCRIPTION`       | 先进入通用表的 `CH_ABBR`、`CH_NAME`、`CH_ABBR_L`，扩展表再关联取得   |
| 英文名         | `INS_ENG_DESC`                                    | 此分支将 `EN_NAME`、`EN_ABBR` 写空，未直接承接该源字段              |
| 市场          | `EXCH_MARKET`                                     | `SRC_MKT_CD` 保留原值；`MKT_CD`、`MKT_CH_NAME` 从通用表取标准结果 |
| 币种          | `CURRENCY`                                        | 经通用表转换为 `CRRC_CD`、`CRRC_NAME` 后关联取得                |
| 来源、发行人      | `DATA_SOURCE`、`ISSUER_ID`                         | 直接写 `DATE_SRC`、`ISSUER_ID`；发行人姓名等另查当事人资料           |
| 到期日         | `MATURITY_DATE`                                   | 转日期键后写 `DUE_DATE`                                  |
| 是否可见穿透持仓    | `IS_UNDERLYING_VISIBLE`                           | `Y→1`、`N→0`，其余写空，进入 `UNDERLYING_VISIBLE_FLAG`      |
| GDR 基础证券与比例 | `BASE_UNDERLYING_INS_ID`、`TRANSFORM_PROPORTION`   | 写 `SCR_INCD_GDR`、`TRAN_PROP_GDR`；比例的换算方向需结合转换规则    |
| 汇总与行业       | `SUMMARY_MAPPING`、`INDUSTRY_NAME`、`INDUSTRY_CODE` | 写 `UNDRL_CLAS`、`INDT_NAME`、`INDT_CD`               |
