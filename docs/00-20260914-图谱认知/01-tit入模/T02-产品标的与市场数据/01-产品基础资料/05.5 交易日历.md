# 05.5 交易日历

**交易日历回答：某个市场在某天是否交易，前一个、后一个交易日是哪天，以及这一天处于周、月、季、年的什么交易日位置。**

它让下游把自然日期转换成业务处理日期。例如公司行为落在某个自然日，相关期权事件应按哪一个交易日检查，需要先查对应日历。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_CFG_CALENDAR` | `PDATA_NEWS_N.T02_TIT_SCR_TRD_CAL` | `SRC_ID='TIT'、GRP_ID='01'` | 161255 |

源表提供 `CAL_DATE`（日期）、`EXCHANGE_CODE`（市场／日历代码）、`IS_HOLIDAY`（节假日标志）。入模读取处理业务日 `BUSI_DATE` 分区里的日历记录，按市场和日期进一步生成交易日关系。

**`BUSI_DATE` 是本次资料的处理日期，`CAL_DATE` 才是这条日历描述的日期。** 一个处理日分区中可以带有其他日期的日历资料，不能把两个日期混为一谈。

## 2. 标志和市场代码怎么看

| 来源 | 入模结果 | 含义 |
| --- | --- | --- |
| `IS_HOLIDAY='N'` | `TRD_FLAG='1'` | 交易日 |
| `IS_HOLIDAY='Y'` | `TRD_FLAG='0'` | 非交易日 |
| `EXCHANGE_CODE` | `MKT_CD` | 源市场／日历代码，原样保留 |
| `CAL_DATE` | `CAL_DATE` | 转为 `yyyyMMdd` 日期键 |

市场名称 `MKT_CH_NAME` 在已查 SQL 中按代码逐项写明，字典关联语句被注释，当前取数并未实际连接字典。

| 本任务使用的代码举例 | 名称／用途 |
| --- | --- |
| `SSE`、`SZSE` | 上交所、深交所日历 |
| `HKEX` | 香港交易所日历 |
| `CFFEX`、`SHFE`、`DCE`、`CZCE` | 相应期货交易所日历 |
| `NATURE` | 消费中作为自然日历使用 |

因此 `MKT_CD` 应连同日期一起读，不能只按日期查询后任选一条，也不能把这里的 TIT 市场代码直接当作其他模型的标准市场码。

## 3. 入模还补出了哪些信息

| 入模字段 | 能回答什么 |
| --- | --- |
| `PREV_TRD_DATE`、`NEXT_TRD_DATE` | 该日期之前、之后的交易日 |
| `WK_STRT_TRD_DATE`、`WK_END_TRD_DATE` | 所在周的首末交易日 |
| `MTH_STRT_TRD_DATE`、`MTH_END_TRD_DATE` | 所在月的首末交易日 |
| `QTR_STRT_TRD_DATE`、`QTR_END_TRD_DATE` | 所在季度的首末交易日 |
| `YEAR_STRT_TRD_DATE`、`YEAR_END_TRD_DATE` | 所在年的首末交易日 |
| `WK_TRD_DATE_NO`、`MTH_TRD_DATE_NO`、`QTR_TRD_DATE_NO`、`YEAR_TRD_DATE_NO` | 该交易日在周、月、季、年内排第几个 |

取数逻辑可以概括为：**先按市场区分交易日与非交易日，再按日期顺序确定前后交易日和各期间首末交易日。** 非交易日的前后交易日从前后 15 天范围内匹配；源日历边界不足时，相应字段可能取不到。期间交易日序号仅对交易日赋值。

中间临时表服务于这一步日历计算，业务阅读直接看最终日历表即可。

## 4. 实际用在哪里

消费 **181555** 检查期权公司行为处理时点时：

1. 读取 `MKT_CD='NATURE'` 的自然日历。
2. 读取 `MKT_CD='SSE'、TRD_FLAG='1'` 的交易日，建立前后交易日关系。
3. 将自然日期匹配到不早于该日的首个上交所交易日。
4. 结合证券公司行为、挂钩期权和相关事件处理时间，形成异常监控指标。

这条已查消费体现的是具体的上交所日历口径。其它业务选择哪个市场日历，要看对应消费或合约规则。

日历消费图还记录了延迟簿记、延迟平仓、结算处理等监控任务；共同作用是提供“业务上应该按哪天判断”的日期参照。
