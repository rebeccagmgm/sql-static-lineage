# 02.2 场内期权

**场内期权属性把“这是一份期权”进一步说清楚：挂钩什么、看涨还是看跌、行权价多少、合约单位多大，以及什么时候能够交易和行权。**

读取时先区分两个对象：**期权自身**有一个工具编号，**它的标的**还有另一个工具编号。两者分别连接金融工具主数据。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.R_REF_LISTED_OPTION_PROPS` | `PDATA_NEWS_N.T02_OPT_BASE_INFO_TIT` | `SRC_ID='TIT'、GRP_ID='01'` | 176204 |

这条链承接场内期权的合约属性。场外期权的结构条款与子交易关系，继续在 T03 合约资料中阅读。

## 2. 取数逻辑

1. 从原表取处理业务日 `BUSI_DATE` 的属性记录。
2. 按 **`KEY_INSTRUMENT_ID = T02_SCR_BASE_INFO.IN_CODE`** 左关联 TIT 通用身份，给期权自身补 `SECU_ID` 和 `SRC_SYS_PRDNO`。
3. 合约代码、行权价、合约单位、看涨看跌及行权方式主要直接承接；部分交易、行权和交割日期转成日期键。

**未匹配到统一证券编号的源属性仍保留。** 此任务没有附加“可交易标志为真”或“尚未到期”的过滤，也没有在入模时计算期权价格。

## 3. 主要属性怎么读

| 业务问题 | 取数原字段 | 入模字段 |
| --- | --- | --- |
| 期权自身是哪一个工具 | `KEY_INSTRUMENT_ID` | `SCR_IN_CODE`；另从通用表补 `SECU_ID`、`SRC_SYS_PRDNO` |
| 挂钩哪个标的 | `UNDERLYING_INS_ID` | `UNDRL_SCR_IN_CODE` |
| 用什么代码、名称识别合约 | `OPTION_CODE_FOR_TRADE`、`OPTION_NAME_FOR_TRADE` | `COMP_CD`、`COMP_NAME_WD` |
| 交易所内的代码和简称 | `OPTION_CODE_IN_EXCH`、`OPTION_NAME_IN_EXCH` | `COMP_TRD_CD`、`COMP_ABBR` |
| 一份合约对应多大单位 | `CONTRACT_MULTIPLIER` | `COMP_UNIT` |
| 看涨还是看跌 | `CALLPUT` | `COMP_TYPE`，保留源代码 |
| 按什么价格行权 | `STRIKE_PRICE` | `EXER_PRIC` |
| 何时、按什么方式行权 | `EXERCISE_TYPE` | `EXER_WAY`，保留源值 |
| 到期日和交割月份 | `MATURITY_DATE`、`DELIVERY_MONTH` | `MATY_DATE`、`DELI_MON` |
| 交易日期范围 | `FIRST_TRADING_DATE`、`LAST_TRADING_DATE` | 转日期键后写 `STRT_TRD_DATE`、`LAST_TRD_DATE` |
| 最后行权和交割日 | `LAST_EXERCISABLE_DATE`、`LAST_DELIVERY_DATE` | 转日期键后写 `LAST_EXER_DATE`、`LAST_DELI_DATE` |
| 挂牌时的基准价、最小报价单位 | `LISTED_PRICE`、`MINPRICEFLUCT` | `LIST_BM_PRIC`、`MIN_OFFER_UNIT` |
| 可交易、是否调整 | `TRADABLE`、`ADJ_SIGN` | `TRD_FLAG`、`ADJ_FLAG`，直接承接 |

最后交易日、最后行权日和最后交割日分别描述三个业务时点，查询时按所需业务含义选择。`LIST_BM_PRIC` 是挂牌基准价，当日市场价格另查行情。

### 看涨看跌代码

源字典 `D_CFG_DICTIONARY_DESC.CallPut`（业务日期 `2026-09-14`）包括：

| 代码 | 含义 |
| --- | --- |
| `CALL` | 看涨 |
| `PUT` | 看跌 |
| `ANY` | 任意 |

字典包含 `ANY`，只说明这个代码在源字典中的定义，不能据此断言所有代码都会出现在场内期权合约属性中。入模没有重新转换 `CALLPUT`、`EXERCISE_TYPE` 或标志字段。

## 4. 期权自身与标的怎么连接

```text
R_REF_LISTED_OPTION_PROPS
    KEY_INSTRUMENT_ID ─→ 期权自身的工具记录
    UNDERLYING_INS_ID ─→ 标的工具记录，例如股票、ETF 或指数

两种编号分别关联 D_REF_INSTRUMENT.KEY_INSTRUMENT_ID
在 T02 内查原始编号，则分别关联 IN_CODE
```

入模只给期权自身补通用身份，同时保留标的内码。下游再用 `UNDRL_SCR_IN_CODE` 查询标的名称和外部代码。

## 5. 下游实际怎么用

| 消费方与目标 | 具体使用 | 调度 |
| --- | --- | --- |
| 风控 `DM_RSK_N.TRD_OPT_BASE_INFO_DAY` | 取行权方式、看涨看跌、行权价、合约单位、日期，再补期权及标的名称、WIND 代码和币种 | 176983 |
| 香港 `DM_HK_N.FDM_INFO_TIT_OPT_BASE` | 接收 TIT／01 的场内期权基础属性，包括标的内码、行权参数、日期和标志 | 195090 |

风控消费有两个具体口径：

- **期权自身需匹配到 TIT 工具资料的 01 组和 WIND 编码的 02 组**，这两处使用内关联，因此进入属性模型不代表一定进入该风控输出。标的名称、标的代码通过左关联补充。
- 输出的结算类型固定为 **`Cash`**。这是该消费任务的写法，不是源属性表对每份合约实际结算方式的证明。

日行情另经共用行情表，由任务 175878 输出风控 `TRD_OPT_MKT_QUOT_DAY`，在行情章节继续阅读。
