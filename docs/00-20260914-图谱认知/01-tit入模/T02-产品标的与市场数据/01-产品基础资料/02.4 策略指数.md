# 02.4 策略指数

初次接触指数、期货和换月，可以先读 [02.4.1 策略指数基础知识讲解](00-20260914-图谱认知/01-tit入模/T02-产品标的与市场数据/01-产品基础资料/02.4.1%20策略指数基础知识讲解.md)，再看本篇的数据与入模说明。

**策略指数维护资料说明：一个策略指数关联哪个子标的，采用什么初始基准，保存哪些数量、版本和业务日期。**

主数据中的 `QIS` 表示策略指数的工具身份。这里继续描述策略与子标的的维护信息，读取时需要同时保留两边的编号。

## 1. 从哪里取，进入哪张表

| 取数原表                               | 入模表                                  | 来源范围                       | 调度     |
| ---------------------------------- | ------------------------------------ | -------------------------- | ------ |
| `ODATA_N_TIT.D_REF_STRATEGY_INDEX` | `PDATA_NEWS_N.T02_IDX_STRG_MATN_TIT` | `SRC_ID='TIT'、GRP_ID='01'` | 219012 |

## 2. 一条记录怎样理解

把记录分成三组信息来看：

| 信息组  | 主要字段                                   | 表示什么             |
| ---- | -------------------------------------- | ---------------- |
| 策略自身 | `KEY_INSTRUMENT_ID`、策略名称、策略代码、策略币种     | 被维护的是哪个策略指数      |
| 子标的  | `KEY_UNDERLYING_INS_ID`、标的名称、标的代码、标的币种 | 这条记录关联哪个工具       |
| 维护内容 | 初始价格、初始点位、初始日期、数量、版本、源业务日期             | 按什么基准和版本理解这条维护信息 |

**一条记录可以按“某个策略、某个源业务日、某个版本下的一项子标的配置”理解。** 同一个版本可以有多个子标的，同一个业务日也可以保存多个版本。入模逐行承接来源记录，没有在这里聚合所有子标的或选择“最新版本”。

### 2.1 GFIC 的记录具体在维护什么

`GFIC` 的策略工具内码是 **`125605`**。它关联的子标的包括不同月份的 IC 合约，例如 `IC2411.CFE`（子标的内码 `1508622`）和 `IC2412.CFE`（子标的内码 `446003`）。

把日期、版本和两个子标的的数量放在一起，就能看出配置变化。下表直接使用 `VALID_NUM`：

| 源业务日 `SRC_BUSI_DATE` | 版本 `VERSION_NO` | `IC2411.CFE` 数量 | `IC2412.CFE` 数量 |
| --- | --- | ---: | ---: |
| 2024-10-31 | 15127 | 3.4000435705 | — |
| 2024-11-01 | 15170 | 2.2666957137 | 1.1372778749 |
| 2024-11-04 | 15226 | 1.1333478568 | 2.2746359212 |
| 2024-11-05 | 15274 | 0 | 3.4118675694 |

“—”表示该版本的导出记录中未见对应条目。

**旧月份合约的配置数量逐步减少，新月份合约的数量增加，最后旧合约归零。从记录变化看，这符合期货换月的表现。** 因而可以把这些 GFIC 记录理解为策略中期货合约的配置及其变化。

这些数量描述策略内部的配置，来源没有说明数量单位，不能直接等同于账户实际持仓手数或已成交数量。旧合约数量为零时条目仍会保留，查看某版配置时要同时读数量。

### 2.2 版本表示什么，同一天为什么不能直接合计

同一个源业务日可能出现不同配置。例如 GFIC 在 **2024-05-06** 的两组记录：

| 版本 | `IC2405.CFE` 数量 | `IC2406.CFE` 数量 | 配置表现 |
| --- | ---: | ---: | --- |
| 10342 | 3.300023763 | — | 该版记录中只有五月合约 |
| 10423 | 2.200015842 | 1.104547212 | 该版同时配置五月、六月合约 |

这说明 `VERSION_NO` 能区分**同一业务日不同的维护版本**。版本之间可能发生子标的、数量或参考基准的变化，不能把它们当成同一份组合的独立成分相加。

查询某版组成时，应按 **策略 → 源业务日 → 版本 → 该版本下全部子标的** 读取。选定版本之后要保留整组子标的；具体哪个版本已发布或生效，仍需源端的版本规则确认。

### 2.3 当前数量与有效数量有什么区别

GFIC 的两列数量大多相同；出现差异的记录与精度处理一致。例如：

| 字段 | 2024-10-31／版本 15127／`IC2411.CFE` 的值 |
| --- | --- |
| `CURRENT_NUM` | `3.4000435705296788` |
| `VALID_NUM` | `3.4000435705` |

**所给 GFIC 记录的 `VALID_NUM` 均与 `CURRENT_NUM` 四舍五入保留十位小数相符。** 在理解这些记录时，可以先按同一配置数量的不同精度表达阅读；是否在所有策略中都采用这条生成规则，仍需源头加工逻辑确认。

两列都会出现小数和零。单凭“有效数量”的名称，不能推导出它是扣除冻结、无效仓位后的数量；当前数据没有提供这种计算依据。

### 2.4 初始价格、初始点位和初始日期具体指什么

GFIC 在 **2024-11-01／版本 15170** 中有两项子标的：

| 子标的 | `INIT_DATE` | `INIT_PRICE` | `INIT_SITE` |
| --- | --- | ---: | ---: |
| `IC2411.CFE` | 2024-10-31 | 5903.4 | 5903.4 |
| `IC2412.CFE` | 2024-10-31 | 5883 | 5883 |

同一个策略、同一天、同一版本，两个子标的的数值不同。**这组字段随子标的记录保存，宜按该项配置采用的参考日期、价格和点位理解，不能把 `INIT_SITE` 直接读成整条 GFIC 指数统一的当日点位。**

GFIC 记录中 `INIT_PRICE` 与 `INIT_SITE` 相等，但数值会随日期或版本更新。`INIT_DATE` 也会更新，并非固定的策略成立日；数据中既有早于源业务日的日期，也有与源业务日相同的日期。具体参考价格来自收盘价、结算价还是其他定价，需要再查生成逻辑。

## 3. 取数逻辑

1. 从原表取处理业务日 `BUSI_DATE` 的记录。
2. 按策略 `KEY_INSTRUMENT_ID` 关联 TIT 通用工具资料，取得策略的 `SECU_ID`；`SRC_SYS_PRDNO` 直接按 `TIT-`＋策略内码生成。
3. 按子标的 `KEY_UNDERLYING_INS_ID` 再关联一次通用工具资料，取得标的 `UNDRL_SECU_ID`。
4. 策略币种与标的币种分别关联 TIT 转换表取得模型币种代码；其他维护内容主要承接原值，日期转换格式。

两次工具身份关联都使用左关联，没有因统一编号为空而剔除原记录。币种关联在该任务中只限定 `SRC_ID='TIT'` 并匹配源币种，没有另限定转换类型。

## 4. 主要字段怎样对应

| 内容 | 取数原字段 | 入模字段 |
| --- | --- | --- |
| 策略工具内码 | `KEY_INSTRUMENT_ID` | `STRG_IDX_IN_CODE`；对应统一编号 `SECU_ID` |
| 策略代码 | `WIND_CODE` | `WIND_STRG_IDX_CD` |
| 策略名称 | `STRATEGY_SHT_NAME`、`STRATEGY_LNG_NAME` | `STRG_ABBR`、`STRG_FULL_NAME` |
| 策略币种 | `STRATEGY_CURRENCY` | 转换后写 `STRG_CRRC_CD` |
| 子标的工具内码 | `KEY_UNDERLYING_INS_ID` | `UNDRL_IN_CODE`；对应统一编号 `UNDRL_SECU_ID` |
| 标的名称、代码 | `STOCK_SHT_NAME`、`UNDERLYING_WIND_CODE` | `UNDRL_ABBR`、`UNDRL_WIND_CD` |
| 标的币种 | `STOCK_CURRENCY` | 转换后写 `UNDRL_CRRC_CD` |
| 初始基准 | `INIT_PRICE`、`INIT_SITE`、`INIT_DATE` | `INIT_PRIC`、`INIT_LOC`、`INIT_DT` |
| 数量信息 | `CURRENT_NUM`、`VALID_NUM` | `CURR_NUM`、`VLD_NUM` |
| 版本和源业务日 | `VERSION_NO`、`SRC_BUSI_DATE` | `VER_NO`、`SRC_BUSI_DATE` |

源元数据把 `STRATEGY_CURRENCY`、`STOCK_CURRENCY` 注释为“汇率”，但实际 SQL 用它们匹配币种代码。**这里按策略币种、标的币种理解，没有进行汇率换算。**

`CURRENT_NUM`、`VALID_NUM` 的实际表现见第 2.3 节。任务 219012 直接承接这些数量，不在入模时计算配置比例、换月数量或指数收益。

## 5. 怎样与金融工具主数据连接

```text
策略工具 KEY_INSTRUMENT_ID
    └─→ T02_SCR_BASE_INFO.IN_CODE → 策略 SECU_ID

子标的 KEY_UNDERLYING_INS_ID
    └─→ T02_SCR_BASE_INFO.IN_CODE → 标的 UNDRL_SECU_ID

两边在同一条维护记录中，通过初始基准、数量、版本和日期联系起来
```

“策略指数自身的身份”与“它关联的子标的身份”因此可以分别查询。后续若要了解更完整的组成和计算规则，再沿策略定义或组成资料继续查。

## 6. 这份资料能回答什么

- 查一个策略关联的子标的，以及两边的名称、代码、币种。
- 查初始化基准和维护版本，结合源业务日期理解记录。
- 为后续消费提供策略与标的的对应和维护参数。

GFIC 的记录进一步说明，这些维护信息能够表达 **不同版本下的期货配置及换月变化**。尚需源头规则补充的是：数量如何算出、参考价格从哪里取、哪个版本正式生效，以及怎样据此计算指数点位和收益。

**现有消费索引尚未确认这张表的明确下游业务读取。** 换月配置的变化由本篇记录支持，实际成交执行和指数计算仍需对应业务链的证据。
