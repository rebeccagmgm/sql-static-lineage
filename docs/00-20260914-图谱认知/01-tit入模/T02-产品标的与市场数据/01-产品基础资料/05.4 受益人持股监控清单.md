# 05.4 受益人持股监控清单

**这份资料维护“哪些标的需要监控受益人持股比例”。实际比例由下游结合合约规模、交易对手受益人关系和股东资料计算。**

目标表名中虽然有“持股比例”，但本次入模字段只有监控工具身份、名称、代码和创建信息。先把它理解成监控标的清单，就能看清它在业务链里的作用。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.R_CFG_INS_BE_SHARE_PROPORTION` | `PDATA_NEWS_N.T02_TIT_STK_BENE_OWSR_PROP` | `SRC_ID='TIT'、GRP_ID='01'` | 208603 |

源表元数据名称是“受益人持股比例监控标的”。取处理业务日 `BUSI_DATE` 的记录，逐项补充证券身份与代码。

## 2. 清单里具体有什么

| 来源／关联 | 入模字段 | 表示什么 |
| --- | --- | --- |
| `KEY_INSTRUMENT_ID` | `REC_ID`、`SRC_REC_ID` | 被监控的 TIT 工具内码 |
| 按内码关联 `T02_SCR_BASE_INFO`，限定 TIT | `SECU_ID`、`SRC_SYS_PRDNO`、`CH_ABBR` | 统一编号、源系统产品编号、简称 |
| 按内码关联 `T02_TIT_SCR_BASE_INFO`，限定 TIT／02／WIND | `UPPER_SRC_CD` | WIND 体系下的大写代码 |
| `CREATED_DATETIME`、`CREATED_BY` | `CREATE_DT`、`CREATE_BY` | 该配置的创建时间和创建人 |

两次身份／编码关联都是左关联。清单入模没有计算受益人是谁、持有多少股、比例是多少，也没有据此判断是否超限。

## 3. 下游怎样算出比例

消费 **208230** 输出 `DM_OTC_N.BENE_OWNER_HOLD_PROP_EXCD_PCT3_DAY`，主要经过以下业务步骤：

1. **圈定工具**：以本清单的 WIND 代码匹配需要监控的标的。
2. **找到挂钩合约**：取存续的安全气囊 X 或收益互换合约，以及合约的动态名义本金。
3. **穿透交易对手**：结合 T01 的受益所有人／持有人信息及持有比例，把相关场外规模归到受益人／持有人。
4. **折成持股比例**：将穿透后的场外规模按标的总市值折算成比例。
5. **叠加场内部分**：匹配上季度末前十大股东中同名股东的持股比例，再输出合计超过 `3%` 的记录。

```text
本表：哪些工具需要监控
    ↓
合约与动态名义本金 ＋ 交易对手受益人／持有人比例
    ↓
场外穿透规模 ÷ 标的总市值
    ＋ 匹配的场内前十大股东持股比例
    ↓
超过 3% 的监控结果
```

这里的 `3%` 是该消费 SQL 的筛选条件。还要注意，前十大股东部分采用名称匹配并使用内关联；没有匹配到这份股东资料的受益人，不会作为“场内比例为零”自然保留。因此应把结果理解为**这项查询范围内的监控输出**。

## 4. 查什么到哪里找

| 想查什么 | 查哪里 |
| --- | --- |
| 某标的是否被纳入监控 | 源配置或 `T02_TIT_STK_BENE_OWSR_PROP` |
| 某受益人的合计比例和相关交易对手 | `DM_OTC_N.BENE_OWNER_HOLD_PROP_EXCD_PCT3_DAY` |
| 比例为什么变化 | 继续核对合约规模、受益人关系、标的市值和所用股东报告期 |
