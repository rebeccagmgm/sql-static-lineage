# 05.6 公司行为

**公司行为资料记录证券发生的分红、送股、转增、配股、拆分等事件，以及登记、除权除息、支付日期和相关比例。**

对挂钩这些证券的场外合约，下游需要知道事件是否落在合约期间、是否需要处理及何时完成处理。本表提供事件事实与参数，合约处理记录再从 T05 等事件资料连接。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_REF_CORPORATE_ACTION_INFO` | `PDATA_NEWS_N.T02_CO_BEHAV_INFO` | `SRC_ID='TIT'、GRP_ID='01'` | 188381 |

取处理业务日 `BUSI_DATE` 的来源事件。按 TIT 工具内码补证券身份，再用统一证券编号连接 WD 证券资料补企业编号；事件日期、比例和描述随记录保存。

## 2. 一项事件怎样识别

| 取数原字段／关联 → 入模字段 | 表示什么 |
| --- | --- |
| `KEY_CA_ID` → `CO_BEHAV_ID` | 公司行为 ID |
| `KEY_INSTRUMENT_ID` → 关联取得 `SECU_ID`、`SRC_SYS_PRDNO` | 事件发生在哪个证券上 |
| TIT 证券身份再关联 WD 证券资料 → `CORP_ID` | 补充统一企业编号 |
| `CA_TYPE`、`CA_SUBTYPE` → `CO_BEHAV_WAY`、`CO_BEHAV_TYPE` | 公司行为方式与子类型，经转换表映射 |
| `CA_TYPE_NAME` → `CO_BEHAV_TYPE_NAME` | 来源提供的类型名称 |
| `OBJECT_ID` → `OBJ_ID` | 来源对象 ID |
| `PROGRESS`、`PROGRESS_DESC` → `SCHM_PROG`、`SCHM_PROG_DESC` | 方案进度代码及说明 |
| `EXPIRE_DATE` → `INVLD_DATE` | 来源失效日期 |
| `DATA_SOURCE` → `DATA_SRC` | 源事件记录携带的数据来源 |

一只证券可以有多项事件。目标记录编号还综合公司行为 ID、方式、子类型、类型名称和对象 ID 生成，不能只按证券编号把事件合并成一条。

入模没有按方案进度或失效日期筛选为“只保留已实施事件”；实际采用哪项事件，要结合进度、日期和下游条件。

## 3. 哪些日期与比例最关键

| 内容 | 取数原字段 → 入模字段 | 怎么读 |
| --- | --- | --- |
| 权益登记 | `RECORD_DATE` → `REG_DATE` | 股票股权登记日、基金权益登记日 |
| 除权除息 | `EX_DATE` → `EX_DVD_DATE` | 股票除权除息日、基金除息日 |
| 支付／上市 | `PAYMENT_DATE` → `CASH_DISTR_DATE` | 派息或红股上市等支付日期 |
| 公告与预案 | `DECLARED_DATE`、`PRE_PLAN_DATE`、`PRE_PLAN_ANN_DATE` → `DIVD_IMPL_NTCE_DATE`、`NTCE_DATE`、`PLAN_DISC_NTCE_DATE` | 实施公告、预案公告、预披露日期 |
| 基准与报告期 | `BASE_DATE`、`REPORT_PERIOD` → `BM_DATE`、`DIVD_ANUL` | 对应股本／份额基准及分红年度等来源信息 |
| 现金派息 | `CASH_RATIO` → `CASH_DISTR_PROP` | 源定义为税前派息比例分子／分母，直接承接 |
| 送股、转增 | `BONUS_RATIO`、`CONVERSED_RATIO` → `STK_DIVD_PROP`、`CPTLZ_PROP` | 相应比例 |
| 配股 | `RIGHTSISSUE_RATIO`、`RIGHTSISSUE_PRICE` → `RIGH_SHR_PROP`、`RIGH_SHR_PRIC` | 配股比例及价格 |
| 实物和认股权证派送 | `IN_SPECIE_RATIO`、`BONUS_WARRANT_RATIO` → `ENTY_DISTR`、`DIVD_WARR_DISTR_PROP` | 相应派送比例 |
| 拆分 | `SPLITINC` → `SPLIT_PROP` | 拆分折算比例 |
| 适用对象与基数 | `CA_OBJECT`、`BASE_SHARE` → `DIVD_OBJ`、`BM_EQUI_SHR` | 分红对象、基准股本／基金份额 |

**比例在源表中已经给出，入模没有按持仓重算应收分红，也没有调整合约期初价格。** 这些属于持仓或合约事件的后续处理。

源注释说基金派息日为空时取除息日，但当前 SQL 只转换 `PAYMENT_DATE`，未在入模补用 `EX_DATE`。因此若看到派息日缺失，要回查源值，不能预设本任务已做兜底。

## 4. 类型和进度怎么转换

| 源字段 | 转换表来源范围 | 转换类型 | 入模字段 |
| --- | --- | --- | --- |
| `CA_TYPE` | `SRC_ID='TIT'` | `var00609` | `CO_BEHAV_WAY` |
| `CA_SUBTYPE` | `SRC_ID='TIT'` | `var00610` | `CO_BEHAV_TYPE` |
| `CURRENCY_CODE` | `SRC_ID='TIT'` | `fin00001` | `CRRC_CD` |
| `PROGRESS` | **`SRC_ID='WD'`** | `evt00001` | `SCHM_PROG` |

转换表均为 `PDATA_NEWS_N.T02_PUB_COVT_CONST`。注意方案进度用 WD 范围的转换规则，不能把整组转换一概写成 TIT。

已查消费还会把行为方式和子类型按原转换类型反查为源码。其中明确使用 `STOCK_DIV`（送股）、`DIVIDEND`（派息）两个子类型；这是该监控的选取范围，并非本表完整公司行为字典。

## 5. 实际用在哪里

消费 **181555** 写入 `DM_RSK_N.OTC_DERI_SETT_ABN_MONTR_INDX`，用于检查相关期权合约的公司行为处理时点：

1. 从本表取得发生事件的证券、除权除息日与行为子类型。
2. 按工具编号连接 `T03_OTC_OPT_COMP_STRU_ELMN_INFO` 的挂钩标的，找出相关期权合约；该分支排除 `AIRBAGX`，并继续应用合约状态、日期等条件。
3. 用自然日历与上交所交易日历确定检查日期。
4. 查 T05 的公司行为、现金分红返还等合约事件及处理时间，判断是否按该任务规则完成处理。

这条链把 **证券事件 → 挂钩合约 → 合约处理事件** 连起来。T02 记录发生了什么公司行为，具体合约是否已经调整要到合约事件中确认。
