# 05.3 标的池与白名单

**标的池属性描述工具在池里的业务配置；白名单进一步保存工具与业务方案、交易对手、标的池及保证金参数的对应。**

前者重点是“这个标的怎样分类、报价和报备”，后者重点是“在什么方案和交易对手上下文中，配置了什么标的和保证金条件”。

## 1. 从哪里取，进入哪张表

| 资料 | 实际读取原表与范围 | 入模表与范围 | 调度 |
| --- | --- | --- | --- |
| 标的池属性 | `ODATA_N_TIT.R_CFG_INSTRUMENT_POOL_PROPS`；处理业务日 | `PDATA_NEWS_N.T02_FIN_UNDRL_ATTR`；TIT／01 | 158210 |
| 标的池批次属性 | `ODATA_N_TIT.R_CFG_INSTRUMENT_POOL_PROPS_PB`；处理业务日，`GRP_ID='exchange_titans_to_sps'` | 同上，仍写 TIT／01 | 158292 |
| 白名单 | `ODATA_N_TIT.D_REF_INSTRUMENT_POOL_WHITELIST`；处理业务日 | `PDATA_NEWS_N.T02_TIT_WI_UNDRL_POOL`；TIT／01 | 171427 |
| 白名单 1230h 批次 | `ODATA_N_TIT.D_REF_INSTRUMENT_POOL_WHITELIST_P`；`BUSI_DATE='h1230'` | `PDATA_NEWS_N.T02_TIT_WI_UNDRL_POOL_PB`；TIT／01，`TIME_FLAG='1230h'` | 221125 |

这里按 SQL 的 `FROM` 写实际来源。158292 的 `SRC_TBL` 仍写普通属性表名；221125 的 `SRC_TBL` 写 `_B`，但实际读取 `_P`。查原始记录时使用上表实际来源和分区。

## 2. 标的池属性具体配置什么

| 配置组 | 取数原字段 → 入模字段 | 业务含义 |
| --- | --- | --- |
| 工具身份 | `KEY_INSTRUMENT_ID` → 关联取得 `SECU_ID`，拼接 `SRC_SYS_PRDNO` | 配置针对哪个工具 |
| 标的池 | `KEY_POOL_ID` → `UNDRL_POOL_CODE` | 这项配置属于哪个池 |
| 报价身份 | `INTEROTC_CODE`、`INTEROTC_NAME` → `OFFR_SYS_CD`、`OFFR_SYS_NAME` | 报价系统使用的代码和名称 |
| 报价分类 | `INTEROTC_UNDERLYING_TYPE`、`INTEROTC_UNDERLYING_CATEGORY` → `UNDRL_TYPE`、`UNDRL_MINOR_CATE` | 报价系统的大类、小类 |
| 交易与报备 | `TRADING_PLACE`、`REPORT_TO` → `UNDRL_DEAL_SITE`、`RGST_SITE` | 交易场所与报备场所 |
| 价格参考 | `PRICE_EXCHANGE`、`PRICE_PUBLISH_ORGAN`、`PRICE_WEBSITE` → `EXCH`、`CLOS_PRIC_OF_PUB_ORG`、`CLOS_PRIC_OF_REF_WEB` | 收盘价参考的交易所、公布机构和网页；这些字段不含实际收盘价 |
| OTC 分类 | `OTC_UNDERLYING_TYPE` → `OTC_UNDRL_TYPE` | 经 TIT 转换类型 `var00575` 映射后的标准码 |
| 保证金参数 | `L`、`H` → `BAIL_L_PARA`、`BAIL_H_PARA` | 来源配置的 L、H 参数，入模不计算保证金金额 |
| 风险等级与日期 | `RISK_LEVEL`、`LAST_TRADE_DATE` → `SCR_RISK_LVL`、`LAST_DEAL_DAY` | 证券风险等级、最后交易日 |

入模按工具内码左关联 TIT 主数据，其他配置主要承接源值。读取时同时保留工具和标的池；目标 `REC_ID` 虽只按工具键生成，也不能据此忽略来源的池维度。

### 报价分类与 OTC 分类分别是什么

本地字典 **`InterotcUnderlyingType`**（业务日期 `2026-09-14`）解释报价大类：

| 源码 | 含义 | 源码 | 含义 |
| --- | --- | --- | --- |
| `EQUITY_INTEREST` | 权益类 | `BULK_COMMODITY` | 大宗商品 |
| `EXCHANGE_RATE` | 汇率 | `INTEREST_RATE` | 利率 |
| `CREDIT` | 信用类 | `OTHER_TYPE` | 其他 |

OTC 分类是另一列。消费 158671 将 `var00575` 标准码反查为源码，再解释为：`EQUITY` 个股、`FUND` 基金、`INDEX` 指数、`BULK_COMMODITY` 大宗商品、`PRECIOUS_METALS` 贵金属、`OTHER` 其他（包括境外）。这些是该消费明确处理的源码，不能拿报价大类字典直接解释 `OTC_UNDRL_TYPE`。

## 3. 白名单为什么要带方案和交易对手

| 取数原字段 → 入模字段 | 表示什么 |
| --- | --- |
| `KEY_INSTRUMENT_ID` → 关联取得 `SECU_ID`、`SRC_SYS_PRDNO` | 被配置的工具 |
| `KEY_PLAN_ID` → `BUSI_SCHM_ID` | 业务方案 |
| `KEY_CTYPTY_ID` → `DEAL_CUTP_ID` | 交易对手，直接保留源编号 |
| `INSTANCE_ID` → `INSTC_ID` | 方案相关实例 |
| `KEY_POOL_ID` → `UNDRL_POOL_ID` | 标的池 |
| `INITIAL_MARGIN` → `BEG_BAIL_LINE` | 初保线 |
| `MARGIN_CALL_FLOOR` → `SUPP_BAIL_KEEP_LINE` | 追保维持线 |
| `BASIC_MARGIN` → `BASE_BAIL_RATE` | 基础保证金率 |
| `SRC_BUSI_DATE` → `SRC_BUSI_DATE` | 来源业务日期，转换为日期键 |

方案与工具共同参与来源记录编号的拼接，交易对手、实例和池也一并保存。**因此理解这份名单时，要问“哪个方案／交易对手下的标的配置”，不能把所有记录抽成一个没有上下文的通用准入集合。**

白名单入模仅关联工具主数据，没有把 `KEY_CTYPTY_ID` 转换成 T01 当事人统一编号。与当事人模型对接时还需核对源编号对应关系。

三个保证金字段分别承接来源数值，当前 SQL 不校验准入、不比较触线、不计算应收保证金。各字段比例单位和源端生成规则，应结合方案定义读取。

## 4. 实际用在哪里

### 标的查询页面：158671

`DM_OTC_N.OPTION_SUBJECT_VIEW` 只取 **`UNDRL_POOL_CODE='10000'`**，按 `SRC_SYS_PRDNO` 与 TIT／01 工具资料连接，输出名称、代码、报价分类和报备场所。不是所有池都会进入这个页面结果。

该消费的报备转换为：

| 源 `REPORT_TO` | 输出值 | 含义 |
| --- | --- | --- |
| `TO_SSE` | `1` | 上交所 |
| `TO_SZSE` | `2` | 深交所 |
| `TO_SSE_SZSE` | `3` | 上交所和深交所 |
| `NO_REPORT` | `0` | 不报备 |

### 配置分发：159250

`DM_OTC_N.CFG_INSTRUMENT_POOL_PROPS_TD` 保留池编号、报价分类和报备配置，并把 OTC 标准分类反查回源代码；该查询没有限定只取池 `10000`。

白名单普通表及批次表在现有发布图中均未检出明确直接消费。当前可确认它们保存了哪些准入相关配置，尚不能据此指定最终执行准入或保证金校验的系统。

依据：入模 SQL 158210、158292、171427、221125；消费 SQL 158671、159250；源字段元数据。报价分类见 [TIT 源字典](../../../../../../数综基础信息/原信息/关键表信息/D_CFG_DICTIONARY_DESC_合并_中英文字段.csv) 的 `InterotcUnderlyingType`；[标的池消费图谱](../消费核对/投影-t02_fin_undrl_attr.json)。
