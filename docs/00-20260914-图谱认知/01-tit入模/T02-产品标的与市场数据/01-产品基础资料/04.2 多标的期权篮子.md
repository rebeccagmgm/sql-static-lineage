# 04.2 多标的期权篮子

**一份期权可以关联一个由多项标的组成的篮子。本表把“哪份合约、哪个篮子、哪项成分、什么权重”放在同一条记录中。**

理解记录时，要区分合约自身的工具编号、篮子编号和成分标的编号。它们分别代表关系中的不同对象。

## 1. 从哪里取，进入哪张表

| 取数原表 | 入模表 | 来源范围 | 调度 |
| --- | --- | --- | --- |
| `ODATA_N_TIT.D_V_RISK_OPTION_BASKET_INFO` | `PDATA_NEWS_N.T02_OPT_MULT_BASK_INFO` | `SRC_ID='TIT'、GRP_ID='01'` | 104478、104481 |

来源已经提供展开后的合约、篮子和成分关系。入模读取处理业务日 `BUSI_DATE`，承接这些关系；再分别按合约工具、成分工具关联 TIT 工具扩展资料，补两边的统一证券编号。

## 2. 一条记录怎样读

| 层次 | 取数原字段 → 入模字段 | 表示什么 |
| --- | --- | --- |
| 合约外部编号 | `CONTRACT_CODE` → `COMP_NO` | 业务看到的合约编号 |
| 合约内部编号 | `KEY_OTC_TRADE_ID` → `COMP_INR_NO` | TIT 场外交易／合约内部 ID |
| 合约工具身份 | `CONTRACT_INS_ID` → `COMP_INS_ID` | 合约在金融工具体系中的编号 |
| 篮子身份 | `BASKET_INS_ID` → `BASK_INS_ID` | 该记录所属篮子的工具编号 |
| 篮子类型 | `BASKET_TYPE` → `BASK_TYPE_CD` | 怎样理解这组标的的组合方式 |
| 成分身份 | `UNDERLYING_INS_ID` → `UNDRL_INS_ID` | 该条成分的工具编号 |
| 成分说明 | `INS_SHT_DESC`、`WIND_CODE` → `UNDRL_ABBR`、`UNDRL_WIND_CD` | 成分简称、WIND 代码 |
| 成分权重 | `WEIGHT` → `UNDRL_WGHT` | 来源给出的标的权重，入模直接保留 |
| 归属 | `BOOK_NAME`、`DEPARTMENT` → `BOOK_NAME`、`BOOK_OWN_DEPT` | 合约账簿和部门 |

例如，假设同一合约的篮子包含 A、B 两项标的，就会看到同一合约和篮子对应 A、B 的成分记录。这个例子说明读取维度，不据此认定来源组合键必然唯一。

## 3. 篮子类型怎么理解

入模不转换 `BASKET_TYPE`。目标 DDL 给出以下代码说明：

| 源码／入模码 | 含义 |
| --- | --- |
| `INDEX_BASKET` | 指数式篮子 |
| `WORST_OF` | 最差成分篮子 |
| `BEST_OF` | 最优成分篮子 |
| `HIMALAYAS` | 喜马拉雅篮子 |

**“有多个成分、有权重”还不足以确定期权怎样支付收益。** 指数式、最差成分、最优成分等类型有不同的组合含义；具体比较哪个指标、在哪些日期观察、如何结算，要继续看合约结构。当前入模没有计算篮子收益，也没有对权重重新归一化。

读取 `WEIGHT` 时保留源数值；仅凭字段注释不能确定按 `0～1` 还是 `0～100` 表达，更不能未经核对就直接加权各成分的原始价格。

## 4. 怎样回到主数据查名称和类型

```text
CONTRACT_INS_ID → T02_TIT_SCR_BASE_INFO.IN_CODE → SECU_ID
UNDERLYING_INS_ID → T02_TIT_SCR_BASE_INFO.IN_CODE → UNDRL_SECU_ID

以上两次关联均限定 SRC_ID='TIT'、GRP_ID='01'
```

两次均为左关联，统一编号未命中时来源成分仍保留。`BASKET_INS_ID` 在本任务中原样保存，没有第三次关联去补篮子的统一编号；查篮子名称时可再按该内码核对主数据。

另一个需要单独记住的口径：本表的 **`SRC_SYS_PRDNO` 是 `TIT-`＋`CONTRACT_CODE`**，没有使用 `CONTRACT_INS_ID` 拼接。关联工具主数据时，直接用 `COMP_INS_ID` 等明确的工具键，不能套用其他表“去掉 `TIT-` 就是工具内码”的规则。

## 5. 能回答什么

- 查一份多标的期权关联哪个篮子、篮子中有哪些标的。
- 查各成分的名称、代码、权重和合约账簿。
- 区分“期权合约自身的工具”与“篮子成分工具”。

现有发布图中未检出 `T02_OPT_MULT_BASK_INFO` 的直接消费。可以据来源与入模解释组成关系；它是否被某项定价、风控或报表正式使用，当前没有对应消费证据。
