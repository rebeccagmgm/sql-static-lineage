# 产品基础资料全貌

**这一部分先回答：TIT 里有哪些产品对象，它们叫什么、属于什么类型、有什么属性，以及与合约和底层资产怎样连接。**

T02 按两条主线阅读：本目录整理 **产品基础资料**；`02-行情与市场参数` 整理价格、净值、汇率、利率报价，以及定价参数和计算结果。本篇以现有《T01–T06 TIT 入模消费与学习导读》为底稿，先建立产品资料的全貌。

## 1. 先看全貌

TIT 的产品资料可以分为五组，**金融工具主数据 `D_REF_INSTRUMENT` 是理解其中编号、名称和类型的主要入口。**

| 资料组 | 主要回答什么 | 代表资料 |
| --- | --- | --- |
| **金融工具身份** | 这个编号是什么对象，叫什么，属于哪一类？ | 股票、基金、指数、期货等标的，以及互换、场外期权、外汇远期等合约自身的工具记录 |
| **品种属性与条款** | 这个工具有哪些具体规则？ | 期货合约参数、场内期权行权参数、货币利率惯例、策略指数定义、部分场外期权障碍条款 |
| **发行产品与票据** | 发行了什么产品，期限、本金、发行和认购情况是什么？ | 产品基础信息、票据条款 |
| **底层资产与组成关系** | 产品或合约关联哪些工具、篮子和交易？ | 发行产品底层资产、多标的期权篮子 |
| **配套资料** | 怎样识别、分类、准入和使用这些工具？ | 外部编码、标签、标的池属性、白名单、持股监控配置、交易日历、公司行为 |

这里的“产品”包含两类需要分开理解的对象：

- **金融工具**：使用 `KEY_INSTRUMENT_ID` 识别，既可以是一只股票，也可以是一份互换合约的工具记录。
- **发行产品**：使用 `KEY_PROD_ID` 识别，记录发行、面值、认购、兑付等信息；通过底层资产资料关联工具和交易。

两类资料可以发生联系，但不能因为目标字段都叫 `PRD_ID`，就把两个编号当成同一套键。

## 2. 金融工具主数据：先查清“这个东西是什么”

详细取数逻辑、类别字典、编号关系和 500 条真实样本见 [01 金融工具主数据](00-20260914-图谱认知/01-tit入模/T02-产品标的与市场数据/01-产品基础资料/01%20金融工具主数据.md)。

### 2.1 `D_REF_INSTRUMENT` 里装什么

源字段 `INS_FAMILY` 表示金融工具类别，`INS_SHT_DESC`、`INS_LNG_DESC` 表示简称和全名，另有币种、市场、WIND 代码、到期日及子类等属性。

| 对象范围 | 代表类别 | 阅读时关注什么 |
| --- | --- | --- |
| 股票、基金、债券 | `EQUITY`、`FUND`、`HEDGE_FUND`、`BOND` | 标的身份、名称、币种和市场等 |
| 指数、商品、货币对、利率 | `INDEX`、`QIS`、`COMMODITY`、`FX`、`RATE_INDEX` | 指数或参考工具的身份；具体行情和参数另查 |
| 场内衍生品 | `FUTURE`、`LISTEDOPTION` | 先取得工具身份，再补期货或场内期权专属属性 |
| 场外合约自身 | `TRS`、`OTC_OPTION_CONTRACT`、`FX_FORWARD` | 合约在金融工具层的记录；本次查询已见互换、场外期权和外汇远期实例 |

这是对象范围示意，不是完整类别字典。**表注释中的“证券基本信息”覆盖的范围比股票更广。**

### 2.2 从 TIT 到 T02 的入口

```mermaid
flowchart LR
    A["TIT 原库<br/>titans_dm.ref_instrument"] --> B["贴源<br/>ODATA_N_TIT.D_REF_INSTRUMENT"]
    B --> C["通用金融工具资料<br/>PDATA_NEWS_N.T02_SCR_BASE_INFO"]
    B --> D["TIT 扩展资料<br/>PDATA_NEWS_N.T02_TIT_SCR_BASE_INFO"]
    C -->|补充统一编号、名称等| D
```

两张 T02 表都读取源金融工具资料；TIT 扩展表还关联通用证券资料，补充统一编号、名称等字段。

| 查什么           | 表与字段                                                             | 取用要点                                  |
| ------------- | ---------------------------------------------------------------- | ------------------------------------- |
| 源端工具的名称和类别    | `D_REF_INSTRUMENT.KEY_INSTRUMENT_ID`、`INS_FAMILY`、`INS_SHT_DESC` | 按业务日期和源工具编号查询                         |
| 通用证券身份        | `T02_SCR_BASE_INFO.IN_CODE`、`SECU_ID`、`SCR_TYPE`                 | TIT 来源下，`IN_CODE` 承接源工具编号；标准类别经过映射    |
| TIT 原始类别与扩展属性 | `T02_TIT_SCR_BASE_INFO.IN_CODE`、`SCR_TYPE_SRC`、`SUB_TYPE`        | 本条基础资料分支使用 `SRC_ID='TIT'、GRP_ID='01'` |

例如 `TRS` 在通用类别中会映射为 `OTH`，在 TIT 扩展资料的 `SCR_TYPE_SRC` 中仍保留 `TRS`。要判断“它究竟是股票还是互换”，优先看保留源类别的字段。

## 3. 资料分别从哪里入模

以下贴源表均位于 `ODATA_N_TIT`，模型表均位于 **`PDATA_NEWS_N`**。调度按具体资料分支列示，便于回到总表查证；同一目标的不同分组和批次须结合对应任务理解。

### 3.1 通用身份、品种属性与条款

期货、场内期权、货币利率、策略指数和 AUTOCALL 条款的详细说明，见 [02 品种属性与条款](00-20260914-图谱认知/01-tit入模/T02-产品标的与市场数据/01-产品基础资料/02%20品种属性与条款.md) 及其子篇。

| 资料 | 贴源表 → 入模表 | 入模重点／调度 |
| --- | --- | --- |
| 通用金融工具身份 | `D_REF_INSTRUMENT` → `T02_SCR_BASE_INFO` | 形成通用证券身份，映射类型、市场和币种；103230、103232 |
| TIT 金融工具扩展资料 | `D_REF_INSTRUMENT`、`D_REF_INSTRUMENT_PB` → `T02_TIT_SCR_BASE_INFO`（01） | 保留源类型、WIND 代码、子类、到期日等；103234、103235、144303、211515 |
| 期货属性 | `D_REF_FUTURE_PROPERTIES` 及其批次表 → `T02_FUT_BASE_INFO`、`T02_FUT_BASE_INFO_EXT` | 补充合约、交易所、交割、乘数等属性；未匹配证券编码的记录被剔除。主表：105612、105862、144301、211516；扩展：105745、105746 |
| 场内期权属性 | `R_REF_LISTED_OPTION_PROPS` → `T02_OPT_BASE_INFO_TIT` | 标的、看涨看跌、行权价、合约单位、行权方式和关键日期；176204 |
| 货币利率属性 | `D_REF_RATE_PROPERITES` → `T02_TIT_IRA_CRRC_ATTR` | 币种、期限、复利、计息、结算惯例与日历；170648 |
| 策略指数定义 | `D_REF_STRATEGY_INDEX` → `T02_IDX_STRG_MATN_TIT` | 策略与标的、初始点位、数量、版本等；219012 |
| AUTOCALL 风险障碍条款 | `D_REF_OPTION_AUTOCALL_KI` → `T02_OPT_DERI_IDX` | 观察日、风险障碍比例和金额写入备注；该分支的 Delta、Gamma 等字段为空。119465 |

股票、基金等对象首先在通用主数据中识别；是否还有专属属性表，要按实际入模来源确认。场外期权的合约结构、互换腿等资料，还需结合 T03 查看。

### 3.2 发行产品、票据与组成关系

产品身份、发行认购和票据条款见 [03 发行产品与票据](03%20发行产品与票据.md)；产品怎样接到工具、合约和估值，以及期权篮子怎样组成，见 [04 底层资产与组合关系](04%20底层资产与组合关系.md)。两章均已按业务对象拆出子篇。

| 资料 | 贴源表 → 入模表 | 入模重点／调度 |
| --- | --- | --- |
| 发行产品 | `P_PRD_PRODUCT` → `T02_TIT_PRD_INFO` | 产品类型、状态、账簿、期限、名义本金、发行及认购信息；160750、211488 |
| 票据条款 | `P_PRD_NOTES` → `T02_TIT_NOTE_INFO` | 序列号、发行数量与价格、面值、利息和赎回基准、ISIN；160751、211487 |
| 发行产品底层资产 | `P_PRD_PRODUCT_ASSET` → `T02_TIT_PRD_ASSET_INFO` | 产品—金融工具—内部交易号关系；补证券编码，不在此计算权重或收益。160753、211486 |
| 多标的期权篮子 | `D_V_RISK_OPTION_BASKET_INFO` → `T02_OPT_MULT_BASK_INFO` | 合约—篮子—标的、类型、权重与账簿；承接已有组成信息。104478、104481 |

`P_PRD_PRODUCT` 来自 TIT 的产品业务资料，原库清单包含 `titans_dm.prd_product`、`titans_product.prd_product`。**这条发行产品链与 `D_REF_INSTRUMENT` 的金融工具身份链要分别阅读，再通过实际关系字段连接。**

### 3.3 配套资料

详细说明见 [05 配套资料](00-20260914-图谱认知/01-tit入模/T02-产品标的与市场数据/01-产品基础资料/05%20配套资料.md)，分为外部编码、金融工具标签、标的池与白名单、受益人持股监控清单、交易日历、公司行为六篇。

| 资料 | 贴源表 → 入模表 | 作用／调度 |
| --- | --- | --- |
| 外部编码 | `D_REF_INSTRUMENT_CODE` → `T02_TIT_SCR_BASE_INFO`（02） | 补充工具在其他编码体系下的标识；103236、103237 |
| 境外期权代码映射 | `R_CFG_ICE_LISTEDOPTION` → `T02_STK_OVERSEAS_OPT_CD_MAP` | 交易代码、市场标识、BB_ROOT 和启用配置；218469 |
| 标签 | `D_REF_INSTRUMENT_TAG` → `T02_SCR_LBL` | 给金融工具补充分类标签；127897 |
| 标的池属性 | `R_CFG_INSTRUMENT_POOL_PROPS` 及其批次表 → `T02_FIN_UNDRL_ATTR` | 标的池的业务属性；158210、158292 |
| 白名单 | `D_REF_INSTRUMENT_POOL_WHITELIST`、`D_REF_INSTRUMENT_POOL_WHITELIST_P` → `T02_TIT_WI_UNDRL_POOL`、`T02_TIT_WI_UNDRL_POOL_PB` | 准入名单及单独的 1230h 批次；171427、221125 |
| 受益持股监控配置 | `R_CFG_INS_BE_SHARE_PROPORTION` → `T02_TIT_STK_BENE_OWSR_PROP` | 标的的持股监控配置；208603 |
| 交易日历 | `D_CFG_CALENDAR` → `T02_TIT_SCR_TRD_CAL` | 计算交易日标志、前后交易日和期间首末交易日；当前 SQL 直接列举市场名称。161255 |
| 公司行为 | `D_REF_CORPORATE_ACTION_INFO` → `T02_CO_BEHAV_INFO` | 分红、送转、配股、拆分等事件、日期和比例；188381 |

公司行为是事件资料，交易日历和白名单是配套规则。本篇将它们放在产品使用背景下，读取时仍保留各自性质。

## 4. 与 T03 合约、底层标的怎样连接

### 4.1 一份合约可以同时有“合约身份”和“金融工具身份”

本次实际查询确认了以下对应：

| 交易表的合约键 | 交易表的工具键＝T02 的 `IN_CODE` | T02 源类别 | T02 简称 |
| --- | --- | --- | --- |
| `14571` | `100225` | `TRS` | `TRS-CCTBBWY20220002` |
| `14433` | `100001` | `OTC_OPTION_CONTRACT` | `XZRH20210059` |
| `139434` | `1025410` | `FX_FORWARD` | `OTCHKFX-SCB-32FZQ1L` |

以第一行为例：

```text
T03 合约：14571
    └─ 交易表 KEY_INSTRUMENT_ID = 100225
         └─ T02 金融工具：IN_CODE = 100225，类型 TRS
```

任务 105386 将这条对应存入 `PDATA_N.T03_AGT_PRD_RELA_H`：`PRD_ID` 按规则拼成 `TIT-100225`，`SRC_PRD_ID` 保留 `100225`。查询 T02 的 `IN_CODE` 时使用原始编号 `100225`。目标关系表的实际落地记录未在本次查询中核验。

### 4.2 合约自身的工具身份，与挂钩资产分别查询

上述 `100225` 已确认是互换工具。要知道它挂钩哪只股票、哪个指数或篮子，需要继续查合约结构或持仓中的标的关系：

| 想查什么 | 关系入口 | 查到工具编号后 |
| --- | --- | --- |
| 合约自身是什么工具 | `D_TRD_OTC_TRADE.KEY_INSTRUMENT_ID` | 查询金融工具主数据的名称、类别 |
| 场外期权挂钩什么标的 | `D_REF_OPTION_DEAL_STRUCTURE.UNDERLYING_INS_ID` | 按主数据键查询；若为篮子，还需展开成分 |
| 普通互换实际关联哪些标的 | 互换腿、持仓资料；已查消费使用 `D_POS_TRS_LEG_HIS_POS.UNDERLYING_INS_ID` | 补名称、代码、类别；一份合约可能涉及多条腿和多个标的 |
| 发行产品关联什么资产和交易 | `P_PRD_PRODUCT_ASSET` 的产品、工具与内部交易号 | 分别连接发行产品、工具资料和交易／合约资料 |

主数据可以同时保存“合约工具”和“底层资产工具”。**它们的业务角色由关联路径决定，不能只看到 `KEY_INSTRUMENT_ID` 就断言指的是股票。** 本次只查实了上表三个合约自身的工具身份，没有查实它们各自的底层资产。

## 5. 入模以后，基础资料有什么用

| 下游需要什么 | 基础资料提供什么 | 已查到的用途 |
| --- | --- | --- |
| 识别交易、持仓或行情里的编号 | 名称、类别、币种、市场、统一证券编号 | 区分股票、期货、期权等对象，为行情分流和持仓展示补充身份 |
| 建立风控基础资料 | 期货、场内期权、货币利率的专属属性 | `dm_rsk_n` 的期货、场内期权、货币市场利率基础资料 |
| 形成发行、负债和票据明细 | 产品、票据与底层资产／交易关系 | 香港票据明细、香港负债资料、财务票据交割明细 |
| 结合估值形成价格 | 产品发行数量、底层资产关联的交易和估值 | 已查 AMCNote 分支在消费层计算单价，产品入模本身不计算该价格 |
| 向其他系统提供资料 | 模型中的产品与属性记录 | OTC、香港、财务及估值系统相关资料分发 |

基础资料回答对象与规则，行情和计算结果回答特定日期的价格与数值。读消费时，要进一步看实际取了哪个字段、哪个来源分组。

## 6. 与“行情与市场参数”的分工

| 本目录：产品基础资料 | 相邻目录：行情与市场参数 |
| --- | --- |
| 工具编号、名称、类别、市场、币种 | 价格、成交量额、持仓量、净值、汇率和利率报价 |
| 期货与期权属性、利率惯例、发行和票据资料 | 曲线、曲面及其数值，定价环境和选择配置 |
| 资产组成、标的关系、编码、标签、日历等配套资料 | Greeks、隐含波动率、限售股估值等计算结果，注明其结果性质 |

现有 Excel 的“基础资料与配置”是原分类。本次按两条业务主线重新组织，曲线定义、曲面定义和定价环境随其市场参数放到第二部分；AUTOCALL 风险障碍则按已查字段内容放在本篇条款资料中。表名含“指标”或原分类写“业务结果”，都不代替对实际字段的判断。
