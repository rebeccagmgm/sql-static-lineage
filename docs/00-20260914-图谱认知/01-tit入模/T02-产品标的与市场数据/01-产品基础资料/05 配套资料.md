# 05 配套资料

**金融工具有了身份和条款，还需要知道用什么代码识别、带哪些标签、在哪个业务范围内使用、按哪个日历处理，以及发生过什么公司行为。** 这些资料共同支撑报价、交易、风控和数据分发。

## 2. 这几类资料各是什么性质

| 资料 | 一条记录主要围绕什么 | 使用时抓住什么 |
| --- | --- | --- |
| 外部编码 | 工具＋编码体系＋编码值 | 同一个工具可以有多套代码，关联时带编码体系 |
| 标签 | 工具＋一组是／否属性 | 标签表示所属范围或特征，不提供完整业务条款 |
| 标的池属性 | 工具在标的池中的配置 | 同时读工具、池、分类、报备场所和参数 |
| 白名单 | 工具、业务方案、交易对手及标的池 | 看具体业务上下文，不能只取一列工具 ID 当作通用准入名单 |
| 持股监控清单 | 被选中的监控工具 | 清单界定监控范围，比例由下游计算 |
| 交易日历 | 市场／日历代码＋日期 | 同一天在不同日历中的交易属性可能不同 |
| 公司行为 | 某证券的一项事件及其日期、参数 | 区分登记日、除权除息日、支付日和方案进度 |

## 3. 怎样与前面的主数据配合

编码、标签、标的池、白名单、监控清单和公司行为，多数先按 **TIT 工具内码 → 主数据 `IN_CODE`** 补名称或统一编号。交易日历主要按市场代码和日期连接。

例如要向 OTC 系统提供一项标的，主数据给身份、类型和名称，编码资料给 WIND 代码，标签给沪／深港通标志；要进入特定标的查询页面，还可能需要满足标的池范围。它们分别回答不同问题。

## 4. 已确认的实际用途

| 配套资料 | 用在什么地方 |
| --- | --- |
| WIND 编码＋标签 | OTC 标的定义 `DM_OTC_N.OTC_UNDRL_DEF`，调度 119976 |
| 境外期权映射 | 按启用的 `BB_ROOT` 筛选境外场内期权行情推送，调度 234508、96471 |
| 标的池属性 | `DM_OTC_N.OPTION_SUBJECT_VIEW` 取池 `10000`；配置分发保留池编号，调度 158671、159250 |
| 受益人监控清单 | 限定穿透持股比例计算的标的，调度 208230 |
| 公司行为＋日历 | 检查相关期权合约的公司行为处理时点，调度 181555 |

白名单两张目标表在现有发布图中尚未检出明确直接消费；可以解释其配置内容，具体哪个业务环节执行准入仍需相应读取证据。
