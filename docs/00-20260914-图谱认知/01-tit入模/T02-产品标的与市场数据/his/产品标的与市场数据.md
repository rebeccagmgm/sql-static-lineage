# T02 产品、标的与市场数据

TIT 提供哪些产品和证券标的，怎样描述它们的属性、行情和定价参数，又把计算结果放到哪些模型表里。

本页参照 T01，先按业务问题分组，再列贴源参与关系和带中文名称的目标清单。范围限定为现有 TIT 入模盘点中的 T02；不是全部 T02 模型目录。

## 1. 先按业务问题看

| 要弄清什么            | 对应模型表（代表）                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 产品是什么、底层资产有哪些    | `t02_tit_prd_info`（TIT产品信息）、`t02_tit_prd_asset_info`（TIT产品底层资产信息）、`t02_tit_note_info`（TIT票据信息）                                                    |
| 证券、期货、期权怎样识别     | `t02_scr_base_info`、`t02_tit_scr_base_info`（证券基本信息）、`t02_fut_base_info`（期货品种基本信息）、`t02_opt_base_info_tit`（期权基础信息）                                 |
| 哪些标的可用、有哪些标签和属性  | `t02_tit_wi_undrl_pool`（白名单标的池）、`t02_fin_undrl_attr`（标的池标的属性）、`t02_scr_lbl`（证券标签）                                                                 |
| 日期、公司行为与持股信息怎样描述 | `t02_tit_scr_trd_cal`（交易日历）、`t02_co_behav_info`（企业行为）、`t02_tit_stk_bene_owsr_prop`（受益人持股比例）                                                       |
| 市场上的价格、利率、净值是什么  | `t02_fin_curv_mkt_quot`（曲线行情）、`t02_fxr_cfets_quot`（汇率中间价）、`t02_ira_indx_info`（利率指标）、`t02_opt_mkt_quot`（期权行情）、`t02_prd_unit_nav_s_tit`（基金净值）       |
| 定价用哪些曲线、曲面和因子    | `t02_fin_curv_def`（曲线定义）、`t02_fin_prcg_env_curv`（定价环境配置）、`t02_fin_vol_curv_surf`（波动率曲面定义）、`t02_fin_vola_instc`（波动率实例）、`t02_oth_corre_fctr`（相关性因子） |
| 定价、风险与履保产生哪些结果   | `t02_opt_greek_val_det`（子交易希腊值明细）、`t02_opt_mutl_undrl_prcg_indx`（期权多标的定价指标）、`t02_fin_cutp_bail_acct_daily_rslt`（交易对手保证金账户每日履保计算结果）                |

分组是阅读导航，不是表间血缘。尤其“定义、配置、行情、计算结果”具有不同含义；不能把这些表都理解为一张产品主表的附属属性。履保结果和子交易希腊值按现有目标归在 T02，本页保留这个事实，不据此推定它们的业务粒度都是产品。

## 2. 一个具体例子：产品信息怎样入模

```text
odata_n_tit.p_prd_product（产品基础信息）
    ↓ 任务 160750
pdata_news_n.t02_tit_prd_info（TIT产品信息表）
```

已核对任务 160750 的本地 SQL 快照（采集于 2026-09-05）。它读取源表当天 `busi_date`，写入目标 `src_id='TIT'、grp_id='01'` 分区：

| 贴源字段／表达式                                                            | 模型字段                      | 中文含义        |
| ------------------------------------------------------------------- | ------------------------- | ----------- |
| `id`                                                                | `rec_id`、`src_rec_id`     | 记录编号、来源记录   |
| `key_prod_id`                                                       | `prd_id`                  | 产品编号        |
| `key_book_id`、`book_name`                                           | `book_id`、`book_name`     | 账簿编号、账簿名称   |
| `product_type`                                                      | `prd_type`                | 产品类型        |
| `inner_code`、`external_code`                                        | `prd_inr_cd`、`prd_ext_cd` | 产品内部代码、外部代码 |
| `default.date2datekey(trade_date)`                                  | `sale_date`               | 销售日期        |
| `default.date2datekey(start_date)`、`default.date2datekey(end_date)` | `val_date`、`maty_date`    | 产品起息日、到期日   |
| `total_notional`                                                    | `prd_tot_nom_prin`        | 产品总名义本金     |
| `product_status`                                                    | `prd_stat`                | 产品状态        |

这里应区分记录编号 `id` 和产品编号 `key_prod_id`。SQL 展示了字段映射，但没有证明 `prd_id` 唯一；后续分析产品与底层资产、票据的关系，还需核对各表关联键和粒度。`product_type`、`product_status` 在这段 SQL 中直接写入，具体码值含义不能由字段名推断。

同一目标还列有任务 211488，不能只看 160750 就认定已经覆盖该模型全部写入。日期放在字段中，而这里覆盖写入的分区是 `src_id + grp_id`，因此不能据此称为按业务日期保留所有历史快照。
