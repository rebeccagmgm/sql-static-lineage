# T02：按业务类别看入模加工与下游消费

本篇回答三个问题：**什么数据入模、入模做了什么加工、下游怎样使用。**

整理日期：2026-09-14。覆盖现有 TIT 入模盘点的 **42 张业务目标表、3 张临时辅助表、85 个入模任务**；另外补充普通证券行情共用的 `tyzx_exch_quot_h_fk`，否则会漏掉期货、场内期权、股票和基金的重要消费链。这里的“全部”限定于这份 TIT 参与盘点，不是数仓所有来源的 T02 目录。

除特别注明，正文 T02 表均属于 `pdata_news_n`。基础证券关联、日期格式转换等常规处理不逐字段展开，只保留会影响数据范围、数值口径、业务分类和下游使用的加工。推送或加工到 `dm_rsk_n` 直接归为风控消费；财务、香港等归属以实际输出结合 SQL 判断，不只看任务执行库。

## 一、先看行情主线

**普通行情、reset 行情、风管行情和定价参数，是几条不同的链路。**

| 类别 | 主要承接表 | 实际消费重点 |
| --- | --- | --- |
| 期货普通行情 | `tyzx_exch_quot_h_fk` | 按证券类型筛选期货，向风控输出开高低收、结算价、成交量额 |
| 场内期权普通行情 | `tyzx_exch_quot_h_fk` | 按 `LISTEDOPTION` 筛选，向风控输出日行情 |
| 期权 reset 行情 | `t02_opt_mkt_quot` 的 TIT 分区 | reset 值放在结算价字段；香港按其账簿范围取用，财务接收该分区 |
| 股票、指数普通行情 | `tyzx_exch_quot_h_fk` | 筛选股票和指数，向风控输出价格、复权信息、交易状态 |
| 基金普通行情 | `tyzx_exch_quot_h_fk` | 筛选基金，向风控输出收盘价、资产净值、累计／复权单位净值 |
| 风管部私募等行情 | `t02_prd_unit_nav_s_tit` | 进入价格类因子行情；同标的、同日期优先于普通 TIT 行情 |
| 汇率中间价 | `t02_fxr_cfets_quot` 的 TIT 分区 | 财务 TRS 报表补充人民币汇率，香港接收中间价；另有风控及业务报表读取 |
| 利率报价 | `t02_ira_indx_info` 的 TIT 分区 | 入模乘 100；风控再除以 100，作为货币市场利率的中间价 |
| 收益率／分红曲线行情 | `t02_fin_curv_mkt_quot` | 风控收益率曲线视图、分红因子行情和行情异常监测 |
| 波动率实例、相关性 | `t02_fin_vola_instc`、`t02_oth_corre_fctr` | 与因子定义匹配，生成风控波动率、相关性因子行情 |

### 共用普通行情怎样加工

入模任务 104663 从 `odata_n_tit.d_mkt_ins_daily_info` 接收价格、成交量额、复权信息、净值等，写入 `tyzx_exch_quot_h_fk`。主要是字段承接，统一证券编码优先匹配 TIT，缺失时尝试 WIND 匹配；没有在这段 SQL 中重新计算收盘价或复权价格。

有两个不能忽略的口径：源注释说明 `pric_chg` 对场内期权、港股期货表示价格变化，其他类型表示百分比；成交量也有股、张、千克、手的区别。不能把整张共用行情表一概解释为同一种涨跌幅或成交量单位。该任务读取源表时没有按 `busi_date` 过滤，目标业务日期也不能直接替代每条行情的实际交易日期。

下游通过证券基础资料识别品种后分流，而不是从每张品种基础表“算出行情”：

| 消费目标 | 具体使用 | 证据任务 |
| --- | --- | --- |
| `dm_rsk_n.futr_mkt_quot` | 保留 `FUTURE`，输出期货价格、结算价、量额与币种 | 164723 |
| `dm_rsk_n.trd_opt_mkt_quot_day` | 保留 `LISTEDOPTION`，输出开高低收、复权收盘价、涨跌、均价、成交量 | 175878 |
| `dm_rsk_n.stk_spi_mkt_quot_day` | 保留 `INDEX`、`EQUITY`，输出价格、复权因子、成交量和交易状态 | 175782 |
| `dm_rsk_n.fnd_mkt_quot_day` | 保留 `FUND`，输出收盘价、资产净值、累计及复权单位净值 | 175843 |

以上均核对了查询 SQL；不把“关联基础证券表”单独写成一种业务计算。

## 二、期货

### 入模内容与加工

| 表 | 数据性质 | 入模加工总结 |
| --- | --- | --- |
| `t02_fut_base_info` | 期货基础资料 | 接收标准合约、交易所、上市／最后交易／交割日期、合约乘数、涨跌限制和标的；将源期货类型映射为模型代码。**无法匹配统一证券编码的记录被剔除**。交割月、连续合约类型等一部分信息装进备注 JSON |
| `t02_fut_base_info_ext` | 期货扩展资料 | 承接交割月份、交易代码、英文简称、源数据来源等，同样剔除证券编码为空的记录；不是期货行情表 |

主表有常规及 `h15` 贴源批次写入，均写 TIT／01；不能把批次任务当成四套不同业务数据。证据：105612、105745、144301 及其同表任务。

### 下游实际消费

风控 `dm_rsk_n.futr_base_info` 从主表及备注中取出合约类型、连续合约类型、交割月份和交易日期，形成期货基础资料；香港 `dm_hk_n.ref_future_properties` 也会拆备注，并将期货类型反向还原为源代码。这说明备注里的信息有真实消费者，并非随意附注。证据：164500、160530。

投影还显示主表参与互换／期权标的宽表、风控对冲持仓、TRS 风险损益、商品期货行情异常检查，以及 OTC 期货属性输出。它们属于**基础参数被消费**，不应全部叫作“期货行情消费”。具体目标保留在逐表投影索引中。

期货扩展表检出的“期货合约基本信息”任务 216196 只取 `CH` 来源，**不算 TIT 扩展资料的消费**；目前未找到 TIT 分区的明确业务读取。普通行情消费见第一节。

### 2. reset 行情

`t02_opt_mkt_quot` 的 TIT／01 来自 `r_ref_option_quote_reset`：观察日映射为交易日期，`reset_value` 映射为 `sett_pric`，标的编码写入备注。开高低收、成交量、持仓量、涨跌等字段在这条入模 SQL 中为空。**它是借期权行情模型承接 reset 值，不是完整的期权日行情。** 证据：139409。

下游有两条明确消费：

- **香港**：`dm_hk_n.ref_option_quote_reset` 把结算价还原为 `RESET_VALUE`，并关联期权子交易和账簿，只取归属 `GFS_HK` 的记录；不是全量原样复制。证据：134518。
- **财务**：`dm_fin_n.civ_opt_mkt_quot` 直接接收 TIT／01 行情字段，SQL 中没有进一步计算价格。证据：220853。

财务另有“ETF 期权成交量额汇总”任务 230940，但取的是 `WD`／01，不是这批 TIT reset 行情。普通场内期权行情来自第一节的共用行情表。

## 四、基金及风管行情

### `t02_prd_unit_nav_s_tit`

来自风管部私募行情 `d_mkt_risk_daily_info`，按证券和报价日期生成记录标识；承接单位净值、资产净值、虚拟净值、结算价、收盘价、成交额、市值及行情来源。虽然表名是基金净值，字段内容比单位净值更广，入模 SQL 没有额外按基金证券类型过滤。没有在入模层计算基金净值。证据：207284。

**真正的消费是风控价格类因子行情 `dm_rsk_n.pric_fctr_mkt_quot_day`。** 下游按标的内码匹配权益因子，输出单位净值和收盘价；同标的、同日期若风管行情已存在，会排除共用 TIT 普通行情的对应记录。也就是：**风管行情优先，普通 TIT 行情补缺**，而非两份行情直接叠加。风管分支需要匹配权益因子，不能据此理解为所有输入记录都会输出。证据：177526、182738、182755。

基金普通行情另走第一节的 `fnd_mkt_quot_day`；两个出口的目的和取值不同。

## 五、汇率与利率

### 1. 汇率：`t02_fxr_cfets_quot`

TIT 中间价来源于 `d_ref_rmb_midrate` 及其批次表。入模承接源 `MIDRATE`，转换币种代码，对应的另一币种固定为人民币代码 `156`；没有倒数换算或重新计算中间价。常规任务生成日期＋币种记录标识；`h15` 版本还有币种映射缺失的回退处理。证据：105616、144298。

**财务 TRS 损益报表** `dm_fin_n.v_fin_trs_plreport` 按结算币种和日期关联 TIT 中间价，生成 `exchangeRateCny`，人民币取 1。不同分支按业务日期或实际结算／终止定价日期匹配。这段 SQL 能证明“报表带出人民币汇率”，不能简单改写成“所有盈亏都由本表乘汇率计算”。证据：118174。

**香港** `dm_hk_n.ref_rmb_midrate` 将源币种、行情日期、中间价还原为香港接口字段。证据：166014。

已发布投影还找到风控 TRS 风险损益、保证金明细／组合保证金，以及 OTC 账簿资产、合约和业务报表等去向。它们在逐表投影中保留为可查清单，正文不把每条表级候选都断言为已核验的 TIT 金额折算公式。尤其汇率表是多来源共用模型，其他来源消费者不算 TIT 消费。

### 2. 利率：报价、批次、属性分开

| 表 | 入模内容与加工 | 下游实际消费 |
| --- | --- | --- |
| `t02_ira_indx_info` | `m_ref_cbond_rate` 的 RATE **乘 100** 写入利率百分数；以证券和报价日期形成记录标识 | 风控 `crrc_mkt_intrt` 再将利率 **除以 100**，匹配 WIND 市场代码，写到 `min_pric`；买价、卖价为空。香港 `info_tit_ira_indx_day` 接收利率指标 |
| `t02_ira_indx_info_pb` | 同样 RATE × 100，单独保存 `0830h` 批次 | 当前证据未找到该批次表的明确下游读取 |
| `t02_tit_ira_crrc_attr` | 参考资料：币种、期限、到期日、复利／日算／结算／工作日调整惯例和日历，主要直接承接 | 风控 `crrc_mkt_intrt_base_info` 以 `RATE_INDEX` 证券为范围补齐利率属性，缺名称或币种时从证券资料补充 |

例如源 RATE 为 0.02，模型利率为 2，风控 `min_pric` 为 0.02。这是 SQL 运算示例，不是抽样业务数据。

## 七、产品、票据与底层资产

### 入模内容与加工

| 表 | 入模加工总结 |
| --- | --- |
| `t02_tit_prd_info` | 承接产品类型、状态、账簿、期限、名义本金、发行价格／数量和认购信息。日期格式化，产品类型／状态直接承接；没有在入模层只保留有效产品 |

证据：160750、160751、160753 及对应同表任务。按用户关注的加工尺度，这组可概括为“以透传为主”，不必逐项解释常规补码和日期转换。

### 下游实际消费

**香港票据明细 `dm_fms_n.gfhk_fnd_note_detail`**：产品表作为主表，区分融资型／结构型票据，排除作废及部分测试数据；票据表提供利率类型，底层资产表提供内部交易流水，用来寻找合约及利息腿。再带出交易对手、利率和付息信息，计算发行金额及折港币金额。底层资产按产品排序取一条用于关联，不是将所有底层资产等权汇总。证据：163640。

**风控香港负债 `dm_rsk_n.trd_rsk_hk_liab_basic_day`**：读取产品和底层资产关系，结合交易及合约利息腿形成融资票据负债资料；过滤作废产品。证据：176443。

**财务价格 `dm_fin_n.civ_market_prices_spt_cp_t`**：筛选未到期、发行数量非零的 AMCNote，经底层资产内部交易号关联估值；用“动态名义本金减未实现损益，再除以发行数量”形成该分支的市场价／收盘价等。**这是下游计算，不是产品入模计算。** 证据：199871。

**财务票据交割明细 `dm_fin_n.civ_trd_bill_deli_dtl_day_hk`**：结合产品、票据交易流水、底层资产和估值；包含起息日期范围筛选及相邻估值利息差额处理。证据：202510。

**资料分发**：三张表先复制至 OTC 对应表，再推送 `gfval.src_t02_tit_*`；香港还有产品及底层资产接口，财务另接收产品资料。此类归为“资料分发”，不能直接写成已在接收系统完成估值计算。证据：181136／181140／181142、181181／181182／181183、183259／183294、202957。

### 3. 持股监控清单

**`t02_tit_stk_bene_owsr_prop` 应在认知上归为监控配置，而不是已计算的持股比例。** 入模只接收监控证券，补证券简称和 WIND 代码，没有受益人持股比例字段或比例计算。证据：208603。

下游 `dm_otc_n.bene_owner_hold_prop_excd_pct3_day` 才做实际计算：以清单限定标的，关联存续的安全气囊 X／收益互换合约、交易对手受益人／持有人比例、动态名义本金和股票市值，计算场外穿透比例；再加上匹配的前十大股东场内比例，输出合计超过 3% 的记录。证据：208230。

这支持原笔记对“表名容易误导”的质疑。更准确的文字是：**模型名写持股比例，实际承接监控标的清单；比例在下游计算。** 至于是否调整模型名称或设计，是另一个决定。

### 4. 交易日历

`t02_tit_scr_trd_cal` 不是单纯透传节假日：按市场计算交易日序号、前后交易日，以及周／月／季／年首末交易日。非交易日前后交易日使用一定日期窗口匹配；源节假日标志反转成交易日标志。证据：161255。

风控 `otc_deri_sett_abn_montr_indx` 使用这些日期关系检查延迟簿记、延迟平仓、公司行为调整和结算事件处理时点。它是用于判断“该什么时候处理”的参考资料，不是行情。证据：180692、180700、180714、181553、181555、181556。
