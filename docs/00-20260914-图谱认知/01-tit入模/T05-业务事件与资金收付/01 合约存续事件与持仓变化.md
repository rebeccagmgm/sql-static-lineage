# 01 合约存续事件与持仓变化

**合约事件用于记录合约建立及存续期间的业务事项，包括规模调整、终止、重置、公司行为、费用与收益等。** 本篇整理 TIT 普通互换、期权、极速互换的事件类型、字段含义和模型表达，并说明普通互换持仓变化的具体记录方式。

存续事件、腿、持仓及变动明细的概念关系，单独见 [01.1 存续事件与持仓明细的关系](00-20260914-图谱认知/01-tit入模/T05-业务事件与资金收付/01.1%20存续事件与持仓明细的关系.md)。

## 1. 对象与业务关系

源表位于 `ODATA_N_TIT`，模型位于 `PDATA_N`。

| 对象 | 一条记录表示什么 | 源表 → 模型表 |
| --- | --- | --- |
| 普通互换主事件 | 一次普通互换合约变化 | `D_TRD_TRS_EVENT → T05_OTC_COMP_DURA_CHG_EVT` |
| 期权主事件 | 一次期权合约变化，包含期权专门的本金、价格和公司行为信息 | `D_TRD_OPTION_EVENT → T05_OTC_COMP_DURA_CHG_EVT` |
| 极速互换主事件 | 一次极速互换变化 | `D_TRD_FAST_TRS_EVENT → T05_OTC_COMP_DURA_CHG_EVT` |
| 结构化腿变动明细 | 一次互换事件下，某条腿／持仓的数量与金额变化 | `D_TRD_TRS_EVENT_STRUC_DETAIL → T05_OTC_SWAP_COMP_HOLD_CHG_DET` |

三类合约的主事件共用 `T05_OTC_COMP_DURA_CHG_EVT`。本篇展开的结构化腿明细属于普通互换分支，期权和极速互换的具体内容按各自事件字段读取，不套用普通互换的明细关系。

普通互换的关联条件为 `主事件.Src_Id = 明细.Dura_Chg_Src_Id`，两侧同时限定普通互换来源；主事件与明细各有自己的 `Evt_Id`。

极速互换通过同日 `D_TRD_OTC_TRADE` 按产品编号补合约；结构化腿明细通过同日 `D_REF_TRS_LEG` 按腿编号补合约。辅助表在这里提供合约归属信息。

## 2. 字段与处理规则

### 2.1 先按事件类型理解业务事项

存续事件的作用并不相同：有些调整合约规模或持仓，有些重置条款，有些记录公司行为、费用或收益。先确定事件类型，再选择相关字段，才能知道这次事项具体改变了什么。

| 业务分类 | 事件类型代码与含义 | 阅读重点 |
| --- | --- | --- |
| 合约建立 | `new_contract` 新增合约 | 关联哪份合约，事件日期和建立时的业务内容 |
| 规模调整 | `buy` 加仓；`sell` 减仓；`notional_reset` 名义本金重置 | 名义本金前值、变动值、后值；涉及持仓时继续看腿明细 |
| 终止与观察期 | `partial_termination` 提前部分平仓；`early_termination` 客户提前终止；`termination` 合约到期；`cumulator_clearing` 观察期清算 | 区分具体终止或清算事项，读取对应的本金、持仓、定价及款项资料 |
| 条款重置 | `contract_reset` 合约重置；`interest_rate_reset` 利率重置 | 识别重置事项，结合合约资料理解相应条款 |
| 公司行为 | `corporate_actions` 公司行为；`cash_dividend` 现金红利；`dividend_stocks` 分红；`rationed_shares` 配股；`send_stocks` 送股；`share_capital_increase` 转增股本 | 相关标的、价格调整、数量或分红信息，按具体类型分别读取 |
| 费用与收益 | `fee_payment` 支付费用；`coupon` 债券付息；`income_stocks` 提取增强收益；`rebate_interest` 计提返息；`withdraw_interest` 利息提取；`trans_curr_bonus` 跨币种分红费用 | 费用或收益事项本身，以及相关支付计划、收付款 |

上表按事件类型代码 `CD375` 列示含义。普通互换、期权入模保留源类型原值，极速互换转小写；交易事件汇总使用 `PARTIAL_TERMINATION`、`NEW_CONTRACT` 等大写条件。查询时按具体来源保留大小写。

**类型说明发生什么，状态说明处理到什么阶段。** 源类型和状态分别引用 `TRS_EVENT_TYPE`、`TRS_EVENT_STATUS`。TIT 的状态通过各自来源的 `REF_CD_CVT_MAP` 转换，未命中时保留源 `EVENT_STATUS`，不能直接套用其他系统的状态含义。

`EVENT_REAL_TIME` 保存实际成交时间／审批结束时间，进入 `Appr_End_Time`。事件日期、处理状态与审批结束时间分别描述事项的业务日期和处理情况。

### 2.2 三类合约的字段如何进入共同模型

普通互换、期权和极速互换各有源事件记录，入模后共用一张主事件表。使用这张表时，同时保留合约类型和来源，才能正确解释各字段。

| 项目 | 普通互换 | 期权 | 极速互换 |
| --- | --- | --- | --- |
| 源主键 | `KEY_TRS_EVENT_ID` | `KEY_OPTION_EVENT_ID` | `KEY_FAST_TRS_EVENT_ID` |
| 模型 `Evt_Id` | `TIT229-事件日-源事件ID-合约ID` | `TIT230-事件日-源事件ID-合约ID` | `TIT337-事件日-源事件ID` |
| `Src_Id` | 源互换事件 ID | 源期权事件 ID | 源极速互换事件 ID |
| 合约 | `KEY_OTC_TRADE_ID`；非空时修饰符 `20206` | `KEY_OPTION_DEAL_ID`；非空时修饰符 `20207` | `KEY_INSTRUMENT_ID` 左连同日交易表的同名字段，取后者合约；非空时修饰符 `20206` |
| 事件类型 | `EVENT_TYPE` 原值 | `EVENT_TYPE` 原值 | `lower(EVENT_TYPE)` |
| 模型业务日期 | `EVENT_DATE` 截取到日 | 同左 | `Busi_Date` 为空，`Evt_Date` 仍取事件日 |
| 模型兑付日期 | `Pay_Date` 为空；源表的 `PAYMENT_DATE` 未承接到这列 | `PAYMENT_DATE` 截取到日 | 同期权 |
| 事件状态 | 按该来源的转换配置映射，未命中回退 `EVENT_STATUS` | 同左，使用期权来源的转换配置 | 空字符串 |
| 事件金额 `Evt_Amt` | `EVENT_AMOUNT`，本币事件金额 | `EVENT_FEE` | `AMOUNT` |
| 事件费用 `Evt_Fee` | `EVENT_FEE`，平仓费 | 空 | 空 |
| 名义本金前／变动／后 | `NOTIONAL_BEFORE/DELTA/AFTER` | 同左，另有绝对／动态本金 | 公共本金字段为空 |
| 币种 | `CURRENCY` | 公共 `Crrc_Cd` 为空；普通／特殊分红另有币种字段 | `SETTLEMENT_CURRENCY`；标的币种另取 `CURRENCY` |

`Evt_Amt` 的含义随来源而不同：普通互换承接本币事件金额，期权承接事件费用，极速互换承接自己的金额字段。阅读时先识别来源，再解释该列代表的业务内容。

### 2.3 期权事件具体记录哪些变化

期权事件除公共名义本金外，还保存提前终止定价、期初价重置、分红等专门内容。按事件类型选择对应的一组字段读取。

| 业务问题 | 源字段 → 模型字段 | 使用方式 |
| --- | --- | --- |
| 名义本金怎样变化 | `NOTIONAL_* → Adj_Frnt_Nom_Prin / Nom_Prin_Chg_Delta / Adj_Pst_Nom_Prin` | 分别读取前值、变动值、后值 |
| 绝对／动态本金怎样变化 | `ABS_NOTIONAL_*`、`DYNAMIC_NOTIONAL_*` → 各自对应三列 | 三套本金分别表达，不互相替代 |
| 提前终止怎样定价 | `EARLY_TERMINATION_PRICE`、`EARLY_TERM_INTRINSIC_VALUE`、`EARLY_TERM_PRESENT_VALUE` → 价格、内在价值、PV | 模型承接源结果，价格与金额区分单位 |
| 公司行为怎样影响期初价 | `INITIAL_PRICE_BEFORE_RESET/AFTER_RESET → Adj_Frnt_Bgng_Pric / Adj_Pst_Bgng_Pric` | 结合事件类型、除权除息日和标的读取 |
| 普通／特殊分红 | `CASH_*`、`SP_CASH_*` → 各自币种、汇率、结算金额 | 分别按对应的币种和汇率理解 |
| 生效更新是否完成 | `IS_TASK_FINISH_FLAG → Vld_Upd_Comp_Flag` | `Y → 1`、`N → 0`，其他值保留；表达生效更新情况 |

本金前后值与变动值是否可以直接做加减，要结合具体事件类型；生效更新标志与收付款状态分别读取。

### 2.4 普通互换的持仓变化落在哪些字段

主事件描述合约层面的事项；明细通过腿、持仓和标的编号定位具体变化对象，并保存数量前值、变动值、后值及明细金额。名义本金表达合约规模，持仓数量表达具体持有数量，两者分别读取。

| 源字段 | 模型字段 | 含义 |
| --- | --- | --- |
| `ID` | `Evt_Id = TIT215-ID` | 明细自身身份 |
| `KEY_TRS_EVENT_ID` | `Dura_Chg_Src_Id` | 引用主事件的 `Src_Id` |
| `KEY_LEG_POSITION_ID` | `Swap_Comp_Hold_Id` | 持仓身份 |
| `KEY_LEG_ID` | `Leg_Glbl_Seq_No` | 腿身份，按腿关联资料补合约 |
| `UNDERLYING_INS_ID` | `Src_Prd_Id`、带 `TIT-` 的 `Prd_Id` | 源标的与模型标的身份 |
| `QUANTITY/QUANTITY_BEFORE/QUANTITY_AFTER` | `Occu_Qty/Occu_Frnt_Qty/Occu_Pst_Qty` | 发生数量、变化前数量、变化后数量 |
| `AMOUNT/AMOUNT_ORG/CURRENCY` | `Occu_Amt/Ocrrc_Occu_Amt/Crrc_Cd` | 明细金额、原币金额和币种 |

### 2.5 数据日期与记录维护

主事件和明细读取指定源 `BUSI_DATE`，覆盖各自的 `SRC_TBL` 来源分区。模型保存该次装载后的内容，不为每次状态修改另存一条历史版本。

普通互换、期权模型的 `Busi_Date` 来自事件日期；它可以与源数据分区日不同。极速互换的 `Busi_Date` 为空，查事件日使用 `Evt_Date`。

## 3. 业务应用

### 3.1 理解加仓、减仓与名义本金调整

查看规模调整，先从主事件确定合约、事件类型、日期和处理状态，再读取名义本金前值、变动值和后值。这组字段表达合约规模的变化。

普通互换涉及具体持仓时，继续从结构化腿明细读取腿编号、持仓编号、标的编号，以及数量前值、变动值和后值。这样可以把合约层面的规模变化，具体定位到相关持仓和标的。

`notional_reset` 表达名义本金重置，应按该事件的本金字段理解；不能把所有规模调整都解释成买入或卖出某个标的。

### 3.2 理解提前终止与合约到期

先区分 `partial_termination`、`early_termination`、`termination`，明确记录的是提前部分平仓、客户提前终止还是合约到期。

期权提前终止还保存终止价格、内在价值和现值；这些字段帮助解释终止处理中的定价结果。普通互换则可结合主事件和腿明细，读取相关本金及持仓变化。

与终止相关的款项另在 Transfer 中保存。主事件的日期、状态、定价或金额信息，与收付款的支付日期、状态和金额各自表达不同内容；款项读取见 [02 收付款记录与金额口径](00-20260914-图谱认知/01-tit入模/T05-业务事件与资金收付/02%20收付款记录与金额口径.md)。

### 3.3 理解条款重置与公司行为

合约重置、利率重置首先是条款相关事项，应按事件类型识别处理内容，并结合合约资料读取相应约定。

期权公司行为中，`INITIAL_PRICE_BEFORE_RESET/AFTER_RESET` 保存期初价调整前后值；普通分红和特殊分红各自保存币种、汇率和结算金额。理解这些事件时，需要将事件类型、相关标的、除权除息日与对应字段一起阅读，而不是只关注持仓数量。

### 3.4 理解费用与收益事项

`fee_payment`、`coupon` 等类型标识费用或收益相关事项。主事件用于识别发生了什么及其处理情况；支付计划用于解释支付安排，Transfer 用于解释相关款项。

事件金额、平仓费、支付计划金额和收付款金额分属于不同字段和对象。先按本篇的来源对照识别事件字段，再按需要进入 [03 费用支付计划](00-20260914-图谱认知/01-tit入模/T05-业务事件与资金收付/03%20费用支付计划.md) 和 [02 收付款](00-20260914-图谱认知/01-tit入模/T05-业务事件与资金收付/02%20收付款记录与金额口径.md)。

## 4. 查询入口

### 4.1 源字段速查

下面按一个源业务日查看普通互换事件。日期按需要替换；源分区日期与事件日期分列保留。

```sql
SELECT KEY_TRS_EVENT_ID AS "源互换事件ID",
       KEY_OTC_TRADE_ID AS "源互换合约ID",
       EVENT_DATE AS "事件日期",
       EVENT_TYPE AS "事件类型原值",
       EVENT_STATUS AS "事件状态原值",
       NOTIONAL_BEFORE AS "调整前名义本金",
       NOTIONAL_DELTA AS "名义本金变动",
       NOTIONAL_AFTER AS "调整后名义本金",
       EVENT_AMOUNT AS "事件金额_本币",
       EVENT_AMOUNT_ORG AS "事件金额_原币",
       CURRENCY AS "币种",
       EVENT_FEE AS "平仓费",
       EVENT_REAL_TIME AS "实际成交时间_审批结束时间",
       BUSI_DATE AS "源业务日期"
FROM ODATA_N_TIT.D_TRD_TRS_EVENT
WHERE BUSI_DATE = '2026-09-15'
ORDER BY EVENT_TYPE, EVENT_STATUS, KEY_OTC_TRADE_ID, KEY_TRS_EVENT_ID
LIMIT 500;
```

T98 交易事件汇总的互换分支从明细出发，依次关联主事件、协议关系、合约和账簿，再按持仓编号及合约期初定价日查持仓。合约、账簿、腿取调度日，持仓取期初定价日，主事件和明细限定普通互换来源。

该分支对 `COUPON` 的变动金额取 `0`，其他分支使用：

```sql
abs(round(明细.Occu_Qty * 持仓.Bgng_Pric * nvl(合约.Lcrrc_Ori_Bgng_Rate, 1), 2))
```

同一汇总中的期权部分终止分支，变动金额使用 `abs(Nom_Prin_Chg_Delta) * (-1)`。它与互换按数量、价格、汇率计算的方式分别保留。

互换现金收付筛选 `TRS`、`Del_Flag=0`、状态 `VERIFIED`，按“支付日＋源事件号”汇总 `Aft_Adj_Amt`，再按源事件号连接。一个事件涉及多个支付日或多条明细时，结果会按这些组合展开，详见 [02 收付款](00-20260914-图谱认知/01-tit入模/T05-业务事件与资金收付/02%20收付款记录与金额口径.md)。

这一互换汇总还限定事件状态 `3`、部门 `GFS_FICC`、非虚拟账簿和合约状态非 `218`。这些条件共同确定该项汇总的业务范围。
