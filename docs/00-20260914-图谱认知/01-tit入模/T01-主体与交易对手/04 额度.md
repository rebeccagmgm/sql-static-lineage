# 04 额度

**TIT 客户资料中的授权额度、名义本金上限，与风险限额表中的指标阈值，是不同位置、不同粒度的业务信息。查额度先确定指标与适用业务；当前已查入模没有计算占用或剩余额度。**

```sql
SELECT
    CTPTY_ID AS "交易对手ID",
    APPROVED_TYPE AS "适用业务原码_按入模字段理解",
    LIMIT_INDEX AS "限额指标原码",
    UPPER(LIMIT_INDEX) AS "入模指标代码",
    LIMIT_INDEX_VALUE AS "指标值原值",
    CREATED_DATETIME AS "创建时间_入模选最新依据",
    UPDATED_DATETIME AS "修改时间",
    BUSI_DATE AS "业务日期"
FROM ODATA_N_TIT.D_RISK_CTPTY_LIMIT_THRESHOLD
WHERE BUSI_DATE = '2026-09-15'
ORDER BY LIMIT_INDEX, APPROVED_TYPE, CTPTY_ID
LIMIT 500;
```

## 1. 贴源与模型：客户层额度与风险指标分两条路径保存

### 1.1 涉及哪些贴源，各自记录什么

以下贴源均位于 `ODATA_N_TIT`。本篇有两处直接提供额度数值的来源；静态主体为客户资料入模补身份。

| 贴源表 | 保存内容与记录组织 | 本篇职责 |
| --- | --- | --- |
| `D_REF_CTPTY_EXT_PARAM` | 围绕 `KEY_CTPTY_ID` 保存客户条件，包括名义本金上限、授权额度及有效期 | 提供客户层直接约定的额度参数 |
| `D_REF_COUNTERPARTY` | 客户的主体身份 | 在 150757 中按同日 `ID = KEY_CTPTY_ID` 关联扩展参数，不是另一份额度数值来源 |
| `D_RISK_CTPTY_LIMIT_THRESHOLD` | 围绕客户 `CTPTY_ID`、指标 `LIMIT_INDEX`、业务原码 `APPROVED_TYPE` 保存指标值及记录时间 | 提供按指标和业务区分的风险阈值；同日同维度可能有多条候选记录 |

风险阈值源还保存初保线、追保线、同一客户和管理人等字段；本篇对应的额度入模只承接其中一部分，不能把整张源表的内容都当成额度模型已提供的信息。

### 1.2 两条路径分别落到哪里

| 模型表 | 源字段怎样进入模型 | 模型怎样组织这部分信息 |
| --- | --- | --- |
| `PDATA_N.T01_OTC_DERI_CUST` OTC 衍生品客户 | 150757：`NOTIONAL_LIMIT → Nom_Prin_Ulmt`；`GRANT_BALANCE → Auth_Lmt`；`GRANT_BALANCE_EXPIRE_DATE → Auth_Lmt_Vld_Pd` | 把名义本金上限、授权额度及有效期作为客户资料中的独立字段 |
| `PDATA_N.T01_PTY_LMT_H` 当事人额度历史 | 229973：`CTPTY_ID → Pty_Id`（加 `TIT060-`）；大写 `LIMIT_INDEX → Pty_Lmt_Type_Cd`；`APPROVED_TYPE → Perm_Busi_Type`；`LIMIT_INDEX_VALUE → Lmt` | 按“主体＋指标＋业务类型”分别选择记录并维护历史；同一客户可有多种指标 |

两条路径没有在这两段加工中相互校准或取最小值。`GRANT_BALANCE` 不能默认等于某一项风险阈值，客户表的金额也不能与额度历史各行相加为“总额度”。下面按指标含义、单位及版本选择继续解释风险阈值这条路径。

## 2. 一条风险阈值要带哪几个维度

| 源信息 | 入模表达 | 业务含义 |
| --- | --- | --- |
| `CTPTY_ID` | 加 `TIT060-` 前缀 → `Pty_Id` | 对哪个主体记录该项值 |
| `LIMIT_INDEX` | 转大写 → `Pty_Lmt_Type_Cd` | 指标是什么；大小写不同的同码会归入同一指标 |
| `APPROVED_TYPE` | 原样 → `Perm_Busi_Type` | 该指标对应的业务维度；具体枚举尚未核实 |
| `LIMIT_INDEX_VALUE` | 原样 → `Lmt` | 指标值；本段无单位换算 |

229973 用“主体＋大写指标码＋业务类型”选择记录。同一主体下的不同指标、不同业务各自保留，不能按主体只取一个最大值，也不能从不同业务记录里任意挑一条。

`APPROVED_TYPE` 的本地源注释带 AI 标记并称“审批类型”，SQL 却将它写入“允许业务类型”。本篇依据目标用法保留业务维度，暂不把它解释成通过、拒绝等审批状态；也不把它与业务授权表的 `ALLOWBUSITYPE` 当作同一枚举。

## 3. 额度指标字典里实际包含什么

下表列本地 **CD1562 当事人额度类型代码**中备注为“场外衍生品交易对手限额指标”的条目。含义采用字典标签；读法用于区分信息性质，尚未取得各指标的计算公式与单位。

| 指标代码 | 字典含义 | 阅读要点 |
| --- | --- | --- |
| `APPROVEDVALUE` | 获批额度 | 表达批准的额度值，不等于当前剩余可用值 |
| `CLIENTLIMIT` | 同一客户限额 | 涉及同一客户口径，归并规则需另查，不自动等于当前单一 TIT ID |
| `SINGLEPRODUCTLIMIT` | 单产品限额 | 限制维度为产品，不直接代表客户全部产品总额 |
| `SINGLEUNDERLYINGLIMIT` | 单标的限额 | 限制维度为标的；具体标的范围需结合业务定义 |
| `SINGLEUNDERLYINGCONCENTRATIONUPPERLIMIT` | 单标的集中度上限 | 与金额类限额分开读；比例存储尺度尚未确认 |
| `DOUBLECONCENTRATIONUPPERLIMIT` | 双创集中度上限 | 是集中度指标；“双创”范围与比例尺度需另查 |
| `USSTOCKLIMIT` | 美股限额 | 保留市场范围，不能并成通用限额 |
| `HKUSSTOCKLIMIT` | 美股期权限额 | 按字典解释；不能仅凭代码前缀改称“港美股限额” |
| `NETVALUE` | 产品净值 | 是基础量性质的指标，不能只因进入额度表就改称获批限额 |
| `ADMINISTRATORLIMIT` | 管理人限额 | 涉及管理人维度，不等于当前主体自行占用的金额 |
| `ADMINISTRATORLIMITQUANTIFY` | 管理人限制量化 | 字典只有该标签，不能补造成金额或比例公式 |
| `ADMINISTRATORQUANTIFY` | 管理人限制 | 与上一项分列，不能因名称相近合并 |
| `SINGLEUNDERLYINGLIMITQUANTIFY` | 单标的限额量化 | 具体量化口径未取得 |
| `SINGLEUNDERLYINGLIMITSPAN` | 单标限额距离 | 距离的参照量和算法未取得，不当作剩余额度 |

同一代码域还包含交易对手授信、股票质押信用及交易额度等其他条目；本地字典有这些值，不证明它们实际出现在此 TIT 阈值来源中。上表也不是当前源样本的实际取值清单。

**单位目前不能统一补成“元”“万元”或“%”。** 229973 将指标值直接写入 `Lmt`，币种字段为空；现有字典没有给出这些指标的存储单位。使用金额、比例、净值等不同性质的值时，应保留指标代码，待源定义或明确的消费换算支持后再规范单位。

## 4. 最新记录选择对额度解释有什么影响

实际选择逻辑为：

```sql
ROW_NUMBER() OVER (
    PARTITION BY CTPTY_ID, UPPER(LIMIT_INDEX), APPROVED_TYPE
    ORDER BY CREATED_DATETIME DESC
) AS RN
-- 在指定 BUSI_DATE 内，仅保留 RN=1
```

这里选的是**当日来源中，同一主体、指标、业务类型下创建时间最新的一条**。没有按 `UPDATED_DATETIME` 取最新修改，也没有读取审批通过标志。若业务维护以修改旧记录为主，不能把“最新创建”口头改成“最新审批有效”；创建时间相同的候选也没有第二排序字段来确定选择。

入模随后按相同三维度维护模型历史。对业务最重要的区别是：客户资料中的 `GRANT_BALANCE_EXPIRE_DATE` 是源授权额度有效期，而本阈值分支的 `Lmt_Eff_Date / Lmt_Exp_Date` 都为空。模型历史区间表达数据版本，不能据此补出额度批准日或授权到期日。

## 5. 阈值、占用、剩余分别还需要什么信息

| 信息 | 当前资料能否提供 | 业务解释 |
| --- | --- | --- |
| 指标阈值或配置值 | 可以，按指标取 `LIMIT_INDEX_VALUE` | 说明该维度保存了哪个值，性质由指标决定 |
| 实际占用 | 此入模未计算 | 需要实际交易、持仓或风险暴露，以及同一客户、标的、业务范围的占用规则 |
| 剩余额度 | 此入模未计算 | 需要同口径有效额度与占用，并确认调整规则；不能把任意两列相减 |
| 是否超限 | 此入模未判断 | 要匹配指标、主体归并、业务范围、单位和时点，才能进行阈值比较 |

例如客户同时有单标的限额与单标的集中度上限，它们描述不同约束，不能相加成“总额度”；`NETVALUE` 即使存入 `Lmt`，也不能被当成可再使用的获批额度。

源表还包含 `INITIAL_MARGIN`、`MARGIN_CALL`、`MARGIN_CALL_FLOOR`、`WITHDRAW_FLOOR`、`MARGIN_MODE` 等履保字段，以及同一客户、管理人信息。**229973 的取数映射没有承接这些字段**。所以查 `T01_PTY_LMT_H` 不能期待同时得到初保线、追保线或管理人归并规则；这些资料要回源或继续查其专门加工。

### 资料来源与取用边界

依据本地 SQL 229973、150757，及 CD1562 中备注为场外衍生品交易对手限额指标的 `MANU_MATN` 记录（业务日期 2026-04-03）。源表部分注释带 AI 标记，仅作字段定位，不作为指标算法、审批语义或单位的确认依据。

本批尚无风险阈值与客户扩展参数的业务行样本，故未构造真实额度算例。已查同名额度表的其他任务包含融资融券、其他 schema 等分支，不能作为本 TIT 阈值已被消费的证明。实际消费中的单位换算与占用计算尚未确认。入口见 [本地 SQLite 查询导航](../../../local-sqlite-guide.md)。
