# T06 区域范围说明

**T06 是区域主题。当前明确的核心模型是行政区域表，用来统一表达省、市、区县等区域的编号、名称和层级关系，供客户、机构等业务资料引用。** 本篇说明它在模型体系中的位置，以及与本次 TIT 入模范围的关系。

## 1. 贴源与模型：区域资料从哪里来

| 层次 | 表或加工 | 保存与处理的内容 |
| --- | --- | --- |
| 已核实贴源 | `ODATA_N_SIP.F_WEBDATA_RPA_XZQH_CODE` | 行政区划资料，属于 SIP/RPA 来源 |
| 加工入口 | 61790 | 整理区域字段，并在指定来源分区内比较新旧记录、维护模型数据 |
| 核心模型 | `PDATA_N.T06_ADMIN_AREA` 行政区域 | 保存区域身份、名称、层级、省市归属与上级区域引用 |

已有资料还记录了模型中的 `MANUAL` 来源分区。因此，上面是已核实的一条生产路径，不能把整张区域模型都视为这一个贴源的复制。

这里描述的是区域本身。一条行政区域记录以 `ADDR_ID` 表达区域身份；理解数据时还需保留 `SRC_TBL` 来源分区。它不以客户、交易对手、机构或合约为记录主体。

## 2. 区域编号、所属省市、直接上级各有什么用

| 字段 | 含义 | 阅读作用 |
| --- | --- | --- |
| `ADDR_ID` | 地址编号，在本表中用于标识行政区域 | 确定具体区域对象 |
| `ADMIN_AREA_NAME` | 行政区域名称 | 展示该区域的名称 |
| `ADMIN_AREA_LVL_CD` | 行政区域层级代码 | 区分记录所处层级，不能只从名称判断 |
| `PROV_ID`、`CITY_ID` | 所在省份、所在地市 | 保存省市归属，便于按相应区域汇总或展示 |
| `UPPER_ADDR_ID` | 上级行政区域编号 | 表达直接上级，用于理解区域层级关系 |

以“广东省—广州市—天河区”作概念示意：天河区是一个区域对象，有自己的编号；所属省、市说明归属，直接上级说明它在层级结构中的上一层。**自身编号、所属省市与上级编号各有职责，不能互相代替。** 这个例子只帮助理解字段，不代表本篇已核验这几条实际数据或所有层级规则。

## 3. 它怎样与客户、机构资料配合

客户资料中的“注册地址”、机构资料中的“办公地址”，描述的是某个业务对象的地址；T06 提供这些地址可能引用的标准区域信息。例如，客户资料保存一个区域编号，关联区域模型后可以补出区域名称或归属信息，再按省市组织查询。

这也解释了两者为什么分别建模：区域的名称、层级和上下级关系可以被多个客户、机构共同引用；具体客户的街道、门牌及地址用途仍由客户地址资料表达。**不能因为 `ADDR_ID` 叫“地址编号”，就把 `T06_ADMIN_AREA` 当成客户详细地址表。**

实际关联要看各业务来源保存的是区域编码、名称还是需要先转换的代码。本篇没有建立 TIT 客户与区域表之间已经验证的通用关联键，也不把资料中出现省份字段等同于已经进入 T06。

## 4. 为什么本次 TIT 文档单独保留这篇

当前 TIT 入模盘点覆盖的候选中，**尚未发现 TIT 直接写入 T06 的证据**；上面已核实的区域生产来自 SIP/RPA。因此，本篇帮助读者认识区域主题，不将这些其他来源计入 TIT 的入模表或任务数量。

这表示本次来源范围没有命中直接路径，不表示区域模型不存在，也不表示 TIT 业务永远不会引用区域资料。经过其他模型的间接关系仍未穷尽。

本篇保持一页说明即可：认识区域对象、核心模型及来源边界。详细区划加工、各系统地址匹配和区域维护规则，留到确有使用需求时再展开。
