# TIT 关键入模链路

以下分别解释源业务对象、模型粒度与字段形成方式。SQL 摘录见 [固定版本与原始证据](证据/关键SQL与缺口核对.json)；图谱查询均使用当前发布版本，五条代表字段查询未触及查询截断限制。未截断不代表所有源边界、运行状态或业务约束都已证明。

## 1. T01：交易对手中的个人如何形成当事人

任务 **104298** 实际读取 `odata_n_tit.d_ref_counterparty`，按业务日期和 `CTPTY_TYPE='INDIVIDUAL'` 选取个人记录，写入 `pdata_n.t01_indv`。模型当事人编号为 `CONCAT('TIT060-', ID)`，姓名取 `LONG_NAME`；出生日期、性别等多项字段在这条分支中填空，不能因为进入“个人”模型就认为信息完整。

输出采用 `busi_date + src_tbl` 分区；SQL 以当事人编号与上一交易日记录比较，区分新增、删除、变化和不变。这里解释的是每日快照加工，不能一概称为区间历史。

有一个直接影响源归属的事实：它的 `FROM` 是 **`d_ref_counterparty`**，写入 `src_tbl` 却仍标 **`d_ref_counter_party`**。后者还存在独立的旧分支任务 105075。两张名字相近的源表不能合并，也不能用来源分区标签覆盖实际读取。

图谱对 `pty_id` 已追到 `titans_dm.ref_counterparty.id`，经采集任务 213687 进入贴源，再由 104298 加前缀形成模型键。见 [字段追溯](证据/图谱-104298-pty_id.json)。

## 2. T02：产品记录与业务产品编号是两个键

任务 **160750** 从 `odata_n_tit.p_prd_product` 取指定业务日期的记录，写入 `pdata_news_n.t02_tit_prd_info`。

| 模型字段 | TIT 源字段 | 含义与边界 |
|---|---|---|
| `rec_id`、`src_rec_id` | `id` | 来源记录身份 |
| `prd_id` | `key_prod_id` | 产品业务编号；不与记录 ID 混用 |
| `book_id` | `key_book_id` | 关联账簿的编号；本任务没有展开账簿关系 |
| `prd_tot_nom_prin` | `total_notional` | 直接映射的总名义本金，没有在这里重算 |
| `val_date`、`maty_date` | `start_date`、`end_date` | 通过 `default.date2datekey` 转换 |

输出覆盖 `src_id='TIT', grp_id='01'` 分区，业务日期保留为普通数据字段。不能把这个输出分区误解为按 `busi_date` 保留全部每日历史。

原库上游保留两条：`titans_dm.prd_product` 与 `titans_product.prd_product`，分别通过任务 156659、211524 写入同一贴源对象。当前静态接续接受两条路径；尚未确认哪个任务当前在用。见 [字段追溯](证据/图谱-160750-prd_id.json)。

## 3. T03：互换协议的持有人来自账簿连接

任务 **103930** 以 `odata_n_tit.d_ref_trs` 为主输入形成 `pdata_n.t03_agt`：`Agt_Id=KEY_OTC_TRADE_ID`，`Agt_Modifr='20206'`，`Agt_Type_Cd='20206'`。协议身份应保留编号与修饰符，不能跨协议类型只用编号拼接。

```sql
-- 固定版本 create 槽 28～59 行的核心关系，省略快照日期与其他字段
A.KEY_OTC_TRADE_ID                       AS Agt_Id,
'20206'                                 AS Agt_Modifr,
CONCAT('TIT060-', C.KEY_CTPTY_ID)         AS Agt_Holder,
NVL(D.DW_CD_VAL, A.CONTR_STATUS)          AS Agt_Stat_Cd
-- A: d_ref_trs
-- A.KEY_OTC_TRADE_ID = B.KEY_OTC_TRADE_ID，B: d_trd_otc_trade
-- B.KEY_BOOK_ID = C.KEY_BOOK_ID，C: d_ref_book
```

因此 `Agt_Holder` 的值来自 **账簿表的 `KEY_CTPTY_ID`**，交易父表用于连接；不能因为三个表同任务共现，就把它们全部当作该字段的值来源。

状态字段通过 `pdata_n.ref_cd_cvt_map` 匹配目标表、目标字段、源表、源字段和源系统；没有匹配时回退到源 `CONTR_STATUS`。SQL 证明转换规则存在，尚无 TIT 转换表全量实值证明转换覆盖率。

图谱的 `agt_holder` 值路径已追到 `titans_dm.ref_book.key_ctpty_id`。该值路径不会替代 Join 条件解释；两个采集写入均保留，未选取唯一生产者。见 [字段追溯](证据/图谱-103930-agt_holder.json)。左连接是否一对一、是否造成扩行，仍需业务行数据核验。

## 4. T04：机构来自配置对象，名称来自字典

任务 **165634** 从 `odata_n_tit.d_bk_department_properties` 分别取去重后的 `DEPARTMENT` 和 `COMPANY`，以 `UNION ALL` 合并为内部机构候选。`Inr_Org_Id` 取该编号，机构类型按 `Department/Company` 映射为 `620/621`。

名称来自另一张 TIT 表：`d_cfg_dictionary_desc.DICT_ITEM_LABEL`。连接同时使用 `ID=DICT_ITEM_NAME` 和 `TYPE=DICT_NAME`，代码域不能省略。图谱对 `inr_org_name` 的值来源也落在字典表，而非部门配置表，见 [字段追溯](证据/图谱-165634-inr_org_name.json)。

两个分支内部的 `DISTINCT` 不证明公司编号与部门编号跨类型唯一；后续历史比较按 `Inr_Org_Id` 连接，唯一性仍待业务数据验证。

同属 T04 的任务 **159422** 将 `a_adm_user.KEY_USER_ID` 加 `TIT007-` 前缀形成 `t04_user.User_Id`，将 `STATUS` 经转换表映射为用户状态，未匹配时回退原值。这条线描述系统用户身份；不能与 T01 的交易对手身份混用。

## 5. T05：收付款事件保留多种日期与金额角色

任务 **104934** 从 `odata_n_tit.d_trd_transfer` 形成 `pdata_n.t05_otc_recv_pymt_evt`。`Evt_Id=CONCAT('TIT157-', TRANSFER_ID)`；交易号、合约号、账簿号、产品号及当事人号分别保留，不以同一个“合约 ID”替代。

`PAYMENT_DATE`、`CLEARING_DATE`、`ACTUAL_PAYMENT_DATE` 分别进入支付日期、清算日期、实际支付日期。它们说明事件的不同时间属性；有某个日期字段不能证明已经付款成功。

常规金额字段为 `PAYABLE → Our_Payb_Amt`、`RECEIVALBE → Our_Rcvb_Amt`。但调整后字段存在值得核对的方向命名：`AMOUNT_RECEIVALBE → Aft_Adj_Our_Payb_Amt`，`AMOUNT_PAYABLE → Aft_Adj_Our_Rcvb_Amt`。先保留 SQL 事实，不能凭英文字段名直接判业务错误。

固定版本中，这段源读取没有 `busi_date` 过滤；不能声称所有 TIT 入模都是“读取当日分区”。也不能在没有运行数据时断言它必然重复或错误。图谱对事件键已追到 `titans_dm.trd_transfer.transfer_id`，见 [字段追溯](证据/图谱-104934-evt_id.json)。

## 6. TIT 可以只为其他来源模型补充信息

任务 **168302** 的主输入是 LBR 来源的权益因子定义，TIT 的 `d_cfg_dictionary_desc` 只为交易所补充说明：过滤 `DICT_NAME='EXCHANGE'`，按市场代码连接，读取 `DICT_ITEM_COMMENTS`。它应描述为“TIT 字典参与模型加工”，不能把整个模型归给 TIT。

当前发布投影对该任务保留了异常的候选数据集身份，不能据 `PROJECTED` 状态宣称该分支图谱完整。业务解读使用固定 SQL，图谱缺口另列。
