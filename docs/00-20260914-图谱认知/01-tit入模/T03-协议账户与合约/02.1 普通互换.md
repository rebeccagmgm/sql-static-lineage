## 1. 对象与关联

**`D_REF_TRS` 是 TRS 合约头层的业务记录**，集中保存合约身份、交易对手、资金账户、交易条款、名义本金、币种和生命周期。腿明细、账簿归属、估值及结算结果通过其他表补充。

| 信息    | 关键字段或关联                                                                      | 业务含义                                                          |
| ----- | ---------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 合约身份  | `KEY_OTC_TRADE_ID`、`CONTRACT_CODE`                                           | 前者是内部交易流水号，后者是对外合约编号；关联内部交易用前者                                |
| 交易对手  | `KEY_CTPTY_ID`、`SELLER`、`PARTY`                                              | 分别记录交易对手、卖方主体引用、我司甲乙方身份，三者不能互相替代                              |
| 资金账户  | `KEY_CAPITAL_ACCT_ID`                                                        | 合约引用的资金账户；与 `KEY_ACCOUNT_ID`、银行账号字段分开                         |
| 合约组合  | `BUNDLE_ID`、`TRS_BUNDLE_TYPE`                                                | 组合标识及分类；不是账簿 ID                                               |
| 账簿归属  | TRS → `D_TRD_OTC_TRADE` → `D_REF_BOOK`                                       | 先按 `KEY_OTC_TRADE_ID` 关联交易，再按交易的 `KEY_BOOK_ID` 关联账簿，各表取相同业务日期 |
| 合约间关系 | `ARBITRAGE_CONTRACT_ID`、`ROLLOVER_INTERNAL_TRADE_ID`、`COVERED_CALL_CONTRACT` | 分别表达配对、被展期、备兑合约引用，不合并为一种关系                                    |

本份数据为单一业务日期下的 500 条合约记录。跨日保存时需保留 `BUSI_DATE`；`VERSION_CODE` 也不能直接当作数仓历史版本主键。

## 3. 合约生成渠道：这笔合约怎样产生

`SOURCE_CHANNEL` 直接进入 `Comp_Create_Chan_Cd`，对应代码域 **`CD1764`（合约生成渠道）**。它描述创建路径，和 `DATA_SOURCE` 的来源系统、`TRS_TYPE` 的业务类型是三个不同维度。

| 本份数据中的代码                  | 字典含义                             |
| ------------------------- | -------------------------------- |
| `COPY`                    | 复制                               |
| `DOMESTIC_SWAP_EOD`       | 境内互换日终流水                         |
| `EXCEL_IMPORTED`          | Excel导入                          |
| `FAST_ROLLOVER`           | 快速展期                             |
| `N_CROSS_EQUITY_O32_EOD`  | 北上跨境O32日终流水                      |
| `N_CROSS_EQUITY_QFII_EOD` | 北上跨境中信QFII日终流水                   |
| `N_CROSS_FUTURE_EOD`      | 固收北上期货日终流水                       |
| `N_CROSS_STOCK_BANK`      | 北上借券日终流水                         |
| `S_CROSS_EQUITY_EOD`      | 港美股日终流水                          |
| `S_CROSS_FUTURE_EOD`      | 境外期货日终流水                         |
| `STOCK_BANK`              | 股票银行                             |
| `X_BOND`                  | TRS利率债                           |
| `OPTION_MARGIN_EOD`       | 本地 `CD1764` 及本次源字典 CSV 均未命中，保留原码 |

`DATA_SOURCE_ID` 需要结合渠道解释：字段元数据注明，展期和复制时为合约 ID，其余为流水 ID。因此不能对所有记录都把它作为合约外键。`FAST_ROLLOVER` 表达创建渠道，`ROLLOVER_INTERNAL_TRADE_ID` 表达被展期合约引用，两者职责不同。

## 4. 身份、状态与其他码值

| 字段 | 已核对的含义 | 依据或边界 |
|---|---|---|
| `PARTY` | `PARTY_A` 甲方、`PARTY_B` 乙方；表示我司身份 | 源字段注释与同日源字典 `Party`；我司为乙方时不能仍按“甲方支付＝我司支付”解释 |
| `CLEARING_HOUSE` | 使用甲方/乙方身份枚举 | 字段注释及同日源字典 `ClearingHouse`；不是一个可直接关联外部清算所的机构编号 |
| `CONTR_STATUS` | `DRAFT` 草稿；`TOTRADE` 待交易；`EFFECTIVE` 生效；`TERMINATED` 终止；`CANCELED` 作废 | 同日源字典 `ContrStatus`；本份合约数据仅出现生效、终止，入仓状态还经过转换表 |
| `TERMINATION_TYPE` | `EARLY_TERMINATION` 客户提前终止；`TERMINATION` 合约到期；`KNOCK_OUT` 合约敲出 | `CD706`；最后一种为字典补充，未出现在本份数据中 |
| `CONTRACT_USE` | `FEE_SWAP` 互换费用 | `CD1763`（合约用途）；不能套用 `TRS_TYPE` 同名代码的域 |
| `FX_RATE_MODEL` | `MID` 中间价；`SHANGHAI_HONGKONG_STOCK_CONNECT` 沪港通；`SHENZHEN_HONGKONG_STOCK_CONNECT` 深港通 | SQL 进入 `Rate_Mode_Cd`，`CD1036` 标签可匹配；仓库域名为“利率模式”，与源字段“汇率模式”存在命名差异 |
| `CROSS_CURRENCY_TYPE` | 本份数据有 `FLEXO`、`COMPOSITE` | 已确认进入 `Cros_Crrc_Type_Cd`，本次源字典未命中跨币种域；`SettlementTypeEnum.COMPOSITE` 的说明为“复合”，属于交收类型，不能跨域套用 |
| `REPEAT_CHECK_STATUS` | 本份数据出现 `PASS`；源复核状态需转为仓库复核状态 | SQL 使用 `REF_CD_CVT_MAP`；源字典 CSV 未命中 `PASS`；`CD398` 存数字状态码，不能未经映射把 `PASS` 指定为某一数字码 |

`TRS_BUNDLE_TYPE`、`RELATE_PRODUCT_TYPE`、`FUND_SETTLEMENT_TYPE` 在本份数据中为空，不能据此认定系统没有对应功能或字典。`NOTIONAL_CHECK_STATUS=PASS` 也不等于复核通过或合约生效，应保留各自审核环节。

## 5. 条款、生命周期与金额口径

### 日期与状态

- **约定安排**：`TRADE_DATE` 为交易达成日，`START_DATE / END_DATE` 为期初/期末定价日，`PAYMENT_DATE` 为兑付日；定价结束与兑付不是同一时点。
- **实际处理**：`INPUT_DATE` 为实际审批生效日，另有首次生效、平仓生效、提前终止和估值终止日期，各自描述不同环节。
- **提前终止条款与结果分开**：`EARLY_TERMINABLE` 表达是否允许，`TERMINATION_TYPE / EARLY_TERMINATION_DATE` 表达终止方式及日期。合约终止也不单独证明资金已交收。

### 名义本金与币种

原始/动态名义本金、原币/本币/结算币种口径应同时保留。它们不能直接混加，也不能将名义本金当作结算金额或损益。

| 字段 | 当前加工 SQL 的口径 |
|---|---|
| `NOTIONAL_ORG / DYNAMIC_NOTIONAL_ORG` | 原币名义本金 / 原币动态名义本金 |
| `NOTIONAL_BASE / DYNAMIC_NOTIONAL_BASE` | 本币名义本金 / 本币动态名义本金 |
| `NOTIONAL / DYNAMIC_NOTIONAL` | 结算币种名义本金 / 结算币种动态名义本金 |
| `NOTIONAL_RMB` | 人民币名义本金字段，独立保留 |

**中文别名已按入模口径修正**：`NOTIONAL`、`DYNAMIC_NOTIONAL` 分别标为“名义本金(结算币种)”“动态名义本金(结算币种)”；`ACTUAL_PAYMENT_DATE` 标为“实际终止日期(入模口径)”。文首 SQL 与整理版 CSV 同步使用这些名称。原注释中的本币/日期误标及“实际兑付日”称谓不再直接作为正文定义；该修正依据 `103941` 的目标字段映射，不代表已验证源系统实际兑付与终止日期相同。

## 6. 入模关系

| 目标 | 主要表达 |
|---|---|
| `T03_AGT` | 内部交易流水号作为 `Agt_Id`，修饰符 `20206`；持有人经交易→账簿取得，与合约交易对手分开 |
| `T03_OTC_SWAP_COMP_INFO` | 互换类型、生成渠道、本金、币种、日期和控制属性等合约详情 |
| `T03_AGT_RELA_H` | `A17`：TRS→资金账户；`N08`：TRS→配对合约；`N03`：TRS→账簿，最后一项来自交易表 |

`BUNDLE_ID` 虽存在于源表，但所查关系 SQL 的组合关系分支已注释，不能把该分支当作已生产的关系。合约主信息、资金账户关系和账簿关系来自不同加工分支，查询时需同时限定关系类型及对象修饰符。
