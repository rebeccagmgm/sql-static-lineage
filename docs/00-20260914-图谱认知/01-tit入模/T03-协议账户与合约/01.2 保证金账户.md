# 01.2 保证金账户

**保证金账户是用于交易对手保证金管理的账户对象。** 本篇讲账户身份、持有人与账户代码；保证金余额、组合履保结果及追保安排分别属于金额或业务安排资料。

## 1. 来源与入模分工

原库逻辑表沿用已有资料：`titans_dm.margin_account`；贴源表为 `ODATA_N_TIT.D_MARGIN_ACCOUNT`。

| 保存的内容 | 入模表 | 调度 ID | 取数逻辑 |
| --- | --- | --- | --- |
| 账户身份、持有人、币种和启用状态 | `PDATA_N.T03_AGT` | 103928 | 身份任务用源表参数读取账户主资料 |
| 协议持有人关系 | `PDATA_N.T03_AGT_PTY_RELA_H` | 103931 | 账户编号关联 `KEY_CTPTY_ID`，关系类型固定 `01` |
| 保证金账户代码 | `PDATA_N.T03_AGT_STATI_INFO_H` | 103939 | `MG_ACCT_CODE` 写入补充信息，类型固定 `04` |

## 2. 三个编号各自表示什么

| 信息 | 源字段 | 入模表达 |
| --- | --- | --- |
| 保证金账户内部编号 | `KEY_MRG_ACCT_ID` | 写入 `Agt_Id`，三项任务的修饰符均为 `10219` |
| 持有人编号 | `KEY_CTPTY_ID` | 加 `TIT060-` 前缀，进入主表 `Agt_Holder` 或关系表 `Pty_Id` |
| 保证金账户代码 | `MG_ACCT_CODE` | `103939` 写入 `Stati_Qty_Info`；虽然目标字段名含“数值”，这里保存的是账户代码 |

内部编号用于识别账户，账户代码是补充属性，持有人编号用于识别当事人，三者不能互换。

身份任务 `103928` 将 `CURRENCY` 原样写入币种；将创建时间的日期部分转换后写入 `Vld_Date`；将 `ENABLED` 按 TIT、`MARGIN_ACCOUNT.ENABLED → T03_AGT.Agt_Stat_Cd` 转码，标准码为空时保留源值。已查三个任务的源取数段均没有显式源业务日或“仅启用账户”筛选。

**一个需要保留的实现差异：** `103928 / 103931` 的 `Agt_Type_Cd` 为 `10219`，`103939` 则写 `10217`，但后者的 `Agt_Modifr` 仍为 `10219`。这里按 SQL 原值记录，不把两列自动视为相同，也不据此推导新的账户类别。

## 3. 与资金账户、合约及组合怎样区分

资金账户和保证金账户分别使用 `KEY_CAPITAL_ACCT_ID`、`KEY_MRG_ACCT_ID`。同一交易对手可以出现在不同账户资料中，但共同持有人不能证明两个账户直接从属或一一对应。

本次三项入模保存账户主资料与持有人、代码，不生成保证金账户到某份合约、CSA 或履保组合的关系。旧稿关于这些关系的追问保留在 [账户与账簿的原始笔记](01%20账户与账簿.md#3-原始账户观察笔记)；组合成员、履保参数及每日结果的职责见 [全貌](00%20协议账户与合约全貌.md#52-组合身份成员参数结果与追保安排分开)。
