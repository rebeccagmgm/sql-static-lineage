# 06.1 业务分类

**协议分类回答：按哪个维度看，这份合约属于哪一类。** 本次包括合约业务类型、SBL 合约类型、SBL 结算类型，写入 `PDATA_N.T03_AGT_CLAS_H`。

## 1. 分类维度与分类值

| 字段 | 字典域 | 表达什么 | 例子 |
| --- | --- | --- | --- |
| `Agt_Clas_Type_Cd` | CD632 协议分类类型代码 | 按哪个维度分类 | `05`：场外合约业务类型 |
| `Agt_Clas_Cd` | CD799 协议分类代码 | 该维度下的具体分类值 | `TRS_ISDA`：互换-ISDA |

例如，`05 + TRS_ISDA` 才完整表达“这份合约的业务类型是互换-ISDA”。分类维度 `05` 不等于具体业务类型，也不替代 `Agt_Type_Cd` 中的互换／期权／外汇远期对象类型。

本地 CD632 的九个码值如下，本次使用 `05 / 06 / 07`：

| 分类类型代码 | 字典正式名称         | 本次使用 |
| ------ | -------------- | ---- |
| `01`   | 金证条件单用户认证类型    | —    |
| `02`   | 金证条件单用户        | —    |
| `03`   | 资管客户           | —    |
| `04`   | UFT柜台账户        | —    |
| `05`   | 场外合约业务类型       | 是    |
| `06`   | 场外互换SBL合约类型    | 是    |
| `07`   | 场外互换SBL合约结算类型  | 是    |
| `08`   | 股票质押合约成本利率合约类型 | —    |
| `13`   | 股票质押合约资产风险类别   | —    |

## 2. 各分类的取数规则与具体码值

**合约的实际分类值取自业务源字段，字典负责解释代码含义。** 以下规则共同适用：

- 源表均位于 `ODATA_N_TIT`，取 `BUSI_DATE = 加工日期`；`KEY_OTC_TRADE_ID` 进入目标表的 `Agt_Id`。
- 各分支固定 `Agt_Clas_Type_Cd`，将对应源字段原样写入 `Agt_Clas_Cd`，不按字典过滤或转码；源空值也不会由字典补齐。
- 字典按 CD799 备注指定的分类维度分组：本地共 28 项，本页列出 `05 / 06 / 07` 对应的全部 22 项。字典有定义不等于源数据已使用，其他维度及备注未明确维度的值不列入。

### 2.1 业务类型（05）：从交易表取 BUSINESS_TYPE

**分类类型固定为 `05`，分类值取这份合约的 `BUSINESS_TYPE`。** 下列 17 个字典值共用这一规则，SQL 不按 `OPTION_`、`TRS_`、`SBL_` 等前缀另选来源表。

| 取数分支 | 分类值的直接来源 | 取数范围 | 调度 ID |
| --- | --- | --- | --- |
| 普通交易分支 | `D_TRD_OTC_TRADE.BUSINESS_TYPE` | 加工日交易记录 | 106661 |
| PB 交易分支 | `D_TRD_OTC_TRADE_PB.BUSINESS_TYPE` | 加工日且 `GRP_ID='h15'` 的交易记录 | 144287 |

#### 协议类型与修饰符如何确定

同一批交易记录还需识别 `Agt_Type_Cd / Agt_Modifr`：按同日 `KEY_OTC_TRADE_ID` 左关联以下合约表，以首个匹配结果赋值。关联表负责识别合约类别，`Agt_Clas_Cd` 仍取交易表的 `BUSINESS_TYPE`。

| 匹配顺序／合约类别 | 106661 关联表 | 144287 关联表 | 协议类型／修饰符 |
| --- | --- | --- | --- |
| 1．普通互换 | `D_REF_TRS` | `D_REF_TRS_PB` | `20206` |
| 2．期权 | `D_REF_OTC_OPTION_DEAL` | `D_REF_OTC_OPTION_DEAL` | `20207` |
| 3．外汇远期 | `D_REF_FX_FORWARD` | `D_REF_FX_FORWARD` | `20208` |
| 4．极速互换 | `D_REF_FAST_TRS` | `D_REF_FAST_TRS_PB` | `20206` |

均未匹配时，协议类型及修饰符为空字符串，交易记录仍保留。144287 的三个 `_PB` 表（交易表、普通互换表、极速互换表）均额外限定 `GRP_ID='h15'`。

### 2.2 SBL 类型与结算类型（06、07）：从同一合约记录取两个字段

> **SBL 在证券业务中通常指证券借贷（Securities Borrowing and Lending）**，直观理解就是“借入／借出证券，之后按约定归还”

**任务 139853 读取 `D_REF_SBL`，分别生成分类 `06` 和 `07`。** 两个分支均要求源记录按 `KEY_OTC_TRADE_ID` 内关联到同日 `D_REF_TRS`；未匹配则不进入这两个分支。协议类型及修饰符固定为 `20206`，分类值分别取下表字段。

| 分类维度 | 分类值的直接来源 | 分类值 | 字典正式名称 |
| --- | --- | --- | --- |
| `06`：场外互换 SBL 合约类型 | `D_REF_SBL.SBL_TYPE` | `HKS_RSBL` | HKS_RSBL |
| `06`：场外互换 SBL 合约类型 | `D_REF_SBL.SBL_TYPE` | `USS_RSBL` | USS_RSBL |
| `07`：场外互换 SBL 合约结算类型 | `D_REF_SBL.SETTLEMENT_TYPE` | `DAD` | 见款付券 |
| `07`：场外互换 SBL 合约结算类型 | `D_REF_SBL.SETTLEMENT_TYPE` | `FOP` | 纯券过户 |
| `07`：场外互换 SBL 合约结算类型 | `D_REF_SBL.SETTLEMENT_TYPE` | `PAD` | 见券付款 |

例如，满足匹配条件的 SBL 记录若有 `SBL_TYPE='HKS_RSBL'`、`SETTLEMENT_TYPE='FOP'`，就为同一 `Agt_Id` 分别生成 `06 + HKS_RSBL` 和 `07 + FOP` 两条分类记录。该示例说明 SQL 规则，不代表已查到这份合约的实际数据。

字典未进一步解释 `HKS_RSBL / USS_RSBL`，这里保留原文。同名 `SETTLEMENT_TYPE` 在其他产品中可能属于其他字典域，本节含义仅适用于 CD799 明确标注分类 `07` 的记录。
