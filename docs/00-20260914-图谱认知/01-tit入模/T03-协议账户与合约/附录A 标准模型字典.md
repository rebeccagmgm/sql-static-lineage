## 2. 先懂代码域：`06` 本身没有唯一含义

代码必须与字段及代码域一起读。例如：

| 完整读法 | 含义 |
| --- | --- |
| 当事人关系 CD050 / `06` | 协议交易对手 |
| 分类类型 CD632 / `06` | 场外互换 SBL 合约类型 |
| 补充信息 CD146 / `06` | 账簿柜台，当前 SQL 取 `DESK` |

这些 `06` 互不等价。类型和值也不同：`Agt_Stat_Type_Cd='10'` 表示记录“协议状态”这一维度，实际处于哪种状态还要读 `Agt_Stat_Cd`；不能把 `10` 直接解释成“存续”或“已终止”。

以下“字典名称”保留本地 `value_description` 的内容；“记录业务日期”是字典行的 `business_date`，**不是本次查询日、采集日或已确认生效日**。所有命中项的 `source_table` 都是 `MANU_MATN`，除特别列出的备注外，本次命中记录备注为空。

## 4. CD050：当事人以什么角色参与

对应模型：`pdata_n.t03_agt_pty_rela_h`；类型字段：`Agt_Pty_Rela_Type_Cd`。

| 代码 | 字典名称 | 本次分支的具体表达 | 记录业务日期 |
| --- | --- | --- | --- |
| 01 | 协议持有人 | 资金账户、保证金账户、账簿关联各自源记录中的当事人 | 2020-10-22 |
| 06 | 协议交易对手 | 普通/极速互换、期权、远期关联合约源记录中的交易对手 | 2024-07-24 |
| 12 | 协议管理人（手工映射） | 依据 103932、222317 的 SQL 注释；取资金账户 `KEY_CTPTY_ID`，管理职责细节待核实 | 原始字典无记录 |

例如“资金账户持有人（01）”表达“谁持有这个账户”，而“合约交易对手（06）”表达“谁是这笔合约的对手”。资金账户同时写 `01/12`，是生成两种角色记录，不是一个角色叫“01/12”，也不是说账户有 12 个人。

本地原始 CD050 字典包含 `01` 至 `11`；本页另外手工补充 `12 → 协议管理人`，依据为同一目标字段的 SQL 注释。01 和 12 虽取同一个源当事人，仍表达不同角色。

| 代码  | 字典名称          | 本次 SQL 实际保存的方向与对象                              | 记录业务日期     |
| --- | ------------- | ---------------------------------------------- | ---------- |
| A17 | 资产账户与场外互换合约   | 互换合约 → 资金账户，右端修饰符 10220                        | 2023-05-23 |
| A18 | 资产账户与场外期权合约   | 期权合约 → 资金账户，右端修饰符 10220                        | 2023-07-27 |
| N03 | 场外互换合约与账簿协议   | 普通/极速互换合约 → 账簿                                 | 2023-05-23 |
| N04 | 场外期权合约与账簿协议   | 期权合约 → 账簿                                      | 2023-05-23 |
| N05 | 账簿协议与账簿协议     | `KEY_BOOK_ID_FROM` 原账簿 → `KEY_BOOK_ID_TO` 目标账簿 | 2023-05-23 |

## 6. CD718：协议与产品是什么关系

对应模型：`pdata_n.t03_agt_prd_rela_h`；类型字段：`Agt_Prd_Rela_Type_Cd`。

| 代码 | 字典名称 | 本次 SQL 用途 | 记录业务日期 |
| --- | --- | --- | --- |
| 01 | 协议和交易标的 | 交易键识别合约，`KEY_INSTRUMENT_ID` 构造产品身份并保留源产品键 | 2023-05-30 |

字典称“交易标的”，不意味着源产品键必然是股票代码；具体产品层次仍须按源模型核实。此处的 `01` 与“协议持有人”的 `01` 属于不同代码域。

## 7. CD632：按哪个维度给合约分类

对应模型：`pdata_n.t03_agt_clas_h`；类型字段：`Agt_Clas_Type_Cd`。

| 类型代码 | 字典名称 | 分类值从哪里取 | 记录业务日期 |
| --- | --- | --- | --- |
| 05 | 场外合约业务类型 | OTC 交易的 `BUSINESS_TYPE` → `Agt_Clas_Cd` | 2023-07-11 |
| 06 | 场外互换SBL合约类型 | SBL 的 `SBL_TYPE` → `Agt_Clas_Cd` | 2024-01-02 |
| 07 | 场外互换SBL合约结算类型 | SBL 的 `SETTLEMENT_TYPE` → `Agt_Clas_Cd` | 2024-01-02 |

本表揭示“分类问题是什么”。`BUSINESS_TYPE` 等源字段每个取值具体代表什么，是下一层的分类值字典；不能把类型代码的名称套到所有分类值上。本页没有将未核实的源分类值纳入 32 项计数。

对应模型：`pdata_n.t03_agt_stat_h`；类型字段：`Agt_Stat_Type_Cd`。

| 类型代码 | 字典名称 | 本次 SQL 用途 | 记录业务日期 |
| --- | --- | --- | --- |
| 10 | 协议状态 | 四类合约的 `CONTR_STATUS` 经转换后写入 `Agt_Stat_Cd`，转换缺失则回退源值 | 2020-10-22 |

实际状态代码对应 CD041，但本章 SQL 通过 `REF_CD_CVT_MAP` 做来源转换。本地当前查到的是仓库字典 `REF_DW_CD_VAL`，不是转换表内容；未核实源状态到仓库状态的对应关系前，不给出“哪些代码等于有效合约”的筛选结论。

## 9. CD146：补充信息到底是什么内容

对应模型：`pdata_n.t03_agt_stati_info_h`；类型字段：`Agt_Stati_Info_Type_Cd`。

| 类型代码 | 字典名称 | 当前源字段 → 目标内容 | 记录业务日期 |
| --- | --- | --- | --- |
| 04 | 交易对手保证金账户 | `MG_ACCT_CODE` → `Stati_Qty_Info`；实际存账户代码，不能求和 | 2023-05-30 |
| 06 | 账簿柜台 | `DESK` → `Stati_Cont_Desc` | 2023-05-30 |
| 07 | 账簿所属部门 | `DEPARTMENT` → `Stati_Cont_Desc` | 2023-05-30 |
| 08 | 账簿所属公司 | `COMPANY` → `Stati_Cont_Desc` | 2023-05-30 |
| 09 | 场外合约协议内部合约号 | `INTERNAL_TRADE_ID` → `Stati_Cont_Desc`；与模型协议键分开 | 2023-05-30 |
| 25 | 场外衍生品合约背靠背关联合约 | 仅 `PROPERTY_NAME='relatedOption'` 的 `PROPERTY_VALUE` → `Stati_Cont_Desc` | 2025-09-18 |

**25 的字典原备注：`合约编号，非协议编号`。** 这比“相关合约”更具体：文本值不能直接当作目标协议 `Agt_Id` 连接，必须核对合约编号与协议身份的映射。

字典名称与 SQL 字段名也要分别保留：09 的名称是“内部合约号”，源字段叫 `INTERNAL_TRADE_ID`；本章说明实际字段对应，不将其与其他合同号自动视为同一编号。
