**地图因此只是其中一种呈现。**

同一份共享模型可以支持：

- **人找数据**：按业务分类浏览，查看资料职责、范围和口径。
- **人理解关系**：看合约、账户、账簿之间的业务联系，并定位数据实现。
- **人查加工**：从实现进入现有图谱，查看字段来源和加工条件。
- **Agent 理解数据**：直接取得结构化的定义、映射、证据和限制，不必重新读页面猜含义。
- **后续统一查数**：在确有需求时，进一步使用已经确认的粒度、关联与计算规则。

这里也保留了建设顺序：**共享定义和数据映射需要先形成；查询编译、自动推理和完整执行引擎不必同时建设。** 但它们在整体中的位置要说清楚，不能因为首版暂时不做，就在方案里消失。


对现有成果的安排也就稳定了：

- 标准模型、字典、知识库提供业务定义的依据；
- data-graph 提供加工实现的证据；
- 新增工作负责把定义与实现建立明确对应，并维护差异、版本和确认状态；
- 目录、关系视图、血缘下钻和 Agent 共同使用这些内容。
