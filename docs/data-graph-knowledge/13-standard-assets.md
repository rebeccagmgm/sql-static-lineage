# 交叉销售规模怎样进入标准资产，月口径与年口径又有什么不同

交叉销售月日均已经回答“规模归给哪个客户、机构和员工”。进入标准资产后，它又要经历一次组织变化：员工维度被汇总掉，规模按标签进入客户与机构的资产口径，再经过系数、机构映射和纳入条件处理。

本篇沿 OTC 分支核验四个主要任务：148368、148763、159768、149048。它们所在的标准资产模型还处理其他资产类型；本文解释完整的已检查 OTC 接续及共同出口，不把其他资产分支一并认定为已讲透。

## 先看需要区分的三个结果

| 结果                         | 主要对象与时间                               | 本轮核验任务                                   |
| ---------------------------- | -------------------------------------------- | ---------------------------------------------- |
| 交叉销售月日均               | 客户×机构×员工×标签，月份                    | 159763，见[前文](04-contract-to-cross-sale.md) |
| 折算前、折算后标准资产月日均 | 客户×机构×标签，月份；另有合计标签           | 148368、148763                                 |
| 折算后标准资产年日均         | 客户×机构×标签，输出业务日；内部使用年内口径 | 149048，OTC 来源为 159768                      |

折算前月表为 `dm_index_n.index_grp2_std_ast_bef_covt_mth_apd`，折算后月表为 `dm_index_n.index_grp2_std_ast_aft_covt_mth_apd`，年表为 `dm_index_n.index_grp2_std_ast_aft_covt_year_apd`。这些对象维度是 SQL 的分组和选择意图，不代表已通过数据验证的唯一键。表名中都有“日均”，也不意味着它们用同一份日序列或同一种加权方法。

## 月口径：先把员工贡献汇到客户与机构

148368 读取 `dm_index_n.index_grp3_compscal_otcderi_cs_mthapd`，按客户组合、机构组合、标签、月份汇总 `index_val`，不再保留员工组合。于是，一位客户在同一机构下不同员工的贡献可以在这里相加。

该分支取运行月往前六个月起至运行月的月份范围，后续出口又要求月份不早于运行年份的一月；不能只看前面的范围就说最终保留了跨年七个月。

这里的输入是[已分配的交叉销售日均](04-contract-to-cross-sale.md)。员工字段消失并不代表上游归属规则失效：上游的比例和机构回退已经改变了各机构会收到多少贡献。

这个 OTC 分支与经纪资产、托管外包、期货等材料一起组成共同资产集合。148368 再生成 `tag999999999` 的客户×机构合计，同时保留分项标签。因此读表汇总时不能不分标签地把“分项”和“合计”再次相加。SQL 的分支注释写“跨境期货”，但这一段没有单独只筛一个 OTC 标签；解释范围应以 SELECT/WHERE 为准。

证据：[148368](../../../sql-static-lineage-data/task-projections/tasks/148368/versions/ab6106d5a9bb9a4c27dd31551c4a5235048a218dc51aaf805b0a22728178658e.evidence-v3.json)，query 第 239–244、329–344、388–390 行。

## 折算：一个系数字段怎样改变整项结果

148763 的一般资产分支先重新汇总折算前结果，再按 `tag_id` 左连接运行年份的 `pdata_nds.aum_asset_ast_style_cd`，计算：

```text
折算后分项值 = 折算前分项值 × ast_exam_coef
```

这一分支明确排除若干由其他逻辑单独处理的标签以及上游合计标签。前文交叉销售的两个标签没有出现在该排除列表中，因此按所见 SQL 属于这里处理的候选输入；实际是否进入，还取决于输入记录及后续条件。

这给“公共规则”提供了比字段数量更直观的例子：系数表即使只提供一个金额乘数，也会改变整项标准资产。它是业务口径的一部分，不能因为来源字段少就当作可忽略背景。

需要特别留意：表达式没有给缺失系数补默认值。若关联不到系数，乘法可能产生 NULL；若同一标签与年份有多条系数记录，也可能增加匹配行数。当前只核实 SQL 与表引用，没有读取系数数据，不能把年口径里的常量直接补成此处月口径的实际取值。

证据：[148763](../../../sql-static-lineage-data/task-projections/tasks/148763/versions/2942afc4ba95be6e33ea2c9835e34f6097f3a0bd7a0840ce0ebe0b02c94df7d2.evidence-v3.json)，query 第 928–954 行。

## 结果还会经历机构改挂和客户排除

折算前、折算后月表的共同出口都使用 `pdata_nds.om_flip_new_orgid` 将旧机构连接到新机构，再次按输出机构汇总。它改变的是最终承担结果的机构对象，不能只视为显示名称替换。

随后通过客户排除材料构造排除集合，使用左连接后要求排除侧为空；最终还要匹配客户和机构组合定义。中间算出金额不等于最终一定出现，组合映射缺失、多重匹配及排除条件都可能影响出表。

排除材料中有一部分按系统当前时间的前一天取快照，而不是统一采用传入业务日期。历史重跑时是否重现相同纳入范围，需要进一步核实业务和运行约定。本文不根据 SQL 单独断言重跑必然发生数值变化。

证据：148368 query 第 346–391 行；148763 query 第 1084–1128 行。

## 年口径：OTC 使用另一条年内日均来源

149048 的一般分支读取各月折算后标准资产，结合日历中各月记录数占年内总记录数的比例加权。所见日历查询限定来源、分组、市场和日期范围，但没有按交易日标志筛选；实际记录唯一性和日历覆盖尚未核验，不能把权重直接称为交易日权重。

**OTC 的两个标签被明确排除在这个一般月度加权分支之外。**它们改从 `dm_index_n.index_grp3_compscal_otcderi_cs_yearapd` 读取，这张表由 159768 生产。

159768 与月日均任务采用相似的产品纳入和归属结构，但每日明细范围改成当年一月一日至运行日，分母也改成年初至运行日的自然日数。它的 `busi_mon` 标识计算所在月份，不能据字段名把值解释成只覆盖该月。

149048 再把此年内日均按标签乘以固定值：

| 标签           | 年口径 SQL 中的系数 |
| -------------- | ------------------: |
| `tag074443705` |                 0.8 |
| `tag074443704` |                0.26 |

这两个常量是已保存 SQL 的实现，不是本篇确认的业务制度依据，也不能推定它们与月口径系数表在所有年份一致。149048 还有运行月初两天补取上月口径的分支，阅读它时需区分计算时点与结果所指的期间。

因此，从月标准资产表沿一条表级边走到年标准资产表，不能证明每个标签都经过那条边。这里已经出现了一个清楚的字段与条件级反例：同一目标表按标签选择不同来源路线。

证据：[159768](../../../sql-static-lineage-data/task-projections/tasks/159768/versions/2b15865851e166768cd124074d8c2552233efecf18e1f3d13cf4ffae0294e376.evidence-v3.json)，query 第 19–33、56–63 行；[149048](../../../sql-static-lineage-data/task-projections/tasks/149048/versions/f3b36228e9dfcf43e0f6344177b1f77bbee975472bd9f924682d236764043ee5.evidence-v3.json)，query 第 3–45、58–99、118–125 行。

## 一个最小的理解例子

教学示意：同一客户、同一机构、同一标签，两位员工的交叉销售月日均分别为 12 和 8。忽略其他来源并假定所有纳入和关联条件满足，折算前该分项汇成 20。若系数数据恰为 0.8，折算后是 16；这里的 0.8 只是说明乘法的假设值，并非对月系数表实际记录的确认。

如果再查询合计标签，不能把合计 16 与同一分项 16 相加成 32。若改问年日均，也不能直接把这一月的 16 当作答案，要回到对应年内来源和分母。

## 已经接通的知识与仍需确认的内容

从合约每日规模，到员工与机构归属，再到客户与机构的标准资产分项，这条已检查的 OTC 路线已经能够连接起来解释。新增的关键知识是：维度减少会保留上游分配影响，系数改变口径，标签决定接哪条来源，合计行与分项行共存，以及运行时点可能参与历史范围选择。

仍待确认的是月系数的实际取值与制度、年系数的适用依据、年月口径差异是否符合业务预期、客户排除快照的重跑约定，以及完整年度日明细是否足够。这些问题不应通过表名、注释或“当前任务成功”替代核实。

本篇证据行号均指对应 evidence 中 `sqlSources[slot=query]` 的 SQL 行号；固定版本及其他通用边界见[证据说明](evidence.md)。
