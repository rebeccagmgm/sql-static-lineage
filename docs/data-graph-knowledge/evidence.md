## 怎样回查一条结论

行号指 evidence 的 `sqlSources` 中指定槽的 `content` 按换行拆分、从 1 开始计数，**不是 JSON 文件行号**。绝大部分使用 `query`；生产预处理可能在 `create`，风险报表接续在 `finish`，个别目标刷新在 `truncate`。以引用明确的槽为准；这些槽名不保证其中只含同名字面意义的操作。

字段核验以 `bindings.expression_id` 对应 `expressions.expression_id`，并保留 `target_dataset、write_observation_id、statement_id` 的写入范围。关系节点用于解释 JOIN、过滤、分组、窗口等；不能把控制来源都算成字段值。空绑定、`PARTIAL`、`DERIVED_OUTPUT` 等边界均保留，不把未解析看成没有影响。

表元数据不一定与任务 evidence 同时采集。任务证据固定于发布批次，但各任务 SQL 的实际采集日期也可能不同；同一发布版本不等于来自同一次调度运行。来源中的固定日期、运行参数和业务日期应分别阅读。

## 本版完成的核验与它的限度

全图复算时，各任务投影的声明 `contentHash` 与 manifest 一致，未发现声明不匹配。直接引用的 109 个任务均来自该 manifest 指定路径；其 224 段 SQL 内容重新计算 SHA256 后与记录值一致，未缺少 SQL 哈希。

这说明材料引用和 SQL 内容一致，不是重新计算投影全部字节的内容哈希，也不能证明运行、数据到达或业务正确。另检查了全部 Markdown 本地链接与章节锚点、代码围栏及空白格式；全文中的教学编号和数字不作真实业务数据。

关键新主题经过独立交叉核验，并修正了静态分配分母、余额集合起点、到期后归零、LIKE 模式匹配、回补与导出窗口等表述。三组字段统计也独立复算一致。覆盖账本经正文逐项对照，未解释具体表的项已退回候选或边界。

当前未查询生产业务记录，未执行调度任务，也未证明表键唯一、关联不增行、历史区间无重叠、日期序列完整、分配比例守恒或业务金额正确。正式制度、源模型和实际消费缺口见[待确认问题](open-questions.md)。
