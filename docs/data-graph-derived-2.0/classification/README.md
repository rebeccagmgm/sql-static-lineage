# 可复用分类底账

人工标记入口现为 [全量表统计与人工标记.xlsx](../outputs/01a07ffc-dc41-7a62-9e17-f5103cdc7e07/全量表统计与人工标记.xlsx)。用户只维护其中黄色列，已有判断单独作为参考。后续回收时按物理表ID核对，将明确标记更新到本目录底账；Excel空白不代表清除已有分类。“是否排除”是待回收的用户意向，不自动改变任何统计视图。下面的CSV和JSON由执行者维护，用户不必同步编辑。

本目录保存可以跨统计批次继续维护的分类。表的角色、某次消费中的用途、某个视图的排除决定分开保存；排名和度数由分析缓存计算，不作为表的固有属性。

| 文件                       | 保存内容                                                                       | 复用方式                                   |
| -------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------ |
| `table-roles.csv`          | 唯一分类主账：物理表身份、多角色、中文注释、判断理由、证据级别、核验范围和版本 | 用 Excel 筛选、编辑，保存为 CSV UTF-8      |
| `table-role-evidence.json` | 按证据ID关联的 SQL 行段、哈希、元数据证据及历史结构观察                        | 只维护详细证据，不保存第二份分类结论       |
| `consumer-uses.json`       | 基础表、消费任务、具体写入、字段用途及 SQL 证据                                | 仅复用已经说明的消费问题，不推广成全表用途 |
| `exclusion-views.json`     | 各对照视图排除的精确表身份、理由及适用版本                                     | 生成本批派生排名，保留完整基线             |

当前采用 CSV 分类主账、JSON 详细证据和生成的 Markdown，不改原图。`analysis/role-labels.json`、`foundation-uses.json` 等是历史研究快照，不再与主账同步维护；长期入口是本目录。`table-roles.json` 仅保留迁移指针，没有第二份分类内容。

本批最终包含57张排名表、8项有限范围SQL角色核验、7项排除决定，以及4张基础/参数表在5个任务中的6项用途。`table-roles.md` 是当前可读清单。

`analysis/persist-classification.mjs` 是旧版初始化脚本，检测到 CSV 主账后拒绝运行。分类只编辑 `table-roles.csv`；SQL 等详细证据只编辑 `table-role-evidence.json`，通过“证据ID”关联。实际排除仍唯一由 `exclusion-views.json` 决定，修改角色不会自动新增排除。

CSV 中“角色”多个值用英文分号分隔；“待确认问题”允许单元格内换行；图版本、物理表ID和证据ID按文本保留。保存格式必须为 CSV UTF-8，不能保存为 ANSI。ID、平台、数据源和表名需与图中物理身份一致，不用于改名。新增分类行时先补充同物理表的证据记录；仅提高“证据级别”不能代替核读 SQL。排名、度数和下游 schema 数仍由统计生成，不混入可编辑分类属性。

当前底账与统计缓存版本一致时，可运行 `node docs/data-graph-derived-2.0/analysis/recompute-role-views.mjs`，从 CSV 主账重算对照报告、排名 CSV 和 `table-roles.md`。该命令不读取源SQL、不访问图、不改分类，遇到版本、身份、证据关联错误会停止。保留新增判断的理由与核验范围，不从旧快照覆盖主账。

## 表身份和角色

匹配依据是平台、数据源、限定表名组成的物理身份，同时保留图中的 datasetId。不能只用末段表名，也不能把不同物理身份的中文注释互相覆盖。中文注释记录来源；缺少注释时明确标记，不由标签反推注释。

一张表允许多个角色：

| 标签                | 含义                                       |
| ------------------- | ------------------------------------------ |
| SYSTEM_LOG          | 系统运行、推送或交付日志                   |
| ACCESS_MANAGEMENT   | 用户、角色或权限等管理对象与结果           |
| PUBLIC_DEFINITION   | 字典、组合等公共定义及编号解释域           |
| PUBLIC_PARAMETER    | 映射、转换或计算参数                       |
| BUSINESS_FOUNDATION | 账簿、证券、客户等公共业务基础             |
| BUSINESS_RESULT     | 规模、收益、风险、客户经营等业务事实或结果 |
| TRANSFER            | 明确的传输或分发作用，限定已核范围         |
| UNKNOWN             | 当前无法可靠归类                           |

`METADATA_ONLY` 是候选认识，`SQL_VERIFIED` 表示声明范围有具体静态 SQL 依据，不代表全部写者、全字段或运行正确。高出度的销售基础不因复用高就自动归为可排除的公共参数。未进入本批排名范围的表是未研究，不是无角色。

下游 schema 数与具体列表属于版本化的结构观察，保存到 `structuralObservation`，不当作永久标签。按直接出邻表去重，包含同 schema，不递归；每次排除后重新计算。分散到多个 schema 可以支持“复用分布较广”的判断，但同一业务的分层落地和分发也可能跨 schema，不能单凭这个数认定跨业务。

## 用途落在具体消费上

用途记录以“源物理表＋消费任务＋具体写入”为定位，字段集合和 SQL 行段限定解释范围。同一表可以在不同消费者中承担不同用途，也可以同时具备多个用途。

- ATTRIBUTE_ENRICHMENT：补充名称、属性。是否不影响行数，要看匹配唯一性及后续过滤、分组、去重。
- IDENTITY_MAPPING：编号、组合或归属映射。
- SCOPE_CONTROL：过滤、纳入资格、有效期等范围选择。
- CALCULATION：系数、折算、分配或条件取值。
- GRAIN_CHANGE：有证据支持的展开、聚合、行粒度变化。

潜在多匹配不是已经发生的粒度变化。没有唯一性证据时，在条件或未知项中记录“可能倍增”，不要直接认定数据已倍增。“参与 JOIN”只是 SQL 形态，不能独立证明是纯属性补充。

## 分类不自动触发排除

保留完整基线，再保存三个累积对照视图：排除明确日志/权限；加上明确公共定义/参数；再加上明确业务基础表。最后一类只是结构敏感性对照，基础表仍作为学习对象保留。

每个排除项必须有精确身份、决定理由和证据。本批排名范围以外、只有元数据候选、用途不确定的表，不凭名称全域扩展排除。删去相关边后形成的新孤点仍计入视图节点分母。

## 新版本如何更新

1. 按稳定物理身份关联旧记录。表角色先保留为既有认识，不把旧度数与排名带入新版。
2. 检查支撑该判断的写入身份、SQL 槽位哈希和相关材料。全 evidence 哈希变化不等于规则必变，相同文件名也不证明材料一致。
3. 证据仍一致时，在声明范围内复用局部判断；新增写者、消费方式或角色上下文变化时，补充核验范围。
4. 证据缺失、变化未核的项标待复核。默认不将其自动带入新版排除名单，继续处理其他证据明确项。
5. 为新版保存明确适用版本的排除快照后，再重算派生统计；不要静默覆盖旧版解释。

本次只交付底账和固定版本消费流程，尚未实现自动跨版本语义核验。以上是维护约定，不是已经运行的自动化。
