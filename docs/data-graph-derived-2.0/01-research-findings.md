# 调研结论：方法可复用，分析基线需要更新

本文保留 2026-09-08 的历史调研观察。后续统计与局部知识成果见 [工作入口与覆盖](work-index.md)；2026-09-09 重组后的图上单元、跨单元专题及收尾要求以 [执行方法](02-analysis-method.md) 和 [执行说明](03-executor-brief.md) 为准。下文“当前”“新版本”均指调研当时，不代表本次修订重新核验。

核对日期：2026-09-08。本轮读取现有方法文档、知识库入口、发布指针／manifest／publication，并调用现有 CLI 的 `status`，检查了消费入口及 detail 的作用范围。没有重跑全图统计、扫描全部 SQL、重新发布图或修改解析器。

## 1. 当前发布与旧分析范围

| 项目              | 旧知识库分析版本 | 本次核实的新版本 |
| ----------------- | ---------------: | ---------------: |
| 任务数            |            3,615 |            7,234 |
| PROJECTED         |            2,385 |            5,489 |
| SCHEDULE_ONLY     |            1,084 |            1,482 |
| COLLECTION_FAILED |              146 |              263 |
| 物理表目录身份    |            2,903 |            6,893 |

新版本的发布覆盖分类进一步区分：5,489 项具有投影，1,005 项属于预期调度参考，740 项属于材料缺口。740 = 477 项 schedule-only 缺口 + 263 项 collection-failed 缺口。预期调度参考不等于“没有业务价值”，材料缺口也不等于“没有业务加工”。

新发布的节点种类仍包含 TASK、PHYSICAL_DATASET、PHYSICAL_FIELD、READ_OCCURRENCE、TARGET_WRITE、READ_FIELD、WRITE_FIELD；保留表级 IO、VALUE、CONDITION、DATASET_CONTROL 与跨任务接续等边。当前主发布入口仍调用 `compileTask`，发布 compilerVersion 为 `1.0.9`。这些事实支持继续消费既有模型，不能据此保证所有旧查询或语义缺口均未变化。

旧版 2,654 张保留表、5,084 个表对、49 张角色变化表、199 条线性链，以及旧热点排名和候选簇，都是旧版本结果。6,893 是新图的全部物理表身份，不能直接与旧过滤后的 2,654 比较增长率。

## 2. 可以沿用与需要更新的部分

| 旧方法／材料                                 | 新一轮处理                                                                     |
| -------------------------------------------- | ------------------------------------------------------------------------------ |
| 全局去重表对、全局计算度数，再按 schema 展示 | 继续使用；schema 不当作互斥业务领域                                            |
| 复用、汇聚、连接承接分别观察                 | 继续使用；所有排名和可达范围重新计算                                           |
| 先找候选，再查具体写入、字段、规则           | 继续使用；不能先读几个熟悉案例充当全图发现                                     |
| 临时排除四张公共基础表                       | 保留为旧版对照视图；不能直接当作新全域的公共资产清单                           |
| 至少三个源字段、50% 目标字段覆盖率的分组     | 仅作为待复验参数；先看新版分布，再检验敏感性                                   |
| 旧业务文章                                   | 比较固定证据、写入、来源分支及上下文变化后复用；本轮尚未完成逐篇复核           |
| 109 个任务的旧取证覆盖                       | 保留为历史范围；扩容不会自动扩大解释完成度                                     |
| 旧临时统计脚本／摘要                         | 先确认文件存在、输入口径及版本；旧摘要不是新版图数据，不能冒充可直接执行的工具 |

一个重要变化是：新增生产路径可以改变目标字段并集，即使某个旧任务的 SQL 没变，其全局字段覆盖比例也可能改变。另一方面，相同 SQL 中的局部规则可以仍然成立，但其下游范围、热点角色与“是否首次出现”的判断需要重新审视。

## 3. 现有消费入口已足以开始

| 需要回答的问题                   | 优先入口                              | 边界                                                                |
| -------------------------------- | ------------------------------------- | ------------------------------------------------------------------- |
| 当前版本、发布覆盖               | `status`、固定 manifest／publication  | status 的发布统计不等于知识完成度                                   |
| 跨任务接续缺口、候选原因         | `metrics`、`query-read-candidates`    | 读取发布 INDEX；不是全局表权重或业务风险评分                        |
| 搜索、字段、上下游路径           | `search`、`fields`、`trace`           | 遵守分页和截断；候选接续与已确认接续分开                            |
| 表热点、字段聚合、链与簇探索     | 现有连接上的只读 Cypher，随后本地计算 | 当前 CLI 没有这些全局分析的成品命令；不必先开发一套 API             |
| 公式、过滤、关联、窗口、SQL 原文 | `detail`、`processing`、固定 evidence | detail 的 controls 主要按语句取上下文，不能一律当作字段精确因果控制 |

现有 [CLI 使用说明](../agent-graph-cli.md)、[CLI 合同](../../packages/data-graph/src/asset-graph/cli-help.ts)、[图连接入口](../../packages/data-graph/src/asset-graph/config.ts)、[detail 实现](../../packages/data-graph/src/asset-graph/service.ts)提供具体入口。连接参数复用项目配置，不复制凭据或另建数据库连接体系。

本轮没有重新验证所有 trace 细节，也没有验证新版 WINDOW／CASE 投影覆盖。已知消费边界继续保留：边数不是规则数，缺少控制边不是缺少控制操作，完整 SQL 语义要按问题回查证据。

## 4. 两套旧知识库怎样帮助新工作

- [旧方法复盘](../data-graph-knowledge/05-discovery-method.md)：保存多写身份、公共控制、分支比较、粒度和反例方面的已验证工作法。
- [图消费专题](../data-graph-knowledge/20-graph-consumption-method.md)：保存表级、字段级统计定义，以及拆图和阈值试验的失败经验。
- [业务过程知识库](../network-understanding/README.md)：扩充财务、合规、权限、质量、交付等主题，可按任务定位正文与 SQL 证据。
- [覆盖账本](../network-understanding/evidence/coverage-summary-19-reviews.md)：提供“任务→已有说明→证据→缺口”的复用索引。“至少一处解释”不能当作全任务已理解。

另一个有价值的补充是从质量检查提取模型被期待满足的条件，以及检查目标端 UPDATE／MERGE／DELETE 怎样保留旧状态。它们可直接加入知识分析，无需为本轮建库先改 graph 点边。

## 5. 调研形成的决定

采用“确定性批量统计 + 有界语义研究 + 旧知识按差异复用”。模型主要负责选择问题、解释规则和判断证据，计数、排序、去重及文件比较交给程序。全局复杂算法按需要启用，不作为开始写知识的前置工程。

本轮尚未测量新版各算法耗时、旧知识可直接复用比例、全网业务主题数量或学习效果。因此不承诺固定 token 成本、固定完成天数，也不宣称新图已被完整分析。
