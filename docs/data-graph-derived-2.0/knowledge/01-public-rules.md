# 公共基础：定义、映射和参数怎样进入结果

公共表不是可以统一删掉的背景。它有时补名称，有时选择编号解释域，有时决定一条已经算出的指标能否出表。新版结构中，`dm_index_n.grp_def` 的出度为 239，代码转换表 `pdata_n.ref_cd_cvt_map` 的出度为 184；这些是选择公共规则问题的依据，不是业务重要性总分。

本篇重新核读新版固定 SQL，沿用旧知识库“定义与应用分开”的讲法。旧 evidence 大多缺失，不能宣称新旧全文一致。当前证据版本与原文件 SHA256 见 [selected-evidence.json](../analysis/selected-evidence.json)。

## 先区分三种职责

| 对象           | 一行或一项表达什么             | 怎样影响结果                                               |
| -------------- | ------------------------------ | ---------------------------------------------------------- |
| 字典定义与码值 | 某个字典中的代码及解释         | 改变分类名称或匹配结果；同一个字符串必须带上字典身份       |
| 合约基础系数   | 某个合约、系数类型下的参数记录 | 提供计算输入；存有参数并不证明已经用于金额计算             |
| 组合定义       | 某类对象值对应的组合 ID        | 使客户、机构、员工指标落到相应对象；未命中内连接会丢失输出 |

代码转换表是另一类映射对象，不能把它与下述 `REF_DW_CD_VAL` 当作同一张表。前者的控制热点是目标表、目标字段、源系统和源字段选择列；本篇对它只确认结构位置，尚未核读具体转换 SQL。

## 代码值必须带上字典身份

142305 先从 `PDATA_N.REF_DW_CD_LIST` 取“源系统数据字典”定义，再按定义中的字典入口连接 TIT 字典明细。源表条件限定这份定义适用于哪个来源；明细必须来自参数日，代码不是 `!`，且失效时间去空白后为空。它使用左连接，因此定义存在、合格明细不存在时，仍可能留下空码值记录。

第二条语句另外把 `Exchange` 字典追加到 `CD082`。第一条是覆盖写入，第二条是追加写入，各段分别 DISTINCT，并没有对两段合并结果统一去重。`CD082` 输出名称为“源交易类别代码”，来源却明确选 `Exchange`；解释码值时应看来源和消费条件，不能只照中文列名理解。

这一步的意图单位是“字典中的代码解释”，不是交易或合约。若两个字典都有代码 `1`，只用代码值连接会混淆含义；即使代码描述不参与金额公式，多匹配也可能扩大后续行数。**只有映射匹配唯一、描述不进入过滤/分组/去重、其余字段不变时，单纯改显示名称才可能不改变金额。**这些前提不能由表出度推断。

依据：[142305 query](../analysis/evidence/142305-0-query.sql)，1–25、27–51 行。历史如何保留旧解释见 [状态与历史](05-history-and-state.md)。

## 同一目标列为什么不能合并成同一参数

133054、133055 都写 `T99_DERI_COMP_BASE_COEF_REF`，但写入来源分区不同。它们先用源合约编号连接交易主表的内部交易号，再识别互换、期权、金仕达确认记录。识别按 CASE 顺序优先取互换，再期权，再金仕达；未命中时编号与修饰符输出空串。

| 比较项             | 内部基础系数 133054  | 交叉基础系数 133055  |
| ------------------ | -------------------- | -------------------- |
| 系数类型           | `INR`                | `CROSS`              |
| `Base_Yield` 来源  | `BASE_EARNING_RATE`  | `BASE_AWARD_RATE`    |
| 拟定基础系数       | 源 `DRAFT_BASE_RATE` | 空串                 |
| 额外奖励标志、金额 | 空串                 | 源奖励标志、奖励金额 |
| 删除标志           | Y→1、N→0，其余保留   | 同样转换             |

这些查询均未按删除标志排除源行，也没有按生效日选出唯一有效参数。目标名为“基础收益率”不代表两个分支的业务输入相同，更不能把它们直接相加。匹配优先级、源行重复或空编号会影响后续能否绑定合约。固定 SQL 中源日期已展开为 2026-05-19；这只是材料中的日期，不是本批图的业务日期，也不代表生产运行使用固定日期。

本篇只授予这两个任务“共同结构及上述差异已核对”，不推广到所有系数任务。参数实际如何进入收入、额外奖励怎样应用，仍需消费端公式证据。

依据：[133054 query](../analysis/evidence/133054-1-query.sql)、[133055 query](../analysis/evidence/133055-1-query.sql)，各 1–42 行；相应 create 定义已保存在同一证据目录。

## 组合定义既提供 ID，也构成出表门槛

159763 先按客户、机构、员工及标签算出月日均，再通过 `grp_def` 取得三个组合 ID。`grp_val` 必须和 `grp_type_code` 一起解释：一个数字在客户、机构、员工域中可以表示不同对象。

最终三个连接都是内连接。客户与员工组合要求 `status='1'`，机构组合查询没有相同状态条件；机构类型还由前面的机构编码连接获得。即使前面已经算出金额，缺少组合映射仍可能使该结果不能出表；映射不唯一则可能增加输出行。这里的组合定义不只是在末端补一个标签。

反例：某员工月日均已算出 12，员工组合缺失时，不能据上游 SUM 宣称最终已经输出 12。反过来，补齐唯一映射可能增加一行输出，但不会改变映射前的 12。若新增重复定义，则必须另查是否倍增。

依据：[159763 query](../analysis/evidence/159763-1-query.sql)，46–63、138–144 行。完整规模过程见 [日均与归属](03-daily-scale-and-attribution.md)。

## 本篇边界

已解释代码定义、两类系数的局部差异和一个指标消费者的组合门槛。账簿属性、客户身份、证券主数据、员工机构主模型还没有在新版逐项核读；它们在候选清单中保留，不能因本篇名为公共基础就算全部完成。映射唯一性、实际参数有效性、业务制度和运行结果均未验收。
