# 权限汇总到导出：最终去重能消除什么

新版 `dm_ctms_n.pwc_psn_sys_user_roles` 有 103 个入邻表、2 个出邻表，值得单独研究。它的汇聚形状不能解释为交易金额汇总。本篇先核读直接消费它的 74272，回答：权限清单导出如何选择操作分支，重复和跨系统编号会怎样影响结果？上游各系统分支仍待新版复核。

## 一行不是一个人

74272 输出员工姓名与编号、任职状态、系统名、系统用户号与名称、账号状态、角色、部门、操作分支、日期、审核权限和人员类别。最终按这些输出列全部 GROUP BY，保留的是不同属性组合；员工有多个账号或角色时，可以有多行。

它不计算人数，不把不同系统的身份统一为一个人。源汇总表名、源列中的员工编号和目标模型都不能替代真正的跨系统唯一性约束。

## 四组候选怎样进入结果

| 候选                                   | 实际选择                             |
| -------------------------------------- | ------------------------------------ |
| 一般系统，无“广发证券”操作分支的用户号 | 留下该用户号非空或 NULL 操作分支记录 |
| 一般系统，有“广发证券”操作分支的用户号 | 选择该用户号的“广发证券”记录         |
| 一般系统，空或 NULL 操作分支           | 单独保留                             |
| 两个指定系统标签                       | 整组保留，不走前述优先选择           |

指定标签在当前 SQL 中是“新意系统”和“ATP快速交易系统”。这里只解释当前条件字符串；旧文所说上游已使用其他 ATP 标签，需要读取新版上游才能确认，不能直接当成本版新增缺陷。

这些候选以 UNION ALL 汇合，最后按全列去重。NULL 操作分支可能同时进入第一组和第三组，全列完全相同时能被最后一步消除；角色、分支或状态不同的记录不会被当成同一行。

## 编号碰撞不是 GROUP BY 能解决的问题

前两组的存在判断与接回明细只按 `sys_num`，没有把 `sys_name` 加入关联键。教学反例：系统甲用户号7有“广发证券”记录，系统乙用户号7只有某营业部记录，两者都属于一般系统。第一组会因用户号7已有优先分支而排除它，第二组只取优先分支记录；乙的营业部记录可能不再进入最终候选。真实是否存在这种编号碰撞需要数据验证。

最终全列去重可以消除多路径生成的相同记录，却不能恢复前面被筛掉的记录，也不能修正用户号在两个系统里代表不同对象的事实。这是“中间重复可消除”与“条件改变结果”的具体区别。
