# 从合约快照到月日均：日期、归属和汇总分别做了什么

一份合约的当日规模不能直接当成月日均。这里需要先恢复每天的规模，再决定哪些天和产品纳入、每天的量分给谁，最后除以月初至运行日的自然日数，并匹配组合定义。

本篇核读新版固定证据的 107491、105743、159763，复用旧文章的讲解顺序，但不主张旧证据哈希一致。讨论范围是这条月日均的指定问题，非全部考核指标。

## 三份材料并行准备，再在结果端汇合

| 材料                | 意图粒度                                 | 结果端用途               |
| ------------------- | ---------------------------------------- | ------------------------ |
| 销售合约基本信息    | 运行日、来源分支下的合约综合记录         | 客户、产品、标的、起止日 |
| 107491 每日附加明细 | 合约与计提日                             | 历史每日动态规模         |
| 105743 管理关系     | 合约对应的机构、人员与比例组             | 分配和纳入条件           |
| 159763 月日均结果   | 月份、客户组合、机构组合、员工组合、标签 | 输出指标值               |

“意图粒度”来自字段、GROUP BY 和关联方式，不表示已用数据证明唯一性。管理关系和每日明细是平行输入，不能画成一条相互生产的直线。

## 日期展开改变了 Busi_Date 的含义

107491 读取运行日合约，提前终止日非 NULL 时优先作为结束日，否则用到期日。它要求结束日晚于 2021-09-30，且起始日不晚于结束日。随后通过 `posexplode` 生成计提日序列，起点表达式使用 `default.gfgreatest(起始日, 运行日前150日)`。自定义函数本体未核，不对异常或空值行为补猜。

输出把 `Accrued_Date` 写进分区列 `Busi_Date`，加载日期字段仍是运行日。一次读取当前快照，可能重建多个历史计提日分区；输入和输出虽然都叫 Busi_Date，却不是同一个时间维度。

每日规模也不是把运行日规模复制到所有天：

| 分支        | 恢复每日量的规则                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| 期权 01     | 起始日取初始规模；随后将已生效的部分终止/提前锁盈事件累计变动按事件日期展开，再与初始值及折算因子合成；结束日后置零 |
| 普通 TRS 02 | 起始日取初始规模，随后按交易与历史日汇总结构腿持仓；缺失时该分支使用零回退                                          |
| 金仕达 03   | 将确认记录从业务日期延续到下一业务日期之前，取来源动态本金                                                          |
| 极速互换 04 | 按工具和历史日汇总日终持仓，关联每日记录                                                                            |

期权事件关联用 `Inr_Seri_No`，金仕达用 `Agt_Id`，极速互换用 `Otc_Seri_No`。把三个编号机械统一会接错来源。该任务还计算利息、成本、佣金、保证金比例等，本篇不把这些列计入已解释范围。

依据：[107491 query](../analysis/evidence/107491-1-query.sql)，11–50、53–131 行；写入 `write-observation:107491:8`。

## 当天的归属重新组织月内历史规模

105743 的目标输出对三组机构、员工和比例逐列使用 `coalesce(合约级值, 客户级值)`。这是按列回退，不是整个关系记录二选一；NULL 才触发回退，空串不自动回退。因此同一组机构、员工、比例可能分别来自两个层次，要额外核查组合是否协调。`DISTINCT` 也只消除全列相同记录，不证明每合约一条。

其合约输入限定运行日及 `Book_Bel_Dept in ('OTC','OTC_HK')`；客户级匹配存在特定客户与浮动收益凭证条件下的客户替换。本文说明该分支存在，不扩展解释替换的制度依据。

159763 读取运行日的合约和管理关系，连接月初到运行日且处于合约有效区间的每日明细。**月内规模按当前归属组织，而不是逐日回溯历史归属。**若当前归属变更，即使每天的规模没变，这次重算也可能改变整个月的人员分配。

依据：[105743 query](../analysis/evidence/105743-1-query.sql)，102–128、163–182；目标绑定见 [Facts](../analysis/evidence/105743-facts.json) 的 `write-observation:105743:17`。不是其中临时写入 `:8`。

## 纳入范围和比例分支会改变分子

159763 合约输入只选 `grp_id in ('01','02','03')`，排除 `Src_Contr_Type='FEE_SWAP'`；类型为 NULL 也无法通过不等比较。基础模型虽然包含极速互换 04，这条输入没有选它。合约与每日明细按 `Agt_Id` 内连接，缺少明细不会进入；管理关系虽为左连接，后续机构和人员条件仍影响保留范围。

合约、标的币种和产品条件决定两个标签。随后最多三组比例形成多条分配记录。对存在机构编码数值小于 8000 的分支，比例取第几组，与最后选中的机构人员可以不同：第1组按1→2→3寻找，第2组按2→3→1，第3组按3→2→1。因此多组比例可能回流同一机构和员工。

另三条 UNION ALL 分支要求各机构经条件归一后都等于 8848；输出仍保留各组原机构人员，没有全部改写为 8848。这些分支不是所有剩余情况的兜底。比例合计是否为1、NULL比例如何分布、关联是否倍增，都尚未数据核验。

依据：[159763 query](../analysis/evidence/159763-1-query.sql)，1–44、65–133 行。

## 分母与最终出表是两道独立规则

SQL 按客户、机构、员工和标签求和，再除以 `datediff(运行日, 月初)+1`，排除汇总值为零的组。分母是自然日数，包含运行日；不是有明细的天数或交易日数。若明细缺日，分母不会相应缩小，但这不证明业务上允许缺日。

教学例：运行日为某月第10日，合约仅第9、10日各有100，人员比例为60%，其月日均贡献为 `(100×0.6+100×0.6)/10=12`。用2天作分母得到60，回答的是另一种均值。

最终三个组合内连接还要求对象定义命中；客户、员工组合要求可用状态，机构查询没有同样条件。相关职责见 [公共规则](01-public-rules.md)。Facts 将查询绑定到平台声明目标 `dm_index_n.index_grp3_compscal_otcderi_cs_mthapd`，写入身份为 `write-observation:159763:platform-target:0`；不能从 SELECT 文本单独推断写入。

还必须看到 [prepare](../analysis/evidence/159763-2-prepare.sql)：第1行建表，第2行删除参数月份分区。它说明流程包含旧月份结果清理；实际执行顺序、占位符替换和失败恢复未验证，不能把本篇规则解释当成成功重算证明。

依据：query 46–63、135–144；[Facts](../analysis/evidence/159763-facts.json) 的输出绑定和 datasetIo。

## 什么可能被汇总消除

同一客户、机构、标签下，两位员工之间调整比例，若纳入合约与日期不变、总比例不变、所有组合映射唯一且均命中、没有额外筛选或舍入差异，则**假如后续再跨员工求和**，机构合计可以不变。但本任务仍保留员工维度，员工行会变；不能说本任务输出不变，也没有据此证明某个实际后续任务一定做该求和。

跨机构转移、员工组合缺失、标签变化、管理匹配倍增、总比例变化，都会破坏抵消前提。相反，单改不参与计算及去重的显示字段，在匹配行集合不变时可能不改变指标值。判断变化必须指定观察层次：每日量、员工结果、机构合计或整行内容。

当前仍待确认：为什么排除04；当前归属与历史归属的制度选择；机构回退与例外名单理由；每日覆盖、比例质量、编号及组合唯一性。它们不阻塞上述静态规则说明。
