# 码表历史：备注改变身份，旧状态参与新结果

212728 将当前码表与已有历史有效记录比较，形成代码取值历史。它回答的是“在什么区间采用哪份解释”，不是简单每天追加一张快照。当前输入没有业务日过滤；参数日主要用于划定历史有效区间和新旧状态。

本篇核读新版 create 与 query 两个槽位，解释状态转换，并保留多写和执行次序边界。

## 匹配键决定什么算同一条记录

create 中将当前 `PDATA_N.REF_DW_CD_VAL` 整理成临时输入，与历史满足 `Strt_Date <= 参数日 AND End_Date > 参数日` 的记录做 FULL OUTER JOIN。

匹配键是 `Dw_Cd_Id + Dw_Cd_Val + Remark`，三列均以 NULL→空串比较。来源和源表没有进入匹配键，而被作为变更比较属性。备注改变，可能形成旧身份删除与新身份新增；它不只是同一行上改备注。相同码值和备注来自多条源记录时，还需要查是否多匹配。

| 情况                   | 标记 | 意图行为               |
| ---------------------- | ---- | ---------------------- |
| 当前有、历史无         | I    | 新开有效区间           |
| 历史有、当前无         | D    | 关闭原区间             |
| 两边都有、指定属性不同 | U    | 关闭旧区间并开启新解释 |
| 比较字段无变化         | S    | 保留原记录             |

指定比较属性包括字典中文名、取值描述、编码方式、维护人、来源和源表。不能把任何未比较字段变化都说成会触发U。

依据：[212728 create](../analysis/evidence/212728-0-create.sql)，27–70。

## query 不是一次覆盖，而是两次目标重写

第一条覆盖语句排除当天开始和当天结束的记录，再将当天闭链记录恢复成结束日2099-12-31，意图处理同日重跑的旧状态。第二条覆盖语句保留非当前有效区间，再按临时比较标记拼入新增/变更的新区间、删除/变更的闭链旧区间、未变记录。

因此结果依赖目标旧状态及临时比较材料，而不只依赖当前码表。虽然语句体现同日恢复意图，但 create 已提前构造比较临时表；具体槽位次序、同日失败重试与历史边界情况下是否满足幂等，需要运行或专项验证。本篇不把“看见恢复分支”当作“重跑一定正确”。

依据：[212728 query](../analysis/evidence/212728-1-query.sql)，1–41、43–117；[Facts](../analysis/evidence/212728-facts.json) 保留多个具体写入，不能合并成一条无状态公式。

## 哪些变化会留下来

假设某个字典码值的描述由“甲类”变成“乙类”，匹配键不变且其他前提满足，旧解释闭链，新解释从参数日起开链。后续按交易发生日连接历史区间，可以保留过去的解释；但如果消费者仍连接当前码表，过去交易可能统一显示新描述。**历史表存在并不证明消费者采用历史口径。**

若只改变备注，同一代码可能走D/I而不是U；若NULL和空串互换，则匹配键把它们视作相同。若消费者只是按代码计算金额，且关联唯一、描述不参与纳入、分组或去重，描述变化可能不改变金额；这不等于历史记录内容不变。
