# 直接消费 graph：全局热点、字段联系与加工簇的策略复盘

分析与整理日期：2026-09-08。本篇承接[第一版方法论](05-discovery-method.md)，记录随后直接消费已发布 Neo4j 图的探索。它回答的是：**怎样从整张加工图发现公共资产、核心结果和值得一起阅读的加工片段；相比此前的表级统计，具体增加了什么认识。**

本轮最有价值的变化有三项：用路径中介性补足直接度数，找到容易被忽视的承接核心；把字段值依赖与关联、筛选控制分开，修正公共资产的折叠方式；用字段足迹筛选局部连接，并通过敏感性试验检验候选边界。现在可以生成更具体的阅读候选，仍没有完成全图业务簇或业务语义验证。

正文保留判断所需的口径与数字；[本轮计算摘要](graph-analysis-20260908.json)保存字段热点、分簇试验、三个候选组的成员和连接，以及临时查询结果的来源指纹。它是本轮分析记录，不是新的事实源或完整图备份。

## 1．先固定目标：发现结构，再决定解释什么

用户希望先系统理解业务与加工，后续能够分享给同事。适合交付的知识片段需要回答：对象是什么、谁给出主要字段、谁控制范围和关联、哪些结果在此汇合或分流，以及哪里值得深入读规则。

本轮应先完成全局热点、出入度、字段热点与簇分析，再挑片段读 Facts 和 SQL。探索初期曾沿字段路径补查 NPV 消费者等具体 SQL，用于验证图的导航能力；用户随后明确要求回到全局结构。这带来一个需要保留的策略约束：**几个有趣的案例不能替代全局候选发现，也不能充当全局分析的增量计数。**这些附带语义线索不计入本篇新增业务覆盖。

因此，本轮分别产出四类结果：

| 结果类型         | 本轮回答的问题                                 | 后续用途                                 |
| ---------------- | ---------------------------------------------- | ---------------------------------------- |
| 直接复用与汇聚   | 谁被很多任务使用，谁组织很多输入？             | 公共知识与汇聚模型候选                   |
| 路径连接位置     | 谁承接更大范围的上下游关系？                   | 调整核心模型的阅读优先级                 |
| 字段值与控制热点 | 哪些列广泛参与输出，哪些列广泛控制关联和筛选？ | 细分公共资产职责，设计不同连接权重       |
| 局部连接与分组   | 哪些表有较强字段联系，哪些边界对方法敏感？     | 生成待核验的加工片段，保留外围公共上下文 |

## 2．固定分析口径，先证明读图结果可比

### 发布范围与表身份

全图是已发布的 `titans-otc`，覆盖 **3,615 个任务，不限于 PDATA**。这些任务的材料覆盖并不相同；第一版范围及固定 manifest 见[证据索引](evidence.md)。

```text
graph state: READY
version: df6f0ae4b6ef465f751351b14fd02ea08542d824d7bfea36e5a58dd1039e23c3
```

直接读图获得 2,718 个参与表级 IO 的物理表身份；按现有配置和四表临时排除后，保留 **2,654 张表、5,084 个有向表对**。它们与目录中的全部物理表节点不是同一个分母。表身份沿用图的 dataset ID，不把不同来源的同名表合并。

排除规则沿用[现有口径](evidence.md)：配置中的参数、字典、日志等命中项，加员工、机构及两张证券基础表的临时分析排除。配置快照也写入计算摘要。排除只改变分析视图，没有删除图节点、改变永久配置或认定这些对象没有业务价值。

### 表图如何得到

```text
源物理表 ──READS_TABLE──→ 任务 ──WRITES_TABLE──→ 最终目标物理表
                          ↓
          每任务读表 × 最终写表，去自连，全局去重表对
```

先在全图计算度数，再按 schema 展示；schema 是展示维度，不是预先裁剪的分析边界。仍保留过滤后无边的 IO 节点。

这是任务级表关联口径。多输出任务可能产生读写组合；此前识别的 175 条仅由多输出任务支持的表对仍在基线中。没有因为切换到 Neo4j，就把这些表对提升为逐输出确认的因果血缘。

## 3．表权重保留多个分量，先区分复用与承接

此前的探索排序为：

```text
原热点分数 = 出度 + sqrt(入度 × 出度)
```

它适合寻找复用和汇聚候选，但容易让直接下游很多的公共输入占据前列。本轮增加有向、无权表图上的路径中介性：对每对可达的起点和终点，统计最短路径经过某个中间节点的比例，再求和；端点本身不计入。多条等长路径分摊权重。

| 对象                                                   | 入／出度 | 原热点排名 | 路径中介性排名 | 可达下游表数 |
| ------------------------------------------------------ | -------: | ---------: | -------------: | -----------: |
| 销售合约基本信息 `t98_otc_deri_comp_sale_info`         |   31／44 |          4 |          **1** |          262 |
| 折算后月标准资产 `index_grp2_std_ast_aft_covt_mth_apd` |   28／46 |          3 |          **2** |          151 |
| 折算前月标准资产 `index_grp2_std_ast_bef_covt_mth_apd` |   17／10 |         47 |          **3** |          170 |
| 交叉销售月日均 `index_grp3_compscal_otcderi_cs_mthapd` |     3／4 |        138 |          **4** |          171 |
| 协议关系历史 `t03_agt_rela_h`                          |    9／98 |          2 |          **7** |          212 |
| 账簿附加信息 `t03_otc_deri_book_adtnl_info`            |   2／155 |          1 |         **17** |          300 |

这里不是宣布账簿变得不重要，而是找到了两个不同维度：账簿广泛被复用；销售、月日均和标准资产在可见加工路线中承担更多承接作用。交叉销售月日均只有 3 入、4 出，仍能处在大量上下游最短路径之间；只看直接度数会低估这种位置。

这些指标仍有边界：

- 可达下游数是静态表关联范围，不是实际受影响的金额、用户或报表数量。
- 路径中介性偏好位于较长可见链中间的节点；它不是业务价值、必经性或实际吞吐量。
- 基线中的多输出组合关系、缺失采集和来源边界会影响路径统计。
- 本轮过滤后的有向表图未发现非平凡强连通分量；这只描述该表图，不证明 SQL 内部或按日期展开的实际加工没有反馈与自读写。

**后续保留指标向量，不急着合成一个总分：**直接复用、输入汇聚、路径承接、字段值复用、控制复用、证据覆盖分别报告，再由当前学习问题决定优先级。

## 4．字段统计先处理身份和输出范围

直接从图中读取 `VALUE`、`CONDITION` 字段边，共 **84,868 条**：其中 VALUE 82,918 条、CONDITION 1,950 条。它们是图内字段关系，不是全量 SQL 的完整字段引用清单。

源字段按平台、数据源、限定表名精确对回物理表身份；本次 54,327 个不同源字段节点均可映射。目标按任务和写入身份对回最终 `WRITES_TABLE`。2,041 个目标写字段节点无法这样映射，相关 3,593 条边单列保留，没有混入本次最终输出热点。它们包含内部暂存或未映射写入，不能一概判成脏数据。

### 不能混用的几个分母

| 步骤                  |   表对及边类型组合数 | 含义                                            |
| --------------------- | -------------------: | ----------------------------------------------- |
| 精确映射后的原始聚合  |                4,514 | 同一表对的 VALUE、CONDITION 分开算              |
| 应用配置及四表排除    |                3,895 | 此时仍含自连                                    |
| 去掉 81 个自连组合    |                3,814 | 与原表图的去自连口径一致                        |
| 再与原 5,084 表对对齐 |                3,798 | 另 16 个组合不属于该外部读表×最终写表基线       |
| 合并同一表对的边类型  | **3,661 个不同表对** | 其中 VALUE 3,659、CONDITION 139；137 对两者都有 |

因此 **3,661／5,084＝72.0%** 的原表对出现了本次所查的值／条件字段足迹。剩余 1,423 对不能叫无贡献或弱连接：可能主要承担关系控制，也可能存在字段材料缺口。

另有 16 个组合与外部读表×最终写表基线不一致，其中包含带 temp 命名的对象到正式结果的连接。尚未逐项确认是内部暂存、读写口径或其他原因；本轮不据此判错，也没有把它们加回基线改变分母。

### 三种统计单位

1. **字段热点：**以精确源物理表和列名聚合，分别统计不同消费任务、不同目标表、不同目标表字段；不是直接数边，也不是数读写 occurrence。
2. **表对字段宽度：**同一源表→目标表涉及多少不同源列、多少不同目标列。多个任务共同支持同一表对时对物理列去重。
3. **具体写入的输入足迹：**继续沿用[第一版方法](05-discovery-method.md)限定 `write_observation_id`。这适合解释某个加工，与全局物理表聚合是两个粒度。

VALUE 中既有能绑定读发生处的 READ_FIELD，也有 PHYSICAL_FIELD 兜底。这些统计没有把候选接续升级为确认；一个字段足迹存在，也不保证能沿 `CONTINUES` 自动追到唯一的上游写者。

## 5．新发现：很多表边很窄，但少字段不等于弱业务作用

在与原表图对齐的 **3,659 条 VALUE 表对**中：

| 字段足迹形态                   | 表对数 |      占比 |
| ------------------------------ | -----: | --------: |
| 只有一个源字段                 |  1,308 |     35.7% |
| 至多两个源字段，含上一行       |  1,817 | **49.7%** |
| 涉及目标已发布写字段不超过 10% |  1,167 |     31.9% |

三行是不同或嵌套条件，不能相加。这些结果证明等权表图会把许多窄连接和较宽的加工输入放在同一等级。

全局表对的目标字段覆盖率采用：

```text
targetCoverage(A → B)
  = 在该表对中被记录为依赖 A 的不同 B 列数
    ÷ 图中 B 的所有已映射最终 WRITE_FIELD 列名并集大小
```

分子和分母都会跨 B 的生产任务、写入和分支聚合。它不是 DDL 宽度，也不是某次写入中有多少字段来自 A，更不是金额贡献比例。不同源表的目标列集合可以重叠，覆盖率不可相加成总贡献。

| 同样进入创收日报的连接         | 相关目标字段／目标字段并集 | 本轮解释                               |
| ------------------------------ | -------------------------: | -------------------------------------- |
| 销售基础表 → 创收日报          |                     40／72 | 较宽的主体字段联系，涉及 36 个源字段   |
| 账簿 `map_undrl_cd` → 创收日报 |                      1／72 | 狭窄的直接输出足迹，但其控制作用须另查 |

这里的 40／72 是整张物理表跨写者的聚合，不应直接替换第一版对某个限定写入的统计。另有账簿 `bel_dept` 和协议关系 `rela_agt_id` 分别关联互换明细的 `department_id`、`book_id`，各占 1／131 个目标写字段，显示出身份、归属连接的窄字段特征。

最初据此考虑统一降低公共表权重。随后控制字段统计表明，这一步必须修正。

## 6．把值依赖热点与控制热点并排，修正公共资产策略

以下按不同消费任务数展示部分热点；范围为能映射最终输出、两端应用分析排除的字段记录。字段热点不等同表对基线中的路径统计，也不代表纯数值贡献。

| ----------------------------------------- | -------: | -----: | -----------: |
| 交易源 `d_trd_otc_trade.key_otc_trade_id` |       48 |     25 |           27 |
| 折算后月标准资产 `index_val`              |       46 |     46 |           75 |
| 账簿附加 `bel_dept`                       |       44 |     30 |           30 |
| 协议统计历史 `stati_cont_desc`            |       40 |     28 |           34 |

这让数值复用与身份复用浮现出来：标准资产的单列指标承接许多结果，汇率一列进入大量输出表达式，身份和名称则有另一种复用方式。指标只有一列，也可能是核心；不能用源字段数多少代替重要性。

### 关联、筛选与分组控制热点

另直接统计 `PHYSICAL_FIELD → DATASET_CONTROL → TARGET_WRITE`。本轮原图记录 48,717 条控制边；经最终写入映射、配置及四表排除、去自连、与原表对基线对齐，保留 37,126 条。保留边中 FILTER 16,602、JOIN 13,499、GROUP_BY 7,025。

| 源表／控制字段                   | 消费任务 |  输出表 | 主要用途                   |
| -------------------------------- | -------: | ------: | -------------------------- |
| 账簿 `book_agt_id`               |  **165** | **150** | JOIN                       |
| 账簿 `busi_date`                 |      165 |     150 | FILTER 为主                |
| 账簿 `src_tbl`                   |      164 |     150 | FILTER 为主                |
| 协议关系 `agt_id`                |  **107** |  **94** | JOIN                       |
| 协议关系 `strt_date`、`end_date` |   各 105 |   各 92 | FILTER／JOIN               |
| 账簿 `bel_co`                    |      101 |     101 | 其中 100 个任务用于 FILTER |

任务数按集合去重，同一字段可在一个任务中承担多个控制用途，不能累加各用途任务数得到总任务数。

**策略修正：公共表可以在主体字段视图里折叠，但其控制关系要保留为独立上下文。**账簿和协议关系常只提供少量输出值，却广泛决定接上谁、选哪天、保留哪些记录；把它们统一当弱边会损害解释。

本轮还验证了两个表示限制：CONDITION 边数不能代替业务规则数；类似 CASE 判断可能落在 CONDITION，也可能嵌入 VALUE 表达式。DATASET_CONTROL 在该快照中只有 FILTER、JOIN、GROUP_BY，没有 WINDOW 子类型；这不意味着 SQL 没有窗口，窗口输入也可能体现在其他表达式证据中。

后续应保留至少两种联系：用于发现主体加工的输出字段联系，以及用于恢复范围、身份和日期语境的控制联系。两种联系如何共同决定最终分簇权重，本轮尚未校准。

## 7．先试简单拆图，确认它解决不了什么

### 剥离外围树枝与连接薄弱点

把方向暂时忽略，反复剥离无向度小于 2 的节点，得到 2-core；它衡量连接冗余，和业务核心不是同义词。

| 结构层次               | 本轮结果                                            |
| ---------------------- | --------------------------------------------------- |
| 原弱连通分量           | 124 个，最大 2,340 表                               |
| 2-core                 | 1,365 表、3,911 边                                  |
| 核心连通分量           | 8 个，大小为 1,333／7／5／5／4／4／4／3             |
| 核心诱导子图关节点／桥 | 19／5                                               |
| 核心双连通块           | 28 个，最大 1,258 表，随后 23、11、7 表             |
| 被剥离部分             | 1,289 表、959 棵树，其中 843 棵挂接核心、116 棵独立 |

剩余核心的 97.7% 仍在同一连通块，92.2% 在同一双连通大块。主体连接并非仅由少数可切断的公共桥造成。

账簿、协议关系、销售基础、折算前后月资产、交叉销售月日均六个重点对象都在最大双连通块中，且都不是核心诱导子图的关节点。销售及月资产表在原图中出现的关节点身份，部分来自外围挂树。因此，**高中介性不能解释为唯一必经桥。**

局部仍有值得观察的结构：23 表双连通块集中于 AML；11 表块围绕 AUM 评分，经 `wide_idx_cust_aum_tot_score` 接入。它们是局部候选，不是对整个图的业务分区。双连通块还可以共享关节点。

被剥离的 1,289 表包括 749 个源、355 个终点、138 个单入单出、20 个分流、6 个汇聚、2 个多入多出和 19 个孤立节点。已有 L001 与 L002 两条链都会被剥掉，而 L002 含标准化和回补规则。**剥树不能用来删除知识、判定低价值或统称运输层。**

### 标签传播及公共复用降权试验

对无向化表图做异步标签传播，使用五个固定随机种子 `1、7、19、43、97`。比较等权边，以及每条有向表边先赋权 `1 / sqrt(源表出度)`、再无向化的复用降权版本；节点和原表对均保留。

等权试验的最大组为 545～677 表，经常把账簿、协议关系、创收、保证金、香港和结构参数包在一起。复用降权后虽然大组经常变小，但账簿所在组仍在 5～291 表之间变化。降低公共出度影响，并没有自动换来稳定、可解释的边界。

本次设置不用于确定业务簇。这个结果只能说明此次方法、权重与种子敏感，不能泛化成标签传播算法不能用，也不能选择看起来最漂亮的一次结果宣布分簇成功。完整运行摘要、收敛次数和敏感性结果保存在计算摘要中。

## 8．以字段足迹筛选主体连接，形成局部阅读候选

在已对齐的 VALUE 表对中，筛选：

```text
不同源字段数 >= 3
且 targetCoverage >= 阈值
```

再把这些连接暂时无向化，计算连通组。这个试验偏向字段联系较宽的主体加工，主动避开一列标识把许多主题粘在一起的情况；它也会排除重要的单列指标、系数及控制资产，因此只能作为一个分析视图。

| 覆盖率阈值 | 保留连接 | 进入分组的表 | 连通候选组 | 最大组 |
| ---------- | -------: | -----------: | ---------: | -----: |
| 30%        |    1,329 |        1,529 |        308 |    193 |
| 50%        |    1,095 |        1,390 |        357 |     42 |
| 70%        |      934 |        1,248 |        362 |     23 |

阈值升高既会切开组，也会让节点完全退出，组数变化不能单独评价质量。50% 不是优化得到的阈值，只是本轮展示候选的一个截面；未进入的 1,264 张基线表不代表没有业务作用。

50% 截面中，按实际成员暂命名的三个候选为：

| --------------- | -----: | ------------------------------------------------------------------------------------------------------------ |

成员及每条入选连接的字段数见[计算摘要](graph-analysis-20260908.json)的 `strongFieldGroups`。这些组包含图中保留的测试、导出或来源变体；还没有筛成正式业务链，也没有证明每两张成员表都紧密相关。

这些候选的价值是缩小下一步阅读范围：先看到主要字段沿哪些对象连续组织，再恢复账簿、关系、字典和日期控制，以及较窄但重要的指标连接。局部组仍需用具体写入、分支、粒度和 SQL 规则核验。

同一 AUM 区域在双连通试验中是 11 表局部块，在强字段试验中可形成 23 表候选组。二者使用不同边和边界定义，不矛盾，也不能混用数字。**簇的定义必须随图层和分析目的一起说明。**

## 9．图消费的增量如何归因

| 观察                          | 可以确认                                         | 暂时不能确认                                        |
| ----------------------------- | ------------------------------------------------ | --------------------------------------------------- |
| 原全局数字与图复算一致        | 已发布图足够支持这类表级结构统计                 | 图中多了此前投影没有的表级事实                      |
| 月日均从原排序 138 到中介性 4 | 增加路径视角会改变候选优先级                     | 这个对象的业务价值精确排第四                        |
| 字段值与控制热点分离          | 能更具体地区分公共资产的不同职责                 | 少字段公共表可以统一降权或删除                      |
| 字段筛选得到局部候选          | 可以缩小主体加工的阅读范围                       | 已得到完整、稳定、互斥的业务簇                      |
| 本次直接读图完成分析          | graph 的统一关系查询与新分析方法共同产生分析增量 | 这些发现只有 graph 能获得，或已证明读取性能优于投影 |

之前主要逐份读取任务投影，再在内存拼表图；本轮全局统计直接消费已发布图中的表级 IO、VALUE／CONDITION 和 DATASET_CONTROL，复用统一身份、任务内字段关系及控制关系。跨任务 CONTINUES 接续只在此前小范围 trace 中验证过可查询，没有参与本轮全局热点或分簇计算，也没有计入本篇全局增量。若用同样方法重新整理投影和相应证据，也可能得到同样结果。**明显增量是相对于此前已经完成的分析，不能全部归因于存储产品本身。**

现成 CLI 提供 status、search、trace、detail、processing 等入口，但当时没有全图热点、表边导出或完整链的成品命令。本轮全局分析通过已有连接读取只读 Cypher，再在内存计算。因而这是图数据可消费性的验证，还不能宣称 CLI 已把这些方法做成标准产品能力。

图负责全局关联与候选发现，Facts、投影负责具体加工结构与写入证据，原始 SQL 用来确认表达式、分支和范围；这些层次的职责可以衔接。图入口中的 detail／processing 会回读发布证据，其公式内容不能全部算成 Neo4j 原生查询产出。

## 10．后续可复用的分析顺序

1. **固定版本和范围。**核对 READY、发布版本、物理身份、材料覆盖、临时与永久排除规则；复查过程中发现版本变化应重新建立基线。
2. **先做可比的表级基线。**保留表→任务→表的方向与支持任务，去重表对、排除自连；不要把调度邻居当数据血缘，也不要悄悄补入内部临时边。
3. **同时看复用、汇聚和路径承接。**保留各项指标，选择不同形态的候选；用核心、关节点等检查区分高中介与唯一必经。
4. **分别计算字段值与控制热点。**源与目标都绑定物理身份及最终写入；明确任务、表、物理列、发生处、边数的区别。
5. **建立字段联系的分布。**先报告单列／少列比例、目标覆盖率和未覆盖表对，再选择权重；未知连接保留为未知。
6. **生成多个局部候选视图。**结构核心、无向块、字段较宽的连接可并列比较；公共控制资产以外围上下文保留，重要单列指标单独纳入检查。
7. **主动测试边界敏感性。**比较阈值、种子、权重和证据层，不把组变小当作成功；记录稳定成员、易变成员和加入／退出原因。
8. **再把候选变成学习问题。**对选中的输出，核验具体写入、粒度变化、首次应用的规则和分支差异；允许同一表参与多个知识片段。
9. **分别登记完成程度。**表级结构、字段足迹、自动接续、候选分组、SQL 解释和业务确认分开计数，避免用局部案例或聚类数量代替全图完成。

现阶段优先保留的策略是：**用表图找位置，用字段值联系圈主体，用控制联系补上下文，再由加工语义决定知识片段边界。**下一步值得验证的是这些候选是否让阅读更集中、是否漏掉关键规则；本轮没有测量学习耗时或同事使用效果。

### 本轮取数与计算的最小复现说明

使用现有 `openAssetGraph()` 配置建立 READ 会话，先后核对 READY 与版本。表级取数沿 `SLAssetNode` 的 TASK、PHYSICAL_DATASET 和 `SL_ASSET_EDGE.kind` 为 READS_TABLE／WRITES_TABLE 的边聚合每任务读写集合；全过程限定同一 graphId，忽略调度关系。

字段取数按 VALUE／CONDITION 保留源、目标节点及关系元数据，对源物理身份和目标最终写入做映射；控制取数则使用 DATASET_CONTROL，并按 subtype 区分。统计使用集合对任务、表和小写物理列去重。候选分组只在明确的表对交集上计算。

路径中介性在原有向表对上计算；2-core 与双连通分解暂时忽略方向；标签传播使用第七节的权重和种子，最多 100 轮，当前标签并列最优时保留，否则在最优标签中按种子选择；强字段分组使用第八节三组阈值。各方法使用的图不同，结果只能按各自定义复核。

这份记录支持按固定证据重做分析，但没有新增可执行分析 CLI 或维护一套统计框架。此次只写知识文档及结果摘要，没有修改源 SQL、图发布、配置、解析器或 HTML，也没有扩大第一版 109 个任务的业务语义取证范围。
