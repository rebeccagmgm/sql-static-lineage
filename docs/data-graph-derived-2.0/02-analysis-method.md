# 执行方法：依托图组织、拓宽并完成业务加工知识

更新：2026-09-09。保留“图上单元＋跨单元专题”，进一步明确先核读具体加工行为、再验证职责边界，并由正文与专题共用规则证据。全图统计、角色分类、Facts 消费与旧解释继续复用。方法更新不代表新的簇或知识覆盖已经完成，实际进度见 [工作入口与覆盖](work-index.md)。

## 一、目标：形成图的解释层

目标读者需要系统理解公共基础、核心模型、主要加工过程和规则差异，并能从解释回到依据。知识库依托既有 data-graph：**用图确定位置和范围，用字段及控制证据发现差异，用正文解释节点和加工关系，再把各单元接成可学习的全貌。**

知识库同时支持两种组织：沿节点、路径或簇解释对象和加工；按“业务对象＋用途”跨单元汇总证据，形成账簿筛选等专题。两者都必须落到具体图对象、字段和发生位置，专题名称本身不能充当无限扩展的边界。图仍是正式材料的可重建投影；业务解释不反向充当 SQL 事实，不因编写知识而新增图节点类型或改变血缘合同。

每轮建设先登记固定图版本、采用的关系视图、总体图范围和计划交付的知识单元。全图底账保留未归组、孤立、材料缺失和暂不研究的部分，说明选择与排除原因。若只交付一个子图，就明确称该子图的知识交付；不能用少数热点代表全域，也不能在验收时缩小范围以适配已完成内容。

全貌允许先有粗略分区，再依据证据调整。调整要留下成员变化及原因，原有范围与未完成项不能静默消失。既有同版本统计足以定位时直接复用；建立全局认识不要求每批重新计算全图。

## 二、图上知识单元与跨单元专题

### 1. 沿图解释节点、路径和簇

| 单元         | 图上的锚点与范围                                           | 应回答的问题                                                         |
| ------------ | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| 节点说明     | 具体表、字段或任务 ID，明确考察的邻域、用途和材料范围      | 对象是什么，怎样形成，关键字段如何被使用，哪些用途存在差异           |
| 加工路径说明 | 确定的输入→任务／写入→输出片段，必要时限定分区、字段及分支 | 输入经过哪些筛选、连接和计算，怎样形成相应粒度的结果                 |
| 簇说明       | 固定的主体成员、内部连接、边界输入输出及公共依赖           | 这些节点共同承担什么职责，主线和重要分支怎样协作，与其他单元如何衔接 |

单元是文档中的组织方式，复用现有图 ID 和证据身份。单节点不默认包含所有上下游；一张宽表可以按不同字段或写入参与多个单元。节点、路径和簇可以相互引用，不要求每张表单独写一篇，也不要求所有单元互斥。

深度取证优先从一项具体加工行为开始：**某个输出／具体写入→相关分支→输入、条件和计算→结果含义**。用已有任务、写入、分支／scope、输出字段和必要分区定位，不新增一种图节点或正式合同。说明粒度以能够独立解释的结果及共同规则为依据，不默认每个字段、谓词或任务都需要独立成篇。

每个单元至少登记以下内容，可直接放在既有 Markdown、CSV 或证据索引中：

- 图版本、单元名称及说明页面；名称可以用业务语言，成员必须能定位到真实图对象。
- 主体成员和选取理由；路径保留任务／具体写入，字段说明保留物理字段及读取位置。
- 采用的关系类型、方向、邻域或其他选取规则，以及实际成员清单或固定清单引用；仅保存会随 current 变化的查询不够。
- 边界输入、输出去向和外部公共依赖；候选关系、未知身份和查询截断分别登记。
- 本轮要解释的问题、需要区分的字段／分支、目标深度、证据引用、覆盖状态和缺口。

在所选关系视图中，成员与边界都要列清。Task 读表×写表形成的边界只能称加工关联候选；要说明某字段影响某次输出，仍需下钻对应写入和关系路径。分区或写入发生处不同，不能仅凭同一物理表节点当作同一份数据。

### 2. 按业务对象和用途组织专题

专题提供横向认识，例如“哪些业务靠账簿筛选范围”“不同过程怎样按状态纳入合约”“哪些金额使用哪种汇率”。专题成员可以来自多个不相邻的簇；它们因问题和规则相关而共同展示，不因此产生新的物理血缘关系。

以“账簿筛选专题”为例，其范围由固定图范围、已定位的账簿字段／身份映射和筛选用途共同限定。不能只找账簿附加信息表的消费者，因为合约、持仓等表上的账簿字段也可直接参与 WHERE。相同字段名先作为候选，再核对物理来源和对象含义；无法确认的字段映射单列。

专题应回答哪些加工使用该对象、在哪里使用、按什么规则区分，以及已知业务含义。每条至少列出：

| 内容           | 账簿筛选专题应保留的证据                                             |
| -------------- | -------------------------------------------------------------------- |
| 加工与图位置   | 任务、节点／路径／簇、输出；业务名称有证据才使用，不能从 schema 猜测 |
| 字段与发生位置 | 实际读取表、账簿字段、别名、relation 和分支                          |
| 筛选规则       | 完整谓词、取值集合或参数／子查询来源、日期和附加条件                 |
| 共性与差异     | 哪些分支共用规则，哪些使用不同集合、排除、配置或优先级               |
| 解释与边界     | 对记录范围的作用、代码含义已知与否、写入定位和未确认项               |

从 WHERE 可先形成明确编号纳入／排除等分组；需要比较配置驱动的资格控制时，再按同一专题的已定范围纳入相关 JOIN 或其他过滤机制，保留机制区别。单纯 GROUP BY 账簿属于粒度用途，不能混算为筛选。

例如 204172 的 `Book_Agt_Id IN ('10218', '10231')` 同时进入其加工路径说明和账簿筛选专题。前者解释它如何与状态、本金及日期窗口共同形成结果；后者比较各加工怎样使用账簿控制范围。共用同一证据定位，不重复制造两份事实。

专题可以作为独立学习入口，并回链到相应单元正文。专题覆盖保留候选字段／任务分母、已核读范围、未映射字段和材料缺口；“已发现这些用法”不等于“所有账簿筛选都已找全”。有限专题清单纳入本轮交付，新的专题候选不自动成为完成前提。

## 三、从结构候选形成可解释的范围

### 1. 用已有结构获得广度

复用出入度、消费计数、弱连通分量、最大线性链、字段联系及现有候选组。选择位置同时考虑公共基础、核心汇聚、跨片段连接、关键消费端和重要单列控制；高出度不能直接替代业务重要性，schema 也不能直接代表业务领域。

公共资产至少区分身份映射、关系有效期、参考参数、共同业务事实和技术支撑。一列系数或纳入条件也可能决定结果，不能因字段少而忽略。公共依赖可在多个单元中引用，不必把其全部消费者吸入同一个簇。

算法簇、强字段联系和线性链均为候选。先从候选位置选取具体输出或写入，在已有证据允许的范围内核读其值与控制路径，再判断哪些加工行为具有共同职责。簇的成立依据包括共同输入输出、内部加工衔接、粒度及规则分支，需要时拆分或合并并记录理由。已有边界清楚的簇可直接推进；边界不清的候选不应先被要求“整簇讲圆”，更不能为迎合候选成员无限扩查。

### 2. 用字段和条件发现增量知识

字段的重要性还来自其实际用途。WHERE、JOIN、CASE、GROUP BY、WINDOW 中的字段，可能分别控制纳入范围、身份匹配、分类、粒度和时间选择；即使没有作为输出值传递，也值得解释。

例如任务 204172 的三个分支在合约表上使用：

```sql
Book_Agt_Id IN ('10218', '10231')
```

这里新增的认识是：`Book_Agt_Id` 在这些分支中承担纳入范围控制，所选取值是区分加工范围的证据。它应进入该字段的用途说明、分支比较和对应路径正文。三个分支使用同一集合属于共性；其他消费者若使用不同集合，应单列差异，不能先假定业务等价。具体账簿含义和筛选缘由仍需定义证据。

字段条件至少保留“所在表／读取位置—完整条件与取值—用途—作用分支／关系—可定位的输出范围—证据”。保留 AND／OR、NOT、NULL、日期参数及嵌套层次；不能把一个 OR 分支中的条件当成所有记录都要满足的限制。无法定位到具体输出时明确写出控制证据的范围。

同名字段不自动是同一业务身份；相同常量也不证明两个分支等价。上述过滤发生在合约表上，不自动生成对账簿附加信息表的物理依赖。跨表的账簿规则可以建立带依据的文档交叉索引，但不能冒充确认血缘边。

字段用途和取值差异可帮助细分簇内分支、修订候选边界或确定下一单元。一次 WHERE 命中支持局部作用判断；其全局重要性还要结合影响、覆盖和消费位置，不能只按出现次数评分。

### 3. 正文与专题共用规则证据

规则条目是对已有证据的可复用解释，可先存放在现有证据文件或 Markdown 条目中，再由节点／路径／簇正文与专题引用。它保留实际字段及完整表达式、简明用途、适用上下文、发生位置、证据版本与解释状态；无须先建设全量规则库才开始交付知识。

相同谓词可以共用已核对的局部解释，但各任务、写入和分支的发生位置及附加条件继续保留。`Book_Agt_Id IN (...)` 可能只是“账簿＋状态＋日期”等完整纳入规则的一部分；不能将每个 WHERE 条件自动宣布为独立业务规则，也不能只凭文本相同合并整段加工。

例如账簿筛选证据在加工正文中说明它如何参与结果，在账簿专题中说明哪些加工采用相应集合和机制；两者引用共同证据条目。已有条目解释发生修正时，检查其引用位置，避免两篇文字分别维护而产生矛盾。

## 四、把既有五条路径组织为一次可完成的工作

| 既有能力         | 在新组织中的职责                                               |
| ---------------- | -------------------------------------------------------------- |
| ① 全图结构统计   | 提供总体范围、候选位置和未覆盖部分的底账                       |
| ② 结构组织与简化 | 形成节点邻域、路径和候选簇，列清主体与边界                     |
| ③ 表级业务标签   | 解释成员的对象和角色，辅助选取与阅读；标签保持来源和待确认状态 |
| ④ Facts 消费分析 | 提取字段用途、条件、分支与写入证据，支持差异识别和范围修订     |
| ⑤ 加工知识摘要   | 形成单元正文与跨单元专题，综合共同规则与例外，衔接图位置并验收 |

这些能力按需要组合，不要求先完成全域标签或所有聚类后才能写正文。总体范围与计划交付目标先登记；实施主线为：**图上定位→核读具体加工行为→归纳规则及差异→验证职责并综合成单元→横向组织专题→按既定范围验收。** 每批按以下顺序推进：

1. **图上定位。** 从节点、路径或候选簇确定本批具体输出／写入及相关分支，限定核读范围和问题。专题则固定对象字段、用途及检索范围，并逐项定位相应加工行为。将已有说明映射进来，保留可复用内容和探索稿的状态区别。
2. **核读加工行为。** 程序复用缓存和已有提取能力，提供相关输入、完整局部条件、计算、输出绑定和证据。模型讲清这一行为的输入范围、加工顺序及结果含义，不默认遍历一张表的全部消费者，也不每换对象重写提取逻辑。
3. **归纳规则及差异。** 在既有材料上整理可复用规则条目，保留发生位置、条件上下文和例外。范围内的新发现进入字段说明和共同证据；超出范围的发现先定位到边界或候选队列。
4. **验证职责与组织范围。** 用已核读行为判断哪些路径应共同解释，再核对主体、重要分支和边界输入输出。需要修订候选簇时记录依据；其余成员未核读就保留相应状态，不能随归组升级为已解释。
5. **综合正文与专题。** 集中说明共同规则和背景，逐项对照重要例外，讲清节点／路径怎样配合。正文与专题引用相同规则证据，分别回答具体过程和横向比较的问题；簇说明与专题都不能只有链接目录。
6. **验收并衔接。** 核对既定目标、成员与边界，分别检查来源覆盖和解释覆盖，标明完成或部分完成。连接已有相邻单元，再依据全图未覆盖位置选择下一批。

边界可以被证据修订：如果新发现改变主体归属、输出含义或关键分支，先记录新增／退出成员、原因和对交付的影响，再更新本单元。不能一面宣称范围固定，一面把后续发现全部排除；也不能让每个新对象自动递归为当前任务。

## 五、证据消费与解释深度

图用于位置、成员关系和导航，Machine Facts／固定 evidence 用于关系算子、表达式、绑定和写入定位，业务资料用于定义与规则缘由。各层保留来源及适用范围；旧正文提供复用线索，不因已有文字就升级为直接事实。

优先消费原始 Facts 的真实 relation／expression／binding 身份、完整条件和源文本。Facts 已能表达的结构无需模型重新解析；表达式截断、控制路径不清、槽位缺失或解释存在歧义时，补读对应 SQL。按任务声明检查与结果相关的 prepare、create、query、finish，特别关注目标端后处理。

不能将 JOIN 同侧表达式的共同输入当成直接对端，也不能将关系预览或任意前若干条证据冒充完整模式依据。值 trace 不等于完整加工，detail 返回同语句控制也不等于每条控制精确影响某个字段。重要结论绑定其真正作用的分支与写入；保留 CONFIRMED／CANDIDATE／UNKNOWN 和截断边界。

| 研究角度         | 正文需要说明的内容                                                     |
| ---------------- | ---------------------------------------------------------------------- |
| 对象与一行的含义 | 连接的对象、键的角色、分组或展开怎样改变粒度；区分意图粒度与真实唯一性 |
| 字段的业务作用   | 值来源、身份连接、范围筛选、分类、日期选择、分组和计算分别是什么       |
| 共性与分支差异   | 来源、取值集合、常量、NULL、公式、连接方向、日期窗口和更新方式逐项比较 |
| 规则与结果的关系 | 规则改变会影响哪些记录、属性或金额；后续去重／汇总能否消除，前提是什么 |
| 状态与质量上下文 | UPDATE／MERGE／DELETE、旧状态、质量 SQL 所检查的键、字段、区间与盲区   |

“规则首次应用”只限定在已核验路径；参数定义与参数应用分开。独立质量检查与加工中的 FILTER／JOIN 控制分开统计，检查存在不证明约束成立。

用少量明确标为虚构的示例解释关键差异，核对算术、日期窗口、条件优先级和空值行为。由结构推演的例子不能当作实际业务数据或已发生问题。没有证据解释业务为什么如此规定时，说明当前实现做了什么并登记定义缺口。

## 六、拓宽、综合与收尾

### 单元怎样完成

单元验收针对预先登记的范围和解释深度，至少满足：

- 成员与边界可定位，采用的关系及证据版本清楚，采样或查询截断未伪装为完整范围。
- 正文能独立讲清承诺解释的对象、主流程、输出含义与粒度，以及相应关键字段和规则。
- 范围内重要分支和例外有具体依据；只核读代表样本时，其余成员仍标未核读，不宣称整个簇已解释。
- 公共依赖、输入与输出接口已经交代。簇有综合说明；成员解释共同支持主线，不能只累加文件或列链接。
- 缺口明确到受影响的判断。缺失足以改变承诺的主结论时，标部分完成；外围定义未知可保留，但要限定已经完成的认识。

静态解释可以完成“SQL 预期粒度与可能扩行条件”的说明，同时保留实际唯一性未知；它不能据此完成“生产数据绝不扩行”的承诺。结构已算、材料／模板已核对、指定问题已解释、单元已完成分别报告，不能相互代替。

专题另核对对象字段的纳入依据、用途分类和检索覆盖。若承诺回答固定范围内“哪些加工使用账簿筛选”，就需要交代该范围的候选与未核验项；只研究几个样本时，应按样本认识交付。专题完成不会自动提升其所引用节点或簇的其他问题覆盖。

覆盖检查分开回答两个问题，可沿用同一覆盖记录而不另建系统：

- **来源覆盖**：选定图范围内，哪些任务、读取、字段、分支和写入已经定位／取得证据，哪些未核读、材料缺失或无法映射。
- **解释覆盖**：已取得的关键规则中，哪些已经解释、哪些引用已核对的共同说明、哪些仍待解释及原因。

已提取规则都有说明，只能证明这些提取结果的去向；不能证明源范围的规则已经全部取得。用原始结构清单与提取记录核对来源范围，保留解析、截断和未检查分支等限制；两种覆盖的分母不能互换。

### 怎样拓宽而不无限延长

完成一单元后，结合它的边界连接和全图未覆盖位置选择下一个单元，同时检查低度数但重要的结果与控制字段。新发现先登记其图锚点、增量认识及所在／候选单元；是否纳入当前批、后续批或仅作背景需要明确决定。

规则差异可形成新的字段说明、分支对照、专题条目或单元，但并非每条 WHERE 都需要新文章。跨单元共性集中复用，特殊规则保留发生位置；专题帮助把分散在不同簇中的同类规则组织起来。每轮综合后应能用更清楚的主线解释更多已知关系，而不是让读者为理解一句话跳转更多页面。

### 整体怎样收尾

整体验收以登记的总体图范围、目标单元和专题清单为依据：列入本次交付的单元与专题达到各自解释深度，关键跨单元接口接通，入口能够展示总体位置、专题入口和推荐阅读路径，未归组、未研究及材料缺口都有位置和说明。

总体图范围中的重要未解释区域不能靠归为“其他”或临时排除而消失。交付范围调整应显式保留原范围、变更理由和剩余工作；尚有影响既定目标的缺口时，报告阶段成果。全图统计完成、所有节点有标签或首个簇写完，均不授予整库完成。

已完成单元保持其版本和范围。后续拓宽可新增单元；只有相关证据或边界变化影响既有结论时才修订旧单元，图换版不自动要求重写全部正文。

## 七、复用、版本和执行边界

使用在线图查询时，先通过 `status` 核对 READY、版本和发布覆盖，开始与结束核对版本。固定 manifest／publication 可用时保存引用；缺失时登记缺口，使用有明确身份的已有缓存或材料，不冒称已验证旧发布一致性。固定旧基线可以继续研究，回答当前全图则需建立相应新基线，两者不得混合。

比较旧、新任务集合及材料身份，区分新增、退出、变化、一致和无法比较。文件名、时间戳或读取位置一致不证明 SQL 语义一致。证据相同的局部规则可复用；即使 SQL 未变，上下游变化也可能改变角色、影响范围和字段覆盖分母。

从两套旧知识库的索引定位“图对象／任务／写入—问题—证据—解释范围”。模板复用只授予声明范围的“模板已核对”；JOIN 数、CASE 数、文本相似或安全结构签名仅用于找候选，业务常量、条件、日期参数、来源身份和写入语义继续比较。

默认一个执行者连续推进。程序批量取数、落地明细、去重和缓存，模型先读摘要再读局部证据；关键复核聚焦身份、公式、分母、纳入范围、分支和示例。每批明确材料范围与补证限度，实际成本同时考虑取证、解释、核验、用户阅读和维护；不可获得的费用与 Token 不估造。

图、SQL、Facts、发布配置与源系统保持只读，新增分析和知识放在 `docs/data-graph-derived-2.0/`。保留现有改动、两套旧知识库和用户 Excel；不默认重建图、修改提取器、开发 HTML、扩采全系统、创建新任务或自动化。必要补证按已有授权处理；局部未知不能成为无限扩查或先建通用框架的理由。

## 八、沿用的结构与字段统计口径

以下口径继续服务于图范围选择，不因知识组织方式变化而重定义。

| 分析视图               | 单位与用途                                                 |
| ---------------------- | ---------------------------------------------------------- |
| 表级加工关联           | 物理表→任务→物理表，观察复用、汇聚、连接和线性片段         |
| 字段值与分支依赖       | READ_FIELD／PHYSICAL_FIELD→WRITE_FIELD，观察值联系及其覆盖 |
| 加工控制               | DATASET_CONTROL 及真实关系身份，观察关联、过滤、分组等控制 |
| 调度、质量与交付上下文 | 单独保留相应任务与证据；scheduleReference 不作为数据血缘   |

不同类型关系不混成无类型网络计算权重。表级 IO 沿 `localClosure.externalReads` 对应 READS_TABLE 与 `finalWrites` 对应 WRITES_TABLE，按任务计算物理读表×最终写表，去自连、全局去重表对，保留支持任务、多输出标记和过滤后孤立的 IO 节点。它是任务级关联，不是逐输出确认因果。额外目录引用不混入 IO 分母；未知物理身份不按同名表合并。

先全局算度数，再按 schema 或其他视图汇总。保留完整基线、公共资产折叠视图和旧四表排除对照；本轮分析排除与正式接续终止策略分开，不能静默改配置。零入度或未知生产者不自动等于真实源系统，材料缺口、未研究和预期调度参考分开保留。

字段映射保留成功覆盖和失败原因，分别计数不同消费任务、目标表、目标物理列、读写发生处和边数。VALUE、CONDITION、DATASET_CONTROL 分开；VALUE 未必是纯数值贡献，CONDITION 数不等于业务规则数。控制按 `(taskId, statementId, relationId)` 去重仅称已入图关系数，缺少身份的项单列。

全局表对字段比例仍为：

```text
targetCoverage(A→B)
= A 经已映射值边触达的 B 不同目标列数
÷ B 在全部已识别最终写入中的不同输出列数
```

它不是 DDL 全字段比例、金额贡献、血缘完整率或某次写入比例。不同来源覆盖可重叠；分母不明或为零时标未知。新增生产分支会改变分母；正文中的具体写入仍需核验 `write_observation_id`。

先看单列／少列联系、覆盖比例和未知分布，再有限比较候选参数；旧“三个源字段、50% 覆盖率”不是固定业务划分标准。线性链按所选有向视图内部节点入度=1、出度=1向两端延伸，另列纯环和孤立情况。链长不是业务价值，单入单出仍可能有日期展开、窗口或状态维护。

现有基础统计优先复用。只有边界问题确实需要时，再使用 2-core、双连通结构、中介性或其他社区方法；近似计算记录种子与误差性质，不将近似称精确。多轮算法无信息增量时，转向字段、控制和实际问题证据。
