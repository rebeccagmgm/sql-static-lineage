# 可直接复制的接续 prompt

更新：2026-09-09。以下 prompt 已按图上单元与跨单元专题重组，详细要求见 [执行方法](02-analysis-method.md) 和 [执行说明](03-executor-brief.md)。

```text
请接续依托 data-graph 的业务加工知识库建设。

工作目录：
E:\02_area\股衍数据-数据cookbook\sql-static-lineage

先阅读 docs/data-graph-derived-2.0/README.md、02-analysis-method.md、03-executor-brief.md 和 work-index.md。01-research-findings.md 与临时交接文件只作历史依据，不覆盖本版方法和实际进度。

已有固定统计、候选组、角色标签、账簿和互换合约试点及规模口径正文。先核对并复用，不按“只有方法尚未开始”的旧状态重做。统计固定版本与当前发布分开；查询当前图时先用现有 status 核对，不混合不同版本的成员或证据。缺失旧 manifest 如实登记。

知识库同时支持两种组织：
1. 依托具体节点、加工路径或簇，解释对象、形成、使用、粒度及规则差异。
2. 按业务对象和用途形成跨单元专题，例如哪些业务通过账簿筛选范围；每条回链实际表字段、任务、分支和证据。

先在总体图范围内登记有限的目标单元和专题、选择理由及未覆盖部分。把已有材料映射到真实图对象，通过节点和候选簇定位，深度取证从具体输出／写入及相关分支开始，明确输入、条件、计算和结果。用已核读行为判断哪些路径有共同职责，再确定单元主体、内部关系及边界；边界清楚的簇可直接推进，其他候选允许有依据地拆分或合并，不强制所有节点互斥归簇。

程序提供已有材料摘要与必要的原始 Facts，小模型按需解释。WHERE、JOIN、CASE、GROUP BY、WINDOW 中的字段用途也有增量价值。例如 Book_Agt_Id IN (...) 既说明该字段负责范围控制，也提供分支取值差异；归入对应路径正文和账簿筛选专题。不能只查账簿维表的直接消费者，也不能把同名字段或专题关联冒充物理血缘。

重点解释输入对象与范围→连接和规则→计算→输出及粒度，并比较关键分支。在已有证据文件或 Markdown 中整理可复用规则条目，正文与专题引用同一证据，保留每个发生位置及附加条件。一条 WHERE 可能只是完整规则的一部分，不按谓词文本相同合并整段加工，也不先建设全量规则库。簇正文讲清内部协作和外部接口，专题横向比较实际用法，都不能只是链接目录。必要时补读 SQL，未查明的代码含义不猜测。

首批使用已有材料完成一次“具体加工行为→共同规则与差异→职责清楚的图上单元→复用规则形成专题”。需要组成簇时先用真实路径验证边界。按证据报告完成或部分完成，不能用继续增加单表说明或方法文档代替本轮实质交付，也不能把几个样本当作整库完成。之后结合边界连接和总体未覆盖位置选择下一单元，不让新发现自动递归扩张当前范围。

新成果全部放 docs/data-graph-derived-2.0/。图、源 SQL、Facts、配置、两套旧知识库及用户 Excel 保持只读，保留现有改动。不要先修图、开发 HTML、建设通用框架、全系统补采或另开任务／自动化。

程序批量整理并缓存，不每换一张表重写提取器；模型先摘要后局部证据，相同材料与解释按适用范围复用。每批限定材料和补证范围，未知登记到受影响判断。结构已算、材料／模板已核对、指定问题已解释、单元／专题完成分别报告。

最终按预先登记的图范围、单元和专题清单验收。分别检查来源覆盖（哪些任务／字段／分支已取得或核读证据）与解释覆盖（已取得关键规则是否已解释或引用共同说明），不能把后者当作前者。核对重要分支与跨单元接口，不临时缩小范围来宣布完成。每批简报新增理解、综合和复用、完成范围、关键缺口及下一步。直接交付实质解释，不只提交计划。
```
