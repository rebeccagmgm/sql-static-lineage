# 数据加工地图：沿对象深入分析

当前主入口：[打开数据加工地图](http://127.0.0.1:8768/)。先启动本机服务；构建和 CLI 命令见[使用说明](../scripts/inventory-map/README.md)。

## 本轮改变了什么

首页从任务汇总改为具体对象的加工分析。点击表、任务或字段，会在原画布展开，保留场景起点和其他连接；点击 schema 进入对象区域。业务解释、字段表达式和 SQL 在画布下方阅读，返回时恢复场景与镜头。

默认案例是 `pdata_n.t98_otc_deri_comp_sale_info`。页面直接保留四个写入任务及消费者，可以继续调查：

1. 点 `init_nom_prin`，比较四个写入分支的表达式、物理输入字段和配置分区。
2. 点 `86840`，看来源与输出字段，再从表达式链接跳到同一证据版本的 SQL 行。
3. 继续点 `107491`，读销售基础如何进入附加明细，并查看已有公共知识中的日期与粒度解释。
4. 从“探索 Schema”进入 `pdata_n`，或搜索其他真实 schema；选择一个表继续分析。
5. 从目录表或视图读取原始定义、列注释与定义候选。定义支持分页阅读，不能解析 CTAS 时不虚构字段。

同名字段不是相同口径的证明。例如本机当前证据中，期权分支的本金表达式包含汇率 CASE 与本金相乘，金仕达分支按互换类型选择 dynamic_notional 或 notional；极速分支本层引用已计算的本金，物理输入指向 dynamic_notional。应继续读各自 SQL 的内层处理，不能仅凭外层表达式认定金额单位、日期范围或汇率口径一致。

`原信息`实际根目录为 `E:/02_area/股衍数据-数据cookbook/数综基础信息/原信息`。本轮只接入所需的两份 Hive 文件，没有为扩大数字导入全部 RDBMS 材料，也没有新生成全域 Facts 或投影。

旧 table-network 中的证据路径已有失效样例，因此新加工关系从当前共享投影重新计算，没有将旧表关系和当前字段证据拼成同一个版本。

## 分析中保留的区别

- 物理对象保留原始 dataset 身份；同名且不同实例不合并。
- 元数据清单和定义的 GUID 不总相同。按名称检索得到的定义显示为候选，不直接贴成物理表的字段或说明；选中定义记录可以读它自身的完整 SQL。
- 平台目标声明在连线上写“配置目标”；配置分区不等于实际运行写入范围。
- 输出字段按 write binding 关联表达式。JOIN/FILTER 等控制关系与字段值来源分开；自连接的不同读取发生次、AMBIGUOUS/UNKNOWN 状态都保留。
- 点击读取 SQL 时核对投影、证据和 SQL 内容哈希；源变化会要求重建，不悄悄串版。
- 场景最多 70 个对象、120 条关系、12 个连续展开对象；超限说明缺口，可“以此为中心”继续。浏览器只读取当前场景和分页内容。

## 运行与验证

加工索引真实构建用时约 17.1 秒、峰值 RSS 210 MiB。该结果是本机一次实测；构建不代表全量业务分析已经完成。

构建、查询及证据回归 37/37 通过，包括连续展开保留上下文、字段写入归属、同名实例隔离、定义候选、SQL 行导航、自连接歧义和联合搜索分页。浏览器验收产物位于 `artifacts/inventory-map/analysis-browser/`。

原加工地图保持在 `/baseline`；上一版库存汇总在 `/inventory`，作为定位和覆盖核对的辅助入口。
