## 1. 第一版的目标

围绕现有股衍材料，解释清楚主要业务对象、区域职责、关键加工主线和重要例外，并让读者通过原地图逐层进入这些解释和依据。

用户认可原地图，是因为它呈现了加工体系的形状：来源、采集整理、模型主题、应用加工、交付之间存在主路线、并行分支和横向支撑。第一版要加深对这些关系的理解。可复用框架、自动布局和全库覆盖暂不作为交付目标。

“分析明白”的范围是：**对本批可见体系形成有依据、能讨论、能追证据的解释，并清楚指出重要空白。** 不要求先逐一读完 3,615 个任务，也不把固定材料说成完整股衍生产体系。

### 第一版完成后的读者体验

- 看总览，知道主要区域各自做什么，以及为什么不是一条严格串行流水线。
- 点来源，知道它提供哪些业务对象、表与视图如何组织、哪些对象被什么下游使用。
- 沿一条关键业务主线深入，知道每一步改变了什么，尤其是对象、日期、粒度、金额与使用用途。
- 点加工区域，先看其内部职责和主要路线，再进入明确标注的案例；不会从整个区域突然跳进几个来历不明的任务。
- 遇到不确定结论，知道已经确认到哪一层、缺什么证据，以及这会影响哪个判断。

## 3. 用五个问题组织分析

下列问题构成一条阅读顺序，不是五个同时开工的大项目。先形成整体判断，再深读主线，最后用对照路线检验解释是否过度简化。

### 问题一：当前股衍加工体系到底怎样分工？

**要回答：**主要来源提供什么；odata、pdata 各区域、应用层和出口分别承担什么职责；哪些区域已能解释，哪些还只是根据名字和网络定位。

**已有基础：**原骨架已经识别采集与整理、PDATA 的不同职责、DM 内部加工、交付与监控日志的区别。

**本次补强：**

1. 对总览每个区域写出“主要输入—核心职责—主要输出—关键消费者”，能定位到实际对象或任务。
2. 区分区域内已理解的主要对象族与尚未解释的部分；一个样例的结论不能覆盖整个 schema。
3. 标出会改变全局认识的例外，例如绕过模型的直接读取、共享参考输入、返回来源区域的输出关联。
4. 复核旧稿和页面的口径差异：以明确的材料版本解释，不沿用相互冲突的旧数字或名称。

**产出：**一份简短的全局解释与待核问题表，挂回原骨架。每个区域都有明确的认识状态，暂不深读的区域也有理由。

### 问题二：一份合约／交易信息怎样进入销售基础宽表？

**要回答：**主业务对象是什么；四产品分支各取什么来源；主记录、腿、事件、持仓、参考资料分别补充什么；这些来源如何进入销售宽表，它与并行实体模型路线的衔接已知到哪一步。

**已有基础：**已有四产品来源及销售宽表的代表解释，也观察到了模型路线和直接成宽表的并行关系。

**本次补强：**

1. 从最终宽表需要表达的业务对象出发，回看来源与关键关联；不能只按 SQL FROM 顺序介绍表。
2. 对主线涉及的来源对象补用途、表／视图性质、重要键与日期含义；缺证据的属性保留未知。
3. 区分“构成主体记录的输入”“控制纳入条件的输入”与“补名称、身份、参数等属性的输入”，解释关键关联是否可能扩行。若连接证据不足，作为解释候选而非事实。
4. 说明四产品分支哪些相同、哪些不同，差异对宽表使用者有什么影响；不预设同名字段就有统一含义。

**产出：**来源到宽表的可穿透主线，以及少量真正需要比较的对象说明。读者能按产品理解“主记录—纳入条件—身份关联—属性补充—产品分区”。Titans 来源页从这些已理解对象展开，同时保留其他可见成员入口。候选 `(busi_date, grp_id, agt_id)` 不能直接当作已证明的主键，也不能预设四产品都已经形成同一种“一合约一行”。

### 问题三：合约快照进入按日明细与收入后，日期和粒度怎样变化？

**要回答：**每一步想表达怎样的一条记录；源业务日期、合约有效期、计提日期、目标分区分别起什么作用；按日展开后下游如何消费，哪些 Join、聚合或补充可能改变结果粒度。

**已有基础：**107491 的按日展开和 223867 收入分支已有知识正文与证据；不能重新概述它们代替新调查。

**本次补强：**

1. 将已有日期与粒度结论放到一条连续主线上，明确每个结论绑定哪个任务、输出和条件。
2. 从既有正文中选择一个会影响读者使用数据的未决问题补证，例如关键 Join 的条件含义、某收入组成的来源，或日期定义的适用范围。223867 已有核读基础，230202 在旧稿中仍主要是表级定位；应先判断这种解释深度差异是否影响当前主线，再决定是否补读，不能默认收入各产品都已讲清。
3. 对“设计上期望的粒度”“SQL 实际构造方式”“数据唯一性是否经运行验证”分别表述。
4. 找到一个真实下游使用位置，说明它怎样依赖这些日期／粒度选择。材料缺失时明确停在可证明的位置。

**产出：**主线中的日期与粒度变化图，以及相对原有销售链正文新增的结论、修正或缩小后的不确定范围。

### 问题四：同名本金等字段，在哪些条件下可以按同一口径理解？

**要回答：**四产品分支对“初始”等概念的实现是否相同；历史选择、金额来源、汇率处理和日期条件各有什么差别；这些差别会如何传递给已知下游。

**已有基础：**四产品本金案例已经展示部分表达式差异，以及一个下游的汇总／NULL 处理。

**本次补强：**只挑选会改变使用判断的未决点，沿正式图／Facts／SQL 或已有业务资料补证；已经讲清的差异直接引用。没有依据时，不给出统一币种、正式初始定义或结果正确性的结论。

**产出：**一份主线内可阅读的口径说明：可比较的部分、带条件的差异、当前不能合并解释的部分，以及它们影响的下游。调查后仍未知也是结果，但应说明缺口为何重要、是否已经缩小。

### 问题五：哪些对照路线说明这套体系不能只用一条主线解释？

按对全局理解的影响选择对照，不要求把以下范围同时做深：

| 对照入口 | 要弄清的事情 | 避免的误读 |
| --- | --- | --- |
| pdata 实体模型与销售宽表的并行 | 两条路线服务的对象和消费需求是否不同，有哪些可见证据 | 宣称所有业务都必须先过统一模型 |
| pdata_news_n 的证券身份／市场资料支撑 | 它怎样让多个业务分支使用同一身份或参考信息 | 把高引用表直接称为一个独立业务阶段 |
| pdata_nds 或 odata 跨层直读 | 哪些场景直接供应源形态数据，实际改变了什么 | 用一个搬运样例概括整个区域 |
| 业务交付、日志、导出 | 哪些是数据输出声明，哪些是监控记录，哪些真实去向仍未知 | 把日志 success 或目标配置当作交付成功 |
| Titans 的反向输出关联 | 已知 4＋1 个任务的关联究竟来自配置、导出还是有明确写入证据 | 未核验就宣称存在生产回写 |

**产出：**对总览解释确有影响的对照或修正，以及未深读区域的边界。对照若没有带来新的认识，应止步，不继续为覆盖率扩查。

## 4. 执行顺序与每轮交付

### 第一轮：整理现有认识，形成问题地图

优先阅读上述现有成稿、原页面和必要的材料定位。将总览区域及主线整理成“已知结论／依据／重要缺口／优先级”。不重新导出图、不重算全部统计、不逐个查询目录对象。

**交付：**一个可讨论的全局解释、一条带已知与未知标记的主线草图，以及接下来最值得核实的问题。读者此时就应能知道本批会加深哪些认识。

### 第二轮：贯通一条业务主线，边分析边落到地图

先处理问题二和三，再处理主线中影响最大的口径问题。围绕明确对象与任务查询材料，每次调用要对应一个具体未知。

主线关键环节有了可读解释，就接入来源／对象／加工页，先交付一条从总览到证据能读通的路线。不要等所有分析结束才做页面，也不要先做完整页面框架再等知识填空。

**交付：**来源—加工—下游的连贯阅读路径；至少一处相对旧稿的实质新增认识、纠正，或通过调查明确缩小的证据缺口。旧结论原样迁移不算新增分析成果。

### 第三轮：用关键对照完善区域认识

按第一轮的问题优先级，从问题五中选取真正影响主线或总体判断的对照。同步完善 Titans 来源和 odata 的区域解释。

**交付：**一份更加准确的全局职责说明，能解释主要并行／支撑／例外；每个案例明确属于哪个区域职责、能代表什么、不能代表什么。

### 第四轮：完成地图阅读与内容验收

按读者问题走图检查：总览是否看得清，来源是否讲得明，区域是否有整体解释，关键对象是否能追到任务和证据，返回是否连贯。

**交付：**可阅读的深化地图、共享知识内容、主要结论及证据、重要未决问题和当前边界。技术问题只修复影响这些阅读任务的部分；暂不做另一来源迁移或全库泛化验收。

以上是持续交付顺序，不要求每一小步额外等待批准；遇到实际范围扩张或证据不足时报告对结论的影响。

## 5. 地图怎样深化

### 5.1 保留全局骨架的阅读组织

继续使用原总览解释主要区域、主流向、并行路线与交付边界。只有新的分析推翻或细化了原判断，才相应修正区域说明与连线解释。框数和数字不作为改造目标。

来源区域的细分服务于“不同来源提供什么”，无需把所有 schema 摊在总览上。共享知识中的说明和标签可以随分析积累，不必先建立完备词表。

### 5.2 Titans 来源穿透

点“Titans 可见来源”进入主画面分析，先解释来源组成、主线涉及的业务对象及其去向，再进入分类和具体对象。schema 是技术位置；交易、合约、持仓、参考资料等是有依据的业务阅读维度，不能混成同一个目录。

当前可见范围为 titans_dm 与 titans_refdata 的 234 个表身份。保留全部可见成员的查找入口；优先深读与业务主线有关的部分，其余成员明确未详读。不是先给 234 个对象全打完标签才能上线。

具体对象页首先解释用途、关键内容、已知类型、已见消费任务及已核实的使用方式，再提供任务和证据入口。分类清单和数量用于查找与界定范围，不能代替来源分析。

### 5.3 odata_n_tit 下钻

第一层先回答：进来的是什么、这里承担哪些整理职责、主要产物供谁使用，哪些类别已有依据、哪些未详读。

原两组代表链放在明确的案例层：

- 144134／144141：采集目标来自配置，后续读取 h15，不能暗示已经证实同一批次接续。
- 41540：展示 UNION ALL 和来源标识，不能将共同输出解释成已经统一业务口径或去重。

每个案例都要说明选它的原因及其在区域中的位置。不能再用三个任务替整个 odata 做完整性背书。

### 5.4 交互保留

来源、区域和对象分析在主画面穿透；任务、SQL、证据继续可使用右侧详情。保留面包屑、返回、缩放位置及原销售／本金知识入口。首批沿用既有 SVG 与布局能力，不要求先迁出所有人工编排或实现自动布局。

未来页面改造先输出并列的 `docs/processing-map-analysis.html`，作为本方案的独立候选入口；保留原 HTML，不与此前技术方案拟定的 processing-map-next.html 混用。本轮不生成这份页面。

## 6. 分析材料怎样消费

**默认继续使用原地图的固定结构材料和已有留存证据。** 本批不先建新的输入包、快照版本体系或图查询平台。

| 具体未知 | 首选材料 | 读取边界 |
| --- | --- | --- |
| 某对象被谁读取、有哪些输出关联、主线是否有其他分支 | 已有表级导出或正式图查询 CLI | 有界查询，区分完整成员与截断；表关联不提升为字段因果 |
| 表还是视图、字段和声明键是什么 | 本地元数据／DDL，复用现有离线读取器 | 按选中对象匹配；重名、类型未确定时保留未知 |
| 日期、金额、条件、Join、聚合怎样实现 | 已有 Machine Facts、SQL 留存或正式 processing／字段查询入口 | 绑定任务、输出、SQL slot／位置及适用条件 |
| 实现为什么这样设计、业务名词是什么意思 | 已有共享知识、对应业务文档 | 名称和相邻对象只作线索，不能代替该对象自身的依据 |

不用为了一个问题同时跑完 SQLite、Input Pack、Facts、图和全部原信息。采用能减少该未知的最少材料。

固定材料不足时，可以对明确对象补查；补到不同时间／发布版本的材料，要在结论旁记录其版本差异，不能默默混进原快照。只记录本次实际使用的版本、SQL 摘要或定位，不建设新版本管理平台。

本地 `数综基础信息/原信息` 已有大型 JSONL 与偏移索引读取能力。按主线需要的对象读取，不先重建全目录、不把原始文件全部载入内存。类型不能由 `v_` 前缀或 `gf_rdbms_table` 目录类别直接判定。

| 要回答的问题 | 对谁有用、影响什么理解或使用判断 |
| 结论 | 读者能直接理解的解释，关联具体业务对象 |
| 范围 | 对应对象／任务、产品、日期或材料版本 |

这张表是内容检查提示，不要求先实现 JSON schema、标签服务或通用知识加载器。已有机器可读知识继续复用，其余先以简洁的结构化正文保存。

允许补少量能重跑的定向脚本，如“给当前选择的来源成员列出消费任务”“核对一组任务的日期条件”。脚本接收明确对象范围，输出供分析使用的结果；不从小脚本扩展成全域平台。

等真实分析中出现重复，再决定抽取什么：反复用到的分类维度、相同的对象说明结构、重复的路线查询，才是后续复用工作的依据。第一版不以迁移到另一来源验证通用性。

## 8. 验收与停止条件

### 内容验收

1. 总览主要区域都有职责解释或明确的结构定位／未知状态；不能只凭 schema 名断言职责。
2. 一条关键业务主线能够连续解释来源、主体与补充输入、核心加工、日期／粒度变化和实际下游使用。
3. 相对既有成稿，明确列出新增理解、纠正或经调查缩小的关键缺口；不能把排版、统计和旧说明迁移计作新增分析。
4. 关键对照能支持或修正整体判断，尤其是并行模型路线、共享支撑、直接读取和交付性质；未深读部分不被默认纳入结论。
5. 重要口径差异带条件与证据，不把静态 SQL 当成运行验证；未知会影响什么说得清楚。

### 地图验收

1. 能走通“总览 → 来源／区域 → 业务对象或加工单元 → 任务／证据”，每层都比上一层多回答一个问题。
2. 来源页有用途与去向的解释，区域页有整体组织，案例页有选例依据与范围；侧栏名单不能代替这些内容。
3. 原有固定 SQL、销售与本金知识可读，返回与阅读位置正常，保留原页面与离线能力。
4. 页面上的陈述与知识正文一致；读者能找到关键结论的依据及未决问题。

### 何时停止继续扩大调查

当前问题已经能形成可靠解释，剩余不确定性不再改变本轮判断时，就交付并进入下一个问题。发现材料根本缺失时，给出具体缺口与影响；不以此为理由无限扫描周边任务。

第一版不要求未知清零。技术检查通过与用户认为“确实更理解这块加工了”分别记录；后者需要真实阅读反馈，不能由 agent 自行宣布。
