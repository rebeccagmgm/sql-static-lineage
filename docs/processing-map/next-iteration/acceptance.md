# 验收标准：可重跑与可阅读分别验证

日期：2026-09-07。状态：**待实施、待验收**。本文件定义实现完成后应提供的证据，不表示下列检查已执行。范围与规则见[本批入口](README.md)、[架构方案](architecture.md)和[详细实现方案](implementation-plan.md)。

## 1. 如何判定本批完成

本批分别报告技术结果与阅读结果，不能用其中一项代替另一项：

- **技术结果**：成员和关联可追溯、输入及解释版本明确、规则重跑确定、视图可迁移、原能力回归通过。
- **阅读结果**：用户可以从总览连续进入来源、类别、具体对象和证据，理解数据承担的职责、实际去向和仍未知的边界。

提交时逐项列出“已通过／未通过／待用户阅读反馈”，附实际路径或截图。技术通过但阅读仍像表清单、数量排行榜、随机挑选案例，不能称为黄金样本已经成立。未完成项写明对交付的影响；不得用勾选任务清单代替演示结果。

## 3. 技术验收

### T1. 固定输入导入和完整成员重算

**操作：**这次黄金基线验收显式提供旧 network、flows、summary 及完整的固定 SQL／本金专题证据，生成版本明确的输入包；从原始 edges 重建去重读／输出集合，与 tasks.inputs/outputs、tables.readers/writers 比较，再重算索引、schema 成员和方向，与两个 sidecar 对照。普通关系导入允许不带 retained SQL／principal；不能把本次基线兼容要求变成所有新图输入的前置条件。

**通过条件：**

1. 满足第 2 节基线；方向集合、schema 集合、任务／dataset 成员逐项一致，不只校验 count。
2. 检出以下真实一致性错误：少一个方向、多一个方向、漏一个合法成员、加入不属于方向的任务、重复身份、未知端点、schema 成员错绑。
3. 即使 count 被同步改成与错误成员一致，仍可检出差异；有效子集不能被误认为完整集合。
4. 输出报告能定位到方向／schema／成员 ID，便于修复输入；失败不覆盖上一份完整快照及 HTML。
5. 缺少必需关系输入或显式提供但不存在的附件时报告具体缺失文件，停止该路径；未提供可选旧证据时仍能导入关系并生成结构，明确缺少历史专题。不能转为全域采集、重新发布图或启动 Facts 全量生成。
6. 加入一个新 schema 的合法关系输入，并配上独立 graphVersion 的旧专题证据，重算结构仍可生成；旧专题进入有版本标识的历史入口或显示需复核，不挂作当前已验证内容，也不被旧 build 的固定版本闸挡住全部新结构。

**交付证据：**导入清单、重算报告、针对完整性缺陷的测试结果。导入包不能只包含指向临时目录的绝对路径。

### T2. 同输入确定与标签重跑

**操作：**以相同输入文件字节、knowledge、视图定义和算法版本连续构建两次，并改变导入位置／时间检查身份；再只修改一个 schema 的分类／阶段映射或一个对象的分类标签，使用同一输入包重建。

**通过条件：**

1. 前两次 snapshotId、规范化快照及布局结果相同；额外记录的导入时间、导入位置、构建机器和文件复制时间不进入内容身份。原材料文件自身的 exportedAt 等字段若改变，其文件字节及 inputRevision 可以改变；不承诺语义相同但重新导出的文件得到同一 ID。
2. 分类变更使受影响成员、聚合关联、导航目标及布局随规则变化；graphVersion 和原始成员身份不变，knowledgeRevision／definitionRevision 按实际修改变化。
3. 前端和视图算法无需增加 schema 特例，不能修改节点坐标以完成该演示。
4. 解释依赖及变更报告能指出影响；缺失解释仍显示结构和“待整理”，不能整批消失。
5. inspect 与页面读取相同快照，对指定来源、对象和方向返回一致的成员及版本，分页默认 30、最大 100，翻页可完整读取成员；不能从另一份最新图补充后伪装成同一次构建结果。

**交付证据：**两次构建摘要对照、变更前后分类配置和截图、视图差异报告。演示改动不得留作不真实的最终知识。

### T3. 标签、身份和元数据可信

**操作：**用本批 Titans 234 个成员及 odata 范围做有界元数据提取与分类；构造或选取多标签、无标签、同名多候选、类型缺失等对象检查行为。

**通过条件：**

1. 从共享 dataRoot 解析 knowledge；由独立 metadata 命令复用既有 JSONL 偏移索引读取器按对象生成不可变小包，build 只消费小包，不隐式建立全库索引，也不把全库 JSONL 或全部投影载入内存。
2. datasetId 为成员身份；同名跨来源对象不被静默合并。匹配区分 EXACT、CANDIDATE、MISSING，能查看范围与依据。
3. TABLE／VIEW 只来自受支持元数据或 DDL；原目录记录类型 `gf_rdbms_table`、图节点类型 `PHYSICAL_DATASET` 及名称前缀均不直接证明 TABLE 或 VIEW。
4. 多标签对象可在不同筛选下出现，联合数量按 datasetId 去重；默认画布主归属由稳定规则决定，其他标签不丢失。
5. 未分类成员可进入主画面，UNKNOWN 类型可见；无元数据不会被默默剔除。
6. 标签、说明与所依据材料绑定，材料时间及范围可追溯；元数据事实、知识分类、视图分组和节点坐标分开保存。
7. 不传 metadata 小包时仍可构建已有关系结构，对象类型保留 UNKNOWN、缺口明确；不能为了完成 build 偷扫原信息目录。metadata 的索引缺失／失效默认报告，只有显式 `--allow-index-build` 才允许顺序构建所需索引。

**交付证据：**提取范围与匹配报告、少量代表对象的绑定例子、多标签与未知对象截图。报告不能暴露连接串、内部地址或凭据。

### T4. 骨架计算、布局和隐藏方向

**操作：**通过视图配置生成初版等价 overview，再执行来源细化配置；检查主路线、跨层、同列和反向关联。

**通过条件：**

1. 初版保留 14／18 基线及可点击的真实成员；后续框数变化有配置和差异依据。
2. 所有新计算视图的坐标来自统一布局规则；配置、knowledge 和前端不存在为具体节点补 x/y 的特例。
3. 布局不改变关系方向、不删除逆向或交叉支撑边。全部 245 个方向都归入已展示、聚合隐藏或未映射集合，逐项可追溯，不能静默漏掉。
4. 总览保留五阶段阅读顺序，并能辨认主流向、并行路线、跨区域直读与交付边界；拥挤时通过规则分组／分页处理。
5. 节点文字、边标签和点击区域可读，标签不会被相邻卡片或边遮住；不以手补位置解决重叠。
6. 各视图遵守架构方案定义的节点／边预算，超限产生明确的分组或分页要求；不能截断后仍声称完整。
7. X“其他可见来源”是所有进入 O 的来源方向中，动态排除 S 当前命中的 schema 及 O 本身后的补集；基线标签下恰好等价于旧排除 titans_dm／titans_refdata／odata_n_tit 的规则。改变 titans_refdata 的 sourceSystem 使其移出 S 后，对应进入 O 的方向必须转入 X，反向迁回也不丢失或重复；X 可能包含其他加工区域，不能误称全部非 Titans 外部源。

**交付证据：**同一窗口尺寸下原图与新图截图、布局与方向覆盖报告、超限行为记录。

### T5. 主画面穿透与原能力回归

**操作：**离线打开新 HTML，走完“总览 → Titans → schema／类别 → 具体对象 → 任务／SQL”以及返回路径；再访问原有专题。

**通过条件：**

1. 来源、类别、具体对象的分析在主画面继续展开；右侧承担任务、SQL 和证据详情，不能用侧栏长名单代替来源分析。
2. 面包屑、返回和直达能到达正确层级；返回后恢复各视图的缩放／平移位置，开关侧栏不重置相机。
3. 本次固定基线下，任务详情、边成员、固定 SQL、销售知识正文、本金专题及仍保留的旧视图可达，原有证据边界仍展示；普通新图不带旧附件时，结构阅读仍成立，页面明确没有收录对应历史材料。
4. `docs/processing-map.html` 保留；新产物为 `docs/processing-map-next.html`，不能悄悄覆盖原入口。
5. `file://` 打开可完成整段阅读，不依赖网络、CDN、API 或 Neo4j；检查未发生外部请求。
6. 记录实际 HTML 字节数、最大视图规模、生成耗时和阅读体验；超过默认 12 MiB 预算需先调整嵌入范围，不能擅自改成在线服务。

**交付证据：**浏览器操作记录、关键截图、原 HTML 前后摘要、外部请求检查、产物大小记录。

### T6. odata 区域和证据边界

**操作：**从 overview 进入 odata，先阅读区域分析，再进入 144134／144141 与 41540 两组代表案例；检查 SQL 与知识依赖。

**通过条件：**

1. 首层回答区域输入来源、已经有依据的加工类别、主要产物与下游用途；范围、分类覆盖和未分类成员明确，不能仍用原 9 节点／7 边代表整个区域。
2. 原三个任务保留在显式案例页，并交代为什么选择、哪些结论只适用于案例。
3. 144134 的目标配置与 144141 的 `h15` 读取分开说明；`_p` 的日期分区与 `h15` 批次尚未匹配，图示不能画成已确认同批次连续链。
4. 41540 的 `UNION ALL` 和来源标识有固定 SQL 支撑；不能改称已经去重、统一业务口径或形成唯一标准数据。
5. SQL／证据摘要或适用 graphVersion 不匹配时，解释显示 STALE／需复核或停留在明确标识的旧历史案例中；历史证据使用独立 graphVersion，不得把旧知识悄悄当作新版本已验证结论，也不阻断合法的新关系结构生成。
6. 表级关联、目标配置、SQL 写入、调度邻居、运行状态的性质不混用。

**交付证据：**区域页和案例页截图、案例证据定位、一次证据失配检查结果。

### T7. 换来源验证复用

**操作：**在这批 3,615 个任务材料内，选一个开发 Titans 模板时未使用的来源，如输入中实际存在的 OIS 范围，补充范围配置和必要知识后重建。

**通过条件：**

1. 复用同一来源算法、布局和前端，允许新增 selector、标签和知识；不复制计算器、不增加指定 schema 的 if／switch。
2. 输出的组成、类别、消费方向、对象穿透和未知边界可读；不是只改标题后沿用 Titans 内容。
3. 给出至少一个对该来源成立、有具体对象和关系依据的阅读结论，以及仍待核验的问题；不能拿“共有多少张表”当作迁移价值。
4. 如数据不足以支撑某层分析，清晰展示缺口并保留已知结构；不得编造分类或调用全域采集补数。

**交付证据：**配置变更范围、迁移页截图、结论与证据、无需改算法／前端的 diff 证明。

## 4. 阅读价值验收

以下检查需要用最终页面回答，并由用户阅读反馈确认。实现 Agent 先提交自己的具体答案与证据入口，不能只写“支持查询”。

| 阅读任务         | 应能得到的答案                                                                     | 不能算通过的替代品                 |
| ---------------- | ---------------------------------------------------------------------------------- | ---------------------------------- |
| 看总览理解全局   | 区域职责、主路线、并行支撑、跨层直读和交付性质，能追到实际成员                     | 只解释五列标题，或只给数量和排行   |
| 进入 Titans 来源 | titans_dm／titans_refdata 的可见组成，主要对象用途与消费位置，哪些类型／分类尚未知 | 在侧栏列出 234 个名称              |
| 从类别进入对象   | 某对象记录什么、已知表／视图性质、被哪些任务和区域使用，必要时读 SQL               | 只有对象名称、度数和百分比         |
| 理解反向关联     | 知道 4＋1 关联存在，能定位任务，知道为何仍不能断言回写                             | 隐藏反向关联，或直接标为“回写源库” |
| 看 odata 区域    | 先理解内部职责与下游关系，再知道案例解释哪类加工和哪些未知                         | 两条精选案例链代替整个区域         |
| 换一个来源       | 同一阅读组织仍能解释新来源，结论来自其真实成员和知识                               | schema 名换了，其余图文照搬        |

至少交付三条具体阅读发现，覆盖来源用途／消费、需要判定的关联、区域加工职责等不同方面。每条都包含“观察到什么、据哪些对象或任务判断、目前不能证明什么、下一步可做什么”。可得出“证据不足，需要核验”这样的结论；不得为了凑发现数量使用未证实的业务判断。
