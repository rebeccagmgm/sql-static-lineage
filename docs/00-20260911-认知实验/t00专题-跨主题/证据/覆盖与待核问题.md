## 2. 已交付覆盖

- 对象：元数据核心199条，补入目录独有12个名称，形成211个名称的七组地图；原始物理范围311条另有完整提取。
- 字段：199条核心元数据中4186个已解析字段按对象组逐表展示，分区列单独标记；新增12个名称转向SQL DDL入口，不把DDL自动并入物理元数据。
- 来源：本地候选中357个任务名称可识别“模型+三位来源代码+三位序号”，涉及202个模型名称。只是命名覆盖统计，不等于357个已确认生产者；它与211目录名称集合不同。
- 内容：七条主线均有对象、粒度、来源、代表加工与使用规则；产品池和数据资产另有跨生产消费的详细案例，TIT/OIS有集中视角。
- 复核：完整SQL候选、选定SQL、码值、目录差异和来源出处均随专题交付。执行期验证结果见[交付核对](交付核对.json)。

## 3. 已确认的差异及使用影响

| 差异 | 直接证据 | 使用影响 |
|---|---|---|
| 12个核心目录名称没有旧字段元数据 | 目录差异JSON；全部有选定SQL入口 | 不可漏掉API、技能、智能体任务、档案管理等对象；DDL仍不是实时物理结构证明 |
| 7个元数据名称在新核心目录未命中 | 同上 | 不能推断已下线；包括应用系统基本信息和测试管理对象 |
| `t00_tbl_info`旧字段没有Tbl_Cmnt/Upd_time等，而113440声明并投影这些列 | [113440](SQL/113440.sql)与物理JSON | 搜索消费者确实引用这些列，不能只拿旧字段库指导当前查询 |
| 档案旧元数据Doc_Type与SQL Doc_Type_Cd不同；通用附件SQL另有MD5/排序/标题列 | [136762](SQL/136762.sql)、[173964](SQL/173964.sql) | 同表结构版本需并列，不能静默换名或省列 |
| 组卷关系SQL包含Qstn_Disp_No，旧字段目录未见 | [156794](SQL/156794.sql) | 展示顺序的证据来自SQL；不伪称物理字段已验证 |
| PURCH-IPM-PRJ、HORAE_TASK未命中对应本地字典；QSTN_CATE_CD同名异域 | [字典说明](../字典/README.md) | 保留未知、限定对象，不能就近配码 |
| Horae依赖列表与关系表的链接状态过滤不同 | [113573](SQL/113573.sql)、[113575](SQL/113575.sql) | 两种表达不保证数据集合一致 |
| TIT附件的Doc_Id/Attach_Id显式为空 | [173964](SQL/173964.sql) | 不能当该来源的可用唯一键 |
| OIS050源声明为OOM，业务来源OIS，另连OIS客户 | [212663](SQL/212663.sql) | 任务后缀、业务来源与物理来源须分开 |
| DMS目录称“增量追加”，选定SQL为日分区INSERT OVERWRITE | [232074](SQL/232074.sql) | 描述口径与代码表达不同，不据目录文字决定重跑语义 |
| DB_TBL记录modify_time为2029-02-07 | 组合定义JSON | 保存原值，不据异常日期判断新旧或当前有效 |
| ACM业务系统信息没有分区，Src_Tbl是普通列 | [62991](SQL/62991.sql) | 全主题不能统一套用“按来源分区覆盖” |

`PARSED`也不保证结构完整：`t00_bat_pcus_qry_task_det`、`t00_bug_task_adtnl_info`、`t00_cust_stmt_vchr_oper_task_adtnl_info`、`t00_horae_task_instc_info`、`t00_jira_task_lbl_info`各只解析到1至5列，需补原始DDL，不能把当前列数当完整表结构。

这些是静态资料之间的差异，不自动等于线上故障。字段版本差异尤其不能通过改写已有元数据来“消除”。
