# TIT 与 OIS 的 T00：合约周边的配置、券源与文件

[返回入口](../README.md)

TIT/OIS是整个T00中的重要来源视角。这里的对象围绕业务运行所需的配置和载体；合约主体仍应到T03，实际业务动作及流水应到T05。

| 对象 | 模型及源头 | 可确认的加工 | 不能越过的边界 |
|---|---|---|---|
| 期权流程模板 | `t00_req_proc_tplt_info`；TIT流程定义 | TIT324前缀身份、动作类型、默认标志、启用状态转码 | 有效模板不是一笔已执行流程 |
| 模板条件 | `t00_req_proc_tplt_def_cond`；TIT条件定义 | 同前缀模板引用、条件名/运算符/值 | 条件组合、优先级及引擎执行结果未知 |
| 券源池 | `t00_prd_pool_info`；TIT券源名称管理 | 池编号名称、OTC池类别、券源类型转码 | 池头不是实时库存 |
| 券源配置 | `t00_otc_deri_prd_pool_adtnl_info` | 还券/约券优先级、交易和约定方式等 | 不证明成员清单、可借余额或实际交易 |
| S3文件 | `t00_doc_attach_info`、`t00_tit_s3_attach_info` | 源文件属性和业务编号 | 通用表中Doc_Id/Attach_Id为空，不能当连接主键 |
| OTC附件补充 | `t00_otc_doc_attach_adtnl_info`；源声明OOM，客户映射OIS | 附件、源合约、源客户及CLIENT_ID映射 | 不自动绑定T03联合身份；映射唯一性与覆盖未验 |
| 功能清单 | `t00_sys_func_info`；TIT系统管理功能 | 功能ID/名称/代码和相关配置 | 本分支父级和层级留空，不能还原完整权限树 |

## 一个具体阅读顺序

理解“某笔期权为何可能需要审批”时，先从T03确认合约或办理对象；在T00查对应动作分类的模板和条件定义，再到实际业务流程记录核验本次选用哪个模板。不能只看CD1756有“生效流程”“终止流程”就把字典当作已经执行的状态机。

理解“某个文件属于谁”时，先确定它来自TIT附件还是OOM/OIS附件来源。前者提供Busi_Id且两个通用标识为空；后者提供源合约、源客户和客户映射。只有进一步确认这些源编号的目标模型转换规则，才可以连接交易或客户主体。

理解“券源能否使用”时，T00解释池类型和经营配置；具体证券成员、余额、有效库存及交易可用性还需要对应来源与业务数据。本专题不以一个配置状态代替交易判断。
