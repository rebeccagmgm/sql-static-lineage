# T00 字典：先确定代码域，再确定适用分支

[返回入口](../README.md) · [字段代码域候选索引](字段代码域索引.md) · [重点原值](重点代码域原值.md)

T00 不共享一套万能类别树。项目类别、任务类别、池类别、试卷类别和文件类别分别解决不同问题；一个值的含义依赖代码域及适用条件。

## 1. 先看哪些域

| 对象 | 代码域 | 怎样配合理解 |
|---|---|---|
| 项目 | CD598类别、CD418类型、CD449状态类型、CD419状态 | 租赁、投行、种子基金属于不同安排；立项状态与项目运行状态不能当同一流程步骤 |
| 项目客户关系 | CD1146 | 01主客户、02一般客户、03收购方、05被收购方等是角色，不能反向理解 |
| 任务 | CD646类别、CD647状态类型、CD648状态、CD650关系 | 任务种类、任务状态和依赖方向分开 |
| 池 | CD1259类别、CD1260类型、CD1261成分类型、CD1262状态 | 先决定哪套池，再解释成员到底是债券、池、利率还是参与方 |
| 文件 | CD1472 | 02回访单文件、03回访录音、08场外衍生品业务S3文件等 |
| 流程模板 | CD1755模板分类、CD1756流程分类、CD1754状态 | 期权流程定义适用于哪类动作，与流程是否发生分开 |
| 字段关系 | CD1958 | 01下游、02上游；是相对当前字段的方向 |

以上代码域可在[原值页](重点代码域原值.md)或[完整候选JSON](../证据/字段代码域候选.json)核对日期、来源、备注。码值快照状态是 **UNVERIFIED**，不能当作全量或实时定义。

## 2. 三个必须保留的冲突

**同名字段对应不同代码域。** `QSTN_CATE_CD` 同时命中CD167“试题类别代码”和CD899“问题类别代码”。前者本次值0/1/2/3是客观情况、主观意向等，来源备注限定柜台字典；后者是 `GKS-KNWLG / IQA-KNWLG`，表示知识系统类别。GKS生产SQL明确写 `GKS-KNWLG`，因此不能拿CD167解释知识库问题。[问题SQL](../证据/SQL/62875.sql)

**SQL值在字典快照中缺失。** `62906` 的项目类别为 `PURCH-IPM-PRJ`，本地CD598没有该值；`113573` 的任务类别为 `HORAE_TASK`，本地CD646也没有该值。应报告“代码存在于SQL、字典未命中”，不能改成最相近类别，更不能认定源数据违规。

**转码后的值可能仍是源代码。** TIT流程模板用 `NVL(DW_CD_VAL,IS_ENABLE)`，池类型用 `NVL(DW_CD_VAL,EQ_SOURCE_TYPE)`。字典中有01/02或001…007，不足以证明所有输出都已标准化；未匹配时会保留原值。Jira需求则使用999/99等回退常量，这又是另一种策略。[模板](../证据/SQL/207935.sql)、[池](../证据/SQL/208593.sql)、[Jira](../证据/SQL/62871.sql)

## 3. 来源转换与值解释是两件事

`REF_CD_CVT_MAP` / `_TEMP` 根据来源系统、源表、源字段、目标表和目标字段，把源代码映射到仓库代码。`REF_DW_CD_VAL` 则解释某代码域中的目标值。本次资产库保存的是后者的离线码值；未取得完整转换表行数据，不能仅凭SQL使用转换表就说转换覆盖已核验。

字段名不完全相同也不能直接硬绑：旧元数据 `t00_doc_info.Doc_Type`，所选SQL声明为 `Doc_Type_Cd`；`t00_req_base_info_s.Stat_Cd` 与各对象的 `*_Stat_Cd` 也不自动等价。先核对表、来源、版本和转换条件，再选择字典。

某些原值本身还有待确认备注，如CD1756中的 `ACT_PASSIVE/ACT_TERMINATING/ACT_TERMINATING_V2`。正文保留原备注，不把它们加工成完整且确定的期权流程状态机。
