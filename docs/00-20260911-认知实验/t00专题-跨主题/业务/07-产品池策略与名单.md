# 产品池、策略与名单：集合与成员决定了筛选口径

[返回入口](../README.md) · [本组字段](../资料/字段/07-产品池策略与名单.md)

## 1. 池、池成员和产品不是同一个对象

`t00_prd_pool_info` 回答“哪个池、叫什么、什么类别与状态”；`t00_prd_pool_compnt_info` 回答“池里有哪些成分、何时入池、来自哪里”。产品或证券自己的资料应去T02。一个产品可以属于多个池，一个池又可以容纳不同类型成分，不能将池行数、成员行数和产品数混为一谈。

| 来源与模型 | 池的业务含义 | 必须保留的差别 |
|---|---|---|
| PRD，pdata_n | 产品中心证券池 | 池类别 `PRD_SCR_POOL`，成员是该分支的产品代码 |
| TIT，pdata_n | 场外衍生品券源池 | 类别 `OTC_DERI_SCR_POOL`，附加资料保存还券/约券优先级等配置 |
| XIR，spdata_n | 自营场外债券池 | 类别 `SB_OTC_BND_POOL`，成分有独立类型，并保留源交易序号 |

类别、类型与成分类型分别来自CD1259、CD1260、CD1261。CD1261中包含债券、池、利率、交易对手、发行人，因此通用 `Compnt_Id` 不能一律按证券代码连接。[原码值](../字典/重点代码域原值.md)

## 2. PRD的成员是怎样挑出来的

池头来自 `P_CUSTOM_PROD_WAREHOUSE`；成员来自 `P_CUSTOM_WHS_PROD_REL`，以 `PRODWHS_ID → Pool_Id`、`PROD_CODE → Compnt_Id`。关联 `P_CUSTOM_FIELD` 取得自定义属性后，按池+产品、入池日期倒序编号，只保留RN=1。[156848.sql](../证据/SQL/156848.sql)、[156849.sql，38–74行](../证据/SQL/156849.sql)

这段代码保留当前选择的成员版本，不是完整的每次出入池事件流水。相同日期并列时没有稳定次级排序；自定义字段源若重复，也可能影响被挑中的属性。本次未以数据证明唯一性。

目标存量比对条件包括池、池类别、成分类型、成分ID；PRD这支成分类型明确留空，因此实际业务含义还依赖PRD来源。连接池头和成员时要分别限定各自来源，不能要求两个Src_Tbl相等。

## 3. TIT池附加表保存经营配置

TIT池头从 `K_EQ_EQUITY_SOURCE` 取券源编号和名称，将EQ_SOURCE_TYPE转换为Pool_Type_Cd；未命中保留源值。附加表从同一源保存还券优先级、约券优先级、交易/约定方式以及O32账户及操作员字段。[208593.sql](../证据/SQL/208593.sql)、[208592.sql](../证据/SQL/208592.sql)

这些字段解释券源如何配置和使用，不是证券库存或可借余额。池头存在不能证明当前池成分完整，也不能证明存在对应可交易头寸。TIT成分生产与实时库存不在本次闭合范围。

## 4. XIR：成员类型和交易记录必须保留

XIR分支将 `COMPONENTTYPE` 写入成分类型、`COMPONENT` 写入成分ID，同时保存入池/出池时间、操作者和 `SYSORDID → Src_Trd_No`。[110348.sql，38–62行](../证据/SQL/110348.sql)

同名模型因此不能完全沿用PRD的“池+证券代码”假设。自营债券池附加表还提供父池等信息，支持层级组织；本次保留字段，未验证整棵池树的无环性或所有层级数据。

## 5. 下游会把池变成业务筛选条件

已读消费有三种实际用法：资讯分类任务对指定PRD池筛选未删除成员，再按成员代码连接T02产品；营销销售任务取指定活动配置的池，用成员范围参与新客口径；移动端基金统计从指定池的自定义属性取有效期，再按交易日限制。[66074.sql](../证据/SQL/66074.sql)、[159558.sql，208–224行](../证据/SQL/159558.sql)、[98035.sql，407–413行](../证据/SQL/98035.sql)

可见“在池里”只是一个筛选维度，金额、客户范围、活动日期和业务状态还由下游各自决定。详细分析见[产品池完整案例](../实现详解/01-产品池从来源到下游.md)。

## 6. 策略和名单为什么也在这里

`t00_strg_info` 在FS2来源只收 `STRATEGYTYPE='1'`，构造 `FS2003-STRATEGYID`，保存策略名称、类别、创建日投影的生效日期和说明；状态、到期日期及策略内容等列在该分支留空。[240240.sql，47–66行](../证据/SQL/240240.sql)

`t00_list_info` 的字段同时包含名单内部编号、名单类型、黑名单标志、作用对象类型、作用对象编号及有效起止时间。按字段结构，它不应仅理解为名单头一行；一个名单可能面向不同对象。该支本次整理到结构与来源候选，尚未精读生产SQL确认实际去重键与外部判断机制。

算法、量化CTA策略与名单均有独立目录入口。不能把它们的存在推断成一个统一的策略执行引擎。
