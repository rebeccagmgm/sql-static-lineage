# 档案、附件与印章：载体、关联和管理状态分开

[返回入口](../README.md) · [本组字段](../资料/字段/03-档案附件与印章.md)

## 1. 不要把所有文件都当作一个附件模型

| 模型层次 | 入口 | 记录什么 |
|---|---|---|
| 档案对象 | `t00_doc_info` | 档案身份、类型、路径或流程关联等公共信息 |
| 附件载体 | `t00_doc_attach_info`、`t00_tit_s3_attach_info` | 文件名称、源文件类型、存储定位及业务编号等 |
| 来源专属属性 | OTC、投研、尽调、入职、对账单、云上管家等附加表 | 合约/客户关联、原文件属性或该业务专用信息 |
| 业务归属 | `t00_doc_evt_rela_h`；spdata_n另有档案与当事人、用户、机构的关系 | 该档案属于什么业务或由谁关联 |
| 归档管理 | `t00_doc_mgmt_info` | 采集、客户归档、综合归档各自状态和时间 |
| 印章管理 | `t00_seal_info`及状态、员工、机构关系表 | 印章身份、启停、保管与所属责任 |

图中可以先想成“业务对象—档案—附件”，但只有实际存在且可用的编号才能连接；TIT这一分支恰好说明这个限制。

## 2. TIT附件：不能拿空Doc_Id或Attach_Id连接

173964向 `t00_doc_attach_info` 写档案类型08，保留文件类型、文件名、存储定位、源数据来源和 `BUSI_ID → Busi_Id`。**该SQL把 `Doc_Id` 与 `Attach_Id` 都写成空字符串。** [173964.sql，38–64行](../证据/SQL/173964.sql)

因此，表名叫附件信息、DDL中有附件编号，不等于这个来源已经提供可用的全局附件主键。按两个空编号Join其他附件表可能造成扩行。这里应先用业务编号及来源语义定位，再核对文件级标识；本次未证明 `Busi_Id` 单列唯一，也没有核实每个文件可访问。

同源S3资料还有 `t00_tit_s3_attach_info` 的独立生产SQL。两个模型均有记录，不意味着可以把行数相加当附件数。[124870.sql](../证据/SQL/124870.sql)

## 3. OIS附件：业务归属与实际源表不同

212663的任务后缀为OIS050，输出 `Data_Src_Cd='OIS'`，但源表声明是 `ODATA_N_OOM.G_AMAZONS3_FILE_INFO`。它保留源附件ID、源合约编号和源客户编号，再以 `A.CUSTPTY_ID=B.ID` 左连同一天 `ODATA_N_OIS.G_HK_COUNTERPARTY`，把 `CLIENT_ID` 写入 `Pty_Id`。[212663.sql，27–46行](../证据/SQL/212663.sql)

这说明应同时保留OOM物理来源、OIS业务来源及客户映射。`Src_Comp_Id` 仍是源合约编号，不能假定已经满足T03协议编号及修饰符合同。LEFT JOIN未命中的客户将没有映射结果；本次没有读取行数据验证覆盖率。

## 4. 回访档案：相同编号前缀仍要核对来源

CC2档案分支从 `C_CCB_ARCHIVE_FILES` 构造 `CC2017-ID`，将 `SOURCE_ID` 写为流程编号；对应档案事件关系把同一档案ID指向 `SOURCE_ID`，关系02表示呼叫中心回访事件归档。[136762.sql](../证据/SQL/136762.sql)、[136764.sql](../证据/SQL/136764.sql)

目录补出的 `t00_doc_mgmt_info` 则从DMS的 `T_CCB_ARCHIVE_FILES` 使用 `CC2017-ID`，记录附件编号、采集状态、客户归档状态、综合档案状态及各自时间。[232074.sql，32–68行](../证据/SQL/232074.sql)

共享前缀提供了对照线索，但两者来自CC2与DMS两个源对象。没有来源同步或实际映射证据前，不能保证同数值ID就是同一份档案。归档管理SQL的日分区也与目录“每天增量追加”的文字描述不同，应分别保留。

## 5. 印章：所属部门与保管部门不同

`t00_seal_info` 的BPM分支保留印章类型、专管用户、保管部门、所属部门、状态、有效标志、启用/停用/销毁日期、申请流程和电子签章信息。[84458.sql](../证据/SQL/84458.sql)

保管部门回答谁负责保管，所属部门回答该印章归属于谁；不应只留一个机构ID。印章当前状态也不等于某次盖章事件。本次该SQL为渲染快照，部分投影和注释粘在同一行，只用作结构和源投影证据，不据此断言线上脚本不可执行。

档案与事件两端的实际唯一性、文件级主键、CC2/DMS编号一致性、客户/合约映射覆盖及文件可读性均未在本次进行数据验收。文件关系能解释业务归属，不能代替文件交付或归档成功证明。
