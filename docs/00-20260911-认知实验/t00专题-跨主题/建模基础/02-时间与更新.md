# 时间与更新：同样带日期，回答的问题不同

[返回入口](../README.md)

## 1. 先看日期承担哪一种职责

| 时间字段 | 例子 | 使用时的区别 |
|---|---|---|
| 业务观察日 | 需求、题目、评分、整改、AI技能的 `Busi_Date` 分区 | 限定某天资料，不是创建日或执行成功日 |
| 对象自身时间 | 项目开始结束、试卷创建、入池日期、附件创建时间 | 来源业务记录的时间；可为空，与加载时间独立 |
| 关系有效期 | `Strt_Date / End_Date` | 决定某一天关系或状态是否适用 |
| 数据处理时间 | `Data_Etl_Date / Data_Upt_Date / Data_Time` | 记录模型加工所使用的日期/时间，不能代表全部业务事件时间 |
| 快照观测时间 | SQL头部 `observed_at`、目录 `collected_at` | 说明证据何时取得，不表示SQL里的业务日期就是当天 |

## 2. 已确认的三类写法

**每日分区替换。** Jira需求写入来源+业务日期；RCC评分按业务日期及来源分区；DRC整改和AI技能也是日分区。分析数量要先选日期，或明确以对象跨日去重。[Jira](../证据/SQL/62871.sql)、[评分](../证据/SQL/62888.sql)、[整改](../证据/SQL/209830.sql)、[技能](../证据/SQL/234469.sql)

**一个来源分区中的当前属性维护。** 项目、PRD池和GKS问题等先把来源投影为临时数据，再与该来源存量做全外连接，区分新增I、变更U、删除D和不变S，最后重新写本来源数据。读取主表不能据此推断每次变更都保存了有效期版本。[项目](../证据/SQL/62906.sql)、[池](../证据/SQL/156848.sql)、[知识问题](../证据/SQL/62875.sql)

**关系历史维护。** 租赁项目客户关系按 `Strt_Date <= d AND End_Date > d` 读取当天有效关系；新增开链到2099-12-31，删除/变动关系在d闭链，旧闭链记录保留。这里明确是左闭右开，不宜使用包含两端的BETWEEN。[162666.sql，62–72及130–183行](../证据/SQL/162666.sql)

```sql
-- 仅展示已读租赁关系的时点筛选方式，不是跨来源通用查询。
WHERE Src_Tbl = 'ODATA_N_GLM.P_PRJ_PROJECT'
  AND Strt_Date <= :business_date
  AND End_Date  >  :business_date
```

同样带 `_h` 的其他表，需要分别看生产代码；不能仅凭后缀认定都采用完全相同的维护算法。

还有一个明确例外：ACM的 `t00_busi_sys_info` 在已见DDL中没有分区，Src_Tbl只是普通字段，生产为整表 `INSERT OVERWRITE`。因此“按来源分区写入”是大量模型的设计方式，不能不查结构就套到所有T00表。[62991.sql，24–100行](../证据/SQL/62991.sql)

## 3. 两个实际容易混淆的场景

**某客户在历史日期是否属于一个项目。** 先选当天有效的项目客户关系，再决定需要当前客户名称还是历史客户名称。关系有历史，并不自动让关联的基本资料也回到当时版本。租赁关系里的 `Create_Time` 又是源记录创建时间，不能替代 `Strt_Date`。

**某只基金在历史日期是否纳入一项运营统计。** PRD成员主加工按池+产品取最新入池记录；下游 `98035` 对指定池另从 `Pdef_Attr_Info` 取两个自定义日期键，条件为业务日不早于开始时间、严格小于结束时间。它使用的有效性来自这一池的配置，不等于通用 `In_Pool_Date/Out_Pool_Date`。[消费局部](../证据/SQL/98035.sql)

## 4. 历史快照与重跑的边界

本次选定SQL有模板变量，也有2026年5月、8月和9月的固定渲染日期。文件保存于9月不意味着按9月数据运行。部分脚本连续多次 `INSERT OVERWRITE` 同一目标，用于处理当天重跑及写回；顺序不能随意合成一条表级边，也不能据此宣称具有事务原子性。

本次没有执行这些SQL，也没有用目录或运行日志节选证明任务已成功、数据已到达。正文只解释所见代码的静态逻辑；当前实际版本及结果需要独立核验。
