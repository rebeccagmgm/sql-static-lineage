# 分类评价与状态：解释判断结果

[返回专题入口](README.md) · [平台分类对照](00-平台分类与业务阅读对照.md)

本章讨论的是“主体被怎样分类、评价或标记”。平台资产目录给**表**贴分类标签；本章各模型表为**主体记录**保存分类、评级、状态等值。两者都叫分类，但对象和用途不同。

## 1. 平台分类提供什么依据

本次目录将 `pdata_n.T01_PTY_RAT` 放入“客户风险信息”，把 `T01_PTY_STAT_H` 放入“客户衍生信息”。这能帮助组织章节，但不能据此认为评级表只含客户风险等级，或所有状态都属于同一个业务状态域。

02 中的 Pty_Cate_Cd 对应已找到的 CD002 字典，登记含义混合了主体性质、业务角色和来源语境。完整枚举统一见 [CD002 附录](附录-CD002当事人类别代码.md)；它不能替代本章的 Pty_Clas_Type_Cd / Pty_Clas_Cd、评级类型或状态类型，也不能把 CD002 的解释套给这些其他字段。

## 2. 按“类型＋结果”读模型

| 对象 | 先选什么视角 | 再解释什么值 |
|---|---|---|
| `T01_PTY_CLAS_H` | Pty_Clas_Type_Cd | Pty_Clas_Cd |
| `T01_PTY_INDT_H` | Indt_Clas_Type_Cd | Indt_Cd |
| `T01_PTY_RAT` | Rat_Type_Cd，并核对评级机构和来源 | Rat_Cd |
| `T01_PTY_SCOR_H` | Pty_Scor_Type_Cd | Scor_Rslt 与评分日期 |

字段入口来自[原对象与层级目录](../04-t01-层级映射-3.0.md)。它们是阅读坐标，不是本章宣告的正式主键。同一主体可以有多个类型、多个来源和多个时间版本，不能只取一个“最新等级”。

## 3. 评级表里的内容不只有一种评级

任务 179723 向同一来源分区依次写入 PI_LVL、RISK_LVL、AML_LVL、CRED_LVL、OTC_CUTP_LVL。各类型的来源字段、码值转换和实际取值源不同；反洗钱评级的 Real_Src_Tbl 与 Src_Tbl 分区标签还不相同。见[差异案例证据](../t01-系统核验/差异案例证据.md)。

原 PPM005 案例 204548 又把供应商级别写成 SPLR_LVL，评级日期、机构及生效/到期字段填空。因此，平台归入“客户风险信息”并不能替代对具体记录类型的解释；统一用“评级日期最新”也可能丢掉未填日期的来源。

这不是认定目录错误，而是说明目录分类的粗细与模型容纳的记录类型并不一致。

## 4. 码值、转码和分类目录分开查

- 表目录 `observed_classifications`：告诉我们资产归哪类。
- 资产码值库 `ref_dw_cd_list` / `code_values`：告诉我们代码域、代码值、中文含义与备注。
- SQL 中的 `REF_CD_CVT_MAP`：描述来源代码怎样转换为仓库代码，不能由字典含义反推实际转码已成功。

查某个代码时，至少带“字段或代码域＋类型条件＋来源＋快照日期”，并保留备注中的限定条件。同一个数字在不同代码域中不能互相套用。具体库位置和查询约束见[本地 SQLite 导航](../../local-sqlite-guide.md)。目前已单独提取并核对 CD002 的本地完整查询结果，其他业务代码域未在本章全量核验；资产字典快照状态仍为 UNVERIFIED，不能默认是线上最新全量。

## 5. 状态与时间怎样读

业务状态、模型删除标志、角色准入状态、区间开关链，分别回答不同问题。01 说明公共状态和删除资料，02 说明角色与准入的区别；这里补充状态类型和结果的解释。

日快照按目标分区选择日期；区间记录按具体起止谓词裁剪；只有固定起止常量的分支不能直接称为历史维护。源评价日期与模型加载日期也不能互相代替。算法差异集中见[来源、时间与消费专题](../04-t01-建模专题-3.1.md)。

如果问题是“某客户当时风险如何”，应先指定评级类型、来源和业务时点，再核对结果码含义；如问题是“当时是否允许交易”，还需要权限/准入和具体业务规则，评级结果本身不足以证明。
