# 经纪商视角：主体身份、交易服务与系统配置

核对日期：2026-09-12。与 [交易对手视角](专题补充-交易对手视角.md)、[02 主体类型与业务参与角色](02-主体类型与业务参与角色：明确它以什么身份出现。.md) 配合阅读。本篇围绕本地 T01 模型解释，不作为经纪业务法规或所有业务模式的定义。

## 1. 先区分三个视角

| 视角 | 阅读时关注什么 | 本地证据入口 |
|---|---|---|
| 经纪商 | 哪个机构提供经纪相关服务，在来源系统中如何登记和配置？ | `T01_BROK_INFO`；CD002 的 `280200` 及相关细分 |
| 经纪业务客户 | 谁作为客户接受经纪业务服务？ | CD002 的 `110100` 经纪业务个人客户、`210100` 经纪业务对公客户 |
| 交易对手 | 谁以交易对手身份参与相应业务？ | `T01_PTY_CUTP` 的身份、类型、内外部分类 |

这是角色维度的区别。某家券商在不同业务中可能承担不同角色，是否为同一家机构要靠身份对照确认。不能因为“都是券商”，就把经纪商记录直接当成交易对手记录。

交易通道又属于另一层：账户、平台参数、委托等记录描述怎样接入和执行业务。经纪商是参与机构；通道、账户和委托是连接或使用它的业务对象。下面列出的本地字段支持沿这些方向探索，但尚不构成已验证的完整连接链。

## 2. 经纪商信息表实际装了什么

Hive `pdata_n.t01_brok_info` 的注释为“经纪商信息”。从字段组成看，它同时保存身份资料、会员编号和来源系统的业务配置。

| 内容层 | 字段 | 怎样理解 |
|---|---|---|
| 身份与名称 | `Brok_Pty_Id`、`Pty_Cate_Cd`、`Brok_Name` | 经纪商当事人编号、登记类别、名称 |
| 机构分类 | `Brok_Clas_Cd` | 券商还是期货公司等分类 |
| 市场会员身份 | `Zj_Exch_Mem_No`、`Sq_Exch_Mem_No`、`Zz_Exch_Mem_No`、`Dl_Exch_Mem_No`、`Ny_Exch_Mem_No` | 分别为中金所、上期所、郑商所、大商所、上海国际能源交易中心会员编号；不要与经纪商主体编号混用 |
| 盈亏、两融与额度配置 | `Pal_Avl_Method_Cd`、`Marg_Para_Imp_Mode_Cd`、`Spec_Lmt_Mode_Cd` | 描述处理方式，不能当成余额、额度金额或持仓 |
| 核对、委托与合约配置 | `Mutl_Busi_Chk_Method_Cd`、`Supt_Unistke_Trust_Flag`、`Comp_Supt_Renw_Flag` | 多业务核对方式、支持合笔委托、合约支持展期 |
| 价格与分仓参数 | `Pric_Mode_Cd`，上海／深圳／股转分仓申报编号有效位数 | 描述价格模式和申报编号参数，具体取值、算法需继续核对来源 |
| 来源与时间 | `Data_Src_Cd`、分区 `Src_Tbl`、加载／更新日期、`Del_Flag`、`Del_Date` | 保留来源与记录生命周期；删除标志不能解释为机构注销或业务资格取消 |

同名的 `spdata_n.t01_brok_info` 另有港股、新加坡、郑商所分仓申报编号有效位数及 `Real_Src_Tbl` 字段。它与 `pdata_n` 的结构不同，应分别阅读，不能把这些额外字段自动归到 `pdata_n`。

## 3. 最值得熟悉的六组字典

### 3.1 登记身份：CD002 / Pty_Cate_Cd

| 代码 | 字典原文 | 备注或解释 |
|---|---|---|
| 280200 | 经纪商 | 原文备注：包含券商、期货经纪商等 |
| 280201 | 恒生PB经纪商 | 对应恒生PB业务登记身份 |
| 280202 | 投易通PB经纪商 | 对应投易通PB业务登记身份 |
| 280203 | 托管外包估值经纪商 | 与估值来源有关 |
| 280204 | 资管O32通用经纪商 | 与资管O32来源有关 |

前 3 条日期为 2023-09-13，后 2 条为 2026-06-17。细分混有系统／业务来源信息，不能把它们理解成五种互斥的法人机构类型。

### 3.2 机构分类：CD2205 / Brok_Clas_Cd

| 代码 | 含义 | 原文备注 |
|---|---|---|
| 0 | 默认 | 无，空 |
| 1 | 券商 | 空 |
| 2 | 期货公司 | 空 |

代码域标记为“源系统硬编码”，码值来源 `MANU_MATN`（手工维护标记），业务日期 2026-08-07。SQL 写入空字符串时，不能自行改成 `0`；“默认”也不能解读为已经确认的其他机构类型。

### 3.3–3.6 业务处理配置

| 字典 | 完整本地码值 | 阅读重点 |
|---|---|---|
| CD929 / Pal_Avl_Method_Cd 盈亏可用方式 | `1`仅亏损计入；`2`净亏损计入；`3`盈亏轧差计入 | 先认清处理方式；计入什么金额、按什么范围计算仍需消费 SQL |
| CD930 / Marg_Para_Imp_Mode_Cd 两融参数导入模式 | `1`按营业部模式；`2`按券商模式 | 参数组织层次不同，不代表授信对象已经识别 |
| CD931 / Mutl_Busi_Chk_Method_Cd 多业务核对方式 | `1`按汇总核对；`2`按业务分类核对 | 核对粒度不同；具体汇总键需看加工实现 |
| CD932 / Spec_Lmt_Mode_Cd 专项额度模式 | `1`不支持专项额度；`2`不支持额度混合使用；`3`支持额度混合使用 | 描述支持方式，不是实际专项额度金额 |

四组码值来源均为 `MANU_MATN`，业务日期均为 2023-09-13。任务 128892 中，以上四字段分别来自 `C_PROFIT_AVAILABLE`、`C_RZRQ_IMPORT_TYPE`、`C_ACCOUNTCHECK_TYPE`、`C_SPECIAL_QUOTA_MODE`，是已核对的恒生PB来源字段映射。

## 4. 来源系统与实际加工差异

来源中文名称由 CD100 核对。下面是四个明确标有目标 schema 的任务案例，SQL 采集时间均为 2026-09-05；不是全部生产来源清单。

| 来源系统 | 实际源表与中文说明 | 目标／任务 | 身份与分类规则 |
|---|---|---|---|
| HPB：恒生PB主经纪商系统 | `ODATA_N_HPB.T_TBROKER` 券商表 | `pdata_n`／128892 | 编号 `HPB019-` + `VC_BROKER_NO`；类别 `280201`；分类取 `C_TYPE` |
| GPB：广发投易通系统（极速版） | `ODATA_N_GPB.U_BROKERLIST` 券商清单 | `pdata_n`／128888 | 编号 `GPB010-` + `BROKERID`；类别 `280202`；分类写空字符串 |
| ACV：托管外包估值系统 | `ODATA_N_ACV.H_TQS` 券商 | `pdata_n`／136329 | 编号 `ACV033-` + `VC_BH`；类别 `280203`；分类取 `L_JGSX` |
| AO3：资管O32投资交易系统 | `ODATA_N_AO3.T_TBROKER` 券商表 | `spdata_n`／237755 | 编号 `AO3106-` + `VC_BROKER_NO`；SQL 实际写类别 `280203`；分类取 `C_TYPE` |

这里有一个应保留的差异：字典已有 `280204=资管O32通用经纪商`，但任务 237755 的采集 SQL 仍写 `280203`，行内注释为“QDII券商”。不能根据字典名称把 SQL 改述为 `280204`，也不能仅凭这个差异认定生产错误；需要核对任务适用范围与版本。

HPB 分支在限定来源分区后，以 `Brok_Pty_Id + Pty_Cate_Cd` 比较新旧记录；GPB 分支以 `Brok_Pty_Id` 比较。两者并没有声明同一套跨来源全局主键。GPB 还按 `BROKERID` 做无显式排序的 `ROW_NUMBER()` 去重，因此仅凭这段 SQL 不能确定重复来源记录中哪条会保留。

这些编号前缀说明来源参与身份构造。不同系统各自编号为 123 的券商不自动相同，名称相同也不足以合并；需要实体身份对照证据。

## 5. 从经纪商继续读到账户、委托和交易

以下是元数据中已找到的相关字段，属于连接候选，不是已核验的 JOIN 合同或已证明的下游血缘。

| 业务问题 | Hive pdata_n 表 | 字段与中文含义 |
|---|---|---|
| 哪个PB资金账户关联哪个经纪公司？ | `t03_pb_fnd_acct` | `Brok_Id` 经纪公司ID |
| 平台如何配置经纪公司？ | `t99_pb_plfm_brok_ref` | `Brok_Id` 经纪公司ID |
| 投易通委托记录使用哪个经纪商？ | `t05_gpb_entr_evt` | `Brok_Id` 经纪商编号 |
| 托管外包产品投资交易关联哪个券商？ | `t05_acv_prd_ivst_undrl_trd_evt` | `Brok_Pty_Id` 券商当事人编号 |
| 下游账户快照如何带出经纪公司？ | `t98_pb_fnd_acct_base_info` | `Brok_Id` 经纪公司ID；表说明为每日一份账户快照 |

实际消费时，先检查 `Brok_Id` 是原始来源编号，还是已经带前缀的当事人编号；再核对来源、账户／市场限定、日期和连接基数。不能直接把这些表的 `Brok_Id` 等同于 `T01_BROK_INFO.Brok_Pty_Id`。

先读 T01 可了解“经纪商是谁、配置是什么”；进入账户和委托表，才开始回答“谁通过它办理业务”；进入交易、费用、结算资料后，才能研究实际成交或收费。本篇没有核验佣金、清算关系和运行结果，不从经纪商档案推导这些事实。

## 6. 名字带“经纪”，但应另行理解的字典

| 代码域 | 含义与本地证据 | 与本文的关系 |
|---|---|---|
| CD1288 / Brok_Corp_Cust_Type_Cd | 经纪业务公司客户类型：公司散户、中户、大户，以及一级至五级客户等；备注指向零售柜台字典条目 1050 | 描述经纪业务客户，不是经纪商分类 |
| CD1362 / Rcc_Cust_Src_Cd | 经纪客户来源：营业部自然增长、员工拓展、银行渠道等；条目 1054 | 描述客户获客来源，不是交易执行通道 |
| CD2222 / Crrc_Brok_Cd | 货币经纪商代码；定义指向衡泰交易管理系统（XIR）的 `ODATA_N_XIR.T_TTRD_SYS_CONVERT_MAP`，`MAP_ITEM='INTERMEDIATION'` | 是进一步研究货币经纪商的入口；本地 `code_values` 未命中该域明细，不能列举机构或认定与PB经纪商共用编号 |

前两组码值来源为零售柜台字典 `ODATA_N_RCC.U_SYSDICTIONARY`，业务日期 2026-08-21。CD2222 的代码域创建日期为 2026-08-26；创建日期不代表已经采集到码值数据。
