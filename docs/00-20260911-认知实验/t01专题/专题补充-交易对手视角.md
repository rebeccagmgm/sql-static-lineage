# 交易对手视角：从业务身份到关系、评价与授信资格

核对日期：2026-09-12。独立阅读补充，与 [02 主体类型与业务参与角色](02-主体类型与业务参与角色：明确它以什么身份出现。.md)、[经纪商视角](专题补充-经纪商视角.md) 配合使用。

## 1. 先建立一张业务地图

理解交易对手，要连续回答六个问题：**谁参与业务 → 以什么身份登记 → 对象是什么类型 → 与谁有关系 → 如何评价 → 具备什么业务资格。** 这些维度并列描述一个主体，不是一棵逐级细分的类别树。

| 阅读层次 | 业务问题 | 本地模型或字段入口 | 应保留的区别 |
|---|---|---|---|
| 主体资料 | 这个对象是谁？ | T01 的名称、证件等公共资料；`Pty_Id` | 编号需要来源语境；名称相同不证明同一主体 |
| 业务身份 | 为什么登记进这套业务？ | `Pty_Cate_Cd` / CD002 | OTC客户、资管交易对手、自营交易对手等身份 |
| 交易对手档案 | 对手是个人、机构还是产品？内部还是外部？ | `pdata_n.t01_pty_cutp` | `Cutp_Cate`、`Cutp_Type_Cd`、`Cutp_Clas_Cd` 各自解释 |
| 主体关系 | 法律主体、产品、实际控制人和其他主体如何关联？ | 交易对手档案相关字段；当事人关系类型 | 字段存在不等于已建立完整关系；同一主体与关联主体不同 |
| 分类评价 | 从哪个角度评价，结果是什么？ | `T01_PTY_RAT`：`Rat_Type_Cd` + `Rat_Cd` | 专业投资者、反洗钱、授信、风险等评价分别成立 |
| 业务资格与状态 | 可否授信，审核和报备进展如何？ | `pdata_n.t01_otc_deri_cust` | 允许授信、授信评级、额度金额、实际使用不能混为一谈 |

阅读示意：某条记录可以同时被描述为“OTC对公客户”“证券公司”“外部对手”，并分别拥有反洗钱评级和专业投资者评级。这些是不同问题的答案。本例只是维度组合示意，不代表已查询到实际客户记录。

## 2. 身份、类型与分类：最容易混淆的三个层次

### 2.1 业务身份：CD002 / Pty_Cate_Cd

| 代码 | 字典原文 |
|---|---|
| 110500 | OTC场外衍生品个人客户 |
| 210500 | OTC场外衍生品对公客户 |
| 210501 | OTC场外衍生品对公客户(固收) |
| 290200 | 交易对手 |
| 290201 | 资管交易对手 |

完整码值见 [CD002 完整附录](附录-CD002当事人类别代码.md)。CD002 还包括资管运营非标、自营、自有资金、商贸等交易对手分支。因此不能只筛 `290200` 就宣称拿到了全部交易对手，也不能用 `210500` 判断具体机构类型。

### 2.2 对象类型：CD388 / Cutp_Type_Cd

本地有 87 条记录。以下按含义分组帮助阅读，分组不是另外建立的正式代码层级。

| 理解分组 | 典型代码与含义 |
|---|---|
| 总体对象 | `0`个人；`1`机构；`2`产品 |
| 银行业机构 | `10101`银行；`10102`银行子公司；`10103`财务公司 |
| 证券、基金、期货等机构 | `10201`证券公司；`10203`证券投资基金管理公司；`10205`期货公司；`10208`私募；`10209`期货公司风险管理公司 |
| 其他机构 | `10301`信托公司；`110`境内非金融机构；`120`境外金融机构；`130`境外非金融机构 |
| 银行、信托类产品 | `201`银行理财产品；`202`银行子公司公募理财；`203`银行子公司理财产品；`204`信托计划 |
| 证券、基金类产品 | `209`证券公司资产管理计划；`212`基金管理公司公募基金；`213`基金管理公司资产管理计划；`217`私募投资基金 |
| 其他资金产品 | `219`全国社保基金；`221`基本养老保险基金；`223`企业年金；`227`境外资金（QFII） |

这里最有价值的区别是“管理机构”和“它管理的产品”。例如证券投资基金管理公司与公募基金是不同对象，不应因为名称相近就合并。`T01_PTY_CUTP` 中存在 `Cutp_Legal_Enty`（交易对手法律主体）、`Cutp_Prd_Id`（交易对手产品编号）、`Cutp_Actl_Ctrl`（交易对手实际控制人），可以作为继续理解关系的入口；这些字段是否填充、指向哪个编号体系，需要逐来源确认。

### 2.3 内外部分类：CD389 / Cutp_Clas_Cd

- `1`：外部对手。
- `2`：内部对手。

这里的“分类”不表示风险高低。`Cutp_Cate` 则尚未找到同名代码域；已核对的任务 144563 为它写入 `OIS_HK_OPT_DERI`。这是一条来源加工事实，不能套用 CD388 或 CD389 翻译。

## 3. 评价必须带上评价类型

CD036 定义“评什么”，CD055 定义评级结果。CD055 本地有 140 条记录，其中存在相同码值对应不同评级类型的情况。

| Rat_Type_Cd | 中文含义 | 理解用途 |
|---|---|---|
| AML_LVL | 反洗钱评级 | 理解反洗钱评价结果 |
| PI_LVL | 专业投资者评级 | 理解投资者身份评价 |
| RISK_LVL | 风险评级 | 结果需结合来源和类型备注，不能概括为所有信用风险 |
| CRED_LVL | 授信评级 | 理解信用评价，与允许授信状态分开 |
| OTC_CUTP_LVL | 场外交易对手等级 | 理解场外业务专用评价 |

具体反例：`Rat_Cd=1` 在 `AML_LVL` 下为“低风险”，在 `PI_LVL` 下为“专业投资者”。仅按 CD055 与码值连接会产生歧义；必须使用类型约束，核对字典备注，再连接结果。

本地还有一个实际质量问题：CD036 的场外交易对手等级原始码值为 `" OTC_CUTP_LVL"`，带前导空格；任务 179723 写的是 `"OTC_CUTP_LVL"`。阅读时可识别其意图，精确关联时应把原值与规范化处理分开记录。

## 4. 关系、检查结果与授信资格各回答什么

| 字典 | 本地码值示例 | 不能据此推出什么 |
|---|---|---|
| CD178 / Pty_Rela_Type_Cd 当事人关系类型 | `01`同一个当事人；`03`上级当事人；`06`一致行动人；`07`同一控制人；`08`担保关系 | 同一控制人不等于同一个法人；关系定义不证明某条关系已存在 |
| CD1371 / Cutp_Join_Side_Chk_Rslt_Cd 交易对手关联方检查结果 | `true`命中；`false`未命中；`doubt_true`原文为“疑似命” | 疑似结果原文疑有截断；不能自行补齐并当成正式定义，也不能据字典存在证明检查已完成 |
| CD1038 / Perm_Cred_Stat_Cd 允许授信状态 | `no`禁止；`yes`可以；`credited`经风控部批准可以授信 | 不能据此计算授信额度、剩余额度或实际敞口 |

`T01_OTC_DERI_CUST` 还包含 `Appr_Stat` 审核状态、`Rep_Stat` 报备状态，以及代签产品、补充协议、履约协议报备状态字段。本次未按这些字段精确定位到对应代码域，暂不套用通用当事人状态字典。

## 5. 来源怎样改变读法：一个已核对案例

任务 144563，SQL 采集时间 2026-09-05，来源 OIS（**OTC综合业务平台**），生成交易对手档案：

| 字段 | SQL 中的规则 | 消费含义 |
|---|---|---|
| Cutp_Cate | 固定 `OIS_HK_OPT_DERI` | 区分该业务分支 |
| Cutp_Type_Cd | `NVL(DW_CD_VAL, CLIENT_TYPE)`，引用 `REF_CD_CVT_MAP` | 有映射时取仓库代码；未命中时保留源类型，不能保证全部值都在 CD388 中 |
| Cutp_Clas_Cd | 固定 `1` | 该分支按外部对手写入，不推广为全部来源 |

还有 CD1737 / Src_Cutp_Type_Cd“源交易对手类型代码”，本地 22 条、备注为**中证报价**。其中 `0=证券公司`，而 CD388 中 `0=个人`。这证明“值一样”不足以连接，源代码域、来源系统与仓库代码域都必须明确。

本地资产库有 `REF_DW_CD_VAL` 的含义字典，没有独立的 `REF_CD_CVT_MAP` 数据表；SQL 引用了映射表，不等于已经掌握实际映射行。

## 6. 拿到一条交易对手记录，按这个顺序读

1. 确定物理表、来源系统、`Src_Tbl` 和记录时间，再解释编号。
2. 用 CD002 解释登记身份，用 CD388 解释对象性质，用 CD389 解释内外部。
3. 确认产品、管理机构、法律主体、控制人是否分别有资料和可核对的关系；不按名称强行连接。
4. 将评级按类型展开，并核对评价时点；不要把一个评级列当作总评价。
5. 分别读取关联检查、审核、报备、允许授信状态；需要额度或实际交易时，再进入相应业务表。
6. 跨来源去重和关联，必须继续核对编号转换、来源限定与实际匹配；字典只能解释语义，不能证明实体已统一。
