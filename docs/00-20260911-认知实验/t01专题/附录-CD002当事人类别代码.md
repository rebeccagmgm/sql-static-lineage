## 2. 怎样理解编码

字典明确有 100000“对私”、200000“对公”，并有个人客户、对公客户、销售机构、登记机构、托管机构等分类。具体代码还带业务和来源语境，如 110500“OTC场外衍生品个人客户”、280202“投易通PB经纪商”。本字段是复合的主体登记类别，不是纯自然人/法人二分，也不是一个主体全部角色的集合。

下面的层级关系是依据代码形式和中文含义归纳的阅读示意；查询到的字典结构没有显式父子字段，代码域备注也没有给出完整的位数规则：

```text
280000 其它中介服务机构
  280200 经纪商
    280201 恒生PB经纪商
    280202 投易通PB经纪商
```

不能把每两位的含义机械固定，也不能依据补零规则生成字典没有的代码。管理人分布在 21100x 和 2501xx 等不同分支，交易对手既出现在 OTC 客户分支，也出现在 2902xx；合并这些身份需要来源和业务依据。详见 02 的对应角色段落。

## 4. 查询与使用约束

```sql
SELECT code_value, value_description, remark, source_table, business_date, record_id
FROM code_values
WHERE code_id = 'CD002'
ORDER BY code_value, record_id;
```

精确查询应使用代码域＋代码值；不同域中的同值不能套用本附录。REF_DW_CD_VAL 说明仓库代码含义，REF_CD_CVT_MAP 说明来源代码怎样转换，两者不互相替代。任务也可能直接赋常量或回退源值；结果是否落在 CD002 中，需要结合具体 SQL 和业务数据另行核验。
