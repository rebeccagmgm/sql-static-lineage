# 销售入口如何进入交易统计

[返回入口](../README.md) · [应用与入口说明](../业务/04-应用与销售入口.md)

## 1. 业务参数先到来源表

Wiki把应用入口、页面来源、页面内模块分成不同参数。例如应用内某页面的模块带来的订单，可以同时有app_id、source和sub_source。该文中的“场外”是基金销售场景，本专题不把它扩成TIT/OIS衍生品渠道定义。[Wiki参数章节](../../../attachments/02-销售入口如何进入交易统计/IMG-02-销售入口如何进入交易统计-20260914110950619.json)

SIP两个来源分别保存产品销售入口和场内交易入口参数。二者共用模型结构，但源分区和业务类型不同。

| 源字段 | T08目标字段 | 作用 |
|---|---|---|
| SOURCE | Lvl1_Entr | 一级入口标识 |
| SUB_SOURCE | Lvl2_Entr | 二级入口标识 |
| PRIMARY_CLASS / SECONDARY_CLASS | Lvl1_Cate / Lvl2_Cate | 来源分类 |
| THREE_CLASS或THIRD_CLASS | Lvl3_Cate | 不同源字段名归到同一模型字段 |
| SOURCE_NAME / SOURCE_CN等 | 入口名称与中文描述 | 仅部分来源有值 |
| 源BUSI_DATE | 目标Busi_Date分区 | 限定参数快照日期 |

86942是产品销售参数；86944是场内交易参数。字段映射可以对齐结构，不能证明两份参数值能够跨业务互换。[86942](../../../attachments/04-应用与销售入口/IMG-04-应用与销售入口-20260914110952789.sql)、[86944](../../../attachments/04-应用与销售入口/IMG-04-应用与销售入口-20260914110954288.sql)

## 2. 交易消费使用了两级等值连接

98035 的 `gfmobile_fund_trade_daily` 读取SIP场内交易参数分区，在多个子查询中使用：

```sql
a.source = b.Lvl1_Entr
AND a.sub_source = b.Lvl2_Entr
```

参数快照日期通过 `default.pretradedate(date_add(d,1),1)` 取得。本文保留函数表达式，不把它换成自然日前一天；函数日历行为并非由字段名决定。来源分区是 `ODATA_N_SIP.G_GFMOBILE_FUND_CHANNEL_LABEL`。[98035](../../../attachments/02-销售入口如何进入交易统计/IMG-02-销售入口如何进入交易统计-20260914110954748.sql)

**假设示例：**同一页面source=P下有模块M1、M2，两行分类不同。一笔来源P/M1的交易只应该按完整参数找M1。仅按P连接会产生两条候选，并可能让金额在后续聚合时翻倍。这个例子说明Join风险，不是对实际数据重复情况的断言。

## 3. 为什么最终分类不一定等于T08分类

同一消费还读取 `t99_trd_entr_clas_info`，按一级入口连接额外分类。在已读子查询中使用 `coalesce(T99分类,T08分类)`，优先采用T99的非空分类。又有交易明细、销售来源补充、产品池等输入，最终按业务日期、产品及多种交易维度聚合。

因此出现“T08查到的分类与统计表不同”时，应先核对消费选的是哪个来源/日期，以及T99覆盖条件；不能立即认定T08或统计表错误。若T99同入口有多条，也会影响Join行数，本次未执行唯一性验证。

## 4. 这条链能回答什么

已确认：两级参数如何进T08、消费者使用的来源/日期表达式、Join键及部分分类优先规则。未确认：源埋点参数是否全量上报、全部交易来源是否匹配、参数键唯一性、实际成交统计与业务对账结果。此处讲的是维度解释如何进入交易统计，不把参数配置当成交易事实。
