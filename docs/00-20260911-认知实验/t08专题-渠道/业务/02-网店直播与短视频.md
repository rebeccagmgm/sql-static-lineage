# 网店、直播与短视频：经营空间、内容和行为

[返回入口](../README.md)

## 1. 先分清三个对象

店铺组织经营展示；直播间承载一场可观看和交互的内容；短视频保存一个发布内容对象。主播、店主、观众、商品、观看事件不应全部压入店铺一行。

| 表 | 对象身份 | 主要属性与时间 |
|---|---|---|
| `t08_shop_info` | `WOS018-` + 源店铺 ID | 店主、简介、服务人员、资质和推送/隐藏/关闭标志；当前属性加删除标志 |
| `t08_wos_live_info` | `WOS007-` + 直播间 ID；同时保留 `Src_Chan_Id` | 主播、房间、播放时间、受众限制、产品及观看相关统计；来源 + 业务日期快照 |
| `t08_wos_shor_vdo_info` | `WOS003-` + 源 `_ID` | 视频属性、发布/上传/删除时间、状态、累计点赞及 PV；当前属性加删除标志 |

店铺生产 [90406](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110950605.sql) 从 `ODATA_N_WOS.G_SHOP` 取店铺；`OWNER` 加 `CFM001-` 生成店主用户编号。店主用户不是直接的员工身份，店小二和职员信息又是独立字段。不能仅凭店铺属于某人推断所有观看或销售业绩属于该员工。

## 2. 直播资料为什么还需要 T07、T05

直播生产 [62886](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110951202.sql) 从 `W_ROOMS` 映射房间资料，`IS_TEST_USAGE` 的 true/false 被转换成 1/0。计划、预设、真实开播、结束、更新时间分别保存。表中的 PV、UV、在线峰值是源系统返回的统计属性，本次未取得这些指标完整的计算及去重定义。

真实消费 [121294](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110952634.sql) 将 `t08_wos_live_info.Src_Chan_Id` 连到 `t07_live_act_info.Live_Id`，按日期、非测试、活动业务类型等筛选，再连接直播时长、观众等指标。T08 给出房间资料，T07 决定活动业务归类，指标/事件层给出观看和互动表现。该复杂消费仅精读了涉及 T08 的输入和连接，未全段审计。

测试消费 [110118](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110954050.sql) 也以源直播间号连接用户行为中的 `page_ob_code`，再从销售事件中去除 `WOS007-` 前缀取得源房间号。这个例子证明源编号在消费中有明确作用；它属于测试库任务，不能当作正式上线验收。

## 3. 组合定义是另一层身份

[91394](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110955554.sql) 从直播资料按 `Src_Chan_Id` 分组，以房间名的 `max` 形成 `WOS_LIVE` 组合定义。组合的 `grp_id` 是下游分配的身份；`grp_val` 才装源直播间号。源码在这一步没有按某一 `Busi_Date` 限定 T08，因此同一房间多日资料被压成一组，名称选择规则是字符串 `max`，不能解释为“最新房间名”。

## 4. 当前属性与每日快照的区别

短视频来源 SQL 的实际读取表是 `ODATA_N_WOS.F_TR_MEDIAS`，而历史比对来源分区仍是 `ODATA_N_WOS.T_MEDIA`。[82616](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110957322.sql) 显示同一个 `WOS003-` 身份随属性变动更新，并维护删除标志。源视频删除时间与数仓删除标志的产生时间需要分别理解。

直播则按业务日期保存资料。若要取“某场直播最终观看数”，要先确定哪个快照/结束条件代表最终，不能把同一房间每天的累计值相加。若问“今天观看次数”，应优先找今天的观看事件或明确定义的日指标。

## 5. 两个需要保留的差异

店铺主表来源 [90403](../../../attachments/02-网店直播与短视频/IMG-02-网店直播与短视频-20260914110958498.sql) 写渠道类型 `05020`，专有表90406写 `0520`；本地CD434字典仅命中前者“理财网店”。两表可依据已见一致的 `WOS018-ID` 建立候选对应，但不能追加类型等值条件后声称全覆盖。

调度目录同时有58780、62886两个同名直播任务，前者为渲染日期的SQL快照，后者保留模板变量。两者都写同一模型，但本次未核实运行职责和生效状态；不能用“有两个任务”推断每天必定写两遍。[覆盖边界](../证据/来源覆盖与待核问题.md)
