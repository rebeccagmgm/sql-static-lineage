# 开户引流与合作渠道：入口、归属和归因分开理解

[返回入口](../README.md) · [完整加工案例](../实现详解/01-开户渠道如何成为客户归因.md)

## 1. 渠道不是客户，也不是开户订单

渠道先定义入口和办理规则，客户通过入口留下申请或订单，后续加工再把客户归入某种渠道分类。因此“配置了一个引流渠道”“某客户使用过它”“最终业绩归给它”是三个不同结论。

| 对象 | 模型表达 | 一行主要描述什么 |
|---|---|---|
| 渠道的共用身份 | `t08_chan` | 来源渠道的编号、名称、类型、状态和删除标志 |
| 开户入口的丰富属性 | `t08_gks_chan_info` | 营业部、引流营业部、推荐人、主子场景、套餐、分类、锁定及优先级 |
| 引流渠道补充属性 | `t08_crm_dvrs_chan_info` | 引流机构、佣金代码、合作类型、打折和特殊引流来源 |
| 合作银行组织 | `t08_gu_bnk_org_info` | 金纽带组织节点、父节点、银行编号及组织级别 |
| 引流合作银行 | `t08_oact_dvrs_bnk_info` | 渠道下的合作银行代码和名称 |
| 限制配置 | `t08_oact_chan_lmt_plac_info` | 一条配置及其渠道、场景、限制类型、阈值和状态，按日保存 |
| 引流费用 | `t08_chan_dvrs_fee` | 一条来源费用记录及月份、应付、实付、分摊机构 |

`t08_gu_bnk_org_info` 中有 `Prnt_Chan_Id`，表示金纽带组织节点的上下级。它和特殊引流渠道的 `t08_chan_rela_h` 是不同关系，不能混成一棵“全渠道树”。

## 2. 三套来源分别做什么

**OAO 负责当前已读代码中的开户渠道参数。** `C_CHANNELTYPE` 提供 CHANNEL、营业部、推荐人、场景、套餐、锁定标志等。62878/62891 仍生成 `GKS030-CHANNEL`；旧来源分区仍可出现 `ODATA_N_GKS.J_CHANNELTYPE`，实际主要读取对象则为 OAO。

**AUM 提供普通、特殊、打折三路引流资料。** 普通渠道先进入 `CRM049-CHANNEL` 身份；特殊表以 `YLQD1` 补入普通表没有的对象；打折表再补前两路都没有的对象。扩展属性中还把打折存在性、特殊来源并到普通对象上。三路是有优先次序的补齐，不能简单把表行数相加当不同渠道数。

**GKS 的上传分类表补充经营管理分类。** `UPLOAD_BOSS_CHANNEL` 给出三级分类、匹配模式、财务分类和负责人。62891 将它连接到 OAO 主记录；62908 则为不在 OAO 主表中的分类记录补充专有表行。`DISTINCT` 去掉的是整行重复，并不证明按 CHANNEL 唯一。

## 3. 一个渠道为什么有多个“归属人”和“营业部”

`Inr_Org_Id`、`Dvrs_Inr_Org_Id`、推荐人、负责人、申请人、联系人用途不同。渠道机构关系代码 01/02/03/04 分别表示归属、引流、特殊引流、锁定机构。62891 还将“允许修改推荐人/营业部”的源标志反向转换成“锁定”标志：源为 0 时目标锁定为 1。

OAO 用户关系来源中，申请人写关系类型 `2`，联系人写 `3`；联系人经拆分后可有多条。没有证据证明所有 `User_Id` 都是员工号或统一用户号，因此不能直接连接任意 T04 用户/员工表。先确认来源值及映射，再连接。

## 4. 限制和费用怎样读

开户限制以 `Plac_Id` 为配置身份，附带渠道、主子场景、推荐人及银行合作方字段。CD1687 中 Invalid、SecretKey、Threshold 分别表示失效、秘钥核销、熔断配置；恢复方式 Daily/Manual 表示每日自动/人工申请。字段中的渠道限制阈值和状态描述配置及源状态，不能证明某客户已被限制。[199420](../../../attachments/01-开户引流与合作渠道/IMG-01-开户引流与合作渠道-20260914110955468.sql)

费用来源 [186145](../../../attachments/01-开户引流与合作渠道/IMG-01-开户引流与合作渠道-20260914110957252.sql) 通过分类表与费用表的 `TCATEGORY` 相等关联，再取分类表的 `A.CHANNEL` 输出 `GKS030-CHANNEL`。费用侧提供源 ID、`COSTDATE → Fee_Mon`、`EXPENSE → Payb_Fee`、`ACTL_EXPENSE → Actl_Fee`，机构编号左补零到四位。**这不是按渠道号关联费用；若一个三级分类对应多个渠道，同一费用源记录就可能被展开到多个渠道。** 读取时必须保留源 ID 和月份，先核查展开规则，再讨论汇总。不能把应付和实付混加，也不能仅据“实付费用”字段认定付款已独立核销。

## 5. 使用边界

渠道三级分类怎样影响客户归因，需要继续读 T98 消费；`Mode='like'` 实际按正则规则解释。AUM 来源字段 `LXBH/LXMC` 的元数据为类型编号/类型名称，但62895将它们投向 `Co_Org_Name/Co_Org_Cd`，存在名称与代码投影对置，正文按实际投影记录，未替平台修正。[待核清单](../证据/来源覆盖与待核问题.md)
