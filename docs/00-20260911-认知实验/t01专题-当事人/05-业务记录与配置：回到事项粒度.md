## 1. 平台分类与业务内容

本次 `pdata_n.T01_CUST_CMS_DECT_DET` 的平台归属是“营销考核及奖励信息”，区别于个人/机构客户基本信息。整个平台 T01 前缀对象还观测到“客户服务信息”“非居民涉税信息”“客户合约合同信息”等路径，但不同路径覆盖哪些具体表，应以[逐对象原始清单](00-20260911-认知实验/t01专题-当事人/00-平台分类与业务阅读对照.md)为准，不能仅按表名代填标签。

从业务阅读角度，这些内容分为下面几组。分组沿用已有元数据和 SQL 案例的解释，不冒充平台统一分类标准。

## 2. 四组业务记录

| 组别 | 对象入口 | 一行还可能需要什么坐标 |
|---|---|---|
| 尽调、材料、报告与涉税资料 | 背景调查、尽调附件、财务报表明细、个人/机构/控制人涉税资料 | 记录号、流程号、附件、报表项目、报告期、版本 |
| 准入、名单与服务配置 | 持牌业务、黑白名单、行情试用、通知/订阅、服务申请 | 业务类型、名单类型、服务或产品、申请/有效时间 |
| 方案与业务参数 | 履保方案、保证金率、费率、额度、银行账户附加资料 | 方案号、协议、产品、币种、账户、期间 |
| 认领、分成与计量 | 客户佣金提成、收入协作、创收目标、指标价值切分 | 业务流水、员工/机构、产品、席位、月份、指标 |

报告和材料也有各自编号：既有结构中，尽调相关对象出现 `Dd_Rpt_Id`，附件包含 `Proc_Id`、`File_Id`；财务报表明细包含 `Fin_Rpt_Id`、`Fin_Rpt_Item_Id`、报告期、币种和版本。这些坐标提示应先区分报告、明细项目、流程与附件，再连接主体。它们不是已证明的统一主键。

实际有哪些字段、各字段属于哪个对象，见[对象目录](00-20260911-认知实验/t01专题-当事人/资料/物理对象目录.md)与[原业务层级映射](00-20260911-认知实验/t01专题-当事人/资料/对象业务归类.md)的 C1–C4。这里没有把每个入口都认定为完成了全部来源核验。

## 3. 三个已有案例说明为什么不能一客一行

### 履保方案：记录的是方案及参与方

原任务 200060 将源 ID 写为 Perf_Marg_Plan_Id，将交易对手键构造为主体号，还保留管理人主体号、履保协议和大合约编号。方案 ID 与主体 ID 承担不同作用：一个主体可以关联多个方案，一个方案又有多个参与角色。

方案参数不能直接解释成当日已发生的保证金收付；把方案表按主体连接后求和，也要先明确要统计的是方案还是资金事实。详见[原建模研究第 2.3 节及证据 S18](00-20260911-认知实验/t01专题-当事人/证据/案例详解与SQL索引.md)。

### 客户提成：字段存在不等于金额已有取值

原任务 63116 的提成明细分支主要提供客户、类型、状态和月份备注，部分编号、金额等字段填空。它虽然属于提成相关对象，也不能仅凭表名和金额列存在就当作可汇总的实际收入事实。分成规则、目标值、业务认领和实际金额应分别识别。

### 死亡材料：事项粒度与元数据冲突同时存在

任务 231126 的 SQL 输出客户号、一码通账户、材料编号、材料名称和归档日期，说明这段加工在组织主体相关材料。调度详情可补齐默认库，但目录记录的字段结构与该 SQL 不一致，不能按目录字段位置直接绑定。此案例的冲突及原文见[06 的第6节：证据冲突](00-20260911-认知实验/t01专题-当事人/06-来源时间与消费.md)。

## 4. 名单、材料和配置不能替代业务判断

有附件不等于尽调完成，有名单记录不等于获准开展业务，有试用配置不等于已经使用服务。名单是允许集合还是排除集合，要看下游消费条件；材料是否齐备、配置何时生效，要有明确状态和时间规则。

同一主体同时有三份附件和两个方案时，直接按主体号连接会产生六种组合。这个数字只是粒度示意，不是实际统计。若只问“是否存在材料”，需要先定义符合条件的材料范围；若要看“哪个方案对应哪份材料”，需要方案与材料之间的关系依据。

## 5. 名单结合“类型＋状态”读，配置还要看作用范围

2026-09-12 核对本地字典及 Hive `pdata_n` 字段：`T01_PTY_INR_LIST_DET`（当事人内部名单明细）、`T01_PRD_BWL_CUST_DET`（产品黑白名单客户明细）都有 `List_Type_Cd` 与 `List_Stat_Cd`；`T01_BROK_IMP_MONTR_CUST_ADTNL_INFO`（经纪业务重点监控客户附加信息）也有名单状态字段。

| 字典 | 典型码值与含义 | 帮助理解什么 |
|---|---|---|
| CD153 / List_Type_Cd 名单类型，本地130条 | `ARP_BL`约定购回客户黑名单；`AST_ACCT_WL`资产账户白名单；`APP_SEPR_VIP_TRD_UNIT_SERV_CUST`申请独立VIP交易单元服务客户；`BROK_BRCH_IMP_PRVCY_CUST`经纪业务营业部重要隐私客户 | 名单不仅有黑白名单，也保存服务申请和特定客户集合；必须先明确名单用途 |
| CD538 / List_Stat_Cd 名单状态，本地11条 | `0`已加黑名单；`1`已去除黑名单；`2`监控；`3`作废；`4`有效；`5`过期；`6`待生效；`7`失效；`8`待分配；`9`未分配；`10`无需审核 | 状态横跨加入／移除、有效期、分配与审核，不能自行排成单一状态机 |

示例均来源 `MANU_MATN`（手工维护标记）。上表 CD153 四例日期分别为 2023-01-03、2023-06-28、2025-02-12、2025-02-28；CD538 日期跨 2023-01-03 至 2025-12-19。完整原文、备注和逐条日期见 [字典附录](00-20260911-认知实验/t01专题-当事人/字典/分类评价关系与名单字典.md)。

字段同名只提供字典查找入口。本次未逐任务证明所有名单分支都使用这套仓库码，也没有得到名单类型与状态的完整适用矩阵。例如“有效”可能表示黑名单记录有效，其业务效果不能翻译成“允许交易”；“无需审核”也不等于已审核通过。需要按具体名单类型、来源转码、有效期间和消费条件解释。

配置可参考 [经纪商专题](00-20260911-认知实验/t01专题-当事人/视角/经纪商.md) 中已核对的盈亏可用方式、两融参数导入模式、多业务核对方式和专项额度模式。它们是处理方式枚举，方案中的金额、比率、期间和参与方另有粒度，不能用一个方式代码替代全部业务参数。

## 6. 从业务问题回到取数路径

先把问题写成“哪个主体的哪件事，在什么时候，归哪个对象或人员，以什么规则计量”。再选择事项表、裁剪期间和状态、确认与主体的关联，最后才补名称和角色资料。

[06 的实际消费案例](00-20260911-认知实验/t01专题-当事人/06-来源时间与消费.md)表明，下游会混合主体当前资料、名称快照、关系区间、席位和月度分配规则。表级连线只能帮助定位；Join 筛选、重叠期间和多行组合决定最终结果，静态证据不能代替业务数据验收。
