本章讨论的是“主体被怎样分类、评价或标记”。平台资产目录给**表**贴分类标签；本章各模型表为**主体记录**保存分类、评级、状态等值。两者都叫分类，但对象和用途不同。

## 1. 平台分类提供什么依据

本次目录将 `pdata_n.T01_PTY_RAT` 放入“客户风险信息”，把 `T01_PTY_STAT_H` 放入“客户衍生信息”。这能帮助组织章节，但不能据此认为评级表只含客户风险等级，或所有状态都属于同一个业务状态域。

02 中的 Pty_Cate_Cd 对应已找到的 CD002 字典，登记含义混合了主体性质、业务角色和来源语境。完整枚举统一见 [CD002 附录](00-20260911-认知实验/t01专题-当事人/字典/CD002当事人类别代码.md)；它不能替代本章的 Pty_Clas_Type_Cd / Pty_Clas_Cd、评级类型或状态类型，也不能把 CD002 的解释套给这些其他字段。

## 3. 分类：先确定“按什么分”，再翻译分类码

CD138 的类型同时包含机构性质、业务分类、客户等级和标志。例如 `02`中登机构类别、`07`关联人类型、`09`金融业客户标志、`13`私募基金管理人类别、`14`私募基金类别、`17`资金融出方质权人类型、`18`资金融出方类型、`45`经纪商分类。

这说明同一主体可以同时按多个标准分类；这些类型不构成从大类到小类的一棵树。CD139 的备注直接规定结果码适用的类型：

| 分类类型及含义 | 分类码 | CD139 含义 | 记录业务日期 |
|---|---|---|---|
| `07` 关联人类型 | `0` | 非关联人 | 2021-12-17 |
| `09` 金融业客户标志 | `0` | 非金融机构 | 2026-03-12 |
| `12` 客户重复考核标志 | `0` | 不参与有效户计算 | 2022-07-21 |
| `45` 经纪商分类 | `0` | 交易所 | 2023-09-13 |
| `17` 资金融出方质权人类型 | `02` | 证券公司集合资管 | 2022-07-21 |
| `18` 资金融出方类型 | `02` | 证券公司集合或专项计划 | 2022-07-21 |

上述来源均为 `MANU_MATN`（手工维护标记）。必须同时带类型和值；若只用 `CD139 + 0` 查中文，会命中多个含义。

还有一个与经纪商专题直接相关的区别：这里 `CD139 / 类型45 / 0=交易所`，而经纪商信息表的 `CD2205 / Brok_Clas_Cd / 0=默认`。两个地方都叫“经纪商分类”，仍不能共用字典。见 [经纪商视角](00-20260911-认知实验/t01专题-当事人/视角/经纪商.md)。

## 4. 评级：评价角度与结果必须成对

| CD036 评级类型 | 字典含义 | 如何理解 |
|---|---|---|
| AML_LVL | 反洗钱评级 | 与反洗钱评价相关 |
| PI_LVL | 专业投资者评级 | 表达投资者身份评价 |
| RISK_LVL | 风险评级 | 具体结果要结合来源，不能自动解释为信用违约风险 |
| CRED_LVL | 授信评级 | 与授信评价相关，不等于已批准额度 |
| OTC_CUTP_LVL | 场外交易对手等级 | 场外业务专用评价；原始码值有前导空格，见下文 |
| SPLR_LVL | 供应商级别 | 说明评级表也容纳供应商评价 |

CD055 中 `Rat_Cd=1` 在 `AML_LVL` 下为“低风险”，在 `PI_LVL` 下为“专业投资者”（两条日期均为 2020-11-11）；在 `SPLR_LVL` 下为“重点”（2025-07-03）。三条来源均为 `MANU_MATN`，由结果记录的备注限定类型。

CD036 的场外交易对手等级原值为 `" OTC_CUTP_LVL"`，任务 SQL 使用 `"OTC_CUTP_LVL"`。附录保留原始空格；不能一边悄悄清洗，一边声称按原值精确命中。评级结果的同码多义，也不应被误判为可以直接去重的脏数据。

任务 179723 向同一来源分区依次写入 PI_LVL、RISK_LVL、AML_LVL、CRED_LVL、OTC_CUTP_LVL。各类型的来源字段、码值转换和实际取值源不同；反洗钱评级的 Real_Src_Tbl 与 Src_Tbl 分区标签还不相同。见[差异案例证据](00-20260911-认知实验/t01专题-当事人/证据/差异案例证据.md)。

原 PPM005 案例 204548 又把供应商级别写成 SPLR_LVL，评级日期、机构及生效/到期字段填空。因此，平台归入“客户风险信息”并不能替代对具体记录类型的解释；统一用“评级日期最新”也可能丢掉未填日期的来源。

这不是认定目录错误，而是说明目录分类的粗细与模型容纳的记录类型并不一致。

## 5. 偏好：投资什么与投资多久是两套问题

CD176 六种类型的本地完整枚举：`01`投资品种、`02`投资期限、`03`私募基金投资品种、`04`私募基金投资期限、`05`柜台投资品种代码、`06`柜台投资期限代码。

| 类型 | Prefr_Cd | CD177 含义 | 备注中的约束 |
|---|---|---|---|
| `01` 投资品种 | `101` | 固定收益类投资品种 | 类型01，投资产品偏好 |
| `02` 投资期限 | `207` | 五年以内（可购买或接受五年期以内的产品或服务） | 类型02，投资期限偏好 |
| `05` 柜台投资品种代码 | `1` | 固定收益类投资品种 | 柜台投资品种偏好原值 |
| `06` 柜台投资期限代码 | `1` | 1年以内 | 柜台投资期限偏好原值 |

来源均为 `MANU_MATN`；上述四条业务日期依次为 2021-06-30、2021-08-27、2023-07-11、2023-07-11。柜台原值与一般偏好代码在本地同时存在；不要因为含义相近就推定已经转码统一，也不能把期限代码的数值大小当作期限长短。

偏好描述本人表达或来源记录的倾向，是否允许购买仍需适当性、准入和实际业务规则；字典里的“可购买或接受”原文不能独立充当授权。

## 6. 状态：状态类型有缺口，不能补猜

CD021 本地五条分别为：`1`含义为空、`2`销售商TA5代销状态、`3`销售商分TA代销状态、`4`客户合同状态、`5`经营状态。第一条不能根据码值顺序补成“客户状态”。

CD022 结果中有 `01`新建、`02`待审核、`03`审核未通过、`04`正常、`05`冻结、`07`销户，也有休眠等其他值。上述示例日期为 2020-09-22，来源 `MANU_MATN`。这些记录的备注未给出完整的状态类型与结果对应矩阵，因此**不能认定每个状态类型都适用这套全部结果，更不能由枚举顺序推导状态流转**。

若记录为 `Pty_Stat_Type_Cd=4`，首先知道它谈的是客户合同；结果是否来自 CD022、是否保留源值，要继续核对该来源 SQL。`04=正常`也只解释对应状态，不能推出客户全部业务均可交易。

## 8. 码值、转码和分类目录分开查

- 表目录 `observed_classifications`：告诉我们资产归哪类。
- 资产码值库 `ref_dw_cd_list` / `code_values`：告诉我们代码域、代码值、中文含义与备注。
- SQL 中的 `REF_CD_CVT_MAP`：描述来源代码怎样转换为仓库代码，不能由字典含义反推实际转码已成功。

查某个代码时，至少带“字段或代码域＋类型条件＋来源＋快照日期”，并保留备注中的限定条件。同一个数字在不同代码域中不能互相套用。具体库位置和查询约束见[本地 SQLite 导航](../../local-sqlite-guide.md)。本次已提取 04 的 12 个相关代码域，并与 03 的关系类型、05 的名单类型和状态一起形成 15 域、932 条本地原始明细。它们是当前本地命中记录的完整导出，不是线上全量认证；快照状态仍为 `UNVERIFIED`。

将字典连接到业务数据时，应先限定代码域，再根据备注明确类型条件，核对来源与业务日期，并检查连接后的行数是否膨胀。结果为多条或无匹配时分别保留歧义或缺失，不取任意第一条，也不把空值当成默认代码。备注中的类型条件是原始文本，本次没有把它自动转为一套已验证的生产连接规则。

## 9. 状态与时间怎样读

业务状态、模型删除标志、角色准入状态、区间开关链，分别回答不同问题。01 说明公共状态和删除资料，02 说明角色与准入的区别；这里补充状态类型和结果的解释。

日快照按目标分区选择日期；区间记录按具体起止谓词裁剪；只有固定起止常量的分支不能直接称为历史维护。源评价日期与模型加载日期也不能互相代替。算法差异集中见[来源、时间与消费专题](00-20260911-认知实验/t01专题-当事人/06-来源时间与消费.md)。

如果问题是“某客户当时风险如何”，应先指定评级类型、来源和业务时点，再核对结果码含义；如问题是“当时是否允许交易”，还需要权限/准入和具体业务规则，评级结果本身不足以证明。
