## 1. 本次字典材料是什么

从资产目录 SQLite 的 `ref_dw_cd_list` 按 T09 已见字段英文名进行大小写归一后的精确匹配，再按代码域取 `code_values`。保留代码域、取值、说明、备注、业务日期和来源。完整结果见 [字段代码域与码值](attachments/README/IMG-README-20260914111012382.json)，便于逐条复核。

这是一批“同名字段对应代码域”的线索，不代表每个 T09 来源已执行同一套标准化。采集库的码值快照状态仍为 `UNVERIFIED`；码值中的业务日期是各条资料的日期，不能写成“全部截至 2026-09-14 最新”。

## 3. 三种加工方式不可混为一谈

**原值投影：** ERP 凭证头把源 `STATUS` 直接放入 `Vchr_Stat_Cd`。

**规则转换：** CVS 估值将方向 `1/-1` 转 `DR/CR`；FMS 账单状态前拼 `0`；FAF 的转换标志还做了反向映射。

**映射后回退：** ERP 凭证行和多个估值来源使用 `NVL(DW_CD_VAL, 源值)`。映射未命中仍有字符串输出，不能凭非空断言字典匹配成功。

`REF_CD_CVT_MAP` 是源值到仓库值的转换，`REF_DW_CD_VAL` 是仓库值到说明。当前本地资产库有后者；本次没有取得前者的完整实际转换记录。SQL 引用转换表只证明代码需要它，不证明映射覆盖率。

## 4. 未匹配到代码域怎么办

字段英文名精确匹配没有命中时，应标记为待查，而不是随便选相似中文代码域。科目编号、账套编号、组合编号、机构段值本身也不必是码值字典；它们可能需要另一张实体、关系或参数表解释。

若要判断“状态 3 是不是已经付款”，需要先确定字段、来源和制度，再核对原始数据与流程。此处的本地字典不足以证明银行到账或真实流程完成。
