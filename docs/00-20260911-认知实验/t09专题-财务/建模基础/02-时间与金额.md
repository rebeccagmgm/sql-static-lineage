# 时间与金额：日期名称不能替代加工口径

[返回入口](00-20260911-认知实验/t09专题-财务/README.md)

## 1. 先识别五种时间

| 时间 | 在 T09 中回答什么 | 已读例子 |
|---|---|---|
| 源快照日期 | 从哪一天采集资料 | FAC 卡片按源 `Busi_Date` 取数 |
| 会计期间 | 属于哪一个核算期 | ERP `JAN-2026` 一类期间文本；FMS 年月拼接 |
| 业务或估值日期 | 哪一天发生或估值 | `Eff_Date`、`Nav_Date`、`Trd_Date` |
| 关系有效期 | 某关系或状态何时有效 | 账单状态 `Strt_Date ≤ d < End_Date` |
| 加载与更新时间 | 仓库何时生成或修改记录 | `Data_Etl_Date`、`Data_Upt_Date`、`Data_Time` |

一个日期字段可以承载与名称不同的格式。ERP 凭证头把 `UPPER(PERIOD_NAME)` 写入分区 `Busi_Date`；会计期间表则把当天日期写进普通列 `Busi_Date`。不能在全部 T09 表上统一套用 `busi_date='YYYY-MM-DD'`。[ERP 案例](00-20260911-认知实验/t09专题-财务/实现详解/01-ERP凭证与余额消费.md)

## 2. `_H`、`_S` 与分区各能证明什么

`T09_BILL_STAT_H` 的已读代码确实开闭状态版本，当前链结束日为 `2099-12-31`。但 `T09_BILL` 的 `End_Date` 在源投影中为空，更新逻辑维护当前属性与删除标志，不能拿它代替状态历史。

`T09_SUBJ_BAL_S` 在 ERP 分支按来源和会计期间覆盖，`T09_VALU_H` 按日期及来源容纳估值。名字里有“历史”不等于所有变更版本都保留，也不等于每个来源采用同一种历史维护方式。

静态 SQL 中的多次 `INSERT OVERWRITE` 必须按先后、目标分区与回填逻辑解释。一个任务先整理历史再写当天状态，不是两个可以任选的“生产者”。

## 3. 回看窗口不同，历史可解释性也不同

- ERP 余额 61644 以“上一年同月”构造下界，代码未同时限定上界，不能直接叫“过去 12 个月”。
- ACV 62967 的近期数据从上月月初起读取，较早日期另从 TPA 资料回补；H12 快照又出现固定日期与交易日函数。
- CVS 80211 回看 24 个月的估值，但用当天科目资料补属性；这是历史估值与当前分类相结合。
- YAV 62978 回看 7 个交易日范围的源快照，再按方案有效期和估值日期连接确认记录。
- FAC 236259 取一份源快照中的多个月份，并处理当前、下一期结转候选。

上述参数、来源、完整条件见相应实现文档。它们说明已采集代码的行为，不能证明现在每天按相同参数运行。

## 4. 金额至少保留六个维度

**对象粒度、币种、借贷方向、期间或时点、金额类型、业务状态。**

ERP 凭证行分别保存原币借贷额与本币借贷额；该分支行上的 `Crrc_Cd` 为空，需要从凭证头等受约束的上下文取得币种。估值保存成本、估值、增值、收市价市值等不同指标。资产期间表保存月折旧、本年折旧、累计折旧，三者不能相加当总折旧。

已读 ERP 消费任务用 `贷方金额 − 借方金额` 得到特定科目及公司的收入口径。这不意味着全 T09 的收入、负债或费用都应用同一个正负公式。

很多模型金额列为 `STRING`。字符串能被 SQL 强制转换，不代表每一行都可成功转换；空串、空值、非数值及精度损失需要实际数据验证。

## 5. 来源分区是语义条件

`Data_Src_Cd` 是系统来源代码，`Real_Src_Tbl` 描述真实源表，`Src_Tbl` 还可能是逻辑分流标签。例如自营 FIA 分支真实读取 PB 表，但写 GF 标签；YAV 来源代码配合 HAV 物理视图。三者应一起读，不能仅凭前缀判成错误或将同名分区跨库合并。
