# 身份与粒度：先问这一行是什么

## 1. T09 没有一根适用于全部对象的统一主键

`Sob_Id` 表示账套，`Sob_Plan_Id` 表示账套方案，`Subj_Id` 表示科目，`Subj_Comb_Id` 表示多个核算段组成的组合。字段都带 `Id`，并不说明它们可互相替代，也不说明编号在所有系统之间唯一。

| 对象 | 本次已读身份线索 | 还必须保留的条件 |
|---|---|---|
| ERP 账套 | `LEDGER_ID → Sob_Id` | ERP 来源与具体快照；不能按账套名称合并 |
| ERP 会计期间 | `PERIOD_NAME → Acctnt_Pd`，`PERIOD_SET_NAME → Cal_Name` | 该加工 `Sob_Id` 为空，不能直接依赖它与账套等值连接 |
| ERP 科目组合 | `CODE_COMBINATION_ID → Subj_Comb_Id` | 公司、部门、科目等多个段；不是单一科目编号 |
| 凭证头 | `JE_HEADER_ID → Vchr_Head_Id` | 来源、账套、期间；是否全局唯一尚未验数 |
| 凭证行 | `JE_HEADER_ID + JE_LINE_NUM` | 来源与期间；不能只用凭证头编号标识一行 |
| FMS 记账单与明细 | `BILL_ID`，`BILL_REL_ID → Bill_Det_Id` | 单与明细各自来源分区、删除标志；父单号不是明细号 |
| PMS 申请与明细 | `PMS002-ID`，`PMS004-ID` | 编号前缀不可去掉后跨对象连接，关系表另行表达归属 |
| FAC 卡片与期间余额 | 卡片 `ASSET_CODE`；期间记录保留 `PK_CARDHISTORY → Src_Id` | 资产账簿、会计期间、来源和记录状态 |
| 产品实收与明细 | `PRD051-ID / PRD053-ID / PRD080-ID` | 收入业务分支及明细层级，不能把三者的数字尾段当统一身份 |

这些是从字段与 SQL 得到的身份线索，不是已验收的数据库主键声明。具体证据分别在 [ERP](00-20260911-认知实验/t09专题-财务/实现详解/01-ERP凭证与余额消费.md)、[申请与账单](00-20260911-认知实验/t09专题-财务/实现详解/03-记账单状态与采购身份.md)、[资产](00-20260911-认知实验/t09专题-财务/实现详解/04-FAC资产卡片与期间余额.md)、[收入](00-20260911-认知实验/t09专题-财务/实现详解/05-保险收入怎样展开到保单.md)。

## 2. 为什么“科目”和“科目组合”要分开

把“费用记在哪个科目”与“由哪个公司、哪个部门、哪个项目承担”放在一起，得到的是核算组合。ERP 组合加工把 `SEGMENT1…8` 分别映射为公司、部门、科目、子目、业务产品、内部往来、管理、项目段。

因此一个 `Subj_Seg` 可以出现在许多 `Subj_Comb_Id` 中。先按科目查组合再连接凭证行，必须预期存在多个组合；按一个科目直接拼一条机构记录，会抹掉成本归属维度。组合也不能与资产账户或客户证券账户混称为“账户”。

## 3. 关系本身也有一行的粒度

`T09_SUBJ_RELA_H` 保存两端科目及关系类型，`T09_SOB_RELA_H` 保存账套关系，`T09_APP_DOC_RELA_H` 保存申请关系，`T09_PMS_PROJ_SCONTR_APP_DOC_RELA` 保存分包与申请明细关系。关系类型、两端编号和时间共同说明关系，不能只保留一侧编号。

尤其是采购：项目、分包和申请明细不是顺次生成的一列编号。一个分包引用哪些申请明细，应查看桥接关系。是否一对多或多对多，本次没有全量行数据验证。

## 4. 金额与编号一起决定粒度

收入头上的 `Income_Amt` 是收入记录金额；收入明细上的同名字段是按客户、保单或其他对象展开后的金额。头连接明细后，头金额会重复出现。类似地，凭证头连接多条凭证行不能再把头金额按行加总，估值父科目与明细科目不能混在一起累计。

先选度量所在的对象层级，再连接描述属性。连接后应检查行数和分组金额是否变化；这些检查属于实际消费验收，本次只有静态风险定位。

## 5. 物理身份与业务身份是两件事

同名 `pdata_n.t09_valu_h` 与 `spdata_n.t09_valu_h` 是不同物理对象。资料保留平台、完整表名和物理身份哈希，各目录的来源与字段独立保存。哈希只是避免暴露连接标识，不能当成业务主键。

正文中出现的连接条件来自具体任务。任务中的未限定表名、`${src_table}` 宏和同名 TEMP 对象，不能仅靠词法检索确定到唯一物理表或跨任务生产者。
