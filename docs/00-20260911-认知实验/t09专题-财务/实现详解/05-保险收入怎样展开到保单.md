# 保险收入怎样展开到保单

[业务入口](00-20260911-认知实验/t09专题-财务/业务/06-产品收入与分配.md)

证据为 [任务 121468](attachments/05-保险收入怎样展开到保单/IMG-05-保险收入怎样展开到保单-20260914111012614.sql)，输出 `dm_index_n.prd_income_insure_detail`。这是已采集、固定为 `2026-05-19` 的 SQL，不能当作当前业务数据。

## 1. 收入头先确定范围

从 `T09_CHREM_PRD_ACTL_RECV` 读取保险来源 `ODATA_N_PRD.C_INSURANCE_PROD_INCOME`，排除状态 `5`。用 `Recv_Id` 的前缀后片段作为中间连接 ID，取交易日期、收入金额、状态和收入期间。

这次拆前缀只在已经固定保险来源的局部查询中使用，不能推广成跨普通收入、保险和特殊奖励的统一编号规则。`NOT IN ('5')` 也不会保留状态为空的行。

## 2. 明细先聚合，再与头连接

从 `T09_CHREM_PRD_ACTL_RECV_DET` 固定保险收入明细来源，按收入 ID、保单、产品、客户及客户机构分组，求明细 `Income_Amt` 之和，再与收入头连接。

输出同时保存头的 `income_amount` 与明细的 `income_amount_cust`。例如一笔 100 元收入分成两份保单明细 60、40，连接结果可能为 `(100,60)` 与 `(100,40)`。这只是概念示例；对第一列求和得到 200，是重复统计头金额，不能解释为实收增加。

## 3. 产品、订单、人员继续增加解释维度

- 产品从 T02 产品资料按源产品号连接，还限定保险产品类型范围。
- 保单销售人员从 T03 保险订单和另一套保单附加信息 `UNION ALL` 后取得。
- 员工机构取指定日期的 T98 员工资料，再用 T04 当前有效的 ERP—柜台机构对应补充。

两套保单来源用 `UNION ALL` 不会自动去重，产品和机构对应也没有在这段 SQL 中证明连接键唯一。若同一保单号在两个来源都出现，可能把已聚合明细再次放大；需要行数据核实，不能宣称已经发生。

## 4. 这份输出还有两个具体边界

一是中间层把最终 `income_id` 设为空串，实际连接用另一列临时 ID。输出字段存在，并不意味着收入身份已经可用于稳定回查。

二是 DDL 注释把状态 3/4 写成“已下发未推送 / 已下发已推送”，本地 CD1077 则为“部分下发 / 已下发”。字典日期是 `2023-12-20`，旧 SQL 注释的制度含义未重新确认。正文保留原状态，并指出两种解释的冲突，不择一冒充现行流程。

因此这条链说明 T09 收入如何进入产品、保单和人员视角，尚未验证金额守恒、机构历史还原、分配已执行或款项到账。
