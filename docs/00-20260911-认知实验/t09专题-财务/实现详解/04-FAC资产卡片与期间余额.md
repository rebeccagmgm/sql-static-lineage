# FAC：资产卡片怎样进入期间核算

[业务入口](00-20260911-认知实验/t09专题-财务/业务/05-固定资产与折旧.md)

## 1. 卡片是一套独立身份

任务 [236257](attachments/04-FAC资产卡片与期间余额/IMG-04-FAC资产卡片与期间余额-20260914111012603.sql) 的主源在 SQL 注释中标为 `ODATA_N_FAC.P_FA_CARD`；查询主体使用 `${src_table}`，因此具体宏绑定仍需与任务配置一起核对。已读投影和显式连接能确认：

| 模型列 | 源表达 | 解释 |
|---|---|---|
| `Ast_Card_Id` | 主表 `ASSET_CODE` | 会计卡片编号 |
| `Ast_Id` | 附表 `DEF15` | 另一资产编号，不能与卡片编号合并 |
| `Purch_Ord_Id / Ast_Contr_No / Inv_Id` | 附表 `DEF5 / DEF16 / DEF4` | 采购、合同和发票的引用线索 |
| `Purch_Pric / Tot_Amt / Adj_Amt` | `CURRMONEY / DEF8 / DEF9` | 不同金额含义，代码没有证明可相加 |
| `Co_Seg / Proj_Seg` | 优先映射组织或定义代码，否则保留源值 | 目标字段可能混合映射后值与原始值 |
| `Splr_Pty_Id / Splr_Src_Id` | 空串 / `PROVIDER` | 只保留供应商源号，未完成 T01 统一身份 |

卡片主、附表按 `PK_CARD` 左连，均筛当天且 `DR='0'`；用户、组织、定义资料也采用当天未删除快照。用户映射不到时保留原始用户值，不能把字段名当作统一用户编码保证。

## 2. 卡片历史记录才提供期间视角

任务 [236259](attachments/04-FAC资产卡片与期间余额/IMG-04-FAC资产卡片与期间余额-20260914111014674.sql) 从 `P_FA_CARDHISTORY` 读取期间资料，保留 `PK_CARDHISTORY → Src_Id`，经 `PK_CARD` 取卡片编号，再补账簿、部门、使用状态等信息。

其中 `Acctnt_Date` 由 `ACCYEAR + PERIOD` 拼接；`Ast_Pd_Stat_Cd` 来自 `NEWASSET_FLAG`；月折旧、本年折旧、累计折旧分别取不同源列。`Sob_Data_Src_Cd` 仍为空，源码旁也保留“待确认”，不能把账簿来源说成已统一。

## 3. 这不是简单地按卡片取最新一行

在已展开为 `2026-08-27` 的快照中，代码对 `DR='0'` 的卡片历史分两路：

1. `LASTSTATE_FLAG='Y'` 使用原会计年月构造 `MTH`。
2. `LASTSTATE_FLAG='N'` 将原会计年月前移一个月构造 `MTH`。
3. 合并后按 `PK_CARD + MTH` 分组，按原 `ACCYEAR + PERIOD` 降序取一条。
4. 再左连当天卡片、组织、部门、使用状态与账簿资料。

范围从快照月向前六个月的月界起，到下一月月界之前。第二路的分组月份与最终输出的 `Acctnt_Date` 并非同一个表达式，不能擅自把输出解释为已按 `MTH` 改写后的月份。排序也没有展示同月并列候选的额外决胜键，这需要实际源数据与规则确认。

部门身份使用 `CO-DEPT-` 前缀，与另一些 T09 分支的 `ERP-DEPT-` 不同；是否存在正式跨体系映射还没有证据。

## 4. 字段版本冲突必须显示给读者

旧元数据目录记录 16 列、无分区信息；平台目录有 51 个字段引用；本任务 SQL 含有资产卡状态、资产期间状态、账簿、月/年/累计折旧等一套声明与投影。

本专题按 FAC SQL 解释 FAC 加工，并把三种来源各自保存。不能把旧 16 列当这段 SQL 的完整目标结构；也不能因为平台引用较多就断言当前线上 DDL 与它完全一致。[物理字段](attachments/04-FAC资产卡片与期间余额/IMG-04-FAC资产卡片与期间余额-20260914111015526.json) · [平台字段](attachments/平台分类与范围统计/IMG-平台分类与范围统计-20260914111012385.json)

## 5. 使用上的实际含义

取某个月的折旧，应选择明确的期间记录及金额列，再核实卡片、账簿和机构对应。不能累计每天保存的月折旧快照，也不能把累计折旧加上本年折旧。固定资产附加信息与会计卡片之间目前只有字段线索，尚未证明可靠的一对一连接。
