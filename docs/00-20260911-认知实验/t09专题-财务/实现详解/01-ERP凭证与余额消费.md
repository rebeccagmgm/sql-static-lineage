## 2. 一个最小例子说明“科目组合”

下面是已读投影的简化表示，省略其他列，不是可直接运行的全量任务：

```sql
SELECT CODE_COMBINATION_ID AS Subj_Comb_Id,
       SEGMENT1 AS Co_Seg,
       SEGMENT2 AS Dept_Seg,
       SEGMENT3 AS Subj_Seg,
       SEGMENT5 AS Busi_Prd_Seg
FROM ODATA_N_ERP.A_GL_CODE_COMBINATIONS;
```

同一个科目段可以对应多个部门或产品段。分录中的 `CODE_COMBINATION_ID` 才是去这份组合资料取维度的线索。61604 对来源分区覆盖，已读 SELECT 没有源日期过滤；是否源表只保留当前资料，不能单由这段 SQL 判断。

## 3. 凭证头和凭证行的时间并不对称

62993 先找创建或最后更新日期不早于参数日的 `PERIOD_NAME`，再回取这些期间的所有凭证头。写入 `Busi_Date` 的是大写期间名，不是参数日。这是一种按受影响期间重写的策略。

62995 则从当天源快照取凭证行，按 `Acctnt_Pd + Src_Tbl` 动态分区写入。头的分区名叫业务日期、行的分区名叫会计期间，两者可能表达同类期间文本；不能因此机械要求两个表都有普通日日期分区。

该分支原币金额来自 `ENTERED_DR / ENTERED_CR`，本币金额来自 `ACCOUNTED_DR / ACCOUNTED_CR`，但行的 `Crrc_Cd` 为空。凭证头保存 `CURRENCY_CODE`，说明币种解释需回到凭证层上下文。

行状态使用转换表，约束目标表、目标字段、源系统、源表和源字段，转换缺失时保留源 `STATUS`。因此“已取到状态字符串”不等于“已全部标准化到 CD170”。

## 4. 余额怎样形成

61644 的核心规则是：

- 期初借方、贷方余额分别取 `BEGIN_BALANCE_DR / CR`。
- 期末借方、贷方余额分别为期初余额加期间发生额，转为 `decimal(18,2)`。
- 本币金额使用对应的 `_BEQ` 源字段。
- 年至今发生额在这个分支留空，不应由字段存在推断已计算。
- 会计日期写参数日；分区却按来源和大写期间名。

筛选下界是“参数日期上一年同月”，不是严格封闭的最近十二个月。源字段若为空或无效，也不能仅凭表达式保证金额质量。

## 5. 一个真实消费怎样定义收入

任务 [166973](attachments/01-ERP凭证与余额消费/IMG-01-ERP凭证与余额消费-20260914111016671.sql) 写入 `dm_index_n.fin_erp_line`。它依次连接凭证批、凭证头、凭证行、科目组合：

1. 各表分别限定 ERP 对应 `Src_Tbl`。
2. 凭证头限定 `Bal_Type_Cd='A'`、`Vchr_Stat_Cd='P'` 和指定账套。
3. 行限定会计期间年份不早于 2024，生效日期不晚于快照中的 `2026-05-19`。
4. 组合限定两个科目段、一个公司段，并要求 `Summ_Tplt_Id IS NULL`。
5. 按期间、摘要、凭证来源、业务产品段、公司段及科目段分组，计算 `SUM(Cr_Amt)-SUM(Dr_Amt)`。

它把英文月份期间转换为 `YYYYMM`，不是按字符串格式自然识别所有期间类型。特殊或调整期间能否映射，需要另核。

这个输出可以解释“特定账套、公司及科目范围内的借贷净额”。它不代表整个 T09 的收入，也没有在该 SQL 中按币种分组。使用者需要确认范围内币种一致、各 Join 未放大分录，并识别固定日期快照的限制。
