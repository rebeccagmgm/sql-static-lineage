# 账套、科目与核算框架

[返回入口](00-20260911-认知实验/t09专题-财务/README.md) · [本分支 19 个对象](00-20260911-认知实验/t09专题-财务/资料/逐表对象目录.md)

## 先理解四个不同问题

账套回答“在哪套账里核算”，科目回答“按什么财务类别记录”，科目组合回答“还带上哪些组织和业务维度”，会计期间回答“归入哪个核算期”。它们共同限定核算上下文，但不构成一条可忽略来源的统一主键。

| 模型入口 | 主要内容 | 容易误解的地方 |
|---|---|---|
| `T09_SOB` | 账套名称、币种、COA、日历、分类及控制属性 | 账套不等于 T03 资金账户，也不必对应单一产品 |
| `T09_ACCTNT_PD` | 期间名称、日历、起止日期、年度、期间号及调整标志 | ERP 分支账套号为空，期间要结合日历理解 |
| `T09_ACCTNT_SUBJ` | 科目编号、名称、层级、上级、方向及来源附加内容 | 同一科目号在不同方案、账套或来源中不一定同义 |
| `T09_SUBJ_COMB` | 公司、部门、科目、子目、产品、内部往来等段 | 多个组合可以共用一个科目段 |
| `T09_SUBJ_NAME_H / T09_SUBJ_RELA_H` | 名称版本与两端科目关系 | 历史有效期及关系类型应参与解释 |
| `T09_SUBJ_SYS_PLAN_INFO / T09_SOB_PLAN_RELA_H` | 科目体系方案及账套与方案关系 | 方案编号不能直接替换账套编号 |
| `T09_SOB_RELA_H / T09_SUBJ_COMB_RELA_H` | 账套间、组合间关系 | 要先查关系类型，不能默认都是父子关系 |
| ACV、CVS、LPS 附加信息及内部公司、部门表 | 不同核算系统保留的专用属性 | 财务公司段、部门段不自动等于统一机构 ID |

## 用 ERP 走一遍

`A_GL_LEDGERS` 的 `LEDGER_ID` 进入 `Sob_Id`，`CHART_OF_ACCOUNTS_ID` 进入 `Coa_Id`，`PERIOD_SET_NAME` 进入 `Cal_Name`。`A_GL_PERIODS` 提供同类日历名及期间；其 `Sob_Id` 留空，因此“账套 → 期间”应研究日历和期间条件，不能硬做两个 `Sob_Id` 等值关联。

`A_GL_CODE_COMBINATIONS` 把 `CODE_COMBINATION_ID` 作为组合编号，把 `SEGMENT1…8` 展开为核算段。凭证行保留组合编号，下游再通过它取公司、科目和业务产品段。详细 SQL、来源及消费限制见 [ERP 实现](00-20260911-认知实验/t09专题-财务/实现详解/01-ERP凭证与余额消费.md)。

## 分类不是统一的公司树

CD160 同时有 `PRIMARY/SECONDARY` 与 `01…06/99` 等账套分类取值。ERP 源的账套分类直接投影，其他系统可以使用另一组取值。这不能解读成所有账套共同遵守同一棵分类层级。

较新的平台字段中，科目关系还出现 `Sob_Id / Subj_Plan_Id` 及对应端字段，旧目录没有这些列。因此使用新科目方案逻辑前，应核实具体来源版本；不能只照旧的 `Sob_Plan_Id + Subj_Id` 认定完整身份。[冲突台账](00-20260911-认知实验/t09专题-财务/证据/冲突与待核问题.md)
