## 估值表的一行未必是一只证券

`T09_VALU_H` 同时有账套方案、科目、证券、备用识别号、数量、成本、估值和确认信息。ACV 保留科目层级及明细标志；CVS 由 `FISTOTAL` 派生明细标志；YAV 还保留记录类型与核算项目。因而表中可以包含科目汇总和底层明细，不能先假定“证券代码 + 日期”就是一行。

| 对象群 | 代表模型 | 回答什么 |
|---|---|---|
| 估值主体 | `T09_VALU_H` | 某时点在核算对象层级上的成本、价值、数量与增值 |
| 估值索引和控制 | `T09_ACV_VALU_IDX_INFO`、`T09_CVS_FIN_LOCK_REC_INFO`、`T09_VALU_SOB_BACK_CALC_INFO` | 哪次估值、是否确认或锁定、是否返账 |
| 投资与持仓细节 | `T09_ACV_PRD_IVST_DET`、`T09_ACV_SCR_SETT_HOLD_INFO`、`T09_CSTD_SOB_FUTR_HOLD_SHR_DET`、`T09_SUBJ_HOLD_STOR_DET` | 投资明细、结存、期货持仓、科目库存，不应与估值汇总重复计量 |
| 特殊估值 | 限售股、停牌资产调整、债权实际利率摊销 | 特定资产的估值或成本调整资料 |
| 计提设置 | `T09_SOB_PRVS_OPER_FEE_SET`、现金利息、定额待摊及扩展设置 | 费用或利息按什么配置计算 |
| 计提结果与调整 | `T09_SOB_PRVS_FEE_DET`、`T09_SOB_APRN_AMT_ADJ_DET`、`T09_ACV_EXPE_AMTE_INFO` | 发生了哪笔计提、摊销或调整 |
| 税率与核算参数 | 账套和科目税率、资管账套配置、资产分类参数、NSFR 调整 | 解释规则与管理配置，不是金额发生事实 |

## 来源分支必须保留

ACV 的 `L_ZTBH` 进入账套方案编号；CVS 先由产品记录取得 `FSET_CODE`，确认标志还来自锁定记录；YAV 以组合代码为入口，必须匹配有效方案和确认记录。相同的目标字段并不意味着源对象层级完全一致。

更具体地，CVS 的确认连接允许没有锁定记录，随后生成 `0`；YAV 对确认表使用内连接，没有对应记录时该估值行不能进入这个分支的结果。`Cfm_Flag=0` 与“没有结果行”不是同一种事实。[多源估值实现](00-20260911-认知实验/t09专题-财务/实现详解/02-多源估值与确认.md)

## 计提设置与计提结果怎样分开

任务 163935 将源设置 `C_IDEN` 拼为 `YAV019-…` 的 `Set_Id`，保存运营费用配置；236252 把另一份源明细的 `C_IDEN` 拼为 `YAV047-…` 的 `Det_Id`，保存计提费用明细。这证明它们是不同对象；尚未据此证明一个设置一定对应哪些结果明细。
