## 从一笔收入逐层展开

`T09_CHREM_PRD_ACTL_RECV` 保存收入记录及状态、分配方式、计算时间等属性；`…RECV_DET` 保存进一步分配到对象的明细；产品关系、下发、下发明细和奖励切分前明细说明收入怎样关联产品、组织分配与发放。收益凭证月度应收明细另有自己的期间及应收口径。

| 对象 | 应回答的问题 |
|---|---|
| `T09_CHREM_PRD_ACTL_RECV` | 原始收入或奖励记录是什么，金额及处理状态如何 |
| `T09_CHREM_PRD_ACTL_RECV_DET` | 收入怎样分到产品、客户、保单等明细对象 |
| `T09_CHREM_PRD_RECV_RPD_RELA_H` | 实收记录与产品怎样关联 |
| `T09_CHREM_PRD_ACTL_RECV_DISTR` | 一次收入下发如何记录 |
| `T09_CHREM_PRD_ACTL_RECV_DISTR_DET` | 下发继续分解成哪些明细 |
| `T09_CHREM_PRD_ACTL_RECV_RWD_SPLIT_BEF_DET` | 奖励切分前的明细基准是什么 |
| `T09_INCOME_VCHR_MTH_RCVB_INCOME_DET` | 收益凭证在某月形成什么应收收入 |

## “实际收入”表中也有不同业务分支

| 已读分支 | 收入 ID 构造 | `Income_Amt` 的源字段 | 特有内容 |
|---|---|---|---|
| PRD051 普通产品收入 | `PRD051-ID` | `INCOME_AMOUNT` | 收入区间、分配范围、预跑标志等 |
| PRD053 保险收入 | `PRD053-ID` | `INCOME_AMOUNT` | `Income_Busi_Type_Cd='insu'`，保单级明细在另一表 |
| PRD080 特殊奖励 | `PRD080-ID` | `BONUS_AMOUNT` | 业务类型 `spec`，已读投影的收入开始/结束日期及收款账户留空 |

“实际收入”是模型名称，不能据此认定每行都是银行已结算现金收入。特别是特殊奖励使用另一种源金额，还需结合业务类型、状态和后续分配看待。[SQL 139847](attachments/06-产品收入与分配/IMG-06-产品收入与分配-20260914111012591.sql) · [139849](attachments/06-产品收入与分配/IMG-06-产品收入与分配-20260914111014203.sql) · [162990](attachments/06-产品收入与分配/IMG-06-产品收入与分配-20260914111014982.sql)

## 保险案例把重复金额问题说明白

下游 121468 先从保险收入头取金额，再按收入、保单、产品、客户、机构聚合明细，最后关联产品、订单及人员。输出同时有 `income_amount` 和 `income_amount_cust`：前者在一笔收入对应多个保单时会重复，后者才是该层明细金额。[完整消费](00-20260911-认知实验/t09专题-财务/实现详解/05-保险收入怎样展开到保单.md)

CD1077 与旧消费表注释对状态 `3/4` 的文字解释并不一致。专题保留这种冲突；状态、已下发、已推送以及真实支付不能相互替代。下发链路的完整运行和金额守恒尚未验证。
