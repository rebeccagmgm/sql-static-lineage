## 设备、会计卡片、账簿和期间是不同对象

一件实物可能有管理编号；财务会计卡片记录取得、原值、使用和折旧属性；期间余额记录这张卡片在某账簿与期间的会计状态。把三层压成“资产一行”，会丢失月份、机构归属或核算版本。

| 模型 | 本次已见内容 | 证据深度 |
|---|---|---|
| `T09_AST_ACCTNG_CARD_INFO` | 资产卡编号、资产编号、购置金额、折旧标志、采购/合同/发票引用、用户和供应商源号 | FAC 原始投影与多表连接已读 |
| `T09_AST_PD_BAL_INFO` | 卡片、账簿、会计期间、原值、月/年/累计折旧及部门等 | FAC SQL 已读；旧目录与新结构明显不同 |
| `T09_AST_BOOK_USER_RELA_H` | 资产账簿与用户的关系历史 | 有字段及 ERP063 SQL 证据，未逐来源做关系验收 |
| `T09_OUR_FIX_AST_ADTNL_INFO` | 固定资产 ID、源 ID、FA 编号、原值净值、责任人、使用及成本承担机构 | 平台字段；本次未找到对应生产 SQL |
| `T09_FIX_AST_LKMAN_H` | 固定资产重要联系人 | 平台字段，生产与关系基数待核 |
| `T09_FIX_AST_INR_ORG_RELA_H` | 固定资产与内部机构关系 | 平台字段，关系类型与来源映射待核 |
| `T09_FIX_AST_CLAS_H` | 固定资产分类历史 | 平台字段，分类体系与生产逻辑待核 |

## FAC 卡片为什么不能直接当实物主档

任务 236257 的 `Ast_Card_Id` 来自 `ASSET_CODE`，`Ast_Id` 来自卡片附表 `DEF15`。这两个值来自不同源字段。供应商当事人编号 `Splr_Pty_Id` 留空，但供应商源编号保留 `PROVIDER`；因此不能直接用这张卡片与 T01 供应商完成统一身份关联。

用户也采用“优先映射用户代码，缺失时保留源值”的逻辑。字段叫用户编号，不保证每行已经进入统一用户体系。已知限制与具体 Join 见 [FAC 实现](00-20260911-认知实验/t09专题-财务/实现详解/04-FAC资产卡片与期间余额.md)。

## 折旧一定要讲期间

期间余额保留月折旧、本年折旧、累计折旧，以及期初、当前的部门和资产状态。后两种累计值不是新的当期发生额，不能把多个日期快照逐行相加。

旧目录的这张表只有 16 列、无分区信息；平台有 51 个字段引用，FAC SQL 的声明与投影又保留独立结构。因此本专题按具体 FAC 加工解释，不把旧元数据修写成新版本，也不默认平台字段就是最终物理 DDL。
