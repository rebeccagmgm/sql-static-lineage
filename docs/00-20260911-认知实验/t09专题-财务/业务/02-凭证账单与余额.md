# 凭证、账单与余额

[返回入口](00-20260911-认知实验/t09专题-财务/README.md) · [本分支 20 个对象](00-20260911-认知实验/t09专题-财务/资料/逐表对象目录.md)

## 从记录层级理解，不先从表名理解

凭证批组织一组凭证，凭证头描述一张凭证，凭证行承载具体借贷分录。记账单是另一个业务单据对象，有自己的状态与明细；余额是按核算维度和期间保存的结果。即使它们都带金额，也不能相加作为财务规模。

| 记录层级 | 模型 | 本次确认的关键内容 |
|---|---|---|
| 凭证批 | `T09_VCHR_BAT` | 批编号、批状态、默认期间及过账等属性 |
| 凭证头 | `T09_VCHR_INFO` | 头编号、批编号、账套、期间、来源、状态及币种 |
| 凭证行 | `T09_VCHR_LINE_INFO` | 头编号与行号、组合编号、原币及本币借贷额 |
| 业务附加与付款 | `T09_LPS_VCHR_ADTNL_INFO`、`T09_FIN_SHR_VCHR_ADTNL_INFO`、`T09_VCHR_PYMT_INFO` | LPS/FSC 的业务上下文与付款信息；不能由凭证存在推断已到账 |
| 回单对应 | `T09_VCHR_LINE_BNK_RECPT_RELA_INFO` | 凭证行与银行回单的对应记录，不是凭证金额本身 |
| 记账单 | `T09_BILL`、`T09_BILL_DET`、`T09_BILL_STAT_H` | 主单、金额明细与状态版本 |
| 科目余额 | `T09_SUBJ_BAL_S / T09_SUBJ_BAL_HFM_S` | 期间、借贷方向、币种、预算及汇总背景 |
| 财务段和专用凭证 | 银行账户财务段、柜台非交易财务段、席位佣金凭证等 | 业务对象怎样接入核算维度，需要来源分支说明 |

## 凭证与余额为什么不互相替代

ERP 余额加工直接读 `G_GL_BALANCES`。例如期末借方余额由 `BEGIN_BALANCE_DR + PERIOD_NET_DR` 计算，期间借方发生额来自 `PERIOD_NET_DR`。本次未见该任务从 T09 凭证行重算余额；所以可以从业务含义理解它们的联系，不能宣称已证明两套结果逐笔勾稽相等。

余额还保留 `ACTUAL_FLAG`、预算版本和保留类型等维度。同账套、同组合、同期间但标志不同的行，可能有不同含义。只按三个编号去重可能误删有效记录。

## 为什么账单状态需要独立历史

FMS 账单主表维护当前属性和删除标记，状态历史表另以账单编号及状态类型比较新旧状态，更新时关闭旧链、开启新链。问题“这张单现在是什么状态”与“上月末是什么状态”因此需要不同对象。[详细案例](00-20260911-认知实验/t09专题-财务/实现详解/03-记账单状态与采购身份.md)

## 下游怎样真正使用

[ERP 消费](00-20260911-认知实验/t09专题-财务/实现详解/01-ERP凭证与余额消费.md) 连接批、头、行和科目组合，限定已过账凭证及特定科目、公司后计算借贷净额。[LPS 消费](00-20260911-认知实验/t09专题-财务/实现详解/06-LPS凭证与账户机构.md) 还要连接账户、机构及有效期内科目关系。两者证明 T09 可以被下游组合使用，但不是一套通用财务宽表规则。
