## 报表项定义与指标值分开

`T09_FIN_STMT_ITEM` 定义报表项，`T09_FIN_STMT_ITEM_IDX_VAL` 保存账套、公司、部门、期间、报表项、指标及值。后一张表不是“一个部门一个金额”，还包含 `Idx_Id` 与指标值来源类型。

任务 196399 从 `F_EXAM_PROFIT_INDEX` 投影：`ACCT_ID → Sob_Id`，`SRC_BUSI_DATE → Acctnt_Pd`，`INDEX_ID / INDEX_VAL → Idx_Id / Idx_Val`；公司、部门分别加 `ERP-CO-`、`ERP-DEPT-` 前缀，报表项用 `FMS030-` 前缀。它直接承接源指标，不是在这段 SQL 内从 T09 凭证重算损益。

因此在报表上看到一个数值，还需要知道指标定义、单位、来源类型及期间；不能用 `Idx_Val` 字段名宣称所有指标都是金额。[SQL 196398](attachments/07-财务报表成本与档案/IMG-07-财务报表成本与档案-20260914111012595.sql) · [SQL 196399](attachments/07-财务报表成本与档案/IMG-07-财务报表成本与档案-20260914111014321.sql)

## 成本分摊为什么需要动因和费用两类对象

`T09_FIN_COST_APRN` 的平台字段包括管理部门、受益机构/部门、分摊动因代码、动因值、维护日期和有效标志。`T09_FIN_COST_APRN_FEE_DET` 则保存费用明细编号、业务日期、公司及部门、核算段、凭证摘要、发票等。

前者表达“依据什么分摊”，后者提供“待解释的费用明细”。目前没有相应正式加工 SQL 证据证明使用了哪种比例公式、怎样处理零分母、哪个版本有效，也不能把测试主题下的任务名称当上线证明。两对象已进入完整目录，但算法与消费仍是明确缺口。

`T09_FMS_EXAM_ADJ_RSLT`、`T09_BUSI_IDX_SUBJ_MAP` 属于考核调整、业务指标与科目的映射背景。后者只在旧字段目录命中，本次平台目录未见，应保留单侧来源状态。

## 会计档案记录材料和配置，不承载分录金额

`T09_FAF_ATTACH_INFO` 保存附件身份、类别、格式、大小、哈希、页数、上传类型和 ERP/OA 关联；`T09_FAF_ATTACH_PLAC_INFO` 保存配置背景。

任务 101607 从附件表左连配置表，按 `ATTCFG_ID` 关联。它将 `IS_CONVERT='0'` 映射为目标“已转 PDF 标志”`1`，将 `'1'` 映射为 `0`。这个例子说明相近字段名称不保证原值可直接照抄；此处只描述已读转换，不以该标志验证真实文件可打开。

附件信息库也不等于附件正文库。本次没有打开文件路径、调取财务原件或验收归档完整性。[SQL 101607](attachments/07-财务报表成本与档案/IMG-07-财务报表成本与档案-20260914111015155.sql)
