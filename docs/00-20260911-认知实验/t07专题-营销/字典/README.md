## 1. 使用顺序

先确认目标字段属于什么对象，再核对本来源的 SQL 是直接保留源码、写常量，还是调用转换表。随后用代码域解释仓库码，并保留原值、备注和日期。缺任一环，都不应把字典含义当作实际行值已经标准化的证明。

本次从 T07 字段英文名精确匹配得到 **85 个代码域候选**，包含通用性别、币种、状态等域。候选命中不等于每一来源都适用。完整入口为[字段代码域索引](00-20260911-认知实验/t07专题-营销/字典/字段代码域索引.md)、[原始域与码值 JSON](attachments/字段代码域索引/IMG-字段代码域索引-20260914110643035.json)。码值快照状态为 UNVERIFIED。

## 2. 先读这些代码域

| 业务问题 | 代码域 | 需要一起保留的上下文 |
|---|---|---|
| 这是哪种活动 | CD672 `PROM_TYPE_CD` | 来源身份；字典含直播、投研、回访、运营、销售、销控、赛事等 |

| 名单里是哪类身份 | CD386 `CUST_TYPE_CD` | 交易账号、广发通、游客、嘉宾、手机号等；PRD黑名单51另有SQL说明 |

| 礼品类别与状态 | CD468 `GIFT_TYPE_CD`、CD469 `GIFT_STAT_CD` | 券配置、实际券、服务权益及来源差异 |

## 3. 四层代码不要混在一起

| 层次 | 例子 | 本次证据能证明什么 |
|---|---|---|
| 源系统值 | WOS 的 `STATUS`、MIO 的 `configed` | 该 SQL 读取或过滤的原值 |
| 源→仓库转换规则 | `REF_CD_CVT_MAP` 的目标表/字段、源系统/表/字段条件 | 已读 SQL 如何选择映射，不证明映射行实际齐全 |
| 仓库代码域 | CD487、CD672 | 本地字典记录的值和含义 |
| 业务消费条件 | 92199 的状态31、104076 的状态4 | 该消费语句选择什么范围，不是全主题默认口径 |

本地资产 SQLite 导入了代码域与仓库码值；本次未查询到独立的源转码明细数据。因此 `NVL(DW_CD_VAL, SRC_VALUE)` 应解释为“命中转换则用仓库码，否则回退源码”，不能写成“全部转码成功”。

香港礼品市场转换使用当地 `T99_CD_CVT_MAP`，不拿境内转换规则替代。

## 4. 本次查得的差异，需要原样保留

| 差异 | 两端证据 | 对使用的影响 |
|---|---|---|
| CD1447部分值带前导空格 | 字典为 `" MIO_COMN_CAM_STRG"`、`" MIO_MSG_PUSH_STRG"` 等，SQL写值无空格 | 严格字符串等值Join会不同；展示可解释，原值不静默修正 |
| ART关系类型1与01 | 179998/179999写`'1'`，CD1522/CD1523为`'01'` | 不声明已完全字典匹配，不能擅自数值化丢失前导零 |
| 礼品类型10 | 79213固定写10；CD468/10为权益积分，01才是优惠券 | 不能凭来源表名将10解释为优惠券 |
| ECR活动状态47 | 109333将“已拒绝”映射47；CD487/47描述直播“结束(已屏蔽)” | 同域不同来源的语义冲突，保留源含义和差异 |
| 黑名单类型51 | 167367注释为黑名单交易账号；CD386未命中51 | 可引用SQL说明，不能编造字典行 |
| WOS状态历史未转码 | 88662直接保留STATUS；主表88559调用转换 | 历史值不能直接套主表状态筛选 |

这些差异说明的是当前所读快照。没有用它们断言最新平台仍有相同错误。

## 5. 代码域缺失与同名歧义

本地 `ref_dw_cd_list` 未命中 `PROM_STATI_INFO_TYPE_CD`、`PROM_IMP_TIME_TYPE_CD`、`GIFT_STAT_TYPE_CD`。已有 SQL 中的具体取值可以逐分支解释，例如 WOS统计01/02/04对应点赞/PV/UV、ESS重要时间01/02对应报名开始/结束；但不据此编造全局完整字典。

`EQUI_CATE_CD` 对应的 CD340 同时含证券权益及营销服务权益条目。字段同名只提供候选域，仍应对照 MSA 源 TYPE 与实际值。平台没有命中、SQLite没有导入和字典不存在，是三种不同结论。
