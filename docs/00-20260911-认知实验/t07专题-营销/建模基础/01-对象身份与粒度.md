## 1. 一场活动为什么需要多张表

以 RMS 活动为例：活动主表保存主题与时间，报名表保存报名记录，日程表保存具体安排，日程员工表保存参与角色，活动事件关系连接服务事实。把这些数据拆开，才能表达“一场活动有多条报名、多项日程、多个参与角色”。

因此，活动编号在多张表重复是正常建模现象。只有当我们确定当前要统计的是活动、报名、日程、员工角色还是服务事件后，行数才有业务含义。[完整案例](00-20260911-认知实验/t07专题-营销/实现详解/03-投研活动服务报名与合集.md)

## 2. T07 的身份并不只有 Prom_Id

| 身份 | 已读来源表达 | 一行首先应如何理解 |
|---|---|---|
| `Prom_Id` | `MIO010-` + 活动号；`WOS007-` + 直播号；`RMS011-ACT-` + 活动号 | 来源内的活动或内容对象 |
| `Cam_Strg_Id` | `MIO015-`、`MIO020-`、`MIO028-`、`MIO052-` + 各自源号 | 商机来源任务名为 MIO032，实际前缀为 MIO028；必须读投影表达式 |
| `Cam_Mdl_Id` | `ART001-` + `MODEL_ID` | 模型定义，非某客户的预测输出 |
| `Cust_Seg_Id` | 可能为裸 `ID` 或拼前缀编号 | 分群定义或成员关系端点，按来源核对 |
| `Msg_Id` | `MSC001-`/`MSC002-` + `MID` | 广播或定向消息 |
| `Task_Id` | 呼叫中心或 AI 任务源号 | 回访/外呼任务，非调度系统任务 ID |
| `Gift_Id` | `PRD016-`、`PRD058-` + 源号；香港直接 `BATCH_ID` | 礼品配置、券或批次，不能统一假定为单张券 |
| `Prom_Enrl_Id` | `RMS036-` + 报名 `ID` | 一次报名记录，不等同参与人 |
| `Sched_Id` | `RMS051-` + 日程 `OBJID` | 活动下的一项日程 |
| `Set_Id`、`Elemt_Id` | `RMS079-`、`RMS081-` + 源号 | 投研合集及其中的内容元素 |

来源见 [MIO](attachments/03-来源职责与交叉矩阵/IMG-03-来源职责与交叉矩阵-20260914110643657.sql)、[WOS](attachments/01-对象身份与粒度/IMG-01-对象身份与粒度-20260914110644726.sql)、[ART](attachments/02-策略模型与规则/IMG-02-策略模型与规则-20260914110651069.sql)、[客群](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110643005.sql)、[消息](attachments/04-消息分发与回访/IMG-04-消息分发与回访-20260914110643014.sql)、[香港](attachments/逐表SQL候选覆盖/IMG-逐表SQL候选覆盖-20260914110643010.sql)。这些是加工身份规则；没有据此宣称数据库主键约束或运行数据唯一性。

## 3. 同一字段名不保证同一身份空间

`t07_prom_cust_list.Cust_Id` 必须与 `Cust_Type_Cd` 一起解释。字典 CD386 包括交易账号、广发通账号、游客、对公客户联系人、外部嘉宾、OA 账号、手机号等。RMS 嘉宾分支甚至把 `Cust_Id` 写空，只保留姓名与源记录 ID。[嘉宾 SQL](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110644593.sql)

产品中心名单分支又写入 `Cust_Type_Cd='51'` 表示黑名单交易账号，该值未在本地 CD386 中命中。不能删掉类型后把所有 `Cust_Id` Join 到同一个 T01 主键。[名单 SQL](attachments/01-对象身份与粒度/IMG-01-对象身份与粒度-20260914110651525.sql)

`User_Id` 也并非总是客户号。客群成员中有 `RCC213-` 前缀和用户编号类型，策略用户关系可能表达内部使用者。账号相同的字面值不自动代表同一个人。

## 4. 五种常见行粒度

| 表达形式 | 例子 | 主要风险 |
|---|---|---|
| 对象当前资料 | 活动主表、营销策略、礼品资料 | 多来源同名对象；删除标志与业务状态混淆 |
| 关系及关系历史 | 策略→活动、活动→员工、礼品→当事人 | 一个对象有多条角色/关系；Join 后乘行 |
| 配置或规则明细 | 产品活动指标配置、分群筛选条件、外呼触发参数 | 规则描述被误当执行结果 |
| 参与或办理记录 | 报名、客户名单、金钥匙分发、回访任务 | 名单黑白属性、重试、任务池与执行任务重叠 |
| 观察或汇总结果 | 活动统计历史、榜单、库存历史 | 同时点重复累计、不同状态数量重复相加 |

没有统一的“T07 一行”。逐表入口见[对象职责与粒度](00-20260911-认知实验/t07专题-营销/资料/对象职责与粒度.md)。

## 5. 物理身份与业务身份分两层

先用 `platform + data_source + qualified_name` 定位表，再用来源分区、业务编号、类型及时间定位数据。`pdata_hk.t07_gift_info` 与 `pdata_n.t07_gift_info` 保留各自的物理身份和字段说明；`public` 同名目录也不借用 Hive 注释。

本专题所有候选键都是阅读与后续验证的起点。没有客户行数据、重复键检查或约束证据时，不用“唯一主键”替代“已见身份字段”。
