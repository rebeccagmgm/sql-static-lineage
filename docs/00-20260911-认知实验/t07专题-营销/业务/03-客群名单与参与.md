## 1. 先区分六种集合

| 对象 | 回答什么 | 不能代替什么 |
|---|---|---|
| 客群规则 `t07_prom_cust_seg_rule` | 如何筛选、多久更新、哪些范围包含/排除 | 具体客户成员 |
| 客群成员 `t07_cust_seg_info` | 哪个用户在某项目和分群中 | 通用当事人身份映射 |
| 客群关系 `t07_cust_seg_rela_h` | 一个客群与另一分组有什么关系 | 规则执行后的客户清单 |
| 活动客户名单 `t07_prom_cust_list` | 哪类人员/账号被这份来源名单记录 | 实际参与或成交客户 |
| 策略触达客群名单 `t07_cam_strg_cust_seg_cust_list` | 某策略关联的客群文件及客户记录 | 已触达成功的回执 |
| 报名 `t07_prom_enrl_info` / MSA 参与信息 | 报名状态、签到或特定活动行为 | 上述名单的全部成员或最终营销效果 |

名称中的“规则/信息/关系”不能替代字段核对。`t07_cust_seg_info` 虽叫“分群信息”，其字段却是用户、项目、用户类型、分群号、分群时间及日期，表达的是成员记录。

## 2. CPL 规则不是未经处理的全量规则表

86912 读取 `P_GF_CUST_CLUSTER`，按 `NAME` 分组、`ID` 降序，保留 `ROW_NUMBER=1`。目标 `Cust_Seg_Id` 取裸 ID，筛选条件、特征标签、简化 SQL 和中文解释分别保留。创建人还按员工来源区分登录名与拼接编号。[SQL](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110643005.sql)

因此，一条规则记录可以携带用户数、筛选表达式、更新时间，但该 SQL 没有执行这段表达式去重新证明人数。按名称去重还意味着同名不同 ID 不会全部保留。关系表端点与规则 ID 的差异见[策略与客群案例](00-20260911-认知实验/t07专题-营销/实现详解/01-策略到活动与客群.md)。

## 3. MIO 成员记录有项目和用户体系限制

85259 的历史渲染快照取指定项目的 `FILE_USER_GROUP`，用户编号为 `RCC213-` + `DT_ID`，用户类型由 `SCENARIO_CODE` 转换，保留 `SEGMENT_ID` 和 `STAT_DATE`，写来源加业务日期分区。[SQL](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110644555.sql)

这不能代表 MIO 所有项目、所有身份系统的完整分群成员。快照内渲染日期是 2026-05-21，不把查询文件的采集日改写成成员的业务日。

## 4. 活动名单里的“人”不止客户

RMS074 的活动嘉宾名单用 `RMS011-ACT-` + 活动号、`Cust_Type_Cd='5'`，客户编号为空，源记录 ID 与嘉宾姓名保留。RMS073 还有电话会议参会名单附件来源；ECR 来源为活动联系人，ESS 来源为模拟炒股参赛用户。名单的来源角色必须保留。[103000](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110644593.sql)、[102999](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110648350.sql)、[116192](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110648427.sql)、[168846](attachments/03-客群名单与参与/IMG-03-客群名单与参与-20260914110651240.sql)

PRD086 将逗号分隔的 `BLACK_CLIENT`、`WHITE_CLIENT` 分别展开为行，黑名单类型为 `51`，白名单交易账号类型为 `1`。把整表客户号去重后称“活动参与人数”，会把明确被排除的名单也算进去。[167367](attachments/01-对象身份与粒度/IMG-01-对象身份与粒度-20260914110651525.sql)

## 5. 新对象：策略客群文件与客户

238508 将 `P_GF_RYZJ_BOARD_DATA` 写入 `t07_cam_strg_cust_seg_cust_list`：策略为 `MIO020-STRATEGY_ID`，分类为消息推送策略，`Cust_Seg_Id` 留空，文件号取 `GRP_UUID`，客户号取 `CLIENT_ID`。[SQL](attachments/03-来源职责与交叉矩阵/IMG-03-来源职责与交叉矩阵-20260914110650389.sql)

业务日期取源 `SRC_BUSI_DATE`，但目标只按 `Src_Tbl` 分区。不能看到 `Busi_Date` 列就假定有日期分区，也不能用空的 `Cust_Seg_Id` 直接接分群规则。文件链接是证据中的属性，本次没有下载名单文件。

## 6. 产品分群这一支也要保留

239514 的 `t07_prom_prd_seg_rule` 每条记录同时含 `CPL021-CLUSTER_ID`、分群名称、证券代码、交易所类型与交易场所类型。它至少表达分群中的标的明细，而不是只有一行的抽象规则。[SQL](attachments/03-来源职责与交叉矩阵/IMG-03-来源职责与交叉矩阵-20260914110652755.sql)

与 T02 对接时要解释证券代码及市场类型，不能将 `Prd_Seg_Id` 当作 `Prd_Id`。与客户群同属“范围定义”，但两端对象完全不同。
