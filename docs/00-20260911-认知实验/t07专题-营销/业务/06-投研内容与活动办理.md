## 1. 投研这一支为何属于营销主题

投研向客户提供路演、电话会议、调研、内容合集等服务，需要组织对象、参与人员、日程、报名和后续服务记录。T07 在这里保存活动与内容组织方式；实际服务事件可由 T05 记录。Wiki 也明确把投研合集列在 T07。[主题定义](attachments/06-投研内容与活动办理/IMG-06-投研内容与活动办理-20260914110643018.json)

## 2. 活动与路演不是同一种构造

RMS011 来源的活动主表编号是 `RMS011-ACT-OBJID`，`t07_rms_act_info` 保存会议类型、审批、嘉宾、录音、报名设置与费用等专项属性。

RMS005 路演主记录来源更复杂：61582 关联预约关系、路演申请与服务记录，过滤删除、状态和服务类型；同一 `REQUESTID` 按服务创建时间升序取第一条，活动号使用该服务的 `OBJID`。[RMS 活动](attachments/06-投研内容与活动办理/IMG-06-投研内容与活动办理-20260914110645561.sql)、[路演构造](attachments/06-投研内容与活动办理/IMG-06-投研内容与活动办理-20260914110649289.sql)

因此，RMS 路演活动数不是无条件的服务记录数，也不是从表名直接得到的申请数。`t07_rms_rd_show` 另外保存路演时间、类型、申请员工、研究组和申请序号。

## 3. 一场活动的办理层次

| 层次 | 表 | 需保留的区别 |
|---|---|---|
| 报名 | `t07_prom_enrl_info` | 报名身份、参与人身份、报名状态与签到标志 |
| 客户与嘉宾名单 | `t07_prom_cust_list` | 客户、联系人、外部嘉宾、名单附件来源不同 |
| 日程 | `t07_prom_sched_info` | 一个活动可有多项日程，日程还有产品和地点 |
| 日程员工 | `t07_prom_sched_emp_prtc_info` | 计划、实际、历史流程、有效参与是不同类型 |
| 活动员工/员工组 | `t07_prom_emp_rela_h`、`t07_prom_emp_grp_rela_h` | 活动层角色，不代替日程层角色 |
| 专家 | `t07_prom_eprt_info` | 专家身份、费用与反馈，非统一员工身份 |
| 服务联系 | `t07_prom_evt_rela_h` | 活动与 T05 客户服务事件的专门关系 |
| 费用承担 | `t07_prom_fee_emp_grp_bear_prop` | 承担对象、组类型、源组和比例 |

这些层次通过特定来源编号连接，不能全部在活动编号上展开后直接累计费用。完整实例见[实现详解](00-20260911-认知实验/t07专题-营销/实现详解/03-投研活动服务报名与合集.md)。

## 4. 费用比例还需要哪一步解释

191467 从 `N_ACT_COST_ASSUME` 取费用比例 `PROPORTION`。研究组、销售小组、员工小组的编号规则不同，代码根据源群组和映射命中分别决定类型及前缀。[SQL](attachments/06-投研内容与活动办理/IMG-06-投研内容与活动办理-20260914110649340.sql)

该投影没有将比例除以 100，也没有计算实际费用。比例到底是 0–1 还是 0–100、各承担方是否加总守恒、删除记录是否剔除，需消费规则或业务行数据。表名有“承担比例”不能代替这些证据。

## 5. 合集是一套内容组织对象

`t07_rms_set` 是合集；`t07_rms_set_elemt` 是元素；`t07_rms_set_elemt_rela` 保存集合包含什么元素、置顶和顺序；合集员工/员工组关系表达参与或归属。

134984 的集合主键拼 `RMS079-ID`，134985 将集合号与 `RMS081-TARGET_ID` 元素号关联。集合里的一个内容元素并不总是一场活动，不能把 `Elemt_Id` 拆前缀后当 `Prom_Id`。[集合](attachments/03-投研活动服务报名与合集/IMG-03-投研活动服务报名与合集-20260914110652292.sql)、[关联](attachments/02-关系时间与连接/IMG-02-关系时间与连接-20260914110650569.sql)

另有 `t07_rms_strg_conf_info` 描述策略会议标题、地点、时间、议程和报名入口。这是会议内容及入口资料，不能因为含“策略”就并入 `t07_cam_strg` 的营销策略。
