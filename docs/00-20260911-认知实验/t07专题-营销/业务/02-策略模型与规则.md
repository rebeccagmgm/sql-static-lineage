## 1. 策略不等于活动，也不等于模型

活动回答“开展什么”；策略回答“如何选择、安排和触发”；模型描述一种预测能力及其产出对象。三者可能协作，但已见模型里没有证明任意营销模型都能直接连到某个策略或活动。

`t07_cam_strg` 保存策略身份、类别/类型、名称、有效时间、状态、分类和计算时间。通用策略、推送策略、商机策略、定向策略共用此表，并保留自己的编号前缀。

| MIO 分支 | 身份 | 分类 | 代表加工行为 |
|---|---|---|---|
| 通用策略 MIO015 | `MIO015-ID` | `MIO_COMN_CAM_STRG` | 仅取 `STATUS='configed'`，状态写 `01`；起止从统计时间数组拆出 |
| 推送策略 MIO020 | `MIO020-ID` | `MIO_MSG_PUSH_STRG` | 关联策略分析资料取统计起止与计算时间，状态转码 |
| 商机策略 MIO032 | 实际为 `MIO028-ID` | `MIO_OPTY_STRG` | 任务名后缀不能用来推断业务编号；状态写 `01`，起止时间留空 |
| 定向策略 MIO052 | `MIO052-ID` | `MIO_DF_STRG` | 计划和计算时间加 8 小时，状态通过映射后回退源值 |

## 2. 策略的附加信息与关系

`t07_mio_cam_strg_adtnl_info`、`t07_mio_msg_push_strg_adtnl_info`、`t07_mio_df_strg_adtnl_info` 分别承载不同策略分支的专项配置。机构和用户关系描述谁使用或负责，标签信息描述策略关联的标签，活动关系描述策略对应的活动。

这些对象要沿 `Cam_Strg_Id` 和来源连接。标签表中出现标签号，并不代表所有客户已打上该标签；关系历史中存在活动端点，也不证明活动已执行。策略活动关系的具体分支见[完整案例](00-20260911-认知实验/t07专题-营销/实现详解/01-策略到活动与客群.md)。

触发事件定义与参数 `t07_mio_push_trgr_evt_def`、`t07_mio_push_trgr_evt_para` 描述“出现什么情况可触发”。它们的“事件”是配置对象，不应直接计入 T05 发生事件数。

## 3. 模型定义与产出关系

ART001 → `t07_cam_mdl_info` 保存模型类别、描述、使用建议、更新频率、版本号、生命周期和上线时间；只有更新频率在已读 SQL 中调用了代码转换，不能把所有代码列都叫已标准化。[179997](attachments/02-策略模型与规则/IMG-02-策略模型与规则-20260914110651069.sql)

ART003 的同一源 `A_MODEL_PREDICTION_OUTPUT` 被拆成两个分支：

| 源筛选 | 目标 | 实际保存 |
|---|---|---|
| `MODEL_PREDICTION_OUTPUT_TYPE='1'` | `t07_cam_mdl_lbl_rela_h` | 模型编号 + 标签编号 + 关系有效期 |
| `MODEL_PREDICTION_OUTPUT_TYPE='2'` | `t07_cam_mdl_idx_rela_h` | 模型编号 + 指标编号 + 关系有效期 |

这记录“模型产出哪项标签/指标”，没有保存客户预测分数，也不能据此判断模型准确率。源对象名有“预测产出”并不改变目标表粒度。[179998](attachments/02-策略模型与规则/IMG-02-策略模型与规则-20260914110653304.sql)、[179999](attachments/03-来源职责与交叉矩阵/IMG-03-来源职责与交叉矩阵-20260914110654942.sql)

两段 SQL 关系类型写 `'1'`，本地 CD1522/CD1523 保存 `'01'`。概念含义可以说明，但严格字符等值映射仍是缺口。指标关系表在较新平台目录未命中，旧元数据和 SQL 均可见，本专题保留这一支。
