## 1. 公共活动表如何容纳不同业务

`t07_prom` 保存活动编号、类型、主题/描述、起止、对象、目标、预估费用、预估参与人数和状态。它把多个系统的对象放进同一个公共结构，但很多来源只填其中一部分列。

| 来源分支 | 活动身份与类型 | 具体表达 |
|---|---|---|
| MIO 活动 | `MIO010-` + 活动号，`MIO_ACT` | 名称放 `Prom_Intro`，`Prom_Subj` 留空；起止显式加 8 小时 |
| WOS 直播 | `WOS007-` + 直播号，`WOS_LIVE` | 主题取标题，开始取真实开播，过滤测试用途 |
| WOS 短视频 | `WOS003-` + `_ID`，`WOS_VDO` | 内容是营销承载对象，结束时间可以为空 |
| ECR 拜访 | `ECR047-` + `ROW_ID`，`ECR_VST_ACT` | 对象为拜访客户名称，目标取两级活动目的 |
| PRD 销售活动 | `PRD086-` + 活动号 | 活动类型、状态经转换表处理 |
| RMS 活动 | `RMS011-ACT-` + 对象号，`RMS_ACT` | 会议/调研活动；与服务记录、报名、日程分开 |

证据：[84132](attachments/01-活动内容与销售安排/IMG-01-活动内容与销售安排-20260914110643001.sql)、[88559](attachments/01-对象身份与粒度/IMG-01-对象身份与粒度-20260914110644726.sql)、[88560](attachments/01-活动内容与销售安排/IMG-01-活动内容与销售安排-20260914110647990.sql)、[109333](attachments/01-活动内容与销售安排/IMG-01-活动内容与销售安排-20260914110648041.sql)、[167365](attachments/差异与待核问题/IMG-差异与待核问题-20260914110646888.sql)、[61527](attachments/06-投研内容与活动办理/IMG-06-投研内容与活动办理-20260914110645561.sql)。

读者不能只用 `Prom_Subj` 非空筛选“有名称活动”，也不能把 `Prom_Expe_Prtc_Cnt` 当成实际参加人数。字段为空可能是来源未提供；不是零。

## 2. 为什么还需要专项表

| 对象组 | 表 | 与公共表的互补关系 |
|---|---|---|
| 直播与内容 | `t07_live_act_info`、`t07_shor_vdo_info`、`t07_arti_nws_info`、`t07_chat_rm_prom_info` | 保存主播、内容、播放/访问参数、受众约束和来源专项字段 |
| 数字运营 | `t07_mio_act_adtnl_info` | 保存阶段、执行规则、流程、项目、画像配置和计算时间 |
| 销售活动 | `t07_prd_sale_prom_adtnl_info`、`t07_prd_sctrl_prom_info` | 前者是销售活动说明及奖励附件；后者含限额、次数及失效时间 |
| 赛事与拜访 | `t07_ess_simu_ivst_prom_adtnl_info`、`t07_vst_prom_info` | 前者有报名窗口与主办机构；后者有拜访对象、商机、沟通形式和有效拜访标志 |
| 状态及观察 | `t07_prom_stat_h`、`t07_prom_imp_time_h`、`t07_prom_stati_info_h` | 分别保存状态版本、重要时间值的版本、统计观察值的版本 |

`t07_prom_imp_time_h` 在字段目录中为 INVALID、零解析字段，但本地 168847 的任务 DDL 和加工明确提供报名开始/结束等时间。专题用任务 DDL 补充解释，保留原元数据异常，不宣称线上表没字段。[DDL 补充](attachments/平台分类与范围差异/IMG-平台分类与范围差异-20260914110643037.json)

## 3. 产品范围、指标配置和目标各自回答什么

`t07_prom_prd_info` 保存活动相关产品描述；`t07_prom_prd_rela_info` 保存活动产品关联、源代码、有效窗口及折算比例；`t07_prom_prd_pool_rela_info` 将关联对象换成产品池。不能把产品池一行当作一只产品，也不能从中文名推断产品编号已经统一。

`t07_prd_sale_prom_idx_plac_info` 描述要怎么算：指标类型、统计范围、新老客户规则、复合计算规则、是否匹配活动产品等。`t07_prom_tgt_info` 描述要达到多少，以及目标分配给总部、所有分公司、所有营业部还是指定机构。

174285 把源目标对象 `1/-1/-2` 转成 `HEAD/ALL_DIV/ALL_BRCH`，其他对象补成四位机构编号；`AMOUNT` 原样成为 `Tgt_Val`。值的单位还要由目标类型确认，不全是金额。[目标 SQL](attachments/01-活动内容与销售安排/IMG-01-活动内容与销售安排-20260914110650890.sql)

CD1450 指标类型中的 `2` 是“保有净增”，CD1452 目标类型中的 `2` 是“开户数”。同样的数字跨字段不具备相同含义。[字典](00-20260911-认知实验/t07专题-营销/字典/README.md)

## 4. 活动关系与观察结果

活动可以关联渠道、员工、员工组、内部机构、产品、礼品及另一活动；`t07_prom_rela_h` 不能替代所有这些专门关系表。关系类型决定是“谁负责”“谁参与”还是“归属什么”。

MSA 参与、猜涨跌排名和活动排名，分别落在 `t07_msa_prom_prtc_info`、`t07_msa_guess_rise_fall_prom_rn_info`、`t07_msa_prom_rn`。这些表的 `排名/收益/次数` 来自各自来源字段，不能合并成统一活动效果度量。[逐表字段](attachments/来源与覆盖/IMG-来源与覆盖-20260914110644101.json)

## 5. 新近目录里还有两个容易漏掉的分支

**私募比赛榜单。** `t07_pvt_major_cmpt_act_leadbd_rn_det` 保留榜单编号、类型、参赛组、策略组、机构与产品名称及排名相关字段；238506 来自 BSP 榜单数据，按来源分区写快照。它没有因此自动变成 `t07_prom` 的下级活动，也不能把参赛产品名称当 T02 产品键。[SQL](attachments/01-活动内容与销售安排/IMG-01-活动内容与销售安排-20260914110653094.sql)

**广告投放素材。** `t07_xhs_note_ad_mtrl_info` 用 `UFS009-` + 笔记号作为 `Prom_Id`，保留广告主协议、内容属性、阅读/互动量与比率。242370 在源日期内按 `NOTE_ID` 分组，取 `COLLECT_TIME` 最新的一行；相同采集时间的并列选择未进一步约束。阅读率、互动率是源提供值，没有在该 SQL 中重算分母。[SQL](attachments/00-全貌与范围/IMG-00-全貌与范围-20260914110650039.sql)

这两个对象与销控活动、策略触达名单一起纳入较新目录补充，避免只沿旧字段库形成片面的 T07。
