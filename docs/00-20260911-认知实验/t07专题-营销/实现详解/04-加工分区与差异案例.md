## 2. 当前资料的 I/U/D/S 与历史链不同

当前资料分支会将新快照与已有来源分区做比较：新增 I、变化 U、消失 D、未变 S。随后保留或更新记录，维护删除标志、加载日期和更新时间。

“知道它删除了”不等于“能重建它每一天所有属性”。完整历史要有版本记录和有效区间。与此同时，源快照不完整是否会被视作删除，是依赖源质量与调度完整性的运行风险，本次没有运行数据评估。

历史分支 112265 会先处理当日重跑的版本，再保存闭链记录、新开链及未变记录。不能仅用 `End_Date='2099-12-31'` 回答任意历史日；历史日仍应按左闭右开区间筛选。

## 3. Src_Tbl、Real_Src_Tbl 与源注释

`Src_Tbl` 经常兼任分区隔离标记；`Real_Src_Tbl` 指明实际来源；SQL `FROM/JOIN` 给出本次语句的读取；注释提供作者声明。它们不保证永远相同。

| 案例 | 实际差异 | 解释边界 |
|---|---|---|
| WOS 短视频 88560/88664 | 旧说明为 T_MEDIA，实际 FROM 为 F_TR_MEDIAS | 按真实语句解释；不自动替换既有来源分区 |
| GKS 行为 63002 | 注释带 `_F`，实际读取不带 `_F` | 不靠注释补造读取表 |
| 香港礼品 160663 | 任务名带 GMP014，源表与来源代码为 HCC | 来源系统由正文与配置确认 |
| 商机策略 135322 | 任务名为 MIO032，业务编号前缀为 MIO028 | 编号来自 SELECT，任务名不能替代身份规则 |

## 4. 历史渲染快照与当前实现

195 份候选包含 LOCAL_CODE 142、SQL_MCP 46、HORAE_LOG 7。来源不同，文本完整性也不同。文件头的 `observed_at` 是采集时间；渲染后的 `2026-05-19`、`2026-07-16`、`2026-08-27` 等日期是 SQL 中的具体运行上下文，二者不互换。

SQL_MCP 有些片段把 `--注释` 后的多个表达式压到同一行。普通 SQL 注释规则下，这不是可直接执行的完整程序。本次保存原文、不修写源证据；索引只作为候选，关键投影按人工可见证据解释，完整程序行为仍有缺口。

## 5. 跨表差异应如何保留

PRD084 产品关系与 PRD086 主表的活动编号、CPL001 规则与 CPL012 关系的客群编号、WOS 主表与状态历史的状态域都存在已读差异。它们会影响具体消费，但不能在本次知识整理中偷偷修正为“统一模型”。

对每项差异，专题保留两端证据、会影响什么问题、还缺什么核验。详见[差异与待核问题](00-20260911-认知实验/t07专题-营销/证据/差异与待核问题.md)。
