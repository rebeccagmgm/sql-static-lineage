1. **模型层主题划分**（Wiki pageId `255499828`）
    
    - T01 / PTY = 当事人。
    - 细分到：当事人、个人、当事人评级、当事人名称、TA 信息等。
    - 还明确提到：
        - `busi_date` 常用于历史/快照分区；
        - `src_tbl` 常用于多来源表；
        - 缓慢变化维度采用历史拉链，关键字段是 `begin_date`、`end_date`。
2. **基础模型**（Wiki pageId `214137197`）
    
    T01 主要存放客户、机构客户、管理人、托管人等主体及基本信息，细粒度对象包括：
    
    - 当事人
    - 当事人名称历史
    - 对公客户
    - 当事人鉴别信息历史
    - 当事人地址信息历史
    - 重要联系人历史
    - 重要日期历史
    - 当事人评级历史
    - 当事人状态历史
    - 企业注册信息历史
3. **基础模型命名规范**（本地镜像，pageId `172993522`）
    
    - `T01 = PTY = Party = 当事人`
    - 表名基本结构：主题代码 + 主体名称 + 后缀。
    - 表名大写、下划线分隔；字段采用中心词 + 类型词，如 `Id`、`Name`、`Date`、`Cd` 等。
    - `H` 通常表示历史表，`CD` 表示代码表。
    
    [2.基础模型命名规范-172993522.md](E:/03_resource/wiki-down/大数据研发组/大数据研发组/2.数据治理/制度/大数据研发规范/2.大数据平台库表管理规范/2.基础模型命名规范-172993522.md)
    
4. **码值转换及部分常用表**（Wiki pageId `314632670`）
    
    有比较实用的表级信息：
    
    - `pdata_n.ref_dw_cd_list`：代码组目录；
    - `pdata_n.ref_dw_cd_val`：代码值及描述；
    - `pdata_n.t01_prd_sale_rela_clm`：客户产品销售关系认领；
    - 该表分区字段为 `src_tbl, busi_date`，每天一份快照；
    - T98 客户基本信息宽表是从 T01 相关表加工出来的，但文档特别提醒：如果只需要某条业务线，建议直接使用对应业务线表，T98 汇总表时效性不一定可靠。
5. **模型层常用表**（Wiki pageId `255497706`）
    
    主要覆盖：
    
    - 基础模型和资讯模型的码值转换；
    - `t99_trd_cal_ref`、`t99_rcc_busi_flag_ref` 等常用关联表；
    - T01 客户、当事人、证券账户、产品销售关系等关联对象。
6. **分区血缘元数据模型设计**（本地镜像，pageId `237564702`）
    
    这份对“细粒度”最有价值：

    - 血缘过程有 `operationType`、`recentQueryText`、`version`、`inputs`、`outputs`、`scheduleJobId`；
    - 明确支持表分区级上下游关系，而不是只做表级血缘。
