## 同样按客户和产品组织，记录的事情不同

| 表 | 已见计量字段 | 当前可以怎样理解 |
|---|---|---|
| pdata_n.t98_cust_prd_sale_info | Mtch_Vol、Mtch_Amt、Chrg_Fee | 销售相关数量、金额和费用；本次读到一条真实加工分支 |
| pdata_n.t98_cust_prd_ret_info | Ret_Vol、Ret_Mval | 保有数量与市值；本次核对元数据，未精读生产 SQL |

两表都包含客户、机构、产品等定位字段，元数据均列出 `Src_Tbl + Busi_Date` 分区。它们能服务相近的分析维度，但数量和金额所表达的业务不同。保有量跨日重复出现是可能的，不能未经口径确认就按销售流水一样累加。

## 一支销售加工实际做了什么

任务 66277 的顺序是：

```mermaid

  A[T05证券交割事件] --> B[限定来源、日期与业务标志]
  B --> C[重组产品编号，映射购买类型]
  C --> D[按客户、机构、产品、类型与日期聚合]
  D --> E[用T02产品分类补充属性]
  E --> F[T98客户全产品销售信息]
```

图概括这份 SQL 的处理步骤，未声明全产品销售的完整生产链。

SQL 第 79—86 行限定 `pdata_n.t05_exch_scr_deli_evt` 的一个来源分区及业务标志，并含产品及客户产品组合排除。第 68—74 行对产品编号做拆分重组，将两个业务标志分别映射为 `scrp`、`purch`，并将 `Evt_Type` 固定为 `OTC`。这些都是本分支常量，不能推广成整个字段字典。

第 60—62、87—94 行按客户、机构、产品编号、产品代码、购买类型、事件类型和日期，对数量、金额与费用聚合。随后第 96—108 行按产品代码左连接 T02 分类，限定来源 `PRD` 和分类标准 `PRD01`。如果分类侧同一代码有多行，连接后仍可能展开，本次未用实际数据检查。

证据：[66277.sql](../证据/SQL/66277.sql)，写入第 31 行。本份 SQL 的业务日固定为 **2026-05-18**，不能将它描述成今天正在执行的参数化口径。

## 还不能替读者决定的选择

`t98_cust_prd_sale_info`、`t98_cust_prd_sale_det` 和 `t98_cust_prd_sale_day_det` 都已进入目录。名称与注释相近，不足以证明替代关系、增量关系或同一粒度。真实选型需要并排核对它们的来源、过滤、分区、消费者和使用时点。

这组代表内容解释的是一种加工形态：T98 可能把已有业务记录筛选、分类并重新组织。它没有覆盖全部销售来源，也没有完成保有表的生产核验。
