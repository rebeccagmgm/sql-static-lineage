# 员工与机构：把分散资料整理成可查询的日快照

## 员工表怎样形成

`pdata_n.t98_org_emp_base_info` 的使用入口是员工资料查询。元数据包含员工编号、OA 用户、姓名、状态、机构、联系资料等字段，分区字段为 `Busi_Date`。不能因为“一张表里有很多属性”，就把所有属性都看成员工源表原样提供。

已读任务 61573 的第 253—280 行写入该表，员工编号来自主表，姓名有备用取值，OA 用户的选择还受员工状态影响。第 341—367 行以 `T04_EMP` 为主干，关联鉴别信息和员工状态；鉴别信息按员工分组排序后取一条，状态连接则限定类型与有效区间。

这表明 T98 在这里承担的是**资料选择与拼接**：把不同来源或不同种类的属性放到一个日快照入口。它不以求和为主要目的。`Emp_Id + Busi_Date` 可以作为研究行粒度的候选，但本次没有验证实际唯一性；其他连接仍可能引入多行，`SELECT DISTINCT` 也不等于目标键约束。

证据：[61573.sql](../证据/SQL/61573.sql)，本次重点读取第 253—280、341—381 行，写入位置第 253 行。更完整的 T04 背景见[机构专题](../../t04专题-内部机构/README.md)。

## 机构表不能照抄当前长注释

`pdata_n.t98_org_inr_org_base_info` 的字段是机构编号、名称、类别、状态、地址、上级、分公司归属及财务相关属性。任务 37439 第 71—103 行将这些内容写入日分区；第 131—156 行读取 `T04_INR_ORG` 及名称、状态、地址、联系信息。

当前字段目录的表说明却写成期货客户交叉销售的客户、员工和机构关系。这个说明与字段、SQL 的主体不符。本专题将其标记为疑似错配，按已读证据解释为**内部机构资料宽表**，并保留原说明供复核。

证据：[37439.sql](../证据/SQL/37439.sql)。组合配置还将它声明为分公司、营业部等组合的属性表，详见[组合属性配置](../资料/组合属性配置索引.md)。

## 实际使用时保留什么

员工、OA 用户和机构编号是不同身份；行政机构和柜台机构也可能需要映射。历史资料应按 SQL 规定的有效条件选择，不要给所有连接套用同一个“取最新”规则。要追具体某人的任职或机构变化，应回到 T04 的关系与历史资料，不宜单靠当前 T98 快照重建全部历史。
