## 2. 找到表以后看哪几个字段

先识别**业务对象、观察时间、来源范围、计量值和关系角色**，再决定连接和聚合。

| 线索 | 例子 | 如何使用 |
|---|---|---|
| 业务身份 | Emp_Id、Pty_Id、Agt_Id、Prd_Id、Inr_Org_Id | 找到对象定位字段；同名编号不能自动跨系统相连 |
| 快照或业务日期 | Busi_Date、Stati_Date、Prtt_Mth | 确认日期到底是快照日、统计日还是分区月份 |
| 有效期间 | Strt_Date、End_Date、Stati_Strt_Date、Stati_End_Date | 历史关系有效期与统计期间分别解释 |
| 来源与写入分支 | Src_Tbl、Data_Src_Cd、Grp_Id | 来源码、来源表和并行分组的职责不同 |
| 金额与数量 | Mtch_Amt、Ret_Mval、Dyna_Nom_Prin | 先核对对象、单位、币种、时点和业务筛选，再计算 |
| 归属和分配 | Cust_Mngr_Emp_Id_1、Inr_Org_Id_1、Allo_Prop_1 | 槽位、角色、比例和缺失值都可能影响展开后的粒度 |

这些是读法，不是所有 T98 都具备的公共字段合同。完整字段原说明见[字段 JSON](资料/物理对象与字段.json)；日期列也未必就是分区列。

## 3. 三个容易混淆的选择

**客户销售与客户保有。** 已见销售表包含成交数量、成交金额和费用，保有表包含保有数量、市值。需要解释“今天卖了多少”与“今天还持有多少”时，应分别选表；跨日求和前必须确认观察类型。[代表页](代表表/02-全产品销售与保有.md)

**合约销售基础与管理关系。** 合约的本金、期限等事实，和客户经理、机构、分配比例等归属关系，解决不同问题。只有目标口径要求归属分配时才把它们连接，并检查一份合约事实会被展开成几行。[代表页](代表表/03-场外销售基础附加明细与管理关系.md)

**指标配置与指标结果。** 配置表中的科目、取值列名和指标类型控制如何取数，不能被当作金额结果参与汇总。已读资本中介消费 SQL 就依据配置决定取数量、成本、市值等不同列。[代表页](代表表/04-指标配置与技术统计.md)

## 4. 主库之外的阅读原则

`spdata_n` 和 `pdata_hk` 分别有 88、55 条字段目录记录。它们在本次盘点中保留完整名称、字段及候选任务；没有把同名表复制成同一实体，也没有给整个 schema 套上同一种业务含义。是否是独立业务口径、服务副本或历史版本，需要看该对象自身证据。

只有平台目录、没有字段的资产仍保留入口；只有 SQL 文字、没有目录对象的名称留在证据层。这样可以继续调查，同时避免把不确定名称写成确定业务表。
