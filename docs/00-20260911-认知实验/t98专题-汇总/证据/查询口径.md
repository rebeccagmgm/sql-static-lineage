# 查询口径与复核方法

## 1. 基础选择条件

SQLite位置按[本地导航](../../../local-sqlite-guide.md)定位，打开时使用 `new DatabaseSync(path, { readOnly: true })`。统计及导出在各库只读事务中进行；不同库是各自快照，不宣称跨库同一时点。

```sql
-- 字段元数据目录：表名前缀按字面比较，下划线不是LIKE通配符。
SELECT * FROM tables
WHERE substr(lower(table_name), 1, 4) = 't98_';

-- 每条记录的字段独立查询，不按裸表名拼接。
SELECT name, ordinal, raw_type, comment, is_partition
FROM fields WHERE table_id = ? ORDER BY ordinal;

-- 平台目录：按已有GUID记录保留物理资产，分类另查。
SELECT guid, name, database_name, qualified_name
FROM assets WHERE substr(lower(name), 1, 4) = 't98_';

SELECT path, category FROM observed_classifications
WHERE guid = ? ORDER BY path;

-- SQL候选：排除作为独立证据项保存的目标DDL。
SELECT task_id, evidence_type, direction, depth, payload_text,
       content_sha256, observed_at, imported_at
FROM evidence
WHERE format = 'sql'
  AND evidence_type IN ('hive-task', 'run-script')
  AND instr(lower(payload_text), 't98_') > 0;

-- 组合：属性配置与定义SQL分别保留，不混为一条数据血缘。
SELECT * FROM grp_type_info
WHERE instr(lower(grp_attr_table_name), 't98_') > 0
   OR instr(lower(grp_def_sql), 't98_') > 0;
```

这里展示的是本次固定范围导出条件；普通交互查询请按表名、任务ID或记录ID限定，并使用LIMIT。未再次导入、重建库或采集全平台数据。

## 2. SQL候选的具体匹配

SQL文字先去除反引号，按大小写不敏感的名称模式提取可选schema及 `t98_` 开头的标识；注释、字符串和脚本头不排除。因此索引故意保留检索候选，不宣称完成SQL语法解析。

完整schema.表名进入Q列；未限定表名结合头部 `-- hiveDb:` 提示进入H列；没有这个提示则进入U列。默认库提示不是已核实的物理数据源。相同任务在多个列有命中时，不能直接相加当不同任务数。

所有候选的原定位键、文本哈希和日期均保留在[任务SQL文本候选](任务SQL文本候选.json)。精读代表SQL时，按 `task_id + evidence_type='hive-task' + direction='' + depth=0` 取原文。

## 3. 名称差异、归组和缺失的含义

两个目录的pdata_n范围按规范化schema+表名求交集及差集，不使用名称匹配来合并物理身份。仅SQL名称中，带schema者按完整名称比较；不带schema者只检查裸表名是否在两目录出现。缺少匹配并不证明实际没有表。

主库用途归组有固定优先顺序，并保留人工按名称调整的例外，详见[归组规则](阅读归组规则.json)。它只为浏览提供稳定入口，不能用于自动判定建模层次或系统职责。

`tmp`、`temp`、`test`、`bak`、`mid`、`frnt`及其数字变体仅作表名提示；schema含test、uat或以temp开头仅作位置提示。名称提示之间可能重叠，不能转化成废弃资产数。
