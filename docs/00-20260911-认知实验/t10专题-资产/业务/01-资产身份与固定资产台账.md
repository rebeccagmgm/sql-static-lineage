## 1. 主表回答“这是什么资产”

`pdata_n.t10_ast_info` 接纳资产共性资料；已读 FAM 分支以 `ASSET_TAG_NO` 为 `Ast_Id`，由源 `ASSET_NAME` 给出名称。权属类型固定为 `01`，权属人编号固定为 `GF`。本地 `CD2113` 中 `01` 表示自有，因此该分支表达的是我司自有口径，而不是从源逐条识别七种权属。[236109.sql，48–56 行](../../../attachments/建模基础-身份粒度与时间/IMG-建模基础-身份粒度与时间-20260914110004614.sql)、[权属字典](../字典/README.md)

这也解释了一个看似矛盾的设计：附加表有“租借期限”和“租借使用人”，主表仍写自有。资产的所有权与谁借用、使用多久是两件事；但现有代码固定权属是否适合全部源资产，仍需源数据和业务核验。

主表保留入库时间、使用年限、使用开始时间、锁定原因、折旧标志等字段。当前分支的币种、有效日期、到期日期、资产标签、取得方式均写空字符串。**结构里有字段，不表示当前来源提供了该内容。**

## 2. 类别、类型、属性是不同描述

| 模型字段 | 当前来源加工 | 正确理解 |
|---|---|---|
| `Ast_Cate_Cd` 资产类别 | 优先取非空 `ASSET_SON` 转码；小类为空才取 `ASSET_TYPE` 转码 | 使用不同源字段选择仓库类别；不能直接当源大类 ID |
| `Ast_Type_Cd` 资产类型 | `ASSET_TYPE` 经指定目标字段的转换表映射 | 源字段中文叫“资产类别ID”，目标却是“资产类型”；应按实际映射解释 |
| `Ast_Prop_Cd` 资产属性 | `ASSET_NATURE` 转码 | 仓库属性与源性质值可能采用不同编码 |
| `Ast_Stat_Cd` 资产状态 | `STATUS` 转码 | 主表只保留这一个状态维度，不包括投保和入账两种状态历史 |

这四处转码都使用 `NVL(映射值,源值)` 一类兜底。因此转换未命中时源值仍可能进入模型，不能据字段名断言值域全部标准化。完整解释见[字典](../字典/README.md)。

## 3. 附加表回答“这项固定资产在某日还有哪些经营资料”

`pdata_n.t10_our_fix_ast_adtnl_info` 按 `src_tbl + busi_date` 覆盖当天分区，直接投影同日源台账。它与主表通过 `Ast_Id = Fix_Ast_Id` 在语义上对应同一个固资标签号，但当前 SQL 没有替消费者保证一对一。[236119.sql](../../../attachments/01-资产身份与固定资产台账/IMG-01-资产身份与固定资产台账-20260914110004761.sql)

| 资料组 | 代表字段 | 用途与边界 |
|---|---|---|
| 编号桥接 | `Fix_Ast_Src_Id`、`Fa_Ast_Id`、`Ast_Ref_No` | 保留源内部 ID、FA 编号及参考号；不是三种可互换的主键 |
| 金额与折旧 | `Ori_Val`、`Net_Val`、`Depr_Way`、`Curr_Mth_Depr_Amt`、`Incrs_Depr_Amt` | 原值来自不含税原值，净值与折旧直接来自源，不是本任务计算 |
| 责任与归属 | 员工号、用户号、责任人名、使用部门、成本承担部门及段值 | 保存源快照；关系历史表可能另经身份转换，不能假定字段逐日完全一致 |
| 采购与租借 | 订单号、合同号、PO 号、租借起止 | 可追溯业务背景，未核实 T03 具体键或合同有效状态 |
| 保险 | 需投保标志、保单号、保险起止 | 是否需投保、投保状态和保单期间是不同信息 |
| 处理与接口标志 | BPM 实例、流程发起人、流程标题、信创、推送共享/云管标志 | 标志保留不证明流程完成或接收系统已成功入库 |

当前 DDL 中这些金额及数量相关字段仍有大量 `STRING` 类型，附加表金额列均为字符串。做金额计算前需要转换、处理空字符串并确认单位；不能仅因列注释写“金额”就直接求和。[当前字段手册](../资料/主模型字段手册.md)

## 4. 固定资产与云管的职责怎样交叉

Wiki《固定资产对接需求》（pageId `282687270`）说明：指定设备小类中有 SN 的资产才同步到云管；新增 IT 资产由固资系统提供，云管更新后再回供 SN、责任人、设备状态、位置等信息。它强调的资产标签号、SN、责任人、原值和设备资料，与 T10 保留的多个对象有对应的业务用途。[本次读取的正文](../../../attachments/01-资产身份与固定资产台账/IMG-01-资产身份与固定资产台账-20260914110004793.json)

这份需求解释**为何台账会同时具有财务和运维属性**；它没有证明接口已经按文档运行，也没有证明接口通过 T10 供数。尤其不能看到 `Push_Cloud_Flag` 就把本专题图画成“T10 已投递云管”。

## 5. 读者应能做出的判断

要盘点资产身份，从主表开始；要看某日金额或 FA 号，转到附加表；要回看责任人、类别、状态的变化，进入对应历史表。用原值求总额之前，必须先把其他关系压到与资产快照一致的查询粒度。
