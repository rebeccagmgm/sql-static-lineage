# T06 学习入口：区域、层级与归属

整理日期：2026-09-14。**T06 为业务对象提供区域坐标：一个地方怎样命名、属于哪一级、上级在哪里，以及某种号码怎样对应到区域。** 客户住址、员工联系地址和机构所在地仍由各自主题记录；T06 提供它们可以引用的区域资料。

本专题参照 T01 的对象、身份、时间与真实案例写法，以及 T03 的“先全貌、分维度理解、再交叉”的组织方式。T06 目前已找到的正式模型规模很小，因此按问题深入，不按其他主题的篇幅扩张。

## 本次已经形成的认识

- 正式元数据中的核心对象是 `pdata_n.t06_admin_area`，20 个普通字段加 1 个来源分区字段。表内同时表达省级、地市级和县区级记录。
- RPA 加工只覆盖其指定来源分区。本次正式表首屏实际返回 10 条 `MANUAL` 来源记录，不能把整张表等同 RPA 分区。
- 已读主加工保存更新后的属性与删除标志，没有完整的有效期版本链。下游业务表即使有历史日期，也不自动获得同一历史时点的区域解释。
- 本地检索得到 21 份直接提及行政区域表的任务 SQL：1 个主加工任务、20 个直接读取任务。其中含测试任务、同名任务和内容相同的快照，不能说成 20 套独立业务。
- 手机号归属有 Wiki 定义，也找到 `T06_MOBILE_BEL_AREA` 的注释草稿；本次未找到其正式物理对象或有效生产链。
