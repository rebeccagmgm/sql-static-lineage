# 客户地址标准化：同一目标字段，多种来源规则

[返回入口](00-20260911-认知实验/t06专题-区域/README.md) · [全部读取任务](00-20260911-认知实验/t06专题-区域/证据/直接读取任务对照.md)

这里固定观察 T06 的使用方式，T01 的主体身份模型仍留在原专题。不同来源将文本或源代码写入同名省、市、县区字段时，处理规则并不相同。

## 1. TA5：补齐城市编码，再单独处理直辖市

35133 与 63605 的本地业务 SQL 内容相同。以 [63605](attachments/客户地址标准化/IMG-客户地址标准化-20260914105650269.sql) 第 47–62、114–128 行为例：

- 普通城市：`RPAD(A.C_CITY,6,'0') = E.ADDR_ID`，E 限有效二级区域。
- 特殊分支：按源码前两位寻找有效一级区域，且要求 `PROV_ID=ADDR_ID=CITY_ID`。
- 省份输出：优先 F 的省份，否则 E 的省份，再否则 `999999`。
- 城市输出：优先 F 的城市，否则 E 的城市，再否则补齐的源 `C_CITY`。
- 县区直接沿用 `A.C_COUNTY`，没有通过同一 T06 查询验证。

因此，一个未匹配的城市码仍可能输出成六位字符串；空值和默认码也有不同含义。该分支筛删除与层级，但没有限定来源分区。

任务 233986 使用 `ADRCTY` 而非 `C_CITY`，采用相似逻辑；目录将其标在测试主题，不能与上述正式库任务合并汇报为生产覆盖。[233986](attachments/客户地址标准化/IMG-客户地址标准化-20260914105652300.sql)。

## 2. AMS：按名称片段找省市

[53294](attachments/客户地址标准化/IMG-客户地址标准化-20260914105653179.sql)／[63617](attachments/客户地址标准化/IMG-客户地址标准化-20260914105653582.sql) 生产当事人地址资料；[53337](attachments/客户地址标准化/IMG-客户地址标准化-20260914105653831.sql)／[63155](attachments/客户地址标准化/IMG-客户地址标准化-20260914105653863.sql) 在资管客户模型中使用相近区域映射。

程序从 T06 全名取前两字作为省份，从连字符分割后的第二段取前两字作为城市。城市按省片段与市片段联合匹配，省份另查 `PROV_ID`；区域候选筛 `DEL_FLAG='0'`，没有限定来源或层级。

其成立依赖于全名的分隔格式，以及截短后能唯一指向目标编号。`DISTINCT 省片段,市片段,CITY_ID` 只去掉相同三元组；同名片段若对应多个城市编号，仍能放大业务行。63155 的主体编号桥接另有 STA／TA5／AMS 条件，不能用这一段区域相似性宣称整个任务相同。

## 3. SMP：逐级按名字关联，但父级约束并不完整

[113227](attachments/直接读取任务对照/IMG-直接读取任务对照-20260914105652384.sql) 第 46–88 行把来源中的省、市、区名称分别关联到 RPA 分区的一级、二级、三级记录。区县条件额外要求 `C.ADDR_ID=D.CITY_ID`，未命中写空字符串。

这比单独按区名匹配多了城市约束；不过市名称关联没有同时限定省份，三组区域查询也没有删除标志过滤。源读取表名为 `W_APPLET_PEPC_USERINFOS`，输出 `SRC_TBL` 字面值却是 `W_USERINFOS`，所以来源分区标记与实际读取表也不能机械等同。

该案例说明：业务字段记录名称、算法依据名称做匹配、结果字段看起来是编码，这三步之间各有条件；不能只看最终列名。

## 4. ICR：区域未命中时保留明确兜底码

[63177](attachments/客户地址标准化/IMG-客户地址标准化-20260914105654113.sql) 读取内部评级客户来源，先对同一客户按 ID 排序选一行。省份取前两字匹配有效一级名称，城市匹配有效区域名称，但没有限定城市层级和所属省份。对少数来源地名追加 `☆` 来对齐参考名称。

省市未命中写 `999999`，国家写 `999`。前者是该任务的字段兜底值，后者在 CD010 本地字典中可查到“其他”；它们不能混为同一编码域。[字典边界](00-20260911-认知实验/t06专题-区域/字典/代码与编码边界.md)。

## 5. ECR 受益所有人资料：编码列可能保留原始文字

[173979](attachments/直接读取任务对照/IMG-直接读取任务对照-20260914105653636.sql) 第 103–134 行分别匹配省前两字、去掉“市”字的二级名称、一级名称的城市补充、三级县区名称。匹配候选均筛有效状态并区分层级，但市县未进一步按上级地域约束。

输出为 `NVL(T2.ADDR_ID,PROVINCE)`、`COALESCE(T3.ADDR_ID,T32.ADDR_ID,CITY)`、`NVL(T4.ADDR_ID,COUNTY)`。这意味着字段可能包含标准编号，也可能保留原文本。取这些列与 T06 继续关联时，应先确认取值形态，不能默认它们全部属于 `ADDR_ID`。

## 6. 汇总比较

| 来源案例 | 匹配入口 | 失败后输出 | 主要待核条件 |
|---|---|---|---|
| TA5 | 源城市码补齐、一级特殊分支 | 省 `999999`，市保留补齐值 | 编码有效性、来源内唯一性、县区未标准化 |
| AMS | 省市名称片段 | 以具体目标分支的投影为准 | 名称格式、截短碰撞、跨来源多匹配 |
| SMP | 分层名称全等，区县约束城市 | 空字符串 | 市与省未绑定、未筛删除、RPA 范围 |
| ICR | 省名前两字、市名全等 | `999999` | 市分支未限层级和上级、特殊符号规则 |
| ECR | 名称处理后分层匹配 | 原省市县文本 | 同列混合编码与文字、上级范围缺失 |

这些差异都有 SQL 依据；是否已造成实际漏配、错配或重复，需要按具体业务日期查看数据。本次没有把静态条件差异写成已确认的数据质量事故。
