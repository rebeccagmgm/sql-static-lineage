## 2. 原始行如何变成区域节点

主加工第一组 SELECT 的主要映射如下：

| 目标 | 表达式／规则 | 含义 |
|---|---|---|
| `ADDR_ID` | `REGION_CODE` | 沿用源行政区编号 |
| `ADMIN_AREA_NAME` | `SHORT_REGION_NAME` | 沿用短名称 |
| `ADMIN_AREA_FULL_NAME` | `REGION_NAME` | 保留完整名称串 |
| `PROV_SHOR_NAME` | 全名中文括号之间的字符串 | 依赖源命名格式 |
| `PROV_ID` | 编号前两位 + `0000` | 省级归属 |
| `CITY_ID` | 命中 B 时取 B 编号，否则前四位 + `00` | 普通与特殊层级归属分支 |
| 层级 | 后四位 `0000` → 1；否则后两位 `00` → 2；否则 → 3 | 算法派生的层级分类 |
| 直接上级 | 县区取前四位补 `00`；地市取前两位补 `0000` | 省级原始行没有对应 CASE 分支，结果可为 NULL |

邮编对 `110000/120000/310000/500000/810000/820000` 有固定分支；电话区号对四个直辖市有固定分支。其余沿用源值。固定值是当前证据中的加工规则，不是本文发布的最新邮政或行政标准。

## 3. 一个必须说明的实现假设

B 子查询的注释写“直辖市”，实际条件是 `SUBSTR(REGION_CODE,-4)='0000'`。它没有枚举四个直辖市，也没有额外城市性质字段。因此 SQL 的真实条件是“同日源表出现省级后缀编号”。

如果普通省的省级行也出现在该源分区，相关城市和县区可命中 B，其 `CITY_ID` 会取该省级编号。这是从代码推出的条件性影响，尚未取得同日全量源数据来判定是否实际发生。

这也解释了为什么不能直接把注释中的“直辖市”当作已证明的输入集合。验证时应检查该日源表所有省级编号及其覆盖区域，而不是只检查四个代码是否存在。

## 4. 为什么还有第二组省级行

主加工第二组 SELECT 从地市级源行中按编号前两位分组：对人口和面积求和，用 `ROW_NUMBER` 按区域编号选一行，把编号改成省级编号，名称从全名的省份部分截取，层级写 `1`，市归属、直接上级等写空字符串。

由此得到三个具体限制：

1. 这是“基于所取地市集合补省级行”。人口和面积依赖源集合完整性、可转换性及统计口径，不能从这个 SUM 宣称权威省级统计。
2. `CPTL_NAME` 随所选行取得，程序没有独立核验省会；所选地区的驻地不应直接解释为省级权威驻地。
3. 两组结果使用 `UNION ALL`。若源中本来已有某普通省省级行，又由第二组生成同编号，两组可能形成重复。`SELECT DISTINCT` 对多个字段去重，不保证单编号唯一。

上述都是待数据验证的前提与风险，不是对当前生产数据重复的断言。
