## 1. 三种用法，三种变化

| 用法 | 输入与输出 | 代表实现 |
|---|---|---|
| 标准化 | 业务资料中的文本或源编码 → 区域编号 | TA5、AMS、SMP、ICR、ECR 客户资料 |
| 解释或展示 | 区域编号 → 省市县名称、拼接地址 | 机构地址、员工汇总、分公司信息 |
| 重组 | 一套区域资料 → 满足消费者需要的另一套节点与层级 | `pdata_news_n.tyzx_admin_area` |

三者都可能读取同一张 T06 表，但结果不是同一种“区域映射”。详细任务逐项见[直接读取任务对照](00-20260911-认知实验/t06专题-区域/证据/直接读取任务对照.md)。

## 2. 一条具体主线：客户的城市怎样变成可汇总坐标

TA5 来源先把 `C_CITY` 用 `RPAD(...,6,'0')` 补成六位，再查 T06 的有效二级节点；还单独寻找 `PROV_ID=ADDR_ID=CITY_ID` 的有效一级节点作为直辖市分支。省份未命中时写 `999999`，城市未命中则可能保留补齐的源编码。[63605 SQL](attachments/客户地址标准化/IMG-客户地址标准化-20260914105650269.sql)。

因此，从客户表取到六位 `CITY` 只证明该字段现在是这样的字符串，未必代表已匹配 T06。真正做省市统计，还要知道匹配是否成功、城市所属省份如何确定、兜底值如何处理。`RPAD` 是字符串变换，不负责验证源代码是否有效。

AMS 则用省市名称片段匹配；SMP 使用名称全等并在区县匹配中增加城市编号条件；ECR 受益所有人资料在失败后可以保留原省市县文本。这些路径不能用同一套字段格式假设统一解释。[客户地址标准化](00-20260911-认知实验/t06专题-区域/实现详解/客户地址标准化.md)。

## 3. 关联条件会实实在在改变结果

| 条件 | 影响 | 本次证据中的例子 |
|---|---|---|
| 来源分区 | 是否包含人工补充，以及是否混入其他来源 | 38151／61593 只读 RPA；正式表首屏却是 MANUAL |
| 删除标志 | 是否包含源中已消失但仍保留的记录 | 105420 全表读取；SMP 未筛删除；部分客户路径筛 `0` |
| 层级 | 同名省、市、县是否同时参与匹配 | TA5 分层；ICR 的市名称分支未限层级 |
| 上级区域条件 | 同名地区能否被定位到正确父级 | SMP 区县约束城市，市名称关联本身没有再约束省份 |
| 键与基数 | 一个业务行匹配一行还是多行 | `DISTINCT 名称,编号` 仍可能保留同名异码的多行 |
| 时间 | 用的是哪个时期的区域属性 | 员工历史地址按有效区间选取，区域表仍使用可见版本 |

这些是 SQL 可见的语义差异。本文没有用样例证明某个消费者已经发生行数膨胀或错配；要断言实际影响，还需要目标日期的数据校验。

## 4. 先确认来源范围，再谈“完整区域”

假如需求是按已核对的 RPA 编码解释营业部所在地，可以限定 RPA 分区；假如需求明确包含人工补充区域，就需要把对应来源纳入，并核对不同来源间的编码冲突和取值优先级。

本次没有全量来源清单或优先级规则，因而不提供“所有场景都应该只筛某分区”的通用结论。选定的来源组合内，应检查 `ADDR_ID` 是否唯一；冲突时先保留冲突，不能用任意取第一行隐藏它。
