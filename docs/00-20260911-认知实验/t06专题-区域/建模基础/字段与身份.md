# 字段与身份：一张表里的不同角色

[返回入口](00-20260911-认知实验/t06专题-区域/README.md) · [物理目录](00-20260911-认知实验/t06专题-区域/资料/物理对象目录.md)

## 1. 先确定三个身份层次

物理身份由平台、数据源和完整表名共同确定。正式 `pdata_n.t06_admin_area`、测试库中的同名表、TEMP 中间对象不能相互替代。完整原始身份保留在[元数据 JSON](attachments/物理对象目录/IMG-物理对象目录-20260914105650275.json)及[平台目录 JSON](attachments/00-全貌与范围/IMG-00-全貌与范围-20260914105651214.json)，正文使用业务相关表名。

表内 `SRC_TBL` 区分来源；`ADDR_ID` 定位一个来源中的区域。61790 的新旧比较先限定 RPA 来源，再按 `ADDR_ID` 关联，这是来源内的候选业务键证据。DDL 没有声明主键，`SELECT DISTINCT` 也覆盖多个内容字段，不能证明一个编号只有一行。

因此，暂以 **选定物理表 + 来源范围 + 区域编号** 理解记录身份。需要将多个来源合并时，再检查冲突、来源优先级和有效状态，不假定全局唯一。

## 2. 全部 21 个字段

以下类型在正式元数据中全部为 `string`。字段定义来自元数据，加工说明限定为已读 SIP 分支；人工来源不自动继承其规则。

| 字段 | 定义及角色 | 已读加工或使用要点 |
|---|---|---|
| `ADDR_ID` | 地址编号；本模型用于区域身份 | 原始区域编号或补出的省级编号；不是客户详细地址 ID |
| `ADMIN_AREA_NAME` | 行政区域名称 | 原始短名称；省级补出行由全名截取 |
| `ADMIN_AREA_FULL_NAME` | 行政区域全称 | 源样例包含省简称括号与连字符，部分消费者据此拆分 |
| `PROV_SHOR_NAME` | 所属省份简称 | 从全名的中文括号中截取；没有括号时的结果需结合来源检查 |
| `PROV_ID` | 所在省份 | SIP 分支按编号前两位补四个零；归属属性 |
| `CITY_ID` | 所在地市 | 普通分支按前四位补零，另一分支按命中省级源行取值 |
| `ZIP_CODE` | 邮编 | 保留前导零及来源长度；主加工有部分代码的固定值分支 |
| `AREA_CD` | 电话区号 | 主加工从 `DIVISION_CODE` 或四个直辖市固定值取得；不是行政区划编号 |
| `ADMIN_AREA_LVL_CD` | 行政区域层级代码 | SIP 按编码后缀派生 `1/2/3`；未找到独立字段代码域定义 |
| `UPPER_ADDR_ID` | 上级行政区域编号 | 直接上级候选，不能假定父节点一定存在 |
| `CPTL_NAME` | 驻地 | 源驻地资料；省级汇总分支取所选地市行，不等于独立核验的省会名录 |
| `POPU` | 人口，注释单位为万人 | 字符串；补省级行对地市来源值求和，不能作为当前人口统计 |
| `AREA_SIZE` | 面积，注释单位为平方千米 | 字符串；补省级行有求和逻辑 |
| `DEL_FLAG` | 删除标志 | 已读算法中 `0` 为保留／恢复，`1` 为新源中缺失 |
| `DEL_DATE` | 删除日期 | 首次转入删除分支填写；持续删除时沿用旧值 |
| `DATA_SRC_CD` | 数据来源代码 | 主加工固定 SIP；人工样例为空，不能要求必有 |
| `TASK_NAME` | 任务名 | 加工标记；人工样例也记录主任务名，不能独立证明写入者 |
| `DATA_ETL_DATE` | 数据加载日期 | I 分支为本次逻辑日期；U 分支沿用旧值 |
| `DATA_UPT_DATE` | 数据更新日期 | 变更或首次标删时更新；部分恢复路径不更新 |
| `DATA_TIME` | 数据时间 | 主加工使用任务时间参数；不是行政区法定生效时间 |
| `SRC_TBL` | 来源分区字段 | RPA 完整源表名与 MANUAL 样例已见；全部来源枚举尚未完成 |

表结构没有 `BUSI_DATE` 分区，也没有开始／结束有效期字段。不能因其他模型采用“来源+日期分区”就套用到本表。[61790 DDL 与加工](attachments/01-区域对象与层级/IMG-01-区域对象与层级-20260914105651381.sql)。

## 3. 常见同名误解

- `ADDR_ID` 在这里指区域节点；`HOME_ADDR` 等字段在 T01 中可以是自由文本联系地址。
- `AREA_CD` 在本表是电话区号；代码域 CD583 的同名英文属性是业务区域代码，不能直接绑定。
- `DATA_SRC_CD` 是系统代码，`SRC_TBL` 是分区来源标识，元数据中的 `source` 则是采集来源。三个字段分别记录不同事实。
- 层级 `2` 是模型值；不能仅凭地名以“市”或“县”结尾重新给它定层级。

## 4. 关联键的最小检查

按编码关联前，要检查所选来源范围内 `(SRC_TBL, ADDR_ID)` 的有效记录重复；跨来源还要检查同编号是否有不同名称、层级或上级。按名称关联前，应在具体层级和父级范围检查名称到编号是否唯一。

本次没有执行这些全量业务数据检查，因此不会把候选键表述成已证明的唯一键。质量任务“主键唯一性检查”在目录中存在，执行结果、实际检查列及覆盖日期尚未取得。[质量任务证据](attachments/字段与身份/IMG-字段与身份-20260914105652092.json)。
