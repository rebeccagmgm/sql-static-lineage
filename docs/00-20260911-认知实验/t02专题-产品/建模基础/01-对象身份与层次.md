# 对象、身份与层次：先确定这一行是谁的什么记录

[返回入口](../README.md)

## 1. 对象类型和描述方式分开看

“基金”是一种业务对象，“名称”是属性，“管理人”是参与角色，“净值”是一个时点的观察，“公告”是文档。它们可以围绕同一只基金出现，却不能放进一列统一的“产品类型”。

| 表达层次 | 代表对象或表 | 一行的解释 |
|---|---|---|
| 身份 | `T02_SCR_BASE_INFO`、`T02_CO_BASE_INFO` | 某来源口径下的一只证券或一家企业 |
| 品种/业务专档 | 股票、基金、债券、期货、产品中心、托管专档 | 对某类工具或某种业务安排的专门描述 |
| 双端关系 | `T02_SCR_RELA`、`T02_IDX_COMPNT_INFO`、`T02_TIT_PRD_ASSET_INFO` | 两端对象之间的一种关联，可能另带类型和期间 |
| 分类 | `T02_SCR_TYPE` | 某来源按某分类标准给对象的结果 |
| 时点/期间事实 | 行情、净值、股东资料、财报 | 对象在某时间、口径和来源下的观察或披露 |
| 文档与版本 | 公告、研报、附件 | 一份文档或版本，可能涉及多个业务对象 |
| 消费表达 | `NEWS_SECU` 等组合类型 | 下游怎样把对象作为指标的一维，并选出成员与显示名 |

“产品中心档案”和“指标产品维”不是两个新增的现实产品。前者是某种业务档案，后者是消费层表达。把它们混称为三类业务对象，会遮住实际对应关系。

## 2. 五种编号各自承担什么

| 编号 | 已见用途 | 定位时需要什么 |
|---|---|---|
| `secu_id` | 证券主档身份；某些遗留表也把合约身份放进此列 | 表、来源和生产公式，不能只看列名 |
| `src_sys_prdno` / `in_code` | 追到源编号或源内码，常用于专档连接主档 | 来源标签、实际构造方法；WD 常用 Wind code 对 `in_code`，TIT 用工具内码 |
| `scr_cd` + `mkt_cd` | 交易代码及其市场语境 | 品种、市场及来源；不得仅以简称认定同一物 |
| `corp_id` / `src_corp_id` | 企业模型身份与源企业编号 | 企业来源；不天然等于 T01 的当事人编号 |
| `prd_id` / `grp_val` | TIT 内部产品号 / 指标组合成员值 | 所属产品表 / `grp_type_code` 的定义 SQL |

`secu_id` 不是一个可脱离表解释的万能主键。例如两融分支用合约号生成 `secu_id`，用股票信息生成 `tgt_secu_id`；TIT 内部产品用 `prd_id`，其挂钩工具另有 `undrl_secu_id`。这两例都是模型真实表达，不是命名理论。[两融与基金](../业务专题/02-基金销售托管与两融.md)、[TIT/OIS](../业务专题/04-期货期权与TIT及OIS产品.md)

上表以资讯分支为中心。港股产品使用另一套 `Prd_Id` 与 `Data_Src_Cd`，资管偿付使用 `sk_f_bmpk_id`；前缀都为 T02 也不能直接判等。具体构造见 [跨库模型与编码](../业务专题/10-跨库产品模型与编码差异.md)。

## 3. 同一现实对象与同一模型编号不是同一个判断

PRD 主档调用编号函数；WD 主档先拼候选编号，再查替换表；TIT 主档按源工具信息构造候选编号，也查替换表。XLA 之后按已有 `secu_id` 选来源。它们是不同步骤。

因此两条记录同名，只能提示值得比对；跨来源编号相同，也应检查构造和使用范围。XLA 的排序能处理“已有同一编号的多来源候选”，不会自动识别所有“编号不同但现实相同”的对象。[编号详解](../实现详解/01-证券身份与XLA加工.md)

## 4. 为什么表会拆开，又为什么不能把每张表都当新对象

一只基金的代码改变，不代表管理公司改变；销售下架不代表市场停牌；净值更新不代表基金重新成立。独立变化的资料需要各自的时间和口径。

但 `_ext` 扩展表可能只是增加属性，`_tmp` 可能只是中间处理，`_p`/`_pb` 可能保存批次，历史后缀也可能采用不同机制。先看字段和写入，再确定是否增加了业务对象。`T02_SCR_BASE_INFO`、其 WD 临时表和 XLA 来源分区不是三只证券。

## 5. 学会判断连接后的行数

教学例子：证券 S 有两条分类、三个交易日行情、两份公告。若只按 S 连接三张明细，最多会得到 2×3×2=12 个组合。新增的是关联组合，不是 12 只证券，也不是 12 笔交易。

正确做法取决于问题：做行情列表，就先固定分类标准，并将公告作为独立明细或先聚合；统计公告数，就先按文档身份和版本定义计数。没有脱离业务粒度的统一“去重字段”。

进一步选择时间见 [时间与连接](02-时间与连接.md)。
