# 时间与连接：把同一对象的哪份资料放在一起

[返回入口](../README.md)

## 1. 一个日期不能回答所有时间问题

| 时间 | 问的是 | 已见实现 |
|---|---|---|
| 观察日 | 这个价格、净值或利率属于哪天 | 行情 `trd_dt`；净值从 `PRICE_DATE` 投影到 `trd_dt` |
| 报告期 | 这份财务信息描述哪个期间或期末 | 财报 `end_date` 来自 `report_period` |
| 公告/披露日 | 这份信息什么时候发布 | 财报 `pub_dt`、利润表 `actual_ann_date`；公告 `ann_date` |
| 业务分区 | 本次写入维护哪块数据 | 行情/净值 `_H` 的 `busi_date` 分区 |
| 有效区间 | 关系在何时成立 | 证券关系 `valid_date/end_date`，指数成分 `indate/outdate` |
| 记录处理时间 | 源或仓库何时修改、落地 | `rec_upd_time/rec_down_time`，不同任务取源时间或执行时间 |

例如六月末财报八月才公布。查询六月末经营状况与回测六月末当时可知信息，使用的是两个问题；后者必须增加披露时间约束。读取了当日仓库分区，也不代表那天已能获知其中全部历史财务记录。

## 2. 分区方式决定读取范围，不能代替业务时间

主档通常按 `src_id` 覆盖，`busi_date` 是普通列。当前主档有日期列，并不意味着每天的旧版本都还在。

已读日行情 `_H` 按业务日、来源、组别写入，并筛当日交易日期；`_S` 按来源、组别覆盖，却同样读取日终价格，而且该 SELECT 没有相同的交易日限制。净值则在一次执行中写当日和回补多个历史交易日。三者分别解释见 [历史回补](../实现详解/02-行情净值与历史回补.md)。

财报主表按来源与组别覆盖。`busi_date` 是本次处理日期，报告期可以是更早年份。查询历史报告期不能机械地加“业务分区等于报告期”。

## 3. 已有连接模式怎样选择

| 目的 | 已读连接 | 需要检查的结果 |
|---|---|---|
| WD 行情补证券身份 | 行情 Wind code → WD 主档 `in_code`，LEFT JOIN | 主档缺失时行情仍可保留，`secu_id` 为空；主档多行可能放大行情 |
| WD 净值补证券身份 | 净值 Wind code → WD 主档 `in_code`，INNER JOIN | 缺身份的源净值不会进入该结果 |
| TIT 期货补身份 | `key_instrument_id` → TIT 主档 `in_code`，再筛编号非空 | 虽写 LEFT JOIN，最终效果仍排除未匹配身份的期货 |
| OIS 凭证补身份 | `prd_no` → OTC 主档 `scr_cd` | 允许不同来源标签，但必须遵循该任务约定 |
| 证券关系解析两端 | 两个源代码分别连接同一来源主档 | 两端可能各缺失或各多行，不能自动成为已确认一对一映射 |
| 指标成员取名称 | `NEWS_SECU` 定义先选来源，再按编号排序取行 | 名称选择不等于实体解析，也不表示各来源属性已一致 |

来源、编号、时间、关系类型共同定义一次连接。没有“所有表都加同样三个条件”这种通用答案。

## 4. 有效区间不能只看字段名

证券关系保留源生效与失效日期，指数成分保留进入与退出日期。本轮 SQL 没有给出这些源区间是否右端包含的统一规范，因此不能直接套用 T01 某分支的左闭右开规则。确认源定义后再选择 `<=` 或 `<`，并处理空结束日期。

股东资料的 `end_date` 是持股报告截止日，不是证券关系的失效日；财报的 `end_date` 又是报告期末。同一英文列名必须结合对象解释。

## 5. 一个可推理的取数顺序

先明确结果的一行：例如“某只基金的某个净值日期、选定来源的一条单位净值”。据此选择净值事实，再决定如何补名称、基金份额和管理人。若还要展示该基金当时的销售状态，需要历史销售记录或已验证的历史重建路径，不能直接拿当前产品中心状态充当历史状态。

最后检查未匹配记录、每一步行数和是否需要先聚合。静态 SQL 可以解释这些风险出现在哪里，实际漏数和重复规模仍需运行数据核验。
