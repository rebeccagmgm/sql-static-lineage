# 平台分类与业务范围：两种导航怎样对照

[返回入口](README.md) · [全貌](00-全貌与阅读方法.md)

平台分类回答资产被放在哪里；本专题的业务结构回答记录描述什么。两种导航可以相互定位，不能互相替代。

## 1. 设计名称与物理落地并存

本次读取的 Wiki《新模型框架》（203509209）同时列出通用主题的T02／产品和资讯库的T02／资讯。本地元数据则存在证券、产品、企业、财报、公告、市场与宏观等对象。正文按实际对象解释，不将某个前缀直接等同于产品中心。

## 2. 原平台分类如何进入新版

以下路径来自2026-09-12调查底稿 `_survey-part1.json` 的已观测分类，不是本轮重新抓取的全量平台目录。

| 平台内容方向 | 新版阅读位置 |
|---|---|
| 基础代码／证券代码、企业代码 | 证券身份、企业身份与常量转换 |
| 基本信息／股票、基金、债券、期货期权 | 各业务专档，以及其源对象结构 |
| 基本信息／其他金融产品 | 销售、托管、TIT/OIS内部产品等，逐对象分辨 |
| 行情交易／日行情、产品净值、利率汇率 | 观察值及其日期、单位、价格口径 |
| 公司治理、股本股东、工商企业 | 企业关系、期间资料和事件 |
| 财务数据 | 企业财报、报表类型与分析指标 |
| 综合资讯／研报、公告、预测 | 文档、版本、对象关联与可得时间 |

早期底稿中公共证券主档实际挂基础代码／证券代码，企业主档挂基础代码／企业代码；不能笼统写成“所有主档都在基本信息”。一表多标签也不是多张业务表。

## 3. 跨库与临时表怎样处理

本地T02前缀对象包含资讯模型、香港、受限模型、资管、集市和其他物理来源，还存在扩展、历史、批次、临时及未解析记录。正文以资讯模型的主要业务范围为中心，目录保留跨库身份；同名跨来源不合并字段说明。

`pdata_n` 中本次范围仅见三条T02前缀元数据记录，与大量资讯库对象不是同一数量口径。原平台GUID数与本地元数据记录数也不能相加。统计条件、快照及范围见 [证据与覆盖](证据/覆盖与证据.md)，具体对象见 [逐表目录](资料/物理对象目录.md)。
