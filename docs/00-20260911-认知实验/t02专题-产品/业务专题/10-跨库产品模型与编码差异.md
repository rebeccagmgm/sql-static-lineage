# 跨库产品模型：同是 T02，身份与时间约定也会不同

[返回入口](../README.md) · [对象身份](../建模基础/01-对象身份与层次.md) · [来源矩阵](../来源与职责/交叉矩阵.md)

## 1. 先辨认模型体系，再连接产品

前面主要分支以 `pdata_news_n` 为中心。它的证券主档、来源分区和企业模型解释了大量资讯对象，但本地 T02 还分布在港股、资管和通用模型等库。**主题号相同，不保证主键、来源字段、有效期或码值相同。**

| 已读体系 | 保存什么 | 代表身份或时间 | 已读输入与加工 |
|---|---|---|---|
| 资讯模型 `pdata_news_n` | 证券、企业、市场观察及业务专档 | 常见 `secu_id`、`src_id`、`grp_id`，具体按表解释 | 多来源构造、映射身份，XLA 和下游再选择 |
| 港股模型 `pdata_hk` | 产品主档、基金/债券/note 专档、名称与评级等历史 | `Prd_Id`、`Data_Src_Cd`；名称历史另有 `Name_Type_Cd` 和起止日期 | GMP 产品按类型构造编号；名称变化关闭旧区间并建立新区间 |
| 通用模型 `pdata_n` 的因子分支 | 股票某交易日的风格、行业因子暴露 | `secu_id`、`stk_cd`、`trd_dt`、来源与分组 | TL 因子值接资讯股票主档，保留源因子值 |
| 资管模型 `pdata_ams` 的偿付分支 | 债券付息与兑付资料 | `sk_f_bmpk_id`、公告/登记/除息/付息日期、日期分区 | Wind 资料经市场与币种转换，另造资管编码 |

这是已读代表实现的比较，不是各库全量合同。尤其不能将港股 `Prd_Id`、资管债券市场编码与资讯 `secu_id` 直接判等；跨体系映射尚需单独证据。

## 2. 港股：产品主档和名称历史承担不同职责

### 产品主档回答“现在保留哪份产品资料”

[任务77510](../证据/SQL/77510.sql) 读取 GMP 的基金、债券、note 和 model portfolios。基金候选号为 `m-` 加 ISIN，债券为 `b-` 加 ISIN，note 使用内部代码，model portfolio 为 `D00-` 加代码。它们写入同一个产品主档结构，却保留各自的类型、市场和原编码。

其中基金、债券分支会排除已经存在于 HKDC 来源、相应市场和相同 ISIN 的候选；币种等属性通过 `T99_CD_CVT_MAP` 转换。因而“源系统里有这个 ISIN”还不足以推出“GMP 主档一定有一条”。

任务将新候选与旧 GMP 主档按 `Prd_Id` 做全外连接，分成新增 I、源中消失 D、属性变化 UP 和不变 S。新增/变化取新资料，D 分支保留旧属性并写 `Del_Flag='1'`。这里的删除标记反映这一加工的源记录变化，不能直接解释成产品到期、法律终止或客户持仓清零。

### 名称历史回答“某天应使用哪个名称”

[任务77545](../证据/SQL/77545.sql) 以 model portfolios 为样本，`Prd_Id='D00-'+code`，名称类型为 `19`，来源为 GMP。它按“产品号＋名称类型”比较新名称与当天有效旧记录。

已读判断条件为 `Strt_Date <= d AND End_Date > d`，即左闭右开的有效区间。名称改变时，旧记录结束日设为 d，新记录开始日设为 d；源中消失则关闭旧区间。这与主档的删除标记是两种时间表达。

教学例子：若产品在 6 月 10 日改名，当天查询命中新名称；旧名称的结束日虽是 6 月 10 日，当天已不再有效。不能使用两端都包含的条件，否则交界日可能命中两条。该区间规则来自这条名称任务，不扩展为全部 `_H` 表的约定。

两个任务保存的是不同固定日期的静态脚本：77510 为 2026-05-22，77545 为 2026-05-21。本版解释其加工方法，没有把这两份快照拼成同日完整产品状态。

## 3. 因子暴露：使用证券身份，却不是另一份产品主档

[任务203243](../证据/SQL/203243.sql) 从 `q_dy1d_exposure` 读取交易日期、股票代码，以及 BETA、动量、市值、盈利等风格因子和行业因子；结果写 `pdata_n.t02_stk_fctr_expo_sw` 的 TL／01 分区。

它按 `a.ticker_symbol = b.scr_cd` 左连资讯股票专档，右侧限定 TL／01 和 SSE、SZSE、BSE，取得 `secu_id` 与源系统产品号。这说明通用模型可以消费资讯模型的身份成果，不能只按库名画成彼此独立的两套链。

这里也有清晰边界：左连接可能保留未匹配身份的源行；连接没有进一步按源市场列判等，如果右侧同一代码多行，仍需检查基数。正文没有实际样本来宣布该键唯一。

因子值用于描述某日股票在对应因子定义下的特征，不是持仓金额，也不是收益率本身。解释某个暴露值的标准化方式、样本空间和可比性，还要取得厂商模型定义；这条投影 SQL 没有给出这些算法。

## 4. 资管偿付：日期、单位和编码都需要重新确认

[任务107580](../证据/SQL/107580.sql) 从 Wind 债券偿付资料出发，内连证券代码对照，再左连资管的市场和币种转换。目标是 `pdata_ams.t02_bond_payment`，不是资讯证券主档。

它构造 `sk_f_bmpk_id = 'BMKT' + 市场转换码 + 债券交易代码`；市场未转换时用 `000`。因此这列不能与 `secu_id` 直接连接，也不能把 `000` 当成已识别市场。`sk_primary_key` 使用无排序的 `row_number()`，不能据此假定跨次运行稳定。

表中分别保存公告日、债权登记日、除息日、付息日，以及每手付息数、每手兑付本金数、税后金额和每百元赎回净价。把不同单位直接相加，或把公告日当成资金实际入账日，都会改变含义。已读 SQL 投影厂商资料，没有客户账户与实际入账流水，故不能证明某客户收到了款。

脚本写固定日期分区 2026-05-18，但源查询没有据此限定所有偿付日期为当天。日期分区在这里也不能代替业务付息日筛选。

## 5. 跨库查证时，解析成功还不够

本次发现，元数据缓存中的港股 `t02_prd` 字段为组合检查形态，`t02_prd_name_h` 等对象仅列 `check_result`，与上述有效写入列明显不一致，尽管解析状态是 PARSED。因此本节主档与名称历史解释以所链接的写入 SQL 为依据，原元数据仅保留作差异证据。

港股基金、债券、note 和评级历史等代表对象则有相应字段快照，可用于认识专档范围，但本版没有将其生产逐条核完。详见 [覆盖与证据](../证据/覆盖与证据.md)。

跨库取数应先确定完整物理对象，再核对实际字段与写入、身份和来源约定、业务时间与单位，最后才决定连接。统一主题目录帮助找到对象，不能替代这些确认。
