# 证券身份与股票专档：一只工具怎样找到自己的资料

[返回入口](../README.md) · [编号加工](../实现详解/01-证券身份与XLA加工.md)

## 1. 先有公共坐标，再谈品种属性

股票、债券、基金份额和期货都需要代码、市场、名称、币种等公共资料。`T02_SCR_BASE_INFO` 提供这层坐标，便于行情、分类、关系和文档用相应来源的编号找到工具。

股票还需要上市日期、上市板块、上市状态、退市日期等专属信息，因此另有 `T02_STK_BASE_INFO`。企业则是发行方，保存于 `T02_CO_BASE_INFO`。同一家企业发行多只证券时，企业资料无需复制成多个企业身份。

| 模型 | 一行主要描述 | 连接时保留什么 |
|---|---|---|
| 证券公共主档 | 某来源下的一只工具的公共资料 | `secu_id`、源内码、证券代码、市场、来源 |
| 股票专档 | 一只股票的上市与品种属性 | 证券身份、来源、必要的组别 |
| 企业主档 | 发行企业或其他企业的资讯资料 | `corp_id`、源企业号、来源 |
| 股票发行事项 | 一次发行相关的信息与明细 | 发行对象、日期、承销/募资等子记录，不能用主档行数代替 |

## 2. 一条实际股票专档生产路径

66002 读取 `odata_n_uip.w_asharedescription`，以源 `s_info_windcode` 连接 WD 主档 `in_code`，得到统一证券编号、源编号及企业号；将上市、退市日期和板块等投影到股票专档，写 WD／grp01。

板块处理既有 CASE：如主板的明确赋值，也有 `var00005` 常量转换。脚本还排除一只同时出现在 A股与 CDR 来源中的证券。由此可见，专档是有来源选择、身份补充和分类转换的模型结果。[66002，53—117行](../证据/SQL/66002.sql)

该连接是 LEFT JOIN。源股票存在而主档没匹配到时，专档的统一编号可能为空；主档若有多条匹配，又可能扩大专档行数。静态脚本展示了机制，实际异常数量没有在本次核验。

## 3. 证券如何找到企业

WD 公共主档并不是把证券代码当企业号。59493 先用源证券记录的公司编码，连接 WD 企业主档 `src_corp_id`，取其 `corp_id`。股票专档随后沿证券主档取得企业身份。

企业主档自身又有编号处理：59471 优先使用非空注册号，否则保留源公司号。因此企业关系需要遵循同来源的映射路径，不能把任意来源 `corp_id` 直接与 T01 当事人号连接。[企业专题](05-企业股东与治理关系.md)

## 4. 发行事项为什么不是股票主档的一组宽列

股票主档可以告诉我们证券是什么；发行信息还包括发行方式、时间、主承销和资金用途等。一个发行对象可能关联多个承销或用途明细，展开后行数的增加来自事项细分。

本地消费案例 105135 从 WD 的 `T02_STK_ISS` 取得发行资料，并组合主承销、资金用途信息。它证明某种发行分析需要事项表与明细，而不能只读股票简称。该任务是消费证据，本版不据此宣称已核验发行表的完整生产及主键唯一性。[105135](../证据/SQL/105135.sql)

## 5. 带着业务问题选入口

查“这只代码叫什么”，先查公共主档及来源；查“何时在哪个板块上市”，进入股票专档；查“发行企业经营怎么样”，沿企业身份进入财报；查“这次发行募集资金做什么”，进入发行事项及用途明细。

来源的“当前状态”也需要区分：产品中心投影的主档状态与股票市场上市状态并非天然同义。证券存续、当日停牌和是否在某业务渠道可交易，应分别核对。
