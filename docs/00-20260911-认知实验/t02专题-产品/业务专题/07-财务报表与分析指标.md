## 1. 企业身份只回答了第一个问题

财务信息还要说明报告期、报表范围、期间口径、披露时间、币种和版本。资产负债表描述期末状况，利润和现金流信息描述期间发生；相同的截止日期不能让这些数值自然互换。

本地模型入口包括 `T02_CO_BAL_SHT`、`T02_CO_INCOME`、`T02_CO_CASH_FLOW` 及财务指标、专用行业指标和扩展表。此处精读 WD 资产负债表与利润表两条生产，现金流和全部派生指标保留结构入口。

## 2. WD 财报如何找企业并保留时间

69799 从当日采集的 `w_asharebalancesheet` 读取各报告期数据；69798 对 `w_ashareincome` 作对应处理。两者用源 Wind code 连接 WD 证券主档 `in_code`，从主档取得 `corp_id`，同时保留源公司号。

| 目标表达 | 源字段/规则 | 影响 |
|---|---|---|
| `corp_id` | 证券主档的企业号 | 财务归属企业，但身份通过证券代码桥接 |
| `pub_dt` | `ann_dt` 转为日期 | 公告时点不能用报告期替代 |
| `end_date` | `report_period` | 财务数据描述的截止日 |
| `rpt_type` | 报告期月日结合 `statement_type` 派生 | 同一截止日不只一种期间口径 |
| `data_flag` | `statement_type` 经 `inf00010` 常量转换 | 报表类型仍需要具体码值解释 |
| `busi_date` | 当前处理日普通列 | 不等于报告期；目标按 WD／grp001 覆盖 |

## 3. 同一个六月末，为什么可能出现不同报告期代码

两条 SQL 对 `REPORT_PERIOD` 的末四位作 CASE。0331 写1；0630 根据源报表类型是否属于指定集合写2或6；0930写3或9；1231写4或12。它们反映同一截止日还要区分期间口径。

本版保留这组实际转换，不在没有读取 `inf00010` 全部实值及源类型规范时，擅自把每个数字命名为“合并”“母公司”“累计”或“单季”。读者至少应知道：**按企业和六月末直接取第一行，会丢掉一个真实存在的口径维度。**

教学例子：上半年累计收入120、第一季度50，只有在报表范围、币种、会计口径和版本一致时，才可能用差值得到第二季度70。若把另一份单季报告再相减，就会重复调整。这个算术例子说明需要哪些条件，不是对当前代码2/6含义的认定。

## 4. 同一财务列还可能随时期改变取值

69798 的营业总成本在报告期不早于2019年时取 `tot_oper_cost2`，更早时取 `tot_oper_cost`。部分费用又按公司类型作条件取值；利润表另保留 `actual_ann_date`，并把原始 `STATEMENT_TYPE` 放入备注。

这意味着查询“历年营业成本”不能只看模型列名，就断言它在全部时期来自同一个源字段。生产规则解释了模型试图如何保持可用口径，是否满足具体分析的可比性还需业务核对。[69798，216、233、281—282行](../证据/SQL/69798-hive-task.sql)

## 5. 公告时间与回测可得性

查企业截至六月末的状况，可以按六月末报告期找后来披露的报告；重建六月末当时能知道什么，必须排除后来才公开的信息，并明确更正版本如何处理。

当前主表按来源/组别覆盖，未由该结构证明保留了每次观测版本。因此不能仅使用当前表的历史报告期记录，就声称完成了无未来信息的历史回测。需要数据版本或可得时间证据。

## 6. 财务指标是在报表口径上再计算一层

财务比率、盈利预测、行业专用指标可以共享企业坐标，却可能使用不同分子分母、期间或预测时间。本地目录保存相应入口，但本版没有逐一复算。

取数应先固定报表身份、范围、时间和单位，再理解指标公式。把多来源、多报表类型、多个公告版本按 `corp_id` 汇成一个平均值，不会自动形成“公司真实财务”。
