# 期货期权与 TIT/OIS 产品：工具、产品和交易约定怎样分层

[返回入口](../README.md)

## 1. 先把四种“合约/产品”拆开

| 对象 | 需要回答的问题 | 本地模型入口 |
|---|---|---|
| 市场工具/标准合约 | 哪个交易代码、到期月、乘数、行权价或标的 | 证券主档、`T02_FUT_BASE_INFO`、`T02_OPT_BASE_INFO_TIT` |
| 内部发行产品 | 发行了什么、规模多少、哪本账簿管理 | `T02_TIT_PRD_INFO`、`T02_TIT_NOTE_INFO` |
| 产品资产关系 | 某个产品涉及哪些工具及内部交易标识 | `T02_TIT_PRD_ASSET_INFO` |
| 客户具体交易约定 | 谁与谁做了哪笔交易、持有多少、怎样结算 | 主要回到 T03/T05 对应交易与事件模型 |

同一种期货可以被许多账户交易；同一个内部产品又可以关联多项工具。标准合约资料的一行不是客户的一笔成交，内部产品号也不是每张表共用的证券号。

## 2. TIT 先提供工具公共身份

103232 从 `odata_n_tit.d_ref_instrument` 建证券主档：源工具内码保留在 `in_code`，类型与市场被投影为公共表达，候选编号经过替换表后写入 TIT 分区。专档随后用 `key_instrument_id` 去连接这份主档。[身份详解](../实现详解/01-证券身份与XLA加工.md)

### 期货：乘数、到期与标的各有列

105612 从 `d_ref_future_properties` 投影标准合约代码、最后交易日、交割日期、合约乘数、上市日、交易所、价格限制和标的内码。期货类型通过 TIT 常量 `var00001` 转换。

`UNDERLYING_INS_ID` 写到 `undrl_scr_cd`，`undrl_secu_id` 却写空。这说明标的源内码被保留，尚不能把该行当作“标的统一编号已解析完成”。主工具身份 LEFT JOIN 后又筛 `b.secu_id is not null`，未匹配主档的期货被排除。[105612，73—125行](../证据/SQL/105612.sql)

### 场内期权：自己的工具号与标的号分开

176204 从 `r_ref_listed_option_props` 读自己的 `key_instrument_id` 与 `underlying_ins_id`，分别保留到 `scr_in_code`、`undrl_scr_in_code`；通过自己的工具内码接主档取得 `secu_id`。合约单位、认购认沽类型、行权价、到期、最后交易日、结算价及调整标志分别投影。

此任务没有像上述期货任务一样在 JOIN 后过滤主档编号非空。两份专档的缺身份保留方式不同，不能套用“所有专档都只收录已解析工具”。[176204，63—108行](../证据/SQL/176204.sql)

## 3. 内部产品是另一层管理对象

160750 从 `p_prd_product` 读 `key_prod_id` 作为 `prd_id`，保留发行部门、账簿、产品类型、内外代码、销售/起息/到期/结算日期、总名义本金、发行数量、面值和状态。

这份产品资料不靠证券主档才能存在；它的 `prd_id` 也不是该表隐含的 `secu_id`。同一产品的发行数量、累计认购额和剩余状态，分别回答不同的经营问题。[160750，63—103行](../证据/SQL/160750.sql)

160753 再从 `p_prd_product_asset` 取产品号、工具内码与内部交易流水号，将工具内码连接 TIT 主档，写入 `undrl_secu_id`。一行描述产品与一项资产/内部交易记录的联系，产品号可以重复。[160753，42—66行](../证据/SQL/160753.sql)

```mermaid
flowchart LR
    P[内部产品 prd_id] --> R[产品资产关系]
    R --> I[工具内码及统一证券号]
    R --> T[内部交易流水标识]
    I --> D[期货或期权专档]
```

图中的内部交易号只是已见字段。本次没有证明它能唯一连接到某张 T03 客户交易表，不能据此绘成完整交易闭环。

## 4. OIS 的贡献与 TIT 不同

OIS 的已读收益凭证对象提供产品条款、保本及兑付等属性，并在 XLA 产品分类中作为补充判断来源。它与 TIT 的工具定义、内部产品或客户交易约定并非天然一一对应。[债券及凭证分支](03-债券发行条款与偿付.md)

因此查一只内部产品的收益凭证属性，应从产品号与对应映射出发；查它挂钩什么市场工具，走产品资产关系；查某客户持有或交易多少，继续查具体账户/合约/事件。每一步都需要新的对象身份，而不是沿同一个“产品代码”盲目连接。

## 5. 把一个变化放回正确层次

教学假设：产品 P 挂钩工具 I，客户甲买入 P 后又部分退出。I 的标准条款不一定变化；P 的汇总认购或存续值可能变化；甲的具体交易/持仓记录需要变化。仅因为三层共同涉及同一产品，就把三种变化写到一张主档，会丢掉谁、哪次、何时这些关键问题。

本节完成上述层次及代表生产规则的解释；TIT note 专项、其他工具来源、全部客户消费路径仍按具体问题继续核验。
