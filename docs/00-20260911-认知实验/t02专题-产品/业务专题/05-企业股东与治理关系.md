# 企业、股东与治理关系：被描述企业与参与角色怎样区分

[返回入口](../README.md)

## 1. 企业不是证券的一个名字字段

企业可以是发行人、基金管理公司、托管机构、股东或被投资企业。一家企业可能对应多只证券，一只证券也会涉及多个承担不同角色的企业。

`T02_CO_BASE_INFO` 保存企业资讯身份；证券主档以 `corp_id` 指向企业；股东表、公司治理、工商变更和风险事项表达企业参与的关系和事件。这些记录不能都压成“公司当前属性”。

## 2. WD 企业号怎样形成

59471 读取 `odata_n_uip.w_compintroduction_p`，源分区固定为 `h16`。它优先使用非空、非纯空格的注册号作为 `corp_id`，否则使用源 `comp_id`；源企业号另外保留在 `src_corp_id`。

币种、省市、企业性质、国别分别通过限定类型的资讯常量转换。企业性质还有匹配类型条件；国家匹配使用源中文名称。这些都是特定分支的加工约定，不能只看一列“统一企业号”就认为所有来源已按统一社会信用代码合并。[59471，123—247行](../证据/SQL/59471-hive-task.sql)

`h16` 是源批次值，不是某个业务日期。该任务输出的处理日期也不代表企业成立或注册信息变更的时间。编号回退、批次选择及映射覆盖都影响消费。

## 3. 一份持股记录有两个企业角色

70610 从 `w_ashareinsideholder` 构造持股记录：

| 角色/时间 | 实际连接或投影 | 应怎样理解 |
|---|---|---|
| 被持有证券 | 源 Wind code → WD 主档 `in_code` | 找到这份股东资料描述哪只证券 |
| 发行企业 | 主档 `corp_id` → WD 企业表 | 谁发行了被持有的证券 |
| 企业股东 | 源 `s_info_compcode` → WD 企业表 `src_corp_id` | 股东若能匹配到企业，取得股东企业编号 |
| 公告日期 | `ann_dt → iss_date` | 资料何时公告 |
| 持股截止日 | `s_holder_enddate → end_date` | 持股信息描述哪个时点 |

脚本还保留持股数量、比例、股东序位等，部分自然人标识字段写空，并把源股东名称保留到备注。没有匹配出企业股东号，不意味着原记录没有股东，更不能默认这人是未知的发行企业。[70610，88—148行](../证据/SQL/70610.sql)

## 4. 为什么不能只按企业号拼股东

教学例子：企业 A 发行证券 S；B 和 C 是某期披露的股东。B 又是另一企业 D 的股东。A→B、A→C 与 D→B 是不同关系；把 B 当成 A 的一个普通属性，会失去角色、比例和时间。

本地还存在企业投资、分支机构、工商变更、受益所有人、处罚、诉讼和异常信息等对象。它们分别涉及关系、变更或事件，不应一律按当前企业号一对一拼宽。具体表可在 [逐表目录](../资料/物理对象目录.md) 按中文说明检索。

这些扩展分支在本版建立了对象位置；其全部生产规则、关系穿透和真实控制链未做全量审计。不能把存在“受益所有人”表等同于已经验证最终控制人。

## 5. 与 T01 的关系

资讯企业号、内部当事人号、工商登记号和源机构号分别服务于不同系统。基金 TL 分支已经展示“源管理机构号→资讯企业号”的连接，但接到 T01 客户仍需要明确的映射证据。

要统计“客户涉及哪些上市公司风险事件”，至少要分三步：客户身份映射到企业，企业关联到适用的事件，按事件发生/披露时间选范围。跳过第一步直接等值连接两个同名编号，会把身份推断隐藏在结果里。
