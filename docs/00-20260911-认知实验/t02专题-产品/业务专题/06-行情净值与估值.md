# 行情、净值与估值：先问这个数表示什么，再问是多少

[返回入口](../README.md) · [实际加工与回补](../实现详解/02-行情净值与历史回补.md)

## 1. 三种数值的业务含义

行情记录市场观察，例如开高低收、成交量额；基金净值描述某份额在净值日期的净资产计量；估值根据指定来源和方法给出计价结果。它们可能用来回答相近的问题，但不应仅因都是小数就相互替换。

| 观察 | 本地代表模型 | 需要固定的口径 |
|---|---|---|
| 证券日行情 | `T02_EXCH_QUOT_H`；另有 `_S` 结构 | 证券、交易日、来源、组别、价格列、单位 |
| 基金净值 | `T02_PRD_UNIT_NAV_H` | 基金份额、净值日、来源、单位/累计/复权净值 |
| 债券价格与估值 | `T02_BND_QUOT_H`、`T02_BOND_VALU_ANLS` 等 | 净价/全价、估值提供者、日期、币种、每百元或其他单位 |
| 分红及拆分 | `T02_FND_DIVD`、`T02_FND_SHR_SPLIT` | 一次权益安排及其日期，不是每日价格的一列 |
| 基金规模 | `T02_FND_SCAL` | 规模时点和范围，不是单位净值 |

估值等扩展模型的存在由元数据支持；本节实际生产解释集中在 WD 日行情与净值，未逐一验证所有估值方法。

## 2. 单位、累计、复权净值为什么不能混用

70232 将源单位净值 `F_NAV_UNIT`、累计净值 `F_NAV_ACCUMULATED`、复权因子 `F_NAV_ADJFACTOR`、复权净值 `F_NAV_ADJUSTED` 和累计单位分配分别写入目标字段。

教学假设：某份额分红前单位净值1.20，派现0.10，暂忽略市场变化，则除息后单位净值可能降到1.10。只比较两个单位净值会漏掉派现；复权或总回报分析需要按约定处理分配与再投资。这个例子解释为何保存多列，不能据此断言厂商的累计/复权净值算法完全等同本例。

查某时点持仓价值通常需要与持仓份额匹配的计价依据；研究收益率则需要说明分红和拆分的处理。应由消费用途选择数值，不能默认“累计净值更大所以更正确”。

## 3. 日行情不仅是源价格直投

WD A股脚本从日终价格表读数据，经主档取得身份、经常量转换币种，还引入除权、配股、分红和部分历史价格。原稿把 `_S` 解释为“快照/日内”没有足够依据；本次已读 S/H 两支都来自日终价格。[加工详解](../实现详解/02-行情净值与历史回补.md)

复权价与未复权价各自服务于不同问题。核对交易当天市场成交价时，应明确所用的是原始还是调整口径；分析跨分红时期的变化时，又要理解调整规则。不能把两种任务的列名相近当作数值必然可互换。

## 4. 净值可能晚到，也可能被回补

净值脚本先写当日，再回补前五个交易日，并使用 INNER JOIN 取得主档身份。这使“某日目标没有值”至少有三种解释路径：源当时没给、基金代码未匹配、采集/回补时点不同。

行情分支的 LEFT JOIN 则允许源价保留但编号为空。两者对缺身份记录的处理不同，因此“有行情无净值”不能直接解释为“基金没公布净值”。

## 5. 将观察与主档拼接时，先固定输出粒度

如果结果是一行“份额 S、净值日 D、来源 WD 的单位净值”，应先取得这一事实，再补名称。要展示多来源对照，就将来源保留为一列或并列比较；要用一个来源，就说明选择依据。

同一证券的多条分类、多个公告、多个管理人历史都可能把价格行放大。补充这些资料时，应按问题选出有效版本，或单独聚合/展示明细，而不是最后用 DISTINCT 隐去连接问题。
