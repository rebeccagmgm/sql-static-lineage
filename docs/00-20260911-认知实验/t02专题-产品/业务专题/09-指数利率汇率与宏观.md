# 指数、利率、汇率与宏观：参考体系也有自己的对象

[返回入口](../README.md)

## 1. 指数名称、成分和点位是三件事

指数定义告诉我们按什么规则观察一组对象；成分关系告诉我们某时点包含谁；指数点位是某时点的计算结果。一个指数有很多成分，一只证券又可以同时属于多个指数。

70047 从 `w_aindexmembers` 读取指数与成分的两个 Wind code，分别连接 WD 证券主档 `in_code`，形成 `idx_secu_id` 和 `con_secu_id`。同时保留入选日期、退出日期及当前标志，写 `T02_IDX_COMPNT_INFO` 的 WD／grp04。[70047，46—66行](../证据/SQL/70047.sql)

这条路径解释了关系两端都可能是证券主档身份。查询历史成分要处理进入/退出时间；只取当前标志再回看过去，会把今天的成员带回历史。区间边界与空退出日期的规范仍需在具体源定义中核对。

该 SQL 未写成分权重，因此不能由它推出等权、实际权重或历史组合收益。权重、点位和成分是需要分别查证的模型。

## 2. 利率是一条有期限与日期的序列

155318 从 `w_hiborprices` 取交易日期和利率，通过源 Wind code连接 WD 主档，取得统一编号、币种和名称，写 `T02_IRA_IBOR` 的 WD／grp03。[155318，46—67行](../证据/SQL/155318.sql)

利率记录有统一证券编号，不代表它就是可以按证券份数直接持有的资产。这个编号也用于组织一条参考序列。取用时要辨认期限、币种、报价单位、年化方式和观察日期；不同期限不能因同一天都有数值就平均成“当天利率”。

本次脚本展示了序列映射与数值投影，没有核验所有期限的常量、当前市场规则或所有利率来源。

## 3. 汇率必须保留货币对与倍率

70149 读取 `q_mkt_fx_ref_rate`，拆开 `CURRENCY_PAIR` 的斜杠两侧，移除货币文本中的100，再分别通过 TL／`fin00001` 转换两端币种；源货币对和 `MID_RATE` 另行保留。[70149，43—62行](../证据/SQL/70149.sql)

脚本没有在这一投影里按100缩放 `MID_RATE`。因此“货币代码清洗掉100”不等于“报价已换算成一单位”。要做金额换算，必须核对货币对原文、方向与源报价单位；仅看目标两列中文的本币/外币说明不够。

教学假设：若报价表示100单位A兑换若干B，直接当成1单位A的汇率使用，会差100倍。这是单位检查的例子，不是对该表全部货币对的实际报价约定。

## 4. 宏观指标定义不是证券主档，也不是指标值

156365 写 `T02_EDB_IDX`，主要从 IRP 预设指标元数据取编号、来源、频率和更新时间；将逗号分隔的多个数据编号展开为多行；过滤删除、更新状态和采集方式，再与补充配置合并。

该任务限定部分供应来源，并把结果写到 RPA 来源分区。指标名称、单位在本段输出中留空，源数据提供方却写进 `src_rec_id`。这再次说明“来源分区”和“记录字段注释”不能自动代表资料职责。[156365，41—97行](../证据/SQL/156365.sql)

`T02_EDB_IDX` 是定义/采集配置层。命名候选中另有 `T02_EDB` 的156367任务，但本次未取得其SQL，当前表元数据子集中也未命中该精确对象。定义存在不能证明每期指标值已到达，因此本版未宣称值生产和下游研究消费闭合。

## 5. 把参考数据用于研究时

先确定观察对象：指数成员、指数点位、某期限利率、某方向货币对或某频率宏观指标；再固定日期与单位。宏观月频、利率日频和行情日频混合时，需要明确对齐与可得时间规则，不应将缺值自动前填后当作已经验证的事实。

这些对象扩大了 T02 的实际范围：它既组织可交易工具，也组织解释市场、定价和研究所需的参考序列与定义。
