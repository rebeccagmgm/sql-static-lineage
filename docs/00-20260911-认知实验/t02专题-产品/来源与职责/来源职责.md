# 来源与职责：谁提供什么，哪一层改变了含义

[返回入口](../README.md) · [交叉矩阵](交叉矩阵.md)

## 1. 来源不是一个字段就能讲完

一次取数至少有四种来源问题：现实资料由谁维护，仓库实际读取哪张表，结果写到哪个来源分区，下游从哪些分区挑值。它们可能一致，也可能因整合和迁移而不同。

`src_id` 是当前模型的来源标签，`src_tbl` 是脚本写入的追溯字段。实际输入以 SQL 的有效 FROM/JOIN 为依据。**标签保留旧系统名字、源表已经迁移，是本次实际读到的情况。**

## 3. 三个必须理解的来源反例

### XLA：来源分区也可能保存一个整合结果

61529 读取同一证券主档中的 PRD、RCC、WD 分区，按 `secu_id` 分组后用优先级取一条，写回 XLA。它不是从“XLA 原始业务库”搬一张表。这一分支已经做过有界整合，因此不能笼统说所有来源分区都只是原样并列。

它也没有证明现实世界同一产品一定共用一个编号：不同编号不会被这条排序合并；同一优先级的多个候选也没有完整的稳定排序保证。详见 [主档与XLA加工](../实现详解/01-证券身份与XLA加工.md)。

### MOT：标签与实际输入分离

69852 的 `TPDTFUNDINFO`、`tpdtfundextinfo` 是当前 SQL 中用 CAP 源表构造的 CTE。之后结果按 MOT 分区写入，`src_tbl` 仍写旧 MOT 表名。只看任务名或追溯字段，会错过真实来源已经变化这一事实。[SQL 69852](../证据/SQL/69852.sql)

### OIS：输出与身份来源可以不同

92881 从 OIS 收益凭证表读 `prd_no`，连接证券主档的 OTC 分区 `scr_cd`，写入 OIS 凭证专档，并使用 OIS 常量转换资金类型。因此要求所有 Join 两端的 `src_id` 必须相同，也会把合法的已见路径排除。条件必须来自该条加工约定。[SQL 92881](../证据/SQL/92881.sql)

## 4. 模型和消费各负责到哪

模型层负责将源对象投影到公共结构，保留必要原码，形成编号、常量、关系和时间表达。它有可能留空字段，也可能为兼容历史保留旧标签。统一列名不代表统一了所有含义。

组合层负责定义维成员及显示名称。例如 `NEWS_SECU` 只读 WD、RCC、ICC、XLA、PO3T，按 `secu_id` 取简称/名称较长的一条。它没有把 PRD、TIT 等全部分区直接纳入；XLA 又可能间接带入 PRD。报表层则继续选择符合业务条件的产品。

所以“源系统有产品”“模型有记录”“组合有成员”“报表有结果”是四个可以分别核验的问题。前一项成立，不能省略后一层的筛选与连接。

## 5. 如何辨认生产任务

Wiki《1.资讯模型命名规范》（172993517）区分模型任务、来源完成标识任务和主数据任务。任务名只帮助定位。此次 `66042`、`69638` 名称像股票/基金生产任务，但已采集正文仅有建表定义；股票实际写入例子来自 `66002`，基金例子来自 `69826`。

正文中实际生效的写入语句、目标对象和输入才支撑某条生产解释；DDL、检查任务和名称一致都不足以独立证明生产关系。全部来源与消费者的枚举仍需另作有界审计，不能由这张职责表推算。
