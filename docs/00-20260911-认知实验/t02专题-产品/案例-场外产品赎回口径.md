# 案例：场外产品赎回口径怎样形成

[返回入口](README.md) · [来源与职责](来源与职责/来源职责.md) · [基金与业务档案](业务专题/02-基金销售托管与两融.md)

证据为任务100743的本地SQL快照，目标名属于 `dm_wm_test`，正文含固定日期2026-01-17。本页解释这份测试目标脚本中的消费结构，不将其当作当前生产报表或完整月末口径。[原始SQL](证据/SQL/100743.sql)

## 1. 结果先定义对象集合，再配事实

脚本按机构与产品组织赎回金额、客户数、保有等指标，并计算赎回率：赎回金额／（赎回金额＋保有金额）。这里的产品集合经过了分类与销售属性过滤，不能用证券主档总数替代。

整体顺序是：取得客户×产品指标 → 解释两维组合 → 通过XLA分类换键 → 产品中心筛选 → 归属机构并汇总。后半段另建立机构×产品网格，关联赎回、销售、保有等结果。

## 2. 指标里的产品维先有明确的定义

赎回事实读取客户×产品的场外金融产品、场外衍生品赎回指标，限定脚本中的月份与标签值。客户维使用个人/机构客户组合；产品维使用NEWS_SECU。

已采集组合定义明确以证券主档 `secu_id` 为 `grp_val`，从WD、RCC、ICC、XLA、PO3T取候选，按编号选择显示名称。它不等于产品中心全量，也不是源产品号或交易代码的模糊别名。[组合原文](资料/组合类型.json)

## 3. 分类表负责换键和限定匹配范围

脚本将 `grp_val` 对到 `T02_SCR_TYPE.secu_id`，限定 `src_id='XLA'`、`scr_type_std_cd='PRD01'`，取出 `scr_cd`，再与产品中心交易代码连接。

```text
指标产品成员值
  → XLA / PRD01 分类的 secu_id
  → 取分类记录的 scr_cd
  → 产品中心 scr_cd
```

这条链确认了两次不同的键：前半段是统一证券编号，后半段是交易代码。分类匹配和产品中心匹配均参与收窄范围；不能只因为三边都出现“产品”就认为一定配上。

XLA自身的身份选择和分类来源已经补在 [编号与分类加工](实现详解/01-证券身份与XLA加工.md)。分类表的 `type_name_zh` 在该标准下实际保存代码，本案例也不能把它当产品中文类型直接显示。

## 4. 产品中心决定报表的类型与策略范围

| 本脚本的分类 | 过滤规则 | 含义边界 |
|---|---|---|
| 公募 | `scr_type='9999'`，资产类型不为1或2 | 按脚本解释排除现金货币、固定收益类 |
| 私募 | 字符串条件 `'7000'<scr_type AND scr_type<'8000'`，策略不为2 | 按脚本解释排除固定收益策略 |

这些是该脚本的具体表达，不能把产品号段或字符串比较无条件推广为全库标准。空分类、空资产类型或空策略也不能自动视为满足排除条件；SQL的NULL判断与日常“不是某类”并非完全相同。

产品中心 `strg` 的本地元数据和本脚本CASE接近，但生产脚本旧注释存在另一套策略含义。因此可复述本报表的过滤规则，尚不能证明所有历史数据都按同一字典填写。[策略冲突](建模基础/03-分类常量与口径.md)

## 5. 机构归属与最终输出继续改变粒度

客户组合值按业务日期连接客户宽表，取得所属机构；再补机构名称及分公司归属。客户×产品事实由此汇总到机构×产品，并在后续处理中形成其他汇总层级。

脚本先用 `join ... on 1=1` 建机构与合格产品的组合，再LEFT JOIN赎回、销售和保有。但该段最后还有“这些事实值之和不等于0”的过滤，不能说最终必然保留所有零活动机构×产品行。网格是中间处理方式，输出范围要继续看最后的WHERE。

## 6. 时间口径也要从当前脚本读

这份文本用固定日期2026-01-17限定月份，部分保有取该日值，另有上年末保有。不能因为任务名含月度或注释写“月末保有”，就当成已经取到完整自然月月末。

资讯主档/分类和产品中心在这里也没有按历史产品版本重建。若要复现某个历史月份当时的产品分类，需要额外的历史来源，而不是直接用今天的销售档案。

## 7. 这条案例应该让读者学会什么

产品集合不是一张表自动给定的：模型身份、组合定义、分类匹配、销售条件及最终输出过滤共同决定结果。事实缺席、身份没配上、分类被排除、机构归属失败，是不同问题。

因此核对一只产品为何没出现，应沿上述顺序逐层查证，而不是只看证券主档有没有名称。整个T02的其他分支有不同对象和使用目标，不能用本案例替代行情、财报、托管或交易工具的解释。
