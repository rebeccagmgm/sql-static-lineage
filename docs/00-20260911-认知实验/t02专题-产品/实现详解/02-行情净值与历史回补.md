# 行情、净值与历史回补：一次运行可能维护哪些日期

[返回入口](../README.md) · [行情净值业务页](../业务专题/06-行情净值与估值.md)

## 1. `_S` 与 `_H` 都可能来自日终行情

本次对照 WD A股两个具体任务：69692 写 `T02_EXCH_QUOT_S`，69825 写 `T02_EXCH_QUOT_H`。两者都读取 `odata_n_uip.w_ashareeodprices`，不能根据 S/H 后缀把前者说成日内行情。

| 维度 | `_S` 的已读分支 | `_H` 的已读分支 |
|---|---|---|
| 目标分区 | WD、grp01 | 业务日、WD、grp01 |
| 交易日 | 投影源 `TRADE_DT` | 投影源 `TRADE_DT` |
| 主查询交易日限制 | 没有与 H 相同的当日条件 | `trade_dt='${data_day_int}'` |
| 业务日期 | SELECT 写入当日普通字段 | 写入当日分区 |
| 主档连接 | WD `in_code`，LEFT JOIN | WD `in_code`，LEFT JOIN |
| 补充计算 | 除权、分红、配股等处理 | 除权处理，并读取前一交易日行情及交易日历 |

S 的实际覆盖多少交易日还取决于源表内容，本次没有查询行数据。这里确认的是代码差异，而非实时覆盖范围。[69692，190—248行](../证据/SQL/69692-hive-task.sql)、[69825，177—237行](../证据/SQL/69825.sql)

## 2. 价格投影和公司行为会一起参与加工

两条脚本在最终写入之前，分别构造沪深除权相关计算，关联配股、分红、价格与股本信息。它们还对特定证券作排除，以避免同一工具在 A股/CDR 源中重复处理。

这说明模型行情不是所有列都从一张日行情表直搬；“原始收盘”“调整价”“复权因子”应按具体投影解释。两个任务的补充输入时间也不完全相同：H 的部分 TL 配股输入使用前一交易日分区，S 对应位置使用当日。

读者若要复制某条价格口径，应保留其来源、公司行为输入及时间条件；仅挑一列名字相近的价格不足以重现。

## 3. 净值当天写入，然后回补历史

70232 先读取 `w_chinamutualfundnav` 中净值日期为运行日的数据，写 WD 当日分区。币种经过常量转换，基金代码与 WD 主档 `in_code` 内连接取得身份。

之后第二段动态分区写入，分别读取前1、2、3、4、5个交易日的净值，并把对应历史交易日作为分区值。脚本后部还有其他源净值分支，不能把全任务理解为只有第一段当日覆盖。[70232，53—307行及后续](../证据/SQL/70232.sql)

因此，一次 D 日运行可以修改 D 之前的净值分区。查询结果变化时，先考虑是否发生历史回补或源更正，不应仅按文件生成时间归入 D 日业务。

## 4. 一个日期例子

假设 D 为周一，前一个交易日为上周五；具体日期仍由任务调用的交易日历函数决定。D 日脚本可以把新到的周五净值写回周五分区。

如果某份导出上周五晚未见该净值，周一再导出却有值，两次都可能忠实反映各自采集时点。要复现“当时知道什么”，必须保留观测/发布版本，不能只靠净值日期。

## 5. 身份匹配会直接改变覆盖

行情使用 LEFT JOIN：源价可以保留而身份为空。已读净值分支使用 INNER JOIN：主档未匹配的源净值被排除。这是两种不同的数据到达边界。

查“为什么这只没有净值”时，应先拆成：源是否有该日期的记录、用的是哪个基金份额代码、对应来源主档是否命中、目标是否被回补覆盖。不能从空结果直接推断基金未公布净值。
