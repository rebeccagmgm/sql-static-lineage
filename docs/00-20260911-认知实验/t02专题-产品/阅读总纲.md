# 同一只基金怎样贯穿 T02：从业务变化推导模型

[返回入口](README.md) · [全貌](00-全貌与阅读方法.md)

以下 F、FA、FC、M、C、P 等名字和数值都是教学假设。它们用于推导对象区别；后半部分再与本地模型和实际 SQL 对照，不代表已经把真实基金跨系统逐行配对。

## 1. 先有基金安排，再有需要分别识别的份额

设基金 F 由管理公司 M 管理、机构 C 托管，有 A、C 两类份额 FA、FC。两类份额共享部分投资安排，但各自有代码、费用和净值。

如果只保存“基金F，代码FA”，遇到FC时就会产生两个错误选择：把FC覆盖掉，或把同一基金的共有属性重复当成两个基金。需要同时保留基金层和份额层。

| 对象 | 要保存的主要信息 | 为什么独立 |
|---|---|---|
| 基金F | 管理、托管和基金层安排 | 多种份额可以共享 |
| 份额FA、FC | 各自代码、费用和计价身份 | 认购登记与净值需要区分 |
| 管理公司M、托管机构C | 企业身份与机构资料 | 它们还可能管理/托管别的基金 |

实际 TL 分支先从基金表连接份额表，再按份额证券内码连接证券主档；管理公司和托管机构另连企业。这一结构由 [69826](证据/SQL/69826.sql) 的连接支持，并非把同名表想象成上下级。

## 2. 公司决定代销，增加一层业务档案

现在公司登记了一份销售档案 P，说明风险、策略、是否销售、成立到期和控制属性。市场上的 FA 不会因为销售部门更新风险标签而变成另一只份额；P 的上架状态也不等于交易所上市状态。

因此证券公共身份、基金专档和产品中心档案各有职责。PRD 的真实加工也从同一源产品表分别生产证券主档和产品中心资料。两者并非“前一张表加工成后一张表”的固定链条。

若P下架，首先变化的是销售安排。查询市场历史行情仍然需要保留FA；查询在售名单则要按销售状态及有效时点筛选。当前销售表不能自动恢复某个过去日期的在售状态。

## 3. 两天净值变化，增加的是观察记录

再设FA在D1、D2两个净值日的单位净值分别为1.20、1.18，D2每份分配0.02，暂忽略其他变化。这不意味着基金从F变成了另一对象：变化的是日期、价格和分配。

| 日期/事项 | 记录需要表达什么 |
|---|---|
| D1单位净值 | FA、D1、来源、1.20及计价单位 |
| D2单位净值 | FA、D2、来源、1.18及计价单位 |
| D2分配事项 | 哪个份额、哪次分配、每份金额及相关日期 |

要解释投资表现，还要考虑分配或采用已定义的调整口径；要算某时点份额价值，则按消费要求选计价依据。这解释了为什么模型把单位、累计、复权净值和分配分别保存。

实际 WD 净值任务会回补前五个交易日。假设D2净值在D3才补到仓库，净值属于D2，新增观测发生在D3，两种时间都不能丢。[净值与回补](实现详解/02-行情净值与历史回补.md)

## 4. 一个来源没有必要包办所有职责

WD可以提供市场资料和净值；TL分支提供基金、份额及机构连接；PRD维护产品中心属性；XLA主档对部分来源按同一证券编号选优；组合再挑成员与名称。

同一个现实份额可能被多套来源描述。来源间的编号是否能对齐，要看构造与映射；XLA只按已有同号候选排序，并不会把所有同名异号的记录识别为一物。

因此这里的箭头分两种：业务关系说明“F具有FA份额”，加工关系说明“某任务读取哪些源记录写到哪张表”。业务上相关，不能直接冒充已验证的物理血缘。

## 5. 客户赎回时，产品资料与交易事实合流

设客户甲赎回FA。T02可以解释FA是什么、产品是否属于这张报表的范围；客户身份、赎回金额和账户/交易事实还要从对应主题及指标取得。

本地100743案例从客户×产品指标开始，用NEWS_SECU成员值对应XLA分类，再用交易代码接产品中心并筛选类型、资产和策略。报表中的产品集合由这一系列规则形成，不等于全部基金，也不等于全部证券主档。[赎回案例](案例-场外产品赎回口径.md)

如果甲的一笔赎回在产品分类桥上未匹配，事实本身可能存在，但该报表不会得到同样结果。这就是“源有业务、模型有对象、组合有成员、报表有结果”需要逐层解释的原因。

## 6. 管理公司资料与基金资料也要分开

若管理公司M发布半年度报告，财务记录描述的是M的报告期经营情况，不是FA的净值。若某研报同时点评F和M，文档可能关联多种对象；研报数量不能当基金数量，企业收入也不能当基金资产规模。

由同一个例子，可以逐步引出企业、财报、文档三条分支。这使T02的全貌超出“证券主档的附表集合”。

## 7. 改一个条件，检查是否真的理解

- 新增FC份额：需要新的份额计价与登记身份，管理公司M不必新增。
- P下架：销售范围改变，不自动删除FA的市场历史。
- 净值在D3更正：可能回补D2记录，D2观察日与D3观测时点不同。
- F更换管理人：需要处理角色关系或对应档案的时间，不应改写基金全部历史为当前管理人。
- 一份公告提到FA、FC：证券关联可以有两条，文档仍可能只有一份。

这些问题可以先在对象层推理，再回到来源和实现验证。继续阅读 [交叉矩阵](来源与职责/交叉矩阵.md)，选择需要深入的分支。
