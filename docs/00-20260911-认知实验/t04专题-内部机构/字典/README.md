## 1. 本版提供什么

按 `pdata_n` T04 字段名与 `ref_dw_cd_list.dw_cd_eng_name` 忽略大小写精确匹配，找到 195 个代码域、4,048 行本地码值。它们包含性别、币种等共用代码域，并非 195 个“T04 专属字典”。别名字段及未命中字段不在这个自动匹配范围。

## 2. 最重要的四组区别

**类别与类型。** 机构类别 CD014 先区分机构体系，类型 CD015 再说明体系内具体类型。TIT 的类别 17 对应类型 620/621，不能靠截取类型前缀构造通用树。

**关系类型与另一端编号。** CD018 的 10 是上级机构，11/12/15 是跨体系映射，14 是营业部到分公司归属。CD183 又区分员工行政归属、费用公司段、费用部门段和负责人。把它们都叫“所属部门”会丢失问题本身。

**对象类型与权限值。** CD663 的 11 是菜单，其备注要求权限类别为功能权限；同一个 `Righ_Obj` 字段还可以承载表、产品、交易账簿、交易对手等标识。必须一起看 `Righ_Cate_Cd + Righ_Obj_Type_Cd + Righ_Obj + 权限值`。

**状态与判断维度。** 员工在职、用户启用、机构正常、商机生效是四个不同对象的状态。角色关系 0101/0102 是长期／临时角色，与用户状态也不同；不能把任意字段中的 0、1 或 01 解读成同一状态。

## 3. 源码转换与仓库字典不是同一张表

`REF_CD_CVT_MAP` 将特定源系统、源表、源字段的代码映射到目标表字段；`REF_DW_CD_VAL` 解释仓库代码含义。已有 SQLite 导入的是字典码值，未提供可直接全量核验的独立源代码转换明细表。

PAS 机构类型样例按目标 `T04_INR_ORG/Inr_Org_Type_Cd`、源 `HSSORG_ORG_VER/TYPE_ID`、系统 PAS 过滤转换表；未命中时 `NVL(DW_CD_VAL,TYPE_ID)` 保留源 ID。因而模型字段名带 `_cd` 并不保证每一行都属于仓库代码域。[IMG-README-20260914110800287.sql](attachments/README/IMG-README-20260914110800287.sql)

WMP 成员分成任务还复用 `T04_EMP_EMP_GRP_RELA_H` 对成员类型的转换定义；不能根据当前目标表名去查另一份映射并判断缺失。[IMG-README-20260914110803338.sql](attachments/README/IMG-README-20260914110803338.sql)

## 4. 已发现的字典覆盖边界

本地 CD018 有 10 条码值，PAS 完整 SQL 却还产生关系 21/22。本文保留它们在 SQL 中的财务段解释，并明确“未命中本地字典”，没有新增字典值冒充规范。

精确字段匹配也会漏掉别名和结构差异。例如权限物理快照列 `Righ_Cd`，SQL 用 `User_Righ_Cd`；招聘快照列面试状态，SQL 用面试轮次。先核实字段究竟是什么，再查字典，不能挑一个中文近似的代码域来填。

CD663 的部分源码值带尾随空格，完整实值页原样保留。下游是否应 trim、是否已有规范化，都属于另一个加工问题。
