# 团队、分成与考核：组织协作不等于收入分配

[返回入口](00-20260911-认知实验/t04专题-内部机构/README.md)

## 1. 员工组是管理对象，成员关系才说明包括谁

`pdata_n.t04_emp_grp` 描述团队本身；`t04_emp_emp_grp_rela_h` 描述员工与团队的关系；`t04_emp_grp_rela_h` 描述团队之间的关系；名称、机构、产品、职位和统计信息又在对应附属表中。

团队可以是业务协作单位，未必是正式行政部门。`t04_emp_grp_inr_org_rela_h` 的存在，意味着“团队”和“内部机构”需要通过关系表达对应，不能直接把 `Emp_Grp_Id` 当 `Inr_Org_Id`。

PAS 团队配置样例给了一个清楚的拆分：`196117` 将 `TEAM_LEADER_CODE` 放入员工号、`PAS062-` 加团队 ID 放入组号，关系 `02` 表示队长；`196118` 从同一配置表产生团队到上级团队的关系 `01`，空或零上级 ID 留空。[队长关系](attachments/04-团队分成与考核/IMG-04-团队分成与考核-20260914110757620.sql)、[团队层级](attachments/04-团队分成与考核/IMG-04-团队分成与考核-20260914110759705.sql)

所以这一份队长生产 SQL 只能解释负责人，不能冒充完整团队成员名单。普通成员来自其他来源分支；本版候选目录保留它们，但未把全部成员来源逐个展开。

## 2. 团队成员、岗位和分成比例要分开

## 3. 直播团队分成：比例来自角色配置

`181722` 先读 `P_LIVE_TEAM_MEMBER`，按团队 ID 左连 `H_LIVE_TEAM_INFO`。成员类型为主播、内容制作、运营助理、直播导演或其他协作人员时，分别取团队配置中的对应比例列；同时把成员类型通过转换表映射到模型成员关系类型，分成类型写 `01`，组号使用 `WMP006-` 前缀。[181722.sql，31–57 行](attachments/README/IMG-README-20260914110803338.sql)

这段 SQL 说明：比例并非直接来自成员表上的个人比例字段，而是从团队按角色选取的配置。若一个角色有多个成员，每个成员都会命中同一角色比例；是否应再均分，当前 SQL 没有给出。这也不能据以判断各成员比例之和一定为 1 或 100。

历史比对保留 `员工 + 团队 + 成员关系类型 + 分成类型`，比较比例是否变化并维护期间。因此连接时只用员工号会串团队；只用员工和团队又可能串角色。[181722.sql，60–81 行](attachments/README/IMG-README-20260914110803338.sql)

另一来源 `157713` 直接取 `RYXX/TD/TCBL`，起止日期来自 `SXRQ/JZRQ`，无截止日期时写 `2099-12-31`，成员关系类型为空。它保留的是源期间，不能把直播团队的模型开闭链机制推广过去；两分支都未证明比例单位。[157713.sql，26–44 行](attachments/04-团队分成与考核/IMG-04-团队分成与考核-20260914110804488.sql)

## 4. 考核方案、维度、因子和结果各在一层

| 模型对象 | 表 | 说明 |
|---|---|---|
| 方案 | `t04_inr_org_exam_schm`、`t04_perf_schm_def` | 定义一套考核或绩效安排，不能直接当结果 |
| 适用对象及目标 | `t04_inr_org_exam_schm_use_scop`、`t04_inr_org_exam_schm_tgt`、`t04_emp_perf_tgt` | 谁适用、期望做到多少 |
| 维度与因子 | `t04_exam_dim`、`t04_exam_fctr`、`t04_exam_schm_dim_rela_h`、`t04_exam_dim_fctr_rela_h` | 方案按哪些方面和具体因子展开 |
| 结果 | `t04_inr_org_exam_rslt_det` | 记录方案、机构／员工、因子、期间上的标准、指标值、得分 |
| 调整或激励参数 | `t04_emp_exam_rank_adj_info`、`t04_inr_org_emp_exam_coef`、`t04_org_dect_rati` | 参数与实际兑现结果分开 |

这是对象分工图，不代表所有表必定由一条线性流水加工。表与表之间的每条连接仍需来源中的方案、维度和因子编号证据。

## 5. 考核结果表不等于在 T04 内重算得分

`182044` 把源机构号补成四位，方案号加 `AUM023-`，投影考核标准、权重、指标值、基准值、平滑值、月得分、年度得分和剩余分值。SQL 中 `Mth_Scor=EXAM_SCORE`、`Anul_Scor=Y_SCOR`，主要在搬运已经给出的结果，没有展示由指标值计算最终得分的公式。[182044.sql，52–99 行](attachments/04-团队分成与考核/IMG-04-团队分成与考核-20260914110806432.sql)

它读取 `busi_date >= add_months(运行日,-12)` 的源记录，并按源 `Busi_Date` 写动态分区。这个条件只有下界，不能说代码严格限定“过去十二个月且不含未来日期”。表内同时有 `Mon`、`Exam_Anul` 和分区 `Busi_Date`：考核月份、考核年度和数据快照日期必须分别限制。

因此汇总某员工考核前，应先固定方案、对象层次、考核期间和因子粒度；不能把每条因子上的月得分、年度得分直接加总，也不能把它们等同已发薪酬。若要还原得分算法，下一份必要证据是源计算程序，而不是继续扩充 T04 字段清单。
