# 招聘与培训：人员生命周期中的不同事项

[返回入口](00-20260911-认知实验/t04专题-内部机构/README.md)

## 1. 招聘先产生应聘事项，未必已经有员工身份

候选人、简历、应聘和职位相互关联，但不是同一个对象。一个候选人可以有多个应聘过程；完成笔试或面试也不等于入职。

| 模型入口 | 记录对象 | 关键区别 |
|---|---|---|
| `pdata_n.t04_cand_acpt_empt_info` | 候选人的应聘／人才库信息 | 有候选人、简历、应聘和职位编号 |
| `t04_cand_wrt_exam_info`、`t04_cand_intv_info` | 笔试和面试记录 | 一次应聘可有多次测评，不能按候选人直接一对一拼接 |
| `t04_pos_rcrt_prog`、`t04_rcrt_pos_adtnl_info` | 招聘职位及进展 | 描述需求岗位，和某个人是否录用分开 |
| `t04_pend_entr_emp_info` | 待入职安排 | 仍不自动等于 `t04_emp` 中的在职人员 |
| `spdata_n.t04_intn_sbsd_info` | 实习津贴事项 | 津贴期间、实际实习期间和人员身份分别保存 |

`97715` 对有 `APPLY_ID` 的记录构造 `PAS001-CAND-` 候选人号，否则使用 `PAS001-PHEN-` 加简历号。它同时保留应聘号、简历号和职位号，并通过转换表解释应聘状态、简历类型等。这个构造首先表达来源记录的身份策略，不能单凭该候选人号就宣称跨应聘、跨系统统一自然人身份。[97715.sql，61–90 行](attachments/05-招聘培训与学习记录/IMG-05-招聘培训与学习记录-20260914110757621.sql)

此处有一项必须保留的冲突：表字段快照在相应位置写 `Intv_Stat_Cd`（面试状态），SQL DDL／SELECT 使用 `Intv_Rnk_Cd`（面试轮次），取源 `INTERVIEW_TYPE`。不能把轮次字典解释成状态字典；使用前需核实部署字段顺序和语义。[差异台账](00-20260911-认知实验/t04专题-内部机构/证据/已知差异与待核实事项.md)

## 2. 实习津贴体现“人、事项、期间”同时存在

`132322` 从投行实习补助来源读津贴记录，关联招聘资料，分别尝试按简历关联号、证件与姓名匹配，相关子查询按应聘日期倒序取一条；再把源实习部门连到部门视图，取机构编号。

它分别保存实习起止、补助起止、工作天数、津贴金额、反馈日期以及实际实习起止。`Sbsd_Amt` 直接来自源 `SALARY`，当前 SQL 没有按工作天数重算津贴。因此从表中可读到“来源申报的津贴记录”，不能直接当成支付到账证据。[132322.sql，48–101 行](attachments/05-招聘培训与学习记录/IMG-05-招聘培训与学习记录-20260914110759892.sql)

本版只分析结构与代码，没有读取候选人或员工行数据。投行面试附加、合作方面试评价等其他结构已收入目录；尚未逐一还原录用、入职、薪酬和支付全流程。

## 3. 课程、培训班、课件、讲师和学分不是同一层

一门课程是可学习的内容；培训班组织某次教学安排；课件是材料；讲师是授课角色；用户课程记录是学习事实；学分和讲师授课学时是不同计量。

| 对象 | 模型表 | 读法 |
|---|---|---|
| 课程与课程库 | `t04_less_info`、`t04_less_house`、`t04_less_less_house_rela_h` | 内容定义与归库关系 |
| 培训班与课程 | `t04_train_clas`、`t04_clas_less_rela_h`、`t04_clas_plac_info` | 班次安排及其包含的内容 |
| 课件与讲师 | `t04_crsw_info`、`t04_clas_crsw_rela_h`、`t04_teac_info`、`t04_teac_lvl_h` | 教材关系与讲师资料 |
| 学习过程及结果 | `t04_user_less_study_det`、`t04_user_less_chpt_score_info`、`t04_user_less_score_info` | 用户、课程／章节、时间及学习结果 |
| 学员和讲师计量 | `t04_stu_get_scor`、`t04_teac_get_scor`、`t04_teac_eval_det` | 学员获分、讲师学时、讲师评估分别看 |
| 考试 | `t04_exam_base_info`、`t04_exam_batch_info`、`t04_exam_exam_batch_user_info`、`t04_exam_pass_rule` | 考试、场次、人员及通过规则 |

表名 `exam` 在此表示考试，在上一章部分表中表示绩效考核。必须结合中文注释和字段判别：课程考试场次不是经营考核月份。

## 4. 在线课程主表并不提供所有学习事实

`105798` 将源课程 ID 和名称投影到 `t04_less_info`，授课形式写 `ONLINE`。学习开始、结束、时长和讲师类型在本分支都为空。因此不能用该表的空时长推断课程没有时长，也不能用主表计算员工实际学习时长。[105798.sql，36–51 行](attachments/05-招聘培训与学习记录/IMG-05-招聘培训与学习记录-20260914110802865.sql)

`88170` 则读取用户课程结果，保存课程分 `Less_Scor`、学分 `Study_Scor`、获分时间、学习状态、首次及最后学习开始时间，并通过 OA 资料把登录名转员工号。课程分和学分是两个源字段，不应合并成“得分”。[88170.sql，31–52 行](attachments/05-招聘培训与学习记录/IMG-05-招聘培训与学习记录-20260914110804687.sql)

这个消费样例还有两点会影响统计：

1. 对 OA 资料虽然使用 `LEFT JOIN`，随后 `WHERE B.LOGIN_ID IS NOT NULL` 会排除无法匹配的学习记录。所以输出不是源学习记录全集。
2. 子查询计算了按工号排序的 `RN`，却没有 `RN=1` 过滤。不能按注释认定已经完成去重；是否实际重复，需要按登录名检查连接基数。

当问题是“某员工本月取得多少学分”，应先确定学分的获分日期范围、课程记录是否可重复、OA 映射是否多条和缺失影响，再聚合。`src_tbl` 覆盖分区不提供自动的每日快照历史。
