## 1. 员工宽表怎样选出一个可展示的员工视图

`pdata_n.t98_org_emp_base_info` 的已读生产 SQL `61573` 以 `t04_emp` 为入口，补姓名、鉴别信息、员工状态、所属机构、OA 账号、地址、职级、费用段和其他属性，写按 `busi_date` 分区的宽表。

它不是简单把相同 `Emp_Id` 的所有表连起来：

| 处理 | 实际选择 | 对读者的含义 |
|---|---|---|
| 机构和员工机构历史 | 部分 PAS 分支只限制开始日期不晚于当天，再按结束日期倒序取一条 | “截至当天最近资料”与“当天仍生效关系”并存 |
| 旧新号 | 用员工关系 `07`、员工状态和离职日期挑选对应 | 工号变更需明确关系方向，不能按姓名合并 |
| 所属机构 | 员工机构关系 `10`，再按机构关系 `11/15` 尝试转到行政体系 | 机构显示值经过身份转换 |
| 证件资料 | 对候选排序并限定来源后取一条 | 一人多证件必须选择，不能直接横向扩行 |
| OA 账号 | 对应关系 `10`、未删除、OAS 来源；再配用户状态历史 | 有员工不保证有符合显示条件的 OA 用户 |
| 当前显示 | 员工在职时选择状态为 `101` 的 OA 用户候选，否则使用另一候选 | 展示字段有专门业务选择，非普通 COALESCE |
| 费用和责任 | 分开连关系 `13/14/15` | 费用公司、费用部门和负责人不能合并成一个归属字段 |

证据见 [61573.sql，185–251、341–452 行](00-20260911-认知实验/t04专题-内部机构/证据/SQL/61573.sql)。其中排序本身并不证明并列时唯一；`SELECT DISTINCT` 也不能证明目标键唯一。

因此“员工昨天属于哪个部门”存在至少两种合理业务需求：严格还原昨日有效关系，或者复现该宽表保留离职人员最近资料的口径。需求不同，不能随意互换筛选条件。

## 2. 营业部与分公司：先找归属，再切换编号

`t98_org_brch_div_info` 的 `61593` 从 PAS 生产、沿用 ERP 来源标签的机构关系中取 `14`，得到营业部行政编号与分公司行政编号；再分别用 `11` 转到柜台编码，补名称、状态和地理资料，最后写日快照。

```text
营业部行政编号 --14 归属--> 分公司行政编号
      |                         |
      11 映射                   11 映射
      v                         v
营业部柜台编号              分公司柜台编号
```

第一条柜台映射是 `JOIN`，分公司柜台映射是 `LEFT JOIN`。因此没有营业部柜台对应的候选会被排除，而没有分公司柜台对应的记录可以保留空值；这是下游范围选择，不是来源表不存在相关机构。[61593.sql，44–58 行](attachments/07-从模型到下游消费/IMG-07-从模型到下游消费-20260914110757601.sql)

该任务对关系使用 `strt_date <= d AND end_date > d`，对主表使用类别 `2`、未删除、PAS 数据来源及特定 ERP 标签。四个条件共同限定口径，单独写一个 `Inr_Org_Id` 连接不足以复现结果。

它还在物理地址连接中使用 `B.INR_ORG_ID`，而注释称“取柜台四位编码”。正文保留实际连接式，不把注释自动改成 `B.RELA_INR_ORG_ID`；两种编号是否在对应地址来源一致，仍需核验。

## 3. TIT 机构配置怎样进入互换交易的本币

`211619` 生产 `pdata_n.t98_otc_swap_comp_trd_undrl_info`。已读片段先取得合约所属账簿，再从 `t03_otc_deri_book_adtnl_info` 取得账簿 `Bel_Dept`，按部门连接 T04 部门配置，最终投影 `DP.Lcrrc_Crrc_Cd`。

```mermaid
flowchart LR
    S[D_BK_DEPARTMENT_PROPERTIES] -->|部门、公司、本币| T[T04_OTC_DERI_DEPT_ADTNL_INFO]
    B[T03 账簿附加信息] -->|Bel_Dept = Inr_Org_Id| J[部门配置连接]
    T --> J
    J -->|Lcrrc_Crrc_Cd| O[T98 互换持仓标的汇总]
```

这是一段按 SQL 复核的读写与连接说明，未声明端到端运行或分区因果闭包。[生产配置 SQL](attachments/07-从模型到下游消费/IMG-07-从模型到下游消费-20260914110758654.sql)、[消费 SQL，95、129–136 行](attachments/07-从模型到下游消费/IMG-07-从模型到下游消费-20260914110758686.sql)

这里的本币来自账簿部门配置，不能直接用标的币种、合约币种替换。消费者只按部门号连接并限定来源，没有带 `src_id`，因此若同部门存在多条配置会放大后续记录；当前没有实际行数据，不能宣称一定一对一。

配置表按来源覆盖，消费者也未在该连接加历史日期。如果回算历史交易，它使用的是执行时可读到的配置；是否符合历史配置口径，需要业务要求和配置历史证据共同确认。

## 4. 从消费反看 T04 的价值

三条路径体现了 T04 的三类作用：把人和账号联系起来，把业务归属转换为可用的机构编号，把组织配置带入业务计算。它们并不是同一种“组织层级”。

Wiki 的机构编码规范要求为业务语义加前缀，例如开户机构、营销机构，以及分公司编号。这并非单纯命名美观，而是让下游知道究竟按哪个归属过滤或授权。字段名只能提示语义，完整口径仍由来源、关系、时间和连接决定。[规范正文](attachments/07-从模型到下游消费/IMG-07-从模型到下游消费-20260914110801685.json)
