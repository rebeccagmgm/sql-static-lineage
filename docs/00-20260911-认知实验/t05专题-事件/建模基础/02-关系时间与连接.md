# 关系、时间与连接

## 1. 连接的是哪一类对象

| 连接方向 | 识别依据 | 已核对例子 |
|---|---|---|
| 事件 → 合约/账户 | 协议编号、修饰符、来源；必要时再限定业务时点 | TIT互换 `20206`、期权 `20207`；保证金账户 `10219`、资金账户 `10220` |
| 事件 → 主体 | 源主体编号及其拼接规则 | TIT交易对手通常为 `TIT060-` + 源对手方编号；CRM客户为12位补零客户号 |
| 事件 → 产品 | 产品编号的具体命名空间与映射 | TIT `TIT-` + 产品源编号；CIS借CAP产品映射输出 `MOT-` 编号 |
| 明细 → 主事件 | 显式主事件编号或已核对的源事件键 | TA5 `Main_Evt_Id`；TRS `Dura_Chg_Src_Id = Src_Id` |
| 事件 → 事件 | 关系表两端身份及关系类型 | TIT292通知 → TIT157收付，关系类型 `01` |
| 事件 → 员工 | 事件身份、员工角色及来源内员工映射 | RMS服务事件 + `SERV_EMP`，员工优先取ERP编号，未匹配回退源员工号 |

编号规则事实见 [业务章节](../README.md) 中相应来源；它们不能直接证明主外键约束或 Join 基数。尤其是账户/合约的裸编号，不要脱离修饰符推广为全主题 Join 键。

## 2. 关系表不能靠同名前缀猜两端

`t05_otc_deri_evt_rela_h` 的已读 TIT298 分支来自 `N_OPE_SETTLE_NOTICE_TRANSFER`：左端是 `TIT292-KEY_SN_ID`，右端是 `TIT157-TRANSFER_ID`，代码 `01` 的含义由该 SQL 注释指向结算通知书与收付款记录。

它不是“任意两条 T05 记录都能连接”的通用桥。关系历史按两端编号比对；读取当日有效关系使用 `Strt_Date <= d AND End_Date > d`。一次通知可对应多少收付、单个收付可对应多少通知，本次没有业务行数据可验证。

`t05_evt_emp_rela_h` 的 RMS006 分支左端为 `RMS005-SERV-SERID`。不能把它当作 `CRM028-ID` 服务事件的现成员工桥，哪怕两边中文都叫“客户服务”。[关系SQL](../../../attachments/02-加工与分区/IMG-02-加工与分区-20260914110200114.sql)、[员工关系SQL](../../../attachments/05-客户服务营销与数字行为/IMG-05-客户服务营销与数字行为-20260914110159624.sql)

## 3. 时间至少分四类

| 时间 | 回答什么 | 实例 |
|---|---|---|
| 业务发生与生效 | 何时发生，何时计入业务？ | 保证金 `Occt_Date` 来自 `SRC_BUSI_DATE`，`Vld_Date` 来自 `ACTUAL_BUSI_DATE` |
| 办理与结果 | 何时申请、审批、确认、支付？ | `Inpt_Time`、`Appr_End_Time`、`Paid_Date`、`Actl_Paid_Date` |
| 对象有效区间 | 此关系或资料在哪段时间成立？ | 关系历史的 `Strt_Date` / `End_Date` |
| 采集与落盘 | 取了哪个快照，写入哪个分区，何时加工？ | 源 `Busi_Date`、目标分区、`Data_Etl_Date`、`Data_Time` |

这些列可能碰巧同日，也可能不同。TIT保证金任务读取调度日源快照，却按源业务发生日写目标 `Busi_Date`；OIS报告回看近三个月源分区。不能把“今天跑的 SQL”解释成“只包含今天发生的业务”。

## 4. 一个有证据的连接例子

在 T98 消费任务228195的互换分支，代码明确使用：

```sql
-- 摘录连接条件；完整来源过滤、状态和日期见原SQL。
event.Src_Id = detail.Dura_Chg_Src_Id
payment.Swap_Dura_Evt_No = event.Src_Id
```

这里连接的是源事件 ID，不是两个表的 `Evt_Id`。明细自身是 `TIT215-ID`，主事件则拼入日期和合约；前缀不同并不妨碍通过专门关系字段连接。

完整阅读见 [T98消费案例](../实现详解/01-TIT事件怎样进入T98.md)。该任务还按来源、合约状态、事件状态、部门及账簿筛选；省略这些条件会改变结果范围。

## 5. 取数前先把一句话说完整

例如：“统计指定来源、指定业务日、指定状态的**确认主记录**，以确认单身份去重，取确认金额；明细先按主事件聚合，再连接；产品身份使用该来源的映射。”

如果还说不清加粗位置是申请、确认、明细、版本还是执行尝试，就尚未确定统计粒度。此时进一步查字段和来源比直接写 `sum` 更有意义。
