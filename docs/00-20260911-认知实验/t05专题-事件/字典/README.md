## 3. 一项真实的弃用线索

CD375的 `contract_reset`原记录备注说明：来自TITANS，与`reset_trs`同含义，上游已弃用，但流水仍存在，后续需排查转码。该记录业务日期为 `2026-05-22`，来源 `MANU_MATN`。

这是字典记录携带的历史维护说明；本次没有独立验证上游实际弃用进度，也没有自动把两个值合并。已读T98条件使用大写 `PARTIAL_TERMINATION`，而导出含小写 `partial_termination`，同样需要先核对实际值与转换规则。

## 4. 转码和查含义是两层

例如保证金TIT279会按目标表、目标字段、源表、源字段、源系统限定 `REF_CD_CVT_MAP`，再把源值转为仓库值；找不到使用 `NVL`回退源值。

`REF_DW_CD_VAL`/本地`code_values`解释代码含义，`REF_CD_CVT_MAP`负责源值转换。当前资产库没有独立导入的转换明细表，SQL引用转换表不等于转换数据已可查。不能把未匹配时保留的源值当作已标准化成功。

## 5. 附件是候选索引，不是自动绑定结果

[字段同名代码域候选](../../../attachments/03-来源职责与交叉矩阵/IMG-03-来源职责与交叉矩阵-20260914110158588.json)按已导出的`pdata_n`字段英文名匹配代码域，并加入少数明确参考域。它便于寻找可能相关的字典；是否适用，需要继续检查模型、来源和SQL。特别是 `EVT_STAT_CD`、`EVT_TYPE_CD`这类通用名称，不采用“第一个匹配即答案”。

附件保留全部候选定义及命中行数，仅为本专题使用的10个代码域保留完整码值行；其余候选按`values_exported=false`标明，需要时回本地SQLite查询，未把未经适用性核验的码值全量复制为专题结论。

查到某个值后，应至少同时记录代码域、原代码、含义、适用来源/类型备注与记录日期。来源系统中文名在同一附件的CD100中保留。
