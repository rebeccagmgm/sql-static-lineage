# 资金变动类型、对象关系与金额方向

**资金变动类型解释“为什么记这一笔”，关系说明“它关联谁”，方向说明“从哪个账户或主体看增减”。这三个问题需要分别回答。** 同一个合约事件可能形成收付记录、账户流水与保证金流水；类型名称相似不足以证明它们是同一笔可相加金额。

本页按业务含义把CD397 `FND_CHG_TYPE_CD`的65个原值分成12个阅读组，再接上TIT实际转码与关系例子。分组为本专题整理，不是官方父子层级或资金正负规则。来源为本地资产目录，查询日2026-09-14，码值快照`UNVERIFIED`；65条来源表均为`MANU_MATN`，逐条日期、原备注见[原值附件](重点代码域原值.md)。

## 1. CD397同时包含业务动作、审核和记账处理

## 2. 资金与保证金模型怎样得到这个字段

| 对象与模型 | 源字段及写入方式 | 可确认的结论 |
|---|---|---|
| TIT保证金台账 `t05_otc_deri_cutp_marg_chg_evt` | `D_MARGIN_ACCOUNT_LEDGER.MARGIN_ACTION_TYPE`经`REF_CD_CVT_MAP`，以`NVL`回退原值 | 字段是保证金流水动作的表达；每个源动作实际映射到CD397哪一条，还需转换明细：[173965](../../../attachments/01-事件身份与模型表达/IMG-01-事件身份与模型表达-20260914110158585.sql) |
| TIT资金台账 `t05_otc_deri_cutp_fnd_chg_evt` | `D_CAPITAL_ACCOUNT_LEDGER.CAP_ACTION_TYPE`经`REF_CD_CVT_MAP`，以`NVL`回退原值 | 动作类型与`LEDGER_TYPE → Evt_Stat_Cd`是两条不同映射，不能混用：[173966](../../../attachments/02-资金划转与账户变动/IMG-02-资金划转与账户变动-20260914110159330.sql) |
| 期货及其他公司资金变动模型 | 元数据还在`t05_futr_fnd_chg_evt`、`t05_otc_deri_comp_fnd_chg_evt`、`t05_sfb_comp_fnd_chg_evt`发现同名字段 | 这是进一步核对的模型入口，本页未逐项确认其转码与全部类型适用性 |

表中模型范围为`pdata_n`。当前资产SQLite有仓库码值，但没有独立导入`REF_CD_CVT_MAP`转换明细；SQL中的源表名、字段、系统限定应作为下一步查询坐标。未命中时保留原值意味着“有类型值”并不等于“已标准化到CD397”。

## 3. 关系类型：先说清两端是谁

| 关系 | 已核对代码及来源 | 用于什么，不足以证明什么 |
|---|---|---|
| RMS服务事件与服务员工 | CD104 `EVT_EMP_RELA_TYPE_CD`的`SERV_EMP`＝事件-服务员工；`MANU_MATN`，2021-01-26；SQL38361固定写入 | 左端是`RMS005-SERV-SERID`，右端经过员工身份映射。能解释角色；不能直接套到`CRM028-ID`服务记录，也不证明一件服务只有一个员工：[38361](../../../attachments/05-客户服务营销与数字行为/IMG-05-客户服务营销与数字行为-20260914110159624.sql) |
| TIT结算通知与收付款记录 | SQL185098固定写入关系类型`01`，两端分别拼`TIT292-KEY_SN_ID`、`TIT157-TRANSFER_ID` | 这是具体SQL分支的枚举与两端证据，本页未找到可独立确认为该关系字段的完整本地代码域；不把它当作CD1318或通用事件类型：[185098](../../../attachments/02-加工与分区/IMG-02-加工与分区-20260914110200114.sql) |

关系有效期、来源身份及Join基数仍要保留。关系存在说明两件记录有关，不能证明收款已到账、通知与收付一一对应，或两边金额应该相等。[关系、时间与连接](../建模基础/02-关系时间与连接.md)

## 4. 金额方向：类型名称不能代替账户视角

| 要解释的金额 | 需要一起看的信息 |
|---|---|
| 资金流水发生额 | 所属资金账户、币种、动作类型、原流水号、操作前后余额及可用/冻结/挂账字段 |
| 保证金变化 | 保证金账户、触发动作、发生额与前后保证金余额，区分是否影响现金的类型标签 |
| 合约收付款 | 收付方向字段`Recv_Pymt_Dir_Cd`、收付状态`Recv_Pymt_Stat_Cd`、付款日与实际付款日、源合约/事件连接 |
| 跨账户或账户组汇总 | 转出与转入的身份对应、明细与汇总层、同币种及选定业务日 |

本次未核实收付方向/状态字段的完整本地码域与映射，不能借CD397的名称生成数值符号规则。已读收付SQL的金额方向还存在注释与表达式冲突，保留在[来源变体与证据冲突](../实现详解/03-来源变体与证据冲突.md)。

一个可操作的读法是：先选资金或保证金账户的那份流水，再用本页识别动作类别，核对本分支转码与状态，最后检查关系和金额方向。完整对象与字段案例见[资金划转与账户变动](../业务/02-资金划转与账户变动.md)。
