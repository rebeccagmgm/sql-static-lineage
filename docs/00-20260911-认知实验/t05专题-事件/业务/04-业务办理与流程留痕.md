# 业务办理、受理与流程留痕

## 1. 受理单、执行记录和步骤记录为什么分开

客户办理一项业务，先有受理对象，之后可能复核、执行、失败重试或停留在某个步骤。模型需要同时回答“办的是哪件事”“目前到哪一步”“谁执行过什么”。因此一件办理业务可能对应多种T05记录。

| 层次 | `pdata_n`模型入口 | 阅读粒度 |
|---|---|---|
| 受理主体 | `t05_nbo_busi_acpt_evt` | 受理单、业务类型、客户与最后停留步骤 |
| 受理执行 | `t05_nbo_busi_acpt_exec_evt` | 受理单关联的跑批执行情况 |
| 子任务执行 | `t05_nbo_busi_acpt_sub_task_exec_evt` | 子任务层；本次仅核对元数据入口 |
| 复核与步骤 | `t05_nbo_busi_acpt_revw_evt`、`t05_nbo_busi_acpt_revw_step_evt` | 复核单与复核步骤；不能与受理单计数相加 |
| 变更留痕 | `t05_nbo_busi_acpt_chg_evt`、`t05_nbo_busi_acpt_chg_log` | 受理单的变化或操作记录 |

## 2. NBO受理模型保留了哪些坐标

任务63314的源头包括 `ODATA_N_NBO.B_BUSINACPTFORM` 和 `S_BUSINACPTFORM`。模型保留 `Acpt_Id`、客户号、资金账户、业务类型/子类、受理状态、最后更新时间、最后及最大停留步骤，以及关联成交号和子任务号。

操作机构、所属机构和操作员工是不同字段。`Oper_Inr_Org_Id`与`Inr_Org_Id`分别按来源字段补零；不能据此认定两者必须相等。T04只负责另行解释这些机构对象，本专题不重建其组织树。

`B_`和`S_`来源必须按本任务实际查询理解：已读SQL分别处理历史与另一来源分支，不以命名前缀代替实际日期筛选。相同 `Acpt_Id`在不同来源或快照中的重叠，需要实测后才能去重。[63314](../../../attachments/04-业务办理与流程留痕/IMG-04-业务办理与流程留痕-20260914110158576.sql)

## 3. 执行记录不等于受理成功

任务82077把 `B_BATCHTASK`和`S_BATCHTASK`写入 `t05_nbo_busi_acpt_exec_evt`。事件号为 `NBO015-ACPT_ID`，`EXEC_STATUS`进入 `Acpt_Exec_Stat_Cd`；历史分支限定调度日，另一分支读取 `S_BATCHTASK`。目标按来源分区保留来源区别。

这说明执行层与受理层可以通过受理单坐标追查，但不能直接把两表 `Evt_Id`相等作为连接规则，更不能把“有执行记录”当作最终办理成功。重试是否留多条、同一受理号是否复用及状态终态含义，都需补充核验。[82077](../../../attachments/04-业务办理与流程留痕/IMG-04-业务办理与流程留痕-20260914110159499.sql)

## 4. OAS流转：排序号能标记本次记录，未必能长期追踪

`t05_proc_cir_evt`来源 `odata_n_oas.g_gf_oaitflowstep`，请求号使用 `OAS-docid`，事件号却使用 `OAS-row_number()`，按 `docid DESC`排序生成。多个步骤可能属于同一个请求；请求数量和步骤数量不是同一统计。

该SQL通过经办人显示名称匹配用户表，通过部门名称匹配部门对象。名称匹配没有提供唯一性保证；排序号也可能随快照变化。它适合说明当前导出的流转信息，却不能被直接包装为“稳定事件ID串起全部历史”的事实。[66114](../../../attachments/04-业务办理与流程留痕/IMG-04-业务办理与流程留痕-20260914110200923.sql)

## 5. 范围还包括哪些办理业务

全量元数据还包括非现场开户、网上开户订单步骤、账户控制变动、司法协助、程序化交易报备、利益分享申请、投顾TOF流程、TIT流程实例等。它们共享“办理事项与过程留痕”的理解方式，但各自的主体号、步骤号和状态体系需要单独核对。[逐表目录](../资料/逐表对象目录.md)

真正回答“为什么卡住”，应沿受理单或请求号检查最新状态、步骤与执行结果；字段中最后停留步骤的存在，并不证明某个当前业务真的停在该处。

## 字典补充：受理、执行和日志动作分开读

[状态与阶段矩阵](../字典/02-状态与阶段矩阵.md)将NBO受理状态按受理、复核、业务处理、补正、挽回、回访、签章分组，并单列执行状态。例如受理码1为受理成功，执行码1却为处理中。同域中带CC2备注的50暂存/51异常终止也未并入NBO。

OAO订单日志把源EVENT写入事件类型，RCC账户控制变动则按资产/证券来源写入不同固定类型。它们分别说明“记下哪个操作”和“控制哪类账户”，不能替代当前办理结果。[事件类型与模型对应](../字典/01-事件类型分组与模型对应.md)
