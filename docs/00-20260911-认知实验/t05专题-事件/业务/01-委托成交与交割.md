# 委托、成交、交割与申请确认

## 1. 先分清业务阶段

委托表达交易请求；成交表达撮合或交易结果；交割保存清算交收及费用等记录。一个委托可以涉及多次成交，业务也可能撤销或失败；实际连接基数需按来源核验。模型把这些记录分开，是为了保留阶段、时间和计量差异。

在 `pdata_n` 中，主要入口是 `t05_exch_scr_entr_evt`、`t05_exch_scr_mtch_evt`、`t05_exch_scr_deli_evt`。**三表不是一条已证实的“委托表加工出成交表，再加工出交割表”的任务链**；已读分支分别投影柜台的不同源表。

## 2. RCC：日期、账户与来源一起定义交易记录

| 模型 | 已读源对象 | 加工中的具体作用 |
|---|---|---|
| 场内证券委托 | `ODATA_N_RCC.H_HIS_ENTRUST` | 取调度日源分区，保留委托信息、客户/账户、来源和终端信息；市场与币种转码 |
| 场内证券成交，信用分支 | `ODATA_N_RCC.H_HIS_CRDTREALTIME` | `Evt_Id = RCC-CRD-INIT_DATE-POSITION_STR`；成交数量/价格/金额来自 `BUSINESS_AMOUNT/PRICE/BALANCE` |
| 证券交割 | `ODATA_N_RCC.H_HIS_DELIVER` | 保留交割、费用和处理状态；`REAL_STATUS` 经该目标字段的映射处理 |

成交分支有 `Entr_No`、`Mtch_Id`、`Mtch_Seq_No`、`Canc_Seri_No`、`Mtch_Stat_Cd`。这意味着同一委托编号不是成交唯一标识，源状态和冲销语义也不能从汇总前省略。

`Ast_Acct_Agt_Id` 取资金账户号，修饰符为 `10201`；证券账户协议修饰符进一步组合 `10101-市场-证券账户`。产品号使用 `RCC-市场-证券代码`。直接拿证券代码跨市场、跨来源 Join，或者将资金账户号与证券账户号当同一个键，会丢失模型身份。

本次没有证明委托与成交的完整复合 Join 键，也没有验证冲销处理后的净交易量。以上来自 [35754](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110158575.sql)、[37305](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110159444.sql)、[36301](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110200873.sql)，不把信用成交分支的规则套到全部RCC/ICC来源。

## 3. TA5：申请、总确认、确认明细

| 层次 | 模型与源表 | 身份和计量 |
|---|---|---|
| 申请 | `t05_ams_ta_trd_app_evt` ← `ODATA_N_TA5.D_TA_TREQUEST_IMP` | 租户、申请号、申请日、销售商和TA代码拼事件号；`F_SHARES/F_BALANCE`为申请份额/金额 |
| 总确认 | `t05_ams_ta_trd_cfm_evt` ← `ODATA_N_TA5.D_TA_TCONFIRM` | 租户 + `C_CSERIALNO`；`F_CONFIRMSHARES/F_CONFIRMBALANCE`为确认份额/金额 |
| 确认明细 | `t05_ams_ta_trd_cfm_det_evt` ← `ODATA_N_TA5.D_TA_TCONFIRMDETAIL_HIS` | 自身确认流水构造Evt_Id；`C_CSERIALNOTOTAL`按相同前缀构造Main_Evt_Id |

申请是业务意图，确认是处理结果，明细是结果拆分。申购、赎回、分红等还需结合各来源业务标志，不能见“确认表”就把所有记录算成赎回。

产品身份为 `TA5-TA代码-基金代码`。还有一个不能忽略的来源差异：申请的 `Pty_Id` 用 `TA5001-C_FUNDACCO`，总确认用 `TA5001-C_CUSTNO`；明细份额持有人又用 `TA5001-C_FUNDACCO`。同一前缀没有证明基金账户号与客户号相等。跨表回到T01时，需要补充对应关系核验，不能仅凭“当事人编号”直接合并。

总确认与明细有明确主事件字段，仍需检查所选日期和来源下的覆盖、重复及一对多；申请到确认不能拿两个 `Evt_Id` 直接相等。证据：[39802](../../../attachments/02-加工与分区/IMG-02-加工与分区-20260914110158583.sql)、[40632](../../../attachments/01-事件身份与模型表达/IMG-01-事件身份与模型表达-20260914110200312.sql)、[58387](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110201526.sql)。

## 4. FCT与XIR：不要套用柜台的一套身份

**期货成交**入口 `t05_futr_brok_mtch_evt` 来自 FCT 成交明细查询视图。SQL保留交易引擎日、实际交易日期/时间、交易所、成交编号、报单编号、投资者与账户；投资者号加 `FCT008-`，账户修饰符为 `10211`。价格和数量分别取 `PRICE`、`VOLUME`，没有生成通用 `Evt_Id`。

该分支用 `IF(TRIM(OFFSETFLAG) != '0', 'C', 'O')`形成开平标志，并另保留平仓类型；空值与异常值的实际表现尚未核验。交易类型按交易所分支解释；例如DCE的源类型另有CASE映射。不能把数量直接解释成证券股数，也不能无视交易所把源交易类型合并。`Prd_Id`仍直接取 `INSTRUMENTID`，SQL注释还保留规则待补的提示，因此与T02的正式映射未闭合。[91492](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110201992.sql)

**衡泰自营场外交易**入口 `t05_sb_otc_trd_main_info` 来自 `ODATA_N_XIR.T_TTRD_OTC_TRADE_T`，事件号为 `XIR442-INTORDID`。它同时保存委托数量/金额、已成交数量、成交净价金额、订单状态和结算日，并保留一级/二级资金与证券账户。资金账户修饰符分别为 `1020901/1020902`，证券账户为 `1010201/1010202`。这张“交易主信息”不能被当作纯成交明细，与子品种交易、费用或账户对象连接时要先确认层级。[66107](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110202206.sql)

## 5. 香港：保留独立来源与缺口

元数据中香港T05有客户成交、场外委托/成交、互换、外部期权、融资票据、回购及事件状态历史等对象。它们是独立物理模型，不能因名称相似直接套入内地RCC或TIT分区。

本次还读到一条历史SQL：任务28188写 `pdata_hk.t05_otc_real_mtch_evt`，来源 `ODATA_HK.HKDC_V_GTP_TRD_HIS_REALTIME`，交易日期取 `load_date`，发生日期取 `init_date`，字典使用 `pdata_hk.t99_cd_cvt_map`，且SQL已固化业务日期 `2026-08-27`。该目标名未在本次香港元数据的19条记录中命中，应记为“SQL可见、元数据未匹配”的来源变体，不据此认定现行主模型。[28188](../../../attachments/01-委托成交与交割/IMG-01-委托成交与交割-20260914110202355.sql)

## 6. 从本分支可以独立推理什么

统计“交易笔数”要先选择委托、成交还是交割；统计“申赎规模”要选申请或确认；追溯差异时，再沿源流水、主从关系和业务日期连接。一个字段叫“金额”，不足以证明它是同一阶段、同一币种、同一可加口径。

## 字典补充：成交类型与成交状态分别解释

[事件类型页](../字典/01-事件类型分组与模型对应.md)补充了TIT账簿成交模型中的场内交易与票据交易两类来源，SQL均固定写入对应码值。RCC成交则使用自己的状态域；[状态矩阵](../字典/02-状态与阶段矩阵.md)把明确RCC来源的成交、废单、确认与人工补充状态分开。不能把CD375的真实/虚拟成交标签直接绑定给这里所有FCT或RCC来源。
