# 风险合规、损失与经营事项

## 1. 风险记录不只有告警

T05覆盖异常交易告警、反洗钱审核/复评、适当性问卷、客户认证、操作风险损失、处置流程及版本。告警是识别结果，调查/审核是处理活动，损失是事件影响，版本是记录演变；不能用告警数量直接表示已确认风险或实际损失。

## 2. DRC操作风险：主事件、影响与版本

`pdata_n.t05_oper_risk_los_evt`来自 `ODATA_N_DRC.D_DCAR_LDC_EVENT`，用 `DRC001-ID`形成事件号，另保存业务损失事件编号 `EVENT_NO`。

源记录分别带入发生部门、发现部门、发起部门，以及发生日期、发现日期和最后更新时间。三个部门字段有不同业务职责，不应该在机构统计里任取一个替代。

金额也分层：`EXPECT_FINANCE_LOSS`进入预计损失，`CONFIRM_FINANCE_LOSS`进入确认损失，`ADJUSTED_FINANCE_LOSS`进入调整后财务损失。还有“是否有财务损失”“是否确认财务损失”等标志。回答已确认损失，必须结合状态、标志、金额和选定时点，不能把预计、确认、调整后金额求和。[110536](../../../attachments/06-风险合规与经营事项/IMG-06-风险合规与经营事项-20260914110158580.sql)

`t05_oper_risk_los_evt_ver_info`来自 `D_DCAR_LDC_EVENT_VERSION`，自身事件号 `DRC003-ID`，`Main_Evt_Id = DRC001-EVENT_ID`，并保存版本号、使用标志和更新内容。版本行是主事件的演变证据，不是又发生了一次损失。该导出固定读取 `2026-05-19`，不能用它证明当前版本。[110538](../../../attachments/06-风险合规与经营事项/IMG-06-风险合规与经营事项-20260914110159674.sql)

## 3. NBO适当性：做过测评与当前适当性是两件事

`pdata_n.t05_cust_elig_qstnn_evt`来自 `ODATA_N_NBO.S_ELIGTESTJOUR`，事件号使用 `NBO016-POSITION_STR`，保存交易日期、客户、办理信息及问卷相关字段，证件类型按来源映射。[88539](../../../attachments/06-风险合规与经营事项/IMG-06-风险合规与经营事项-20260914110201043.sql)

这说明模型保留一次测评办理记录。要回答客户当前适当性，需要确认测评结果、有效期、撤销/重测规则以及T01相关评价对象；本次没有将“有测评记录”自动解释为当前合格。

同样，`t05_otc_deri_cust_aml_manu_rat_evt`、`t05_aml_cust_risk_lvl_appr_evt`、`t05_aml_cust_risk_lvl_reval_evt`分别提示人工评级、审核和复评等不同活动，不能仅因表名都含风险等级便合并为一个事件类型。

## 4. 经营管理与技术运作也是主题范围

| 业务对象 | 已存在的模型例子 | 应避免的混淆 |
|---|---|---|
| 员工事项 | `t05_emp_atten_evt`、`t05_emp_leav_evt`、`t05_emp_leav_rec_evt` | 考勤、休假与离职备案不是同一个员工状态 |
| 财务与付款申请 | `t05_fin_bdgt_adj_app_evt`、`t05_fin_leas_comp_pymt_app_evt_det`、`t05_fms_bill_fir_onacct_evt` | 预算申请、付款申请和入账处于不同环节 |
| 经营协同流程 | `t05_bene_shr_app_proc`及奖励明细、`t05_ia_tof_proc`及节点任务 | 流程主体、明细和步骤分别计数 |
| 技术操作 | `t05_data_mdl_mgmt_oper_log`、`t05_bdp_user_data_righ_app_evt`、`t05_app_sys_chg_appr_evt` | 操作、权限申请和审批完成不是同一个事实 |
| 系统执行 | `t05_schd_cmd_log`、`t05_schd_sys_oper_log` | 业务事件表中的技术日志不等于当前任务运行核验结果 |

这一组来自物理字段目录的范围核对，尚未逐项深读生产SQL。保留这些对象，是为了呈现整个T05；不使用衍生品加工规则替代它们的来源规则。[逐表目录](../资料/逐表对象目录.md)
