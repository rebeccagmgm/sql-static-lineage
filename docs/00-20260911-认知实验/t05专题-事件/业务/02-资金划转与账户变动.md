# 资金划转、资金流水与保证金变化

## 1. 资金的三个观察位置

| 观察对象 | 回答什么 | 代表模型 |
|---|---|---|
| 支付或划款指令 | 打算划多少，谁复核，处理到哪一步？ | `pdata_n.t05_cstd_tran_instr_evt` |
| 收付款记录 | 哪笔合约或费用形成哪张收付记录，金额与状态是什么？ | `pdata_n.t05_otc_recv_pymt_evt` |
| 账户台账 | 账户的余额、可用、冻结或保证金怎样变化？ | `pdata_n.t05_otc_deri_cutp_fnd_chg_evt`、`pdata_n.t05_otc_deri_cutp_marg_chg_evt` |

三者可能围绕同一业务，但不代表同一笔可相加的金额。实际付款、收付处理、账户记账也不是同一个状态判断。

## 2. TIT保证金：一条台账记录怎样进入模型

保证金模型来自 `ODATA_N_TIT.D_MARGIN_ACCOUNT_LEDGER`。一行用 `TIT279-KEY_MRG_LEDGER_ID` 标识，保留账户、发生额、操作前后保证金余额、触发编号和触发变动类型。

源流水通过 `KEY_MRG_ACCT_ID`左连接 `D_MARGIN_ACCOUNT`，取得交易对手；对手方拼为 `TIT060-KEY_CTPTY_ID`，保证金账户协议修饰符为 `10219`。资金变动类型先查询目标表/字段、源表/字段、系统限定下的转码，找不到则保留 `MARGIN_ACTION_TYPE` 原值。

时间有三种：读入的源快照日是 `${data_day_str}`；发生日和目标业务分区取 `SRC_BUSI_DATE`；生效日取 `ACTUAL_BUSI_DATE`。另有 `D_MARGIN_ACCOUNT_LEDGER_TEMP` 限定业务日期集合，这份导出没有给出其生产过程，因此不能宣称已闭合重写分区的完整范围。

“操作后余额 − 操作前余额是否等于发生额”可以成为后续数据核验问题，但本次没有核对源台账行数据及方向规则，不能写成已验证恒等式。[173965](../../../attachments/01-事件身份与模型表达/IMG-01-事件身份与模型表达-20260914110158585.sql)

## 3. TIT资金：除了余额，还有可用、冻结和挂账

资金模型来自 `ODATA_N_TIT.D_CAPITAL_ACCOUNT_LEDGER`，用 `TIT280-KEY_CAP_LEDGER_ID`识别台账，保留原流水号；资金账户协议修饰符为 `10220`。同一记录分别保存发生金额、操作前后余额、可用金额、冻结金额以及挂账相关金额。

源字段 `LEDGER_TYPE` 经映射进入 `Evt_Stat_Cd`。这提醒我们：即便字段名字是“事件状态”，也不能直接套用报告成功失败或风险事件审核状态的含义。

资金和保证金两表记录不同账户维度；仅凭相同交易对手、相同发生日，无法证明两条记录是同一资金动作。触发号、原流水号等可以用于查关系，但没有唯一映射证据时应保持候选状态。[173966](../../../attachments/02-资金划转与账户变动/IMG-02-资金划转与账户变动-20260914110159330.sql)

## 4. CIS划款：指令主体与产品映射

`t05_cstd_tran_instr_evt`来自 `ODATA_N_CIS.P_TINS_ZLXX`。事件号为 `CIS007-L_ID`；此外分别保存指令编号、外部系统指令号、处理明细号、本方及对手账户、划款金额、划款日、申请/复核信息和拒绝原因。它首先是一条指令信息，不能只取划款金额就宣称已经到账。

这条SQL的产品映射尤其值得注意：原来关联MOT产品表的语句已被注释，实际使用 `ODATA_N_CAP.S_BIZ_PRO_PRD_BASE_INFO`：

```text
CIS.C_CPID = CAP.PRD_CODE
CAP.PRD_INNER_CODE → MOT-产品内部编码 → 模型Prd_Id
CAP限定：调度日快照，DELETED = '0'
```

因此 `MOT-` 是输出编号口径，不能据此前缀断言当前映射直接读取MOT源表。左连接未匹配时模型产品号为空，字段存在不代表映射覆盖完整。

目标仅按 `Src_Tbl`覆盖；主体源 `FROM ${src_table} A`处未写日期限制，CAP辅助表才显式限制日期。不能把这条实现简称为“主辅表都只取调度日”。[155354](../../../attachments/02-资金划转与账户变动/IMG-02-资金划转与账户变动-20260914110200823.sql)

## 字典补充：先区分资金动作、审核与汇总

[资金变动类型与关系方向](../字典/03-资金变动类型与关系方向.md)把CD397的65个原值分为12组。例如入金与入金审核、内转两端、账户组汇总分别列出，便于选择统计层次。TIT资金和保证金模型均存在转码未命中回退源值的规则，因此每个原动作是否落入某个仓库码值仍需转换明细；不能直接从“减少”“转出”等名称生成金额符号。
