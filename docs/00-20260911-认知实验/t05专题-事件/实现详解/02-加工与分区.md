# 加工与分区：事件表并不都是只追加流水

## 1. 先区分维护方式

| 方式 | 已读实现 | 对读者的影响 |
|---|---|---|
| 调度日源分区 → 目标日分区 | RCC成交37305、TA5确认40632 | 分区日来自任务投影，需与业务交易/确认日区别 |
| 按来源覆盖 | TIT存续事件124565/124566、费用计划207947 | 历史业务日期可以放在普通列；不能假设目标有Busi_Date分区 |
| 旧新比对并维护删除标志 | TA5申请39802、TIT收付104934 | 记录可能被更新或逻辑删除；不是只追加 |
| 关系有效期间 | TIT事件关系185098、RMS事件员工38361 | 同一关系随来源变化开闭有效期 |
| 读取回看窗口并写原日期 | OIS报告147451/169162 | 一次执行可能重写多个历史日期 |
| 从调度日快照改写业务发生日分区 | TIT保证金173965、成交回报202899 | 源采集日与目标业务日不一定一致 |
| 本次加工生成编号 | BSS57578、OAS66114 | 编号的跨次稳定性不能先验假定 |

这些是已读任务的实现，不是按表后缀推定的类型。

## 2. TA5申请：有TEMP/MID不代表时间拉链

任务39802先做当天申请投影，再与目标按 `Evt_Id`进行全连接比对，形成I/U/D/S。最终分别写入未变、更新、新增及删除记录；删除分支保留记录并设置 `Del_Flag='1'`和删除日期，其余分支设置 `0`。

目标按 `Src_Tbl`分区。它维护更新和逻辑删除，不是因出现MID表就自动成为 `Strt_Date/End_Date`版本拉链。模型内的冻结截至日、协议起止日也是业务字段，不能被错当成记录版本期间。[39802](../../../attachments/02-加工与分区/IMG-02-加工与分区-20260914110158583.sql)

## 3. TIT事件关系：这里才有明确关系有效区间

任务185098以通知事件号、收付事件号比对历史开链关系和当天源关系。历史有效条件是 `Strt_Date <= d AND End_Date > d`；新关系从d开链到 `2099-12-31`，删除关系于d闭链。

本分支的比较CASE只实际产生I/D/S；后续模板虽然包含 `IN ('I','U')`等写法，不能据此宣称已实现全部属性变更检测。它识别的是这条固定类型关系的出现、消失与保留。[185098](../../../attachments/02-加工与分区/IMG-02-加工与分区-20260914110200114.sql)

## 4. “每天更新”的注释需要落到真实条件

- 费用计划207947确实取调度日主辅表，但目标仅按来源覆盖。
- 托管指令155354在主体 `FROM ${src_table} A`处没有日期谓词，产品辅助表限定调度日。
- 保证金173965通过额外TEMP日期集合选择重写范围；该TEMP的生产不在本次导出内。
- OIS019在三个月窗口内按状态与更新时间分组去重，不能说每个配置只留一行。

因此“日增量”“每日全量”这样的元数据说明，必须对照源谓词、目标分区、覆盖方式和辅助对象再解释。

## 5. 静态SQL和调度执行的界限

附件中既有保留`${data_day_str}`等占位符的导出，也有已替换成日期的SQL。例如DRC版本是2026-05-19、MIO活动是2026-05-22、香港成交是2026-08-27。它们都是所取证据文本，不能互相代表当前生产版本。

SQL里的 `INSERT OVERWRITE`说明写法；不证明任务实际执行成功、数据已到达，也不证明当日分区完整。图谱中的调度邻居同样只能用作线索，不能补成数据因果。
