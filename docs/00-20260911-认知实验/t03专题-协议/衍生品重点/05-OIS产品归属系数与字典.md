# OIS：产品、销售归属、价差系数与源字典

OIS（OTC综合业务平台）中的产品信息、合约开发关系、客户归属和价差系数，解决的是不同业务问题。前者解释销售或发行了什么，归属解释由谁开发及怎样分配，系数提供管理计算的参数。它们不能全部归结为“销售收入表”，也不必全部进入 T03。

## 2. 收益凭证：产品身份、资金类型和支付规则分别表达什么

96673 读取 `O_OTC_INCOMECERTIFICATE` 当日数据，以 `prd_no` 连接证券基础信息的 `scr_cd`，连接分支限定 `src_id='OTC'`。这体现了一次从 OIS 产品编号到仓库证券产品身份的桥接。

对衍生品学习而言，收益凭证值得单独观察：发行产品本身、其收益挂钩条件、相关对冲交易，以及投资者资料，分别属于不同对象。本例证明产品资料进入 T02，不能据此把每一份收益凭证都当成 T03 的场外期权合约，也不能把产品编号当作对冲交易编号。

### 2.1 “代码”和“中文名”可以走不同的回退路径

资金类型的标准代码取自 `T02_PUB_COVT_CONST`，限制来源 OIS、常量类型 `var00512`，使用源 `fund_type` 匹配源常量码。中文名称则额外允许 OIS 源字典补齐：

```sql
fnd_type_cd = C.const_cd
fnd_type_name = COALESCE(C.const_cn_desc, D.dict_prompt)
```

其中 D 是 `G_OTC_DICTIONARY`，限定 `dict_entry='fund_types'`，用 `fund_type=subentry` 连接。

由此可以推导一个实际排查场景：标准常量未匹配，源字典匹配成功时，资金类型中文名可有值，标准代码仍为空。报表上“名称看着完整”不等于完成标准化。做聚合、维表连接或校验时，名称非空不能代替代码覆盖率。

这里的资金类型是该产品来源字段的语义，不应仅凭 `fund_type` 英文名解释成基金产品大类，或与期权结构类型混用。[[00-20260911-认知实验/t03专题-协议/证据/衍生品补充/SQL/96673.json|96673]]。

### 2.2 支付规则是解释资金时序的线索，但还不是现金流明细

所读 CASE 将 `BALLOON_PAYMENT` 标为一次性到期还本，`AMORTIZED_PAYMENT` 标为分期付息到期还本；远期联动标志 true/false 转 1/0，未匹配时没有给出同等含义的默认值。

这些标签帮助判断应该继续查哪类日期、付息计划和提前终止记录。要解释具体哪天付多少，仍需实际计划或流水及其计算来源；不能从这两个标签直接生成完整现金流。

提前终止来源在本地检索中同时关联产品信息与负债现金流目标，是值得沿着产品生命周期继续查的入口。本篇保留这两个候选位置，不宣称两条任务已经证明了同一笔产品终止后的完整现金流衔接。

## 3. 合约开发分成：先找到交易，再找到分成人

134215 的 OIS 源表 `O_CONTRACT_INTRODUCTION` 保存的是合约开发关系及分配比例。它进入 `T03_AGT_DIV_RATI`，但要把源合约与 TIT（场外衍生品投资管理系统）的合约身份对齐。

| 步骤 | 实际规则 | 业务含义 |
|---|---|---|
| 源合约找 TIT 交易 | OIS `CONTRACT_CODE` = TIT `INTERNAL_TRADE_ID` | 两套平台的显示编号与内部交易 ID 并不相同 |
| 确认交易种类 | 是否存在于互换、期权来源 | 决定 `20206/20207` 协议修饰符 |
| 确认书分支 | 对齐 `KEY_TRADE_COMFIRM_ID` | 有独立的 `20206-KST` 身份路径 |
| 找不到标准交易 | 编号 COALESCE 最终保留 OIS 合约代码 | 编号非空仍不证明标准身份成功，修饰符可能为空 |
| 人员桥接 | OIS 客户经理登录号连接 IOA 员工资料 | IOA 本地中文名为“企业门户2.0” |
| 未匹配人员 | `NVL(ERP_ID,CUSTOMER_MANAGER)` | 同一个目标编号字段可能混有员工号和源登录号 |
| 分配比例 | 直接投影 `ALLOCATION_PROPORTION` | 比例是来源值，不是这里计算的收入或支付额 |

编号与修饰符分别决策，应一起检查。不能先把编号 COALESCE 成功视为完成身份识别，再忽略修饰符为空。保留 `Src_Agt_Id` 可以返回源平台定位。

人员分支合并在职和删除用户资料，使用 UNION ALL，再筛选主部门及非空 ERP 编号。一个登录号是否只有一个匹配需要数据核对，不能因目标字段名是“编号”就默认唯一。

任务固定分成类型 `IB_CUST_DIV`、对象类型 `01`，源删除 Y/N 转 1/0。这些可作为本分支的已见编码，但本地尚未确认这两个字段各自完整的类型全集。比例直接传递也不意味着系统在此检查了分成合计 100%。[[00-20260911-认知实验/t03专题-协议/证据/SQL/134215.json|134215]]。

## 4. 客户级归属与合约级归属，实际按字段决定优先级

105743 中的消费逻辑使用多处 `COALESCE(ci.field,cpi.field)`，其中 ci 为合约级，cpi 为客户级。这不是“整条合约归属优先，否则整条客户归属兜底”。

例如合约级有部门 D1、姓名 NULL、比例 0，客户级有部门 D2、姓名甲、比例 0.5，逐字段选择的结果可能是 D1、甲、0。这个演示说明三个值可以来自不同层次；不是实际人员或业务数据。

源临时聚合又有 `ELSE ''`、`ELSE '0'`，这些并非 NULL，会阻止相应字段继续回退。因此归属缺失时，要分别查看关联是否成功、字段是否 NULL、是否已填空串或零。

该任务还读取 OIS 客户开发关系、合约开发关系及基础费率相关来源。仅仅存在费率表连接，不足以说明每个目标字段都使用了它的数值；有些连接可能为了经办人或组织归属。具体值来源仍应沿表达式看。

这条任务未在已读路径证明直接消费 `T03_AGT_DIV_RATI`。它与 134215 可用于业务对照，不能连成未经证实的一条物理流水线。[[00-20260911-认知实验/t03专题-协议/证据/SQL/105743.json|105743]]、[[00-20260911-认知实验/t03专题-协议/视角/TIT与OIS|原有销售归属深入分析]]。

## 5. 价差系数：临时、正式、去重和合约身份各有不同规则

补充证据边界：本次进一步检查 Input Pack/Facts，发现当前解析目标结构为 26 列、SELECT 投影为 29 列，输出字段绑定尚未完成。以下解释的是原始 SQL 的来源、表达式及筛选逻辑，不宣称这条任务已经完成全部字段的物理绑定或运行验收。[[00-20260911-认知实验/t03专题-协议/证据/衍生品补充/InputPack与Facts交叉核对.json|交叉核对]]。

246739 从 `G_CONTRACT_SPREAD_RATE_TEMP` 生成 `T99_DERI_COMP_SPRD_COEF_REF`。字段包含业务类型、系数类型、源合约类型及名称、源标的类型、价差计算类型、年化价差系数、绝对价差系数、生效日、审批事件编号、交易对手和拟稿人。

这些字段共同表达一项管理参数。年化价差系数与绝对价差系数是不同参数，不能混用为分成比例；审批事件编号提供追踪线索，也不等于本任务执行了审批或证明审批通过。

### 5.1 “取最新”究竟在什么范围内

窗口分组为：

```text
合约代码 + 系数类型 + 合约类型 + 价差计算类型
+ 年化价差系数 + 绝对价差系数
```

组内按更新时间降序取 RN=1。**系数值本身也是分组字段**，因此这是每种字段组合的最新记录，不是每份合约只留一组最新系数。若系数从 a 改成 b，这两种值组合仍可能各自保留一行，是否最终都保留还要看下面的正式表排除条件。

这种规则符合“保留尚未归档的不同参数组合”的实现形态，但是否完全对应业务期望，当前不能仅从代码推定已经验收。

### 5.2 正式表参与的是排除，不是给临时表补值

源临时记录先筛选 `IS_DELETED='N'` 和业务日，再用 NOT EXISTS 排除正式表 `O_CONTRACT_SPREAD_RATE` 中同一天、未删除且上述六项一致的记录。

```mermaid
flowchart LR
  T[临时系数有效记录] --> R[按六项分组取最近更新]
  F[正式系数有效记录] -.六项一致则排除.-> R
  R --> O[T99 保留的临时系数分支]
```

所以正式表“被 SQL 引用”是确定的，但这个分支的系数数值仍来自临时表。把表级依赖画成双方共同提供系数，容易误解来源。比较字段还没有包含生效日和源标的类型；它不是全行完全一致检查。比较用普通等号，含 NULL 时也不能擅自解释为自动相等。

### 5.3 身份回退与合约分成任务不一样

该任务在互换、期权识别成功时使用 TIT 交易 ID，确认书匹配时保留对应的源合约代码，未识别时填空。134215 却允许 Agt_Id 最终回退至源合约代码。

同一 OIS 合约在分成表有编号、在系数分支编号为空，并不必然是源系统丢了记录，可能是两条加工规则不同。应比较源 `CONTRACT_CODE`、匹配路径及修饰符，而不是只比较目标 Agt_Id。[[00-20260911-认知实验/t03专题-协议/证据/衍生品补充/SQL/246739.json|246739]]，48–124 行。

## 6. OIS 字典至少有三种使用方式

第一种是产品资金类型的 `G_OTC_DICTIONARY`，按字典入口和子项连接。第二种是客户综合视图的 `G_DICTIONS/G_DICTIONS_DETAILS`，还需与 FICC 分支区分来源。第三种是已整理到仓库字典的源产品类别，例如 CD081 中备注为 `OTC_DERIVATIVE_COUNTERPARTY.PROD_TYPE` 的记录。

216975 对客户性质 `xz`、注册国家 `nation` 的字典连接，同时使用来源标签、类别和码值。这意味着同一个码值在不同来源或类别下不能随意共享中文含义。

它对行业代码还有一个细节：读取 `REF_CD_CVT_MAP` 后取的是 `SRC_CD_VAL/SRC_CD_DESC` 来解释源行业，不能因为使用了转换表，就说输出已经换成标准仓库行业码。

CD081 的产品类别在此解释的是**作为客户出现的产品载体**，包含银行理财、私募基金、信托产品及不同机构的资管计划等；不是标的股票/债券分类，也不是雪球/香草期权结构分类。完整的 14 个本地命中值见 [[00-20260911-认知实验/t03专题-协议/衍生品重点/06-字典与映射逐层解读|字典逐层解读]]。

## 7. 用业务问题选择下一张表

问“卖的是什么”，从 T02 产品及产品编号桥接开始；问“哪份交易”，转向 TIT 交易身份；问“谁开发、分给谁”，看 OIS 开发关系及人员映射；问“为什么取这个系数”，看参数类型、有效日、临时正式关系及去重范围；问“收入是多少”，则必须继续找实际消费这些参数的计算任务。

产品、交易、归属、参数、计算结果这五层连接起来，才能解释业务。但只有已被 SQL 或明确关系证实的连接，才能画成物理数据链。
