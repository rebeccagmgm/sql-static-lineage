### 覆盖状态进一步区分

- **结构与代表加工已说明**：柜台资金/证券、XPB子账户、STA登记/渠道、TA5份额、场外交易重点、租赁合同/批次/现金流等；不表示全来源已验收。
- **独立结构已补代表源加工**：XIR一级/二级资金与证券账户、两级余额历史及业务余额、CVS托管股东层级、CIS周期划款、深圳股票期权和黄金延期。源对象、身份、映射、计量与时间在[[00-20260911-认知实验/t03专题-协议/实现详解/账户/自营与托管账户|自营与托管账户详解]]展开。
- **独立结构加工仍有缺口**：托管对账64053关键SQL压缩且混有行注释，未确认完整语义；自营股东登记其他来源、B21关系生产和父产品业务定义仍缺。测试schema消费者146124仅作历史消费示例，不等于当前生产消费。
- **可按同一模型的来源变体继续核验**：TA5/TA6等既有目标模型的来源分支；同模型仅提供共用字段结构，不能证明拼键、转码、日期完全相同。
- **是否同构仍未证实**：HPB/GPB全账户结构不能套XPB；其他订单类型也不能从共用T03_ORD就推断业务流程相同。

自营与托管分支后续已定向补读13份上下文，其中11份用于具体解释，64053与119831仅保留受限或排除证据。下面27份是此前批次，不能代表当前全部案例。两批共40份，37份用于选择性解读，3份为受限候选；不等于全部字段或来源已验收。

## 3. 旧候选索引的修正

继续调查时发现旧资料索引存在两处抽取问题：默认库名 `PDATA_N/pdata_n` 没有统一比较；空库名头部的匹配跨到了下一行，误将 `-- source: SQL_MCP` 当作库名。

本轮直接回 SQLite 纠正头部值，仅读取同一行、将非空库名转小写。相同的词法候选据此重新关联：256 个可解析对象中，未命中明确库范围内写候选由 69 个变为 **26 个**，未命中读候选由 122 个变为 **117 个**。这些数量仍不是已核验生产者/消费者数量。

288 个任务的默认库为空，未通过任务名强行归到 PDATA_N；其中同名未限定写入在映射 JSON 中以 `unknown_schema_write_candidates` 单独记录。因而托管、采购等正文有逻辑 SQL 案例，不等于该案例在严格物理索引中已经有唯一库身份，两者并不冲突。

更新后的 [[00-20260911-认知实验/t03专题-协议/证据/逐表SQL候选覆盖|逐表候选覆盖]] 和 [[00-20260911-认知实验/t03专题-协议/证据/逐表SQL候选映射.json|完整映射]] 均说明这一边界。索引的修正补回了已有资料，不代表新增采集了一批生产任务。

## 4. 如何理解“本轮完成”

本轮形成了整个主题的统一对象层次、主要分支的代表加工与消费推导，并把 TIT/OIS 进一步穿透到贴源关系和字段证据。它不是所有物理表、来源变体、字典、运行和下游的全量验收。剩余工作可按上表的具体分支继续，而不应再用泛泛的“其他业务”掩盖空白。
