## 3. 如何回到原始证据

SQL 文件保留任务 ID、获取时间、完整原始 payload 的 SHA-256 和带原行号的 SQL 上下文。展示上下文省略前部连接及任务头信息；哈希对应 SQLite 完整 payload，不对应截取后的 JSON 文件。调度 SQL 库位置与字段见 [[local-sqlite-guide|本地 SQLite 导航]]。

旧稿图证据继续使用 [[00-20260911-认知实验/t03专题-协议/证据/图谱-账簿下游.json|账簿下游]]、[[00-20260911-认知实验/t03专题-协议/证据/图谱-互换上游.json|互换上游]]、[[00-20260911-认知实验/t03专题-协议/证据/图谱-分成字段.json|分成字段]]。本轮 Mermaid 是带业务说明的阅读图，未冒充新发布的图谱投影。字段比例值来源与身份 Join 的区别仍以原字段证据为基础。

## 4. 明确保留的缺口

- 246739 的 SELECT 29列与目标结构26列不一致，Facts没有可证明的输出绑定；147452窗口框架及107018临时对象schema也仍有明确缺口。

- 主协议对象及协议条件到逐笔交易的完整物理连接仍未闭合；源里存在相关对象不等于已经形成统一链。
- CD631 缺 13/14；部分收付款和观察属性的完整字典仍未取得。SQL 常量可以解释分支用途，不能补造正式字典名称。
- 10 行转换表样例不含 TIT/OIS；因此仍未取得这两个来源的完整源值→标准值实值集合。
- 规则表没有证明执行引擎的 AND/OR、优先级、冲突处理；公式文本没有证明可复算。
- 样例并未测量全部关联唯一性、字段填充率、金额正确性或生产运行结果。
- OIS 产品提前终止、附件和部分台账仍是清晰标记的候选入口，未冒充逐字段解读完成。
