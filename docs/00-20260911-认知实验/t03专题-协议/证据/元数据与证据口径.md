# T03元数据与证据口径

## 4. 为什么出现四组不同数量

物理元数据的 1,073 条是跨平台和 schema 的记录；其中 Hive / pdata_n 有 346 条，256 条解析成功，90 条不支持解析。其他记录中有 spdata、临时 schema、业务数据集及其他数据库。不能把后缀近似的名字合成一张，也不能只用“有字段的 256 张”代表整个 T03。

平台目录的 546 个 GUID 使用另一套资产身份；分类关系还有 1,441 条，因为同一个资产可以在多个分类轴出现。当前目录采集是 PARTIAL，故这些数字只代表本地已采集范围。目录中的委托成交、结算台账、客户签约、客户风险、采购合同、系统配置等路径，能帮助发现被遗漏的业务分支，但目录标签本身不证明行粒度或模型边界。

SQL 文本命中的 2,348 个候选也不能当成生产任务总数。注释里出现表名、读取旧目标表来做历史维护、不同默认 schema、同一目标有多个来源任务，都会增加命中。已读任务 103935 中，关系 A17 的分支有效，而后面的 N01 分支处于注释中，这是不能把关键词扫描直接升级为血缘的具体例子。

调度目录则有 EDW_AGT 1,319、SEDW_AGT 208 个条目，采集观察日期为 2026-09-04。周期分别是每日 1,289 / 198、手工 30 / 10；状态列为空。它说明主题下有哪些调度登记，不说明当日运行、启停、到数或业务验收。也不能根据主题名直接把它与 pdata_n 或 spdata_n 做一一对应。
