# 交叉矩阵：把业务、模型、来源与实现连起来

阅读位置：[[00-20260911-认知实验/t03专题-协议/README|第三步]]。先完成单维度学习，再用本页横向串联。行按业务对象分支定位，列观察不同方面；这张矩阵不是官方分类，也不证明每个来源都已覆盖全部模型。

## 先用一个对象练习

以TIT普通互换为例：

| 维度 | 同一对象的不同观察 |
|---|---|
| 业务 | 一份互换约定及其收益、支付组成 |
| 模型 | 通用身份、互换主信息、腿、持仓、账户及主体关系 |
| 来源 | TIT的互换要素、交易主信息、腿和持仓等源对象；OIS的合约开发关系可补分成信息 |
| 加工 | 普通互换以交易ID构造20206身份，腿保留自己的标识；OIS合约关系需桥接TIT身份 |
| 消费 | 某个互换标的消费分支会继续筛状态、关联账簿、收益腿与持仓，输出范围由其条件决定 |

所以，知道“来自TIT”仍不足以知道“在讲哪一层对象”；知道“是互换”也不足以知道“这一行是合约、腿还是持仓”。矩阵用于让这些信息同时成立。具体证据见[[00-20260911-认知实验/t03专题-协议/衍生品重点/00-模型层与贴源层如何对应|TIT/OIS对应链]]。
