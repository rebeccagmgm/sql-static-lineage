# 加工与消费维度：源记录怎样变成模型，模型怎样形成业务结果

阅读目标：先认识加工的作用，再按需要核对具体SQL。业务对象说明现实中是什么，模型说明保存什么信息，加工则说明这份实现如何选择和组织源记录。

## 一份任务通常要解决哪些问题

| 加工动作 | 实际改变什么 | 已读例子 |
|---|---|---|
| 选择来源与记录 | 哪些记录有资格进入目标 | RCC/ICC资产账户合并时，ICC分支排除同日RCC已存在的账号 |
| 构造身份 | 源编号怎样在模型中被识别 | 证券账户把资金账号放编号列，把市场和证券账号拼入修饰符 |
| 关联补充 | 目标的一行从哪些对象取得不同属性 | XPB以子账户ID定位，资金账号取父账户，产品沿父账户关系取得 |
| 转换代码 | 原系统的值怎样表达为仓库代码 | 按目标字段及来源条件查转换，未命中可能保留原值 |
| 维护日期与历史 | 新旧记录怎样保留、覆盖或形成区间 | 状态历史可能开链闭链；通用AGT的维护不一定采用相同区间方式 |
| 组织下游结果 | 为某个业务用途重新筛选、连接或汇总 | 互换标的消费继续关联账簿、腿及持仓，按其条件形成输出 |

这些不是每份任务都包含的固定步骤，也不意味着SQL写入成功就证明业务运行结果正确。学习重点是看每个动作对输出身份、内容、范围和时间的影响。

## 一个例子：为什么“取自哪个源表”还不够

如果只说 `T03_PB_FND_ACCT` 来自XPB子账户表，读者会以为账号、产品、类型都来自子账户。实际任务从子账户出发，关联父账户拿账号及类型，再关联产品—账户关系及产品表拿产品代码。一个目标行汇集了多个源对象，目标身份仍取子账户ID。

所以加工逻辑不只是字段翻译，还包括对象连接与记录选择。具体代码放在[[00-20260911-认知实验/t03专题-协议/实现详解/账户/柜台与PB账户|柜台与PB加工]]；先读业务背景，再核对这些连接更容易判断它们是否合理。

## 入模与消费分开

入模任务将源对象表达为某种模型。消费任务为报表、管理归属、标的分析等需求重新组织它们。一个合约能进入主表，不等于一定进入某个下游：下游的状态过滤、必需关联和日期条件都可能缩小范围。

反过来，下游关联到多个腿或多个标的，也可能从一份合约产生多行。此时要先知道结果在描述“合约”“腿”还是“标的持仓”，再判断数量或金额如何使用。
