# 来源职责维度：谁提供哪一部分信息

阅读目标：固定来源系统，理解它管理哪些源对象、各对象承担什么职责。先认识系统内的对象层级，再追踪具体字段入模；来源代码不是业务对象类型。

## TIT：交易、结构、账户与管理范围

TIT的本地代码域中文名是“场外衍生品投资管理系统”。已读源对象可以这样理解：

| 源对象层次 | 代表源表 | 提供什么 |
|---|---|---|
| 交易身份 | `D_TRD_OTC_TRADE` | 交易ID、工具ID等桥接信息 |
| 交易条件 | `D_REF_TRS`、`D_REF_OTC_OPTION_DEAL` | 互换或期权的交易约定及状态等 |
| 内部结构 | `D_REF_TRS_LEG`、`D_REF_INS_OPTION_INFO` | 腿或期权工具层信息，各有自己的标识 |
| 账户及账簿 | `D_CAPITAL_ACCOUNT`、`D_REF_BOOK` | 资金账户和交易管理上下文 |
| 持仓及组合管理 | 腿历史持仓、组合成员与账户映射 | 某时点的持有信息，以及哪些交易、账户属于管理范围 |

这些层次可能直接提供T03不同模型，也可能先通过工具—交易关系取得身份。普通互换、极速互换和KST确认书又有不同来源分支。需要业务背景时读[[00-20260911-认知实验/t03专题-协议/衍生品重点/01-一笔衍生品交易如何贯穿模型|互换贯穿例子]]；已经理解对象、要核对实际来源时，按问题查[[00-20260911-认知实验/t03专题-协议/衍生品重点/02-TIT交易结构与存续期|TIT交易结构]]或[[00-20260911-认知实验/t03专题-协议/衍生品重点/03-TIT履保账簿映射与结算|账簿履保]]。

## OIS：客户条件、运营安排与归属信息

OIS的本地代码域中文名是“OTC综合业务平台”。已读对象包含客户资料及条件、报告配置与执行、产品、合约开发关系和价差系数。这里首先要辨认配置、关系和执行记录的区别：配置说明应怎样处理，执行记录说明某次处理情况，开发关系说明业务归属。

这些内容跨主题落地：客户资料与部分条件到T01，产品到T02，合约分成到T03，报告执行到T05，管理归属和参数还涉及T98/T99。因此学习OIS时要看完整业务分工，再辨认哪些部分属于T03，不能先按目标前缀删去上下文。

详细见[[00-20260911-认知实验/t03专题-协议/衍生品重点/04-OIS主体准入协议与运营|OIS准入与运营]]、[[00-20260911-认知实验/t03专题-协议/衍生品重点/05-OIS产品归属系数与字典|OIS产品归属与系数]]。

## 其他来源：按职责对照

- RCC/ICC提供柜台账户、信用交易等来源；跨系统重叠记录的选择属于后续加工问题。
- XPB提供PB父子账户与产品关联；GPB和HPB是另外的来源，不能由XPB结构推定它们相同。
- STA/TA5帮助区分基金登记、渠道与份额；XIR提供自营账户及持仓层级。
- CRM、GCM、GLM等提供服务、合同及履行信息，业务对象与交易系统不完全相同。

中文名称与既有职责表保留在[[00-20260911-认知实验/t03专题-协议/00-全貌与证据边界#5. 来源系统要带着业务职责理解|全貌第五节]]，扩展来源名称及具体证据见相应业务正文。本页仅归纳已读职责，不把资料范围当成各系统的完整功能清单。
