# 字典如何帮助理解 T03：先读代码域，再读码值

本篇供业务阅读中查码使用：对象类型回答“是什么”，分类维度回答“按什么角度看”，状态回答某方面的情况，额度与权限表达约束。需要先有具体业务对象，再选择相应代码域，不能把所有码值拼成统一业务流程。

## 1. 字典要嵌入解释链，不能只做一个翻译附件

面对 `Agt_Clas_Cd` 或 `Agt_Stat_Cd`，只把值翻成中文仍不足以说明业务。完整链条是：字段属于哪个代码域，是否还受类型字段限定，来自哪个系统与源字段，是否经过转换，码值快照的日期和备注是什么，消费者又怎样使用它。

本地资产 SQLite 中，`ref_dw_cd_list` 描述代码域，`code_values` 保存代码含义，其资料来源对应 `REF_DW_CD_VAL`。它与 `REF_CD_CVT_MAP` 不同：后者描述源代码如何转换成仓库代码。当前本地未确认独立导入了转换表行数据。因此能读到目标码值的含义，不等于能够枚举每个源系统的全部转换对照。

本稿选取 39 个相关代码域，导出 1,047 行本地码值；快照状态为 UNVERIFIED。每行保留代码域、码值、描述、备注、来源和业务日期。`业务日期` 是该字典记录上的字段，不直接等于法律或业务规则的生效日，也不意味着所有代码截至这一天完成最新核验。见[[00-20260911-认知实验/t03专题-协议/字典/代码域索引|代码域索引]]。

## 2. 类别、业务类型、分类是三个层次

| 层次 | 字段及代码域 | 典型内容 | 应怎样使用 |
|---|---|---|---|
| 大类别 | Agt_Cate_Cd / CD038 | 101交易账户、102资金账户、202场外合约 | 快速确定大范围 |
| 协议类型 | Agt_Type_Cd / CD039 | 10101沪深证券账户、20206互换、20411账簿 | 确定对象种类和可能的身份规则 |
| 分类维度 | Agt_Clas_Type_Cd / CD632 | 05场外合约业务类型、06 SBL合约类型、07 SBL结算类型 | 指定“按什么问题分类” |
| 分类结果 | Agt_Clas_Cd / CD799 | AB_MAIN、DAD、FOP等 | 在维度与来源范围内解释结果 |

CD799 的 `AB_MAIN=主合约` 备注限定分类类型 05；`DAD=见款付券`、`FOP=纯券过户` 限定类型 07。它们不是同一条业务轴上的互斥值。不能按分类结果直接画一个包含“主合约、见款付券、纯券过户”的单层树。

同域中还包含 `1=存量合约`、`2=逾期合约`、`3=增量合约`，备注指向类型 08；另有 `ATTR_DSZH=对手账户`、`ATTR_WTRZH=委托人账户`、`ATTR_ZYZH=自有账户` 等记录，备注未给出同等明确的类型限定。后者不能为了填满矩阵而按名称猜一个类型。码值真实命中与类型关系已确认要分别记录。

来源日期也不同：主合约记录为 2023-07-11，SBL 结算方式为 2024-01-02，1/2/3 为 2025-03-20，ATTR 系列为 2026-07-24。一个分类域本身包含多年维护积累，不能把它解释成一次性设计的整齐枚举。

## 3. 状态不是一条从草稿到终止的通用流程

CD040 有 21 个状态类型，包括协议状态、展期状态、预处理状态、PB 期货自动平仓状态、指定状态、中登账户状态和支付状态等。CD041 有 288 行码值，本地能查到正常、生效、冻结、挂失、销户、暂停买、暂停卖、休眠等，也有交易、审核等相关状态。

这些值来自不同业务对象和维护时期。没有生产转换与状态变化记录，就不能把 288 个值按中文排成全域生命周期。状态码大小没有保证时序，源系统同名“正常”也不保证映射到同一业务含义。

任务 103937 给出一条具体链：期权源 `D_REF_OTC_OPTION_DEAL.CONTR_STATUS` 经目标 `T03_AGT_STAT_H.Agt_Stat_Cd` 的转换配置写入，状态类型固定 10。该任务只能证明期权这一分支的主状态历史，不能代表所有状态类型都在同一任务维护。

更细的消费者例子是 107018，它排除 `230,254,253,218,255`。本地 CD041 的对应命中如下：

| 代码 | 本地含义 | 备注及日期 | 本文判断 |
|---|---|---|---|
| 218 | 作废 | 2020-10-22 | 可报告本地词义，实际转换仍以任务为准 |
| 230 | 未处理 | **备注：定投合约状态**；2021-02-08 | 与互换消费者场景存在语境差异，不能直接宣称“互换未处理” |
| 253 | 待交易 | 2023-05-12 | 结合过滤可以理解为排除某些未进入目标业务阶段的记录，但不是完整流程证明 |
| 254 | 待审核交易 | 2023-05-12 | 同上 |
| 255 | 草稿在途 | 2023-05-12 | 同上 |

这正是字典与 SQL 联读产生的价值：不只是为过滤条件补中文，也能发现解释边界。对于 230，需要源状态转换配置或业务口径进一步确认。本稿保留原码值和备注，没有把它改写成听起来顺畅的互换流程。[[00-20260911-认知实验/t03专题-协议/证据/SQL/107018.json|107018]] 155 行、[[00-20260911-认知实验/t03专题-协议/证据/SQL/103937.json|103937]] 31–50 行。

## 4. 关系域帮助分角色，不自动确定方向

CD050 区分持有人、销售商、出借方、交易对手、保证人等；CD051 则区分账户与合约、合约与账簿等关系。本次核心命中有 `A17=资产账户与场外互换合约`、`N03=场外互换合约与账簿协议`。

但 A17 在 103935 中左端实际是互换，右端才是账户。关系词义不能替代字段方向。此外 103935 注释中的 N01 与当前字典 `N01=投顾订单与投顾合约`（2024-07-05）不能直接拼成有效关系：注释本来就不是活动分支，不同快照语境又可能存在差异。本文不据此宣称字典错误，只说明不得将注释、码值与实际加工不加区分地合成结论。

## 5. 额度、权限、担保比例：看起来都是数字或开关，业务含义不同

CD078 的额度类型包括综合业务授信总额度、融资回购最大额度、当日开放额度、已用额度、融资额度上限、融券额度上限等。它们同时存在，说明同一协议可以从“授权多少”“开放多少”“已使用多少”等不同维度记录额度。

因此，计算剩余额度之前，必须明确总额和已用额是否同币种、同业务范围、同时间，以及是否确实具有减法关系。不能把所有额度类型加总称为“总授信”。词义相近也不表示彼此互斥，例如综合授信与融资额度可能处于不同范围。

CD079 的权限类别包含业务权限、扩展业务权限、市场权限、委托方向权限、证券类别权限和算法交易类型权限等。它告诉读者权限针对什么方面，不直接告诉每一位、每个字符串值代表允许还是禁止。权限字段若为组合编码或位串，还需对应 SQL 与源定义；码值域无法自动解开未采集的位含义。

维持担保比例、保证金比例、折算率和额度也不可混为一谈。比例用于衡量或计算，额度限制业务规模，余额记录存量，权限决定能否办理某类业务。目录中 `AGT_KEEP_ASS_PROP_H`、`AGT_LMT_H`、`AGT_RIGH_H` 分开，正是不同问题的表达，不应为了减少章节而合并成笼统“风控信息”。

## 6. “统计信息”未必可统计求和

CD146 协议统计信息类型里有首次投资日期、UFT节点、原席位信息、交易对手保证金账户、账簿柜台、账簿所属部门、账簿所属公司、场外合约内部合约号等。它实际承担了一部分通用信息槽位的功能，里面可能是日期、标识或文本。

107018 取类型 09 的 `Stati_Cont_Desc` 作为内部合约编号，是一个明确的消费例子。若只见到 `STATI_INFO` 就把内容当统计数值，会把合约号转换为数值甚至求和。正确做法是先用类型字段筛出语义，再决定内容字段的类型和使用方式。

同样，重要日期域 CD1109 与期限域 CD499 只提供日期类型和期限类型语义；审批生效、应付、实际支付、定价起止和仓库有效期不能因为都叫 Date 就互相代替。

## 7. 源码回退使“标准字段”里可能保留源值

在 103941、103937、163771 等任务中，多处写法为：

```sql
NVL(mapping.DW_CD_VAL, source.CONTR_STATUS)
```

这明确意味着转换未命中时保留源状态值。目标字段名称标准化了，内容却不保证全量转成仓库码。当前没有转换表行数据和业务行，无法计算映射覆盖率，也不能把目标中的任意代码都拿到统一字典强行翻译。

不同于这类回退，有些 CASE 对未知值填空，有些保留原值；例如账簿 Y/N 开关在 105382 中映射为 1/0、其他值原样保留，互换腿部分标志在未知时填空。空值、未知和源值保留三种结果在数据质量判断中不等价。

若业务需要可解释报表，理想输出应同时保留原值、仓库值、转换命中状态及来源。这是由当前证据得出的消费建议，本次没有修改生产任务或宣称这些字段已经存在。

## 8. 缺失也应明确留在字典索引

导出的 CD1105 协议组状态、CD2242 协议组类别有代码域定义但本地未命中码值。核心选择中没有按完全同名找到独立 `ORD_STAT_CD`、`COMP_STAT_CD`、`DIV_TYPE_CD`、`DIV_OBJ_TYPE_CD` 的定义，不能由此断言整个仓库没有这些语义：可能复用通用域，也可能采用不同英文名，或本地采集不全。

例如分成任务中明确写出 `IB_CUST_DIV` 和 `01`，SQL 能证明这是该分支的常量，但码值全集及所有来源解释尚未确认。正文会从源表用途和投影说明分成，不会把一个样本常量扩展成完整字典。
