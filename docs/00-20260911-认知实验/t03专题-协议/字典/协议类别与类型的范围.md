## 2. 类型字典揭示了哪些业务范围

101/102账户类区分了不同业务与系统中的登记、资金和管理对象：同样叫证券账户，可以分==柜台、自营、资管、托管==；同样叫资金账户，也会区分==内外部层级、保证金、结算、银行或虚拟账户==。

201/202/203合约类区分==交易与业务安排==。例如20101融资融券合同与20102融资融券合约分别登记，20109转融通资格合同与2010801/2010802逐笔借入/出借也分别登记。字典提供对象区别，实际生命周期与相互连接仍需SQL和业务证据。

204并不只包含日常理解的“其他合同”：订单、保单、账簿、投资组合、服务签约及租赁借款等都在其中。这正是理解T03广义“协议”需要跨过的一步：它采用共同身份表达，并没有把这些对象变成相同业务。

有些类型还带细分码，例如10102及1010201/1010202、20402及其订单细类。下文会同时列出，**145条不是145个互斥的最末级类型**。源码也不能靠截取前几位就自动认定完整业务父子关系。

两个实际差异特别值得保留：

## 4. 字典、映射、分类、图谱分别补哪一层

| 资料 | 能回答的问题 | 不能代替的证据 |
|---|---|---|
| CD038 / CD039码值 | 本地定义了哪些类别与类型、名称是什么 | 不证明每个类型都已在业务行中出现 |
| REF_CD_CVT_MAP实值与SQL转换条件 | 某来源字段的值怎样对应模型值，适用哪个目标字段 | 不能只按源值跨代码域解释；条件索引也不是映射实值 |
| 表自身的平台分类 | 表被登记在客户账户、合约、持仓、结算等哪个业务目录 | 它分类的是表资产，不是表内每行的Agt_Type_Cd |
| 任务SQL | 哪个源对象进入哪个目标，类型常量、身份构造、过滤与历史维护 | 不证明实际到数、码值频率及唯一性 |
| 图谱 | 从目标表定位生产任务、相关源与下游，继续追踪字段 | 一个类型不必对应一张表；表级边也不自动给出每种类型的来源 |
| 有界样例 | 样例中实际出现了哪些值与填充形态 | 十条样例无法证明完整类型集合或全量缺失 |

本地已取得REF_DW_CD_VAL对应字典。REF_CD_CVT_MAP仅有部分样例及SQL配置索引，尚无TIT/OIS完整实值集合。因此目前可以完整列出这个类型字典，但不能宣称完成所有类型的“来源→映射→目标→消费”核验。字典快照状态为UNVERIFIED，记录日期也各不相同。

## 5. 为什么列完类型，仍没有列完所有T03信息

一种互换类型20206可以对应通用身份、互换主信息、腿、关系、持仓等多张表；一张T03_AGT也可以容纳多种账户和合约身份。类型与表是两个维度。

此外，状态、分类、协议组关系、观察要素、余额、权限等表描述对象的某一方面，它们不必各自成为CD039中的一种新协议类型。回答“T03全部包含什么”需要两层清单：**先列协议对象类型，再列围绕各类型组织的信息模型。** 本篇完成第一层的本地枚举；第二层结合[[00-20260911-认知实验/t03专题-协议/资料/逐表对象目录|逐表目录]]和[[00-20260911-认知实验/t03专题-协议/00-全貌与证据边界|全貌的信息分工]]阅读。
