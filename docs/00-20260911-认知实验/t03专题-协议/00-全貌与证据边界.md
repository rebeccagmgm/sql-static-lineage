# T03全貌：先认识业务范围与主要联系

**T03围绕账户、合约、合同、订单和管理对象，保存它们的身份、内容、关联及存续信息。** 读完本篇，应能说清T03的主要对象及联系；随后沿[[00-20260911-认知实验/t03专题-协议/README|单维度学习路径]]逐项深入，最后用交叉矩阵串联。

## 1. 先把分类维度分开

| 维度 | 回答什么 | 例子 | 在本文怎样使用 |
|---|---|---|---|
| 业务对象 | 正在描述什么业务对象？ | 资金账户、互换合约、保险订单、账簿 | 作为主要阅读入口 |
| 模型表达 | 正在保存这个对象的哪一方面？ | 身份、名称/状态、关系、内部结构、持仓、控制参数 | 在每个业务对象内部展开；不是另一个业务目录 |
| 对象的分类属性 | 这个对象按某个分类维度取什么值？ | `Agt_Cate_Cd`、`Agt_Type_Cd`、`Agt_Clas_Type_Cd + Agt_Clas_Cd` | 查对应字典及适用范围；字段分类不等于目录分类 |
| 来源系统 | 哪个系统提供这些信息？ | TIT、OIS、RCC、XPB | 在对象行内标明，同一模型可有多个来源 |
| 加工与消费 | 源记录怎样变成模型，下游怎样使用？ | 拼键、转码、Join、历史维护、聚合 | 作为对象下的实现详解，按问题查阅 |

它们可以交叉，但不能排成“账户、状态、TIT、历史维护”这样一组并列类别。比如一份互换属于业务对象，合约状态属于它的信息，TIT是来源，状态转码是加工：四者描述的是不同问题。

本页的业务分组是阅读导航。模型自己的类别/类型原名与完整范围见[[00-20260911-认知实验/t03专题-协议/字典/协议类别与类型完整树|协议字典树]]：CD038有9条类别、CD039有145条类型，包含上层与细分值，不能直接等同业务表数量。平台给表贴的资产标签另见[[00-20260911-认知实验/t03专题-协议/资料/平台分类说明|平台分类说明]]。

## 2. T03主要管哪些对象

| 对象 | 在业务中负责什么 |
|---|---|
| 账户 | 定位办理、登记和核算范围，例如资金账户、证券账户、基金登记账户 |
| 交易合约 | 记录某份具体交易约定，以及它的组成和存续情况，例如两融、互换、期权 |
| 服务签约与经营合同 | 记录服务或经营安排，后续通过计费、放款、提款、付款等明细履行 |
| 订单与办理 | 记录提出了什么请求、怎样处理、办到哪一步 |
| 管理对象与安排 | 组织哪些账户或交易一起管理，例如账簿、资产单元、投资计划与保证金组合 |

它们相互连接：订单可能申请办理账户业务；合约通过账户履行并关联产品和当事人；账簿与组合组织交易的管理范围。余额、持仓、权限和状态是围绕这些对象保存的信息。

这一节先建立对象轮廓。具体业务范围沿[[00-20260911-认知实验/t03专题-协议/维度学习/业务对象|业务对象维度]]展开；学完单维度后，再看[[00-20260911-认知实验/t03专题-协议/维度学习/交叉矩阵|交叉矩阵]]对应具体模型和来源。

## 3. 从全貌往下，怎样逐步学清楚

以场外互换为例，先理解双方约定如何形成收益和支付组成，再认识合约、腿、账户、交易对手、账簿与保证金组合。接着看这些对象分别进入哪些模型，最后才去查TIT交易ID如何桥接、OIS分成如何关联，以及下游如何筛选合约。

因此阅读路径是：**业务背景与对象关系 → 模型中的身份及信息分工 → 对应来源与具体加工 → 实际消费。** 各业务入口先讲前两项；“实现详解”提供后两项的已读证据。能复述一组字段不是学习终点，能说明为什么有这些对象、到哪里查某个业务问题才是。

全貌之外还有当事人和产品：协议参与角色连接T01，产品或标的连接产品侧；部分OIS客户条件和报告事件进入其他主题。不能把所有与场外交易有关的数据都算成T03。
