# 订单与办理：从提出请求到业务完成

所属位置：全貌中的“订单与业务办理”分支。读完应能区分申请、审核、激活、交易触发与成交，并说明为什么不同来源的“订单数”不能直接当成一种业务量。

订单首先记录一次办理请求。保险订单对应保险业务申请，开户订单对应开立账户的办理过程，智能条件单则记录满足条件后希望执行的交易指令。请求提交后，可能继续经历审核、支付、激活或交易执行；不同业务需要记录的阶段不同。

因此看订单，先明确“用户请求办什么”，再看“现在办到哪一步”。例如开户审核通过之后还有激活等信息；条件单存在之后还可能尚未触发或成交。模型把这些状态和过程保留下来，供后续查询业务进展。

| 已读分支 | 业务请求 | 模型入口 |
|---|---|---|
| PRD产品中心保险订单 | 办理保险相关业务 | `T03_ORD` |
| OAO网上开户 | 开立账户的申请和处理 | `T03_OAO_ORD_INFO` |
| 智能条件单 | 按设定条件触发交易指令 | 下文对应源指令及加工，区分创建、触发与成交 |
