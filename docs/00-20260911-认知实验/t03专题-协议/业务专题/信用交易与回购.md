# 信用交易与回购：从业务约定到逐笔负债

所属位置：全貌中的“交易合约”分支。读完应能把合同层安排、具体合约、账户、标的和归还过程放在同一张图中，区分资格、成交与仍在履行的义务。

这组业务的共同点是：交易发生后，仍有借入、返还、购回或担保等约定需要跟踪。两融涉及借资金或借证券；股票质押式回购涉及质押标的及购回安排；转融通来源还区分资格合同和具体合约。它们都需要账户和标的，但源系统的编号、阶段和金额不能互相套用。

先看两融的完整例子，再对照股票质押、债券协议回购和转融通的差异。RCC/ICC账户自身如何形成，见[[00-20260911-认知实验/t03专题-协议/业务专题/账户/柜台与PB账户|账户分工]]。

## 模型对应：签约、逐笔合约和存续记录

| 业务对象 | 模型位置 | 需要理解的内容 |
|---|---|---|
| 两融合同 | `T03_MARG_CONTR_INFO`，20101 | 合同层安排 |
| 两融合约 | `T03_MARG_COMP_INFO`，20102 | 具体合约引用合同、资金账户、证券账户和产品，并保留委托、成交、归还、计息及展期信息 |
| 股票质押式回购 | `T03_SRP_COMP_INFO`，20104 | 合约、质押标的、购回与部分解押等信息 |
| 转融通资格合同 | `T03_REF_CONTR_INFO`，20109 | 资格、合同安排和适用条件 |
| 转融通具体合约 | `T03_REF_COMP_INFO`，已读借入分支2010801 | 具体借入、返还、期限及展期信息 |

以融资买入为例：委托表达想买多少，成交表达实际买成多少，后续归还和计息改变存续中的义务。假设融资成交8万元，后来归还3万元本金，简化剩余本金为5万元；历史成交仍是8万元。这是业务示例，不把5万元直接指定给某个尚未确认口径的源字段。

因此理解这类表，要同时看到交易如何形成和义务如何履行。“期初”“日间实时”等字段再表达不同观察时点；具体源端计算和刷新规则在实现详解中区分已知与待确认。
