# 管理对象与业务控制：哪些账户和交易放在一起管理：模型与加工证据

业务背景与模型定位见[[00-20260911-认知实验/t03专题-协议/业务专题/管理对象与业务控制|管理对象与业务控制：哪些账户和交易放在一起管理]]。本篇按需核对源字段、身份构造、连接、转码及时间维护，不作为必须顺序阅读的课程。

## 基金投顾：资产单元与实盘组合并不等价

64170 从 RCC（零售柜台新一代清算系统）`A_ASSETUNIT` 生成基金投顾资产单元：ASSET_UNIT 为编号，修饰符带 `10208-机构号`。它保留客户、投顾账户 INVESTOR_ACCOUNT、组合 COMBINE_CODE，以及费用类型串、允许委托方式和扩展权限。机构号参与修饰符，说明单元编号不能脱离机构范围理解。

该分支采用目标与当日源比较、保留未出现对象并标记删除的维护方式，不能仅凭模型存在就认定单元仍有效。[[00-20260911-认知实验/t03专题-协议/证据/全域分支补充/SQL/64170.json|64170]]。

62495 则从 FAP（基金投顾组合管理平台）的 `F_INVEST_PLAN` 进入名字带“组合持仓”的表。Agt_Id 实际取 FUNDACCOUNT、修饰符 10201，源实盘组合 ID 另存；策略和投顾组合产品分别构造 FAS-S、FAS-P 前缀身份，还保留首次转入金额、开始运行、退出、关闭和续期等字段。

这个已读分支更接近**账户下实盘投资计划的状态和关联信息**，不能只按“持仓表”三字把一行理解为一只证券的持有数量。首次转入金额也不是当前组合市值。

两边都出现资产单元、组合和账户，但本次没有证明 RCC COMBINE_CODE 等于 FAP BINDPORTID，不能靠字段名字把两套组合直接连成同一对象。要贯通实际业务，需验证双方共同标识及来源范围。[[00-20260911-认知实验/t03专题-协议/证据/全域分支补充/SQL/62495.json|62495]]。

## 权限和白名单：描述适用范围，不是在描述持仓

PB资产单元操作业务权限模型 **T03_PB_AST_UNIT_OPER_BUSI_RIGH** 从 GPB（广发投易通系统极速版）`U_OPERBUSIRIGHT` 取 PROJECTID，修饰符区分 SH/SZ；记录控制层次、产品、操作员、组合，以及查询、操作、允许投资范围和委托权限串。操作员也按来源区域构造不同前缀。

因此它描述的不是“账户是否可用”一个开关，而是在某个控制层次、某操作员及产品/组合条件下的权限。仅按 Agt_Id 合并或挑一条，会丢掉实际约束维度。权限串的分隔、逻辑组合和最终执行机制未在该投影中展开，不能自行解释成 AND/OR。[[00-20260911-认知实验/t03专题-协议/证据/全域分支补充/SQL/64342.json|64342]]。

两融业务产品白名单明细模型 **T03_AST_ACCT_MARG_BUSI_PRD_WL_DET** 又有另一套范围语义：FUND_ACCOUNT 或 STOCK_CODE 为 `!`、空等情况，会被转换为空的目标身份；市场或产品条件不足时也不构造产品 ID。这类特殊值的业务范围需查源定义，不能直接当作普通缺失数据，也不能未经确认就称为“全账户通配”。

名单状态只在到期日早于处理日时写 5（注释为过期），其余没有 ELSE，可能为 NULL。**状态为空不能反向解释为一定有效。** 名单类型、两融业务名单类型、允许业务串和到期日应共同解释。此处 SQL 日期绑定 2026-05-20，非当前资格核验。[[00-20260911-认知实验/t03专题-协议/证据/全域分支补充/SQL/181043.json|181043]]。
