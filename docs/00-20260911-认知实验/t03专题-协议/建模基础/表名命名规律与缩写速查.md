# T03 表名怎么读：命名规律与缩写速查

先记住：`T03_AST_ACCT` = 协议主题 + 资产 + 账户；`T03_AGT` = 协议主题 + 协议。**主题编号表达归属，后面的词表达具体对象和信息内容。** T03 下可以有账户、合约、订单、持仓等表，不要求都以 `T03_AGT` 开头。

本文归纳本地表名与中文元数据中的实际用法，作为阅读指南；尚未找到正式的英文词根标准清单，不能把归纳结果当成强制建表规范。下列英文用于帮助记忆，中文含义以所举表的元数据为依据；有歧义的词单独说明。

## 1. 一张长表名通常怎么拆

常见组合是：`主题_业务领域或来源_业务对象_组成部分或信息内容_存储或加工后缀`。这是常见排列，不是每张表都满足的固定语法。

| 实际表名 | 分段理解 | 读成什么 |
|---|---|---|
| `T03_AST_ACCT` | T03 / AST / ACCT | 资产账户 |
| `T03_AGT_PTY_RELA_H` | T03 / AGT / PTY / RELA / H | 协议—当事人关系历史 |
| `T03_OTC_SWAP_COMP_LEG_INFO` | T03 / OTC / SWAP / COMP / LEG / INFO | 场外互换合约的腿信息 |
| `T03_OTC_OPT_COMP_SUB_TRD_OBSV_DATE_ATTR_INFO` | T03 / OTC / OPT / COMP / SUB_TRD / OBSV_DATE / ATTR / INFO | 场外期权合约子交易的观察日属性信息 |
| `T03_AST_CRRC_ACCT_BAL` | T03 / AST / CRRC / ACCT / BAL | 资产账户按币种记录的余额 |
| `T03_FIN_LEAS_COMP_LOAN_DET_CASH_FLOW` | T03 / FIN_LEAS / COMP / LOAN_DET / CASH_FLOW | 融资租赁合同放款明细现金流 |

读长名字时先找到中心对象（账户、合约等），再看它后面在描述什么。不能把整个名称都当成业务种类：同一份互换的主信息、腿、持仓是不同信息粒度。

## 4. 信息内容与常见结尾

| 片段 | 含义 | 不能仅凭它推断什么 |
|---|---|---|
| `INFO` | 信息 | 不保证“一对象一行”，也不保证是主表 |
| `ADTNL` | 附加 | Additional，不保证与主表一对一 |
| `DET` | 明细 | Detail，不直接说明明细键 |
| `RELA` | 关系 | Relation，需看两端、关系类型和方向 |
| `MAP_REGU` | 映射规则 | Mapping rule，不等于已经执行出的映射结果 |
| `ATTR` | 属性 | Attribute |
| `NAME` | 名称 | 名称类别及变更规则另查字段 |
| `CLAS` | 分类 | Classification |
| `STAT` | 状态 | Status |
| `STATI` | 统计 | Statistics；`T03_AGT_STATI_INFO_H` 与状态历史不是同一含义 |
| `RAT` | 评级 | Rating，如 `T03_AGT_RAT_H` |
| `RATI` | 比例 | Ratio；不能与 RAT、RATE 混读 |
| `RATE` | 利率、费率等 | 按前置词判断，如票息率 |
| `BAL` | 余额 | Balance，币种、日期、余额类型另查 |
| `HOLD` | 持有、持仓 | Holding，持有对象及数量口径另查 |
| `SHR` | 份额 | Share，不能总读成股票 |
| `LMT` | 额度、限额 | Limit，适用对象和额度类型另查 |
| `RIGH` | 权限 | Right |
| `CTRL` | 控制 | Control |
| `SETT` | 结算 | Settlement |
| `RSLT` | 结果 | Result，不证明结果已被下游使用 |
| `CASH_FLOW` | 现金流 | 不自动等于实际已收付款 |
| `H` | 通常表示历史 | History；是否拉链、快照、增量，必须看字段与SQL |
| `T0` | 名称中的T0变体 | 不能据此认定实时刷新或具体调度频率 |
| `MID / MID1` | 中间加工命名 | 具体用途和保留方式须查SQL |
| `TEMP / TEMP1` | 临时加工命名 | 不等于数据库会话临时表，也不能据此直接删除 |

`REF` 尤其要按位置读：`T03_REF_COMP_INFO` 的注释是“转融通合约信息”，`T03_OTC_COMP_PERF_MARG_REF` 是履保参数。TIT源表的 `D_REF_*` 又处在另一套命名中。**相同字母不保证相同词义，更不能跨模型层和源系统机械套用。**

`COMP` 与 `CONTR` 也不能简单互换：本地同时有 `T03_MARG_CONTR_INFO`（融资融券合同）与 `T03_MARG_COMP_INFO`（融资融券合约），以及转融通合同和逐笔合约。区别是业务对象层次，详见[[00-20260911-认知实验/t03专题-协议/实现详解/服务与经营合同|合同与合约层级]]。

## 5. 系统代码、业务词根与加工标识分开看

`TIT`、`OIS`、`XIR` 等来源代码的中文名称和已读职责，集中看[[00-20260911-认知实验/t03专题-协议/00-全貌与证据边界#5. 来源系统要带着业务职责理解|来源系统与业务职责]]。`PB` 在账户名中表达主经纪商业务；`XPB / GPB / HPB` 则区分具体来源，不能混为一套账户实现。

元数据中的 `pdata_hk.t03_agt_stat_h_mid_gmp011` 可拆成：库名 + T03协议状态历史名称 + MID加工片段 + GMP011标识。末尾的数字和代码含义尚不能仅凭名字确认。核心模型 `T03_AGT` 反而不带 TIT 或 OIS；一张模型表可以接多个来源，必须查 SQL 或来源字段才能判定贡献。
