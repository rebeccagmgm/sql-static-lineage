# **分区方式**

由于数据会不断更新，且数仓需要记录历史数据，所以往往会以busi_date为分区字段。

此外，一个常用的分区字段为src_tbl，往往出现在与协议、事件等集合了多源系统数据的相关表中，方便根据业务系统/业务主题快速查找数据。

组合其实有点类似于OneData中提到的”缓慢变化维“的维度概念，需要存储所有历史记录，但又不会经常变化的数据一般用历史拉链表的形式存储（避免了每天全量存储，造成大量的冗余）。历史拉链表的关键字段：begin_date和end_date。

因此，如员工、营业部、产品等缓慢变化的维度对应的组合（即grp_def）采用历史拉链表存储，包含begin_date和end_date字段，未过期的数据的end_date都配置为‘2999-12-31 00:00:00’。
