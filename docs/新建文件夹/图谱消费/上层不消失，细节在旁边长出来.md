你现在真正应该从它拿走的其实只有两个东西：

> ** 
> **
> ====

1. 视觉上可以把一组资产画成一个盒子，但不能因此在逻辑上把它们当成一个“任意入口都能通向任意出口”的节点
2. 全局层级用 Semantic Zoom 控制整体信息密度；局部研究用 Overview + Detail，避免钻进去以后迷路。
3. ② 一个被抽象的 Group 应该有明确的输入/输出边界（Ports）。
4. ① Overview 不要因为 Detail 展开就丢掉。 
5. 前端怎么折都行，血缘推理永远基于 canonical graph。
6. 可折叠的
	1. ① 真正的加工模块
	2. ② 视觉盒子，但内部端口仍然区分
	3. ③ 单纯的知识区域
	4. 「局部混合粒度」比全图 Semantic Zoom 更适合你
7. “视觉裁剪 + 知识抽象”加上了一个非常关键的底座
	1. **抽象可以自由，推理不能自由。*
	2. 上面越来越“人”，下面越来越“机器”。
	3. 抽象层和事实层之间的契约

你不一定非得：

```
缩小 = Knowledge
放大 = Table
继续放大 = Field
```

可能更适合你的是：

```
主图始终保留：

[持仓] → [估值] → [风险]

我点开持仓以后：

[持仓]
   └────旁边出现──→
        [持仓接入] → [持仓模型] → [日终持仓]

继续点持仓模型：

        [持仓模型]
             └────→
          Table → Task → Table
```

**上层不消失，细节在旁边长出来。**
