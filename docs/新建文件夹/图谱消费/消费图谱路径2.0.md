最终方法可以定为：**以图定位和组织范围，以标签建立对象认识，以 Facts 提供加工证据，用小模型形成可追溯的业务知识，按实际问题逐步深入。**

目标是让你逐渐理解业务对象、公共基础、核心模型、主要过程和规则差异，同时控制阅读、推理和核验成本。

## 一、五条路径，分别承担不同作用

| 路径                       | 主要工作                                                         | 对知识建设的贡献                   |
| -------------------------- | ---------------------------------------------------------------- | ---------------------------------- |
| **① 全图结构统计**         | 出入度、上下游 schema、表／字段热点、汇聚与复用分布              | 找重点，确定阅读优先级             |
| **② 结构组织与简化**       | 线性链折叠、候选簇、跨区域连接；社区／骨干分析按需使用           | 划定学习范围，减少浏览负担         |
| **③ 表级业务标签**         | 对象、角色、人工备注，区分系统支撑、公共参数、基础、明细、结果等 | 提供初步业务认识，支持不同排除视图 |
| **④ Facts 驱动的消费分析** | 提取关联字段、条件、别名、分支、计算、聚合及输出依据             | 解释表和字段实际如何参与加工       |
| **⑤ 加工知识摘要**         | 综合结构、标签和证据，解释对象关系、完整过程与规则差异           | 形成可独立学习、后续可复用的知识   |

**①找重点，②组织范围，③提供认识，④补足证据，⑤形成知识。**

这不是必须逐层全部完成的流水线。可以从一张表或一个业务问题切入，再把发现补回标签、结构说明和知识库。

## 二、分析对象有三个尺度

| 尺度             | 适合回答的问题                                           |
| ---------------- | -------------------------------------------------------- |
| **单表／字段**   | 这是什么对象？怎样形成？被谁使用？承担什么作用？         |
| **具体加工过程** | 输入怎样经过筛选、连接、计算，变成什么粒度的结果？       |
| **主题／加工簇** | 多个过程如何配合？共享哪些基础？相似分支有什么口径差异？ |

先通过单表建立认识；涉及粒度、金额和规则时，沿具体过程讲透；材料积累后，再组织成业务主题。

已经接受的两种入口继续沿用：

- **基础表向下看用途**：如账簿的属性补充、资格控制、映射和分类。
- **核心表看形成与消费**：如互换合约的装载、对象连接、金额计算和汇总。

## 三、每批工作的固定流程

### 1. 选定一个有价值的范围

依据热点、标签、链／簇、业务重要性和你的疑问选对象。

每批明确要理解什么，并限制任务或材料量。既看高复用基础，也看核心结果和关键过程，避免始终围绕少数熟悉样本。

### 2. 程序准备分层材料

先提供小摘要：

- 表名、中文注释、已有标签；
- 结构位置、写者和消费者；
- 材料去重结果；
- 已有知识与差异线索。

按问题再提供具体 Facts：读取位置、别名、JOIN 条件、过滤、表达式、分组和输出绑定。Facts 不足时补相关 SQL 片段；业务定义缺失时，再查已有业务材料。

**确定性提取尽量固定复用，不让模型每换一张表就重新写一套脚本。**

### 3. 小模型形成解释

对象概览回答：

> 是什么对象？怎样形成？有哪些主要用途？哪些差异重要？哪些还不知道？

重要过程进一步讲清：

> 输入对象与范围 → 连接和规则 → 计算 → 输出及粒度。

不能停在“存在 JOIN、CASE、SUM”。需要说明关联了什么对象、规则控制什么、金额从哪里来、结果代表什么。

必要时用少量明确标为虚构的示意数据，解释“改掉这条规则，哪些结果会变”。

### 4. 按疑点补证

只补影响认识的关键问题，例如：

- 同名字段是否实际承担不同身份；
- 两个分支是否采用不同状态或日期范围；
- 动态本金与初始本金是否被混用；
- 聚合发生在连接前还是连接后。

大模型仅在重要疑点或证据冲突时介入，**不作为每批必经的全面审核环节**。

### 5. 保存并反馈

保存正文、证据定位、覆盖范围和未解问题。

经过证据支持的新认识，可以补充表标签、链／簇说明和已有文章。人工标记保留来源；修正判断时留下理由。

## 四、知识内容的质量标准

好的交付应让读者能够：

1. **辨认对象**：理解合约、账簿、产品、持仓、事件等对象及关系。
2. **复述过程**：讲清一份输入怎样形成输出。
3. **比较规则**：知道相似分支在哪些条件、字段、时间或粒度上不同。
4. **推断影响**：说明改动会影响属性、记录范围、匹配数量、分类还是金额，以及后续汇总能否消除。
5. **找到依据**：知道哪些是事实、哪些是解释、哪些仍然未知。

文件数、模式数和扫描任务数只说明工作规模。**核心评价是新增了多少有效理解，以及获得这些理解花了多少成本。**

## 五、复用与成本控制

- 全图统计、材料定位、哈希去重和基础提取由程序完成并缓存。
- 模型先读摘要，按问题展开证据。
- 相同材料复用局部解释；相似加工共用说明，特殊规则单列。
- 新版本只对相关材料差异做必要核对，不默认全部重读。
- 每批设置材料边界；未知登记后继续，不无限扩查。
- 记录材料量、补证次数、复用情况、必要的人工介入；实际费用不可获得就不估造。

成本需要同时考虑：**模型成本、你的阅读成本、补证和纠错成本。**

## 六、证据与进度边界

始终区分：

- **结构已统计**：知道有哪些对象、连接和候选。
- **材料／规则已核对**：确认了指定材料中的加工结构或局部一致性。
- **业务问题已解释**：能够回答具体问题及规则影响。

图可达不等于值一定受影响；结构相似不等于语义等价；常用关联键不等于主键；静态 Facts 不证明实际数据唯一、运行成功或业务正确。

统计绑定图版本，正文绑定具体材料。图换版时登记差异，已有知识按适用范围继续使用。

## 七、当前执行原则

**方法层已收束，小模型帮助业务认知的路径已接受。** 后续直接按批次建设内容，不再反复验证整条路线。

每批只需清楚报告：

- 新增了什么理解；
- 复用了什么；
- 哪些关键问题未解；
- 下一批推进哪里。

逐步接通公共基础、核心对象与主要消费过程，直到读者能够比较重要口径、解释典型变化，再判断整体知识覆盖是否足够。
