### 1. 不只是 Collapse，而是 Semantic Zoom

现在你的想法大概是：

```text
展开
A → B → C → D

折叠
[持仓加工]
```

Semantic Zoom 更进一步：

```text
远景
────────────────
交易 → 持仓 → 估值 → 风险


中景
────────────────
[持仓接入]
    ↓
[持仓模型]
    ↓
[日终持仓]


近景
────────────────
table_a → task_1 → table_b
              ↘ join counterparty


特写
────────────────
position_amt
   ← qty * price
```

也就是说，**缩放改变的不是字号，而是信息语义层级。**

这在研究领域就是 multi-level graph visualization / semantic zoom。2019 年的 ZMLT 工作专门研究大型图的多层级、semantic zoom；2024 年 IEEE VIS 又有工作专门研究 deeply nested compound graph 的 Overview + Detail，而且案例里直接包括 **computational data flow analysis**。([arXiv](https://arxiv.org/abs/1906.05996?utm_source=chatgpt.com "Multi-level tree based approach for interactive graph visualization with semantic zoom"))

这和你的数据地图非常匹配。

我甚至觉得以后你的产品应该允许：

```text
LOD 0  业务域
LOD 1  加工单元
LOD 2  表 / Task
LOD 3  字段
LOD 4  SQL Evidence
```

这比“点击折叠”高级很多。

### 2. Fold 后一定要有「边界接口」

这是我这轮看到以后，觉得你**最值得补进去的一点**。

假设你圈了：

```text
┌──────────────────┐
│ 持仓基础加工       │
│                  │
│ A → T1 → B → T2 → C│
└──────────────────┘
```

折叠以后，现在最朴素的做法是：

```text
X ──┐
Y ──┼→ [持仓基础加工] ─→ PDATA
Z ──┘
```

但真正好的抽象应该告诉你：

```text
                 ┌──────────────────┐
主数据输入 × 3 ─→ │                  │
事件输入   × 2 ─→ │   持仓基础加工    │ ─→ 主输出 × 2
辅助JOIN   × 8 ─⇢ │                  │ ─→ 下游 × 17
                 └──────────────────┘
```

也就是：

> **一个抽象节点必须保留它和外界的“接口”。**

KeyLines 的 Combo 已经会自动把组内节点通往外界的关系组合成 combo links，并且允许用户需要时再 reveal 原始链接；它甚至明确区分 **top-level graph** 和 **underlying graph**，图算法可以针对抽象层或者底层分别运行。([剑桥智能开发者](https://developers.cambridge-intelligence.com/docs/keylines/combos?utm_source=chatgpt.com "Combos – KeyLines Docs"))

这对你特别重要。

因为你拥有 Machine Facts，可以比普通产品做得更好：

```text
[持仓加工]

Inputs
  3 主来源
  8 JOIN 辅助
  2 Filter Control

Outputs
  2 Pdata
  17 downstream consumers
```

**这会让“折叠”真正成为知识抽象，而不是视觉技巧。**

### 3. Focus + Context：别总 Hide

你现在想的是：

> 当事人到处 Join，我把它隐藏。

对。

但还有一种情况：

> 我不是完全不想知道它存在，我只是现在不想让它抢注意力。

这就是经典的 **Focus + Context / Degree-of-Interest**。

例如：

```text
                当事人
                  :
                  :
交易 → 持仓模型 → 估值 → DM
        ↑
      合约
```

当你点“持仓模型”：

```text
交易  █████
       ↓
持仓模型 ██████████
       ↓
估值  █████

当事人 ░
员工   ░
机构   ░
证券   ░
```

没有真正删除它们。

只是：

```text
focus = 持仓模型
importance = 距离 + 角色 + 当前专题
```

Fisheye/Degree-of-Interest 是很老但成熟的可视化思想，后来也有专门针对大型图计算 DOI 的工作。([DOI](https://doi.org/10.1145/765891.766021?utm_source=chatgpt.com "Efficient user interest estimation in fisheye views | CHI '03 Extended Abstracts on Human Factors in Computing Systems"))

你甚至不用搞复杂算法。

第一版：

```text
当前节点               1.0
主链一跳               0.9
主链二跳               0.7
JOIN辅助                0.3
公共节点                0.2
其它                    0.1
```

前端 opacity / size 控一下，就已经很好用了。

## 还有一个我觉得非常适合你的：View 本身成为资产

Neo4j Bloom 有一个我觉得跟你特别像的概念：**Perspective**。

一个 Neo4j graph 可以建立多个 Perspective，每一个针对不同业务目的；Perspective 可以决定：

- 什么实体显示；
    
- 什么关系显示；
    
- 什么属性显示；
    
- 怎么画；
    
- 甚至保存领域化的 Search Phrase。([Neo4j Graph Intelligence Platform](https://neo4j.com/docs/bloom-user-guide/current/bloom-perspectives/bloom-perspectives/?utm_source=chatgpt.com "Perspectives - Neo4j Bloom"))
    

然后用户实际探索出来的一张图叫 **Scene**。

Scene 会保存：

> 当前图内容 + filter + visualization + style。

回来以后还是原来的状态，而且可以复制和共享。([Neo4j Graph Intelligence Platform](https://neo4j.com/docs/bloom-user-guide/current/bloom-tutorial/export-data/?utm_source=chatgpt.com "Scenes and sharing data - Neo4j Bloom"))

这一下让我觉得你之前的设计还能再改一个地方：

不要只有：

```text
Canonical Graph
     ↓
Knowledge View
```

而应该是：

```text
Canonical Graph
     │
     ├── 持仓 Perspective
     │       ├── Scene：持仓全景
     │       ├── Scene：日终持仓
     │       └── Scene：持仓估值关系
     │
     ├── 交易对手 Perspective
     │
     └── ETF Perspective
```

**Scene 本身就是知识资产。**

这特别符合你“我自己圈”的思路。

人工 Visual Reduction
      ↓

      ↓
Business / Knowledge Lineage

```text
事实层
   ↓

   ↓
知识层
```

我觉得这个架构是很稳的。

### 最后还有两个“可以做，但别现在做”的东西

**Edge Bundling** 很适合你的全景模式。当几十个模块都连证券、员工、机构这些公共节点时，不需要画 100 根线，可以把相似路径捆起来。Hierarchical Edge Bundling 本身就是成熟的 graph visualization 方法，目标就是降低 compound graph 的 edge clutter。([埃因霍温科技大学研究门户](https://research.tue.nl/en/publications/hierarchical-edge-bundles-visualization-of-adjacency-relations-in/?utm_source=chatgpt.com "Hierarchical edge bundles : visualization of adjacency relations in hierarchical data - Research portal Eindhoven University of Technology"))

但它只能解决：

> 线太乱。

不能解决：

> 业务是什么。

所以优先级不高。

另一个是 **Progressive Visual Analytics**：不是“算法跑完→人看结果”，而是机器给出部分结果，人不断干预、选择下一块分析范围。这个研究范式强调 analyst-in-the-loop。([PubMed](https://pubmed.ncbi.nlm.nih.gov/26356879/?utm_source=chatgpt.com "Progressive Visual Analytics: User-Driven Visual Exploration of In-Progress Analytics."))

这其实特别像你：

```text
Machine Facts
↓
系统给候选
↓
你圈这一块
↓
系统展开证据
↓
你确认 / 折叠 / 命名
↓
继续下一块
```

所以长期看，你这个东西可能不是“图谱查看器”。

更像：

> **Human-in-the-loop Data Knowledge Workbench**

不过这个名字不用现在造。
