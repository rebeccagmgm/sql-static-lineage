# OTC 合约规模／名义本金：首轮优化建议

评估日期：2026-09-08。对象为当前发布证据中的 14 个代表性加工，另核验 6 个直接下游；范围、版本及原文见[证据索引](evidence.md)。本报告评估数据加工和业务资产，未修改生产 SQL、图、配置或发布结果。

**最值得先做的是核定两处口径、共用一段已证实重复的分类规则，并优先复用已有客户指标。当前没有足够证据批准合并四产品生产任务、合并两个销售日报，或再建一张通用名义本金宽表。**

这次没有把旧比较表换一种格式重列：旧试验用于找到候选，判断重新对照当前发布 SQL、Facts 和元数据。新增决策点包括月占比分母、香港分类规则的明确重复、既有指标的下游出口，以及公共日事实与归属后日指标不能互换的原因。

## R1：先确认本月占比的分母

路径：`dm_index_n.index_grp1_DealScal_OtcDeri_Mth → 199727 → dm_otc_n.trd_deri_type_mth`。

SQL 按期权／互换标签汇总，输入同时取运行日和上月末两个快照。`cur_mth_scal` 只加运行日的值，`cur_mth_scal_all` 却使用 `sum(sum(idx.index_val)) over()`，未限定运行日。最后 `add_nom_prin_mth_rate = cur_mth_scal / cur_mth_scal_all`。DDL 与 SQL 注释都称它为“本月新增名义本金规模占比”。[公式与过滤，L11–30](evidence/sql/199727-query.sql)

在实际被 JOIN 纳入的记录上，令两类本月金额合计为 C，上月金额合计为 P，两行占比之和为 `C/(C+P)`，并非一般意义的 100%。例如 C=100、P=50 时为 66.7%；这是说明公式的假设示例，不是查询到的业务数据。若正式定义确为本月内部构成占比，分母应与分子采用相同月份和群体；若业务有意采用两月基数，则需修正名称和说明。

**建议落点：**复用现有 `dm_index_n` 的月度规模结果，先核定 `199727` 中派生比例的定义；无需新建底层本金事实表。`199706 → trd_deri_stru_type_mth` 已使用结构类型和业务类型对应的月／年新增、存续资产，两个输出可以共用已定义的基础指标及环比规则，但保留“业务类型”与“结构类型”的不同粒度。[199706，L15–23、45–108](evidence/sql/199706-query.sql)

**影响范围：**首先是 `trd_deri_type_mth.add_nom_prin_mth_rate` 及其报表。当前发布范围未发现该输出的直接 SQL 读任务；这不是无人使用的证明，外部报表应另确认。

**收益／待确认：**避免把错误分母变成公共指标；尚未测得真实金额影响。需确认正式分母、零分母行为、月份快照含义、组合定义 JOIN 是否唯一。199727 与 199706 都把上月为零的环比设为 1，这也是可共用的规则，但不应不经定义确认就作为通用百分比规则推广。

## R2：累计绝对本金与累计动态本金为什么一样

路径：`销售合约基础＋按日明细 → 118141／220979 → 国内／香港销售日报`。

两个任务各自均有以下行为：

- `Accum_Dyna_Nom_Prin`：有效日期内的动态本金按日期做窗口累计。
- `Absl_Nom_Prin`：只对 `grp_id='01'` 保留当日动态本金，其余为零。
- `Accum_Absl_Nom_Prin`：与本任务 `Accum_Dyna_Nom_Prin` 完全相同的窗口表达式，没有当日绝对本金的分支条件。

证据：[118141，L222–226](evidence/sql/118141-query.sql)、[220979，L200–204](evidence/sql/220979-query.sql)。因此，若非 01 分支在有效期内有非零动态本金，当日绝对本金可为零、累计绝对本金却可非零。这里的“绝对”也未使用 `abs()`；不能自行解释成数学绝对值。

**建议路径：**若累计两列本来同义，在各自任务内只维护一份窗口定义，保留兼容输出列；若应按当日绝对本金累计，则属于口径修复，应确认历史报表和重算范围。先确认语义，再去重。

两个日报不能直接共用一个现成累计结果。118141 的窗口键是 `agt_id, Contr_Type_Cd`；220979 只有 `agt_id`。前者排除香港部门、`FEE_SWAP` 和 04 分支；后者有香港账簿、客户门槛和明细日期起点。两者都由当前快照输出历史计提日期，累计值不是月日均。[118141，L298–303、399–405](evidence/sql/118141-query.sql)、[220979，L303–318、497–501](evidence/sql/220979-query.sql)

**建议落点：**保留 `dm_otc_n.otc_sale_daily_rpt` 与 `otc_hk_sale_daily_rpt` 的消费职责。二者已共同使用 PDATA 合约基础和日事实，不需要为这两列再建公共宽表。

**影响／收益／待确认：**涉及两个日报的累计字段及其外部消费者；当前图未展示输出端读任务。可以减少重复维护，SQL 引擎是否已复用窗口计算未知。确认“绝对”的业务含义、窗口键差异、JOIN 唯一性和历史口径后，才能选择具体改法。

## R3：香港合约分类是可信的公共逻辑候选

路径：`pdata_n.t98_otc_deri_comp_sale_info → 220981.otc_hk_sale_para / 220979.otc_hk_sale_daily_rpt`。

两任务的 `HK_Contr_Type_Cd`、`HK_Contr_Type_Desc`、`HK_Undrl_Type` 分类片段，经忽略空白和大小写比较后相同：参数表 L127–159 对应日报 L270–302；附近的香港账簿、终止日门槛和客户纳入逻辑也有共同部分。[220981](evidence/sql/220981-query.sql)、[220979](evidence/sql/220979-query.sql)

**建议共用的是香港合约分类定义。**先将已证实等同的规则集中维护，由两个现有结果消费。它是属性和分类逻辑，不是本金指标。是否采用已有查询模块、公共视图或物理表，需结合现有实现方式和运行成本；本轮尚未证明某张已有物理表可以无损替代该片段。

**必须保留的差异：**参数页按合约取最新参数，日报按有效区间及计提日匹配参数；后者还接按日本金并累计。不能把日报改为直接读取参数页的最新结果，否则历史日可能套用当前参数。[参数页 L179、230](evidence/sql/220981-query.sql)、[日报 L369–384、423–429](evidence/sql/220979-query.sql)

**影响／收益／待确认：**确定的直接使用点是这两个任务，输出仍保留在原 `dm_otc_n` 资产。收益是同一次分类调整只维护一处，减少漂移。共用纳入逻辑前还要确认两域日期门槛是否有意独立、分类规则是否需要历史版本、关联键是否唯一。没有运行成本依据，不承诺减少任务或资源。

**影响／收益／待确认：**当前发布范围内基础表有 47 个直接读任务，日事实有 21 个；这是改动复查范围，不是可删除数量。重点核验合约与腿的对应关系、跨分支标识、同日并列记录、币种单位、日期覆盖和 JOIN 放大。可期待集中维护规则；节省任务数和耗时均未测量。

## R5：归属后日规模与月日均应分别复用

两条已存在的路径：

1. `基础＋日事实＋管理关系 → 224351 → dm_otc_n.otc_cust_daily_dyna_nom_prin → 100170`。
2. `基础＋日事实＋管理关系 → 159763 → dm_index_n.index_grp3_compscal_otcderi_cs_mthapd → 标准资产相关结果`。

224351 先按当前合约和管理关系关联历史日事实，再按比例分配；动态本金只在有效期内计入，初始本金只在起始定价日计入。最后按分公司、引入机构、经理、交易对手简称和计提日汇总。结果没有合约编号、稳定客户 ID、产品分支和币种维度，不能充当通用合约日事实。[224351，L21–33、48–70、165–166](evidence/sql/224351-query.sql)

159763 是客户×机构×员工×标签的当月日均：月内纳入的日规模分配后求和，除以月初至运行日自然日数；它只纳入 01/02/03，排除 `FEE_SWAP`，并有机构和人员条件、映射及回退规则。224351 排除 `DIGITAL/FEE_SWAP`、纳入 OTC/HK 部门，采用不同输出键和条件，不能直接取其结果再除以天数替代 159763。[159763，L19–43、58–70、135–144](evidence/sql/159763-query.sql)

**建议落点：**保留日事实在 PDATA；同归属口径的日规模复用现有 `dm_otc_n.otc_cust_daily_dyna_nom_prin`；交叉销售月日均复用现有 `dm_index_n` 指标。不要将机构员工分配后的月日均重复挂到每份合约或每个交易日，再允许直接求和。

**消费与影响：**100170 实际读取日规模，将 `accrued_date` 改名为下游 `busi_date`，并作金额精度转换；这是消费接口的一项关键时间合同。[100170，L9–13](evidence/sql/100170-query.sql) 159763 有 4 个已见 SQL 消费者：148368、160773、160780、165154，其中 160780 还按标签乘不同折算系数。月日均口径变化需沿这些结果复查，不能只看一个目标表。[160780，L61–65](evidence/sql/160780-query.sql)

**收益／待确认：**优先复用现成结果可避免再算归属和月日均。扩大为公共指标前需确认当前归属回看历史的政策、04 不纳入的理由、比例与机构回退、稳定客户键、分区日期和币种。这里没有证明实际金额重复或比例不守恒。

## R6：客户级本金指标已有承接位置

路径：`dm_otc_n.otc_rev_daily_rpt＋合约存续变更事件 → 229121 → dm_otc_n.bi_otc_cust_index → 230266 → 下游客户指标表`。229121 的本金模块实际读取创收日报，不读取 R2 的两个销售日报。

| 现有字段               | SQL 定义                                                 | 使用限制                                         |
| ---------------------- | -------------------------------------------------------- | ------------------------------------------------ |
| `swap_new_principal`   | 本月计提日等于起始定价日的 TRS 初始本金合计，除以 10,000 | DDL 单位万元；不应自动解释为包含全部追加开仓事件 |
| `swap_outst_month_end` | 上月最后一天的 TRS 动态本金合计，除以 100,000,000        | DDL 单位亿元；与新增本金列单位不同               |
| `swap_turnover_rate`   | （本月新增本金＋本月平仓金额）／上月末存续本金           | 比例不可直接加总；事件符号、零分母行为需确认     |

现行处理先按 `USCC, Inr_Seri_No` 汇总，接事件后再按 USCC 汇总；最终回连的客户主集合按公司名称与 USCC 组织，并有自身产品及日期范围。因此“公司×快照日”是用途解释，实际一客户一行未验证。[229121，L49–50、69–80、145–191](evidence/sql/229121-query.sql)

**建议落点：**同口径客户消费优先复用已有 `dm_otc_n.bi_otc_cust_index`。如果需求是合约事件明细，应复用明细与事件来源，不能从客户汇总结果逆推出明细。230266 已将上述三个字段实际选出并推送；已见消费证明到 SQL 出口，未查询下游真实数据或报表。[230266，L22–29](evidence/sql/230266-query.sql)

**收益／待确认：**可避免新增同义客户宽表，复用影响首先涉及 229121 与 230266。模块没有币种归一化步骤，单位缩放不等于已证明人民币统一；还需确认事件表快照范围、平仓金额符号、客户／合约键、分母零值策略。229121 没有本金月日均，不能把上述存量或新增值改名当月日均。

## R7：风险字段别名不等于三次本金计算

路径：`组合保证金每日结果 → 200030 → dm_otc_n.adm_v_risk_daily_bundle_margin`。

同一 SELECT 中 `dynamic_notional`、`notional1`、`notional_or_value` 均直接取 `DR.DYNAMIC_NOTIONAL`，`notional2` 则固定为字符串 0。前三列同值是确定事实，没有看到三次独立恢复本金的计算。[200030，L392、411、418–419](evidence/sql/200030-query.sql)

**建议落点：**保留现有风险结果，以一个值源配多个输出别名解释；零值列标为占位，不能当本金事实。不要将它与销售归属后规模混为同一可互换指标。当前证据未证明可以删列，也未发现此表的批内读消费者。

**影响／收益／待确认：**若将来清理，先确认外部接口字段依赖及组合粒度。输入按当前快照和组合范围筛选，输出还含来源业务日；`MTM_CURRENCY` 的存在不证明名义本金采用相同币种。当前优先级低，最多减少字段解释成本，不能据此申报算力节省。

## 本轮判断的适用范围
