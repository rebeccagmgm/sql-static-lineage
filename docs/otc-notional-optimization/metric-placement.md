# 指标、公共事实与主题宽表的落点

**本轮应优先复用已有日事实、客户指标和交叉销售指标。没有证据支持新建一张包揽全部名义本金的 `dm_otc_n` 宽表。**这里的建议基于已核验加工和消费职责，不替代正式分层规范。

## 候选逐项选择

| 内容 | 最适合的资产类型 | 当前已有落点及建议 | 粒度与不能跨越的边界 |
| --- | --- | --- | --- |
| 合约标识、产品分支、原币／折算信息、账簿和当前属性 | 公共对象与属性 | 优先复用 `pdata_n.t98_otc_deri_comp_sale_info` | 当前快照；普通 TRS 存在腿级处理，不预设一合约一行 |
| 合约每日动态规模及日相关金额 | 公共日事实与基础度量 | 优先复用 `pdata_n.t98_otc_deri_comp_sale_adtnl_det` | `busi_date` 表示计提日期；需保留产品、标识和币种语义，不累计不同日期存量当新增 |
| 香港合约类型／标的分类、纳入标志 | 公共属性／规则 | 共用 220981／220979 已重复的分类定义；尚不指定新物理表 | 不是数值指标；未来如需回溯，需说明规则生效时点 |
| 机构／经理／交易对手分配后的每日动态规模 | 业务口径下的每日指标，可在主题宽表承接 | 已有 `dm_otc_n.otc_cust_daily_dyna_nom_prin`，限相同归属规则复用 | 已丢失合约、稳定客户 ID、产品和币种维度；不能充当全域基础事实 |
| 客户×机构×员工的交叉销售当月日均 | 已有派生业务指标 | 复用 `dm_index_n.index_grp3_compscal_otcderi_cs_mthapd` | 月内已过自然日分母；归属、纳入和标签规则都属于定义 |
| 客户 TRS 本月新增本金、上月末存续、换手率 | 已有客户级业务指标 | 同口径复用 `dm_otc_n.bi_otc_cust_index` | 新增与存续分别为万元、亿元；比例不可加总；客户唯一性待验证 |
| 按业务类型／结构类型的月新增、环比和规模占比 | 月度指标及报表结果 | 复用既有 `dm_index_n` 规模资产，保留 `trd_deri_type_mth`／`trd_deri_stru_type_mth` 各自展示粒度 | 占比先核分母，环比先核零基数规则；结构类型不能当成业务类型重复删去 |
| 销售日报累计本金 | 销售用途下的派生字段，指标资格待口径确认 | 保留现有销售日报，按 R2 核定动态／绝对两列 | 生命周期按日累计不是月日均；不同窗口键不能直接归并 |
| 风险结果同值别名／零值占位 | 接口字段映射 | 留在既有风险结果，说明值源与占位 | 别名不新增指标定义，零占位不视为真实本金来源 |

上述每行的 SQL 与消费者证据均由[主报告 R1–R7](README.md)展开；[表元数据快照](evidence/table-metadata.json)保留描述、分区、DDL 和采集日期。

## 最值得明确为指标的内容

首先复核已有定义，不重复注册：

1. **合约某日动态规模**：稳定的基础度量候选，但定义必须带上产品算法、金额单位与币种、合约／腿／工具身份、业务日期和当前快照／历史事实的区别。先复用已有事实结果。
2. **客户本月新增／上月末存续／换手率**：已有结果与消费出口；适合补齐公式、分母、单位和客户集合的正式说明，支持同口径复用。
3. **归属后日规模与交叉销售月日均**：有明确经营用途，应该保留为不同粒度、不同规则的指标。不能只因金额同源而合为一个定义。
4. **月度产品构成占比与环比**：适合标准化派生定义，但 R1 的分母和零基数处理必须先确认。

香港分类、账户关系、合约标识适合沉淀为属性或关系；它们决定指标范围和 JOIN，但本身不因被广泛使用就成为业绩指标。

## 若确有新宽表需求，先明确这一行代表什么

以下是拟议准入条件，不是本轮新增的表合同：

- **合约日主题**：只有消费者确实需要明细解释时才选择该粒度。应明确产品分支、合约／腿／工具键、计提日期、采集或计算快照、币种与单位；先检查已有 PDATA 明细是否足够。
- **客户经营主题**：优先复用 `bi_otc_cust_index`。增加字段前要验证公司名称／USCC 与销售关系的实际基数，避免一个客户金额被重复挂到多行。跨指标单位也要显式说明。
- **机构员工月度主题**：消费已计算月指标，并明确客户／机构／员工／标签／月份的键。不能把月度分配值重复挂到每份合约再求和。
- **参数展示主题**：最新参数与按历史日有效参数分开使用。香港参数表与日报共享分类，并不意味着两者输出行可以一一替换。

是否增加物理表要有复用人数／应用、查询时效、重算成本、权限及历史快照要求的实际依据。本轮只观察到静态 SQL 消费，未取得这些运行证据，因此建议停在已有资产复用与规则归并层。

## 可直接带去确认的业务问题

| 对应建议 | 需要业务或消费方确认的具体问题 | 答案会改变什么 |
| --- | --- | --- |
| R1 | 本月新增规模占比的分母是本月所有产品，还是两个月合计？上月为零时环比为什么返回 1？ | 决定修公式、修名称，或保留特殊业务定义 |
| R2 | 累计绝对本金是否应累计当日的“仅 01 分支”绝对本金？两个日报窗口键差异是否必要？ | 决定同义复用还是口径修复，并确定历史重算范围 |
| R3 | 香港分类规则需要按历史版本回看吗？两任务的纳入门槛是否应同步维护？ | 决定共享规则的时间参数和边界 |
| R4 | 普通 TRS 合约／腿对应是否一对多？跨来源金额是否已统一？ | 决定可共用的最细事实粒度和是否可跨产品加总 |
| R5 | 当前销售归属回看历史规模是否符合考核政策？04 为何未进入交叉销售月日均？ | 决定公共定义边界，不能单靠 SQL 代为决定 |
| R6 | 新增是否只指起始合约，是否含追加开仓？平仓金额符号和零分母如何处理？ | 决定已有客户指标能否满足新的消费问题 |

这些问题不阻碍本轮提出有证据的建议；它们阻止的是未经确认就实施合并、改口径或下线。
