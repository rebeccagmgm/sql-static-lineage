# data-graph-ui

界面层数按一次完整的表到表加工计数：`表 A → 任务 → 表 B` 为 1 层。前端请求 `/api/trace?depthUnit=table-hop`；字段取值计一层，跨任务接续不另计层。未指定该参数的调用方保持原始边深度。关系数量上限仍可能截断一层，并明确显示提示。

基于 React Flow 的 data-graph 局部血缘探索器。直接调用现有服务的 `/api/status`、`/api/search`、`/api/fields`、`/api/trace`、`/api/task`，不复制图谱、不预加载全图，也不发布 Neo4j 数据。

## 启动

在仓库根目录启动后端和前端：

```powershell
npm --prefix packages/data-graph-ui ci
npm run graph:serve
npm run graph:ui
```

默认页面为 `http://127.0.0.1:8792`，`/api` 代理到 `http://127.0.0.1:8791`。可通过 `DATA_GRAPH_UI_PORT` 和 `DATA_GRAPH_API_ORIGIN` 调整；不要在配置中写入账号或密钥。

## 验证

```powershell
npm --prefix packages/data-graph-ui test
npm --prefix packages/data-graph-ui run typecheck
npm --prefix packages/data-graph-ui run build
```

当前支持 `/api/overview` 的区域加工骨架、`/api/regions` 的区域成员分页，以及表/字段血缘、上下游、深度、150 条边上限、候选接续开关、任务和字段证据、SQL 懒加载、返回恢复视口。进入字段血缘时会带版本校验地分页加载当前锚点的全部字段，但不会默认选择或自动查询；用户可以一键选择全部字段，或按精确调度 ID 和字段名筛选后选择。前端顺序执行单字段查询，按原始身份去重，将合并结果限制在 150 条原始血缘关系；超过上限且深度大于 1 时，自动以 1 层重查一次。1 层仍超限会明确提示。分页前后及后续追溯均校验图谱版本。区域阶段是后端按当前规则推导的视图，无法分类的区域明确显示为 `UNCLASSIFIED`；区域关系只是 `TABLE_IO` 聚合，不能当作字段因果证据。节点使用 API 原始 `id`，不会按表名合并不同任务、读次或写入身份。

搜索、字段和区域成员都采用有界分页。表搜索返回同名物理节点时，UI 使用原始 `nodeId` 请求字段，避免跨物理身份合并。图谱在请求间换版时，UI 会拒绝混合展示旧画布与新证据。

字段选择面板支持独立、精确的调度 ID 筛选和字段名搜索，仅筛选已加载范围，隐藏的已选项不会丢失。点击画布字段时高亮当前子图内该字段的上游来源、下游去向及连线；分别沿正向和反向遍历，不扩散到仅共用来源的旁支；再次点击该字段或画布空白处取消高亮。高亮不请求新血缘。

字段视图采用“表 → 调度任务 → 表”。每条取值关系经过任务形成两段显示连线，因此显示连线数量可能超过原始关系上限。仅凭已确认 CONTINUES 接续、同名限定表及确认的物理身份合并表卡片，字段 alias 保留原始身份和证据。候选生产者默认折叠到来源表入口，可展开查看；普通取值路径不会被任务节点的共享外观扩散成无关字段的血缘。
