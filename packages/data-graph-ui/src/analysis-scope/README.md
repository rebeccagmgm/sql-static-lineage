# 分析范围

在现有图谱左侧进入“分析范围”，或访问原页面的 `?analysis=1`。

1. 起点只分物理表和调度，允许混选。批量输入完整表名和数字调度 ID，自动识别，不要求填写源表或目标表。
2. 点击“打开所选对象”，查询每个起点的一层上下游并合并实际关系。表、调度混选时，每个对象都参与查询；发现的对象无需事先加入起点清单。
3. 单击节点只选中并高亮图内上下游，其余淡化，不切换字段分析对象或加工证据。节点下方直接显示“分析此表 / 分析此调度”和“查看加工证据”，顶部工具栏保留同样入口。再次点击、点击空白处或“取消高亮”恢复。也可用“当前对象”下拉框选择较远的节点；“查看加工证据”才打开该对象的详情。
4. “向上展开一层”“向下展开一层”从当前节点继续读取并加入关系。“收起上次展开”恢复上次展开前的图，保留其他关系。界面不再按源表、任务、目标表固定三列，而是按现有边排列。
5. “分析此表 / 分析此调度”打开该对象的字段选择，再点击“展开所选字段”查询路径。字段仅来自当前已展开物理表与调度；起点调度筛选同样约束实际查询。需要更多环节时，先返回表与任务图展开。候选、未知等标记不因高亮或扩展而提升确定性；同名物理来源不合并。
6. 集群筛选持续约束起点、表与调度展开及字段路径。物理表按所选集群任务的实际读写关系纳入，共享表不会自动带入其他集群的任务。遇到边界提示被排除的调度；字段路径在边界停止，不跳过被排除的加工重新连接。
7. “保存范围”保存起点身份、勾选状态、集群条件、展开步骤与版本到当前浏览器。打开时重新查询、重放展开步骤。旧记录的源表和目标表都迁移为物理表，旧的目标专属聚焦不再裁剪结果；无法验证的身份或步骤明确报错，原记录不覆盖。

TIT 预设采用入模调度作为起点：“当事人分类”为 2 个调度，“TIT → T01 全部”为 23 个调度，其读写表自动发现。这样初始视图聚焦 TIT 的 T01 加工；点贴源表向上展开，可继续看到采集任务与原库。自定义范围可以只选表、只选调度或混选。

查询只调用既有只读 API，每个起点分别查询上下游，每次展开使用表跳数一层、400 条关系上限。已知调度 ID 直接查关系，复用返回的任务身份与集群信息，不反复进行全文搜索。最多四个请求同时进行，显示定位和关系读取进度；单次请求 30 秒未返回会报错。取消或失败保留上次完成的图，迟到结果不覆盖新操作。最多 120 个起点、60 个起点调度、40 次展开，合并关系最多 12000 条；上游截断明确提示。

画布接收并保存 React Flow 节点尺寸和拖动变化，高亮时保留尺寸与位置；切换关系图后待节点完成测量再居中。“重新居中”可随时找回视野。

表级关系表示任务读写观察，不代表字段或分区因果。布局中的列数和位置仅用于阅读，不能解释为固定业务阶段。这里不修改 Facts、发布图或既有自由探索存储。
